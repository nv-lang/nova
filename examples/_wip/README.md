# examples/_wip/ — концепт жив, содержимое переписать начисто

Файлы здесь **не гарантированно компилируются** и **не входят** в будущий
CI-гейт компиляции examples/ (Plan 197 Ф.5). Каждый — концепт, признанный
ценным при аудите Plan 197 Ф.1, но с содержимым, которое дешевле переписать
с нуля, чем чинить построчно (retracted API, wildcard-импорты, невалидные
предположения о типах и т.д.).

## Содержимое

- **`effect_density/`** — демонстрация плотности эффектов в сигнатурах
  реального money-transfer сервиса (см. `EFFECT-DENSITY.md` внутри). Аудит
  2026-07-12: `http.nv`/`main.nv`/`repository.nv`/`service.nv` используют
  retracted wildcard-импорт (`import effect_density.domain.*`); `main.nv`
  не содержит `fn main` несмотря на имя; `domain.nv` ссылается на тип
  `Sql` без импорта `std.data.sql`. Концепт (таблица плотности эффектов
  по функциям) ценен — переписать с текущим import-синтаксисом
  (`import X.{A, B}`) и проверенными типами.
- **`typed_pointers/unsafe_block.nv`** — демо "unsafe block — basic usage".
  Аудит 2026-07-12: relaxed-unsafe-правило (D216 §21) больше не требует
  `unsafe {}` для тривиальной арифметики внутри блоков файла →
  `E_UNSAFE_UNUSED` на всех трёх блоках. Механическое удаление `unsafe{}`
  обессмысливает демо (перестаёт трогать что-либо unsafe). Переписать с
  реальным unsafe-триггером (deref/pointer-op/`.read()`/`.write()`/etc,
  см. список в тексте ошибки D216 §21).

Когда переписан и компилируется канoном — переносить обратно в
соответствующую `examples/`-подпапку.
