## Шаг 1 — `e1262f4a5`: приватный тип модуля тела регистрируется для его экземпляров

**Корень.** После №1491 приватный тип чужого модуля не регистрировался вовсе. Так перестал
мешать приватный `Token` из std/json, вставший на место `lex.Token`. Но заодно собственные тела
модуля, инстанцированные в другой единице, потеряли возможность называть свой тип:
- `type-body-private`: оракул печатает `30`, Карина отказывала «undeclared type name `Cell`»;
- `type-body-sig`: приватный помощник с параметром приватного типа не получал строку
  (`harvest_fn` выбрасывает сигнатуру с неизвестным типом), и метод получал «`open` is not a
  callable».

**Правка.**
- `harvest_types` — два прохода. Сначала типы, видимые файлу. Затем приватные типы чужих
  модулей: с модулем-домом, с пометкой «приватный» и только под СВОБОДНОЕ имя. Урок №1491
  держится теперь порядком проходов, а не отсутствием строки.
- `DefTable.privs` и `@is_private`.
- `Checker @type_seen` — одна дверь «может ли это тело назвать этот тип». Видимый тип — как
  раньше; приватный — только из тела его модуля (`FnIndex @decl_is_home`).
  `@type_name_is_declared` спрашивает её. Судья головы пути (`A.b`) больше не пропускает
  приватный тип чужого модуля как «имя, которое реестр держит».

**Пробы.**

|---|---|---|---|
| `type-body-private` | `30` | отказ: undeclared `Cell` | check rc=0 |
| `type-body-sig` | `4` | отказ: `open` is not a callable | check rc=0, экземпляр зовёт `novac_fn_hp_geo_open` |
| `type-body-private-sum` | `1` | отказ: `pick` is not a callable | check rc=0 |

## Шаг 1b — `99c6c6917`: отказ метода ищет единственный метод имени НА ЕГО ПРИЁМНИКЕ

**Как нашлось.** Полный прогон стражей после шага 1 покраснел на `check-novac-fixture-expect`:
`field_mut_place/neg_1` ждёт «needs a mutable place» (P14), а получал «this type has no such
method».

**Причина.** Вместе с приватными типами строки получили и их методы, среди них
`Lexer @bump(b u8)` из приватного json-лексера std. `@refuse_method_call` спрашивал
`only_row_of(name)` по всей таблице. Имя `bump` перестало быть единственным, и отказ потерял
уже установленную причину.

**Правка.** `check/methods.nv`: `@only_row_on_receiver` — единственная строка МЕТОДА этого
имени, чей приёмник не чужой конкретный тип. Это тот же тест `@receiver_is_foreign`, что отказ
уже применял к найденной строке, только теперь он идёт по цепочке имени.

**Проверка.**
- Тест «another module's PRIVATE type's method of the same name does not hide a call's own
  cause»; КОНТРОЛЬ — тот же вызов на `mut`-корне компилируется.
- В обе стороны: с `only_row_of` тест красный, с правкой — зелёный.
- `fixture-expect` 78/78, `no-cascade` и `diag-schema` — 118 фикстур ok.
- Мера 0.2: 38 → 38, набор тот же.

## Где остановился: тень — оракульная половина

`type-body-shadow`: в `hp.geo` приватный `type Cell { v int }`, его метод строит
`Cell { v: .. }`; в `hp` свой `type Cell { w int, v int }`. **Оракул сам строит `Cell`
ВЫЗЫВАЮЩЕГО** — `geo.nv:8:12: E_MISSING_FIELD_IN_LITERAL … does not initialise field: w`.
Это то падение на двух `Cell`, на котором ты велел остановиться. Неподвижной точки нет:
одноимённые структуры двух модулей сходятся и в C-имени шелла (`Nova_Cell`).

Как ведёт себя Карина сейчас: приватный тип под занятым видимым именем НЕ регистрируется.
Тело получает тип вызывающего и честно отвергается («omits a declared field»), как и раньше.
Тихо неверного кода нет.

Цена полного решения на нашей стороне — объявленные в начале 19+ файлов:
- строки одного имени в цепочке `DefTable` без перехвата головы;
- резолв типа по имени ИЗ модуля в `sem/typeref.nv` (`ty_of_type_name`) и в `ty_of_name`
  (8 файлов);
- C-имя структуры с модулем — а его диктует шелл оракула.

Без оракульной половины не с чем сверять, поэтому дальше не шёл.
