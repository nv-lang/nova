# Отчёт облачной сессии `p274-carina-mono-k2`, третья сдача (слияние sweep, №1558)

Поверх `064beb6b4`. Коммиты: `04eb7301a` — слияние `p274-carina-sweep` с одной дверью символа

СЛИЯНИЕ И ОДНА ДВЕРЬ (слово интегратора про `shell_method_symbol`).
`shell_method_symbol` жил только в ветке sweep (`6acf62803`, №1564), поэтому сначала влил
`origin/p274-carina-sweep` в свою ветку. Конфликты (`check/methods.nv`, `emit_c/emit_expr.nv`,
`emit_c/emit_place.nv` — импорты, `novac-surface.baseline`) сведены. Слияние «как есть» сразу
открыло №1524 заново: обход sweep в `emit_expr.nv` спрашивал шелл по голому ИМЕНИ, находил
`..._method_cap` и перехватывал `v.cap(100)` у второй перегрузки (`shell_overload_test` красный).
Поэтому разрешение конфликта и есть объединение:
- `c_overload_symbol` (`sem/mangle_instance.nv`) строится от `shell_method_symbol` — по строке
  `_consume_` для поглощающего получателя необобщённого типа, иначе `c_method_symbol`, затем
  суффикс перегрузки. `Ctx @instantiates` спрашивает эту же дверь — значит, `consume` отвечает
  верно в `handed_bodies.nv`.
- Обход в `emit_expr.nv` (`shell_sym`/`shells`) снят. Решает `@body_ours`, печатает
  `c_overload_symbol`.

Обе стороны: основа от `c_method_symbol` → `consume_shell_method/pos_1` красный (clang);
вернул — зелёный. Базы поверхности сложены: builtins 64+1=65, sem 323+4=327, обе хроники.

№1558 КОРЕНЬ: суффикс перегрузки получали только экземпляры обобщённых записей; у остальных
получателей шелл спрашивался по имени, и вторая перегрузка уходила в первую:
`sb.append(n)`, `s.contains('e')`, `s.starts_with('h')` — check 0, clang шесть ошибок аргумента.
Порядковый номер считался по ВЗЯТЫМ строкам: отброшенная harvest ранняя перегрузка сдвигала
номер вниз. Кроме того, при проверке нашлись ещё две вещи:
- все примитивы делили один ключ головы `-1`, и `int @max` считал `u8 @max` своей ранней
  перегрузкой;
- `extern "nova"`-методы оракул называет по другому правилу. Моя первая редакция дала три
  ложных отказа меры (`load` ×2, `max`) — поймано мерой и исправлено до коммита /
ФИКС: `sem/mangle_instance.nv`:
- замеренная схема для необобщённых получателей — записи, примитива, newtype
  (`Nova_StringBuilder_method_append__nova_int`, `Nova_str_method_contains__nova_char`,
  `Nova_Vec_method_ptr__mut`);
- сумма и семейство суммы со второй перегрузкой получают написание, которого нет ни у одного
  C-идентификатора: по голому имени спрашивается только первая;
- extern-метод — правило `external_registry.rs`: при ≥2 перегрузках `_<имя типа последнего
  параметра>`, без параметров — голое имя (`Nova_AtomicInt_method_fetch_add_int`, `..._load`).

`check/methods.nv` спрашивает шелл через `c_overload_symbol`. `sem/harvest.nv` +
`sem/handed_bodies.nv`: номер считается по ОБЪЯВЛЕНИЯМ, отброшенное занимает место
(`@note_dropped`), ключ головы хранится, у примитива свой ключ /
ПРОБЫ: программа `plain_overload` (append ×5, contains ×2, starts_with ×2, срез `str`):
после слияния — clang; после — SAME. Пробы прошлых сдач (gen-body-*, shell-overload-*,
coalesce-*, ice-split-at) — SAME /
ПРИЁМКА: да. Шелл спрашивается по выбранной перегрузке на любом получателе; по голому имени —
только первая перегрузка (или extern без параметров, как у оракула); неизмеренное написание
никогда не «несётся» и уходит в отказ по имени. Ограничение схемы: `coerce_shell_symbol`
(`sem/coerce.nv`, sweep) спрашивает шелл через `shell_method_symbol` без суффикса — у
`#coerce`-методов параметров нет, и перегрузок там не встречено /

ФИКСТУРЫ: `plain_overload/pos_1` — байт-в-байт да; заодно зелёные `consume_shell_method/pos_1`
(sweep), `shell_overload`, `generic_body_instance`, `instance_value_arg`, `self_ctor`.
