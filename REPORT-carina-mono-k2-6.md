## №1647 (задание 6)

D478 п.2: имя варианта, видимое из двух и более сумм, выбирается по ОЖИДАЕМОМУ типу позиции. Файл со
своими `Ok`/`Err`/`None` всё равно видит варианты `Result`/`Option`. `variants_named` считал сначала
множество файла — одно имя, — и ожидание спрашивалось только при числе больше одного. Поэтому `Ok(n)`
под `-> Result[int, int]` становился `Verdict` (E7301 там, где оракул компилирует).

- `variant_sum_count` в `sem` — сколько сумм объявляет имя, и файла, и поданных.
- Ожидание спрашивается при ЛЮБОМ числе видимых: вызов (`calls.nv`) и голое имя (`exprs.nv`).
- Аргумент с именем, которое объявляют несколько сумм, откладывается до выбора параметра — та же
  дверь №1565, что у голого `None`. Решётка до решения проверки типа ему не даёт.
- Объявленный тип биндинга становится ожиданием инициализатора.
- Поверхность sem 342 → 343 (у тебя на сведённом — 345).

Фикстуры `variant_by_expect/pos_1` и `pos_2` (сам пример D478 с `Color`/`Signal`) — байт-в-байт. Каждая
из пяти частей по отдельности краснит `pos_1`.

## №1650 — тихая приёмка неверного кода (K1)

**Класс:** статический вызов выбирал строку по имени и написанной арности и ЕДИНСТВЕННУЮ строку брал без
сверки аргументов. Проверка типа и режима жила только в `fits` резолвера, а статический вызов её не
спрашивал.

**Починка.** `resolve` получил дверь `args_misfit`: биндинг (D102), тип (`type_admits` / семья литерала) и
режим (P14). Она возвращает номер слота, который не подошёл, либо `ARGS_UNBOUND`, либо `ARGS_FIT`.
`fits` оставил себе проверки формы вызова и спрашивает её. Статическая дверь (`@static_args_fit`)
судит строку после типизации аргументов:
- биндинг — словами `@binding_refusal`, общими для всех видов вызова;
- тип — E7301 с именем параметра;
- режим — как говорит P14.

Именованный аргумент теперь считается написанным. Экспортов resolve 23 → 26.

**Клетки** (модульный тест `pipeline/static_args_test`, у каждой — подходящий контроль): статический метод
программы, поданный (std/оболочки), обобщённый (судится конкретный слот, параметр типа — нет),
именованный аргумент. Фикстуры:
- `static_args/neg_1` — `Tb.row("s")`;
- `static_args/neg_2` — `k: "s"` по имени;
- `static_args/pos_1` — байт-в-байт.

Проба в обе стороны: сверка выключена → оба neg приняты, три теста красные.

**Регрессия, которую я внёс и исправил** (`0bc92c986`). Голова указателя в `type_admits` требовала
одинаковую изменяемость с обеих сторон. Тело `Vec[T] @cap` из std зовёт
`RawMem.copy_n_nonoverlapping(src *T, ..)` с полем `*mut T`, и `vec_new/pos_4` с `vec_own/pos_1` стали
отказывать. Сверку всех фикстур перед пушем `240f311a6` я не прогнал — это мой промах, теперь гоняю её
перед каждым пушем. По P8 (02-types.md) `*T` принимает `*mut T`, обратное запрещено. В обе стороны:
строгая голова → `vec_new/pos_4` отказ; возвращено → байт-в-байт.

## №1652 — зарезервированное слово как имя

**Класс шире одного слова и одной позиции.** Лексер Карины отдаёт ИДЕНТИФИКАТОРОМ 29 слов, которые оракул
делает ключевыми: `with`, `effect`, `priv`, `true`/`false`, `loop`, `spawn`, `throw`, `select` и другие.
Часть из них Карина читает по написанию в их собственной позиции. При этом любая позиция имени
объявления их принимала.

- Один список `RESERVED_WORDS`/`is_reserved_word` в `builtins` (ключевые слова оракула минус свои
  ключевые слова Карины).
- Одна дверь в парсере, `@push_name`/`@take_name`: зарезервированное слово уходит в собственную
  Err-ветку, курсор идёт дальше. Стоит на позициях: имя свободной функции и тип получателя, имя
  метода/статического метода, параметр, биндинг, константа и модульный `ro` (с квалификатором и без),
  тип, вариант, метод протокола, операция эффекта, образец.
- В `check` слово отказывается в самом себе, словами оракула: «expected identifier, got `X`». Это
  языковой отказ, не подмножество.

Фикстуры `reserved_name/neg_1` (`fn Tab.with`), `neg_2` (`fn throw`), `neg_3` (параметр `select`): по
одному отказу, оракул отказывает на том же слове. В обе стороны: список отвечает «нет» → все три приняты.

**Не покрыто — имя ПОЛЯ записи.** `priv` приходит туда по написанию как маркер поля в std (`priv buf str` в
`CharsIter`), и у читателя поля своя форма. Норма запрещает и это: **D83** («Keywords строго запрещены
как identifier'ы», закрывает Q-keywords-as-fields, 03-syntax.md). Это следующий шаг класса — в коммите
назван упрощением с этапом (274.5 P3).

## НОВОЕ ДЛЯ РЕЕСТРА

1. **Обобщённый статический вызов, который ПОДХОДИТ, падает ICE в экземпляре.** `Gbx.make("t", 2)` при
   `export fn Gbx[T].make(v T, n int)` → «mangle: a substituted type the checker never interned». Было
   и до №1650 (проверено с выключенной сверкой). Тест `static_args_test` поэтому судит обобщённую клетку
   двумя неподходящими вызовами.
2. **D102: обязательный параметр по имени.** Карина отказывает `g(h: 3)` для `fn g(h int)` («has no
   default value, so it is passed positionally»), оракул принимает. Норма D102 («параметр с дефолтом —
   keyword-only») про обратное направление молчит. Вопрос, а не дефект.
3. **Биндинг с зарезервированным словом:** Карина отвечает «expected identifier, got `loop`», оракул —
   «expected pattern, got `loop`». Отказывают оба, слова разные.
