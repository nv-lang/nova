# REPORT-p1179 — дубли объявлений верхнего уровня (№1179, №1183, №1186)

Ветка: `p1179-duplicate-decls-ggzfpi` (от `origin/integrate` 04e9fe2d1, слита с `origin/integrate` ed90b4073).
Облачная сессия, 2026-09-30.

ВОСПРОИЗВЕДЕНИЕ:
№1179 -> на базе жив: два peer-файла с одним именем отказывают без импорта во всех трёх режимах,
но молчат, как только имя объявлено и в единице импортированного модуля; `ro X = …` не судится
вообще ни в одном режиме (нового в строке не было).
№1183 -> жив дословно: проба `699-collision-positive-control/import-silences.py` на базе — без
импорта, `vec`, `duration` отказ; `import std.encoding.serde` — rc=0, `PASS: 1`, и `build` тоже
собирает. Свойство (замер помощника подтверждён): глушит совпадение имени с объявлением в единице
импортированного модуля, `serde` — носитель.
№1186 -> посылка «test не видит никогда» не подтвердилась (как и поправка в строке): без импорта
`test` отказывает; с совпавшим именем молчит (`PASS: 1`), то есть наследует дыру №1183. Отказ по
чужому адресу `Duration.ZERO` на этой базе не воспроизвёлся — там было молчание.

КОРЕНЬ: единственный отказ жил в цикле регистрации `check_module_impl` (types/mod.rs), который
идёт по `module.items` — своим объявлениям вперемешку с влитыми импортами. Повтор имени прощался,
если имя есть в импортированном модуле (`collect_prelude_visibility().merged_from_imports`,
«codegen-only merge, user wins»), без вопроса, с кем столкновение — с импортом или со вторым своим.
`Item::Let` (модульное `ro`) вовсе не проверялся на повтор.

ФИКС: `compiler-codegen/src/types/duplicate_decls.rs:125` (`check_duplicate_decls`) — одна
проверка, зовётся из `check_module_impl` (types/mod.rs:1369) до цикла регистрации, поэтому её
проходят `check`, `build` и `test`. Судит только объявления компилируемого модуля
(`is_entry_module`, `items_here`), сгруппированные по физическому модулю (имя + папка, D78), —
импорты в вердикт не входят. Тип/эффект/протокол/`const`/`ro` — одно пространство; функции и
методы — дубль только при той же сигнатуре D84 (`same_overload_sig`, общий с циклом регистрации,
две копии сравнения удалены); не дубль — `priv(file)`-близнецы (D307) и два одинаковых `extern`.
Код `[E_DUPLICATE_DECL]` (подходящего не было), текст по-английски называет оба файла и модуль,
note — место повтора. Ошибка стоит на ПЕРВОМ объявлении: раннер читает `nova:expect` только из
входного файла.

КЛЕТКИ (род × импорт × режим, до -> после; «с импортом» = имя совпадает с объявлением в единице
`std.encoding.serde`):
- тип: без импорта check/test/build отказ -> E_DUPLICATE_DECL; с импортом молчание/молчание/собрано -> E_DUPLICATE_DECL ×3
- эффект: без импорта отказ -> E_DUPLICATE_DECL; с импортом check молчит, test/build — чужой codegen-отказ `record_schemas` -> E_DUPLICATE_DECL ×3
- протокол: как эффект
- функция: без импорта отказ -> E_DUPLICATE_DECL; с импортом молчание/молчание/собрано -> E_DUPLICATE_DECL ×3
- метод: отказ во всех 6 клетках (до и после), теперь с кодом
- константа: без импорта отказ -> E_DUPLICATE_DECL; с импортом check молчит, test/build — C-ошибка `redefinition` -> E_DUPLICATE_DECL ×3
- `ro`: молчание во всех 6 клетках -> E_DUPLICATE_DECL ×6
Итого: 42 клетки, до фикса своим отказом говорили 22, после — все 42 одним кодом.

ОТКРЫТО:
- Новая строка реестра `| TBD |` (🟡 К2): функция и тип с одним именем в одном модуле — вердикт
  зависит от порядка (`fn Node` выше `type Node` — отказ, наоборот или в разных peer-файлах —
  молчание). Новая проверка этот вид не судит: спека (D29, D84) не говорит, законна ли пара.
  Страж `check-registry-entry-shape` краснеет на `TBD` до присвоения номера — так задумано.
- Дубли внутри ИМПОРТИРОВАННОГО модуля в единице потребителя не судятся (судятся, когда
  компилируется сам модуль) — осознанно, чтобы вердикт не зависел от набора импортов.
- Полный повтор замера по conformance после слияния не делался (std/novac/examples повторены: 0).

ВОПРОСЫ ИНТЕГРАТОРУ:
1. Номер кода: введён новый `E_DUPLICATE_DECL` (среди существующих подходящего не нашлось).
   Варианты: оставить / переименовать. Рекомендация: оставить — прежний отказ был без кода,
   `E_METHOD_REDEFINITION` значит другое (переопределение метода из std/импорта).
2. Пара «функция + тип/константа/`ro`» под одним именем (строка TBD): разрешена или дубль?
   Рекомендация: дубль в одном модуле — вызов `Node(1)` и литерал типа `Node` делят одно имя,
   D29 требует одного смысла имени; решение нужно в спеке до фикса.
3. Имя ветки: задание называло `p1179-duplicate-decls`, среда облачной сессии разрешает пуш только
   в `p1179-duplicate-decls-ggzfpi`, туда и запушено. Реестр ссылается на фактическое имя.
