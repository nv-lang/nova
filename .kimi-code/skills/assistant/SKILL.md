**Это АДАПТЕР, а не вторая копия.** Источник правды роли — файл
`.claude/commands/assistant.md` в корне репозитория: он один хранит правила,
замеры и порядок входа (в этом репозитории две копии одного текста расходятся
молча — прецеденты названы в `AGENTS.md`). Прочитай исходник ЦЕЛИКОМ
инструментом Read и следуй ему, заменяя механики Claude Code на механики
Kimi Code CLI по таблице ниже. Если адаптер и исходник разойдутся — верен
исходник, а адаптер правится.

Первой строкой хода — **местное время** командой `date "+%H:%M"`, и ПЕРЕД
КАЖДЫМ сообщением, несущим время, — `date` ЗАНОВО (правило из `/flow`;
помощник пишет больше всех датированных сообщений).

## Таблица подстановок (Claude Code → Kimi Code CLI)

| В исходнике | В этой сессии |
|---|---|
| slash-команда `/assistant` | этот скилл, вызов `/assistant` |
| `/peers`, `ListAgents`/`SendMessage`, `session-card.sh`, контрольный вопрос «кто тут помощник?», «скажись обоим окнам» | **недоступны** — из Kimi Code нельзя писать соседним Claude-окнам. Очередь у двух окон спрашивается ЧЕРЕЗ ПОЛЬЗОВАТЕЛЯ этой сессии: формулируй сообщения обоим окнам в докладе, и пользователь перенесёт их. Все правила переспроса (таймер, форма, «выбирайте сообща») сохраняются — адресатом становится пользователь |
| **таймер переспроса** — фоновый `sleep 300 && echo …` (`run_in_background`), снятие через `TaskStop` | ставь одноразовый **CronCreate** (`recurring: false`) на +5 минут с промптом «5 минут прошло — переспроси оба окна (через пользователя)»; при раннем ответе снимай через **CronDelete**. Альтернатива — `Bash run_in_background` с `sleep 300`, снятие через TaskStop. Это ровно тот фон, который роли РАЗРЕШЁН исходником; прочий фон по-прежнему запрещён |
| режим `/loop` с динамическим шагом | в Kimi Code его нет — используй cron-напоминания (CronCreate) как назначение следующего пробуждения |
| команды `/save`, `/stop` | запись в `docs/dev/prompts/assistant-handoff.md` инструментом Edit (раздел СВЕРХУ под шапкой, дата из `date`); при остановке — также `docs/.sessions/handoff-<id>.md` (id — из `/status`) |
| команды `/integrator`, `/carina`, `/flow`, `/delegate`, `/peers`, `/id` | читай одноимённый файл `.claude/commands/<имя>.md` как текст инструкций и следуй ему вручную |
| визитка `nova-session-assistant.card` как адресат записки | механизм визиток недоступен; записка — всегда `docs/dev/prompts/assistant-handoff.md` независимо от ветки |
| суб-агенты по `/delegate` — только со слова давшего задание | то же: инструмент Agent без явного разрешения того, кто дал задание, НЕ вызывать |
| `allowed-tools` во frontmatter исходника | не действует; разрешения — permission-режим сессии (`/permission`) |

## Рабочее дерево

Помощник работает в **своей ветке в своём worktree рядом с репой** (ветка под
задачу: `registry/…`, `guards/…`, `docs/…`). Главное дерево и `main` — не
трогать. Если сессия запущена в чужом дереве — работай через
`git -C <свой worktree> …` либо попроси пользователя перезапустить сессию
там.
