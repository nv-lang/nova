# 140: решения владельца по рабочим вопросам (фиксация для маршрутизатора)

Дата: 2026-11-04. Источник: дословный пересказ держателя временной роли
интегратора (сессия 137), чат с владельцем 2026-11-04; возражений владельца
к зафиксированным пунктам не внесено.

## 1. Модульные тесты уезжают в carina-oracle-compat (qmw1zf7cg6fe3)

Критерий 1 задачи читать так: в carina-gate — только то, что Карина умеет
сама. Модульные тесты novac зависят от тест-раннера, который существует
только в Оракуле; до появления команды test у самой Карины (follow-up
«команды build/test в Карине») они живут в carina-oracle-compat. В
carina-gate модульный уровень держат oracle-free замены: check-novac-self-
accepted (один `novac check` по всему novac/src, сверка отвергнутых с базой
в обе стороны) плюс корпусные стражи (no-panic, diag-schema, no-cascade,
fixture-expect). Нечестного «модульного теста» без раннера не существует —
маскировка запрещена.

## 2. Сид: публикация carina-v0.2.2 (qmw20r28mxjek)

Владелец дал слово опубликовать существующий объединённый бинарь поколения
135 как carina-v0.2.2: провенанс — собран цепочкой от 0.2.1 без Оракула,
хеши в уликах задачи 135. Механика публикации и постановка тега — отдельное
слово владельца (теги в репозитории nova — только владельца). После
публикации carina-gate перепинается на v0.2.2: bootstrap по HEAD, критерий
«сид собирает исходники ветки» станет буквально выполним; pinned-путь
(3729abcc, второй checkout) остаётся fallback-формой для старых сидов.

## 3. Поправка по существу

Разработка novac — только поколениями от последнего сида. Оракул — только
в carina-oracle-compat (дифференциал, чужие модульные тесты): измерение
совместимости, не инструмент сборки ни в одном обязательном гейте. Идея
«собрать v0.2.2 с main через Оракул» отозвана как обесценивающая 0.2.1 —
не выполняется.

## 4. Норма от дрейфа (дословно владельцем, чат 137, 2026-11-04)

Механизмами, не обещаниями: (1) обязательный oracle-free контур (carina-gate:
сид собирает управляемое дерево → b1 → b1 повторно эмитит байт-в-байт → b2 →
текстовые стражи и смоук); после включения в обязательные любой дрейф
управляемого дерева от возможностей последнего сида — красный CI на каждом
пуше; (2) страж дрейфа: диф main (novac/src, std/src) против управляемого
дерева последнего сида публикуется списком, растёт только бэкпортами с
номером задачи; (3) публикация сида — часть приёмки волны, локальные
поколения не копятся; (4) Оракул остаётся в своей будке (carina-oracle-compat),
плюс follow-up задача «команды build/test в Карине» убирает оставшуюся
зависимость; (5) правка novac/std, уводящая managed-дерево от последнего
сида без заявленного follow-up, не проходит review интегратора на вливание.

Текст этой нормы идёт в docs/dev в потоке 140/приёмки, не отдельной
бюрократией.
