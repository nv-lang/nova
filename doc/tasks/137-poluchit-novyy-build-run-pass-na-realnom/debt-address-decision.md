## Конкретный следующий шаг

Оформить в Followups плана 274.14 две открытые адресные работы внутри его существующего предмета: live backtick slots по D467 и generic/overloaded implicit empty tag args по D48. Использовать свободные идентификаторы этапов после проверки коллизий, указать точные двери отказов, условия снятия и приёмку §5; явно записать границы и открытые вопросы либо их отсутствие. Это документирование долга, не начало его реализации и не закрытие формы по спецификации. Второй полный инвентарь отказов не создавать.

После появления действительных открытых заголовков исправить два новых сообщения на эти точные адреса. Для отсутствующего shell-вектора переиспользовать существующий `no_shell_vec_msg`, как предложил исполнитель, а не добавлять дублирующий третий отказ. Не маскировать тексты ради счётчика.

До решения о конкретном пересмотре `refusals` снять фактический новый счёт, оба бессрочных счётчика, сохранить поимённое сопоставление baseline parser-fallback → именованные отказы, негативы каждой новой двери и результаты затронутых прежних PASS тем же бинарём. Не писать 148 или 147 заранее по арифметике. При доказанном отсутствии ухудшения интегратор оформит измеренный пересмотр с летописью; этот документ не заменяет сами измерения и не является разрешением вливания.

Целевой факт `string_literals` build+run PASS требуется сохранить полным логом/точным stdout и provenance исходник→C→exe. Готовый runner без результатов не считается проверкой.
