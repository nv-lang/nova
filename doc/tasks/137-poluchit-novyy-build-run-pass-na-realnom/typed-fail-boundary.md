# 137: граница ремонта №1948 после снятия переходной паузы

## Вывод локализации

Новая семантика не нужна: `!!` уже определён D85. Однако одного исправления postfix-разбора недостаточно. Для нормативного исполнения ошибочной ветви требуется **отдельный большой участок реализации типизированного Fail**, отсутствующий в source-language пути Carina. Объём ниже установлен чтением кода и ранее выполненными пробами; это не оценка длительности и не результат нового прогона. Новый build+run PASS по-прежнему отсутствует.

Норма повторно изучена через spec-reader. Самостоятельно сверены `check/check.nv:147–152`, `check/consume_flow.nv:914–927`, `lower/lower_coalesce.nv:101–148`, `check/try_rules.nv:66–137`, `emit_c/emit_never.nv:42–54`.

## Точная граница: что готово и что отсутствует

| Дверь | Что готово | Что требуется для `!!` |
|---|---|---|
| syntax/tree | Postfix `?`/`??` в `parse/expr.nv:331–350`, узел Try | Отдельная форма `!!`, корректная цепочка postfix; сейчас ни этой формы, ни source-language throw/interrupt нет |
| container/check | `type_try` получает payload через `coalesce_payload`, различает Option/Result, получает `result_error` | Успешный тип T и ошибочный E для `Fail[E]`; существующая проверка `?` опирается на return-тип функции и не годится вместо эффектного контракта |
| container/lower | `lower_try`: один `lower_place` в temp, проверка тега, извлечение payload, FailureExit для Result | Ошибочная ветка должна выполнить typed throw вместо `set_err(ret_place)` и `ir.ret()`; весь оператор не является never, только ошибочная ветвь |
| typed effect contract | Эффектные имена и обычные обработчики существуют | `check/check.nv` прямо сообщает, что эффекты не проверяются; текущая сборка имён превращает `Fail[E]` в `Fail`. Нужна совместимость E, private inference и проверка exported-контракта/локального перехвата |
| typed throw / ABI | Shell уже вызывает `nova_throw_typed` для IoError (`shell.tpl.c:6959`) и имеет верхний fail-frame main | Генерация payload и type-id для ошибки операнда, включая SerError носителя; это не готовая дверь эмиттера. Поиск не обнаружил `NOVA_TID_*SerError` в shell. Само наличие struct SerError не подтверждает наличие typed-id |
| cleanup / handlers | `lower_try` умеет FailureExit; `ir_with` ставит/снимает обычные обработчики; runtime interrupt-frame существует | Корректный exceptional выход с cleanup и восстановлением scope. `consume_flow.nv:918–927` явно отказывает failing cleanup: «novac compiles no Fail». Обработка generic Fail/interrupt требует отдельного покрытия; `CalleeEffectOp -> never` также имеет известную незавершённую дверь №1818 |

Последние строки таблицы **не означают, что весь долг effects должен войти в один фикс**. Они запрещают объявить общую поддержку `!!` на основании одного успешного `json_encode`. Возможное подмножество надо заранее назвать, законные неподдержанные контексты явно отвергать, а нормативные проверки принятых контекстов сохранить. Проектировать это подмножество без согласования расширения здесь не начал.

## Минимальный согласуемый объём продолжения

1. Syntax/tree и container check/lower для Result и Option с однократным вычислением; неверный операнд — адресный отказ.
2. Source-language typed-failure дверь: E/payload/type-id, never ошибочной ветви; совместимый Fail-контракт и вывод private, без обязательного изменения сигнатуры исходного main.
3. Зафиксированная граница handler/cleanup-контекстов: либо нормативная реализация, либо честный subset-отказ до эмиссии. Нельзя исполнять их молча как обычный return или panic.
4. Проверки обеих ветвей: payload/type сохраняются при перехвате, Option бросает RuntimeNoneError, side-effect операнда ровно один раз, cleanup/восстановление обработчика на выходе, exported без нужного эффекта отвергается. Контроли `Err => "error"` для этого непригодны.
5. Пересборка локального combined source → C → exe без Oracle; саботаж; исходный `serde_fs_build.nv` без правок должен дать build+run с ожидаемым JSON. Затем соседние носители и прежние PASS в согласованном адресном наборе.

Готовые образцы для переиспользования: `novac/fixtures/try_result/pos_1.nv`, `serde_encode/pos_1.nv`, `with_lit/pos_1.nv`; ни один не доказывает typed Fail. Нормативные Result/Option/Fail-примеры — `spec_tests/conformance/d85_bang_requires_fail_pos.nv` и отрицательные соседи.

## Решение до расширения

Локализация завершена; правок компилятора и новых тяжёлых прогонов после снятия паузы нет. Интегратору передаётся именно эта граница: работа перешла бы от parser fallback к typed Fail в checker, lowering и emitter с эффектным контрактом и exceptional cleanup. Без согласования этого объёма реализацию не расширять. Нового D-блока не требуется, пока сохраняется D85/D61.
