# Задание: Проверять чистую установку релизных архивов Oracle на Windows и Linux

Заказчик: nova-opencode.integrator; задание собрано плагином из полей canopus_spawn.
Репозиторий: проект nova-opencode, ветка main. Дата задания: 2026-11-11.
Источник: слова владельца с датой — раздел «Чего хочет владелец».

## Чего хочет владелец

Рекомендация интегратора: «В релизный гейт добавить установку из чистого архива на Windows/Linux, проверку версии и hello без скрытого локального кэша». Ответ владельца: «согласен» (2026-11-11, текущий чат nova-opencode.integrator).

## Что нужно

1. Добавить проверяемый fail-closed гейт готовых Oracle release archives: Windows/Linux содержат действительно исполняемый CLI, заявленная версия совпадает с --version, manifest соответствует байтам, hello собирается и исполняется после распаковки в изолированном окружении без неявного seed/toolchain cache. Явные необходимые зависимости допускаются только если документированы и проверены. Сначала прочитать release/test/guard конвенции и действующие package scripts; использовать существующие механизмы, не параллельный выпуск. Не требовать от Oracle build другого backend, если он документирован; фиксировать фактическую provenance.

## Критерии приёмки

1. Windows ZIP и Linux TAR проверяются независимо с реальными распакованными assets; отсутствие CLI/ELF/PE или неверная структура даёт понятный ненулевой отказ, не PASS. 2. Для каждого реально запускаемого CLI --version совпадает с переданным ожидаемым Oracle patch; неверное 0.1.0 в пакете 0.1.2 отвергается. 3. Изолированные HOME/LOCALAPPDATA/cache в scratch, без наследования локальных seed; установка, build и run hello проверяют точный stdout/native exit. Внешние compiler/seed/Python зависимости названы явно, отсутствие обязательной зависимости — fail-closed. 4. SHA256SUMS сверен с bytes; точный source/asset provenance и команды отражены в отчёте. 5. RED/GREEN: убрать compiler из пакета, подменить версию, скрыть необходимую внешнюю зависимость; каждый тест должен отвергнуть нужную причину, затем восстановленный контроль проходит. Не заменять доказательство пустым фильтром или compile failure теста. 6. Проверка подключена к подходящему релизному маршруту/CI по действующим конвенциям; неподдерживаемая платформа обозначается как NOT RUN, не зелёный релиз. 7. Адресные тесты, стражи, независимая приёмка exact SHA; никаких публикаций/тегов. Полный дорогой прогон только через очередь проекта.
