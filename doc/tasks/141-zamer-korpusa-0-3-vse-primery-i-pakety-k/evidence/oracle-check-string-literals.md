## Расхождение

Сырые байты stdout (фрагмент вокруг многострочного backtick-литерала,
источник выкачан с CRLF):

```text
carina: b'\r\nfirst\r\nsecond\r\nthird\r\na tagged'
oracle: b'\r\nfirst\r\r\nsecond\r\r\nthird\r\na tagged literal'
```

Карина: значение литерала `first\nsecond\nthird` (CRT text mode разворачивает
`\n` в `\r\n` на печати). Оракул: значение `first\r\nsecond\r\nthird`
(байты исходника как есть; CRT добавляет второй `\r`). Остальной вывод
идентичен, оба run rc=0. Размеры stdout: Карина 183 байта, оракул 185.

## Норма

D467 §7 (`spec/decisions/03-syntax.md`): п.4 «`\r\n` в теле нормализуется
в `\n`» стоит внутри нумерованного списка «Для БЛОЧНОЙ формы (открывающий
backtick, сразу перевод строки)». Литерал в примере — `` `first⏎second⏎third` ``,
открывающий backtick НЕ сразу за переводом строки, то есть не-блочная
многострочная форма; для неё §7 норму не называет. Обоснование §7 («значение
константы не должно зависеть от того, как файл выкачали») говорит за
нормализацию, но выбор нормы — решение спеки.
