### ТОЧКА И ФИКС (критерий 2)

Единый корень №1484/№1705 доказан МИНИМИЗАЦИЕЙ на самой Карине (какая
позиция доносит ожидание, какая нет), не совпадением текста: анонимный
RecordCtor типизируется позицией (`Checker.value_expect`); позиции
выставляли ожидание, но анонимная ветвь `@type_expr` сознательно молчала
(«позиция сама запишет»), никто не записывал — первый вопрос решётки
(`typed_args`, фолд ветки, `type_of` константы) падал ICE.

Фикс (норма — СПЕЦИФИКАЦИЯ, не оракул): D478 (список позиций ожидания,
«биндинг с объявленным типом»), D489/D491 (литерал/значение позиции с
известным типом), D55 (payload — позиция с записанным типом), D52
(newtype-конструктор принимает представление,
spec/decisions/02-types.md:445–451). Язык не меняется — D-блок не нужен.
- `binds.nv`: ОДНА дверь `@settle_anon_ctor` — судит конструкцию
  существующим `@judge_record_ctor` против конкретного ожидания и ЗАПИСЫВАЕТ
  тип на узел; `ro r = { x: 9 }` без типа — громкий E2-b.
- `exprs.nv`: анонимная ветвь идёт в дверь.
- `type_of.nv`: анонимная ветвь сначала читает запись (правило Index/IfExpr).
- `calls.nv`: newtype-аргумент получает ожидание-основу в предоходе вызова.
- `option_rules.nv`: payload-слот → тип слота; обобщённый слот → связка из
  ожидания позиции; «голый» слот → громкий E2-b.
- `const_types.nv` + `module_values.nv`: записанный тип константы
  (`@written_const_type`) — ожидание инициализатора в обеих дверях.
