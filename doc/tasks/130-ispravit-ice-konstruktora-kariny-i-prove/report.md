# Отчёт задачи 130 — ICE анонимного конструктора Карины (класс №1484/№1705) и проверка поставляемого сида

РЕПРО: подтверждён и минимизирован (не по совпадению текста — корень доказан
механикой). На pinned B1 (`novac.exe` sha256 `824bf597…`, source
`3729abcce42ec2d94efc898ec6eafe91ff6210d5`) ВСЕ формы дают exit=2 и дословно
`E_NOVAC_ICE novac/src/check/type_of.nv:632 «(novac bug, not yours): check:
anonymous constructor without a spread»`: №1484 (`0 => { x: 9 }`, тело ветки
match), №1705 (`Wrap({ n: 1 })`, аргумент newtype-конструктора), аргумент
вызова с параметром-записью (`take({ n: 1 })`), аргумент обобщённого варианта
с ожиданием позиции (`Ok({ x: 9 })` при `-> Result[Rec, E]` — полярис-форма
nova-http `Ok({ lower: … })`), модульная константа с записанным типом
(`const StatusCode.OK StatusCode = { code: 200 }` — http/status.nv, 18 штук,
носитель всех 12 входов), «голый» биндинг, неверное поле, не-запись-параметр,
элемент массив-литерала. Команды и дословные выводы —
`evidence/red-probes-pinned-b1.txt`. Норма: оракул `nova check` принимает все
формы; `nova build` строит и запускает носители (p1484 печатает 9,
`Ok({x:9})` печатает ok).

ТОЧКА (единый корень №1484 и №1705): анонимный RecordCtor типизируется
позицией (`Checker.value_expect`); позиции выставляли ожидание, но анонимная
ветвь `@type_expr` сознательно молчала («позиция сама запишет»), никто не
записывал — и первый же вопрос решётки (`typed_args` ключа вызова, фолд
ветки, `type_of` у константы) падал ICE. Константы — двойная дыра: ожидание
гасилось в обеих дверях (`@type_const_decl`, `@type_module_value_at`), а
записанный тип лежал в `@written_const_type`, не в `type_id` регистра
(там изначально `no_ty`).

ФИКС (одна дверь + доставка ожидания; `novac/src/check/`):
- `binds.nv`: `@settle_anon_ctor` — ОДНА дверь для всех позиций: читает канал,
  судит конструкцию существующим `@judge_record_ctor` против конкретного
  ожидания (`@concrete(@value_expect)`), ЗАПИСЫВАЕТ тип на узел; отказ
  конструкции ничего не пишет. Плюс маршрут биндинга: `ro r = { x: 9 }` без
  типа — громкий E2-b (оракул выводит анонимный тип записи — вне
  подмножества), имя связывается отравленным.
- `exprs.nv`: анонимная ветвь RecordCtor идёт в дверь (вместо SILENT-OK).
- `type_of.nv`: анонимная ветвь сначала ЧИТАЕТ запись (правило соседних армей
  Index/IfExpr/ArrayLit); ICE остаётся последним resort'ом; само-именованный
  литерал 632→644 (нижние литералы перенумерованы).
- `calls.nv`: аргумент newtype-конструктора получает ожидание-ОСНОВУ
  (`representation_of`) в предоходе вызова (№1705); перенумерован литерал
  902→936.
- `option_rules.nv`: аргументы варианта получают тип своего payload-слота;
  обобщённый слот связывается из ожидания позиции (`Ok({x:9})` для
  `-> Res[Rec]` — та же связка, что делает инстанс-дверь); «голый» слот с
  анонимной конструкцией — громкий E2-b (`ANON_CTOR_GENERIC_MSG`).
- `const_types.nv` + `module_values.nv`: записанный тип константы
  (`@written_const_type`) — ожидание инициализатора в обеих дверях.

САБОТАЖ (дословно в evidence/): ДВА прохода. (1) `@settle_anon_ctor` опустошена
→ пересборка (B1 emit 3729+фикс → clang) → носители снова ICE дословно
(`cycle_red.log`); восстановлена → GREEN (`cycle_green.log`). (2) тот же

стороны каждого прохода — на одном и том же дереве, отличается только тело
