## Часть 7 — `T` из ожидаемого типа

**Корень.** Карина типизировала аргументы вызова БЕЗ ожидания. Из литералов выходило
`T = int`, и дверь возврата отказывала E7301.

**Правка** (`check/arg_expect.nv`):
- `@expected_ids` — позиция вызова связывает параметры типа через объявленный возврат строки
  (`slot_binding_in`, та же дверь, что у вывода из аргументов);
- `@param_expect` — ожидание аргумента: у конкретного параметра его тип, у голого `T` —
  связанный;
- `@type_arg_expecting` — аргумент типизируется под этим ожиданием. Голый литерал берёт тип
  через дверь диапазона, у значения-`if` его берут литеральные ветки.

Свободный вызов, метод и статический вызов спрашивают это до типизации аргументов, когда
строка одна; набор перегрузок ожидания не даёт.

В `@deduce_from_args` слот, который не закрепил ни один аргумент, берёт привязку позиции.
Типизированный аргумент, закрепивший слот иначе, побеждает: `idf(n)` при `n int` в `-> Row`
даёт `T = int` и прежний отказ возврата.

**Клетки** (`pipeline/return_test`):

| клетка | Карина | оракул |
|---|---|---|
| свободная обобщённая, ожидание из возврата | проходит | `1` |
| статическая обобщённая (переданное объявление) | проходит | `2` |
| метод | проходит | `3` |
| голый литерал `idf(7)` | проходит | `7` |
| параметр типа, которого нет ни в одном аргументе (`fn nothing[T](n int) -> Option[T]`) | проходит | — |
| ожидание из параметра ВНЕШНЕГО вызова (`take(idf(if ..))`) | проходит, `5 8` | **отказ E7301** — см. вопрос 1 |
| привязка с записанным типом (`ro b Row = idf(if ..)`) | **недоступна**: «a declared local type is not compiled yet (E2-b3)» | **отказ E7301** — см. вопросы 1 и 2 |
| КОНТРОЛЬ: без ожидания `T` из аргумента (`ro c = idf(6)`) | `T = int` | `6` |
| КОНТРОЛЬ: типизированный `int` не становится `Row` | отказ | принимает молча — см. вопрос 3 |

**Проверка в обе стороны:**
- аргументы без ожидания — тест красный;
- привязка позиции выключена в выводе — красная клетка «параметр не в аргументах»;
- правка возвращена — зелёный.

**Пробы:**
- `expected-type-param` — оракул `1 3 7 6`, база E7301 ×3, теперь SAME stdout;
- `expected-type-param-outer-arg` — оракул отказывает, Карина печатает `5 8`.

**Тест части 6 заменён.** Он утверждал обратный вердикт для статического вызова (`T = int`,
E7301). Теперь вместо него клетки этого правила.

**Статическая обобщённая в СВОЁМ модуле** проверена только на переданном объявлении. В своём
файле `fn Tb.id[T]` упирается в другой отказ: «this type declares several static methods of
this name and arity». Похоже на двойную регистрацию своего статического метода — зона
статических перегрузок mono-k2, не трогал.

## Найдено по ходу

1. **ICE на базе — исправлен** (`5902cf35b`). `println(idf(if c { 5 } else { 0 }))` проходил
   проверку и падал в `emit`: «expression kind outside the subset». Причины две:
   - `@lower_println` выносил из аргумента-вызова только `??`/`?`, но не значение-`if`;
   - `@hoist_sealed_args` не заходил в аргумент, который сам вызов.

   Падает и с чистыми `int`. Тест `return_pos_test`; проба `println-nested-if-arg`: оракул
   `5 7 8 9`, база `emit rc=2`, теперь SAME stdout. Нужна строка реестра (К2, ICE) — `№TBD`.

2. **Моя ошибка части 6 — исправлена** (`d7766360a`). Языковой отказ `E_MUT_ARG_NOT_MUTABLE`
   для value-временного судил каждый слот, в том числе ПРИЁМНИК. Поэтому `mk().bump()` и
   `Pv { n: 4 }.bump()` получали ложную языковую ошибку на законном коде (D32). Теперь приёмник
   исключён, и для него стоит прежний отказ подмножества до выноса №1630. В `main` с частью 6
   это уже приехало, так что исправление нужно влить.

## Вопросы интегратору

1. **Оракул против D489 на двух клетках.** Аргумент внешнего вызова (`take(idf(if true { 5 }
   else { 0 }))` при `fn take(r Row)`) и привязку с записанным типом (`ro b Row = idf(if ..)`)
   оракул отвергает E7301: «cannot pass `int` as argument», «cannot assign value of type `int`».
   Вывод `T` из ожидаемого типа он делает только в позиции возврата. По D489 обе позиции знают
   тип. Нужна строка реестра на оракул; Карина в первой клетке уже ведёт себя по спеке.
2. **Привязка с записанным типом у Карины** заблокирована пробелом подмножества: объявленный
   тип локала, `ro b Row = …` → «a declared local type is not compiled yet (E2-b3)». Клетку
   не закрыл. Это отдельная волна — назначишь?
3. **Оракул молча принимает `fn b(n int) -> Row => idf(n)`**: выводит `T = Row` из возврата и
   передаёт `int` как `Row`. По D491 значение числового типа неявно тип не меняет. Похоже на
   строку реестра на оракул. Карина отказывает.
4. **Строки реестра:** ICE `println(f(if ..))` (Карина, исправлено); частое «several static
   methods» на своём обобщённом статическом методе (mono-k2?).
