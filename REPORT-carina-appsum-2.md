## Находки

**Д6 — `x is Sum.Variant` не разбирается (существовал до волны, не мой класс).** На базе, на
ПРОСТОЙ сумме:
```
type Shape enum Dot | Box(int)
fn main() {
    ro s = Box(2)
    ro a = s is Shape.Box
    println(a)
}
```
Карина: «novac did not parse this…» (запасной путь парсера); оракул принимает. Проверка
(`type_ref_last_ident`) квалифицированную форму уже читает — не хватает разбора. Класс:
грамматика `is` уже, чем D54.

## Вопросы интегратору

1. **Исключение `*_test.nv` из правила 5 стража mangling-one-way.** Расширенная регулярка поймала
   `assert(c_callable(ctx, row, …).contains("novac_fn_…"))` в `sem/mangle_test.nv`. Я исключил
   тесты из правила 5 по тому же доводу, по которому они уже исключены из правила 4: утверждение
   пришпиливает написание, а не решает по нему. Варианты: (а) оставить так; (б) судить и тесты,
   а утверждения о написании переписать на равенство целому имени (правило 4 его в тестах
   разрешает). Рекомендую (а): (б) меняет форму двадцати с лишним утверждений ради того же смысла.
2. **`CLayout` — запись-значение, возвращаемая из `c_layout` на каждый `c_type`.** Поведение и C
   побайтно те же, а цена — одна запись-значение на вызов. Если в бюджете итерации
   (`novac-iteration-cost`) это будет заметно, пусть тяжёлый прогон это покажет: раннер его
   пропускает, сам я его не гонял (запрещено). Решить: нужен ли замер стоимости до слияния.
   Рекомендую замер в ближайшем тяжёлом прогоне, без отдельного шага.
