## 1. `check/static_call.nv` — утечка ожидания

Правка — сохранить, сбросить и вернуть `@value_expect` вокруг аргументов, как у свободного
вызова и метода.

**Где утечка видна.** Только на обобщённом статическом вызове: в теле `-> Row`
`=> Tb.id(if m { 1 } else { 0 })` выводило `T = Row`. После правки `T = int`, и возврат
отвергается E7301 — как у обобщённого МЕТОДА той же формы.

**Тест.** `return_test`. КОНТРОЛЬ — тот же вызов в `-> int` компилируется.

**Вопрос 1 ниже.** Оракул эту форму ПРИНИМАЕТ: он выводит `T` из ожидаемого возврата. D489 о
таком выводе молчит.

**Находка попутно — нужна строка реестра.** Статический вызов с ОДНОЙ подходящей строкой не
сверяет типы аргументов с параметрами вовсе. `Tb.row("s")` при `fn Tb.row(h int)` Карина
принимает без диагностики (`check/static_call.nv`: после записи типов аргументов сразу
`record_callee`, суда по типу нет). Оракул такое, по всей видимости, отвергает. Строку заводишь
ты, `№TBD`, класс К1/К3 — твоя оценка. Правку не делал: сужение статических перегрузок по типу
аргументов — зона mono-k2, а суд по типу для одной строки — тот же механизм.

## 2. Временное значение в `mut`-параметр

**Правило** — по твоему разбору:
- D84 «`mut` — только изменяемое место» выбирает МЕЖДУ перегрузками;
- что принимает единственный `mut`, решает D326-ревизия Р3/Р6.

**Реализация** (`check/mut_args.nv`, `@lookup_call`) — поиск в два захода:
1. Строгий ключ: ось режимов выбирает, как раньше; временное идёт в `ro`-форму, если она есть.
2. Только если ничего не подошло — тот же поиск, где временные значения КУЧЕВОГО типа взяты
   как место.

Подробности:
- Value-тип: отказ стал языковой ошибкой (E_NOVAC_LANG) с `E_MUT_ARG_NOT_MUTABLE` и Р3 в
  тексте. Параметр типа, указатель или нетипизированный слот получают прежний отказ.
- Дверь поиска ничего не строит — `no-alloc-in-lookup`: ключ строит отдельная функция, только
  на втором заходе.

**Тест** `refusal_test`: `fill(Bag { n: 1 })` компилируется, `inc(3)` при `mut n int` даёт
E_NOVAC_LANG / E_MUT_ARG_NOT_MUTABLE. КОНТРОЛЬ: `ro`-привязка кучевого типа по-прежнему не
место.

**Изменён существующий контроль — смотри внимательно.** `fluent_self_test` (#1540) утверждал,
что `c.fresh().set(4)` — кучевое временное в `mut @`-приёмник — отвергается. Приёмник — нулевой
параметр той же оси, и по уточнённой спеке это законно. Оракул принимает и исполняет. Контроль
теперь утверждает приём, value-контроль живёт в новом тесте. Тест не ослаблен ради
прохождения: он приведён к норме, уточнённой сегодня. Если считаешь иначе — верну.

**Оракул попутно.** Value-временное в `mut @`-приёмник (`mk().set(3)` при `type Pv value`)
оракул на `check` пропускает и падает в C: `member reference type 'NovaValue_Pv *' is a
pointer`. По Р3 должен быть `E_MUT_ARG_NOT_MUTABLE` — похоже на строку реестра (оракул).

## 3. `BuiltinType.ALL` — по классу

**За отказом стояли два разрыва:**
- переданные значения модуля не регистрировались вовсе — только константы с литералом;
- видимость имени, привязанного к типу, спрашивалась по полному написанию `Kind.ALL`, а импорт
  называет `Kind`. Поэтому ЛЮБАЯ такая константа или значение другого модуля программы была
  невидима, литеральная `Kind.MAX` тоже.

**Снято:**
- значение модуля с ЗАПИСАННЫМ типом регистрируется без инициализатора: ячейка и вычисление —
  владельца, тип читается по тексту объявления, канал не нужен;
- видимость имени, привязанного к типу, судится по типу (`seen_by_name`);
- `const_type_at` переехал в `sem` — одна дверь для `sem` и `check`, база sem 341 → 342;
- эмиттер объявляет, вычисляет и упорядочивает только значения своей единицы;
- в `builtins.nv` тип `BuiltinType.ALL` записан.

**Тест** `module_value_test`. КОНТРОЛЬ: значение без записанного типа — «unknown name».

**Проба** `handed-module-value`: оракул `a b 2 5`, база — отказ ×3, теперь проверка проходит.

**Остаток со сроком** — `docs/dev/simplifications.md`, запись части 6:
- переданное значение без записанного типа и переданная константа с нелитеральным
  инициализатором — до ступени 0.3, или раньше, если мера их покажет;
- межъединичная ячейка (у владельца `static`, в имени нет модуля) — тем же шагом, что первая
  линковка двух единиц Карины.
