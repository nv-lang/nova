## D46 — ОСТАНОВЛЕНО, нужен ваш выбор

Из двух отказов на слитом дереве **остался один**.
- `main.nv:189` `!` — **закрыт k1 в main** (часть 5: отказ был каскадом от `nm.ends_with(...)`,
  которого нет в оболочке; `@report_if_unary_needs_protocol` молчит на отравленном операнде). Проба:
  `!ok(n)` и `!s.contains(..)` проходят.
- `types/types.nv:152` — `@args[a..b] == want`, **`[]TyId == []TyId`**. Оракул выпускает вызов
  std `Vec[T] @equal` (`Vec____nova_int_method_equal(a, b)`), то есть D46 сводит `==` на векторе к
  методу. У Карины для этого есть готовый механизм «неявной операции над вектором» (`vec_op_c`:
  символ оболочки, иначе экземпляр из тела std). Но все три источника `equal` для элемента
  `TyId` закрыты:
  1. **тело std** (collections/vec/protocols.nv:30) — `if unsafe { mine.view_at(i, |a|
     theirs.view_at(i, |b| a != b)) }`: замыкания `|a|` Карина не разбирает («did not parse»), плюс
     `view_at` нет в объявлениях и `unsafe` в позиции условия (проба: прямой вызов `a.equal(b)` на
     `[]int` и на `[]Tid`, временный бинарь с открытым `unsafe` — 8 отказов в экземпляре `equal`);
  2. **оболочка, стёртый вектор** — `Nova_Vec_method_equal(Nova_Vec*, Nova_Vec*)` в
     emit_c/shell.tpl.c:5995 — ЗАГЛУШКА, `return (nova_bool){0}`; вектор с элементом-newtype Карина
     ведёт как стёртый (`Nova_Vec_method_push__void_p`), так что путь через неё — тихий K1;
  3. **оболочка, конкретный экземпляр** — есть для `u8`, `str`, `[]u8`, `DirEntry`, нет для
     newtype; растить probe — зона mono-k2 (оболочка).

Варианты (решать вам):
- **(а)** сделать D46-диспатч `==`/`!=` на векторе через `vec_op_c` сейчас, с запретом
  стёртой заглушки (отказ по имени, если символ стёртый). Карина начнёт верно сравнивать `[]u8`,
  `[]str`; носитель types.nv:152 сменит отказ «protocol» на отказ в экземпляре `equal`
  (замыкания) — **мера не изменится**;
- **(б)** отдать носитель тому, кто ведёт замыкания/`view_at` в экземплярах std (или mono-k2 —
  конкретный экземпляр в оболочке);
- **(в)** оставить отказ как есть до замыканий.

Я бы взял (а): класс «`==` на векторе через `@equal`» закрывается честно, а остаток становится
названным отказом с точной причиной, а не обобщённым «protocol dispatch».
