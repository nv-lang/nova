# REPORT-p1343 — мономорфы обобщённых свободных функций по объявлению

Ветка `p1343-generic-overload-mono`, база `origin/integrate` c775a975d, перед сдачей слита `origin/integrate` 04e9fe2d1 (все проверки повторены после слияния).

КОРЕНЬ: реестр мономорфов обобщённых свободных функций `mono_fn_decls` держал одно объявление на ГОЛОЕ имя (last-wins, `emit_c.rs` pre-pass и forward-decl), а символ мономорфа строился от имени (`free_fn_c_name(name)` + подстановка). Две обобщённые перегрузки одного имени при одинаковых аргументах типа давали один символ, и тело бралось по имени — вызов уходил в чужую перегрузку (носитель: `free=2,2` вместо `free=1,2`), остальные пары падали в C-компиляторе.

ФИКС: `compiler-codegen/src/codegen/emit_c/generic_overload_mono.rs` (новый дочерний модуль, правила №1097, ключ — span объявления):
- `note_generic_free_fn` — каждое обобщённое объявление хранится отдельно (запись по имени в `mono_fn_decls` оставлена для прочих читателей);
- `mono_fn_decl_for_call` — вызов берёт объявление, выбранное чекером (`resolved_callees[call_id]`), прежний порядок Facet-B D307 — запасной путь; заменил `facetb_mono_fn_decl_for_call` в обоих местах (`emit_call` и вывод типа результата `infer_call_ret_c`);
- `mono_fn_base_c_name` — у имени с ≥2 обобщёнными объявлениями база символа своя: `decl_base_c_name(f)` + `__ov<i>` (i — порядок объявления среди обобщённых объявлений имени; прецедент — `__ov` у методов). Имя с одним объявлением — байт-в-байт прежнее (`nova_fn_…solo____nova_int`);
- `note_mono_fn_instance` / `mono_fn_decl_for_instance` — сток worklist берёт объявление, записанное для ЭКЗЕМПЛЯРА, а не для имени.
В `emit_c.rs` — только вызовы: регистрация (2 места), сток worklist, `register_mono_instance`, база имени у вызова, одно поле. Схема имён мономорфов у пар изменилась: `nova_fn_<mod><name>__ov0____nova_int` / `__ov1____nova_int` (сгенерированный C проверен: 22 разных символа у 5 пар, столкновений нет).

ОТКРЫТО:
- №TBD 🔴 К1: `mut x T` у обобщённой свободной функции не доходит до вызывающего — мономорф берёт параметр по значению (`bump[T](mut x T, v T)` печатает 1, конкретная `bumpi` — 3; пара по режиму тоже). От №1343 не зависит (одинаково до и после). В строке записано «БЛОКИРУЕТ ТЕГ: ДА» по букве решения 2026-08-16 о тихих мискомпиляциях — при нумерации нужно поднять `blockers` в `registry-routes.baseline`.
- №TBD 🟡 К2: перекрывающиеся обобщённые перегрузки `f[T](x T)` / `f[T](xs []T)` при аргументе-массиве — чекер не выбирает и не отказывает, кодоген сверяет стёртые C-типы: `ty([1,2,3])` попадает в `[]T` случайно, `ty(["a","b"])` — CODEGEN-FAIL. Поэтому в фикстуре форма `[]T` вызвана турбофишем.
- Имена `mfd_a`/`mfd_b`/`helper` вошли в корпус `spec_tests`: в мега-CU появляются две одноимённые обобщённые функции из разных модулей. Точечно зелено; мега-CU мне запрещён — его прогонит интегратор.
