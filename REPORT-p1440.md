# Отчёт: №1440 + №1446 — гигиена C-имён в оракуле

Ветка: `p1440-c-name-hygiene-p8eh5s` (среда сессии назначила ветку с суффиксом;
в брифе — `p1440-c-name-hygiene`). Слита с `origin/integrate`, все проверки
повторены после слияния.

**ПРАВИЛО ЭКРАНИРОВАНИЯ:** имя из исходника пишется в C как `nv_` + имя, если
это ключевое слово C, макрос платформы из списка, фиксированный член структуры
кодогена (`ctx`, `schedlink`), ВСЕ-ЗАГЛАВНОЕ имя от двух символов или имя,
начинающееся с `_`, `nv_`, `nova_`, `Nova`, `NOVA` (кроме собственных
пространств компилятора `_nv_`, `_nova_`, `_at_`, `__`); иначе — как есть.
Отображение инъективно: всё экранированное начинается с `nv_`, и всякое имя на
`nv_` экранируется (раньше `long` и `nv_long` обе давали `nv_long`).

**КОРЕНЬ:** у кодогена была дверь `mangle_field_name`/`is_c_keyword`, но она
ловила только ключевые слова и стояла только на полях записей. Локали,
параметры, захваты (поля ctx у spawn, `parallel for`, замыканий и обработчиков),
поля vtable протоколов и эффектов, варианты сумм и их поля, параметры операций
уходили в C сырыми. Отсюда три вида столкновений:
- макросы Windows (`near`, `far`, `IN`, `OUT`, `ERROR`) — это №1440;
- макросы Linux (`linux`, `unix`, `errno`);
- служебные имена кодогена: указатель окружения `_c` (№1446), `_co`, `ctx`, `schedlink`.

**ФИКС:** `compiler-codegen/src/codegen/emit_c/c_name.rs:129` — единственная
дверь `c_ident` (её старое имя `mangle_field_name` оставлено обёрткой). Через
неё проведены все места, где имя из исходника становится C-токеном:
- в `emit_c.rs` — вызовов двери стало 194 вместо 69: определение и использование, поля, union-члены
  вариантов, `payload.<поле>`, vtable, ctx и env, `#define` и `#undef` захватов,
  параметры обычных, моно- и стёртых функций, связывания `for`, `match`, `select`,
  кортежей и `.value`, локальный и экспортный `const`, сокращённая запись полей;
- в `emit_c/emit_detach.rs` — захваты `detach`.

ABI-имена (`extern "C"`, `#export`, структуры рантайм-типов, рантаймовые vtable
эффектов) через дверь не идут. Функции и методы и раньше получали
модуль-квалифицированные символы.

**ОТКРЫТО:**
1. Сайты кодогена, не покрытые ни фикстурой, ни 147 клетками, возможны: кодоген
   большой, и имя пользователя пишется в C во многих местах. Правка всегда одна —
   обернуть имя в `c_ident`.
2. Список макросов неполон по построению: Linux снят с `clang -dM -E` над
   `nova_rt.h`, Windows — по заголовкам. Новый макрос добавляется одной строкой
   в `PLATFORM_MACROS`.
3. Имена функций libc как локали (`memcpy`, `printf`) не экранируются. Локаль
   перекрывает функцию только в своей области, и сломается лишь вызов этой
   функции из сгенерированного кода внутри той же области. Клеток с таким
   падением не нашёл.
4. Пользовательское имя, начинающееся с `_nv_`, `_nova_`, `_at_` или `__`, не
   экранируется: эти пространства кодоген синтезирует сам и читает через тот же
   путь `Ident`.
5. Тест крейта, переполняющий стек, — существовал до ветки (см. КРЕЙТ). В реестр
   не заносил: класс не мой, и нужна сверка, кто его ведёт.
6. По ходу работы общий CU conformance один раз собрался случайно: фильтр
   `record` захватил мега-тест. Он нашёл два места (локальный `const` и
   consume-выражение), оба починены. Повторно мега-CU намеренно не гонял.

     - (а) да — новая диагностика плюс D-блок;
