**КОМУ ЭТА КОМАНДА: интегратору.** Владелец говорит её, когда хочет занять облачную сессию Claude (Cloud Session) задачей для релиза Карины. Промпт владелец копирует туда сам, и её ответы приносит назад тоже он. Заведена 2026-09-30 по слову владельца («добавь команду: выдать задачу внешнему агенту Claude Session»). В тот день так были выданы и сданы №895 и №1395+№1405, и эта команда записывает, что при этом выяснилось.

Первой строкой хода — местное время командой `date "+%H:%M"`.

## Чем облачная сессия отличается от своего фонового агента

- **Нет связи.** Ни `SendMessage`, ни соседних окон: всё, что ей нужно знать, стоит в промпте, а вопросы она пишет в отчёт.
- **Нет этой машины.** Она не видит локальных путей, scratchpad, незапушенных коммитов, локальных веток и бинарей. Работает в клоне с GitHub, на Linux, зависимости ставит как CI.
- **Видит только `origin`.** Если задача опирается на то, что лежит в `main` незапушенным, сначала выкладывается `main` (или задача откладывается). Иначе сессия будет чинить старое дерево.
- **Среда может назначить своё имя ветки** (например, `claude/<случайное>`). Промпт велит пушить в названную ветку. Если она всё же пушнула в назначенную, ветку принимаешь по факту.

## 1. Выбор задачи

Порядок — как у [`/load-background`](load-background.md): что держит `novac-gate` или меру 0.2 Карины → очередь 274.10 → 274.11 → дефект оракула только с доказанной связью с Кариной. Поле реестра `БЛОКИРУЕТ ТЕГ` — про тег оракула, который не выходит; по нему не выбирают (правка 2026-10-01 по вопросу владельца). **Перед выдачей — САМОПРОВЕРКА из [`/load-background`](load-background.md) (шесть вопросов), её строка `Самопроверка: …` стоит в докладе владельцу вместе с промптом — и в ней ОБЯЗАТЕЛЬНО «почему быстрее и насколько» (вопрос 6: механизм и число с названной базой, либо честное «не измерено, потому что …»).** Дополнительные требования, потому что облачная сессия работает вслепую:
- задача самодостаточна: замер, проба и место уже есть в строке реестра или в `docs/plans/repro/`;
- нет развилки, которую решает владелец. Если она возможна, промпт обязан назвать её и велеть остановиться;
- её не ведут ни ты, ни Карина, ни помощник, ни другая облачная сессия (проверь ветки `git branch -a`, строку реестра, письма соседей).

## 2. Промпт — обязательные разделы

Пиши по-русски, первым абзацем — роль и задача одной фразой. Образцы, на которых всё это проверено: промпты №895 и №1395+№1405 (2026-09-30). Разделы:

1. **Роль и связь:** «ты — облачная сессия в клоне github.com/nv-lang/nova; связи с интегратором нет; вопросы — в отчёт, владелец перенесёт». Сливает в `main` интегратор, сессия сдаёт ветку.
1а. **Связь с релизом Карины:** одна-две фразы — какую ступень порядка задача снимает и факт из самопроверки (число меры 0.2, строка 274.10, пункт 274.11 или место в `novac/src`) и ожидаемый выигрыш из её вопроса 6 (сколько снимает и с какой базы). Без этого раздела промпт не отдаётся.
2. **Сначала прочитай:** `AGENTS.md` (с оговоркой, что правила о времени, worktree и соседних окнах к ней не относятся); строку реестра — только её, `grep -n '^| N '` (файл 2 МБ); пробы из `docs/plans/repro/…`; нужные D-блоки и абзацы планов с номерами строк.
3. **Где работать:** `git fetch origin && git checkout -b <ветка> origin/main`, `git submodule update --init --recursive` — как CI (`submodules: recursive`): одного libuv мало, Карина без `gc` и `libatomic_ops` не собирается (замер kim-code, 2026-10-03, задание №1665). Коммиты — `git commit -s` БЕЗ строки `Signed-off-by` в файле сообщения, иначе трейлер выходит дважды. Сборка — как в CI (`.github/workflows/nova-gate.yml`, `crate-tests.yml`). Если не собирается — вопрос в отчёт, без обходов.
4. **Что сломано:** замер своими словами, с формой кода и текстом отказа. Если уже известен корень или провалившийся узкий фикс — назови, чтобы не повторяли.
5. **Приёмка по классу:** клетки, проба в обе стороны на одном дереве, фикстуры в `spec_tests/…` с префиксом номера. Требования: `emit_c.rs` не растёт (`arch-ratchet`), новый код — в дочерние модули; правка — в канале чекера, а не заплаткой.
6. **Развилка — остановись и спроси:** какая именно и что сделать до остановки (закоммитить замеры и закончить).
7. **Как гонять:** точечные прогоны, `RUST_MIN_STACK=134217728` для крейта. Запрет: мега-CU, полный `nova test`, `gate.sh`, `gate-novac.sh`. Пробы — во временном пакете вне репы, с образцом `nova.toml`.
8. **Реестр:** `ИСПРАВЛЕНО В ВЕТКЕ <ветка>`, прежний статус — в «Статус был:», поле статуса одно, стражи `check-registry-single-verdict` и `-routes` перед коммитом, греп маркеров конфликта в одной команде с коммитом. Строку, которой в клоне ещё нет, не заводить — абзац в отчёт.
9. **Сдача:** перед сдачей `git fetch origin && git merge origin/main` и повтор проверок; `git push origin <ветка>` без `--force`, `main` и метки не трогать; `REPORT-<тема>.md` в корне последним коммитом и его текст в финальном сообщении. Форма:

```
КОРЕНЬ: … / ФИКС: <файл:строка — фраза> / КЛЕТКИ: <клетка -> до / после> / ФИКСТУРЫ: … /
КРЕЙТ: compiler-codegen --lib <прошло>/<упало> / ХРАПОВИК: emit_c строк <n> (база — arch-ratchet.baseline) /
КОММИТЫ: … / ОТКРЫТО: … /
ВОПРОСЫ ИНТЕГРАТОРУ: <каждый: что решить, варианты, рекомендация и почему; или «нет»>
```

Промпт сохрани в scratchpad (`prompt-<тема>.md`) и отдай владельцу целиком, одним блоком для копирования.

## 3. Когда сессия сдала работу

1. `git fetch origin <ветка>`; прочитай `REPORT-*.md` и дифф. Приёмку делаешь ты: отчёт — сырьё, не вердикт.
2. **Ответ на её вопросы** — одним блоком для копирования, по пунктам её вопросов, так, чтобы его можно было переслать без твоего контекста.
3. Слияние в `main` — как любой чужой ветки: сообщение слияния называет корень и приёмку; `REPORT-*.md` убирается отдельным коммитом; строка реестра закрывается `[MERGED-AS: <слияние>]`; открытая часть заводится своей строкой.
4. **Удалять её ветку на origin — только после пуша слияния** (облачная сессия сама справедливо отказалась удалять ветку, влитую лишь локально). Удаление — после слова владельца, данного на эту ветку.
5. Если сессию можно занять дальше — следующий промпт по этой же команде.
