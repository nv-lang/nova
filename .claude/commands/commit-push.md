Реши, что из трёх — коммит, пуш, синхронизация с `main` — сейчас ВОЗМОЖНО и УМЕСТНО, и
сделай ровно это: $ARGUMENTS

Правила — из `AGENTS.md` (Git) и `docs/dev/rules-for-agents.md`; здесь — порядок решения
и команды целиком. Ветка — своя (`main` принадлежит интегратору). Команда ничего не
делает «на всякий случай»: каждое из трёх действий сначала получает вердикт, и в докладе
стоит вердикт по каждому, даже если действие не понадобилось.

## Шаг 0. Вердикты — по фактам дерева, не по памяти

Запусти `bash scripts/tools/git-readiness.sh` и прочитай три блока: `COMMIT`, `PUSH`,
`SYNC` — «ВОЗМОЖЕН / НЕВОЗМОЖЕН: причина / НЕЧЕГО / НУЖЕН / НЕ НУЖЕН» со строками фактов
(незавершённое слияние, маркеры конфликта, изменённые и новые файлы, чужой индекс, автор
непушенных, возраст последнего вердикта гейта относительно HEAD, отставание от
`origin/main`, сдвиг стражей/спеки/оракула в `main`). «Невозможен» — не спорить с
причиной, а устранить её или остановиться и сказать. Дальше — уместность, которую скрипт
не решает:

- **Коммит уместен**, когда единица работы ЗАКРЫТА и это доказано (тест, страж, фикстура,
  строка вердикта — назови её), и правка статуса плана едет тем же коммитом. **Не
  уместен**: посреди правки («половина», красные тесты), «чтобы сохранить» — для этого
  есть worktree, коммитов-заготовок не делаем; чужие правки и черновики «по слову» — не
  твои. Незакрытая работа при передаче окна не коммитится, а описывается в передаче.
- **ПУШ КОПИТСЯ, КОММИТЫ — НЕТ** (владелец, 2026-09-03: «реже пушить, каждый пуш стоит
  полного гейта»). Коммит по-прежнему на каждую закрытую единицу работы — дробность
  истории не трогаем; копится ПУШ, потому что гейт висит именно на нём и занимает машину
  на 20–40 минут. Норма: несколько закрытых волн → ОДИН гейт → зелёный → пуш немедля.
  Гнать раньше — только если (а) ветку ждёт другое окно и сказало об этом, (б) правка
  язык-меняющая и нужна интегратору сегодня, (в) накопилось столько, что разбор
  возможного отказа станет дороже лишнего прогона. Замер, из которого правило выросло:
  за смену 2026-09-03 гейт прогнан ВОСЕМЬ раз, и пять падений были не по коду
  (протухший оракул, долг охоты, бюджет времени, неполный локальный набор стражей,
  чужая замершая ветка) — платой за привычку «волна → гейт → пуш».
- **Пуш уместен**, когда гейт нужного яруса зелёный на ЭТОМ HEAD (вердикт моложе HEAD —
  скрипт это говорит) и волна или веха закрыта в плане. **Не уместен**: гейт устарел или
  красен (чинить причину, не базу); в реестре строка без номера (гейт формы красен —
  номер даёт интегратор до гейта); слияние меняет язык, а D-амендмента в нём нет; в
  `main` двинули стражей или спеку и синк ещё не сделан — локальный гейт судит не тем,
  чем CI.
- **Синк уместен**: перед началом новой волны; когда `main` двинул стражей, гейт или спеку
  (иначе зелёный локально — красный на CI); по слову владельца («обновись» — влить
  `origin/main` к себе; «синканись» — двусторонне, второй половиной занимается
  интегратор). **Не уместен**: посреди волны на грязном дереве (сначала коммит или
  решение, что не едет); когда отставания нет. После синка, если `main` двинул источники
  оракула, — пересборка `nova-cli` и оболочки `novac` ДО гейта.

Аргумент «только синк» или «только пуш» сужает действие, но вердикты печатаются все три.

## Шаг 1. Коммит

1. **Что едет.** `git status --short` и `git diff --stat`. Раздели изменения на коммиты
   **по природе работы**, а не по времени написания: отдельно — тип работ (правка
   компилятора, документ, инструмент, страж, тест), отдельно — каждый пункт или шаг
   плана, отдельно — каждый дефект (строка реестра и её фикс — один коммит), отдельно —
   каждая задача владельца. Разноплановое в один большой коммит не соединять: такой
   коммит нельзя ни прочитать по заголовку, ни откатить по частям. Исключение — **план:
   документ плана едет целиком одним коммитом** (он читается как одно решение), а подплан
   (`NNN.N-…`) можно отдельным. Правка плана, сопровождающая шаг кода (статус, живая
   строка, критерии), едет вместе с этим шагом, а не отдельно.
   Файлы, о которых владелец не говорил (чужие правки, черновики «по слову»), в коммит не
   входят — назови их в докладе как оставленные.
2. **Новые файлы — `git add <имя>` по одному** (никогда `-A`, `.`, `-u`). Файл, который
   игнорирует `.gitignore`, `git add` отклонит — это не повод для `-f`: реши, где ему
   место, или добавь исключение в `.gitignore` с причиной.
3. **Проверь индекс перед коммитом:** `git diff --cached --stat` — в нём только твои
   файлы этой задачи; чужое в индексе общего дерева — не твоё, `--only` его не возьмёт,
   но увидеть надо.
4. **Сообщение — по-английски, файлом по длинному пути** (не через `B7E3~1`):
   `target/msg-<тема>.txt`. Заголовок ≤ 72 знака в форме `тип(область): что изменилось`;
   тело — почему и чем доказано (строка вердикта, тест, замер). Для правок `novac` —
   строка `Donor:` (законный донор или «none — потому что…»; оракул донором не бывает,
   страж `check-novac-commit-donor` откажет).
5. **Коммит с областью и грепом маркеров конфликта В ОДНОЙ КОМАНДЕ:**
   `grep -rn -E '^(<<<<<<<|=======|>>>>>>>)' -- <файлы> && echo "conflict markers" && exit 1;
   git commit -s -F target/msg-<тема>.txt --only -- <файл1> <файл2>`
   Флаги — до `--`, пути — после (хук `guard-git.py` откажет иначе). Проверь, что
   коммит создался: `git log -1 --format='%h %s'` — «Everything up-to-date» при пуше
   означает, что коммита не было.

## Шаг 2. Синхронизация с `main` (когда вердикт — НУЖЕН и уместен)

Только на чистом дереве. `git fetch origin && git merge --no-ff origin/main`. Конфликты —
руками, по смыслу файла: реестр 221.1 — объединение строк по номеру, в общей строке
побеждает `main`; базы стражей — большее из двух с причиной; документы — обе правки, если
не противоречат. Затем в ОДНОЙ команде: греп маркеров по конфликтным файлам → `git commit
-s -F target/msg-merge.txt` с комментарием `# index-verified: merge origin/main, конфликты
разрешены руками` (хук требует явного слова, потому что коммит слияния берёт весь индекс).
Если `main` двинул источники оракула — пересобрать `nova-cli` и оболочку `novac`
(`scripts/tools/novac-regen-shell.sh`) до гейта. Слияние — отдельный коммит, не смешивать
с работой.

## Шаг 3. Пуш

**Гейт и пуш — одной командой:** `bash scripts/tools/push-after-gate.sh`. Она сама откажет
на грязном дереве и на `main`, проверит автора непушенных коммитов, выберет ярус по путям
(`novac/` → `NOVAC_TIER=push` и основной `loop`; иначе только основной `loop`), запушит с
повтором и напечатает `unpushed: N`. Красный гейт — чинить причину, не базу; пуш без
гейта — только `GATE=none GATE_SKIP_REASON="…"`, и причина идёт в доклад.

## Шаг 4. Доклад

Три вердикта шага 0 и что по каждому сделано; хеши и заголовки коммитов; вердикт каждого
яруса гейта с временем; `unpushed: 0`; что осталось незакоммиченным и почему.

Чего команда не делает: не сливает в `main`, не пушит `--force`, не трогает
`git config user.*`, не добавляет `Co-Authored-By`, не делает коммитов-заготовок, не пушит
слияние, меняющее язык, без спек-амендмента в том же слиянии.
