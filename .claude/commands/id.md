**КОМУ ЭТА КОМАНДА: любому окну.** Свой идентификатор нужен, чтобы тебя позвали и чтобы сессию подняли через `resume`.

Покажи id ЭТОЙ сессии. Коротко, ничего не меняя.

Возьми его машинно, из окружения — не из памяти и **не по времени файлов**: рядом
идут параллельные окна того же проекта, и по mtime легко назвать чужую сессию.
Одна команда, целиком:

```sh
CFG=$(cygpath -u "$CLAUDE_CONFIG_DIR" 2>/dev/null || echo "$CLAUDE_CONFIG_DIR")
F=$(ls "$CFG"/projects/*/"$CLAUDE_CODE_SESSION_ID".jsonl 2>/dev/null)
echo "id=$CLAUDE_CODE_SESSION_ID"; echo "file=$F"; ls -l "$F" | awk '{print "bytes="$5}'; echo "lines=$(wc -l < "$F")"
```

Ответ — три строки: id, путь к файлу истории, размер и число записей.

Если `CLAUDE_CODE_SESSION_ID` пуст — так и скажи: «окружение id не отдало».
Не подставляй вместо него самый свежий файл в `projects/` — это будет чужая
сессия, и ошибка молчаливая.

## ID — НЕ АДРЕС. Сообщение идёт на ИМЯ, и это разные вещи

**По id сессию ПОДНИМАЮТ (`resume`), по имени ей ПИШУТ.** Написать соседу «по id»
нельзя: `SendMessage` принимает имя вида `nova-<две буквы/цифры>`, а не uuid. Поэтому
всякий раз, когда ты отдаёшь свой id, отдавай рядом и своё ИМЯ — иначе собеседник
знает, как тебя воскресить, но не знает, как тебя позвать.

**Имя берётся ТОЛЬКО из `ListAgents` и меняется при каждом перезапуске окна.** Первая
строка выдачи называет эту сессию, остальные — живых соседей. Имя, которого в выдаче
нет, мертво: писать туда некуда и ждать оттуда нечего. Из этого два следствия, оба
проверяются одной командой, а не памятью:

- **своё имя не помнят, его смотрят** — после перезапуска оно другое;
- **чужое имя не кэшируют** — записанное вчера имя роли почти наверняка уже чужое
  или мёртвое.

**Как отправить сообщение — коротко, полностью правила в `/peers`:**

1. `ListAgents` — взять живые имена (и увидеть своё);
2. `SendMessage` с полями `to` (имя дословно из выдачи) и `message`;
3. первая строка сообщения — самодостаточная: у получателя видно только её, и по ней
   он решает, разворачивать ли остальное;
4. ответа НЕ ждать в этом же ходе — он придёт, когда сосед дойдёт до своего хода.

**Кого именно звать, если нужна РОЛЬ, а не конкретное окно:** роль не выясняется ни
именем, ни файлом — её называет само окно контрольным вопросом-ответом. Протокол,
фразы и почему отвечают все, включая «не я», — в `/peers`, раздел «КОНТРОЛЬНЫЙ
ВОПРОС-ОТВЕТ». Здесь только ссылка: две копии одного протокола разойдутся на первой
правке, а расхождение в ФРАЗЕ ломает опознание целиком.

**Форма ответа на чужой вопрос «кто ты / дай id»** — четыре факта, и все машинные:
id (команда выше), имя (`ListAgents`), дерево и ветка
(`git -C <дерево> rev-parse --abbrev-ref HEAD`). Дерево и ветка нужны потому, что
роль по ним ПРОВЕРЯЕМА: фразу можно сверить с фактом, а не поверить на слово.
