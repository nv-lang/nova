## СТЫК neg_2 — причина и починка

**Какая правка main меняет путь:** k1 №1539 «instance bodies walk the subset»
(`check/run.nv`, влито `5ef02caa8`). Тело экземпляра теперь проходит тот же обход подмножества,
что и файл, ДО типизации. В `str @to_ascii_lower` первая же строка — `mut out []u8 = []u8.new(cap: n)` —
объявленный тип локала, который обход отказывал целиком. Поэтому у `neg_2` пропали и
пришпиленная причина (`[]u8.new(cap: n)`, №1457), и обе каскадные пробы за ней (приведение
отравленного `out`, «unused» блок `unsafe`). Типизация до них просто не доходила. Отказ к тому же
врал: имя типа бралось по ПЕРВОМУ листу, и про срез `[]u8` говорилось «no type named `[]` ...
a misspelling».

**Класс и починка** (`38d9160e8`): объявленный тип локала, равный типу инициализатора,
компилируется. `Checker @declared_local_type` читает тип через одну дверь типов (с подстановкой
экземпляра), `@type_bind` типизирует привязку по инициализатору и сверяет с написанным. Обход
пропускает такую привязку и обходит только инициализатор. Остаются за подмножеством, с прежним
текстом: тип, который дверь не читает; видовой квалификатор (`ro x ro T` сохраняет языковую
ошибку №1458); конструктор записи (`ro p Pt = Pt {..}` оракул отвергает как избыточный префикс).
Пара «другой тип / по ожиданию» (`ro b u8 = 5`, `ro b str = 5`) — тот же отказ TYPED_LOCAL, сужен
и датирован (E2-b3). Тип из нескольких листов больше не выдаётся за «опечатку».
Фикстура `neg_2` **не тронута** и снова зелёная (один отказ, пришпиленный текст). Новые фикстуры:
`typed_local/pos_1` (байт-в-байт с оракулом) и `typed_local/neg_1`. Проба в обе стороны: дверь
обхода выключена → pos_1 отказан 4 раза, neg_2 отказан на локале; сверка равенства выключена →
neg_1 принят; возвращено → зелено.

## НОВЫЕ ДЕФЕКТЫ (строки реестра — твои)

1. **Метод оболочки у value-записи вызывается через указатель, а Карина передаёт значение**
   (Карина; есть на main до моих правок — проверено бинарём слияния). `ro it = "abc".chars()`
   `println(it.count())` → clang: `passing 'NovaValue_CharsIter' to parameter of type
   'NovaValue_CharsIter *'` (`Nova_CharsIter_method_count`). Держит std `str @pad_start` /
   `@pad_end` (`@chars().count()`). Похоже на дверь D488 `row_recv_by_pointer` для методов оболочки.
2. **Своя сумма файла с `Ok`/`Err` затеняет `Result` под ожиданием** (Карина). `type Verdict enum |
   Ok(int) | Err(int)` + `fn half(n int) -> Result[int, int] { ... Ok(n / 2) }` → E7301 «cannot return
   `Verdict`», оракул — PASS (выбирает по ожиданию). Попытка спросить ожидание первым дала «node
   typed twice» в других дверях — откатил, не входит в коммиты.
3. **Временное значение в `mut`-ПАРАМЕТРЕ** — `fn h(mut b StringBuilder)`, `h(StringBuilder.new(cap:
   4))`: Карина отказывает по P14 (комментарий `mode_admits` ссылается на D133), оракул — PASS.
   Вопрос, а не дефект: D133 против оракула — кто прав, не читал до вердикта.
4. **`check-novac-shell-freshness` красный на main**: `shell.tpl.c` не равен эмиссии свежего оракула
   (14730 против 14765 строк). Ни оболочку, ни оракул я не трогал.
