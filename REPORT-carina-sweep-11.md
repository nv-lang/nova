## 1. Оболочка несёт то, что зовёт носитель (`2ccde0120`)

- `novac/probe/shell_probe.nv` теперь зовёт `replace`, `ends_with`, `to_str`, `is_dir`; оболочка перегенерирована
  `novac-regen-shell.sh`. **Заодно ушёл дрейф оракула с `fe39a83fe`:** `check-novac-shell-freshness` был красным и на
  main, и на ветке — теперь зелёный (14981 строк, windows + linux). Все 127 положительных фикстур — байт-в-байт на
  новой оболочке; `check-novac-mangle-fixed-point` зелёный.
- **`to_str` в оболочке был и раньше** — как `Nova_NovaArray_nova_byte_method_to_str`: метод, ОБЪЯВЛЕННЫЙ на
  конкретном массиве (`fn []u8 @to_str`), оракул именует по рантайм-имени элемента (`receiver_type_c_ident`,
  emit_c.rs:20991), а Карина спрашивала обобщённую форму экземпляра. Дверь `shell_method_symbol` (sem/coerce.nv)
  теперь смотрит на приёмник САМОЙ строки (`array_ext_c_ident`, sem/mangle_instance.nv) — одна дверь для check и
  emit; имя, которого оболочка не несёт, по-прежнему отвергается через `interop.has`.
- Фикстура `shell_text/pos_1` — байт-в-байт. **Честно про обе стороны:** в одиночном файле без правки краснеет только
  `ends_with` — `replace` и `is_dir` Карина и раньше строила из тел std; их отказы были отказами самосборки (мера).
  `to_str` доказан фикстурой шага 3: без правки имени — три отказа.

## 2. Связанное значение импортируется вместе с типом (`dbe28c27c`)

Носитель: `for bt in BuiltinType.ALL` (sem/collect.nv:233). По D200 (02-types.md) `ro/const Type.NAME` живёт в
пространстве имён типа, а экспортируемая форма — только квалифицированная; импортёр пишет
`import ../builtins.{BuiltinType}`. Дверь видимости (`FnIndex @sees_decl`) искала в списке импорта всё имя
`BuiltinType.ALL`, которого никакой список не несёт. Теперь `Type.NAME` ищется по `Type` (`imported_as`).
Тест `pipeline/assoc_import_test.nv` (с контролем: без импорта не видно); обратная проба краснит тест.
**Мера не изменилась:** носитель — `ro` с НЕлитеральным инициализатором, а такие значения чужого модуля пока не
регистрируются вовсе (`harvest_consts`, sem/harvest.nv) — вопрос 1.

## 3. `??` над `Result` (`fcbbf05b0`, D86)

Вскрыт снятием `to_str` (main.nv:171, sem/mangle.nv:570). Отказ стоял с доводом «значение `Result` здесь не
построить — форму нечем проверить»; довод ушёл: std отдаёт `Result` (`to_str`, `read`). Опускание: Option — прежний
Some-тест (C не изменился); `Result` — проверка головы `Ok` рукава `match` и поле 0 его привязки, никогда не дверь
Option. `x?` над `Result` остаётся отказом со сроком E2-b3 (ветка Err строит `Err` типа тела), текст теперь про `?`
один. Фикстура `coalesce_result/pos_1` (Ok и Err, запасное печатает — короткое замыкание, `??` в аргументе, `read`)
— байт-в-байт. **В обе стороны:** бинарь шага 10 — 4 отказа; `Result` через дверь Option — clang падает.

## 4. `*mut T` → `*T` (`0fefc3450`, D246)

Вскрыт снятием `ends_with`: экземпляр std `Vec[T] @ptr() -> *T => @data` для `[]str` и `[]Node` — E7301. D246
(02-types.md): «`*mut T → *T` авто-сужение; `*T → *mut T` ❌». `ptr_weakens` (check/return_rules.nv) — в возврате и
в присваивании; обратное направление — E7301. Тест `pipeline/ptr_narrow_test.nv` (с контролем обратного
направления); без правки тест красный, на самосборке отказы `ptr` возвращаются (23). **Фикстуры нет, и это
сознательно:** в одиночном файле и оракул, и Карина сворачивают `other.ptr()` в чтение поля — фикстура была бы
зелёной и без правки; прямой `ro p = v.ptr(); p.read_at(0)` роняет C у оракула (строка №TBD ниже).
