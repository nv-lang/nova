## ЗНАЧАЩИЙ `if` — одна дверь с рукавом

Пять носителей — четыре формы: литерал в ветви при записанном типе (lex.nv `byte_at`), вложенный
`if` хвостом ветви (lower_match.nv:397, sem.nv:492), цепочка `else if` значением (mangle.nv:479),
`if` скрутини `match` (typing.nv:249).

- **Одна дверь значения в позиции записанного типа** — `@type_value_at(e, want)`
  (check/return_rules.nv). Правило литерала было только у хвоста функции; теперь его спрашивают и
  рукав (`@type_arm_block_value` и тело-выражение), и ветвь `if`. Попутно: рукав `false => 0` в
  `-> u8` `match` отвергался тем же образом — закрыт той же правкой.
- **Ветвь `if` типизируется дверью рукава** (`@type_branch_value` → `@type_arm_block_value`),
  второй двери нет. Своё у ветви — только отказ «ветвь без значения». Продолжение `else if` — `if`
  значением, рекурсивно; хвостовой `if` с `else` — значение блока и в рукаве, и в ветви
  (`is_value_if`).
- **Позиция скрутини** открыта для `if` в обходе формы (check.nv, `scrut_pos`); продолжение
  цепочки `else if` наследует ЛЮБУЮ значащую позицию родителя (раньше только инициализатор —
  цепочка в аргументе отвергалась).
- **Утечка ожидания в аргументы метода** (найдено по пути, класс): свободный вызов сбрасывал
  `@value_expect` вокруг аргументов, вызов метода — нет. Под хвостом `-> TyId` литералы аргумента
  `if is_mut { 1 } else { 0 }` у `@intern` подгонялись к `TyId` (types.nv:229) — новый отказ на
  первом прогоне; сброс добавлен в methods.nv.
- **lower:** хвост ветви размещается через `@tail_places_value` (тест рукава), продолжение
  `else if` кладётся в тот же временный; вызов, который `println` печатает из дерева, поднимает свои
  «запечатанные» аргументы. Последнее — **ICE и до шага 6**: `println(f(if c { a } else { b }))`
  падал в emit «expression kind outside the subset» (проверено на бинаре до правок); закрыт тем же
  классом.
- **D491** (решение владельца, процитировано интегратором): без записанного типа ветви одного
  типа — оставлено правилом согласия; с записанным — каждая ветвь позиция этого типа — сделано.
  В `spec/decisions/` D491 пока нет, поэтому `Spec:` в коммите — D489.

**Расхождение уровней (для владельца, не решаю):** D489 (02-types.md, «рукав `match` и ветвь
`if` без внешнего типа ... сводятся к более широкой стороне по D433 (R1), литерал без типа берёт
`int`») и D433 R4 («литеральный арм ПРОСТО ПРИНИМАЕТ тип другого арма») разрешают то, что D491 в
пересказе интегратора запрещает («ветви без записанного типа обязаны быть одного типа»). Карина
сейчас по D491: `ro x = if c { b[0] } else { 0 }` (u8 и литерал, тип не записан) — отказ
«must agree». Когда D491 ляжет в спеку, D489/D433 R1/R4 нужно сверить с ним.

## ЦЕЛЫЕ С `_` — одна дверь, отказ снят

Читателей текста целого оказалось четыре, а не пять: `int_lit_value` (cast_pairs.nv) разделитель
уже пропускал. Дверь `literal_digits` (sem/literal_spelling.nv; бывшая `float_literal_c_text`,
переименована — поверхность sem та же, 339) спрашивают оба судьи величины (`int_text_fits`,
`int_text_fits_row`; первый судит и литерал рукава) и C-написание целого. Лексер больше не
отвергает `1_000`; шестнадцатеричный прогон берёт `_` между цифрами (`hex_run_end`), `0x_FF` и
`0xFF_` — отказ. Срок не нужен: отказа больше нет.
