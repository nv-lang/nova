# scripts/ — карта каталога

Структура (реорганизована волной `p231-scripts-docs`, указание владельца
2026-07-27 — «скрипты автопроверок собрать в одной папке»):

| Путь | Что там |
|---|---|
| `scripts/gate.sh` | Точка входа: единый авторитетный локальный гейт. Остаётся на верхнем уровне — на него ссылаются доки, память, (в перспективе) CI. |
| `scripts/package-release.ps1` | Точка входа: сборка Windows-релиза (Plan 221 Ф.2). Тоже верхний уровень — самостоятельный инструмент, не гейт и не разовая миграция. |
| [`scripts/guards/`](guards/README.md) | **Постоянные механизмы принуждения** — стражи, ratchet, мета-страж, установщик, их самотесты. Нельзя удалять не глядя. |
| [`scripts/tools/`](tools/README.md) | **Разовые инструменты волн** — миграции/конвертеры конкретных планов + генератор `docs/plans/STATUS.md`. Могут устареть. |
| [`scripts/claude-hooks/`](claude-hooks/README.md) | Хуки Claude Code (PreToolUse) — принуждение ДО исполнения команды агентом. |
| [`scripts/githooks/`](githooks/README.md) | Общий git `pre-commit` — принуждение НА `git commit`, независимо от того, кто готовил изменения. |

Программа, стоящая за большинством файлов ниже — план
[231 «Выход из цикла точечных фиксов»](../docs/plans/231-bug-cycle-exit.md),
раздел **§0а «РЕЕСТР АВТОПРОВЕРОК»** — это ЕДИНЫЙ ИСТОЧНИК ПРАВДЫ о том,
какие механизмы существуют и в каком они состоянии (документирован /
подключён / покрыт самотестом). **Этот README ссылается на реестр, а не
дублирует его таблицу** — при любом расхождении верь плану 231, не этому
файлу.

## guards/ vs tools/ — как отличить

- **`scripts/guards/`** — код, который проверяет, что кто-то (человек или
  агент) НЕ нарушил конвенцию. Работает многократно, бессрочно, обязан
  иметь самотест (см. [`guards/selftest/README.md`](guards/selftest/README.md)).
- **`scripts/tools/`** — код, который что-то ОДНОКРАТНО мигрировал/
  переписал для конкретного плана (напр. Plan 114, Plan 42, D78 rev-3) и
  дальше почти не запускается — но остаётся в репе как справочный
  инструмент и как задокументированная история решения. Плюс один
  генератор (`gen-plan-status.sh`) — не миграция, но и не страж.

## Куда класть новое

- **Новый постоянный механизм принуждения** (страж/линт/гейт-шаг, который
  должен жить долго и не может молча перестать работать) →
  `scripts/guards/` + шаг в `scripts/gate.sh` (если это код-гейт) +
  **ОБЯЗАТЕЛЬНО** собственный самотест в `scripts/guards/selftest/
  test-<имя>.sh` + строка в реестре [231 §0а](../docs/plans/231-bug-cycle-exit.md)
  В ТОМ ЖЕ слиянии. Соблюдение всех трёх проверяет `scripts/guards/
  check-guard-wiring.sh` (мета-страж) — гоняй его перед коммитом нового
  стража.
- **Разовый инструмент волны** (миграция/конвертер для конкретного плана,
  может устареть) → `scripts/tools/` с докстрингом, явно называющим
  план/волну — без требования самотеста/вызова из `gate.sh`.

## Переезд путей (2026-07-27) — если наткнулся на старую ссылку

До этой волны все скрипты лежали плоско прямо в `scripts/`. Если где-то
(старый коммит, внешняя заметка, память агента) встретится путь вида
`scripts/arch-ratchet.sh`, `scripts/check-*.sh`, `scripts/selftest/...`,
`scripts/hardcode-audit.sh`, `scripts/lint-no-silent-int-fallback.sh`,
`scripts/strict_effects_smoke.sh`, `scripts/tsan_concurrency.sh`,
`scripts/install-guards.sh` — читай его как `scripts/guards/...`. Если
`scripts/gen-plan-status.sh`, `scripts/catb_convert.py`,
`scripts/d78_audit_migrate.py`, `scripts/demojibake.py`,
`scripts/plan114_*.py`, `scripts/cdb_session.sh`, `scripts/stress_bisect.sh`,
`scripts/setup_worktree_p118.sh`, `scripts/migrate_modules_rev3.ps1` —
читай как `scripts/tools/...`. Живые кросс-ссылки в CLAUDE.md/docs/**/
spec/**/compiler-codegen/** починены этой же волной; `docs/history/**`
(архив) и ретроспективные упоминания уже ЗАКРЫТЫХ планов оставлены как
есть — они описывают путь НА МОМЕНТ события, а не текущее расположение.
