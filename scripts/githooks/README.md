# scripts/githooks/ — общий git pre-commit пяти реп

## Что это

Обычный git-хук (`pre-commit`), но **не установленный per-репозиторий
через `.git/hooks/`** — вместо этого пять реп проекта Nova указывают
`core.hooksPath` на этот единственный каталог в главной репе, так что один
файл обслуживает git-операции сразу во всех: коммит в любой из пяти реп
прогоняет ровно этот скрипт. Это часть плана
[231](../../docs/plans/231-bug-cycle-exit.md) трек Д (исполнительный дом —
[231.2](../../docs/plans/231.2-enforcement-infra.md) §1) — машинное
принуждение правил, которые раньше были только текстом в CLAUDE.md/памяти.

## Как ставится

```sh
git config core.hooksPath <путь-до-главной-репы-nova>/scripts/githooks
```

Проверено по факту 2026-07-27 (`git config --get core.hooksPath`) в
четырёх из пяти реп, доступных в этой сессии — все указывают на
`.../nova/scripts/githooks`:

- `nova` (сама главная репа)
- `nova-http`
- `nova-tls`
- `nova-polaris`
- `nova-compress` — по описанию в `docs/plans/231.2-enforcement-infra.md`,
  доступа для проверки в этой сессии не было (не подтверждено вживую).

## Что проверяет [`pre-commit`](pre-commit)

На каждый `git commit` (падение = `exit 1`, коммит заблокирован):

1. **Конфликт-маркеры** — `<<<<<<<`/`=======`/`>>>>>>>` среди ДОБАВЛЕННЫХ
   строк staged-диффа.
2. **Авторство** — `git config user.name`/`user.email` не должны содержать
   `claude`/`anthropic` (урок: 349 коммитов ушли под «Claude Haiku» через
   общий `.git` нескольких worktree, 2026-07-25).
3. **План 232 Ф.3** — правка `spec/decisions/*.md` в staged без правки
   обзорного `spec/<тема>.md` в том же коммите.

## Аварийный обход

Проверено по коду — **обход предусмотрен только для правила 3**:

```sh
NOVA_OVERVIEW_NA=1 git commit ...
```

Для правил 1 и 2 (конфликт-маркеры, авторство) скрипт НЕ содержит
переменной-клапана — они блокируют безусловно. Технически `git commit
--no-verify` пропускает хук целиком (правило 1 и 2 тоже), но
`CLAUDE.md`/`dev-workflow.md` прямо запрещают пропускать хуки без явного
разрешения владельца («никогда `--no-verify`… unless the user has
explicitly asked for it») — это не задокументированный самим скриптом
путь, а отдельное операционное правило поверх него.
