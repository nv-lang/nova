# scripts/githooks/ — git pre-commit, независимая копия в каждой из пяти реп

## Что это

Обычный git-хук (`pre-commit`), включённый через `core.hooksPath` вместо
стандартного `.git/hooks/`. **Важно (перепроверено вживую 2026-07-27,
после более ранней и на тот момент неверной версии этого README):** это
**НЕ один общий файл**, который пять реп проекта Nova дёргают по
абсолютному пути из главной репы — это **независимая копия** одного и
того же скрипта в scripts/githooks/pre-commit КАЖДОЙ из пяти реп, и
`core.hooksPath` в каждой репе — **относительный** (`scripts/githooks`,
без указания на nova). Коммит в nova-http прогоняет КОПИЮ pre-commit,
физически лежащую внутри nova-http, а не файл из главной репы.

Это часть плана [231](../../docs/plans/231-bug-cycle-exit.md) трек Д
(исполнительный дом — [231.2](../../docs/plans/231.2-enforcement-infra.md) §1)
— машинное принуждение правил, которые раньше были только текстом в
CLAUDE.md/памяти. §0а того же плана документирует, ПОЧЕМУ это важно:
«`pre-commit` числился настроенным в пяти репах, а фактически каталог
`scripts/githooks` существовал ТОЛЬКО в nova — в nova-http/nova-tls/
nova-polaris/nova-compress машинной защиты не было вовсе». «Числится
настроенным» ≠ «настроено» — урок, из-за которого появился
[`check-guard-wiring.sh`](../guards/check-guard-wiring.sh) и
[`install-guards.sh`](../guards/install-guards.sh).

## Как ставится

`scripts/guards/install-guards.sh` делает это идемпотентно для всех пяти
репозиториев семьи (см. его код): для каждой репы, где физически уже есть
каталог `scripts/githooks` (копия), выставляет

```sh
git config core.hooksPath scripts/githooks
```

Вручную — то же самое, из корня КОНКРЕТНОЙ репы (значение относительное —
не абсолютный путь в другую репу):

```sh
git config core.hooksPath scripts/githooks
```

Проверено вживую 2026-07-27 (`git config --get core.hooksPath` +
побайтовое сравнение файлов): все четыре доступные в этой сессии репы
(`nova`, `nova-http`, `nova-tls`, `nova-polaris`) настроены именно так и
несут байт-идентичную копию `pre-commit`. `nova-compress` — по описанию
в `docs/plans/231-bug-cycle-exit.md` §0а (коммит `75919d9`), доступа для
проверки в этой сессии не было.

## Следствие независимых копий — держи в уме при правке

Правка `scripts/githooks/pre-commit` **в этой (главной) репе не
распространяется** на копии в nova-http/nova-tls/nova-polaris/
nova-compress автоматически — это НЕ symlink и НЕ submodule. Например,
шапка этого файла была расширена волной `p231-scripts-docs` (см. git-
историю) ТОЛЬКО в nova — на момент написания этого README копии в
остальных четырёх репах всё ещё несут короткую версию шапки. Если правишь
ЛОГИКУ хука (не только шапку) — обязана последовать волна ручного
копирования + отдельный коммит в каждой из пяти реп (как это уже было
сделано при первом появлении хука: nova-http `5257f30`, nova-tls `ac7de2a`,
nova-polaris `411dcf3`, nova-compress `75919d9`) либо запуск
`install-guards.sh` после ручного обновления копий.

## Что проверяет [`pre-commit`](pre-commit)

На каждый `git commit` (падение = `exit 1`, коммит заблокирован):

1. **Конфликт-маркеры** — `<<<<<<<`/`=======`/`>>>>>>>` среди ДОБАВЛЕННЫХ
   строк staged-диффа.
2. **Авторство** — `git config user.name`/`user.email` не должны содержать
   `claude`/`anthropic` (урок: 349 коммитов ушли под «Claude Haiku» через
   общий `.git` нескольких worktree, 2026-07-25).
3. **План 232 Ф.3** — правка `spec/decisions/*.md` в staged без правки
   обзорного `spec/<тема>.md` в том же коммите.

## Аварийный обход

Проверено по коду — **обход предусмотрен только для правила 3**:

```sh
NOVA_OVERVIEW_NA=1 git commit ...
```

Для правил 1 и 2 (конфликт-маркеры, авторство) скрипт НЕ содержит
переменной-клапана — они блокируют безусловно. Технически `git commit
--no-verify` пропускает хук целиком (правило 1 и 2 тоже), но
`CLAUDE.md`/`dev-workflow.md` прямо запрещают пропускать хуки без явного
разрешения владельца («никогда `--no-verify`… unless the user has
explicitly asked for it») — это не задокументированный самим скриптом
путь, а отдельное операционное правило поверх него.
