# Конвенция именования — продуктовые имена и имена артефактов

**Нормативна** (см. [conventions-governance.md](conventions-governance.md)) · создана по запросу
владельца, согласовано 2026-07-23.

Документ отвечает на два вопроса: **как выбирается новое имя** и **какие имена заняты сейчас**.
Имена сущностей внутри кода на Nova (типы, методы, поля) здесь НЕ дублируются — только ссылки
(§3), чтобы не плодить вторую редакцию правил, которая разойдётся с первой.

---

## 1. Продуктовые имена (бренды)

### 1.1 Критерии выбора

1. **Тема — звёзды и небесная навигация.** Логотип языка — звезда; имена держат одну линию.
2. **Метафора рабочая, а не декоративная** (критерий зафиксирован в
   [222 §0а](plans/222-http-framework.md)). Имя обязано объяснять, что делает вещь. «Просто
   красивая яркая звезда» — недостаточное основание, такие кандидаты отклоняются сразу.
3. **Коротко и одинаково читаемо латиницей и кириллицей.** Имя мелькает в доках, диагностиках и
   разговоре; `Polaris`/`Полярис` проходит, восьмибуквенное с ловушкой в написании — нет.
4. **Свободно в системном софте.** Занятое известным продуктом имя (особенно в компиляторах,
   рантаймах, инфраструктуре) не берём.
5. **Не входит в список отвергнутых (§1.3) и не совпадает с уже занятым в проекте (§1.2)**
   (· согласовано 2026-07-23). Отказ **персистентен**: отвергнутое имя не возвращается в
   рассмотрение при выборе имени нового модуля или фреймворка — снять отказ может только явное
   решение владельца. Отдельная осторожность к именам, отличающимся одной буквой от занятого
   или отвергнутого (`Vela` при отвергнутой `Vega`): формально это другое имя, но читатель доков
   будет путать — такой кандидат выносится владельцу с явным указанием на сходство.
6. **Имя — сначала бренд в доках, а не переименование путей.** Прецедент Polaris: имя
   зафиксировано, пакеты остались `nova-http` до раскола. Переименование каталогов/пакетов —
   отдельный механический заход одной волной, если вообще понадобится.

### 1.2 Зафиксированные имена

| Имя | Что называет | Метафора | Где зафиксировано |
|---|---|---|---|
| **Nova** | Язык | Новая звезда — вспышка; язык как новая точка на небе | исторически, с начала проекта |
| **Polaris** ⭐ | HTTP-фреймворк (слои 2-3: Router, extractors, respond, middleware, батарейки) | Полярная звезда — та, по которой **навигируют**; ядро фреймворка это маршрутизация = навигация | [222 §0а](plans/222-http-framework.md), 2026-07-23 |

### 1.3 Отвергнутые имена — отказ действует для ВСЕХ последующих выборов

> **Отказ персистентен** (· решение владельца 2026-07-23). Имя, отвергнутое при одном выборе,
> **не возвращается в рассмотрение** при выборе имени нового модуля, фреймворка или инструмента.
> Снять отказ может только явное решение владельца по конкретному имени. Раздел ведётся именно
> для этого — чтобы отвергнутые кандидаты не предлагались по второму кругу.

| Имя | Отвергнуто при | Причина |
|---|---|---|
| **Aster** | выбор имени HTTP-фреймворка, 2026-07-23 | греч. «звезда», минималистично, но метафора не работает — ничего не объясняет |
| **Vega** | там же | яркая звезда без рабочей метафоры (222 §0а) |
| **Lyra** | там же | то же |
| **Altair** | там же | то же |

**Занятые чужими продуктами** (не отказ, а критерий 4 — проверять при каждом новом выборе):
`Solaris`, `Quasar`, `Pulsar`, `Nebula`, `Cygnus` (последнее вдобавок исторически компиляторная
компания).

### 1.4 Открытые (имя ещё не выбрано)

| Что | Статус |
|---|---|
| **M:N-рантайм** (`nova_rt`: spawn/cancel/scope/driver/GC) | Владелец поднял вопрос 2026-07-23. Кандидаты и разбор — ниже; **решение не принято**, в доках и коде до фиксации говорим «M:N-рантайм» / `nova_rt`. |

Разбор кандидатов на имя рантайма (чтобы не начинать с нуля при возврате к вопросу):

- **Плеяды (Pleiades)** — сильнейшая метафора: рассеянное скопление это звёзды, рождённые из
  одного облака и связанные вместе — буквально scope со своими фибрами, структурная
  конкурентность. Против: длинно, легко опечататься (ei/ie), NASA-суперкомпьютер того же имени.
- **Vela** (Паруса) — парная к Polaris по навигации: Polaris указывает *куда*, Vela несёт *чем*.
  Метафора рабочая, четыре буквы, в системном софте свободно. **Оговорка:** отличается одной
  буквой от отвергнутой `Vega` (§1.3) — само имя не отвергнуто, но сходство надо решить явно.
- **Ursa** — вращается вокруг Polaris, связка с уже выбранным именем. Против: метафора про пару
  имён, а не про суть рантайма — по критерию 2 ближе к декоративной.

## 2. Имена артефактов проекта

### 2.1 Язык и инструменты

| Артефакт | Имя | Примечание |
|---|---|---|
| Язык | **Nova** | |
| Расширение исходников | `.nv` | |
| Сайт | `nv-lang.org` | |
| CLI-бинарь | `nova` | `nova build` / `check` / `test`; интерпретатора нет |
| Rust-крейт компилятора | `nova-codegen` | лежит в каталоге `compiler-codegen/` — **историческое расхождение имени крейта и каталога**, не образец для новых крейтов |
| Rust-крейт CLI | `nova` | каталог `nova-cli/` |
| Rust-крейт LSP | `nova-lsp` | |

### 2.2 Пакеты Nova

Имя объявляется полем `name` в `nova.toml`, пишется **snake_case**: `spec_tests`,
`nova_examples`, `xpkg_consumer`. Каталоги соседних репозиториев-пакетов — kebab-case
(`nova-http`, `nova-tls`); при расколе пакетов слои 2-3 переезжают в пакет `polaris`
(см. [222.0](plans/222.0-module-map.md)).

Модель модулей (папка = ОДИН модуль из co-equal файлов; файл и папка одного имени запрещены) —
[module-conventions.md](module-conventions.md), D78.

### 2.3 Планы, маркеры, решения

| Артефакт | Схема | Пример |
|---|---|---|
| План | `docs/plans/NNN-kebab-case.md` | `222-http-framework.md` |
| Под-план | `docs/plans/NNN.M-kebab-case.md` | `222.4-middleware.md` |
| Маркер незакрытой работы | `[M-kebab-case]`, живёт в `docs/plans/backlog-followups.md` | `[M-fn-newtype-return-position-broken]` |
| D-блок спеки | `DNNN` в `spec/decisions/NN-тема.md` | `D246` в `02-types.md` |

Статус плана — пофайлово, строка `**Статус:**`; рукописная сводная таблица статусов запрещена
(conventions-governance).

### 2.4 Диагностики

| Класс | Схема | Пример |
|---|---|---|
| Ошибка | `E_SCREAMING_SNAKE_CASE` | `E_READONLY_COERCE`, `E_TYPE_NAME_TOO_SHORT` |
| Линт/предупреждение | `W_SCREAMING_SNAKE_CASE` | `W_MANUAL_MIN_MAX`, `W_PARAM_TYPE_POS_MUT` |

Имя кода описывает **нарушенное правило**, а не место в компиляторе. Коды стабильны: однажды
опубликованный код не переименовывается (он попадает в тесты, доки и мышечную память) — при
изменении семантики заводится новый.

### 2.5 Тесты и фикстуры

| Что | Схема |
|---|---|
| Тест модуля std | `<модуль>_test.nv` **рядом с модулем**, не в общей папке |
| Фикстура conformance | `spec_tests/conformance/<тема>.nv`; привязанные к D-блоку — с префиксом `dNNN_` (`d52_newtype_fn_type.nv`) |
| Негативная фикстура | тот же файл с суффиксом `_neg` (`d52_newtype_fn_reverse_coerce_neg.nv`) |

Подробности — [test-conventions.md](test-conventions.md).

### 2.6 Ветки и worktree

| Что | Схема | Пример |
|---|---|---|
| Ветка задачи | `p-<тема>` или `p-fix-<тема>` | `p-coalesce`, `p-fix-mn-crash` |
| Worktree под тему | `nova-<короткий-тег>` | `nova-coalesce`, `nova-okno5` |
| Worktree под план | `nova-pNN` | `nova-p222` |

Голый `fix-<тема>` без префикса `p-` встречается в истории — это **дрейф**, для новых веток не
использовать.

## 3. Имена внутри кода на Nova — где искать (не дублируем)

| Правило | Источник |
|---|---|
| Имя типа — PascalCase, **минимум 2 символа** (`E_TYPE_NAME_TOO_SHORT`) | D30 §naming, `spec/decisions/03-syntax.md` |
| Имена несут семантику: полные слова, домен-квалифицированные ошибки | [nv-coding-style.md §21](nv-coding-style.md) |
| Конструктор — `Type.new(...)`; `.of` **только** для вариадик-коллекций | nv-coding-style |
| `with_*` всегда возвращает НОВОЕ значение; поля — одноимённые методы-свойства по арности | D117-амендмент (2026-07-06), D84/D409, nv-coding-style |
| Итераторы/view — единый суффикс `*Iter` | nv-coding-style §8 |
| Перегрузки одного имени — все в одном модуле; не различаются — называй по-разному | nv-coding-style §22 |
| ASCII vs Unicode в именах методов | nv-coding-style §2 |
| Устаревшие имена ловятся линтами | `W_RETIRED_NAME`, `W_RETIRED_PREFIX`, `W_VEC_SPELLING` |

## 4. Порядок фиксации нового продуктового имени

1. Кандидаты проверяются по критериям §1.1 — в том числе греп по репозиторию на коллизии.
2. Решение принимает владелец; агент предлагает и обосновывает, но не фиксирует.
3. Зафиксированное имя вносится в §1.2 этого файла **и** в профильный план (как Polaris в
   222 §0а) — одной правкой.
4. Отвергнутые кандидаты вносятся в §1.3 с причиной и указанием, при каком выборе отвергнуты.
   **Отказ действует дальше:** при следующем выборе эти имена не предлагаются повторно, пока
   владелец явно не вернёт конкретное имя в рассмотрение.
