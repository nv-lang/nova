# 196.7 — Method-dispatch через `resolved_callees` (одно окно для диспетча метода по ресиверу)

**Родитель:** [196 — одно окно правды](196-one-truth-closeout.md) (трекер-closeout).
**Статус:** ✅ ЗАКРЫТ 2026-07-15 (ветка `p196-dispatch`, worktree `nova-196-7`; в main вливает оркестратор ПОСЛЕ 206/209Ф.3/D39 — `emit_c.rs` конкурентно правится).
**Модель:** opus (архитектура dispatch/codegen).

## Проблема (маркер `[M-174.1-to-str-name-collision-codegen-bug]`)

`[]u8 @to_str() -> Result[str, Utf8Error]` (фасадный метод) в compile-unit, где ЕСТЬ
чужой same-name метод — bare-T бланкет `fn[T] T @to_str() -> str` (D410-скаляр→строка) и/или
пользовательский `T @to_str() -> str` (Display, напр. `NetError`/`Path`/`Url`/`SerError`/
`IoError`/`SocketAddr`) — МИС-ДИСПАТЧИЛСЯ: codegen эмитил тело ЧУЖОГО `to_str` вместо
`[]u8`-тела. Симптом: `Nova_Nova_Vec____nova_byte_method_to_str(bytes)` (bare-T бланкет,
возвращает `nova_str`) на месте `Nova_NovaArray_nova_byte_method_to_str` (возвращает
`Result`) → `->tag` на `nova_str` → CC-FAIL. Тот же класс, что D164 (`106ae7207`,
примитивный ресивер) — но D164 чинил ГАРДОМ; здесь — через КАНАЛ, без name-guard.

Обход в std: байт-идентичный алиас `[]u8 @decode_utf8()` (снят этим планом).

## Первопричина (две)

1. **Диспетч (codegen).** Method-call `obj.to_str()` резолвился по ИМЕНИ через
   protocol-aware **blanket dispatch** (`emit_c.rs`, Plan 164 Ф.3, ~37374) и/или single-key
   `method_receivers` (last-wins по имени, ~37570) — оба ИГНОРИРОВАЛИ конкретный
   `[]u8 @to_str`, зарегистрированный под array-C-ident-ключом `NovaArray_nova_byte`.
2. **Канал (checker).** `check_instance_overload` (`types/mod.rs`) НЕ записывал
   `resolved_callees` для этого вызова: array/slice-ресивер нормализуется в `"Vec"`
   (D239 `[]T ≡ Vec[T]`), но фасадный метод лежит под ELEMENT-написанием (`method_table["[]u8"]`,
   `receiver.type_name = "[]u8"`), невидимым для `method_table["Vec"]` → `methods.get("to_str") = None`
   → канал пуст → codegen перевыводит по имени.

## Фикс (одно окно — читаем факт чекера/ресивера, НЕ перевыбираем по имени)

**Checker (`types/mod.rs::check_instance_overload`):** для array/slice/`Vec[E]`-ресивера,
когда метод ОТСУТСТВУЕТ в `method_table[type_name(="Vec")]`, резолвим по ELEMENT-написанию
`[]E` (`render_type_ref`), single/unique-compatible (c1/c2, как Vec-путь) → пишем
`resolved_callees[call_id] = span([]E-метода)`. GATED к методам, которых нет у "Vec" →
байт-идентично для всех Vec-методов; D84 «concrete beats generic».

**Codegen (`emit_c.rs`), ПЕРЕД blanket-dispatch (~37374):** резолвим конкретный фасадный
callee двумя receiver-truthful источниками (НЕ по имени last-wins):
- **(A) канал** — `resolved_callees[call_id] → FnDecl.span`, gated `fn_ret_by_span`
  (только конкретные не-generic callee; бланкет-span отсутствует ⇒ настоящий бланкет-диспетч
  не трогается), находим instance-sig по span в `method_overloads`, лоуэрим её `c_name`;
- **(B) конкретный C-тип ресивера** — `Nova_Vec____<E>*`/`NovaArray_<E>*` + зарегистрированный
  `[]E @<method>` под array-ключом. Покрывает ресивер-формы, которых не достаёт static
  `infer_arg_ty` чекера (`@field`, expression, pattern-binding). GATED: срабатывает ТОЛЬКО
  когда для метода есть unconstrained bare-T бланкет (единственный сценарий перехвата) →
  байт-идентично иначе.

**Codegen return-type (`emit_c.rs::infer_expr_c_type`, «Channel 1b», ВНЕ frozen
`infer_call_ret_c`):** зеркало (B) для ВОЗВРАТ-типа фасад-вызова на `Vec[E]`/`[]E`-ресивере,
у которого канал пуст (pattern/field/expr) — возвращаем `sig.return_c_type` (Result), а не
бланкет-`nova_str`. Держит два окна согласованными без правки замороженной зоны.

Зона frozen `infer_call_ret_c` (46293-48883) НЕ тронута.

## Снятие обхода `decode_utf8`

Удалён `export fn []u8 @decode_utf8()` (`std/src/runtime/string/core.nv`) + экспорт из
`prelude.nv`. Мигрировано на `.to_str()` (все 11 call-сайтов): `encoding/serde/json.nv:383`,
`encoding/url.nv:389`, `fs/fs.nv:412`, `fs/path.nv:119,224`, `io/core.nv:153,231`,
`net/addr.nv:109,121`, `net/error.nv:90`, `net/tcp.nv:197`, `runtime/string_builder.nv:225`.
Устаревшие комментарии-обходы вычищены. nova-tls (`src/stream.nv:58,246,266,286`) — ОТДЕЛЬНАЯ
репа, отдельный коммит.
