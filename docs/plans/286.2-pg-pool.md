# План 286.2 — `nova-postgres`: пул соединений (паритет pgxpool / database/sql)

**Статус:** ✅ РЕАЛИЗОВАН (2026-09-28 вечер) — подплан [286](286-db-driver.md),
волна Д8. Решение по API: **блокирующий `acquire` + канонический
`try_acquire`** (пара try_recv/recv, D325). Пул — не ядро драйвера,
а отдельный модуль поверх (`src/pgnet/pool.nv`, модуль `postgres.pgnet`).

> **Разблокирован 2026-09-28.** Первичный блокер («каналы не переносят
> consume») остался, но дозамер после волны `Vec[T consume]` (план 246)
> показал: **Vec consume-элементов работает** — хранилище построено на
> `Vec[Connection]` вместо `Chan[Connection]`. Два дефекта вокруг
> (repro `nova-postgres/repro-local/chan_conn`, отчёт §8):
> (1) сахар `[]Connection` типизируется в безымянный тип — consume-методы
> невидимы; рабочий spelling — `Vec[Connection]`;
> (2) `import std.prelude.{Vec}` ломает неявный prelude во всём CU
> (println undefined в других файлах); правильно —
> `import std.collections.vec.{Vec}`.
> Плюс форма: push именованного consume-биндинга — частичный consume
> (reserve до move), путь ошибки закрыт флагом+defer (D189; errdefer
> удалён); опустошённый вектор завершается `destroy_empty()`.

## Реализация (как сделано)

- `Pool consume { opts ConnectOptions, consume idle Vec[Connection], mut out, mut limit }`,
  `Pool.new(opts, limit)`.
- **acquire** (блокирующий, эффекты `Net Random Time`): тёплый pop →
  свежий `connect()` пока `out < limit` → иначе файбер-дружелюбный
  sleep-poll 1 мс (`ACQUIRE_POLL_MS.to_millis().sleep()`) — каналов для
  consume всё ещё нет, ожидание это опрос с уступкой файбера.
- **try_acquire** (`Net Random`): то же без ожидания; на лимите —
  `Err(ConnError.PoolExhausted)`.
- **release(consume conn)**: `out -= 1`; запомнена фатальная ошибка
  (не-Server) — `conn.close()` вместо pooling; иначе push в idle с
  defer-флагом. Недочитанные ответы дочитывает implicit drain следующего
  query (Д8в).
- **close()**: drain idle, каждому — вежливый Terminate, затем
  `destroy_empty()`. Выданные conn — забота держателей.
- Live-режим `pool` в examples/live: limit 2 — два живых соединения
  (разные pg_backend_pid), `PoolExhausted` на третьем try_acquire, тёплое
  переиспользование после release (тот же pid). **20/20 зелёных**;
  регрессии multi/rowerr/disable/notify зелёные; `test src` PASS.
  Блокирующая ветка acquire (ожидание) живьём не гонялась: сокетная
  работа в spawn запрещена (E_FIBER_UNSAFE_CALL, отчёт §7), а двух
  файберов с сокетами в одном процессе-примере язык пока не даёт.

## Отклонения от первичного дизайна

- Idle-хранилище — `Vec[Connection]`, не `Chan[Connection]` (причина выше).
- acquire ждёт sleep-poll'ом, не recv() на канале: семантика та же
  (блок до освобождения), гранулярность 1 мс; «pool closed mid-wait»
  через канал-None не нужен — закрытие пула с ожидающими не моделируется
  (close — consume, ожидающих быть не может по линейности).
