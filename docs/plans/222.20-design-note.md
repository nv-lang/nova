## §0. Ключевой языковой факт (проверено пробами — читать ПЕРВЫМ)

Вся нота стоит на пяти эмпирических фактах о том, что эффект-система УМЕЕТ
СЕГОДНЯ. Они не выведены из спеки — они прогнаны на бинаре (§Отчёт, пробы 1-7).

**Ф-A. newtype-over-fn НЕСЁТ конкретную эффект-строку.** `type Handler
fn(int) Db Log -> int` парсится, чекается, форвардится через промежуточную
`fn dispatch(h Handler, x) Db Log -> int => h(x)` под `--strict-effects`, с
`with Db=…{ with Log=… { … } }` (пробы 1, 6 — PASS). Хранение в `Vec[Handler]`,
обёртка middleware-аналогом — тоже PASS. **Т.е. вариант «Handler с ФИКСИРОВАННОЙ
конкретной строкой» реализуем БЕЗ единой языковой доработки.**

**Ф-B. Эффект-строчной ПОЛИМОРФИЗМА (эффект-переменных) НЕТ.** Попытка
`fn dispatch[E](h fn(int) E -> int) E -> int` — `E` трактуется как ЛИТЕРАЛЬНОЕ
имя неизвестного эффекта, НЕ как переменная строки: `E_UNDECLARED_TRANSITIVE_
EFFECT: call to dispatch requires effect E` (проба 2 — FAIL). Единственный
generic-эффект — `Fail[E]` (built-in hardcoded, generic по ТИПУ ошибки, не по
строке — образец `retry.nv:102` `@execute[T,E](body fn() Fail[E] -> T) Time
Random Fail[E] -> T`; форвардит КОНКРЕТНЫЕ `Time Random`, generic только `Fail`).
**Следствие: «Handler, полиморфный по произвольным пользовательским эффектам»
(мечта 0в-п.4 «сильнее Axum-State/FastAPI-Depends») НЕ реализуем сегодня —
требует row-polymorphism (эффект-переменные, Koka-класс). Это крупная языковая
RFC, не объём этого плана. НЕ предполагать, что «само заработает».**

**Ф-C. `--strict-effects` проверяет строки ТОЛЬКО на рёбрах вызова ИМЕНОВАННОЙ
функции, объявившей эффект. Сырой effect-ОП — не проверяется вовсе.** `fn f()
-> int { Log.info("x"); 0 }` (чистая сигнатура, ПРЯМОЙ вызов опа, без `with`,
без `#default_handler`) — PASS, ноль ошибок, ноль warning'ов (пробы 4g/4h/4j).
Ошибка `E_UNDECLARED_TRANSITIVE_EFFECT` возникает ТОЛЬКО когда fn зовёт ДРУГУЮ
ИМЕНОВАННУЮ fn, чья ПОДПИСЬ несёт эффект (пробы 4a `Monotonic.now()`, 4e/4i/2 —
FAIL). **Это дыра №93 «strict-effects исключение», surfaced эмпирически: она
ПРОТИВОРЕЧИТ D62 («прямой эффект обязателен в сигнатуре — compile error»).**
Вся дешёвая ветка рекомендаций (вариант b ниже) ОПИРАЕТСЯ на эту лень. Если №93
закрыть по D62 (сырой оп обязывает объявить) — вариант (b) рушится, остаётся
(a')/row-polymorphism. **Направление №93 = стержневой блокер, решать ПЕРВЫМ.**

**Ф-D. «Конструктор объявляет эффект» — рабочий паттерн для pure-Handler.** fn,
объявившая эффект в СВОЁЙ строке, может строить closure, зовущий именованные
effectful-fn; closure наследует контекст объявления внешней fn и коэрсится в
ЧИСТЫЙ fn-тип. `fn build() Time -> Handler { fn(x) -> int => inner(x) }` где
`inner() Time` — PASS (проба 5a); тот же shape без `Time` на `build` — FAIL
(4a). **Это ровно то, что уже делает `log.nv` (`@middleware() Time ->
Middleware`) — и решение для `require_jwt`/`session_layer` (Q4).**

**Ф-E. `#default_handler` (D431) даёт RUNTIME-реализацию ambient, НЕ снимает
STATIC-требование.** `greet() Log` с `#default_handler(Log)`, вызванная из
чистой `main` → всё равно FAIL `E_UNDECLARED_TRANSITIVE_EFFECT` (проба 3).
default_handler убирает необходимость `with` В ТОЧКЕ ЗАПУСКА рантайма, но
чекер-дисциплина строки не меняется. Полезен для дефолта (Log→stdout), не для
«обхода» строки.

> **Синтез для Q1.** «Честный» Handler (per-handler эффект-строка, видимая в
> подписи — полная D2-ценность) требует эффект-переменных (Ф-B) = язык-RFC.
> Без неё выбор бинарный: **(a') фиксированная конкретная строка** (честно, но
> «one-size» — over-declare, крупный rewrite цепочки) ИЛИ **(b) ambient-pure**
> (Handler чист, эффекты невидимы — частичная потеря D2, но дёшево и уже
> работает, опираясь на дыру №93 Ф-C). Всё остальное — комбинации этих двух.

## §1. Q1 (ключевой) — Handler и пользовательские эффекты

Сегодня: `type Handler fn(ServerRequest) -> ServerResponse` (server.nv:511),
БЕЗ строки. Цепочка диспетча ЧИСТАЯ до дна: `serve(…) Net Time Detach` →
callback `fn([]u8) -> ServerResponse` (router_callback, pure) → `route_once` →
`Router.dispatch` → `Handler(req)`. Чтобы тело хендлера несло Db/Time/…, эффект
надо протащить сквозь ВСЕ звенья ИЛИ дисчарджить ambient.

### Варианты и цены

| # | Вариант | Язык | Компилятор | Polaris-код | Миграция | Dispatch-перф |
|---|---|---|---|---|---|---|
| **a** | Handler ПОЛИМОРФНЫЙ по произвольной строке (мечта 0в-п.4) | **НЕ существует** (Ф-B: нет эффект-переменных) | **крупная RFC**: row-polymorphism, unification строк, inference — research-grade (rustc-эталон: это отдельная система, не «доработка») | — | — | — |
| **a'** | Handler с ФИКСИРОВАННОЙ конкретной строкой (напр. `fn(ServerRequest) Db Time Random Log -> ServerResponse`) | 0 (Ф-A: работает) | 0 | **крупный**: строку получают Handler/Middleware/Router.dispatch/MethodRouter/route_once/router_callback/serve_connection/run_request/serve — всё звено | большой, механический | 0 (эффект = ambient vtable) |
| **b** | Handler ЧИСТЫЙ; эффекты входят (i) через конструкторы middleware, объявляющие эффект на `-> Middleware` (Ф-D, log.nv), (ii) сырыми опами в теле хендлера (Ф-C), дисчардж — ambient `#default_handler`/`with` вокруг dispatch | 0 (работает) | **0, НО опирается на дыру №93** | **малый**: статус-кво + консолидация | малый | 0 |
| **c** | Гибрид: (b)+`#default_handler` для ambient-инфры (Log/Time/Random/Io), (a')-подобный явный канал для Db-класса | 0 | 0 (та же оговорка №93 для сырых опов) | средний | средний | 0 |
| **d** | Эффект-DI: `with Db = pool` / `with SessionStore = store` установлен в `serve`/`session_layer` вокруг dispatch (0в-п.4) | 0 | 0 | малый (это и есть `with`-блок) | малый | 0 |

**«DI» (d) — это НЕ отдельный механизм, а `with`-блок вокруг dispatch.** Его
сила ровно в подмене хендлера в скоупе = ровно определение эффекта (Правило 4).
Он ОРТОГОНАЛЕН вопросу видимости в подписи: с (a') виден в строке Handler, с (b)
невидим. «Сильнее Axum-State/FastAPI-Depends» он становится ТОЛЬКО в паре с (a)
(честная подпись) — которой нет.

### РЕКОМЕНДАЦИЯ Q1

**(b)+(c)+(d), Handler остаётся ЧИСТЫМ — НО обусловлено решением по №93 (Ф-C).**
Обоснование (≤5 строк): (1) честный полиморфный Handler (a) требует
эффект-переменных = язык-RFC вне плана; (2) (a') фиксированная строка одинаково
«нечестна» (over-declare: хендлер, которому нужен только Db, типизирован
`Db Time Random Log`) и стоит крупного rewrite всей цепочки; (3) (b)+(c)+(d) уже
доказаны в коде (log.nv, MockHttp-триада) и стоят почти ноль; (4) эффект-DI (d)
даёт подмену-в-скоупе — 80% ценности мечты 0в-п.4 — без языковой доработки.
**Блокер:** если владелец закрывает №93 по D62 — (b) невозможен, вынужден (a')
или язык-RFC. **Поэтому Q1 = функция от решения по №93.**

**Требует D-амендмента:** только если выбран (a') — тогда амендмент D2/D62 не
нужен (строка уже легальна), но нужен полиморфизм error-типа Handler по `Fail`
(genericity ломает bare-newtype — `Handler[E]`, отдельная цена). Если (b) —
D-амендмента НЕТ, но **обязателен явный статус №93** (закрыть-или-узаконить;
узаконивание = амендмент D62 «сырой оп не обязывает строку»).

## §2. Q2 — SessionStore → эффект

Сейчас: `SessionStore protocol` + `MemorySessionStore` impl + проброс `mut
store` через `session_layer` (auth.nv:365). Ф.1-вердикт: учебниковый Db-класс
подмены (прод Redis/PG vs `MemorySessionStore` в тесте) → **ЭФФЕКТ** по Правилу
4 (прямая параллель `Db`/`Cache[K,V]`, 04-effects.md:2857/2865).

**Форма:** `type SessionStore effect { load(id str) -> Result[Option[SessionData],
HttpError]; save(id str, data SessionData) -> Result[(),HttpError]; destroy(id
str) -> Result[(),HttpError] }`. `now_ms`-параметр УХОДИТ (TTL-логика внутри
handler'а зовёт `Time` сырым опом ИЛИ handler держит свой clock). Прод-handler =
`MemorySessionStore.handler()` (или pool), тест = in-memory `with SessionStore =
mock()` — третья нога триады, как `mock_http()`.

**Совместимость с session_layer:** `session_layer(cfg) Time Random ->
Middleware` (конструктор объявляет Time/Random по Ф-D); `store` больше НЕ
параметр — `SessionStore.save(…)`/`.load(…)` зовутся как опы; handler ставится
`with SessionStore = … { serve_router(…) }` на уровне сервера (вариант d).

**D9-конфликт / «обе двери».** Правило 4 = compile-time enforcement: имя —
ЛИБО эффект, ЛИБО протокол, не оба (mixing → compile error, 04-effects.md:2914).
Значит одновременно `SessionStore` протоколом И эффектом НЕЛЬЗЯ — «две двери
временно» невозможны by construction. Миграция = ЧИСТЫЙ cutover в одной волне:
протокол→эффект, `MemorySessionStore` из impl-типа → factory `-> Effect[
SessionStore]`. Никакого deprecation-моста (pre-release, вторых дверей нет).

**Цена:** язык 0; компилятор 0; polaris — переписать auth.nv sessions-секцию
(~60 строк) + точку установки в serve; миграция — 1 волна, 1 вызывающий
(auth_test.nv). **D-амендмент:** НЕТ (штатная effect-машинерия; это API-решение
polaris, не языковое D-решение).

## §3. Q3 — Log-эффект (сильнейший сигнал: 3 дубля синка)

`background.nv @emit` + `middleware/log.nv emit` + `net/config.nv panic_emit` —
ТРИ независимые ручные копии sink-паттерна (fn-поле + `@sink(f)`-сеттер) в одном
пакете. Ф.1: самый явный сигнал избыточности.

**Форма:** `type Log effect { info(msg str) -> (); error(msg str) -> () }` +
`#default_handler` → stdout через ambient `Io` (проба: user Log + default_handler
+ сырой оп в чистом теле → PASS, 4b/4f). Тест = `with Log = capture() { … }`
(вместо ручной подмены поля). Три поля-замыкания (`@emit`/`emit`/`panic_emit`) и
три `@sink`-сеттера УДАЛЯЮТСЯ.

**Дефолт → println?** НЕ `println` напрямую: log.nv:57 фиксирует, что вариадик
`println` не ЭМИТИТСЯ в external-package CU («undefined identifier println» на
codegen). Дефолт-handler пишет в `stdout().write(...)` через `Io` (как нынешний
`default_sink`) — тот же рецепт, что `real_io()` `#default_handler` уже несёт.

**Связь с policy.panic_sink:** `run_request` (net/serve.nv:192)
`(policy.panic_emit)("handler panic: …")` → `Log.error("handler panic: …")`.
`ServerPolicy.panic_emit`-поле и `@panic_sink`-сеттер уходят; recover-500 логирует
через ambient `Log`. (Оговорка: `run_request` несёт `Net Time` — добавит `Log`;
но `Log` дисчарджится ambient default, а если №93 оставляют — сырой
`Log.error` не потребует даже объявления.)

**РЕКОМЕНДАЦИЯ Q3:** сделать НЕМЕДЛЕННО, НЕЗАВИСИМО от исхода Q1. Самый высокий
value/risk: −3 копии, +1 системный эффект, ноль языковых затрат, штатный D431.
**D-амендмент:** НЕТ.

## §4. Q4 — now_fn/id_gen → Time/Random

5 мест в auth.nv (`require_jwt`, `session_layer`, `jwt_guard_apply`,
`session_apply`, `MemorySessionStore`) тащат `now_fn fn()->u64` (=Time) и
`id_gen fn()->str` (=Random) явными замыканиями — потому что тело зовёт
ИМЕНОВАННЫЕ effectful-fn (`Monotonic.now()`, `Jwt.validate_hs256`), а Handler
чист (Ф-C fires на именованном ребре).

**РЕШЕНИЕ = паттерн Ф-D (уже в log.nv):** конструктор middleware объявляет
эффект на возврате. `require_jwt(auth) Time -> Middleware`; `session_layer(store,
cfg) Time Random -> Middleware`. Внутри closure свободно зовёт
`Monotonic.now()`/`Jwt.validate_hs256` (наследует Time-контекст конструктора,
5a-PASS). `now_fn`/`id_gen` УДАЛЯЮТСЯ; `jwt_check_time(now_ms)` inline-переписку
можно вернуть в делегирование к `Jwt.validate_hs256` (−дублирование exp/nbf).

**Переходный период / обе двери:** НЕ нужен — конструкторы меняют подпись в одной
волне вместе с Q2 (session_layer и так трогается). Никакого «оба API».

**ОТКРЫТО (честно): `Random` не имеет `real_*()`-ctor** (D431 Ф.2-v4 П9: CSPRNG
= hardcoded runtime-путь, `secure()`-фабрика — открытый вопрос). Сырой
`Random.gen()` работает ambient, НО прод-энтропия session-id зависит от того, что
дефолтный runtime-Random криптостоек — проверить перед объявлением
`session_layer … Random`. `Time` — чист (`#default_handler` есть, D431 Ф.2-v4).

**Цена:** язык 0; компилятор 0 (Random-ctor — отдельный открытый вопрос, не
блокер этой волны); polaris — auth.nv ~5 сигнатур; миграция 1 волна.
**D-амендмент:** НЕТ (если Random-CSPRNG-дефолт подтверждён достаточным; иначе —
след-план на `Random.secure()`, вне 222.20).

## §5. Q5 — Паника vs Fail в хендлерах (recover-500 / D416)

D416: `run_request` гоняет хендлер под Stop-supervision (`supervised { spawn {…}
}` + `on_child_fail -> Decision.Stop`); паника/throw ловится, не роняет процесс,
не пробивает частичный ответ (весь handler+write внутри одного spawn) →
`policy.panic_response()`: `InternalError500` пишет 500 (keep-alive сохраняется)
либо `Close`.

**Норма (рекомендация):**
- **Ожидаемый отказ** (плохой ввод, отсутствие ресурса, парс) → `Result` →
  `IntoResponse` даёт типовой ответ (extractors уже `Result[T,HttpError]`,
  `FromRequest`). НЕ паника. Fail НЕ должен покидать тип Handler.
- **Fail, покинувший хендлер:** Handler чист (нет `Fail` в строке) → любой
  непойманный `Fail`/`!!`/`?`-эскейп = паника на границе fiber'а → ловится
  recover-500 (D416). Т.е. Fail-эскейп и паника СХОДЯТСЯ в один путь → 500.
- **Contract-violation / баг** (OOB, overflow, div0 — D13/R0 D325) → паника →
  recover-500. Это БАГ, 500 корректен.
- **Что НЕ ловится:** только то, что вне spawn-скоупа (сам accept-loop, парс
  до dispatch → 400 напрямую). D437: throw-site/trace НЕ доступны
  `on_child_fail` (только message через `.try_as[str]()`) — логируем
  message-only, честно (background.nv тот же предел).

**Итог:** норма = «ожидаемое → Result/IntoResponse; всё непредвиденное (паника,
Fail-эскейп, contract-violation) → recover-500 через D416». **D-амендмент:** НЕТ
(D416/D13/D325 уже покрывают; это кодификация в docs/polaris-guide, не язык).

## §6. Q6 — Что НЕ эффекты (подтверждение Ф.1-п.5)

Прогнано через Правило 4 (подменяемость в тесте) — все три подтверждены как
runtime-mechanic / control-flow, НЕ resource-capability:

- **TLS `@read`/`@write`/`@flush`/`@close`** (nova-tls) — TLS НЕ заводит свой
  capability; sans-I/O помпа гоняет `Net` через `TcpStream`. Тест мокает на
  уровне `Net`/байт, не «плохой сертификат» отдельным эффектом (сертификат =
  параметр `ClientConfig`, не capability). НЕ эффект (пограничный, но закрыт).
- **StreamBody** (`priv f fn()->Option[[]u8]`) — producer над suspension-
  mechanic (`rx.recv()` парк — substrate, D22 closure-light), не resource с
  «прод vs тест» реализацией. НЕ эффект.
- **upgrade-hook** (`Option[fn(TcpStream) Net -> ()]`) / **background-hook** —
  control-flow hand-off МЕЖДУ стадиями одного соединения, не подменяемая
  внешняя зависимость. НЕ эффект. (Внутри BackgroundTasks `@emit` — эффект,
  учтён в Q3.)
- **compress** — 0 эффектов, чистые байты (D407) — подтверждено, вне разбора.
- `FromRequest`/`IntoResponse` — ПРОТОКОЛЫ (реализация привязана к типу,
  подменять нечего) — корректны как есть.

**D-амендмент:** НЕТ.

| **Q2 SessionStore** | protocol → **effect** `{load/save/destroy}`, `now_ms` уходит; установка `with SessionStore=…` в serve/session_layer; чистый cutover (Правило 4: две двери невозможны). | 0/0/средний (~60 строк auth.nv) | синхронно с Q4 (общий session_layer) |
| **Q3 Log** | ОДИН `type Log effect {info/error}` + `#default_handler`→stdout(Io); снести 3 копии sink; panic_sink→`Log.error`. **Делать НЕМЕДЛЕННО, независимо от Q1.** | 0/0/малый | нет (штатный D431) |
| **Q4 now_fn/id_gen** | Удалить; `require_jwt(auth) Time`, `session_layer(…) Time Random` (паттерн Ф-D=log.nv). | 0/0/малый (~5 сигнатур) | Random-CSPRNG-дефолт подтвердить (иначе `Random.secure()` — след-план) |
| **Q5 паника/Fail** | Ожидаемое→Result/IntoResponse; паника+Fail-эскейп+contract-viol → recover-500 (D416); message-only лог (D437). | 0/0/0 (кодификация) | нет |
| **Q6 не-эффекты** | TLS r/w, StreamBody, upgrade/background-hook = runtime-mechanic; FromRequest/IntoResponse = протоколы. Подтверждено. | — | нет |

**Сводно по D-амендментам:** обязателен ТОЛЬКО один — **явный статус №93**
(либо чекер-фикс без амендмента, либо амендмент D62 при узаконивании). Q2-Q6 —
штатная effect-машинерия, D-амендментов не требуют (это API-решения polaris).

## §8. Порядок волн реализации (Ф.3)

1. **Волна 0 — РЕШЕНИЕ ВЛАДЕЛЬЦА по №93** (гейт для всего Q1). Без него Q1 не
   стартовать: направление определяет, возможен ли (b).
2. **Волна A — Q3 Log-эффект** (параллельно, независимо от №93/Q1): ОДИН `Log`,
   `#default_handler`, снос 3 копий. Самый дешёвый и явный выигрыш — можно
   начать сразу.
3. **Волна B — Q2 SessionStore + Q4 now_fn/id_gen** (совместно — общий
   session_layer): protocol→effect, конструкторы-объявители Time/Random, снос
   now_ms/now_fn/id_gen. Зависит: Random-CSPRNG-дефолт подтверждён (иначе
   Q4-Random откладывается в под-план `Random.secure()`).
4. **Волна C — Q5 кодификация** (docs/polaris-guide + пример): норма
   паника/Fail/recover-500. Дёшево, не блокирует.
5. **(Условно) Волна D — Q1 (a') fixed-row**, ТОЛЬКО если Волна 0 закрыла №93 по
   D62: протащить фикс-строку через всю цепочку dispatch. Крупная, отдельный
   под-план с полной картой звеньев (serve→…→Handler).
6. **(Вне 222.20) язык-RFC row-polymorphism** — если владелец хочет истинно
   полиморфный честный Handler (мечта 0в-п.4). Research-grade, отдельный трек.

## Отчёт

**Модель:** opus (волна 222.20-Ф.2).

**Пробы (релиз-бинарь `nova.exe check --strict-effects`, `NOVA_STD_PATH=std`;
временные файлы в scratch, не в репах):**

| # | Что проверяла | Вердикт |
|---|---|---|
| 1 | newtype-over-fn с конкретной строкой `type Handler fn(int) Db -> int` + форвардинг через dispatch + `with Db` | **PASS** — Ф-A |
| 2 | эффект-строчной полиморфизм `dispatch[E](h fn(int) E -> int) E -> int` | **FAIL** `E_UNDECLARED_TRANSITIVE_EFFECT` (E = литерал, не переменная) — Ф-B |
| 3 | user `Log` + `#default_handler`, `greet() Log` из чистой `main` | **FAIL** — default_handler не снимает static-требование — Ф-E |
| 4a | `Monotonic.now()` (именованная Time-fn) в чистом closure, внешняя fn без Time | **FAIL** — именованное ребро fires |
| 4b/4f | user Log/Db + default_handler, СЫРОЙ оп в чистом closure | **PASS** — Ф-C |
| 4c | user Log БЕЗ default_handler, сырой оп в closure | **PASS** — не про default_handler |
| 4d | сырой `Time.now()` оп в чистом closure | **PASS** — сырой оп не проверяется |
| 4g/4h/4j | сырой `Log.info` в чистой named fn / в чистой main | **PASS, ноль warning** — дыра №93, противоречит D62 — Ф-C |
| 4e/4i | pure fn зовёт Log-ОБЪЯВЛЯЮЩУЮ named fn | **FAIL** — именованное ребро fires |
| 5a | closure зовёт Time-named-fn, внешняя fn ОБЪЯВЛЯЕТ Time, коэрс в pure Handler | **PASS** — Ф-D (= паттерн log.nv) |
| 6 | конкретная мульти-строка `Db Log` Handler в `Vec`, dispatch-форвард + mw-обёртка + вложенные `with` | **PASS** — (a') реализуем |
| 7 | effectful Handler в `spawn`/`supervised` | эффект проходит; единственная заминка — ОРТОГОНАЛЬНАЯ `E_CONCURRENT_MUT_CAPTURE` на `mut out` (уже решена в run_request через `share()`+ConnStep) |

**Главный вывод:** Q1 — функция от решения владельца по дыре №93 (Ф-C). Истинно
полиморфный «честный» Handler требует эффект-переменных (Ф-B) — язык-RFC вне
плана. Дешёвая ветка (b)+(c)+(d) работает СЕГОДНЯ, но стоит на №93. Q3 (Log) —
однозначный немедленный выигрыш вне зависимости от Q1. Q2/Q4 — штатная
effect-машинерия, чистый cutover (Правило 4 запрещает две двери), синхронно.
