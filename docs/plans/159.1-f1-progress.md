### Почему рекурсия по droppable-полям НЕ требует отдельного кода (анализ)

- Диспозиция consume-поля — ВСЕГДА явный Nova-код пользователя (нет
  auto-generated recursive drop-glue в кодогене): либо вложенный
  `consume tmp = @field { … }` (сам по себе `Stmt::ConsumeScope` → тот же
  seed уже покрывает), либо прямой вызов `@field.close()`/`.commit()` —
  обычный AST `Call{func: Member}` узел, который генерическая seed-логика
  (`ExprKind::Member` → `out.insert(name)`, `ExprKind::Call` →
  `@method:<name>`) уже покрывает НЕЗАВИСИМО от consume-специфики.
  Проверено: `record_consume_fields` (`emit_c.rs`) используется ТОЛЬКО в
  `consume_fields_for_lit` (reconsume-disarm при move-out из record-литерала),
  никакого auto-cascade cleanup-вызова в кодогене нет.
- TYPE-reachability (`ty_anchored` в `compute_dead_decls_with`) для ЛЮБОГО
  типа, участвующего как поле ЛЮБОГО другого type-decl где-либо в модуле,
  УЖЕ безусловный root (`Item::Type` целиком попадает в `_ =>` ветку
  `compute_dead_decls_with`, т.е. `collect_used_names` от type-decl'а —
  включая имена полей через `collect_tr` — толкается в `worklist`
  БЕЗУСЛОВНО, независимо от того, достижим ли сам containing-тип). Значит
  reachability вложенных droppable-полевых типов уже maximally
  conservative — сид `"cleanup"` (bare-name, не per-type) закрывает ЛЮБУЮ
  глубину вложенности одним и тем же именем.
