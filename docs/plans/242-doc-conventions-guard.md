# План 242 — enforcement doc-conventions: страж + CI-job

**Статус:** 🆕 PLANNED (записан 2026-08-02; запуск — по слову владельца).
**Отношение к тегу: ЖДЁТ 1.0.** Плана касается только одна отложенная вещь —
третий ключ периметра на `novac/src/**` (открытый вопрос ниже), и ждёт он не
«тега вообще», а того момента, когда исходник Карины перестанет меняться каждый
день, то есть ступени 1.0 лестницы 274. Слово поставлено 2026-09-20: страж
`check-plans-tag-bound` справедливо назвал план неразличимым — «до тега» без
ступени читается тремя способами, а лестница у нас три ступени и имеет.
**Приоритет:** P3 (инфраструктура документации).
**Конвенция-подопечная:** [docs/dev/doc-conventions.md](../dev/doc-conventions.md); по завершении обновить её строку `enforcement:` с «частично машинное» на список механизмов (правило 231.2: заметка без механизма = симптом).
**Смежные:** [241](241-spec-bilingual.md) Ф.2 — валидация в синке www (второй рубеж, там); Plan 185 — W-правило линта (бриф отдельно, п.3 ниже).

## 1. Страж `scripts/tools/check-doc-conventions.sh`

Проверки по ИСТОЧНИКУ (репа nova), быстрые (grep/frontmatter, без сборок):

- `spec/*.en.md`: обязательная шапка «Informative translation; the Russian
  text is normative.» + frontmatter `source_rev`/`source_date` — иначе красный.
  (До появления первых переводов по 242 проверка вакуумно-зелёная.)
- Парность guide (ужесточено 2026-08-03, «два языка везде»): канон публикации —
  файл `docs/guide/PUBLISHED.list` В ЭТОЙ репе (вводится 241-Ф.1b; стартовый
  состав = ВСЕ guide-файлы). У каждого файла списка обязана быть пара
  (`X.md` ↔ `X.ru.md`) — отсутствие = КРАСНЫЙ (не warning). www-синк читает
  ТОТ ЖЕ список (никаких зеркал-констант). Правка одного файла пары без
  правки второй В ТОМ ЖЕ коммите — красный (сравнение последних коммитов пары;
  допуск: `source_rev`-обновления).
- `docs/plans/NNN-*.md`: есть строка `**Статус:**`.
- **Ратчет dev-ссылок**: число ссылок на `docs/dev/` из `docs/guide/**` и
  `spec/**` ≤ базы, зашитой в страже (старт = 35, факт 2026-08-02); рост =
  красный, снижение = обновить базу тем же коммитом. Известный долг виден и
  не растёт.
- Дисциплина стража: `LC_ALL=C` + селфтест на fixture-нарушениях в начале
  скрипта (урок msys2: не-ASCII паттерн без LC_ALL=C молча даёт 0 хитов;
  страж без селфтеста не работает).

## 2. CI-job nova

Отдельный быстрый job «docs-guard» в github workflow (авторитетный гейт —
CI github, протокол 2026-07-16): запуск стража на каждый push/PR в main.
Нарушение конвенции физически не доезжает до main.

## 2b. Пакетные репы: раскатка стража (добавлено 2026-08-03 — вопрос владельца
«доки в модулях кто автопроверяет?»; ответ до этого пункта — НИКТО)

Доки пакетов (polaris/docs 26 файлов, README-пары остальных) обязаны проходить
ту же проверку. Механика — два рубежа, скрипт ЕДИНСТВЕННЫЙ (живёт в nova):

- **Скрипт кросс-репный по построению:** `check-doc-conventions.sh <корень-репы>`
  — принимает корень проверяемой репы аргументом; правила читает из
  `PUBLISHED.list` проверяемой репы; норма языка/парности/код-блоков — общая.
- **Рубеж 1, локальный (до коммита):** pre-commit-хук пакетной репы зовёт
  скрипт из главной репы по соседнему пути (`../nova/scripts/tools/…`;
  раскатка и контроль наличия — существующим `install-guards.sh`, он уже
  ставит hooksPath во всех пяти репах и проверяется `--check`).
- **Рубеж 2, CI (авторитетный):** в workflow КАЖДОЙ пакетной репы — быстрый
  job «docs-guard»: checkout своей репы + sparse-checkout `scripts/tools/`
  из nova main → прогон стража. Нарушение не доезжает до main пакета.
- Реестр 231 §0а: строка на каждый подключённый механизм (документирован /
  подключён / покрыт селфтестом) — ТЕМ ЖЕ слиянием, что раскатка.

## 3. Бриф в дорожку Plan 185 (не в этом плане)

W-правило реестра `nova lint`: кириллица в `///`/`//!` и в текстах
диагностик/линта (nv-coding-style §25). Ловится по AST, а не грепом —
дом в линте. Оформить брифом при ближайшей lint-волне.

## Не-скоуп

- Автопроверка компилируемости ```nova-блоков на страницах (экстрактор +
  `nova check`) — отдельная будущая работа, нюансы фрагментов без `module`.
- Валидация в синке www — план 241 Ф.2.

## Приёмка

- Селфтест стража зелёный; на текущем дереве страж зелёный (ратчет = база).
- Искусственные нарушения каждого класса (en.md без frontmatter, guide без
  пары, план без статуса, +1 dev-ссылка) — красные.
- CI-job проходит на main и падает на тестовой ветке с нарушением.
- Обновлена `enforcement:`-строка doc-conventions.md.

## СДЕЛАНО 2026-09-18 (окно Карины): второй периметр `check-doc-examples`

Пришлось не по очереди плана, а из работы над 274.7: интегратор сказал «поправь
`let` в одном док-примере, это просто работа». Перед правкой замерено число — и
оказался класс, а не носитель. Согласовано с интегратором ДО работы (периметр и
база — его территория), исполнено этим окном.

**Что было не так.** Шапка стража говорит, что он заведён против «дока месяцами
учила читателя писать снятый синтаксис (`let`, ...)», а его периметр —
`docs/guide/*.md`, `spec/*.md`, `README*` ВЕРХНЕГО уровня. Док-комментарии `///`
в `.nv` не проверял никто, и страж был ЗЕЛЁН, а зелень читалась как «таких форм нет».

**Две находки, и вторая важнее первой:**
1. **Периметр** не видел `std/src/**/*.nv` — расширен рекурсивно, тот же СПИСОК
   форм, отдельные ключи `nv_*` (храповики двух периметров не смешиваются).
2. **Дыра в САМОМ классе:** `re_let` требовал `=` сразу за именем и потому НЕ
   ловил `let mut x = ...` — снятую форму так же, как простой `let`. Это
   действовало И НА markdown-периметр, то есть на весь страж с его заведения.
   Замер: `let mut b = 1` в док-примере давал 0, `let b = 1` там же — 1.

**Числа (сняты САМИМ СТРАЖЕМ, не грепом):** периметр дал 120; после починки
класса — **165** (45 носителей были невидимы и после расширения); снято 165 строк в
42 файлах двумя подстановками (`let mut x` → `mut x`, 45; `let x` → `ro x`, 120);
контроль `grep -rn "ro mut" std/src` = **0**; база опущена до 0 ТЕМ ЖЕ коммитом.

**Рукопашные замеры давали 191 и 196** — оба верны для своего вопроса и оба не равны
замеру стража: греп считает похожее (проза, блоки-летописи), страж — предмет.
Правило счёта и все три числа записаны В БАЗЕ стража, чтобы следующий считающий
видел ПОЧЕМУ они расходятся, а не открывал это заново.

**Приёмка — в обе стороны, три пробы:** (1) база опущена до 0 на настоящем
дереве → красный с числом 120, восстановлена → зелёный; (2) поддельный корень с двумя
файлами, один `let`, другой канонический `ro` → посчитан РОВНО ОДИН;
(3) четыре клетки самотеста плюс клетка на `let mut`.

**НЕ ДЕЛАЕМ (границы), и это названо КЛЕТКОЙ, а не словом:** страж ПО-ПРЕЖНЕМУ
не видит `novac/src/**`, `examples/**`, `nova_tests/**` и любые `.nv` вне `std/src`.
Шапка стража говорит это прямо, а клетка 7d делает утверждение проверяемым:
тихий периметр и дал 165 невидимых носителей при зелёном страже, и назвать
пробел одной лишь прозой значило бы повторить тот же фокус этажом выше.

**Открытый вопрос (интегратору, умолчание есть):** расширять ли периметр на
`novac/src/**` третьим ключом. Умолчание: не расширять до ступени 1.0 (см. строку отношения к тегу выше) — исходник Карины
меняется каждый день, и третий храповик сейчас добавит шума больше, чем поймает.
