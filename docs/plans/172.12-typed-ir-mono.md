# Plan 172.12 — Typed-IR mono path

**Статус:** 🔧 в работе 2026-07-06 (заход 1: Ф.0 карта закрыта; далее A1 substrate) — из финализации 172.1, главный структурный разрыв с эталонами
**Зонт:** [172-compiler-rework.md](172-compiler-rework.md)
**Порядок:** ПОСЛЕ [172.4](172.4-value-abi-auto-placement.md) (value-ABI сначала унифицирует representation — IR ложится на ОДИН путь вместо трёх), до/вместе со [172.13](172.13-constraint-inference.md).
**Ветка:** `track-a-172-12` (от main `97100017`; рабочая копия `nova-p173`)

## Мотивация

После 172.1 (единый канал `resolved_types`, legacy удалён) остался главный
структурный разрыв с эталонами (rustc HIR→MIR, Zig ZIR→AIR, Swift SIL,
Go typed-AST+SSA): **AST лоуэрится в C-текст напрямую**, и часть типовой
правды живёт в **C-строках**:

- mono-identity = мангл-строка (`Nova_Vec____nova_str*`) — сравнение/декод по
  строковым префиксам (`strip_prefix("Nova_")`, `contains("____")`);
- dispatcher-каналы 6c–6z ([M-172.1-lifted-legacy-arms]) — дословно поднятая
  state-логика (var_types/схемы C-строк), подлежит замещению;
- generic-тела эмитятся erased/по-mono с `current_type_subst: HashMap<String,String>`
  (имя→C-строка) — d119-класс загрязнений субституции пойман в 172.1
  receiver-instance-map'ом, но носитель остаётся строковым.

## Цель

Типизированное промежуточное представление между checker'ом и C-эмиссией:

1. **Узел IR несёт `ResolvedType`** (D315-канон), НЕ C-строку; C-имя выводится
   ТОЛЬКО в финальном принтере (`resolved_type_to_c` становится деталью принтера).
2. **Mono-инстанцирование на IR**: инстанс = (template, `Vec<ResolvedType>` args)
   — структурная identity, mangling лишь при печати. Убивает строковый
   `current_type_subst`, `generic_type_instance_info`-декодирование и
   `is_generic_stub_c`-эвристики.
3. **Замещение lifted-arms классом**: поднятые армы 6c–6z становятся
   IR-лоуэрингом (один узел — один типизированный лоуэринг), закрывая
   [M-172.1-lifted-legacy-arms] не поштучно.
4. **[M-array-vec-unify]**: NovaArray/Vec-раздвоение решается на IR-уровне
   (одно представление, два принтера → одно).

## Не-цели

- Оптимизации на IR (SSA/DCE) — отдельный горизонт; IR сначала как typed-carrier.
- Инкрементальность/query ([IDEA-172-incremental-queries]) — не здесь.

## Фазы (эскиз, детализация при старте)

- **Ф.0** Замер: инвентарь C-строковых identity-сайтов (grep `____`/`Nova_`-префиксов
  в решениях) — карта потребителей.
- **Ф.1** IR-типы: `IrExpr { kind, ty: ResolvedType, span }`; лоуэринг AST→IR
  ЧИТАЕТ канал (аннотации уже полны после 172.1).
- **Ф.2** Mono на IR: worklist инстансов (template, args:Vec<ResolvedType>);
  принтер манглит.
- **Ф.3** Перевод эмиттера на IR-вход посегментно (fn-тела → выражения →
  деклы), гейты 172.1-класса на каждый сегмент (conformance 38/38 + полный
  nova_tests baseline).
- **Ф.4** Снос строковых носителей (current_type_subst, instance_info-декод,
  stub-эвристики) + закрытие [M-172.1-lifted-legacy-arms].

## Критерии приёмки

- Ни одного решения по `contains("____")`/строковому префиксу вне принтера.
- [M-172.1-lifted-legacy-arms] закрыт (армы 6c–6z удалены, замещены IR-лоуэрингом).
- Гейты: conformance + полный nova_tests == baseline; перф не хуже (§2 замер).

### 3. Стыковка с 172.1 (что уже сделано; где разрыв)

172.1 закрыл **уровень ВЫРАЖЕНИЯ**: `resolved_types[ExprId] = ResolvedType` (D315-канон, lossless:
width/sign/effects-type-args/L1-L2-L3/module) + принтер `resolved_type_to_c(rt)` + каналы 1–6 в
`infer_expr_c_type`. Т.е. **типизированный носитель на выражениях уже есть** — это ровно Ф.1-цель
«узел несёт `ResolvedType`, C-имя выводится в принтере». D-status: D315 ✅, каналы+lifted-армы 6i–6z
подняты (tally 6224→338, −95%), `legacy_inner` = panic.

**РАЗРЫВ, который берёт 172.12 — уровень МОНО/ИНСТАНСА (всё ещё строковый):**
- `current_type_subst` / `mono_worklist.type_subst` / `generic_type_instance_info.args` /
  `current_receiver_type` несут **C-строки**, не `ResolvedType`. Принтер (`resolved_type_to_c`
  арм `TypeParam`/`Named`/`Tuple`/Array) вынужден **re-parse** этих строк (`trim_start_matches
  ("Nova_")`, `contains("____")`, `is_generic_stub_c`) — потому что источник mono-контекста
  строковый. Это корень «двух окон правды» (172.1.1 §1: bare vs mangled erased-контейнер;
  gap #2 mono-subst-timing) — субстратные блокеры 172.1.1 (SelfAccess/Ident флип, container-channel)
  **гейтнуты именно на строковость mono-субституции** (proxy `is_generic_stub_c` ложно срабатывает,
  `current_type_subst` не синхронен с контекстом).
- ⇒ **172.12 = поднять типизированность с выражения на инстанс**: `mono_worklist`/subst/instance-info
  несут `Vec<ResolvedType>` (структурная identity `(template, Vec<ResolvedType>)`), mangling —
  ТОЛЬКО в `compute_generic_type_c_name` при печати. Тогда принтер выводит bare/mangled из СОСТОЯНИЯ
  `ResolvedType` (concrete vs `TypeParam`), а не из re-parse C-строки → снимается proxy/`____`-decode
  → разблокируются subst-timing/erased-контекст блокеры 172.1.1 ПО ПОСТРОЕНИЮ.

### 4. Какие недавние фиксы 172.12 поглощает/упрощает

- **wave-4 «дыры кодогенератора» (`97100017`, базис):** (a) вывод type-args конструктора из
  аргументов [`M-176-generic-wrapper-mono-inference`] (`infer_expr_c_type` :39436 — эвристика по
  `current_type_subst` re-map C-строки), (b) value-record-ресивер generic-метод-return, (c)
  turbofish на методах в return-subst, (d) дедуп перегрузок по типам параметров. Все четыре —
  **строковые заплатки на mono-инференс** (re-parse `current_type_subst`/mangled). При структурной
  `(template, Vec<ResolvedType>)`-identity вывод type-args и subst-возврата — по типам, а не re-map
  строк ⇒ заплатки субсумируются (не удалять точечно — они уходят вместе с носителем).
- **D381 module-qualified mangling (`ce1b8758`/`d478e72a`):** коллизия одноимённых типов разных
  модулей решена квалификацией C-**имени**. `ResolvedType::Named{module,…}` уже несёт module
  (lossless) → при печати из носителя квалификация — деталь принтера (`resolved_named_to_c` :2513
  уже склеивает `module.join("_")`), НЕ строковая пост-обработка. 172.12 переносит D381-решение
  в единственный принтер, убирая расходящиеся строковые квалификации в потребителях.

### 5. Последовательность под-атомов (каждый — ЗЕЛЁНОЕ дерево, отдельный коммит)

Порядок = «принтер выводит из состояния → потом источник структурируем → потом сносим потребителей».
Направление §0 (единый носитель, не зеркала): двигаем НОСИТЕЛЬ к `ResolvedType`, потребители удаляем.

- **A0 (этот заход, Ф.0):** карта рисков (этот раздел) + верификация базиса 54/0. Коммит docs-only.
- **A1 (Ф.1-substrate):** ввести `IrMonoArg`/структурную identity инстанса — `generic_type_instance_info`
  и `mono_worklist`/`generic_type_worklist` несут `Vec<ResolvedType>` РЯДОМ с текущей C-строкой
  args (переходно), принтер `compute_generic_type_c_name` получает overload-из-`ResolvedType`.
  Гейт: byte-identical (принтер даёт те же C-имена) + 54/0 + широкий регресс δ0. **Keystone: это и
  есть носитель, не зеркало — C-строка args удаляется в A3, как только все продюсеры пишут RT.**
- **A2:** принтер `resolved_type_to_c` арм `TypeParam` (:2099) выводит subst из
  `Vec<ResolvedType>`-контекста (concrete→mangle, `TypeParam`-остаток→Err/erased) — убрать
  `is_generic_stub_c`/`contains("____")` ВНУТРИ принтера. Гейт: container-класс byte-identical
  (`NOVA_U45_RLCHECK`=0) + 54/0 + регресс δ0. Разблокирует SelfAccess/Ident флип (172.1.1) — но
  флип отдельным под-атомом (A2b) под soundness-гейтом.
- **A3:** `current_type_subst: HashMap<String,ResolvedType>` (был String) + снос C-строка-args из
  инстанс-реестров (продюсеры переведены в A1). Ripple ~139 сайтов — per-файл loop
  (check→fix→re-check), НЕ full-regress в цикле; финальный гейт 54/0 + регресс.
- **A4 (Ф.4):** снести потребительские `____`/`Nova_`-prefix решения (~140) — армы 6c–6z замещаются
  IR-лоуэрингом из носителя; `legacy_inner` уже panic → удалить поднятые дубли ([M-172.1-lifted-legacy-arms]
  закрыт). Гейт: полный nova_tests baseline + 54/0.
- **A5 ([M-array-vec-unify]):** NovaArray/Vec — один принтер из `R::Array` (`resolved_array_to_c`
  :2233 уже мост). После A2 (нет `is_generic_stub_c`) — механический.
