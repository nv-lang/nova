# План 244 — `Channel` на Nova поверх `extern "C"` (снос трёх ad-hoc веток кодогенератора)

> **Статус:** ⏸ ЖДЁТ АПРУВА ВЛАДЕЛЬЦА — план на чтении у владельца 2026-08-02, НЕ НАЧИНАТЬ без его слова. Запланирован 2026-08-02 (решение владельца: делать ДО тега,
> после окна рантайм-гонок Vela). Приоритет — К2 плана
> [221](221-release-v0-1.md) (барьер: «вторая дверь» на встроенном примитиве).

## Зачем

`Channel`/`ChanWriter`/`ChanReader` сегодня — **compiler-intrinsic без единого
`.nv`-объявления**: тела в C-рантайме, а сборка пары `(tx, rx)` держится на
**трёх написанных вручную ветках в кодогенераторе**
(`[M-59.1-channel-new-cleanup]`). Это прямое нарушение нормы «одна дверь» и
конвенции «компилятор берёт типы и функции из `.nv` по максимуму, в Rust —
только непортируемое».

Прежний план закрытия упирался в [115](115-ptr-type-and-tuple-ffi.md)
(кортежный возврат через FFI, статус `🆕 PLANNED`). **Зависимость снята
решением владельца 2026-08-02:** кортеж через границу C не нужен вовсе —
каждая внешняя функция возвращает ОДНО значение, а пару собирает обычный код
на Nova, который кортежи уже умеет.

## Почему `extern "C"`, а не `extern "nova"`

- `extern "C"` — чистый сишный символ, ноль участия компилятора. В std так
  сделана файловая система (`fs_open`/`fs_read`/`fs_close` + обёртка-тип на
  Nova); блокирующие операции через эту форму работают (парковка файбера —
  забота рантайма, не вызывающего).
- `extern "nova"` — форма, которую диспетчит кодогенератор; нужна ради
  методов на типах, перегрузок и дженериков (379 из 456 объявлений в std —
  именно такие).
- Здесь методы и дженерики пишутся **на Nova поверх сырого слоя**, поэтому
  компиляторная магия не требуется. Берём `extern "C"` — меньше магии,
  ближе к «одной двери». Образец: `std/src/fs/`.

## Представление

Ручка — непрозрачный указатель как newtype (образец: `type Mutex(*())` в
`std/src/runtime/sync.nv`). Сторон **две**: в рантайме уже сейчас разные
объекты `Nova_ChanWriter` и `Nova_ChanReader` поверх общего буфера, и `close`
у них разный по смыслу.

**Не экспортируются** (правка владельца 2026-08-02): `ChanBuf`/`ChanTx`/
`ChanRx` — детали реализации, наружу видны только `Channel`, `ChanWriter[T]`,
`ChanReader[T]`.

**`#share` — только на сторонах, что пересекают границу файбера** (правка
владельца + обоснование D415): тип, оборачивающий сырой указатель, «отравлен»
(poison base), и захват его в `spawn` отклоняется энфорсом S1a — снять запрет
может ТОЛЬКО собственное ручательство `#share` содержащего типа. Стороны
канала захватываются в файберы по своему назначению, поэтому ручательство
обязательно; `ChanBuf` в файбер не уходит (живёт только внутри `Channel.new`)
— ему `#share` не нужен. Где именно ставить ручательство — на внутреннем
`ChanTx`/`ChanRx` или на публичных `ChanWriter[T]`/`ChanReader[T]` — решается
ПРОБОЙ в Ф.2 (распространяется ли отравление через поле вouched-типа), а не
рассуждением.

```nova
module std.concurrency.channel

/// Сторона записи. #share — ручательство D415: тип уходит в файбер.
#share
type ChanTx(*())

/// Сторона чтения.
#share
type ChanRx(*())
```

Отдельного типа для буфера НЕТ (правка владельца 2026-08-02): буфер целиком
внутри рантайма, наружу видны только две стороны, которые на него ссылаются.

## Сырой слой — `extern "C"`, создание через out-параметры

**Канал — первый образец типизированных FFI-ручек (№288).** Проба интегратора
2026-08-02: newtype над `*()` уходит в C как `typedef void* Nova_ChanTx` и
передаётся напрямую; `unsafe` для такого вызова НЕ требуется. Поэтому сырой
слой принимает `ChanTx`/`ChanRx`, а не голые `*()` — писателя нельзя передать
туда, где ждут читателя. В std этого приёма пока нет ни разу (все `extern "C"`
на примитивах и сырых указателях) — канон устанавливается здесь, миграция
остальных сайтов идёт после тега (см. №288).

Форма владельца (2026-08-02): **один** вызов вместо трёх, обе стороны
возвращаются через out-параметры. Это штатная сишная идиома для нескольких
результатов, и она уже используется в нашей же std —
`fs_realpath_into(path *u8, out_err *mut int) -> str`.

```nova
// Создание. elem_size — размер элемента; буфер выделяется как cap*elem_size,
// поэтому ограничение «T должен быть размером со слово» снимается вместе с
// ограждением E_CHANNEL_UNSOUND_ELEM_TYPE.
// align_of НЕ передаём: sizeof(T) всегда кратен alignof(T), а база выделения
// выровнена под любой тип (см. §Риски п.1).
extern "C" fn chan_new(cap int, elem_size int, out_tx *mut ChanTx, out_rx *mut ChanRx) -> ()

// Передача элемента — по указателю на значение (src/dst), длина известна
// буферу. Копирование делает рантайм.
extern "C" fn chan_tx_send(tx ChanTx, src *u8) -> bool
extern "C" fn chan_tx_try_send(tx ChanTx, src *u8) -> bool
extern "C" fn chan_rx_recv(rx ChanRx, dst *mut u8) -> bool      // false = закрыт и пуст
extern "C" fn chan_rx_try_recv(rx ChanRx, dst *mut u8) -> bool

extern "C" fn chan_tx_close(tx ChanTx) -> ()
extern "C" fn chan_rx_close(rx ChanRx) -> ()
extern "C" fn chan_tx_is_closed(tx ChanTx) -> bool
extern "C" fn chan_rx_is_closed(rx ChanRx) -> bool
extern "C" fn chan_rx_close_after(rx ChanRx, millis i64) -> ()
extern "C" fn chan_tx_share(tx ChanTx) -> ChanTx                // ref-счёт +1
extern "C" fn chan_len(rx ChanRx) -> int
extern "C" fn chan_cap(rx ChanRx) -> int
```

## Публичный слой — обычный Nova

```nova
export type ChanWriter[T](ChanTx)
export type ChanReader[T](ChanRx)

/// Пара собирается ЗДЕСЬ, обычным кортежом Nova — кортеж границу C не пересекает.
#stable(since = "0.1")
export fn Channel[T].new(cap int) -> (ChanWriter[T], ChanReader[T]) {
    mut tx uninit ChanTx
    mut rx uninit ChanRx
    unsafe { chan_new(cap, size_of[T](), &tx as *mut ChanTx, &rx as *mut ChanRx) }
    unsafe { (ChanWriter[T](tx as ChanTx), ChanReader[T](rx as ChanRx)) }
}

// --- сторона записи ---
export fn ChanWriter[T] @send(consume v T) -> bool =>
    unsafe { chan_tx_send(@, &v as *u8) }          // consume — владение уходит (D131/№144)

export fn ChanWriter[T] @try_send(consume v T) -> bool =>
    unsafe { chan_tx_try_send(@, &v as *u8) }

export fn ChanWriter[T] @close() -> ()        => chan_tx_close(@)
export fn ChanWriter[T] @is_closed() -> bool  => chan_tx_is_closed(@)
export fn ChanWriter[T] @share() -> ChanWriter[T] =>
    ChanWriter[T](chan_tx_share(@))

// --- сторона чтения ---
export fn ChanReader[T] @recv() -> Option[T] {
    mut slot = T.uninit()                             // см. §Открытые вопросы п.2
    unsafe { if chan_rx_recv(@, &slot as *mut u8) { Some(slot as T) } else { None } }
}

export fn ChanReader[T] @try_recv() -> Option[T] {
    mut slot = T.uninit()
    unsafe { if chan_rx_try_recv(@, &slot as *mut u8) { Some(slot as T) } else { None } }
}

export fn ChanReader[T] @close() -> ()        => chan_rx_close(@)
export fn ChanReader[T] @is_closed() -> bool  => chan_rx_is_closed(@)
export fn ChanReader[T] @close_after(d Duration) -> () =>
    chan_rx_close_after(@, d.as_millis())
```

Разделение типов даёт безопасность как следствие системы типов, а не как
особый случай в компиляторе: писатель физически не имеет метода `recv`,
читатель — `send`.

## `select { … }` — форма языка поверх публичного слоя (разбор с владельцем 2026-08-02)

**Изначально в план не входил — пробел, вскрыт владельцем.**

### Почему форма остаётся в компиляторе

`select` нельзя записать вызовом функции: у него ветви с телами и
связыванием переменных. Но это НЕ значит, что компилятор обязан знать
внутренности канала. Прямая аналогия — `for x in v { … }`: тоже форма языка,
но разворачивается в обычные вызовы протокола итератора, а внутренности
`Vec` компилятору неизвестны. С `select` делаем так же: **форма остаётся,
знание о канале уходит**.

### Ключевой момент: регистрация ≠ забор значения

Опасение владельца — «нужно выбрать одного победителя, а из остальных
каналов значения не забирать» — снимается разделением на два шага.

**Шаг 1, регистрация.** `chan_select_arm_recv(ctx, i, rx, dst)` НЕ трогает
очередь канала. Она лишь записывает: «ветвь номер i ждёт на этом канале,
и если ей достанется значение — положить его по адресу dst». Ни одно
значение при регистрации не извлекается.

**Шаг 2, розыгрыш.** `chan_select_wait(ctx)` делает следующее:

1. Обходит ветви **в случайном порядке** и проверяет, нет ли уже готовых.
   Перемешивание — Фишера-Йетса, УЖЕ реализовано в рантайме
   (`nova_select_try_immediate`, `_nova_sel_rng`), семантика как в Go:
   случайность нужна против голодания, иначе первая ветвь всегда съедала бы
   вторую.
2. Если готовая нашлась — значение забирается **только из неё одной**,
   копируется по её `dst`, регистрации с остальных каналов снимаются.
   Возвращается индекс ветви.
3. Если готовых нет — файбер паркуется. Дальше атомарность обеспечивает
   рантайм: первый пришедший отправитель выигрывает CAS на поле `fired`
   ожидателя и передаёт своё значение прямо в слот этой ветви; все
   опоздавшие видят, что ожидатель уже сработал, и проходят мимо, СОХРАНИВ
   своё значение в своём канале (`_nova_select_fire_lost`). Победитель
   ровно один по построению.
4. При пробуждении регистрации снимаются со всех каналов.

Ничего из этого не надо изобретать — так рантайм работает и сегодня. План
лишь выводит эти шаги наружу как обычные функции.

### Сырой слой для select

```nova
type SelectCtx(*())

extern "C" fn chan_select_new(n_arms int) -> SelectCtx
extern "C" fn chan_select_arm_recv(ctx SelectCtx, i int, rx ChanRx, dst *mut u8) -> ()
extern "C" fn chan_select_arm_send(ctx SelectCtx, i int, tx ChanTx, src *u8) -> ()
extern "C" fn chan_select_wait(ctx SelectCtx) -> int   // индекс победившей ветви, блокирует
extern "C" fn chan_select_poll(ctx SelectCtx) -> int   // то же без блокировки; -1 = никто не готов
```

### Разворачивание формы

```nova
select {
    Some(v) = rx     => handle(v)
    tx <- payload    => sent()
    default          => busy()
}
```

компилятор разворачивает в обычный код:

```nova
ro ctx = chan_select_new(2)
mut slot uninit T
chan_select_arm_recv(ctx, 0, rx.handle(), &slot as *mut u8)   // регистрация, не забор
chan_select_arm_send(ctx, 1, tx.handle(), &payload as *u8)
ro which = chan_select_poll(ctx)      // chan_select_wait(ctx), если ветви default нет
if which == 0 {
    ro v = unsafe { slot as T }
    handle(v)
} else if which == 1 {
    sent()
} else {
    busy()
}
```

Компилятор знает про канал ровно одно: как позвать эти пять функций.
Ни заглядывания в структуру буфера, ни ad-hoc веток.

### Следствия — обязаны попасть в фикстуры

1. **Тип элемента в принимающей ветви.** `T` берётся из `ChanReader[T]`,
   слот объявляется той же формой `mut x uninit T`. До этого плана `T` в
   ветви был стёрт ровно как в `recv` (№286).
2. **Снятие ограждения касается и `select`.** `E_CHANNEL_UNSOUND_ELEM_TYPE`
   проверяется и на ветвях; иначе получится нелепость — `recv` над каналом
   строк работает, а `select` над тем же каналом не компилируется.
3. **Ратчет считать итогом.** Правка разворачивания — строки в `emit_c`.
   Цель Ф.3 «ратчет вниз» остаётся, но итог = минус три ad-hoc ветки
   `Channel.new`, плюс-минус правка `select`. Итог вверх — объяснить
   построчно в летописи baseline, не прятать.

Фикстуры (Ф.4): `select` над `Channel[str]` и над каналом записей (сегодня
невозможно); принимающая ветвь связывает значение правильного типа —
одиночно И в сборном compile-unit (регресс на находку окна s1b);
отправляющая ветвь; ветвь по умолчанию; таймаут через `close_after`;
**отдельно — проверка, что проигравшие ветви НЕ теряют значения**: два
готовых канала, `select` в цикле дважды подряд обязан выдать оба значения.

## Фазы

- **Ф.1 — сырой слой.** Экспортировать перечисленные `chan_*` символы из
  `nova_rt/channels.h` (сегодня часть — `static inline`), добавить в буфер
  поле `elem_size` и байтовое хранение вместо словного слота. Прогон:
  существующие channel-фикстуры зелёные на СТАРОМ пути (сырой слой ещё не
  подключён к языку).
- **Ф.2 — `.nv`-модуль** по декларациям выше; `Channel.new`/`send`/`recv`
  идут через него.
- **Ф.3 — снос трёх ad-hoc веток** `Channel.new` в кодогенераторе + снятие
  ограждения `E_CHANNEL_UNSOUND_ELEM_TYPE` (после Ф.1 оно беспредметно).
  Ratchet обязан пойти ВНИЗ — это цель фазы, а не побочный эффект.
- **Ф.4 — расширение типов элементов:** фикстуры на `str`, `f64`,
  многополевую значимую запись — то, что ограждение запрещало.
- **Ф.5 — дока и спека:** `docs/guide/channels.md` (сейчас описывает
  ограничение word-safe), D79/D91-соседство — тем же слиянием.

## Что МОЖНО передавать через `extern "C"` (вопрос владельца про `str`)

`extern "C" fn fs_realpath_into(...) -> str` — **легально**, это не дыра.
`str` в C-мире — обычная структура из двух слов, объявленная в заголовке
рантайма: `typedef struct { const uint8_t* ptr; int64_t len; } nova_str;`
(`nova_rt/nova_rt.h`). Сишная сторона включает этот заголовок и возвращает
структуру по значению (`nova_str fs_realpath_into(...)` в `nova_rt/fs.c`).
Таких объявлений в std десять.

Правило, которое отсюда следует: через границу проходит любой тип с
**фиксированным, объявленным в заголовке представлением**. Кортеж таким
представлением не обладает — у него нет сишного typedef, ABI возврата
кортежа не зафиксирован; ровно поэтому кортежный FFI и вынесен в отдельный
план [115](115-ptr-type-and-tuple-ffi.md), а `str` работает без него.

Для канала это ничего не меняет: сырой слой обходится указателями,
целыми и `bool`, пару собирает Nova.

## Форма взятия адреса

Канон — только `&x` (D9, «одна дверь»). `addr_of(x)`/`addr_of_mut(x)`
существовали как Zig-стиль алиасы (план 118.1) и **ретрактированы** планом
118.6 — сегодня дают `E_ADDR_OF_REMOVED`. Отдельного `_mut`-варианта не
нужно: `&x` сама выбирает `*T` или `*mut T` по связывающей стороне
(`ro p = &x` → `*T`; `mut p = &x` при `mut x` → `*mut T`).

## Риски и что проверить прямым тестом (не рассуждением)

1. **Выравнивание области данных.** Шаг `size_of[T]()` выравнивание не ломает
   (размер кратен выравниванию), но если данные лежат сразу за заголовком
   одного выделения — смещение может быть невыровненным. Решение: отдельное
   выделение под данные либо выравнивание смещения. Проверка: элемент с
   выравниванием 8 в канале, чтение/запись без падения.
2. **Сборщик мусора.** При байтовом хранении буфер обязан оставаться в
   GC-куче, иначе положенная в канал запись со ссылками может быть собрана,
   пока лежит в очереди. Консервативный Boehm к раскладке безразличен, так
   что это выполнимо. **Обязательный тест:** положить запись со ссылками,
   спровоцировать сборку, забрать, убедиться в целостности.
3. **Парковка файбера через `extern "C"`.** Блокирующие `send`/`recv` паркуют
   файбер. Образец `fs_read` показывает, что блокирующая операция через
   `extern "C"` работает, но проверить под M:N с миграцией между потоками.
4. **`#share` и D415.** Стороны канала помечены `#share` — под энфорсом S1a
   это разрешает их захват в файбер. Проверить, что это по-прежнему так и что
   `consume`-семантика `send` (№144) не сломана: use-after-send обязан
   отклоняться.

## Открытые вопросы (решаются в окне, выносятся владельцу отдельно)

1. **Автоматическое закрытие.** Привязывать ли `close` к авто-очистке
   (`@cleanup`, D432), чтобы забытый писатель закрывался при выходе из
   области видимости? Меняет наблюдаемое поведение — решение владельца.
2. **Приём значения без инициализации — РЕШЕНО ВЛАДЕЛЬЦЕМ 2026-08-02.**
   Форма привязки:

   ```nova
   mut x uninit T          // возможно-неинициализированное значение T
   ```

   Закрывает ОБА места разом: out-параметры `chan_new` и слот под `recv`.

   Зануление — РЕШЕНО (владелец 2026-08-02): `uninit` зануляет память,
   цена — один `memset` на слот, поведение детерминированное и GC-чистое.

   Форма вызова (владелец 2026-08-02):

   ```nova
   export fn Channel[T].new(cap int) -> (ChanWriter[T], ChanReader[T]) {
       mut tx uninit ChanTx
       mut rx uninit ChanRx
       unsafe { chan_new(cap, size_of[T](), &tx as *mut ChanTx, &rx as *mut ChanRx) }
       unsafe { (ChanWriter[T](tx as ChanTx), ChanReader[T](rx as ChanRx)) }
   }

   export fn ChanReader[T] @recv() -> Option[T] {
       mut slot uninit T
       unsafe {
           if chan_rx_recv(@, &slot as *mut u8) { Some(slot as T) } else { None }
       }
   }
   ```

   **Язык-меняющее — D-амендмент ТЕМ ЖЕ слиянием** (стоячее правило).
   Два вопроса, которые обязаны решиться вместе с формой (мой разбор,
   решение — владельца):

   а) **Чтение до записи — УЖЕ РЕШЕНО В СПЕКЕ, амендмент не нужен.**
   `E_UNSAFE_T_NARROW_REQUIRES_UNSAFE` (D216 §V2.3b, план 118.5 V2; сиблинг
   `E_UNSAFE_ARG_REQUIRES_WRAP`): явное сужающее приведение `x as T`, где
   `x` — `uninit T`-привязка, а `T` — обычный тип, ВНЕ `unsafe`-блока —
   ошибка. Снятие: `unsafe { x as T }` — вызывающий явно берёт валидность
   значения на себя. Второй путь: объявить принимающую сторону тоже как
   `uninit T`, тогда приведение не нужно вовсе (типы совпадают).
   Цепочка по D-номеру: D216 (базовая модель модификаторов) → §V2.3b
   (сам код ошибки) → §10a (план 174.5, переименование `unsafe T` →
   `uninit T`, семантика гейта не менялась).
   Проверено интегратором: код ошибки живёт в `types/mod.rs`.
   **Следствие для примеров выше:** приведения `tx as ChanTx` /
   `slot as T` обязаны стоять внутри `unsafe`-блока — в кодe плана
   поправлено.

   б) **Мусор в слоте и сборщик — РЕШЕНО: занулять** (см. выше).
   Исходный разбор: Консервативный Boehm сканирует стек: в
   неинициализированной ячейке лежат старые байты, которые он может принять
   за указатели. Порчи не будет (консервативный сборщик к ложным
   срабатываниям устойчив), но возможно удержание мусора. Предлагаю
   `uninit` ЗАНУЛЯТЬ память: цена — один `memset` на слот, зато поведение
   детерминированное и GC-чистое. Если владелец хочет истинный `uninit`
   без зануления — записать это явно как осознанный компромисс.
