# Plan 196.2 — релокация class-C резолюции из `infer_call_ret_c` в чекер

**Родитель:** [196-one-truth-closeout.md](196-one-truth-closeout.md) (Ф.S1b). **Грунтовка:**
разведка 2026-07-12 (карта `infer_call_ret_c`). **Статус:** 📋 план, ожидает go на исполнение.

## Цель

Удалить `infer_call_ret_c` (`emit_c.rs:46293-48883`, **2591 стр**, class-C generic-method-return
mono — крупнейший кусок второго окна) переносом его резолюции в чекер + материализацией в
`resolved_types`. `infer_call_ret_c` — **fallback** (срабатывает только когда Channel-1/2 пусты),
кончается тремя `panic!("[P67-LEGACY]")` (не тихий `nova_int`).

## Метод — ПОРТ, не переизобретение (директива владельца 2026-07-12)

`infer_call_ret_c` уже умеет ВСЁ в том или ином виде. **Переносим готовые алгоритмы на новые
рельсы, НЕ пишем резолв заново:**
1. Взять логику под-случая из `infer_call_ret_c` (как он резолвит этот вид возврата).
2. **Адаптировать фазу:** codegen работает POST-mono и выдаёт C-строку через `type_ref_to_c`;
   чекер работает PRE-mono → выдаёт `ResolvedType` (с `TypeParam`, mono подставит позже в
   `resolved_type_to_c:3203`). То есть меняется НЕ алгоритм, а носитель (C-строка → ResolvedType)
   и место (codegen → `f1_expr_inner`).
3. **Материализовать** результат в `resolved_types_buf.insert(Call.expr.id, rt)` (§1 «материализуй,
   не выбрасывай»).
4. **УДАЛИТЬ** соответствующий под-случай из `infer_call_ret_c`. Сжимающийся fallback держит
   непере­несённое рабочим (strangler-fig).

De-risk: алгоритмы проверены (компилятор работает). Единый C-лоуеринг `resolved_type_to_c:3184`
уже есть — цель, чтобы Call лоуэрился через него, а не через `type_ref_to_c`+string-склейку.

## ★ Фазовая дисциплина — PRE-mono резолв (чекер) vs POST-mono подстановка (codegen). НЕ СБИТЬСЯ.

> **Чекер резолвит ГЕНЕРИК-шаблон (PRE-mono, с `TypeParam`). Codegen подставляет mono (POST-mono).
> Эту границу НЕ двигать. §0 = ПОЛНОТА generic-`resolved_types`, а НЕ перенос mono в чекер.**

Строго по фазам (по коду, арх-карта §3/§5):
- **Чекер (PRE-mono):** резолвит тип возврата Call в **`ResolvedType` с `TypeParam`-носителями**
  (шаблон; generics ещё НЕ подставлены). Материализует в `resolved_types[Call.id]`. Это template-правда.
- **Codegen (POST-mono, лениво):** `resolved_type_to_c` (emit_c:3184) читает generic `ResolvedType`
  + `current_type_subst` → **подставляет `TypeParam`→конкретика** (3203-3237) → C-тип. Mono-подстановка
  живёт ЗДЕСЬ, НЕ в чекере.
- **Mono-registration side-effect** (`register_generic_instances_in_typeref`, 46995/43205) знает
  КОНКРЕТНЫЙ инстанс → остаётся в codegen (emit-пасс), НЕ переезжает в чекер (чекер generic, инстанса
  не знает). При порте — вынести регистрацию в отдельный emit-пасс ДО удаления арма (§1-риск W1).

**Правило порта (чтоб не сбиться):** `infer_call_ret_c` делает резолв+подстановку+регистрацию ВМЕСТЕ
(post-mono, C-строка). В чекер переносим **ТОЛЬКО РЕЗОЛВ → generic `ResolvedType` (с `TypeParam`)**.
Подстановку НЕ переносим (она уже в `resolved_type_to_c`). Регистрацию НЕ переносим в чекер (в emit-пасс).

**Anti-стрелка (стоп-сигнал):** если чекер начал производить КОНКРЕТНЫЙ (mono'd) тип вместо
generic-с-`TypeParam` — СТОП: ты тащишь mono в чекер. Перенос mono в чекер (post-mono типизированный
IR) — это **Стадия 2 (MIR, в-full), НЕ §0.** Здесь чекер резолвит ШАБЛОН, codegen подставляет.

## Правило: баг/улучшение → в НОВЫЙ путь, не в legacy (директива владельца, §10)

> **Любой баг или улучшение в зоне резолюции Call-возврата чинится/вносится в ЧЕКЕР+`resolved_types`
> (новый путь), а НЕ в `infer_call_ret_c` (legacy). Той же правкой удаляется legacy-эквивалент.**

Патч legacy = углубление долга, который мы убираем (§10 анти-паттерн «band-aid старого пути»).
Следствие: **починка бага = прогресс миграции** (фикс в новом пути + снятие legacy одной правкой).
Исключение — только если legacy-правка временно разблокирует срочное И помечена `[M-*]` с планом
переноса (§4а), но по умолчанию — в новый путь.

## Правило: удалить ИЛИ паника — НИКОГДА тихий legacy-fallback (директива владельца 2026-07-12)

> **Перенос фичи в `resolved_types` обязан ПОЛНОСТЬЮ брать исполнение в объёме перенесённой фичи.
> В `infer_call_ret_c` для этой фичи код либо УДАЛЁН, либо (если удалить чисто нельзя — переплетено с
> соседними ветками) ЗАМЕНЁН на `panic!("[MIGRATED-<фича>] должно резолвиться через resolved_types")`.
> Тихий legacy-fallback для «перенесённой» фичи ЗАПРЕЩЁН — это ловушка co-authority (два окна сосуществуют).**

- **Паника = enforcement полного перехвата** (§4 нет тихого fallback, §7.13 инвариант = enforced код):
  сработала на корпусе (conformance/std) → новый путь НЕ полон, дыра → чинить в чекере. Не сработала →
  фича целиком на новом пути → panic'd мёртвый код удаляется (тогда строки убывают).
- **Метрика при панике:** ветка «нейтрализована» (удалена ИЛИ заменена паникой) = фича перенесена
  (счётчик веток / ~114-130). Финальное убывание строк — по мере удаления доказанно-мёртвого panic-кода
  (панику НИКОГДА не пробило по корпусу).
- Это нативный паттерн: `infer_call_ret_c` УЖЕ кончается `panic!("[P67-LEGACY]")` для непокрытого — тут
  то же, но для ПЕРЕНЕСЁННОГО (upstream обязан был обработать). Предпочтение — прямое удаление; паника —
  когда переплетение мешает чистому удалению одним атомом.

## Гранулярность — АТОМЫ по 1-2 часа (директива владельца 2026-07-12)

> **Каждая волна МАКСИМАЛЬНО декомпозируется на атомы. Атом закрывается за 1-2 часа, один
> коммит, и приносит ИЗМЕРИМЫЙ эффект приближения к цели (гейт-1: Δстрок `infer_call_ret_c` < 0).**

- **Атом = ОДНА алгоритмическая ФОРМА резолюции (общая способность чекера), НЕ имя метода.**
  ⚠️ Дробить по ФОРМЕ, а НЕ по имени: `map`/`filter`/`collect` отдельно = per-method хардкод
  (§3-нарушение, перенос хардкода вместо общего резолва). Правильные атомы-по-форме:
  method-generic bare `-> U` из closure-return (покрывает map И любой `@m[U](f)->U`); non-bare
  `-> []U`/`-> Option[U]` (снять bail 13711); container-element из receiver-`T` (get/pop/first
  единообразно); generic-instance с receiver-generic-подстановкой; multi-overload-generic disambig.
  Каждый атом покрывает КЛАСС методов одним путём (резолв `Vec.map` == user-`Stack.map`, §3).
- Атом = порт одной ФОРМЫ → материализация в `resolved_types` → удаление legacy-обработки этого
  класса → замер гейт-1 → коммит. Если ловишь `if method=="map"` — неверная гранулярность.
- **Атом без измеримого убывания строк = НЕ атом** — либо дробить мельче, либо это не перенос.
- Прогресс к цели виден каждый час-два (снятые строки), а не «через месяц». Это анти-«месяц co-authority».

## Риски (из карты)

- **★ Side-effects в inference (§1).** `infer_call_ret_c` при резолве РЕГИСТРИРУЕТ mono-инстансы/worklist
  (A:46356, F0/Array/Tuple в `resolved_type_to_c`). При переносе резолва в чекер — регистрация ДОЛЖНА
  переехать в отдельный emit-пасс, иначе mono-инстанс не эмитится → CC-FAIL. Ключевой риск W1/W2.
- **Дублирующий C-лоуеринг** `type_ref_to_c` (legacy) vs `resolved_type_to_c` (цель). Per-case доказать
  `resolved_type_to_c(from_type_ref(tr)) == type_ref_to_c(tr)` (точка дивергенции — `Ref`/`Mut`-стрип §4).
