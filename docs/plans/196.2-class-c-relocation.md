# Plan 196.2 — релокация class-C резолюции из `infer_call_ret_c` в чекер

**Родитель:** [196-one-truth-closeout.md](196-one-truth-closeout.md) (Ф.S1b). **Грунтовка:**
разведка 2026-07-12 (карта `infer_call_ret_c`). **Статус:** 📋 план, ожидает go на исполнение.

## Цель

Удалить `infer_call_ret_c` (`emit_c.rs:46293-48883`, **2591 стр**, class-C generic-method-return
mono — крупнейший кусок второго окна) переносом его резолюции в чекер + материализацией в
`resolved_types`. `infer_call_ret_c` — **fallback** (срабатывает только когда Channel-1/2 пусты),
кончается тремя `panic!("[P67-LEGACY]")` (не тихий `nova_int`).

## Метод — ПОРТ, не переизобретение (директива владельца 2026-07-12)

`infer_call_ret_c` уже умеет ВСЁ в том или ином виде. **Переносим готовые алгоритмы на новые
рельсы, НЕ пишем резолв заново:**
1. Взять логику под-случая из `infer_call_ret_c` (как он резолвит этот вид возврата).
2. **Адаптировать фазу:** codegen работает POST-mono и выдаёт C-строку через `type_ref_to_c`;
   чекер работает PRE-mono → выдаёт `ResolvedType` (с `TypeParam`, mono подставит позже в
   `resolved_type_to_c:3203`). То есть меняется НЕ алгоритм, а носитель (C-строка → ResolvedType)
   и место (codegen → `f1_expr_inner`).
3. **Материализовать** результат в `resolved_types_buf.insert(Call.expr.id, rt)` (§1 «материализуй,
   не выбрасывай»).
4. **УДАЛИТЬ** соответствующий под-случай из `infer_call_ret_c`. Сжимающийся fallback держит
   непере­несённое рабочим (strangler-fig).

De-risk: алгоритмы проверены (компилятор работает). Единый C-лоуеринг `resolved_type_to_c:3184`
уже есть — цель, чтобы Call лоуэрился через него, а не через `type_ref_to_c`+string-склейку.

## Правило: баг/улучшение → в НОВЫЙ путь, не в legacy (директива владельца, §10)

> **Любой баг или улучшение в зоне резолюции Call-возврата чинится/вносится в ЧЕКЕР+`resolved_types`
> (новый путь), а НЕ в `infer_call_ret_c` (legacy). Той же правкой удаляется legacy-эквивалент.**

Патч legacy = углубление долга, который мы убираем (§10 анти-паттерн «band-aid старого пути»).
Следствие: **починка бага = прогресс миграции** (фикс в новом пути + снятие legacy одной правкой).
Исключение — только если legacy-правка временно разблокирует срочное И помечена `[M-*]` с планом
переноса (§4а), но по умолчанию — в новый путь.

## Число фич (счётчик миграции)

**~27-30 логических под-каналов** в **7 группах** поверх **~114 return-веток** (`infer_call_ret_c`):
A (turbofish static-ctor) · B (fn-field call) · C (protocol/synth/NovaBox) · D1-D5 (multi-overload
method, 807 стр) · E1-E7 (Ident: free-fn/variant/closure/generic-fn, 400 стр) · F0-F13 (instance-
method-on-typed-recv, 926 стр) · G (Path static, 250 стр). **2 уже сняты** (ProtocolLit/HandlerLit,
Ф.S1a `e93fafd07`/`d45b564d6`). Счётчик закрытия = снятые под-каналы + Δстрок → 0.

## Гранулярность — АТОМЫ по 1-2 часа (директива владельца 2026-07-12)

> **Каждая волна МАКСИМАЛЬНО декомпозируется на атомы. Атом закрывается за 1-2 часа, один
> коммит, и приносит ИЗМЕРИМЫЙ эффект приближения к цели (гейт-1: Δстрок `infer_call_ret_c` < 0).**

- **Атом = ОДИН узкий под-случай.** Большой под-канал дробится: D1 → отдельно `map`, отдельно
  `filter`, отдельно `collect`. F9 → отдельно `push`/`pop`/`get`. Не «весь D1 разом».
- Атом = порт одного алгоритма → материализация в `resolved_types` → удаление его legacy-обработки
  → замер гейт-1 → коммит.
- **Атом без измеримого убывания строк = НЕ атом** — либо дробить мельче, либо это не перенос.
- Прогресс к цели виден каждый час-два (снятые строки), а не «через месяц». Это анти-«месяц co-authority».

## Волны — HARDEST-FIRST (директива владельца: «наоборот»)

Тяжёлое class-C ядро ПЕРВЫМ — де-риск главного шеста + крупнейшее убывание строк раньше.
Волна = ГРУППА атомов (см. гранулярность). **Приёмка КАЖДОГО атома включает удаление legacy-строк (гейт-1).**

- **W1 — generic-mono INSTANCE (ядро, самое тяжёлое, ResolvedType-native).** D1+D3+F2+F9
  (`v.map(f).filter(g)`, `xs.iter().collect()`, generic-instance-method, container-method elem-mono).
  Портировать: расширить `resolve_instance_method_return_arity`/`resolve_method_return_with_closure_args`
  — снять bail на не-bare `-> []U`/`-> Option[U]` (mod.rs:13711), multi-stmt closure-body (14127),
  multi-overload-generic; нести `ResolvedType` ПО ЦЕПОЧКЕ (обойти §4-лосс `[]T↔Vec` в chained-receiver).
  **Δ ≈ −600 стр.** Идентично lite/full. Взятие W1 = доказательство осуществимости всего плана.
- **W2 — generic-mono FREE-FN + static-mono.** E6 (остаток после чекерского U4-inference),
  A+F0+G-static (снять bail `recv.kind!=Instance` 13674, static-return-резолвер в чекер;
  **mono-instance-регистрацию side-effect перенести в emit-пасс, НЕ в inference** — §1/риск). **Δ ≈ −500 стр.**
- **W3 — blanket / Vtable / recursive-mono / serde / D-хвосты.** D2/D4/D5 остаток, F11 (Vtable),
  F13 (serialize/opaque/recursive-mono Plan 186), G-serde, C (protocol-shadowing/NovaBox). **Δ ≈ −400+ стр.**
- **W4 — variant-ctor + closure-value + newtype.** E2 (Ok/Err/user-sum-mono), E3/E7/B (closure-value
  calls), E5 (newtype/external-free-fn), F6 (Opt/Result method-return). **Δ ≈ −300 стр.**
- **W5 — builtin-интринсики фикс-возврат (лёгкий mop-up, wire-аннотация).** F3 (ptr-ops), F4/F5
  (Channel/Sender/StringBuilder/…), F7 (from_bytes), F8 (effect-name), F10 (math/str-int), G-builtins.
  Round-trip чист (§4). Материализация declared-return из `external_registry`/`primitive_instance_method_known`.
  **Δ ≈ −500 стр.**
- **W6 — тривиальное + ФИНАЛ.** E1 (`println`→Unit), F1 (`.clone()`→receiver), B (fn-field). Затем:
  `infer_call_ret_c` пуст (три P67-panic'а недостижимы) → **удалить функцию + оба call-site**
  (49447, 50652); Channel-6q схлопывается в `resolved_type_to_c(resolved_types[id])`. **Δ → остаток до −2591.**

## Приёмка (КАЖДОГО пункта/волны)

1. ★ **Удаление legacy (гейт-1, обязателен per-АТОМ) — метрика:**
   - **ГЛАВНОЕ число: `wc -l` тела `infer_call_ret_c`** (46293→конец). Строго убыло каждый атом.
     0 снято = КРАСНЫЙ атом, стоп. **Конечная точка = ~0 строк → функция удалена = §0-цель.**
   - **Спутник: под-каналов закрыто, X из ~27-30** (структурный трекер — закрываем тяжёлое ядро,
     не дешёвую периферию). Опционально ветки из ~114.
   - **Сквозной: `wc -l infer_expr_c_type`** (общая §0-цель, вся функция → тонкий лоуеринг).
   - hardest-first выравнивает строки с трудностью (ядро D1/D3/F9/E6/F0 ≈ 1900/2591 строк), поэтому
     крупное убывание строк рано = тяжёлое сделано рано — метрика не обманывает.
2. **Полнота канала:** для каждого снятого под-случая чекер кладёт `ResolvedType` на `Call.expr.id`,
   т.ч. `resolved_type_to_c` даёт тот же C, что удаляемый legacy-арм.
3. **Byte-parity (встроенная страховка):** emitted `.c` byte-identical vs clean baseline (same-binary
   control отсекает `[M-codegen-emission-nondeterminism]`). Расхождение → чинишь материализацию,
   fallback ловит (не паникует). Спайк-на-авторитет НЕ нужен (доказательство встроено).
4. **Конформанс:** conformance 95/0 · `nova test std` без новых фейлов · nova-build смоук без P67.
5. **Реальная достижимость ПЕРЕД удалением:** трейс-счётчик на арм по корпусу — не «удалять»
   уже-мёртвое (грабли Ф.4c). Снимаем ЖИВЫЕ армы.

**Финал 196.2:** `infer_call_ret_c` удалён (0 недостижимых строк); `resolved_types` полно покрывает
Call; `[M-172.1-lifted-legacy-arms]` (Call-часть) закрыт.

## Риски (из карты)

- **★ Side-effects в inference (§1).** `infer_call_ret_c` при резолве РЕГИСТРИРУЕТ mono-инстансы/worklist
  (A:46356, F0/Array/Tuple в `resolved_type_to_c`). При переносе резолва в чекер — регистрация ДОЛЖНА
  переехать в отдельный emit-пасс, иначе mono-инстанс не эмитится → CC-FAIL. Ключевой риск W1/W2.
- **Дублирующий C-лоуеринг** `type_ref_to_c` (legacy) vs `resolved_type_to_c` (цель). Per-case доказать
  `resolved_type_to_c(from_type_ref(tr)) == type_ref_to_c(tr)` (точка дивергенции — `Ref`/`Mut`-стрип §4).
- **Round-trip лосс (§4)** — только chained-receiver (W1: D1/D3/F9, W2: F0/A). ResolvedType-native обязателен.
- **Ф.4c-обвязка** (мёртвый `resolve_return_channel`+`debug_assert`+`let _=channel`, mod.rs:13761-13768)
  — снести или доразвить в W1; примитивы `constraint_solver.rs` переиспользуемы ВНУТРИ (ResolvedType-native).
- **ExprId staleness / desugar** — синтетические Call после desugar без id → канал промахивается;
  подтвердить `number_unset_exprs` в compile-пути (арх-карта §7 — не подтверждён).
- **Гейт-1 ≠ «трудное сделано»** — W5 (интринсики) снимает много строк дёшево; W1 (ядро) меньше строк
  на больший труд. Не спутать. Ядро W1 — реальный шест.
