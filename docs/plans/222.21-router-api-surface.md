# План 222.21 — поверхность Router/Middleware: кросс-фреймворк-разбор + именование

**Статус:** 📋 Ф.0 ИСПОЛНЕНА 2026-07-27 (оркестратор, opus) — см. [docs/dev/research/http-frameworks-gap.md §6](../dev/research/http-frameworks-gap.md#6-ф0-22221--routermiddleware-поверхность-именование--композит-форма--фичи-разведка).
Рекомендации: §3 `layer`→`use` — **НЕ переименовывать** (парсер-коллизия ПОДТВЕРЖДЕНА кодом:
`use` уже `KwUse`, постфиксный `.method()`-разбор не принимает keyword-токены на позиции имени
метода — `r.use(mw)` сегодня не парсится; цена правки+прецедента не окупается, `layer` уже
однозначен и задокументирован) — **решение по-прежнему за владельцем**, но рекомендация против.
§4 FastAPI-композит — цепочка (`sub.layer(auth).tag()` → `nest`), НЕ kwargs-блоб, согласие с
инстинктом плана. §5 — Ф.1 (merge+group) и Ф.2 (route_layer+per-route MW) остаются
единственными подтверждёнными доработками; НОВЫЙ кандидат — Actix-style `scope`
host/header-guard'ы (условная маршрутизация), не заведён отдельным пунктом до подтверждения
владельцем. Ф.1-Ф.3 (реализация) — В ОЧЕРЕДИ, не начаты. **НЕ СОГЛАСОВАН** до слова владельца.
**Слой:** 2 (Polaris-ядро). **Зависит:** 222.1 (✅ Router влит), 222.4 (middleware-ядро).
**Родитель:** [222](222-http-framework.md) · [222.0](222.0-module-map.md).
**Основание:** сравнение нашей поверхности (`route`/`nest`/`layer`) с Axum · chi · Gin · Express ·
Actix · FastAPI · Flask · ASP.NET minimal · Fiber · Hono · Rocket · Spring · Go stdlib 1.22.

## 0. Наша фактическая поверхность (после раскола, `nova-polaris/src/server_router.nv`)

```nova
export fn Router.new() -> Router
export fn Router mut @route(path str, mr MethodRouter) -> Result[Router, HttpError]
export fn Router mut @get/post/put/delete/patch(path str, h Handler) -> Result[Router, HttpError]
export fn Router mut @nest(prefix str, sub Router) -> Result[Router, HttpError]
export fn Router mut @layer(mw Middleware) -> @
export fn Router mut @fallback(h Handler) -> @          // 404
export fn MethodRouter mut @fallback(h Handler) -> @    // per-route 405
export fn get/post/put/delete/patch(h Handler) -> MethodRouter   // свободные, композируемые
export fn middleware(f fn(ServerRequest, Handler) -> ServerResponse) -> Middleware
```

## 1. `route` — статус: ПАРИТЕТ+ (ничего не требуется)

| Фреймворк | Имя | Заметка |
|---|---|---|
| Axum | `.route(path, get(h).post(h2))` | наш прототип 1:1; **`.get()` на Router у него НЕТ** |
| Express | `app.get(p,h)` · `app.route(p).get(h).post(h2)` | chainable route-объект ≈ наш MethodRouter |
| chi | `r.Get(p,h)` · `r.Method(verb,p,h)` | `Method` — динамический verb строкой |
| Gin | `r.GET(p, mw..., h)` | вариадик: middleware в аргументах роута |
| Actix | `.route(p, web::get().to(h))` | `web::get()` ≈ наш `get()` |
| Go stdlib 1.22 | `mux.HandleFunc("GET /path", h)` | метод внутри строки паттерна |
| FastAPI/Flask/Spring/Rocket | декоратор/аннотация/атрибут | не метод |
| ASP.NET minimal | `app.MapGet(p,h)` | префикс `Map*` |

**Вывод:** у нас ОБЕ двери (мульти-метод `route+get()` и одиночный `.get(path,h)`); Axum имеет
только первую. Пробелов нет. Единственный кандидат — **динамический verb** (`chi.Method(verb,…)`)
для проксей/шлюзов; ценность низкая, отдельно оценить.

## 2. `nest` — статус: ЕСТЬ ПРОБЕЛЫ

| Фреймворк | Имя | Что сверх нашего |
|---|---|---|
| Axum | `.nest()`, `.nest_service()`, **`.merge()`** | merge — слияние БЕЗ префикса |
| chi | `r.Mount(p,h)`, **`r.Route(p, func(r){…})`** | инлайн-группа замыканием |
| Gin / Fiber | **`r.Group(prefix, mw...)`** | группа-объект + middleware ОДНИМ вызовом |
| Actix | `web::scope("/api")` | скоуп с guard'ами |
| FastAPI | `include_router(r, prefix=, tags=, dependencies=)` | префикс + OpenAPI-теги + DI за вызов |
| Flask | `register_blueprint(bp, url_prefix=)` | Blueprint = субприложение |
| ASP.NET | `app.MapGroup("/api")` | chainable, с фильтрами |

**Пробел П1 — `merge`** (слить два роутера на одном уровне без префикса). Дёшево, композиция
модулей приложения. Есть у Axum.

**Пробел П2 — инлайн-группа** (`Group`/`scope`/`Route`/`MapGroup`) — **есть у ВСЕХ сравниваемых,
кроме нас**. Сейчас: `Router.new()` → наполнить → `nest(prefix, sub)`. У них: `api := r.Group("/api")`
и сразу регистрируешь. Самая заметная эргономическая дыра.

## 3. `layer` — статус: ЕСТЬ ПРОБЕЛЫ + ВОПРОС ИМЕНОВАНИЯ

| Фреймворк | Имя | Что сверх нашего |
|---|---|---|
| Axum | `.layer(l)` + **`.route_layer(l)`** | route_layer — только на СОВПАВШИЕ роуты, не на 404/405 |
| chi | **`r.Use(mw)`** + **`r.With(mw).Get(…)`** | With — per-route, chainable |
| Gin | **`r.Use(mw)`** + `r.GET(p, mw1, mw2, h)` | per-route вариадиками |
| Express/Fiber/Hono | **`app.use([path,] mw)`** | path-scoped |
| Actix | `.wrap(mw)` / `.wrap_fn(closure)` | inline-замыкание |
| FastAPI | `@app.middleware("http")` + **`Depends()`** | два уровня: грубый MW + тонкий типизированный DI |
| ASP.NET | `app.Use(…)` + **`AddEndpointFilter`** | типизированные per-endpoint фильтры |

**Пробел П3 — `route_layer`-семантика** (middleware НЕ накрывает 404/405). Реальная тонкость:
logging хотят на всё, auth — только на существующие роуты. Наш `layer` сейчас накрывает всё.

**Пробел П4 — per-route middleware** (chi `With`, Gin вариадик, ASP.NET endpoint-filter).
У нас — только на весь Router либо через `nest`.

**Вопрос именования (владелец 2026-07-25): `layer` → `use`?** `use` — у chi, Gin, Express, Fiber,
Hono, ASP.NET (`Use`); `layer` — только Axum (термин из tower). То есть **`use` — де-факто
лингва-франка**, `layer` — рустоспецифичный жаргон. **Оценить:** (а) узнаваемость `use` для
пришедших из JS/Go/C# (большинство) против одного Axum; (б) коллизия с ключевым словом Nova
(`use`/`import` — проверить парсер!); (в) цена переименования (сайты + доки + план 222.4).
Решение — владельца, не агента.

**Где мы ЛУЧШЕ (сохранить, не растерять):** плоская форма `middleware(fn(req, next) -> resp)` —
у Axum это `tower::Layer` (generic + poll_ready), у chi `func(http.Handler) http.Handler`
(двойная вложенность). Читается лучше обеих. Плюс `MethodRouter.fallback` (per-route 405).

## 4. FastAPI `include_router(prefix=, tags=, dependencies=)` — исследовать (вопрос владельца)

Три возможности одним вызовом: **префикс** (есть у нас = `nest`), **OpenAPI-теги** (группировка
эндпоинтов в доке — смыкается с [222.8а](222-http-framework.md) OpenAPI-генерацией), **dependencies**
(DI, применяемый ко всей группе — у нас ближайший аналог `layer` на суб-роутере + вопрос
эффект-DI из [222.20](222.20-effects-audit.md)).

**Вопрос к разведке:** нужен ли нам композитный вызов (`nest(prefix, sub, tags:, deps:)`) или
это питоновский стиль «всё через kwargs», а нам честнее цепочка
(`sub.layer(auth).tag("users")` → `parent.nest("/api", sub)`)? Второе ближе к нашей конвенции
цепочных вызовов. **Не копировать форму бездумно — оценить по существу.**

## 5. «Чем мы можем быть круче всех» — сводная разведка (вопрос владельца)

Задание разведке: по КАЖДОМУ фреймворку — какая его **самая желанная фича**, которую мы могли
бы дать сразу (дёшево, без течи http в компилятор). Ориентиры-кандидаты (не исчерпывающе):

| Источник | Кандидат-фича | Первая оценка |
|---|---|---|
| chi | инлайн-`Group` + `With` (per-route MW) | П2/П4, дёшево |
| Axum | `merge`, `route_layer` | П1/П3, дёшево |
| FastAPI | теги/группы для OpenAPI, DI-на-группу | смыкается с 222.8а / 222.20 |
| ASP.NET | типизированные endpoint-фильтры | средне; наш аналог — типизированный MW? |
| Gin/Fiber | per-route MW вариадиками | форма спорна (арность), семантика = П4 |
| Actix | `scope` с guard'ами (условная маршрутизация) | оценить: host/header-guard'ы |
| Express | `app.use(path, mw)` — path-scoped MW без суб-роутера | оценить против `nest`+`layer` |
| Rocket/Spring | атрибут-роутинг | ❌ отвергнуто (222.8, «одна дверь») |

**Наше УНИКАЛЬНОЕ преимущество (не потерять из виду):** компилируемость + эффекты + must-consume
Body + fiber-на-соединение. Фичи-заимствования оценивать на совместимость с этим, а не тащить
динамические трюки (middleware, меняющий тип запроса, — уже отвергнут в 222.4 §4).
