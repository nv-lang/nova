# План 274.2 — цена итерации `novac`: секунды, не минуты

**Родитель:** [274](274-novac-self-hosted-compiler.md) (зонтик; «зачем» — §1.4, строка «Цена итерации»).
**Статус:** 🔨 В РАБОТЕ с 2026-08-15 (заведён по слову владельца: «срочно оптимизируй время
компиляции в секунды, а не в минуту» → «ещё в 4 раза» → «запиши это в план — подплан для 274»).
**Результат:** каждый шаг цикла novac (смоук файла, дифф-раннер корпуса, сборка novac,
позже — самосборка) стоит секунды; цена **измерена и записана числом**, а не ощущением;
уроки переносятся в драйвер novac (Э5/Э6) как требования.

## 0. Задача

Цикл разработки novac — «эмитить → линковать → сравнить с оракулом» — на день 2 стоил
~40 с на файл; шесть файлов basics — 4 минуты; полный дифф-гейт — 6 минут. Владелец:
цикл в минуты недопустим. Профиль (`NOVA_PERF_TIMER=1`) показал главное: **компилятор в
этой цене — миллисекунды**; вся цена — драйвер и внешние шаги. Значит задача — не
«ускорить novac», а **убрать драйверные накладные из цикла novac** и записать, какие
свойства драйвера они выявили, чтобы novac-драйвер их не повторил.

## 1. Профиль — числа дня 2 (2026-08-15, машина под чужим гейтом)

Один `nova build examples/basics/hello.nv` ≈ 20 с:

| фаза | время | что это |
|---|---|---|
| `dep-lock` | ~12 с | резолв четырёх git-зависимостей манифеста `examples/` (tls/http/polaris/socks), которые hello.nv не использует; сеть/`ls-remote` на каждый build |
| `vcvars64.bat` capture | ~7 с | детект тулчейна на **каждый** вызов (`test_runner.rs`: «paid once, not per-test» — но per-build; демона нет) |
| `c-compile` | ~1 с | clang: 0.43 с — заголовки рантайма (`nova_rt.h` → gc.h/libuv: 82 тыс. строк после препроцессора), 0.07 с — сама эмиссия, 0.34 с — линк |
| parse/imports/check | миллисекунды | компилятор |

## 2. Что сделано (смоук `scripts/tools/novac-e1-smoke.sh`)

| шаг | было | стало | как | коммит |
|---|---|---|---|---|
| эталонный бинарь оракула | `nova build` на каждый прогон | 0 (кэш) | кэш по (cksum файла, mtime оракула); сборка ВНЕ пакета `examples/` (module → имя файла по D78) — dep-lock не запускается | `0e05a9cec` |
| линковка C от novac | второй `nova build` | ~0.5 с | прямой clang с argv оракула, снятым **один раз** перехватом через дверь `NOVA_CLANG` (`test_runner.rs`) — флаги оракульские байт-в-байт, руками не писаны | `0e05a9cec` |
| заголовки рантайма | 0.43 с на файл | 0.22 с compile | PCH прелюдии `nova_rt.h` — раз на оракул (0.6 с), кэш рядом с argv | `e5612e13f` |
| линк | 0.34 с | 0.27 с | `-fuse-ld=lld`; `-g` снят (смоук не отлаживают) | `e5612e13f` |
| накладные MSYS | десятки fork-ов ×70–200 мс | ≤ 6 процессов в hot path | без `git`/`cygpath`/`md5sum` на прогон; пути и ключи считаются раз в кэш | `e5612e13f` |

**Итог:** тёплый смоук **1.7 с/файл** (было 40), пять файлов **8.8 с** (было 47 с → 4 мин),
холодный 6–8 с (оракул один раз на файл+ревизию). Стоимость записана в
`docs/dev/novac-divergences.md` (сноска ³′).

**Что НЕ сделано и почему:** оболочка объектником (clang только на тело) — невозможно без
правки оракульской эмиссии (в оболочке всё `static`) — не делается; `nova daemon` — проба
`daemon start` зависла — не мой путь, интегратору на заметку; сборка самого novac
оракулом (~10 с) — цена оракула, не трогается.

## 3. Что дальше (в порядке отдачи) — и что уже взято

1. **Дифф-раннер корпуса** — ✅ **334 с → 68 с** (2026-08-15): виновник — `git log
   --follow` на КАЖДЫЙ subset-файл для корзины «вне точки» (0.46 с × ~50 = 25 с) →
   один общий `git log --name-only` (0.35 с) + быстрый смоук. Замер: novac 12 с (60 ×
   старт процесса), оракул 22 с (`check` dep-lock НЕ платит — 320 мс/файл), смоуки
   5 × 1.7 с, остальное — fork-и. Следующий рубеж (≤ 30 с): батч `novac check` одним
   процессом (п.2), кэш вердиктов оракула по (cksum, mtime) при неизменном корпусе.
2. **Фаззер** — 🔨 код готов, ждёт сборки novac (регресс std serde, реестр): было
   **65 с на 192 кейса = 336 мс/кейс** при том, что сам check — 120 мс, из них почти
   всё — старт процесса; остальное — пять fork-ов на кейс. Сделано: все мутации
   генерятся заранее, судятся ОДНИМ `novac check <все файлы>` (батч-режим CLI —
   новая дверь `main.nv`: список путей, per-file диагностики, exit = худший),
   виновник паники ищется бисекцией только на красном прогоне. Ожидание ≤ 5 с.
3. **Страж мэнглинга** — 2 с уже (пять `novac emit`); один emit по списку — тот же
   батч, когда CLI его получит.
4. **Сборка novac** (~10 с оракулом): не наша цена; при Э5 самосборка обязана быть
   быстрее оракула — это и есть первый бенчмарк самосборки.

## 4. Уроки для драйвера novac (Э5/Э6) — требования, не пожелания

Цена «секунды, не минуты» — свойство **драйвера**, не компилятора. novac-драйвер обязан с
первого дня (входит в §11 плана 274 «цикл сборки»):

- **dep-lock только при изменении манифеста/лока** (кэш по хэшу `nova.toml`+lock; сеть —
  никогда в горячем пути); файл без внешних импортов не платит за зависимости пакета;
- **детект тулчейна — один раз в кэш** (по mtime бинарей); демон — опция, не условие
  скорости;
- **PCH рантайма — артефакт сборки**, строится раз на ревизию рантайма; `-g` — только по
  просьбе; **lld по умолчанию**;
- **цена каждого шага печатается числом** (`--time`), бюджет цикла — храповик, как
  `novac-corpus.baseline`: рост цены без причины в коммите — красный.

## 5. Приёмка

- смоук ≤ 2 с тёплый на файлах basics — ✅ 1.7 с (2026-08-15);
- дифф-раннер ≤ 60 с полный — ✅ 68 с (близко; ≤ 30 с — с батч-CLI) / ≤ 10 с без изменений — 🕐;
- фаззер ≤ 10 с — 🔨 65 с → 16.5 с батчем (2026-08-15); остаток — генерация 192 файлов fork-ами (head/tail), следующий шаг — генератор одним awk/python;
- целевая схема — конвенция П14 + страж-храповик цены `check-novac-iteration-cost.sh` (в обе стороны) + бюджет дифф-раннера в `check-novac-differential.sh` — ✅ 2026-08-15;
- требования §4 записаны в 274 §11 — 🕐 при переписывании §11 под Э5;
- каждый пункт закрывается с числом «было → стало» в этом файле.

## 6. Чего этот план НЕ делает

Не ускоряет оракул (не наша земля; профиль передан интегратору как факт), не меняет
кодоген novac ради скорости сборки C (эмиссия — копейки), не вводит новых зависимостей
(PCH/lld — штатные части уже используемого clang).
