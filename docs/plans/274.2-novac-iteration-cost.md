# План 274.2 — цена итерации `novac`: секунды, не минуты

**Родитель:** [274](274-novac-self-hosted-compiler.md) (зонтик; «зачем» — §1.4, строка «Цена итерации»).
**Статус:** 🔨 В РАБОТЕ с 2026-08-15 (заведён по слову владельца: «срочно оптимизируй время
компиляции в секунды, а не в минуту» → «ещё в 4 раза» → «запиши это в план — подплан для 274»).
**Результат:** каждый шаг цикла novac (смоук файла, дифф-раннер корпуса, сборка novac,
позже — самосборка) стоит секунды; цена **измерена и записана числом**, а не ощущением;
уроки переносятся в драйвер novac (Э5/Э6) как требования.

## 0. Задача

Цикл разработки novac — «эмитить → линковать → сравнить с оракулом» — на день 2 стоил
~40 с на файл; шесть файлов basics — 4 минуты; полный дифф-гейт — 6 минут. Владелец:
цикл в минуты недопустим. Профиль (`NOVA_PERF_TIMER=1`) показал главное: **компилятор в
этой цене — миллисекунды**; вся цена — драйвер и внешние шаги. Значит задача — не
«ускорить novac», а **убрать драйверные накладные из цикла novac** и записать, какие
свойства драйвера они выявили, чтобы novac-драйвер их не повторил.

## 1. Профиль — числа дня 2 (2026-08-15, машина под чужим гейтом)

Один `nova build examples/basics/hello.nv` ≈ 20 с:

| фаза | время | что это |
|---|---|---|
| `dep-lock` | ~12 с | резолв четырёх git-зависимостей манифеста `examples/` (tls/http/polaris/socks), которые hello.nv не использует; сеть/`ls-remote` на каждый build |
| `vcvars64.bat` capture | ~7 с | детект тулчейна на **каждый** вызов (`test_runner.rs`: «paid once, not per-test» — но per-build; демона нет) |
| `c-compile` | ~1 с | clang: 0.43 с — заголовки рантайма (`nova_rt.h` → gc.h/libuv: 82 тыс. строк после препроцессора), 0.07 с — сама эмиссия, 0.34 с — линк |
| parse/imports/check | миллисекунды | компилятор |

## 1а. ЦЕЛЕВАЯ СХЕМА СБОРКИ — что обязано быть, а не «что вышло»

Указание владельца 2026-08-17. До него этот документ описывал PCH в разделе
«что сделано» — то есть как ФАКТ ПРОШЛОГО. Факт прошлого не обязывает никого:
его можно снять правкой, и никто не заметит. Ниже — требования; у каждого
назван механизм, который его держит.

| требование целевой схемы | почему | механизм |
|---|---|---|
| **предкомпилированная прелюдия (PCH) обязательна в горячем пути** | `nova_rt.h` тянет gc.h и libuv — 82 тыс. строк после препроцессора; без PCH это половина времени компиляции КАЖДОГО файла (0.43 с → 0.22 с на файл) | `check-novac-pch.sh`: требует построение (`-x c-header` → `*.pch`), применение (`-include-pch`), кэш по ШТАМПУ ревизии оракула и условие «файла нет» |
| PCH кэшируется по ревизии оракула, а не по времени | протухший PCH даёт мусорный объектник молча | тот же страж (штамп в имени) |
| эталонный бинарь оракула кэшируется по (cksum, mtime) | иначе `nova build` на каждый прогон — 10 с | цена цикла (`check-novac-iteration-cost.sh`), бюджет `smoke-warm-ms` |
| линковка своим clang с argv, снятым перехватом ОДИН раз | второй `nova build` стоил ~10 с | там же |
| `-g` в горячем пути не нужен | смоук не отлаживают | там же |

**Замер 2026-08-17 — чего в целевой схеме НЕ хватает у самого оракула.**
`nova build` PCH **не использует вообще**: перехват командной строки даёт один
вызов clang с `--target=... -O0 -g -Wno-everything -ffunction-sections
-fdata-sections` и НОЛЬ упоминаний pch. При этом механизм уже написан и
работает — в нашем смоуке. Профиль сборки novac (5381 строка `.nv`): чек
1.36 с, кодоген+запись 3.19 МБ C ≈ 3.9 с, clang 1.5–2.5 с одним вызовом,
итого тёплая сборка 4.7–6.0 с. То есть **78 % времени — сторона Nova**, и PCH
бьёт только по оставшимся 22 %. Эскалация интегратору: перенести PCH из
смоука в `nova build` (потолок выигрыша ≈ 1–1.5 с из пяти), но главный резерв
не там — см. раздел про раздувание эмиссии (×7.6 строк C на строку Nova).

## 1б. ЦЕНА РАБОТЫ novac — три требования, срок и механизм у каждого

Вопрос владельца 2026-08-17, заданный трижды подряд: «согласен, где это
записано, когда сделаем, страж есть?». До этого раздела ответ был честно
плохим: одно требование жило в комментарии скрипта, два — только в переписке.
Ниже у каждого назван СРОК и МЕХАНИЗМ; там, где кода ещё нет, это сказано
прямо, а не подразумевается.

### 1б.1. Старт процесса не умножается на число файлов — СДЕЛАНО

**Требование.** Инструмент, обрабатывающий много файлов, зовёт novac ОДИН
раз, а не по файлу. Замер 2026-08-17: чистый старт novac 149 мс против ~50 мс
работы на маленьком файле — три четверти пофайлового прохода это запуск.
Корпус в 61 файл платил его 61 раз.

**Сделано.** Дифф-раннер зовёт novac пачкой: 12.8 с → 1.7 с. Фаззер работал
пачкой изначально (192 мутации одним процессом).

**Два предохранителя, оба обязательны.**
* Если пачка УМЕРЛА (код вне 0/1/2 или слово panic в выводе) — её вердикты
  недостоверны, и раннер откатывается на пофайловый проход, а не гадает.
* Пути передаются ОТНОСИТЕЛЬНЫМИ. MSYS переписывает абсолютный `/d/...` в
  `D:\...` на границе exec, novac печатает в диагностике то, что ПОЛУЧИЛ, и
  строки перестают совпадать со списком: первая версия дала «принято 55»
  вместо 5 и раннер покраснел ни о чём.

**Механизм:** `check-novac-batch.sh` — раннер обязан содержать пачечный вызов,
перевод в относительные пути и откат при смерти пачки.

### 1б.2. Меньше C: предкомпилировать неgeneric-часть, дедуплицировать инстансы — Э2-б2/Э3

**Что измерено (2026-08-17).** Эмиссия оракула для novac — 47 192 строки C на
5 381 строку `.nv` (×7.6). Разложение по происхождению: тела std — 65 %,
рантайм-оболочка — 16 %, `Vec` — 7 %, **собственный код novac — 7 %**. То
есть раздувание не в том, что мы многословно печатаем, а в том, что вся
библиотека инлайнится в каждую единицу трансляции.

**Что из этого следует и чего НЕ следует.** Замечание владельца снимает
наивный вариант: std весь на дженериках, целиком в объектник он не
превращается — машинный код зависит от инстанцирования (потому Rust кладёт в
`rlib` MIR, а C++ держит шаблоны в заголовках). Реалистичная форма — две:
* **неgeneric-часть предкомпилировать**: конкретные функции std и рантайм
  компилируются один раз и переиспользуются;
* **инстансы дедуплицировать глобально**: ключ `(DeclId, аргументы)`, один
  инстанс на программу, а не на файл. Донор — rustc: инстансы эмитятся в
  крейте-потребителе, дедуплицируются по символьному имени, дубли схлопывает
  линкер (COMDAT), плюс `-Zshare-generics`.

**Срок.** Дедупликация — Э2-б2 (вместе с mono-коллектором, ключ инстанса там
же). Предкомпиляция неgeneric-части — Э3, когда у novac появится свой шов
сборки.

**Механизм СЕЙЧАС:** `check-novac-emission-size.sh` — храповик на объём C,
который novac выдаёт на корпус. Он не судит оракула и не ждёт Э2-б2: он
краснеет, если НАША эмиссия выросла без объяснения. Механизм ПОТОМ (Э2-б2):
доля собственного кода в эмиссии становится числом в том же храповике.

### 1б.3. Недостижимое НЕ эмитится — Э2-б2

**Требование.** Не «эмитировать и вычистить», а **не эмитировать**:
mono-коллектор идёт от корней (`main`, экспортируемые входы) по графу
вызовов, который уже есть в канале чекера (`resolved_callees`), и в вывод
попадает только достигнутое. Донор — rustc `collect_crate_mono_items`
(roots → neighbours).

**Почему именно так.** В нынешнем компиляторе DCE работает пост-фактум —
сначала эмитируется всё, потом вырезается; владелец 2026-08-17: «кое-как, но
работает». Пост-фактум-проход всегда рискует вырезать нужное и всегда сложен;
коллектор от корней делает вопрос беспредметным — недостижимое просто никогда
не попадает в вывод.

**Срок.** Э2-б2, тем же слиянием, что и ключ инстанса.

**Механизм.** Кода ещё нет, поэтому стража ещё нет — и это сказано прямо, а не
скрыто: строка ждёт этапа в реестре §10.3а с маркером. Что он будет
проверять, известно уже сейчас: в эмиссии нет ни одного инстанса, до которого
нет пути от корня (сверка множества эмитированных символов с обходом
`resolved_callees` от `main`).

## 2. Что сделано (смоук `scripts/tools/novac-e1-smoke.sh`)

| шаг | было | стало | как | коммит |
|---|---|---|---|---|
| эталонный бинарь оракула | `nova build` на каждый прогон | 0 (кэш) | кэш по (cksum файла, mtime оракула); сборка ВНЕ пакета `examples/` (module → имя файла по D78) — dep-lock не запускается | `0e05a9cec` |
| линковка C от novac | второй `nova build` | ~0.5 с | прямой clang с argv оракула, снятым **один раз** перехватом через дверь `NOVA_CLANG` (`test_runner.rs`) — флаги оракульские байт-в-байт, руками не писаны | `0e05a9cec` |
| заголовки рантайма | 0.43 с на файл | 0.22 с compile | PCH прелюдии `nova_rt.h` — раз на оракул (0.6 с), кэш рядом с argv | `e5612e13f` |

| накладные MSYS | десятки fork-ов ×70–200 мс | ≤ 6 процессов в hot path | без `git`/`cygpath`/`md5sum` на прогон; пути и ключи считаются раз в кэш | `e5612e13f` |

холодный 6–8 с (оракул один раз на файл+ревизию). Стоимость записана в

**Что НЕ сделано и почему:** оболочка объектником (clang только на тело) — невозможно без
правки оракульской эмиссии (в оболочке всё `static`) — не делается; `nova daemon` — проба
`daemon start` зависла — не мой путь, интегратору на заметку; сборка самого novac
оракулом (~10 с) — цена оракула, не трогается.

   --follow` на КАЖДЫЙ subset-файл для корзины «вне точки» (0.46 с × ~50 = 25 с) →
   один общий `git log --name-only` (0.35 с) + быстрый смоук. Замер: novac 12 с (60 ×
   старт процесса), оракул 22 с (`check` dep-lock НЕ платит — 320 мс/файл), смоуки
   5 × 1.7 с, остальное — fork-и. Следующий рубеж (≤ 30 с): батч `novac check` одним
   процессом (п.2), кэш вердиктов оракула по (cksum, mtime) при неизменном корпусе.
2. **Фаззер** — 🔨 код готов, ждёт сборки novac (регресс std serde, реестр): было

   всё — старт процесса; остальное — пять fork-ов на кейс. Сделано: все мутации

3. **Страж мэнглинга** — 2 с уже (пять `novac emit`); один emit по списку — тот же
   батч, когда CLI его получит.
4. **Сборка novac** (~10 с оракулом): не наша цена; при Э5 самосборка обязана быть
   быстрее оракула — это и есть первый бенчмарк самосборки.

## 4. Уроки для драйвера novac (Э5/Э6) — требования, не пожелания

Цена «секунды, не минуты» — свойство **драйвера**, не компилятора. novac-драйвер обязан с
первого дня (входит в §11 плана 274 «цикл сборки»):

- **dep-lock только при изменении манифеста/лока** (кэш по хэшу `nova.toml`+lock; сеть —
  никогда в горячем пути); файл без внешних импортов не платит за зависимости пакета;
- **детект тулчейна — один раз в кэш** (по mtime бинарей); демон — опция, не условие
  скорости;
- **PCH рантайма — артефакт сборки**, строится раз на ревизию рантайма; `-g` — только по
  просьбе; **lld по умолчанию**;
- **цена каждого шага печатается числом** (`--time`), бюджет цикла — храповик, как
  `novac-corpus.baseline`: рост цены без причины в коммите — красный.

- смоук ≤ 2 с тёплый на файлах basics — ✅ 1.7 с (2026-08-15);
- дифф-раннер ≤ 60 с полный — ✅ 68 с (близко; ≤ 30 с — с батч-CLI) / ≤ 10 с без изменений — 🕐;
- фаззер ≤ 10 с — 🔨 65 с → 16.5 с батчем (2026-08-15); остаток — генерация 192 файлов fork-ами (head/tail), следующий шаг — генератор одним awk/python;
- целевая схема — конвенция П14 + страж-храповик цены `check-novac-iteration-cost.sh` (в обе стороны) + бюджет дифф-раннера в `check-novac-differential.sh` — ✅ 2026-08-15;
- требования §4 записаны в 274 §11 — 🕐 при переписывании §11 под Э5;
- каждый пункт закрывается с числом «было → стало» в этом файле.

## 6. Чего этот план НЕ делает

Не ускоряет оракул (не наша земля; профиль передан интегратору как факт), не меняет
кодоген novac ради скорости сборки C (эмиссия — копейки), не вводит новых зависимостей
(PCH/lld — штатные части уже используемого clang).
