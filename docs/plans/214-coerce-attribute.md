# План 214 — `#coerce`: декларативные неявные конверсии (str→[]u8 как первый инстанс)

**Статус:** 📋 ДИЗАЙН СОГЛАСОВАН владельцем 2026-07-17 (диалог-ревью: универсальная коэрсия
отвергнута → декларативный атрибут; два атрибута `#view`/`#coerce` схлопнуты в ОДИН `#coerce`
с двумя формами записи). Реализация НЕ начата, ждёт очереди. **Язык-меняющее** → D429-амендмент
в том же слиянии, что код (Ф.0). **Приоритет P2** (снимает §3-нарушение
`[M-d55-str-literal-coercion-name-gated]` общим механизмом + закрывает эргономику str→[]u8).

## 0. Мотив (одной фразой)

Nova уже прячет безопасные zero-cost конверсии (single-wrapper D55: newtype/sum, переменные
включительно, int→i64 widening «невидимо для автора») — но str→[]u8 требует `.bytes()`, а
компромисс-костыль (str-литерал в `write`) захардкожен по ИМЕНИ метода — нарушение
[compiler-conventions §3](../compiler-conventions.md). Нужен ОБЩИЙ декларативный механизм:
объявление в `.nv`, никакого хардкода пар в Rust.

## 1. Дизайн (converged, финал)

**ОДИН атрибут `#coerce`** на функции. Функция обязана быть УНАРНОЙ по входному типу;
объявляет неявную коэрсию `I → O`:

```nova
// форма-ИСТОЧНИК: метод без параметров; I = тип-приёмник, O = возврат
#coerce fn str @bytes() -> ro []u8 => ...              // объявляет str → []u8 (наш инстанс)

// форма-ПРИЁМНИК: статик .new с одним параметром; I = параметр, O = Self
#coerce fn Matrix.new(v []f64) -> ro Self => ...       // объявляет []f64 → Matrix
```

Направление записи — где автору удобнее (у источника примитив уже есть — атрибут без нового
кода; у приёмника — когда конверсию логично декларирует целевой тип). Семантика ОДНА.

### Правила (все — нормативные, в D429)

1. **Унарность.** Ровно один входной тип: метод-без-параметров ИЛИ статик-с-одним-параметром.
   Иначе — compile error `E_COERCE_NOT_UNARY`.
2. **Неявная вставка ТОЛЬКО при `ro`-возврате** (zero-cost view; скрытых аллокаций не бывает).
   `#coerce` на функции с не-`ro` возвратом — error `E_COERCE_NOT_RO` (жёстче, чем «молча не
   вставлять»: атрибут без эффекта = ловушка).
3. **Один `#coerce` на пару (I, O) на программу.** Дубль (в т.ч. с двух сторон) — error
   `E_COERCE_DUPLICATE_PAIR` с указанием обеих деклараций.
4. **Один уровень.** Цепочка `I→O→P` не разворачивается (паритет single-wrapper D55
   «ровно один уровень»).
5. **Exact > coercion.** Перегрузка с точным типом всегда побеждает; коэрсия пробуется только
   когда позиция ждёт `O` и точного совпадения нет. При ≥2 применимых коэрсиях к одной
   позиции — error неоднозначности (паритет single-wrapper «однозначность обязательна»).
6. **Позиции** — та же таблица «явно ожидаемого типа» D55: call-arg на резолвленный параметр,
   `let`/`const` с аннотацией, return-позиция, element-позиция коллекции.
7. **Вставляется ИМЕНОВАННЫЙ вызов** (`s.bytes()` / `Matrix.new(v)`) — АСТ-переписывание в
   существующем expected-type-propagated проходе (`MapLitAnnotator::try_wrap_leaf`-семья);
   неявная форма байт-в-байт эквивалентна явной. Никакого нового C-лоуэринга.
8. **Extension-разрешён** (orphan-развязка): автор `MyId` может объявить
   `#coerce fn str @to_myid() -> ro MyId` extension'ом в своём модуле.
9. **Охват V1: только std/lang-items** (обкатка); user-типы — снятием гейта отдельным
   амендментом после обкатки (консервативный вариант согласован).
10. **Взаимодействие с mut/consume:** `ro O` не матчит `mut`/`consume`-позицию → там как
    раньше, явно (`.bytes().clone()`). Падает из правила 2 само, но проговорить в D429.

### Что НЕ входит (отклонено в ревью)

- Универсальная вшитая str→[]u8 коэрсия (хардкод пары в Rust) — отвергнута владельцем.
- Безымянная call-форма `fn Vec[T](s str)` — новый синтаксис + реинкарнация ретрактированного
  `from` (§1а) + всё равно требует opt-in атрибута.
- Два раздельных атрибута `#view`/`#coerce` — схлопнуты в один (унарность снимает
  двусмысленность источника).

## 2. Первый инстанс и поглощение хардкода

- Ф.3 помечает СУЩЕСТВУЮЩИЙ `str @bytes() -> ro []u8` атрибутом — ноль нового кода.
- **D55-амендмент «Str-литерал → []u8» (2026-07-15) — РЕТРАКТ целиком (владелец 2026-07-17):**
  литерал — просто частный случай str-ЗНАЧЕНИЯ, отдельного правила не остаётся; действует
  ТОЛЬКО общее D429-правило, на литералы оно распространяется автоматически. Подсекция в
  `02-types.md` помечается `RETRACTED → D429` (текст-история остаётся, как у прочих ретрактов).
- Реализация-костыль name-gated `synthesize_write_str_lit_bytes_coercion` (метод буквально
  `write`) СНОСИТСЯ; поведение старых сайтов (`w.write("...")`) сохраняется НОВЫМ механизмом
  байт-в-байт (у str есть `#coerce`→`ro []u8`, позиция — `[]u8`-параметр) — Ф.4-фикстура
  пинует эквивалентность на существующем d55-тесте.
- Маркер `[M-d55-str-literal-coercion-name-gated]` закрывается этим планом (home = 214).

## 5. Риски

| Риск | Митигация |
|---|---|
| Расползание неявности (урок Scala implicit) | правила 2-5 + V1-охват std-only (п.9) |
| Перф sig-скана (реестр) | атрибут редкий; сбор при существующем скане деклараций, O(декл) |
| Конфликт с overload-резолвом (`env(str)`/`env_bytes([]u8)`) | exact>coercion (п.5) — `env("K")` берёт str-перегрузку, коэрсия не пробуется |
| АСТ-rewrite в горячем проходе | вставка только при типовом мисматче ro-позиции — холодная ветка |
