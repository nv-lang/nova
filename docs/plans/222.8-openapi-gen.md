## 0. История дизайна (4 отвергнутых подхода — не возвращаться)

1. ❌ **`#reflect`-атрибут на функциях + JSON-сайдкар call-site'ов** — новый языковой механизм,
   provenance-трекинг builder-цепочек, отдельный формат. Дорого и не нужно.
2. ❌ **Внешний Rust-тул по AST компилятора** (à la nova-lsp) — владелец: «расширение над языком
   с хардкодом синтаксиса Поляриса»; цепляется за нестабильный внутренний AST (прецедент: nova-lsp
   сломался от нового `ExprKind`-варианта в этой же сессии).
3. ❌ **`json_schema()` как побочный продукт `#impl(Serialize)`** — владелец: Serialize не завязан
   на JSON (общая способность, форматы разные); JSON-специфика в общем derive = ошибка слоя;
   плюс цена в бинаре для всех, кто сериализует не для HTTP.
4. ❌ **Промежуточный typed `JsonSchema`-enum** — зеркало `TypeShape` без новой информации;
   владелец: «чем TypeShape не устраивает?» — ничем, JSON пишется напрямую из TypeShape.

## 1. Архитектура (финальная)

**Три куска, каждый на своём слое:**

### 1.1 std: тип `TypeShape` + протокол `Reflect` (формато- и домено-независимые)

```nova
// std (модуль-дом — вопрос §8; рабочий кандидат std/reflect.nv)
export type TypeShape enum
    | Record(name str, fields [](str, TypeShape))   // имена полей — ПОСЛЕ rename/rename_all (wire)
    | Sum(name str, variants [](str, TypeShape))    // + как размечен (tag/content/untagged) — см. Ф.1
    | Ref(name str)                                 // back-edge рекурсивного типа (см. 1.2)
    | Str | Int | Float | Bool | Unit
    | Arr(items TypeShape)
    | Opt(inner TypeShape)

export type Reflect protocol {
    .reflect() -> TypeShape
}
```

Ни слова про HTTP/OpenAPI/JSON Schema — «какая форма у типа», пригодно для любого потребителя
(OpenAPI-эмиттер, GraphQL SDL, CLI-генератор, дебаг-принтер).

### 1.2 Компилятор: `#impl(Reflect)` — синтез в СУЩЕСТВУЮЩЕЙ derive-машине

```nova
#impl(Serialize, Deserialize, Reflect)
type User { id int, name str, tags []str }
// синтезируется:
// fn User.reflect() -> TypeShape =>
//     TypeShape.Record("User", [("id", TypeShape.Int), ("name", TypeShape.Str),
//                               ("tags", TypeShape.Arr(TypeShape.Str))])
```

- **Тот же field-walk `auto_derive.rs`**, что у Serialize/Deserialize; wire-имена — переиспользовать
  `wire_name_for` (rename/rename_all/alias уже резолвятся там, НЕ дублировать).
- **Opt-in**: только явный `#impl(Reflect)` — ноль цены для кода, который не просил (владелец
  подтвердил границу; решает и вопрос doc-комментариев — их НЕ трогаем вовсе, см. §5).
- **Суммы**: маппинг из УЖЕ разобранных `SerdeArg::Tag/Content/Untagged` (auto_derive.rs) —
  ничего нового не решается, форма разметки уже вычислена для serde.
- **Рекурсия**: компилятор видит граф типов статически на синтезе — в точке back-edge цикла
  эмитит `TypeShape.Ref(name)`, в остальных местах инлайнит форму. Рантайм-значение конечно,
  бесконечной рекурсии `reflect()` нет по построению.
- **Blanket-реализации** на примитивах/контейнерах std: `int.reflect()`, `str.reflect()`,
  `Vec[T Reflect].reflect()`, `Option[T Reflect].reflect()`, `Result[T,E]` (см. 1.3-статусы) —
  без них самый частый случай (`id int` как path-параметр) без формы.
- **Язык-меняющее** (новый auto-derive протокол = класс D435-прецедента serde) → **D-амендмент
  в том же слиянии**, что и реализация (жёсткое правило CLAUDE.md).

### 1.3 nova-polaris: бандл-extractors + `introspect()` + in-process `/openapi.json`

**Регистрация — ОДИН record-тип на хендлер** (расширение канона 222.3 «мульти-значения = поля
record'а» с уровня одного источника на уровень источников):

```nova
type GetUserReq {
    id      Path[UserId],     // роль видна из ТИПА-ОБЁРТКИ — никаких #[path]-атрибутов
    filter  Query[Filter],
    payload Json[CreateBody],
}
fn get_user(req GetUserReq) -> Result[User, HttpError] { ... }
r.get("/users/{id}", get_user)      // АРНОСТЬ ВСЕГДА ОДНА
```

- **`FromRequest` компонуется по полям** — та же логика, что у `#impl(Deserialize)` для вложенных
  record'ов: `GetUserReq.from_request(req)` = `Path[UserId].from_request(req)` + … по полям.
  Каждый extractor читает СВОЙ срез уже буферизованного `req` — два `Json[..]`-поля легальны
  (двойной парсинг тех же байт — расточительно, но корректно; НИКАКОГО compile-time запрета —
  запрет был бы хардкодом HTTP-знания, владелец отклонил).
- **Гэп №2 (arity-sibling dispatch) обходится ПОЛНОСТЬЮ**: арность одна, семейство
  `@get[T1]/[T1,T2]/[T1,T2,T3]` не нужно, сиблингов разной арности не возникает. Компилятор-фикс
  Гэп №2 остаётся нужным как баг (реестр №130-родня), но 222.8/222.3-путь от него НЕ зависит.
- Регистрирующая обёртка (generic по `T FromRequest+Reflect, R Reflect`) ПОПУТНО кладёт
  `T.reflect()`/`R.reflect()` в запись роутера:
  `RouteEntry { path, method, handler, req_shape Option[TypeShape], resp_shape Option[TypeShape] }`.
  Сырой `Handler` без обёртки (health-check, статика) → `None` — честное «схема неизвестна».
- **`Router.introspect() -> []RouteInfo`** — отдаёт то, что роутер и так хранит (path/method) +
  shapes. Никакой новой информации — только доступ.
- **In-process эмиттер (aide-модель, НЕ отдельная build-программа)** — решение после вопроса
  владельца «чем aide хуже?» (ничем; отдельный генератор ХУЖЕ — риск расхождения с реальным
  `build_router()`, а цену построения Router сервер платит в любом случае):

```nova
r.get("/openapi.json", openapi_handler(r))   // или это делает serve_router автоматически — Ф.3
```

  Эмиттер гуляет по `[]RouteInfo` и пишет OpenAPI 3.x JSON **напрямую из TypeShape**
  (существующим json-энкодером/строителем; БЕЗ промежуточного JsonSchema-типа — §0.4):
  - роль полей req-record'а по имени типа-обёртки: `Path[..]` → `parameters[in=path]`,
    `Query[..]` → `parameters[in=query]`, `Json[..]` → `requestBody` (это знание — ЗДЕСЬ, в
    polaris, не в компиляторе);
  - `Result[T, E]` в возврате → `responses.200 = shape(T)` + ветка ошибок из `shape(E)`
    (E=HttpError → его статусы; общий generic языка, не HTTP-хардкод в компиляторе);
  - именованные `Record(name,..)`/`Sum(name,..)` — хойстятся в `components/schemas/<name>` +
    `$ref` (дедуп по имени; `Ref(name)` рекурсивных типов резолвится туда же);
  - `Sum` по разметке: tag → `oneOf`+`discriminator.propertyName`; tag+content → `oneOf` из
    `{tag,content}`-объектов; untagged → голый `oneOf`;
  - результат кэшируется в памяти (лениво на первый запрос либо на старте) — на запрос ноль цены.

## 2. Прецеденты (сверка с эталонами)

| Эталон | Что берём / чем отличаемся |
|---|---|
| Rust `aide` | in-process схема из живого роутера (наша модель 1:1); у нас derive компилятором вместо макросов |
| Rust `utoipa` | `#[derive(ToSchema)]`≈`#impl(Reflect)`, но их схема JSON-специфична — наш `TypeShape` формато-нейтрален |
| Python pydantic/FastAPI | `model_json_schema()` — та же идея; у них рантайм-рефлексия, у нас compile-time синтез |
| .NET minimal APIs | source-generators=compile-time (как мы); их спека всё же строится рефлексией на старте |
| Go swaggo | ❌ анти-образец: magic-комментарии текстом, компилятор не проверяет |

## 3. Что НЕ входит (границы, все — решения владельца)

- **(б) route-верификация** (`{id}`↔поле compile-time) — отложена за v0.1 (2026-07-24).
- **`#route(...)`** — отклонён (третья дверь).
- **Doc-комментарии → `description`** — исключено из объёма: докстрока пишется для читателя кода,
  может нести внутренние заметки — автоматически публиковать её наружу нельзя. Если появится
  спрос — потом, явным opt-in, отдельным решением.
- **Арность-сахар 222.3 §5** — НЕ пререквизит (бандл-record снимает потребность); если Гэп №2
  когда-то закроют и сахар вернётся — обёртки те же, схема-механика не меняется.
- **Отдельная build-программа-генератор** — отклонена (§1.3, риск расхождения).
