## 1. Точное правило замены (безопасное, механическое)

Вставить пустую строку МЕЖДУ строкой `i` и `i+1`, когда **ВСЕ** условия:
1. строка `i` НЕ пустая и НЕ начинается с `///`, `//`, `#` (т.е. это реальный конец
   декларации, а не комментарий/атрибут);
2. строка `i` оканчивается на `=> <выражение>` (тело-expression) ЛИБО ровно `}` (конец блока);
3. строка `i+1` (после trim) начинается с `///` ЛИБО с `#<буква>` (атрибут);
4. строки `i+1` ещё не предшествует пустая (не создавать двойную).

Это ловит ровно «конец декларации → начало нового блока». НЕ трогает: строки внутри блока
(`///`→`#`, `#`→`fn`), многострочные `///`, `//`-баннеры-разделители.

**НЕ делать в этом sweep'е** (отдельные, спорные — не механические):
- разрежение голых соседних аксессоров одного поля без доков (§32 допускает их вплотную);
- схлопывание двойных пустых строк (другой дрейф, другой проход).

## 2. Исполнение

Скрипт-детектор интегратора (Python, UTF-8) — в теле этого плана §1 как спецификация; агент
реализует по ней ЛИБО правит вручную по списку файлов. Пофайлово: правка → `nova check <файл>`
(или пакетный) → следующий. Порядок: nova-http (густо), затем std, затем examples.

## 3. Гейт — байт-идентичность codegen

Пробельная правка ОБЯЗАНА давать байт-в-байт тот же C. На КАЖДОМ пакете:
1. до правок — снять C-снимок эталонным прогоном (kill-switch на том же бинаре, см.
   [feedback-codegen-dce-verification]);
2. после — пересобрать, `diff` сгенерённого C = **пусто**. Любое расхождение = стоп (значит
   правило задело не-пробел).
Плюс `nova test` по затронутым пакетам (std) не краснеет. multipart.nv уже прошёл `nova check` = PASS.
