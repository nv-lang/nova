# План 274.3 — находки ревью novac: классы по корню, фикс класса, защита от класса

**Родитель:** [274](274-novac-self-hosted-compiler.md) (зонтик). **Вход:** ревью трёх линз
2026-08-15 — [docs/dev/reviews/274-review-2026-08-15.md](../dev/reviews/274-review-2026-08-15.md).
**Статус:** 🔨 В РАБОТЕ с 2026-08-15 (заведён по слову владельца: «запиши в план все пункты
по улучшениям и наиболее верный вариант исправления каждого; для всех проблем определи класс
(группировать по общему корню); план исправления класса + способ обойти возникновение таких
классов в будущем»).
**Правило документа:** находка живёт в этом файле, пока не закрыта; закрытие = коммит +
номер класса в сообщении + фикстура/страж; класс закрыт, когда закрыты ВСЕ его носители И
стоит страж, не дающий классу вернуться (иначе это фикс экземпляра, план 254 П2-доп).

## 0. Как читать

Каждая находка несёт: `Fn` (номер), где (`файл:строка` на момент ревью), что не так,
**наиболее верный фикс** (один, не меню), сложность (Т — тривиальная ≤ 1 ч, М — малая ≤ ½ дня,
С — средняя ≤ 1 день, А — архитектурная). Находки сгруппированы в **классы К-A…К-J по общему
корню**: у класса — корень (почему это возникло), план фикса класса (порядок, а не список),
и **защита** — правило + страж, чтобы класс не вернулся. Всего находок: 118 (F1..F118); классов: 11. Число пересчитывается ПО ФАЙЛУ, а не правится рукой: расхождение шапки с таблицами (62/10 против факта) поймано адверсарной проверкой 2026-08-17.

Приоритет исполнения (владелец 2026-08-15, ревью-вердикт): К-A → К-B → К-C → К-D → К-E →
остальные; **Э2-б (дженерики/mono) не начинается, пока К-A…К-D не закрыты** — строить mono на
непроверяемом гейте, парсере без приоритетов и плоском пространстве имён значит переписывать.

## К-K. Правило есть, судья слеп или отсутствует (адверсарная проверка 2026-08-17)

**Откуда класс.** Требование владельца: «докажи, что текущий статус работ
соответствует архитектуре, плану, конвенциям». Доказательством не может быть
моё слово, поэтому проверку вели четыре независимых опровергателя (по
измерению: архитектура, конвенции, реестры плана, этап и дисциплина), а
каждое найденное нарушение отдельно перепроверял пятый агент с задачей
ОПРОВЕРГНУТЬ заявителя. Из 34 заявленных нарушений перекрёстную проверку
пережили **24**, десять отклонены как неточные или устаревшие.

**Что именно вскрылось — одним предложением.** Зелёный гейт означал не то,
что я думал: часть судей смотрела мимо подсудимых. Счётчик «налога оракула»
печатал 5 носителей из 15, единственное архитектурное правило обходилось
двумя пробелами отступа, запрет циклов держался на фразе «следует из
таблицы», а инвариант канала «один писатель» — на том, что никто не пробовал
написать напрямую. Ни одно из этого гейт не ловил, и я ссылался на этот
гейт в отчётах.

**Почему это отдельный класс, а не строки в старых.** Корень общий и он не в
коде: правило и его механизм расходятся МОЛЧА. Дефект в самом судье не даёт
красного по определению — он даёт зелёный, и чем дольше живёт, тем убедительнее
выглядит. Поэтому мера против класса — не «починить эти двадцать четыре», а
требование доказывать покрытие судьи мутацией ПОДСУДИМОГО, а не только
мутацией правила: самотест обязан показать, что судья видит каждую живую
форму того, что судит.

### К-K, вторая волна: повторное доказательство 2026-08-17 (вечер)

**Повод.** Владелец потребовал доказательства ещё раз — после того, как
дерево сдвинулось: две волны main, зеркало `E_MISSING_RETURN`, четыре
починенных судьи. Проверка повторена на текущем дереве в два прохода:
сначала мутацией ПОДСУДИМОГО проверены сами вчерашние закрытия, затем
четыре свежие атаки по измерениям.

**Итог по закрытиям: все четыре — «частично».** Судьи стали видеть кратно
больше (счётчик носителей 5 → 23 на синтетическом дереве, импорт с отступом
и цикл ловятся, прямая запись в канал ловится, понижение базы ловится), но у
каждого нашлась остаточная слепота. Это ожидаемо и это правильный результат:
«частично» — честная оценка судьи, которого атаковали всерьёз, а «полностью»
после одной итерации означало бы, что атака была слабой.

**Итог по свежей атаке: 23 находки, большинство НОВЫЕ** — то есть внесены
моей же работой этой смены. Шесть закрыты немедленно, остальные ниже.

**Единственная хорошая новость, и она важная:** зеркало `E_MISSING_RETURN`
проверено сорока пробами, и расхождения класса K7 («novac принял то, что
оракул отверг») нет ни на одной форме — все расхождения были в безопасную
сторону, и после починки их не осталось вовсе.

### Остаточная слепота судей — названа поимённо

Из отчётов опровергателей, дословно по существу:

* **Маркеры обхода.** Проходят молча: `until: E1` с пробелом после двоеточия;
  `until:` вне скобок маркера; файл с NUL-байтом (правило A слепнет);
  файл в UTF-16LE (невидим целиком). В сообщении правила A список мест пуст
  для слаговых форм.
* **Граф модулей.** Цикл судится только по ТАБЛИЦЕ, не по коду; при двух
  циклах в отчёт попадают мосты между ними. `import ../../m` схлопывается в
  пустоту.
* **Канал чекера.** Зелёными проходят: запись через алиас
  (`mut tbl = @out.types; tbl[0] = 0`); вторая дверь, объявленная методом
  `CheckOut` вне channel.nv; мутирующие методы (`push`/`fill`/`clear`);
  `@out.types[0] += 1`; знак `=`, перенесённый на следующую строку.
* **Храповик корпуса.** Сравнение идёт «рабочее дерево против HEAD»: в
  чистом checkout гейта это тавтология — закоммитил понижение, и зелено.
  `NOVAC_CORPUS=0` пропускает ратчет целиком.
* **Предупреждения сборки.** Земля судится по ВСЕЙ строке, а не по полю
  пути: `novac/src/x.nv:4:1: warning: unused import \`std/fmt\`` зелёное
  (чужое имя в тексте), а путь std с обратными слэшами — ложный красный.

Каждая из этих строк — работа, а не оговорка: судья, о котором известно, где
он слеп, честнее судьи, о котором это неизвестно, но зелёный он даёт
одинаковый.
### Что закрыто этой же волной

Три судьи, на которых я ссылался в отчётах, чинены немедленно — ссылаться на
слепого судью хуже, чем не иметь судьи вовсе:

1. **Счётчик носителей обхода** видел 5 из 15. Формы `[LEGACY-#701-slug]` и
   `[LEGACY-#700-slug until:E2b3]` не подходили под регексп, требовавший `]`
   сразу за цифрами. Следствие было не только в счёте: правило A (сверка с
   реестром 221.1) и правило эскалации «семья набрала второго носителя» для
   этих форм не работали в принципе. Заодно введено правило, которого не было
   вовсе: срок `until:<этап>` теперь судится машиной против `stage` из
   `novac/nova.toml` — «самоистекающий обход» перестал означать «автор
   вспомнит».
2. **Импорт с отступом** проходил мимо единственного архитектурного правила:
   якорь `^import` его не видел, а язык — принимает. Проба собиралась и
   создавала ребро вне таблицы.
3. **Запрет циклов** не имел механизма: документ утверждал, что ацикличность
   «следует из таблицы», а цикл добавляется строкой таблицы ровно так же, как
   честное ребро. Теперь алгоритм Кана, и в отчёт попадает сам цикл, а не всё,
   что в него ведёт.

Остальные строки таблицы — очередь работ; порядок разбора: сначала судьи
(правило без механизма), потом единственное `нарушено` (emit_c перерешает то,
что уже записано в канале — это класс О-1 внутри моего же компилятора), потом
расхождения документов с кодом.

## Находка F65 (2026-08-16, владелец): порядок вычисления аргументов теряется в C

**Где.** Оба эмиттера: оракул (`compiler-codegen/src/codegen/emit_c.rs`) и наш
`novac/src/emit_c` — оба печатают вызов «как есть», `f(a(), b(), c())`, и
отдают порядок на откуп C.

**Что не так.** Спека (`03-syntax.md`) объявляет порядок вычисления аргументов
**слева направо нормативным и observable**, и на нём же стоит правило точки
дизарма для consume («после того, как ВСЕ аргументы вычислены»). Стандарт C
порядок вычисления аргументов **не определяет** — при любом соглашении о
вызове. Проба 2026-08-16: программа с тремя печатающими аргументами выводит
`third, second, first`, то есть справа налево. Гарантия языка сегодня не
выполняется.

**Верное исправление — одно, и оно общее для всех «компилируемых в C».**
Гарантия живёт в **лоуэринге**, а не в целевом языке: вызов нормализуется в
A-нормальную форму — каждый аргумент вычисляется в именованную временную в
исходном порядке, а сам вызов берёт уже готовые временные. Тогда порядок,
который выберет C, ничего не решает. Так делают Nim, Vala, Cython, Chicken
Scheme (у Python/Scheme свой порядок, у C — свой); у языков с байткодом
(Java, C#) порядок задан порядком push'ей, у Rust/Swift — лоуэрингом в MIR/SIL.

**Цена — ноль.** Временные попадают под SSA и схлопываются оптимизатором;
на `-O0` остаётся присваивание, которое всё равно было бы.

**Что делаю я.** (а) `novac/src/emit_c` обязан вводить временные для
аргументов вызова, как только в подмножество войдут вызовы с эффектами;
сейчас в корпусе таких нет, но дефект структурный, а не отсутствующий.
(б) Фикстура в дифф-корпус: три печатающих аргумента, вердикт — порядок строк.
(в) Оракульская половина эскалирована в окно компилятора (реестр — за ним).

**Класс.** К-D («молчаливое расхождение с объявленной семантикой»): правило
записано в спеке, механизма проверки нет ни у одной стороны — ровно та же
форма, что у «правил без механизма» плана 254.

## Находка F66 (2026-08-16): диспетчер по ID ТИПА не судится стражем «нет ветки всё остальное»

**Как нашлась.** Разведка по дженерикам (вопрос владельца «по каким id ты ищешь»)
попутно указала на `emit_c` эмиссию `println`: цепочка `if at == prims.str_id …
else if bool_id … else if f64_id … else { nova_print_int }`. Ветка «остальное»
печатала **что угодно как целое** — запись ушла бы в вывод GC-указателем в виде
числа, молча. Это тот же класс, что П21, но диспетчер тут не по ВИДУ узла, а по
**id типа**.

**Дефект починен той же волной:** ветка `int` названа явно, «остальное» стало
`ice("emit_c: println of a type with no printer in the subset")`. C побайтово не
изменился (в корпусе печатаются только int/str/bool/f64). Первый этаж — отказ в
`check` — появится вместе с локальной типизацией (волна 3, C9): сегодня `check`
типов аргументов не знает.

**Дыра осталась в СТРАЖЕ, и это записано честно.** `check-novac-no-default-branch`
судит только диспетчер по `kind`. Попытка расширить его на сравнения `== *_id`
не прошла собственную приёмку: на подложке расширение не доказало ловлю (в
изолированном прогоне awk-логика срабатывает, внутри стража — нет; причина не
локализована). По П16 страж без доказательства запрещён, поэтому расширение
снято, а не оставлено «вроде работает».

**Что делать дальше:** либо локализовать расхождение (подозрение на
взаимодействие с блоком проверки пустого хвоста, добавленным в того же стража),
либо вынести проверку диспетчеров по id в отдельного стража с собственным
самотестом — вторая дверь тут законна, потому что предмет другой: у `kind`
множество закрыто и лечится исчерпывающим `match`, у типов оно открыто и лечится
только явным перечислением плюс отказом.

**Класс:** К-D («молчаливое расхождение с объявленной семантикой») плюс
собственный класс сессии — «правило есть, механизм не доказан».
