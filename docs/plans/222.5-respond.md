# План 222.5 — модуль `polaris.respond`: `IntoResponse` + типизированный статус

**Статус:** 📋 ДИЗАЙН, НЕ СОГЛАСОВАН. **Слой:** 2 (Polaris-ядро).
**Зависит:** 222.1 (✅ влит). Параллелен 222.3 (разные файлы; `IntoResponse` нужен его
арность-перегрузкам — влить ДО или ВМЕСТЕ с 222.3).
**Основа:** Axum `IntoResponse`. **Родитель:** [222](222-http-framework.md) · [222.0](222.0-module-map.md).

## 1. Протокол

```nova
/// Всё, что хендлер может вернуть. Позволяет писать `-> Result[Json[User], HttpError]`
/// вместо ручной сборки ServerResponse.
export type IntoResponse protocol {
    @into_response() -> ServerResponse
}
```

## 2. Реализации (бланкеты — ключевая ценность)

```nova
#impl(IntoResponse) fn ServerResponse @into_response() -> ServerResponse => @   // identity
#impl(IntoResponse) fn str            @into_response() -> ServerResponse => ServerResponse.text(StatusCode.OK, @)
#impl(IntoResponse) fn StatusCode     @into_response() -> ServerResponse => ServerResponse.empty(@)
#impl(IntoResponse) fn Json[T Serialize] @into_response() -> ServerResponse => ServerResponse.json(StatusCode.OK, @data())
#impl(IntoResponse) fn HttpError      @into_response() -> ServerResponse   // status по kind + JSON-тело ошибки

/// БЛАНКЕТ — даёт `?`-эргономику в хендлерах бесплатно:
#impl(IntoResponse)
fn Result[R IntoResponse, E IntoResponse] @into_response() -> ServerResponse =>
    match @ { Ok(r) => r.into_response(), Err(e) => e.into_response() }

/// Кортеж «статус + тело» (Axum-паритет `(StatusCode::CREATED, Json(x))`):
#impl(IntoResponse)
fn (StatusCode, R IntoResponse) @into_response() -> ServerResponse    // ⚠️ см. §5 — проверить
```

## 3. Расширение `ServerResponse`

```nova
/// JSON-ответ одним вызовом (сейчас — только через serdejson вручную).
export fn ServerResponse.json[T Serialize](status StatusCode, v T) -> ServerResponse

/// Заголовок fluent-стилем (property-конвенция).
export fn ServerResponse mut @header(name str, value str) -> @
```

## 4. Чинит «статус голым `int`» (§3.5 research-аудита)

Сейчас: `ServerResponse.text(200, s)` — голый `int`, при том что `StatusCode` **типизирован**
(`status.nv:14`, `StatusCode.new(u16) -> Result[…]`). Внутреннее противоречие; Axum здесь чище нас.

**План:** добавить `StatusCode`-принимающие перегрузки ко ВСЕМ конструкторам
(`text`/`html`/`bytes`/`empty`/`redirect`/`json`), int-формы пометить устаревшими в доке и
мигрировать сайты; удаление int-форм — отдельным шагом после миграции (не ломать флагман в одной
волне). Плюс константы `StatusCode.OK`/`.CREATED`/`.NOT_FOUND`/… если их ещё нет.

## 5. Открытые вопросы (решить на Ф.0, не угадывать)

1. **Кортеж-impl** `(StatusCode, R)` — поддерживает ли наш `#impl` реализацию протокола НА
   КОРТЕЖЕ? Если нет — форма `ServerResponse.json(status, v)` покрывает случай, кортеж отпадает.
2. **`HttpError.into_response`** — маппинг kind→статус и формат тела ошибки (голый текст vs
   JSON `{error, message}`): решить и зафиксировать, чтобы API был предсказуем.

## 6. Фазы
