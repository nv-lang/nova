# План 222.5 — модуль `polaris.respond`: `IntoResponse` + типизированный статус

**Статус:** ✅ РЕАЛИЗОВАН (ревизия «план vs код» 2026-07-31, ~98%): IntoResponse + 6 impl + blanket'ы, StatusCode-канон, deprecated int-мост — всё в nova-polaris. Кортеж-impl сознательно отклонён (задокументировано в response.nv). Остаток: снос deprecated int-форм — пост-тег.
**Зависит:** 222.1 (✅ влит). Параллелен 222.3 (разные файлы; `IntoResponse` нужен его
арность-перегрузкам — влить ДО или ВМЕСТЕ с 222.3).
**Основа:** Axum `IntoResponse`. **Родитель:** [222](222-http-framework.md) · [222.0](222.0-module-map.md).

## 1. Протокол

```nova
/// Всё, что хендлер может вернуть. Позволяет писать `-> Result[Json[User], HttpError]`
/// вместо ручной сборки ServerResponse.
export type IntoResponse protocol {
    @into_response() -> ServerResponse
}
```

## 2. Реализации (бланкеты — ключевая ценность)

```nova
#impl(IntoResponse) fn ServerResponse @into_response() -> ServerResponse => @   // identity
#impl(IntoResponse) fn str            @into_response() -> ServerResponse => ServerResponse.text(StatusCode.OK, @)
#impl(IntoResponse) fn StatusCode     @into_response() -> ServerResponse => ServerResponse.empty(@)
#impl(IntoResponse) fn Json[T Serialize] @into_response() -> ServerResponse => ServerResponse.json(StatusCode.OK, @data())
#impl(IntoResponse) fn HttpError      @into_response() -> ServerResponse   // status по kind + JSON-тело ошибки

/// БЛАНКЕТ — даёт `?`-эргономику в хендлерах бесплатно:
#impl(IntoResponse)
fn Result[R IntoResponse, E IntoResponse] @into_response() -> ServerResponse =>
    match @ { Ok(r) => r.into_response(), Err(e) => e.into_response() }

/// Кортеж «статус + тело» (Axum-паритет `(StatusCode::CREATED, Json(x))`):
#impl(IntoResponse)
fn (StatusCode, R IntoResponse) @into_response() -> ServerResponse    // ⚠️ см. §5 — проверить
```

## 4. Чинит «статус голым `int`» (§3.5 research-аудита)

Сейчас: `ServerResponse.text(200, s)` — голый `int`, при том что `StatusCode` **типизирован**
(`status.nv:14`, `StatusCode.new(u16) -> Result[…]`). Внутреннее противоречие; Axum здесь чище нас.

**План:** добавить `StatusCode`-принимающие перегрузки ко ВСЕМ конструкторам
(`text`/`html`/`bytes`/`empty`/`redirect`/`json`), int-формы пометить устаревшими в доке и
мигрировать сайты; удаление int-форм — отдельным шагом после миграции (не ломать флагман в одной
волне). Плюс константы `StatusCode.OK`/`.CREATED`/`.NOT_FOUND`/… если их ещё нет.

### 4а. Три вопроса владельца по `StatusCode` (2026-07-23, разобрано пробами)

Владелец спросил про `type StatusCode value { priv code u16 }`: (1) зачем u16, лишний каст;
(2) почему не newtype над int; (3) почему не enum с фиксированными значениями. Разбор (факты, не
мнение):

- **Q3 — enum отвергается по существу:** HTTP-статус это ОТКРЫТОЕ множество (серверы легально
  шлют 418/299/вендорские). Закрытый enum потребовал бы ветку `Unknown(u16)`, обесценивающую его.
  Rust (`http` крейт) и Go держат обёртку/константы, а не enum — по этой причине. Правая часть
  вопроса верна: нужны именованные **константы** (`StatusCode.OK`=200 …) — их СЕЙЧАС **ноль**
  (`export const` в `status.nv` = 0), пишется `StatusCode.new(200)?`. Это associated-константы,
  не enum-варианты — уже в плане выше. **БЛОКЕР (проба 2026-07-23):** namespaced `StatusCode.OK` через D200 сегодня НЕ собирается — D200 assoc-const тянет только скалярный constexpr, составное `{ code: 200 }` падает «non-constant exp». Целевая форма (D200-амендмент 2026-07-23): `const StatusCode.OK StatusCode = { code: 200 }` — out-of-body, доступ `StatusCode.OK`. Зависит от ДВУХ маркеров: `[M-assoc-const-out-of-body-syntax]` (парсер `const Type.NAME`) + `[M-d200-assoc-const-composite-value]` (составное значение в `.rodata`). До их закрытия временная дверь — module-level `export const OK StatusCode = …` (доступ голым `OK`).
- **Q2 — почему запись, а не newtype:** запись `priv code` + валидирующий `.new()` — ЕДИНСТВЕННАЯ
  форма, дающая инвариант «валиден по построению» (100..599). Проверено пробой: `type Status int`
  инвариант НЕ держит — и `Status(999)`, и голый `999` в позицию `Status` втекают (D55-коэрсия
  впускает сырой int). Так что запись не произвольна. НО инвариант **уже течёт**:
  `ServerResponse.status` голый `int` — серверный статус не валидируется вообще. Унификация (этот
  план) чинит.
- **Q1 — u16 vs int (НОВОЕ решение, план этого не пинал):** `int` в Nova адресного размера
  (`nova_int`=`intptr_t`); u16 экономит 6 байт/значение, но статусы не хранятся массово →
  выигрыша ноль, а цена реальна — **7+ сайтов `.as_u16() as int`** (respond.nv ×5, wire/client)
  из-за того, что `ServerResponse.status` это `int`. **Решение Ф.0:** поле обёртки хранить как
  **`int`, не `u16`** — каст-мост исчезает, ширина совпадает с унифицированным `ServerResponse.
  status: StatusCode`. u16 остаётся только на границе парсинга (провод отдаёт число), внутри — int.
  Маркер `[M-statuscode-u16-cast-bounce]`.

### 4б. `StatusCode` конструкторы — финал (владелец 2026-07-24, по nv-coding-style R1/R3а)

Вопрос владельца: «`fn StatusCode.new(code int) -> Result[…]` — реально нужен Result, может
контракт/`try_new`?» Разобрано по конвенции (§108-120, D325) + std-прецедент:

- **`try_new` ОТВЕРГНУТ** — R3а: `try_` это bool-попытка (`try_lock`) либо D77-конверсия
  (`from`/`try_from`), НЕ Result-падающий сиблинг `new`.
- **Контрактом целиком заменять НЕЛЬЗЯ** — `requires`-нарушение panic-класс (нерекаверабл),
  сетевой мусор паникнул бы фибру (DoS). Контракт — только для известно-валидного, не для провода.

**Итоговый API (A + unsafe-escape-hatch, всё по конвенции):**
```nova
export fn StatusCode.new(code int) -> Result[StatusCode, HttpError]   // A: primary, валидирует
                                                                       // (R1/R2, как Date.new/TimeOfDay.new)
export unsafe fn StatusCode.new_unchecked(code int) -> StatusCode      // escape hatch, БЕЗ проверки
const StatusCode.OK StatusCode = { code: 200 }                         // частые литералы (§4а)
```
`new_unchecked` = **`unsafe`** обязательно (std-прецедент `to_str`/`to_str_unchecked`; пропуск
проверки чеканит невалидный StatusCode=999 → ломает инвариант `@class()`; unsafe = инвариант на
вызывающем; явная greppable дверь, не молчаливая течь newtype из Q2). **Добавлять по факту нужды
в горячем пути**, не спекулятивно — для литералов консты + `.new(x)!` (паник-сетка, без unsafe)
уже закрывают; конструирование StatusCode не горячее. Маркер `[M-statuscode-ctor-result-vs-contract]`.

Таблица по границе доверия: частый стандартный → конста · недоверенный провод → `.new(x)?` ·
известный литерал → `.new(x)!`/конста · горячий+провалидировано → `unsafe { .new_unchecked(x) }`.

## 4а-РЕШЕНИЕ (владелец 2026-07-24): константы StatusCode — ЕДИНСТВЕННАЯ дверь

- **Форма — строго OUT-OF-BODY** (канон D200-амендмента, 02-types.md:8056): `const StatusCode.OK StatusCode = { code: 200 }` — вне тела типа, как `fn Type.new`; in-body формы НЕТ («одна дверь»). Парсер-кусок — [M-assoc-const-out-of-body-syntax] (компилятор-окно сразу после coalesce); окно №60 закрыло ортогональную половину (composite-значение в .rodata). До парсер-куска константы НЕ заводятся (in-body = против спеки), фабрики временно остаются с TODO.
- **Только assoc-const**: `StatusCode.OK`, `StatusCode.NOT_FOUND`, … Функции-фабрики
  `StatusCode.ok()/created()/moved_permanently()/…` — **УДАЛЕНЫ** (не депрекация: API до релиза,
  внешних потребителей нет; «константа И метод = две двери» — D9). Остаётся только
  конструктор-валидатор из произвольного `int` (parse-путь) — это другая операция, не дубль.
- **Нейминг — ПОЛНЫЕ имена по общепринятому канону** (сверка с Rust `http::StatusCode`),
  UPPER_SNAKE (образец `Duration.SECOND`): `OK`, `CREATED`, `NO_CONTENT`,
  **`MOVED_PERMANENTLY`** (не `MOVED` — неоднозначно), `FOUND`, `NOT_MODIFIED`, `BAD_REQUEST`,
  `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `METHOD_NOT_ALLOWED`, `REQUEST_TIMEOUT`,
  `PAYLOAD_TOO_LARGE`, `UPGRADE_REQUIRED`, `TOO_MANY_REQUESTS`,
  **`INTERNAL_SERVER_ERROR`** (не `INTERNAL`), `BAD_GATEWAY`, **`SERVICE_UNAVAILABLE`**
  (не `UNAVAILABLE`).
- Приёмка: греп `fn StatusCode.[a-z]` = 0 фабрик; все сайты пакета на константах.
