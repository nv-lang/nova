**Статус:** 🆕 PLANNED-DETAILED (детализирован 2026-08-03 по слову владельца «два языка
нам надо везде»; запуск фаз — по слову владельца, Ф.0 можно немедленно).
**Приоритет:** P2 (поднят с P3: полная двуязычная поверхность — релизное качество докы).
**Дом плана:** nova (источник переводов); сайт-фаза — www (план-указатель www/plans/07).
**Конвенция:** [docs/dev/doc-conventions.md](../dev/doc-conventions.md) (язык/нормативность/дрейф).
**Enforcement:** план [242](242-doc-conventions-guard.md) (страж парности/frontmatter/код-блоков).

## 0. Принцип «два языка везде» (владелец 2026-08-03)

Вся ПУБЛИКУЕМАЯ поверхность документации существует в en+ru парах:
- `docs/guide/**` — целиком (29 файлов; сейчас ru-пар только 3);
- `spec/` читательские файлы — 6 штук (en-переводы к русскому нормативу);
- сайт — полные двуязычные маршруты с hreflang и переключателем.
ИСКЛЮЧЕНИЯ (ru-only с честной пометкой на сайте, до отдельного слова владельца):
`spec/decisions/**` (~64k строк рабочего норматива — перевод взорвёт поддержание),
`spec/open-questions.md`, вся зона `docs/dev/**` (не публикуется вовсе).

## Фазы

- **Ф.0 — глоссарий (первым, утверждает владелец):** `spec/GLOSSARY.en.md` —
  единый словарь терминов (consume/ro/эффект-строка/файбер/скрутини/«одна
  дверь»/value-запись/встраивание use и т.д.), ~50-80 пар, с одним примером
  употребления на термин; для каждого термина — русская форма по норме
  «минимум английских слов» (doc-conventions #language) и явная пометка,
  если английская форма сознательно сохраняется. Без него параллельные батчи разойдутся в терминах.
  Исполнитель: sonnet; вычитка владельцем ДО Ф.1/Ф.1b.
- **Ф.0b — актуализация устаревших ИСХОДНИКОВ до переводов (слово владельца
  2026-08-03: «обновить для начала те доки, которые устарели»):**
  (а) `spec/paradigm.md` — единственный файл с шапкой «⚠️ УСТАРЕЛО»:
  содержательная ревизия под текущую парадигму (sonnet; вычитка владельцем —
  это лицо языка), шапка снимается; до ревизии файл в Ф.1 НЕ переводится
  (идёт последним, см. Resolutions глоссария п.3).
  (б) Быстрый скан остальных 5 spec-файлов + 29 guide на ВНУТРЕННИЕ
  устаревания без шапок (переименованные API — Time.now-класс, ro/readonly,
  снесённые формы — блок-realtime и т.п.): грep по известным ретракциям
  из spec/decisions history + точечные правки; находки крупнее точечных —
  списком интегратору, не молча.
  Приёмка Ф.0b: paradigm.md без stale-шапки, вычитан владельцем; скан-отчёт
  со счётом правок.
- **Ф.1 — spec en-переводы (sonnet, ru→en):** по H2-секциям с чекпоинт-коммитом
  на секцию (syntax.md — ~15 батчей, не один). Каждый файл: шапка «Informative
  translation; the Russian text is normative.» + frontmatter `source_rev`/
  `source_date` (коммит/дата ru-источника). Код-блоки БАЙТ-В-БАЙТ (машинный
  дифф в приёмке и в страже 242). Терминология — строго по Ф.0-глоссарию.
- **Ф.1b — guide ru-пары (26 файлов, en→ru):** распределение по сложности:
  терминологически-плотные (language-tour, contracts-класс, typed-pointers,
  consume-types, value-vs-reference, parameters, channels-класс) — sonnet;
  остальные (cookbook/CLI/инструкции) — opencode с Ф.0-глоссарием в брифе.
  Тот же frontmatter (`source_rev` = en-файл). Код-блоки байт-в-байт.
  Батчи по 3-5 файлов, чекпоинт-коммит на файл.
  Одновременно вводится `docs/guide/PUBLISHED.list` (канон публикации, план
  242 п.2): стартовый состав = все 29 (полная публикация — слово владельца
  2026-08-03), исключения только явной строкой с причиной.
- **Ф.2 — сайт (www; план-указатель www/plans/07):**
  - синк читает PUBLISHED.list из nova; тянет ОБЕ стороны пар:
    `content/doc/{en,ru}/`, `content/spec/{en,ru}/`;
  - маршруты: `/doc/<slug>/`=en, `/ru/doc/<slug>/`=ru — для ВСЕХ guide-пар;
    `/spec/<slug>/`=en-перевод (fallback ru+пометка, ни одна страница не
    404), `/ru/spec/<slug>/`=ru; decisions — ru-only с пометкой (как сейчас);
  - hreflang + переключатель RU/EN на каждой паре; ru-шапка ведёт в /ru/;
  - drift-баннер: `source_date` старше даты источника → баннер (обе зоны);
  - подвал 241-www (Edit/Source/дата) наследуется автоматически.
- **Ф.2b — пакетные доки на сайт (polaris и семья; добавлено 2026-08-03 по
  вопросу владельца «по какому плану дока полариса попадёт на сайт?» — до
  этого пункта НИ ПО КАКОМУ, дыра):**
  Инвентарь (снят 2026-08-03): polaris/docs — 26 файлов, УЖЕ двуязычные
  (X.md + X.ru.md пары: routing, extractors, middleware, auth, serving,
  websocket, batteries, errors, handlers-response, overview, static-files,
  roadmap); nova-http/tls/compress/bigint — только README (+README.ru при
  наличии).
  - Синк расширяется на пакетные репы: источник — main соответствующей репы;
    манифест публикации — `PUBLISHED.list` В КАЖДОЙ публикуемой репе
    (polaris: стартово все 26; остальные пакеты: README-пара как единственная
    страница пакета до появления их docs/).
  - Маршруты: `/doc/polaris/<slug>/` (en) + `/ru/doc/polaris/<slug>/` (ru);
    `/doc/<pkg>/` для README-страниц пакетов; индекс `/doc/` получает раздел
    «Packages». hreflang/переключатель/подвал/drift — как у остальной доки
    (подвал ведёт Edit-ссылку в репу-источник пакета!).
  - Страж 242 расширяется на пакетные PUBLISHED.list той же механикой
    (парность = красный; для README-пар — до появления .ru README у пакетов
    допускается warning с строкой-исключением в списке).
  - Версионирование: до тегов v0.1 синк с main пакетов; после релиза —
    решение владельца (main или тег) отдельной строкой.
- **Ф.2c — корректировка СУЩЕСТВУЮЩИХ ru-доков под норму «минимум английских
  слов» (слово владельца 2026-08-03; норма записана в doc-conventions #language):**
  проход по всем уже существующим ru-страницам — polaris/docs 26 ru-файлов +
  guide 3 ru-пары (+ ru-README пакетов) — замена англицизмов по норме и
  GLOSSARY; код-имена не трогать (машинный дифф код-блоков обязан остаться
  пустым). Исполнитель: opencode по словарю замен из GLOSSARY (готовит
  sonnet-вычитка первых 3 файлов как образец). Та же норма ДЕЙСТВУЕТ на все
  новые переводы Ф.1b с первого файла.
- **Ф.3 — поддержание:** правило «правишь публикуемый файл — правь пару ТЕМ ЖЕ
  коммитом» (уже в doc-conventions; страж 242 делает красным); дрейф spec-
  переводов: еженедельная opencode-микро-волна «догнать амендменты» (мелкие,
  не задевшие переведённый текст — только source_rev после сверки); баннер —
  при содержательном расхождении.

## Приёмка

- Ф.0: глоссарий вычитан владельцем (его слово).
- Ф.1/Ф.1b: у КАЖДОГО публикуемого файла есть пара; frontmatter валиден;

- Отчёты по-русски: модель, хеши, счёт файлов/секций, вердикты дословно.


## Для исполнителя из другой сессии (самодостаточность)

- **Онбординг (читать до старта):** [CLAUDE.md](../../CLAUDE.md) →
  [docs/dev/dev-workflow.md](../dev/dev-workflow.md) →
  [docs/dev/doc-conventions.md](../dev/doc-conventions.md). Жёсткие правила
  оттуда действуют целиком (git add по именам; git config не трогать; свой
  worktree `nova-p241` от свежего main; чекпоинт-коммит на батч/секцию;
  фоновые прогоны ждать ТОЛЬКО синхронно — завершать ход «жду уведомление»
  запрещено; отчёты по-русски с моделью).
- **Порядок фаз:** Ф.0 (глоссарий → вычитка владельцем, СТОП до его «ок») →
  затем ПАРАЛЛЕЛЬНО Ф.1 и Ф.1b (после Ф.0 независимы) → Ф.2 (www; только
  после влития Ф.1b-списка PUBLISHED.list в main nova) → Ф.3 фоновая.
  План 242 (страж) встраивается СРАЗУ ПОСЛЕ Ф.0: его проверки на старте
  вакуумно-зелёные и начинают ловить нарушения по мере появления пар —
  исполняется тем же агентом отдельной веткой `p242` ДО массовых переводов.
- **Машинный дифф код-блоков** (приёмка Ф.1/Ф.1b и правило 242): извлечь все
  ```-фенсы обеих сторон пары по порядку (awk по маркерам ``` достаточно) и
  сравнить попарно diff'ом; любой непустой дифф = красный. Скрипт создаётся
  в 242 (`scripts/tools/check-doc-conventions.sh`) и переиспользуется тут.
- **Сдача:** ветки `p241-glossary` / `p241-spec` / `p241-guide` / (www)
  `p241-site` — В MAIN НЕ ВЛИВАТЬ; приёмка и мерж — главный интегратор
  (авторитетные гейты у него). Компилятор не трогать вовсе; ```nova-блоки
  НЕ прогонять компилятором (не-скоуп, см. 242).
