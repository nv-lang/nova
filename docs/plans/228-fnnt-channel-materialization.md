## 1. Механизм (a) — HOF-биндинг: ЕДИНАЯ канал-питаемая регистрация

**Факт:** 196.4-канал (`resolved_types[call_id]`) УЖЕ несёт тип результата вызова. Для
`ro wrapped = mw.apply(h)` чекер пишет `resolved_types[rhs.id] = Named{Hnd}`. Легаси-армы
№78/№90 вручную ПЕРЕ-выводят это в emit-тайме (Ident-скан/Member-скан RHS) — дубль канала.

**Дизайн:** в ЕДИНОЙ точке эмиссии let/ro-биндинга (`emit_c`, где сейчас ветвятся армы
№78/№90): читать `resolved_types[decl.value.id]`; если результат — `Named{X}` и
`X ∈ fn_newtype_sigs` (или сам `Func{..}`) → одна общая регистрация
`fn_param_sigs[binding] = resolve_fn_typeref(X)`. Все шесть ручных армов (Ident/Call-L1/
Call-L2/Member-L1/Member-L2 + `fn_returns_fn_sig_l2`-пропагация) становятся недостижимыми →
NO-HIT-снос по готовым трейс-ID. Канал-промах (residual) — честный фолбэк на время флипа:
существующий legacy, потом диагностика.

*Чекер-дырка, которую закрыть по пути:* `resolved_types` для RHS-вызовов, чей возврат —
fn-newtype, уже пишется (№53/196.4)? Проверить на репро №90; если промах — донаполнить
продюсер (f1_check_call/resolve_return_channel), НЕ emit.

## 2. Механизм (b) — method-value-аргумент → node_substs

**Факт:** mvinfer-Step2m живёт потому, что арг-луп продюсеров 196.5 (`f1_check_call:10597`,
`resolve_return_channel:9688`) не типизирует method-value-аргумент (`Type.@method`):
`infer_expr_type` на нём даёт None → `unify_type` не видит пару → `node_substs` не пишется →
emit-тайм Step2m перевыводит из `method_overloads`.

**Дизайн:** научить ЧЕКЕР типизировать method-value-выражение: `Type.@method` →
`Func{params: [Recv]+params, ret}` из декларации метода (это чекерский `method_overloads`-
двойник уже есть в sig-реестре). Тогда штатный `unify_type(fn(T)->U, fn(int)->str)` в
СУЩЕСТВУЮЩЕМ арг-лупе связывает T/U → `node_substs[call_id]` наполняется штатной записью
196.5 → все три mvinfer-Step2m умирают NO-HIT'ом. Бонус: №82 (бланкет-method-value) —
проверить, закрывается ли той же типизацией (бланкет-сигнатура с подстановкой T=Type).

## 3. Механизм (c) — №96: capture-фильтр через resolved_callees

Фильтр «это глобальная fn, не захватываемый локал» обязан быть USE-SITE-точным: для
`Call{func: Ident(n)}` внутри замыкания — спросить `resolved_callees[call.id]` (чекер знает,
в КОГО резолвится вызов); глобальный каллиси → не захватывать `n`; локал-значение → захватывать.
Name-table эвристика (`var_types`) сносится. Красный пин `n96_*` из ветки p94 — приёмочный
(EXPECT 33 → GREEN).

## 4. №97 — отдельная эмиссия @then-композиции

Репро окна-1 (identity-middleware, без капчеров) — вход. Гипотезы НЕ фиксирую (окно
диагностирует само по репро: подозрение — @-receiver-значение внутри nested closure теряет
