## Зачем — одной фразой и одним замером

Собственная дверь диагностики называет СЕБЯ, а не виновника. Живой носитель: у `novac`
функция `ice()` строит JSON-отчёт с пустой позицией — `"primary":{"file":"","start":0,"end":0}`
(`novac/src/diag/diag.nv`), и её же docstring в `novac/src/main.nv` признаёт причину
дословно: «`ice()` cannot [name the file and line], because a wrapper reports its own body».
То же у любого прикладного `expect`/`require`-хелпера. У `assert` и контрактов локация
есть — её проставляет кодоген; пользовательскому коду этого канала нет.

## Что делаем — решения владельца 2026-09-02

Пересмотру в этом файле не подлежат, разбор в D468:

1. **`type CallerLoc { file str, line int }`** в прелюдии — ЗАПИСЬ (ссылочный тип), а не
   кортеж: значение есть указатель, одно слово, и будущая колонка не удорожает вызов;
2. **`fn caller_loc() -> ro CallerLoc`** — встроенная той же категории, что `size_of`.
   **Настоящего вызова нет**: кодоген подставляет константный указатель на статическую
   запись. Значение — «место ЭТОГО выражения», одно правило без режимов;
3. **место приезжает ОБЫЧНЫМ параметром с умолчанием** — `fn ice(msg str, loc CallerLoc =
   caller_loc())`. Работает потому, что умолчание в Nova подставляется НА МЕСТЕ ВЫЗОВА;
4. **правило тела:** если у функции есть параметр типа `CallerLoc`, его автоматически берут
   `requires`, `assert`, `debug_assert`, `panic` и `throw` (последний пишет его в поле
   `site` записи отказа, D462). **`ensures` — сознательное исключение** (решение владельца
   2026-09-03, три основания в D468): постусловие — вина самой функции, вызывающий не
   может нарушить его даже теоретически. Два таких параметра — отказ;
5. **явные формы** для случая «указать не свой параметр»: `requires bool[, str][, CallerLoc]`,
   `assert(bool[, str][, CallerLoc])`, `panic(str[, CallerLoc])`;
6. **цепочка пробрасывается РУКАМИ** — `ice(msg, loc)`.

## Что ОТОЗВАНО 2026-09-02 — читать до того, как открыть старую редакцию

Первая редакция этого плана строила ДРУГОЙ механизм. Он отозван владельцем целиком, и
перечисляется здесь поимённо, чтобы никто не построил его по сохранившейся копии текста:

- атрибут **`#track_caller`** и все семь слоёв его поддержки (лексер, токен, парсер,
  поле в `FnDecl`, …) — **не заводятся вовсе**;
- **скрытый параметр** `const CallerLoc*` в подписи эмитированного C — нет; ABI не трогается;
- **правила Р1/Р2/Р3** — схлопнулись в одно «место этого выражения»;
- **амендмент к [D437](../../spec/decisions/08-runtime.md#d437)** (кадр `?`) — СНЯТ, D437 без изменений;
- **универсальная смена поведения контрактов** («называет вызывающего ВСЕГДА») — снята;
  контракт без параметра ведёт себя как сегодня, и четыре фикстуры не трогаются;
- диагностики `E_TRACK_CALLER_ON_EXTERN` и `E_TRACK_CALLER_AS_VALUE` — не нужны, потому
  что нет ни скрытого параметра, ни изменения типа функции.

Причина отзыва — в D468, раздел «Почему неявный проброс отвергнут». Коротко: скрытый
параметр всё равно часть подписи, значит переезжает в ТИП функции, значит ломает 62 высшие
функции `std` (правило счёта — в D468; прежнее число 95 не воспроизводилось) и существующий код, передающий функцию с контрактом значением.

## Как это читается — на коде

**Пример 1. Дверь диагностики называет вызывающего.**

```nova
export fn ice(msg str, loc CallerLoc = caller_loc()) -> never {
    report(msg, loc.file, loc.line)      // место ВЫЗОВА ice(), не эта строка
}

// resolve.nv:412
ice("unresolved symbol")                 // loc = { file: "resolve.nv", line: 412 }
```

Почему так, если `caller_loc()` значит «место этого выражения»: умолчание подставляется
на месте вызова, то есть выражение физически оказывается в теле вызывающего.

**Пример 2. Цепочка из двух обёрток — приёмка №683.**

```nova
fn ice(msg str, loc CallerLoc = caller_loc()) -> never { … }

fn ensure(ok bool, loc CallerLoc = caller_loc()) -> () {
    if !ok { ice("check failed", loc) }  // ПРОБРОС РУКАМИ: без `loc` было бы ЭТО место
}

// typing.nv:88
ensure(t.is_known())                     // loc доезжает до ice(): typing.nv:88
```

## Не делаем (границы)

- **колонку** — только файл и строка. По устройству записи колонка добавляется полем и не
  удорожает вызов, поэтому откладывать её ничем не рискованно;
- **стек вызовов** — это трасса (D437), другая задача;
- **автоматический проброс через обёртку** — решение владельца, см. «Что отозвано»;
- **поддержку в `novac`** — подмножество Carina ведёт себя с новыми именами так же, как с
  `#realtime`: имя признаётся, поведение — работа трека 274, не этого плана;
- **правку носителя `novac/ice()`** — она в треке Carina; здесь только механизм оракула;
- **`ensures` под правилом тела** — решение владельца 2026-09-03 после приглашённого им
  спора (три основания — в D468): постусловие — вина самой функции; явной формы с
  `CallerLoc` у `ensures` тоже нет. Граница держится фикстурой Э3, а не памятью.

## Открытые вопросы (адресат, умолчание, срок)

1. **Законна ли `caller_loc()` ВНЕ позиции умолчания — ОТВЕЧЕНО владельцем 2026-09-03:
   ДА.** Законна в любой позиции выражения и означает «здесь» (аналог
   `__FILE__`/`__LINE__`); отдельного правила и отказа в чекере не требуется — правило то
   же самое. Внесено в D468.
2. **Распространяется ли правило тела на `ensures` — ОТВЕЧЕНО владельцем 2026-09-03: НЕТ**,
   и это разворот его же умолчания «да, ради единообразия»: владелец пригласил контрдовод
   и принял его. Основания (полный разбор в D468): доноры единодушны — Eiffel, D, Ada,
   C# Code Contracts винят за постусловие саму функцию; вызывающий не может нарушить
   `ensures` даже теоретически; Z3-ярус и так доказывает его из ТЕЛА. Тем же решением в
   правило тела ЯВНО добавлен `throw` — пишет `loc` в поле `site` записи отказа (D462).
3. **Что делать с формой в путях, где `callnorm` не нормализует вызов** (см. ловушку 1
   ниже). Адресат: интегратор. **Умолчание — отказ в чекере с внятным текстом**, а не
   расширение `callnorm`: расширение трогает зону, которая по комментариям уже роняла
   компилятор в ICE. Срок: до Э2, это часть её приёмки.

Блокирующих вопросов без разумного умолчания нет.

## Как это реализовать — механизм

### 1. Что вообще меняется — гораздо меньше, чем в первой редакции

Атрибута нет, скрытого параметра нет, подпись эмитированного C не меняется, ABI не
меняется. Остаются **шесть точек**:

| # | точка | место в дереве |
|---|---|---|
| 1 | прелюдия: объявление `type CallerLoc` | `std/src/prelude/core.nv` — там объявлены `Option` (:32) и `Result` (:37) ✔ сверено |
| 2 | резолвер: имя `caller_loc` признаётся без объявления | `types/mod.rs:36793` (категория `size_of`/`align_of`) |
| 3 | чекер: тип результата `ro CallerLoc` | `types/mod.rs:11146` — с оговоркой, см. ниже |
| 4 | **`callnorm`: подстановка на месте вызова** | `callnorm.rs:818-834` |
| 5 | кодоген: статическая запись + дедупликация | `codegen/emit_c.rs:1744-1764` (образец — интернирование литералов) |
| 6 | чекер: правило тела, отказ на два параметра, третий слот у `requires`, перегрузки `assert`/`panic` | `types/mod.rs`, `parser/mod.rs` (`parse_opt_contract_message`) |

### 2. Ключевой механизм — точка 4, и она уже наполовину существует

Замер 2026-09-02, читан код, а не память:

- `callnorm.rs:693` — `let sp = e.span;`, где `e` есть **вызов**. То есть `sp` — span
  вызывающего сайта;
- `callnorm.rs:818` — `let def = param.default.clone();` — умолчание КЛОНИРУЕТСЯ;
- `callnorm.rs:831` — `rename_idents(&mut def, &rename);` — клон уже правится на месте, и в
  комментарии рядом записано, что это законно: «это не substitution walk по программе,
  которого D102 избегает, а правка скопированного выражения»;
- `callnorm.rs:834` — клон кладётся в `let_stmt_typed(&bn, def, Some(param.ty.clone()), sp)`,
  то есть в блок, который ЗАМЕНЯЕТ вызов на месте вызова. **В первой редакции этого плана
  стояли `:830` и `:838` — обе мимо на строку-другую.** Найдено перепроверкой; урок тот же,
  что был с `ast/mod.rs:497`: адрес, выписанный по памяти сразу после чтения, — всё равно
  адрес по памяти.

**Значит подстановка `caller_loc()` встаёт ровно туда же, рядом с `rename_idents`, и
получает `sp` даром: прецедент правки клона есть, новой архитектуры не требуется.**

**НО НЕ ВНУТРЬ того `if`, и это ловушка, стоящая отдельного предупреждения.** Правка клона
стоит под условием `if !rename.is_empty()` (`:830`), а переименование — это фикс реестра
**№799** (закрыт 2026-08-31), и срабатывает он, только если фаза 1 что-то положила, то есть
**если у вызова есть хотя бы один ЯВНЫЙ аргумент**. Вызов, состоящий из одних умолчаний
(`ice()`), оставляет `rename` пустым. Подстановка `caller_loc()`, повешенная внутрь этого
условия, для таких вызовов молча не сработает — и `loc` укажет на объявление. Подстановка
идёт РЯДОМ с условием, не под ним, и фикстура на вызов без единого явного аргумента входит в
приёмку Э2.

**Оговорка к точке 3, найденная перепроверкой.** `types/mod.rs:11146` типизирует интринсики в
форме `size_of[T]()` — то есть ветку `ExprKind::TurboFish` (в коде рядом:
`if let ExprKind::Ident(tf_n) = &tf_base.kind`). У `caller_loc()` типового аргумента НЕТ, это
голый вызов, и приходит он ДРУГОЙ веткой. Значит «рядом с типизацией `size_of`» — верный
ориентир и неверный адрес: ветку под голый вызов исполнитель обязан найти сам первым же шагом
Э1 и вписать её адрес сюда. Комментарий на месте называет три соседних спец-кейса (`:2000`, `:2271`, `:16365`) —
начинать с них.

Проверено сборкой и запуском (проба 2026-09-02): запись, `-> ro CallerLoc` и **вызов в
позиции умолчания** компилируются и работают уже сегодня.

### 3. Каналом чекера, а не догадкой эмиттера (правило плана 196)

Решение «эта позиция даёт вот такую статическую запись» принимает чекер и кладёт в канал;
эмиттер ЧИТАЕТ. Переспрашивать синтаксис в эмиттере — класс О-1 (реестр №716). Канал
обязан быть проведён во все три драйвера кодогена — страж `check-driver-channel-parity.sh`,

### 4. Ловушки, названные ЗАРАНЕЕ

**Ловушка 1 — `callnorm` местами отказывается нормализовать, и тогда умолчания не будет.**
`callnorm.rs:548` возвращает `None` для `TurboFish` поверх `Member` (метод с явными типовыми
аргументами); есть и общий нижний `_ => return None`.

**ПЕРВАЯ РЕДАКЦИЯ ЭТОЙ ЛОВУШКИ БЫЛА НЕВЕРНА В ДВУХ МЕСТАХ, И ОБА — ОТ ДОВЕРИЯ КОММЕНТАРИЮ В
КОДЕ ВМЕСТО ЗАПУСКА.** Здесь стояло, что (а) при перегрузке свободной функции нормализация
тоже пропускается и (б) отказ «ГРОМКИЙ», потому что комментарий на месте обещает «a plain
arity mismatch — a diagnosed compile error, never a crash». Пробы сборкой 2026-09-02:

- перегруженные свободные функции **есть, и умолчание у них подставляется** — вызов,
  удовлетворимый только через умолчание, печатает `6`;
- отклоняемая форма падает **не диагностикой Nova**, а ошибкой компилятора C
  (`too few arguments to function call`) на искажённом имени. Заведено как **реестр 221.1
  №886**, пробы с контролем — `docs/plans/repro/p886/`.

**Умолчание по вопросу 3 от этого не меняется, но меняется его основание:** отказ в чекере
при объявлении нужен не потому, что ошибка арности невнятна, а потому, что сегодня НИКАКОЙ
ошибки Nova там нет вовсе. Обе половины этой ловушки согласованы с приёмкой Э2 ниже —
расхождение между ними держалось два часа и было найдено третьей перепроверкой; урок общий:
правка по разделам без перечитывания файла целиком порождает документ, спорящий сам с собой.

**Ловушка 2 — статика и GC.** Измерено: живых бэкендов два (`alloc.c`, `alloc_boehm.c`),
оба терпят указатель вне кучи; Boehm вдобавок идёт с `GC_set_no_dls(1)`
(`emit_c.rs:10198`) — статические данные не сканируются, и сканировать нечего. Третий файл
`alloc_rc.c` со счётчиком ссылок в сборку НЕ подключён (греп по `src`, `nova-cli`,
`scripts`, `.github` — ноль). Подключат — статике понадобится бессмертный счётчик.

**Ловушка 3 — снимок `novac` НЕ протухает, и это отличие от первой редакции.** Эмиссия
функции, не объявившей параметр, не меняется вовсе, значит предсобранный рантайм-архив и
`shell.tpl.c` остаются валидными. В прежней редакции скрытый параметр менял подписи и
требовал пересборки снимка — этой работы больше нет.

**Ловушка 4 — «правило тела» не должно молча промахиваться.** Если у функции параметр
`CallerLoc` есть, а контракт всё равно печатает строку объявления — это тихий провал,
который зелёный прогон не поймает. Приёмка Э3 обязана пинать номер строки ВЫЗЫВАЮЩЕГО, а
не только текст паники.

## Этапы и приёмка

Приёмка везде машинная, кроме прямо названного глазами. Каждая фикстура сопровождается
**пробой красноты**: сломать своё же условие, увидеть FAIL именно на ней, восстановить.

**Что запускается и что считается доказательством — один раз на все этапы, чтобы каждый не
повторял.** Команда:

```sh
nova-cli/target/release/nova test spec_tests --filter <имя-фикстуры>
```

Доказательством считается **строка после `===== SUMMARY =====`** вида `PASS: N  FAIL: 0` —
проверено запуском 2026-09-02, формат приведён дословно. Отчёт, называющий счёт, которого
исполнитель не видел своими глазами в этой строке, приёмкой не является; краснота
доказывается той же строкой с `FAIL: 1` и именем ровно своей фикстуры в выводе выше.

**Э1. Тип и встроенная — «здесь».**
`caller_loc()` в обычном выражении даёт файл и строку самого выражения.
Приёмка: фикстура в `spec_tests/conformance/standalone/`, `EXPECT_STDOUT` с точной парой
`файл:строка`; отдельная фикстура на то, что тип виден из модуля без импорта (прелюдия).

**Э2. Умолчание даёт место ВЫЗОВА.**
Приёмка: одна фикстура, в ней ДВА вызова одной функции с РАЗНЫХ строк — печатаются разные
номера (иначе тест зелёный и при подстановке строки объявления). **Негативная половина этого этапа переписана 2026-09-02 по замеру: прежняя посылка была неверна в
ОБЕИХ половинах.** Первая редакция предлагала фикстуру «на путь, где `callnorm` не нормализует —
перегруженная свободная функция». Пробы (`build`, не чтение) говорят другое:

- **перегруженные свободные функции в Nova ЕСТЬ и умолчание у них подставляется.** Две `fn tag`
  разной арности собираются; вызов, удовлетворимый ТОЛЬКО через умолчание, печатает `6` —
  то есть умолчание подставлено. Комментарий в шапке `callnorm.rs` («D102: overload нет»)
  отстал от компилятора, и планировать по нему нельзя;
- **путь, который `callnorm` действительно отклоняет** (`:548`, turbofish поверх `Member`),
  проваливается НЕ диагностикой Nova. Комментарий на месте обещает «a plain arity mismatch — a
  diagnosed compile error, never a crash»; на деле ошибка утекает до компилятора C:
  `too few arguments to function call, expected 3, have 2` на искажённом имени
  `Nova_Box_method_wrap____nova_str`. Это отдельный дефект, заведён как **реестр 221.1 №886**,
  пробы с контролем — `docs/plans/repro/p886/`.

Отсюда приёмка негативной половины: фикстура берёт РЕАЛЬНО отклоняемую форму (turbofish на
методе с умолчанием) и требует **диагностики Nova, а не ошибки C** — line-pinned `nova:expect`.
Пока №886 открыт, этап Э2 закрывается без неё, и это записано, а не подразумевается: требовать
здесь того, чего компилятор ещё не умеет, значило бы держать план заложником чужой строки.

**Э3. Правило тела.**
Приёмка: по фикстуре на `requires`, `assert`, `panic` и `throw` — каждая пинает номер
строки ВЫЗЫВАЮЩЕГО (ловушка 4; у `throw` судится поле `site` записи отказа, D462). Плюс
негативная на ДВА параметра `CallerLoc` → `[E_AMBIGUOUS_CALLER_LOC]`, line-pinned.
**Плюс граничная фикстура на `ensures` — решение 2026-09-03 держится ею, а не памятью:**
у функции С параметром `CallerLoc` нарушенное постусловие обязано по-прежнему называть
СВОЮ строку, не вызывающего. Проба красноты границы: заменить в фикстуре `ensures` на
`requires` — названное место обязано смениться на вызывающего.

**Э4. Явные формы.**
Приёмка: фикстура на `requires bool, str, CallerLoc` и на `requires bool, CallerLoc`
(различение литерала и значения); на `assert` во всех четырёх формах; на `panic(str,
CallerLoc)`.

**Плюс страница гайда — здесь, а не «когда-нибудь».** Инвентарь ниже обещает это как часть
приёмки Э4, и до третьей перепроверки обещание висело в воздухе: сама приёмка о гайде
молчала. Приёмка глазами, потому что читаемость документа машиной не судится: страница в
`docs/guide/` по образцу `docs/guide/size-of-align-of.md`, с обоими примерами из раздела «Как
это читается — на коде» и с явно названной ценой (проброс цепочки — руками). Основание —
замер: у `#blocking` страницы нет до сих пор, и это ровно то, как «потом» выглядит через год.

**Э5. Цепочка — приёмка строки реестра №683.**
Две обёртки, место доезжает до исходного вызова. **Проба красноты именно этой фикстуры:**
убрать `loc` из проброса в среднем звене — покраснеть обязана ровно она, а соседние Э3/Э4
остаться зелёными (иначе фикстура проверяет не цепочку, а сборку).

**Э6. Носитель — трек Carina, и потому у него отдельный судья.**
`novac/ice()` называет виновника. Приёмка: JSON-отчёт `novac` на фикстуре с намеренной
внутренней ошибкой несёт НЕПУСТУЮ позицию — то есть `"primary"` с реальным `file` и
ненулевым `start`, вместо сегодняшнего `"primary":{"file":"","start":0,"end":0}`, который и
есть носитель строки №683. **Судит окно 274**, не этот план и не интегратор: правило проекта
— стража или фикстуру, удерживающую класс, пишет тот, кто ЧИНИТ дефект. Этап НЕ блокирует
Э1–Э5 и НЕ входит в их приёмку; строку №683 закрывает механизм оракула плюс эта проверка,
и до её появления строка остаётся открытой.

**Э7. Цена — ратчет.** Эмиссия функции БЕЗ параметра `CallerLoc` обязана остаться
байт-в-байт прежней: платит только тот, кто объявил параметр.

**Откуда берётся база — сказано, потому что «сравнить до и после» после слияния
невоспроизводимо.** До первой строки кода Э1 исполнитель собирает нынешним бинарём C для
фикстуры, где `CallerLoc` не упоминается вовсе, и КЛАДЁТ ЭТОТ ФАЙЛ В ДЕРЕВО как базу
(рядом с фикстурой, с датой и хешем бинаря в шапке). Приёмка каждого следующего этапа —
**побайтовое** равенство свежей эмиссии этой базе — и оба прогона идут с **`NOVA_CACHE=0`**,
иначе сравнивается закэшированный артефакт сам с собой и проверка пуста.

**Побайтово — законно, и вот чем это доказано** (проверено по документам, а не принято на
веру): недетерминированность эмиссии закрыта 2026-07-20 вместе с маркером
`[M-codegen-emission-nondeterminism]`; доказательство в записи OPEN-view — три цели
(пустышка, collections-драйвер, флагман) собраны по три раза с `NOVA_CACHE=0`, **SHA256
идентичен 3/3 на всех трёх**, тогда как ДО фикса флагман давал разницу в 68–86 строк между
запусками.

**Ловушка для того, кто пойдёт по ссылке следом за мной.** Раздел «Остаток» плана 145.2
(2026-06-15) говорит, что порядок `NovaOpt`-typedef'ов всё ещё недетерминирован, — и это
УСТАРЕЛО: та же запись OPEN-view прямо называет остаток «снятым по опровержению» (ноль
совпадений `NovaOpt` в диффах на цели, интенсивно гоняющей `Option`). Я на этом успел
споткнуться и ослабить приёмку до «нормализованного» сравнения; статус маркера решает
OPEN-view `docs/plans/backlog-followups.md`, а не прозаический раздел старого плана.

**Чего эта проверка НЕ доказывает, и это надо сказать:** она судит один файл, а не корпус.
Утверждение «никто, кроме объявивших, не платит» проверяется ею лишь на выбранном образце;
расширять образец до подпапки — работа того этапа, где эмиссия впервые меняется.

## Цена и за чей счёт

Работа **оракульская**, и это надо назвать прямо: месяц отдан плану 274 (Carina), а оракул
по решению 274 §1.4 получает только блокеры тега и работы плана 221. Строка №683
блокером тега НЕ помечена. Значит план 280 исполняется **по слову владельца** (2026-09-02
«пиши план + спеку»), а не по остаточному принципу, и время берётся у оракульской очереди
221.1 — то есть в эти окна не двигаются другие открытые строки реестра. Если приоритет
изменится, план останавливается на границе этапа, а не посередине.

**Отзыв неявной формы объём УМЕНЬШИЛ**, и это стоит сказать числом: из инвентаря выпали
семь слоёв поддержки атрибута и вся работа по скрытому параметру в подписи, пересборка
снимка `novac` и правка четырёх фикстур контрактной паники. Осталось шесть точек, из
которых одна (подстановка в `callnorm`) встаёт рядом с существующим прецедентом.

## Инвентарь мест — собран ДО первой строки кода

**Правило счёта:** «место» = отдельная строка в дереве, где имя встречается как ЧАСТЬ
МЕХАНИЗМА (резолвер, чекер, кодоген, спека, дока, фикстура, декларация в прелюдии), а не
как слово в комментарии.

**Встроенная (`caller_loc()`) — по образцу `size_of`/`align_of`:**

| слой | место |
|---|---|
| резолвер: имя признаётся без объявления | `types/mod.rs:36793` — `if name == "size_of" \|\| name == "align_of" { return true; }` ✔ сверено интегратором |
| чекер: тип результата | `types/mod.rs:11146` — ветка `TurboFish` (`size_of[T]()`); у голого `caller_loc()` ветка ДРУГАЯ, её ищет Э1, см. «Оговорка к точке 3» |
| кодоген: эмиссия | `codegen/emit_c.rs:36827` (там `sizeof`/`_Alignof`; наш — статическая запись) |
| дедупликация статики | `codegen/emit_c.rs:1744-1764` (интернирование строковых литералов) |
| подстановка умолчания | `callnorm.rs:693` (span вызова), `:818` (клон), `:831` (правка клона), `:834` (клон кладётся в блок на месте вызова) ✔ сверено |

**Урок из первого инвентаря, который план обязан не повторить:** у `#blocking` **нет ни

**Общий урок того же обхода, он дороже цифр:** из пяти адресов, названных агентом,

утверждалось. Выдача агента годится как карта; каждый адрес перед употреблением сверяется
грепом.
