# Plan 189 — Виртуальные часы: гарантия порядка под armed M:N (вынос из 175)

**Статус:** 📋 PROPOSED 2026-07-10 (решение владельца — выделить в отдельный план).
**Зонт:** [175](175-time-system-rework.md) Ф.5 (auto-idle-advance). **Приоритет:** P2.
**Маркер:** `[M-175-vclock-armed-mn-scope-identity]`.

## Что уже есть (175 Ф.5, влито)

`mut_clock`-хендлер: `sleep(d)` считает абсолютный дедлайн и паркует фибр через
`nova_vclock_park_until` (`nova_rt/fibers.h`, поля `NovaFiberQueue.vclock_*`);
когда весь scope idle — просыпается ближайший по дедлайну (tokio-паритет
auto-idle-advance). Работает: тест со `sleep(10_000)` завершается мгновенно.

## Проблема (объём этого плана)

Гарантия ПОРЯДКА пробуждения таймеров держится только под **кооперативным**
путём (`NOVA_MAXPROCS=1` + `NOVA_AUTOARM=0`). Под дефолтным **armed M:N**
`_nova_active_scope` внутри фибра указывает на приватный `w->scope` воркера, а не
на общий scope `supervised{}` — механизм безопасно ДЕГРАДИРУЕТ (без гарантии
порядка), но не гарантирует, что таймеры сработают в порядке дедлайнов.

Это НЕ баг корректности (значения времени верны, дедлоков нет) — теряется
детерминизм порядка при конкурентных виртуальных снах на разных воркерах.

## Корень

Идентичность scope'а: под armed M:N нет единого «текущего supervised-scope»,
видимого всем воркерам — каждый воркер держит свой. Виртуальные часы scope'а
должны быть общими для всех детей scope'а независимо от воркера.

## Дизайн (эскиз, sign-off нужен)

- **Протянуть scope-identity сквозь armed-путь:** ребёнок `supervised{}` при
  парковке на vclock должен адресовать ОБЩИЙ vclock scope-родителя (через
  retained SpawnCtx 173.0 / per-scope хендл), а не приватный `w->scope`.
- **Сериализованный advance:** решение «прыгнуть к ближайшему дедлайну» — на
  drive-потоке scope'а (как decision-loop супервизора 173.0/173.2), под тем же
  барьером, что гарантирует «все дети idle». Одна точка продвижения = порядок
  детерминирован.
- Взаимодействие с реальными часами: virtual-режим активен только под
  `mut_clock`-хендлером; real-clock путь не задет (байт-паритет вне virtual).

## Фазы

- **Ф.1** scope-identity через armed-путь (SpawnCtx-канал vclock).
- **Ф.2** сериализованный advance на drive-потоке + барьер all-idle.
- **Ф.3** тесты: N конкурентных `sleep` на разных дедлайнах под armed M:N →
  строгий порядок пробуждения; real-clock non-regression.

## Гейты

conformance; std/time + civil δ0; порядок-тест зелёный под дефолтным armed M:N
(не только MAXPROCS=1); байт-паритет real-clock пути.

## Границы

Не меняет user-facing API (`sleep`/`sleep_until` те же); только внутренний
рантайм-механизм. Не трогает civil-time (175.1).
