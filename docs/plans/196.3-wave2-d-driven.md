## Идея — две ВСТРЕЧНЫЕ волны, сходятся в середине

- **Волна-1 (196.2, bottom-up):** по 114 веткам `infer_call_ret_c` — удаляет legacy-ветки (gate-1). Держит
  ВСЮ `infer_call_ret_c` (`emit_c.rs` 46293-48883).
- **Волна-2 (196.3, top-down, D-driven):** по ИНВЕНТАРЮ второго окна (таблица ~30 функций, см. 196) — каждую
  функцию → её D-фиче → полный тест-набор → переписать на новый путь → закрыть. Держит СИБЛИНГ-функции ВНЕ
  диапазона 46293-48883 + `callnorm`/`argbind`/резолверы.

## Метод (идти по инвентарю → D)

Для КАЖДОЙ сиблинг-функции инвентаря:
1. Сопоставить её **D-фиче** (языковой фиче, которую она обслуживает; уточнить точные D-номера).
2. Покрыть фичу **полным conformance-набором** (`d<NNN>_*.nv`; red-до/green-после где применимо). Тесты —
   независимые файлы, параллельно-безопасны обеим волнам.
3. **Переписать на новый путь** (резолв/инференс → чекер → `resolved_types`/`resolved_callees`, per «Целевая
   архитектура» в 196; rustc-эталон; **no new window / §3** — сходимость на существующий путь, не новый сайт).
4. **ЗАКРЫТИЕ D = D работает через новый компилятор (по архитектуре) + удаление legacy-функции ИЛИ
   `panic!("[MIGRATED-<D>]")`** (если переплетена / SHARED-хелпер зовётся волной-1 → detach/panic, НЕ удалять
   пока зовётся).

## Партиция (без конфликта регионов)

**Область волны-2 = ВЕСЬ инвентарь второго окна КРОМЕ `infer_call_ret_c`** (это единолично волна-1/196.2). То
есть волна-2 держит: все сиблинг-`infer_*`/`resolve_*` (`infer_static_method_ret`, `infer_lambda_return_type_with_params`,
`infer_method_level_return_for_sum`, `resolve_result_*`, `infer_type_param_binding`×3, `infer_protocol_structural_binding`,
`infer_result_type_params`, `infer_trailing_block_sig`, `resolve_method_level_subst`, `compute_array_elem_type_for_obj`)
+ `callnorm`/`argbind` + method/static-резолверы + `primitive_instance_method_known` + `type_ref_to_c` + 56×
`_c_type`-хелперы — ВСЕ ВНЕ диапазона 46293-48883 (разные регионы/файлы → merge-чисто). **Сам диспетчер
`infer_expr_c_type` удаляется на ФИНАЛЕ** (когда обе волны закончили). **mono-машинерия** (`compute_mono_name`/
`compute_generic_type_c_name`/`register_generic_instances`) НЕ мигрируется — остаётся в codegen (целевая
архитектура / rustc). **SHARED-хелперы** (зовутся из `infer_call_ret_c`): мигрировать логику в чекер, удалять
только когда волна-1 больше не зовёт (до того detach/panic). **Тесты — параллельны обеим.**

таблица **D → покрыто / НЕ-покрыто** (какие D-фичи инвентаря уже экзерсируются conformance'ом, какие нет) —
в ледере `196.wave2-progress.md` (волна-2 строит первым заходом: `ls spec_tests/conformance/**/*.nv` → мапит
d<NNN> на инвентарь-функции). Для **НЕ-покрытых** D-фич волна-2 ДОБАВЛЯЕТ conformance ДО миграции; для
**покрытых** — byte-parity на существующем тесте = гарантия миграции (red-до/green-после где вводится новый).
