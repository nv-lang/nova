# 221.2 — Каталог «мест на удаче» (аудит-волна 2026-08-02)

**Статус:** 📒 РЕЕСТР-КАТАЛОГ (не план работ; работы разнесены по волнам
196-one-truth-closeout W1-W6/S1-S2 и 221.1-реестру №№259-266).
**Происхождение:** вопрос владельца «что ещё у нас работает на удачу?» →
read-only opus-аудит compiler-codegen по паттернам fallback/tie-break/
молчаливый дефолт/контракт-без-принуждения/порядко-зависимость/текстовые
контракты/санитизация. Известные на момент аудита образцы (№250/253/254/255,
P67-класс, B12h) исключены из каталога — здесь только НОВЫЕ находки.
**Правило:** каждая корзина имеет № в 221.1 (№259-№266); закрытие точек —
отметками прямо в таблицах ниже.

Легенда серьёзности: **ТП** = тихая порча (неверный C собирается и работает),
**CC** = поздняя диагностика C-компилятором/линкером, **ICE** = паника.

## ТОП-5 по опасности (сводка аудитора)

1. **№259 Sentinel-конфляция** `nova_int`/`NovaOpt_nova_int`/`NovaRes_nova_int_nova_str`
   как маркер «не смогли вывести» — валидные типы честных программ теряют право
   голоса; строковый `.replace()` по сэмитированному C (34085-34107) переписывает
   ВСЕ вхождения None-паттерна. ТП высшей категории, бьёт по самому частому типу.
2. **№260 Single-candidate резолв без проверки** — 8 сайтов, где при одном
   кандидате пропускается сверка арности/типов; при нуле — `pool.first()`.
3. **№261 `ident_is_typevar` по форме имени** — любой ≤2-символьный uppercase
   (`IO`, `ID`, `DB`, `OS`, `UI`, `IP`, `KV`) молча становится типовой переменной;
   на depth-1 гейта нет вообще.
4. **№262 Кольцо взаимных допущений чекер↔кодоген** — permissive-чекер ссылается
   на «финальную проверку кодогена», кодоген — на «чекер уже гарантировал»;
   ни одна сторона не проверяет.
5. **№263 Реестры на голом имени + first-wins vs last-wins на одной карте** —
   «right name, wrong body, wrong C type» в штатном merged-CU режиме.

Плюс два сквозных класса: **№264 санитизация/манглинг с потерей информации**
(неинъективные санитайзеры, nv_-префикс, 32-битный хеш-суффикс с ложным
«сохраняет уникальность», assoc_ro `Foo_BAR`, split_tu guard) и **№265
текстовые контракты** (split("__") в operator_dispatch при length-prefixed
рядом, scan_module_decl текстовым сканом, три расходящихся санитайзера,
греп-детекты test_runner). **№266** — U.4.3 side-effect класс: 
`infer_expr_c_type` не чистая функция, регистрация typedef/mono — 
load-bearing побочный эффект запроса типа (обобщение №250; закрывается 
W5 mono-фазой).

Контрпримеры правильной дисциплины (для ratchet-формулировок):
`may_gc.rs:1486` (контракт закрыт assert), `overload_sig.rs:60-66` (честный
None вместо угаданного), `parse_mono_tuple_elements` (length-prefixed вместо
split).
