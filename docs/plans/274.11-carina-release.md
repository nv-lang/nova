## Пункты

### 1. Фасад `polaris.serve(app, ":8080")` — единственное, что реально открыто в 222.22

**Статус по коду: построено на две трети, открыт один пункт приёмки из трёх.**

Приёмка 222.22 дословно: `nova test src --strict-effects` polaris δ0 + смоки ·
флагман собирается и живёт под нагрузкой · **README-пример
`polaris.serve(app, ":8080")` РАБОТАЕТ дословно**.

Третье не выполнено, и проверено это грепом: такой формы нет ни в коде, ни в
README. В README стоит `import polaris.serve.{serve_router}`; ближайшее в коде —
`serve_addr(addr str, router Router, policy ServerPolicy, stop Option[CancelToken] = None)`
(`../nova-polaris/src/serve/serve.nv:63`), то есть другое имя и обязательный
третий аргумент.

**Работа:** либо фасад `polaris.serve(app, addr)` с умолчанием политики, либо
решение переписать приёмку под то, что построено. Час работы, не блокер.

**Первые два условия НЕ ПРОВЕРЕНЫ** — это прогоны, машина была занята.

**ЗАМЕР 2026-09-18 (интегратор), И ОН МЕНЯЕТ РАЗВИЛКУ: буквальная форма
`polaris.serve(app, ":8080")` упирается не в час работы, а в слоевой контракт
пакета.** Чтобы вызов читался ИМЕННО так, функция `serve` обязана жить в
КОРНЕВОМ модуле `polaris` (тогда `polaris.serve` — это квалифицированное имя
функции). Но корневой модуль не может её получить:

* фасад обязан звать `serve_addr`/`serve_router`, то есть импортировать
  `polaris.serve`; а `polaris.serve` уже импортирует `polaris.{Router, ...}` —
  получается взаимная зависимость корня и подмодуля;
* шапка `src/serve/serve.nv` описывает ровно этот случай ЗАМЕРОМ, а не
  опасением: попытка положить функцию, импортирующую нижний слой, в верхний
  модуль дала «spurious `undefined identifier 'serialize_response'`» внутри
  файлов, которые в одиночку проходят проверку, — подпись цикла A⇄B, а не
  настоящего отсутствующего символа;
* проверено грепом: среди ПРОИЗВОДСТВЕННЫХ файлов корневого модуля нет НИ
  ОДНОГО импорта подмодулей `polaris.*` — единственное исключение
  `src/doc_samples_test.nv`, тест. То есть корень сегодня не зависит от
  подмодулей ни разу, и фасад стал бы первым таким случаем.

**ЧТО ИЗ ЭТОГО СЛЕДУЕТ.** Достижимы две формы, и обе НЕ равны записанной в
приёмке: `import polaris.serve.{serve_addr}` + `serve_addr(":8080", app,
ServerPolicy.new())` (есть сегодня) либо новый тонкий `serve(app, addr)` в том
же модуле `polaris.serve`, вызываемый как `serve(app, ":8080")` после импорта.
Третья — `polaris.serve(app, addr)` дословно — требует переноса функции в
корень, то есть правки слоевого контракта, а это уже не час и не пункт списка.

**ВОПРОС ВЛАДЕЛЬЦУ (умолчание названо ниже):** приёмка 222.22 писалась под
форму, которой нет ни в коде, ни в README — в README стоит третья, четвёртая
форма (`serve_router(listener, app, ServerPolicy.new())`). Что считать
условием: (а) чтобы у новичка работала ОДНА строка без листенера и политики —
тогда делаем `serve(app, addr)` в `polaris.serve` и правим README под неё;
(б) чтобы работала форма, записанная в приёмке ДОСЛОВНО — тогда это работа по
слоевому контракту пакета, и её цену надо мерить отдельно; (в) переписать
приёмку под то, что построено.

**УМОЛЧАНИЕ, если владелец молчит: (а).** Довод: смысл пункта — первая строка
новичка, а `serve_router(listener, app, ServerPolicy.new())` требует знать три
понятия до «hello world». Довод ПРОТИВ (а), названный честно: это добавление в
публичную поверхность пакета, то есть обязательство поддерживать ещё одно имя.

### 9. Приоритизация тег-зависимых планов — работа, а не сортировка по номеру

кроме исключений — см. лестницу версий в 274.**

Что значит «приоритизировать» здесь, чтобы это можно было принять:
