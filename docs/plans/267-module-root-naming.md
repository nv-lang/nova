# План 267 — виртуальный корень модулей: `src/` сбрасывает имя пакета (D78 rev-6)

**Статус:** 🆕 ЗАПЛАНИРОВАН 2026-08-10. Основание — решение владельца того же дня
(D78 rev-6, [`spec/decisions/07-modules.md`](../../spec/decisions/07-modules.md),
раздел «Виртуальный корень»). Записи реестра:
[№564](221.1-bug-sweep.md) (`build` и `check` требуют разного имени модуля),
[№531](221.1-bug-sweep.md) (третья причина: LSP судит файл в одиночку),
[№566](221.1-bug-sweep.md) (значение `[lib] src` никем не проверяется).

**Приоритет:** 🔴 **К1, до тега.** Не из-за красоты правила, а потому что сегодня
на верном коде краснеют два инструмента из трёх: `nova check <каталог>` и
редактор. Краснота на верном коде приучает не смотреть на подсветку — и тогда
настоящая ошибка тоже пройдёт мимо. Это единственный дефект в очереди, который
портит саму привычку читать диагностику.

---

## 1. Что решено

Правило целиком — в спеке (D78 rev-6). Здесь одной строкой, чтобы читать план
без переключения:

> Корень исходников — либо сам пакет, либо его папка `src`. Слово `src` в имя
> модуля не входит никогда. Имя модуля = имя корня + папки по пути от корня;
> файлы прямо в корне — один модуль с именем корня. Сброшенный корень зовётся
> именем папки-владельца.

Отозвано: пример rev-5 `.../aggregator/src/main.nv → module main`. Правильно —
`module aggregator`, `src/app/*.nv → module aggregator.app`.

## 2. Почему это один дефект, а не три

Три носителя, корень один: **одиночный путь проверки не восстанавливает
реальную единицу компиляции.**

| носитель | что видно снаружи |
|---|---|
| `nova build` | ЗЕЛЁН — проверяет декларацию только у entry-файла, соседей не смотрит вовсе |
| `nova check <каталог>` | КРАСЕН — судит каждый файл как самостоятельный модуль (№564) |
| языковой сервер | КРАСЕН — `unknown type ConnectFailed` на типе из файла-соседа (№531) |

Флагман `examples/flagship/http_proxy_chain/src/` — шесть файлов, пользующихся
типами друг друга без импортов. Пока корень безымянен, они не образуют модуля, и
каждый инструмент домысливает по-своему. Отсюда правило приёмки ниже: **фикс
считается принятым, только когда все три дают ОДИН вердикт на одном каталоге.**

## 3. Фазы

### Ф.1 — запрет третьего значения `[lib] src` (🔴 К1)

Компилятор при разборе манифеста принимает только `"."` и `"src"`; иначе
`E_MANIFEST_SRC_VALUE`, hard error, с перечислением двух допустимых.

Проверяет **компилятор**, а не страж-скрипт: чужой пакет приезжает зависимостью
и наших стражей не спрашивает. Страж проверяет наши файлы — компилятор проверяет
любые.

Миграция нулевая, сверено по факту: 2055 манифестов во всех репозиториях,
значений ровно два — `"."` (1956) и `"src"` (99).

*Приёмка:* негативная фикстура `[lib] src = "source"` → `E_MANIFEST_SRC_VALUE`;
позитивные — оба легальных значения.

### Ф.2 — сброшенный корень получает имя (🔴 К1)

`expected_root_peer_decl` ([`manifest.rs:1406`](../../compiler-codegen/src/manifest.rs#L1406))
сегодня сверяет root-peer-форму против ИСХОДНОГО манифеста, а не против
`manifest_for_path` — того, что уже сдвинут `apply_src_transparency`
([`manifest.rs:1308`](../../compiler-codegen/src/manifest.rs#L1308)). Поэтому в
сдвинутом корне `package_name` пуст и root-peer-эвристика не применяется вовсе.

Чинится: сверять против сдвинутого манифеста, а имя пустого `package_name` брать
у папки-владельца `src`. Вложенные папки получают префикс корня.

*Приёмка:* фикстура — сброшенный корень из трёх файлов + вложенная папка; типы
видны без импортов; ошибочная декларация в том же корне даёт
`E_D78_MODULE_PATH_MISMATCH`, и перечень ожидаемых форм называет форму корня.

### Ф.3 — `nova check <каталог>` собирает группу, а не файлы (🔴 К1)

`cmd_check` ([`nova-cli/src/main.rs:2041`](../../nova-cli/src/main.rs#L2041))
перечисляет `.nv` каталога и зовёт `check_module_path` на каждом отдельно.
Нужно распознавать root-peer-группу ДО одиночной rev-3-проверки — так же, как
`is_folder_module_peer` уже делает для папочных модулей.

*Приёмка:* на каталоге флагмана `nova build` и `nova check` дают один вердикт.
Проба «подсунь негодное»: сломать декларацию в одном файле — краснеют ОБА.

### Ф.4 — миграция флагманов (🔴 К1, следом за Ф.2)

Шесть файлов `http_proxy_chain/src/` и `aggregator/src/main.nv`:
`module main` → `module <имя папки>`. Механическая правка, но делать её надо
ПОСЛЕ Ф.2, иначе дерево не собирается ни по старому правилу, ни по новому.

### Ф.5 — сравнение LSP и компилятора на многофайловом модуле (🟡 К2, план 262 Б)

Шаг, гоняющий обе диагностики на одном наборе. **Набор обязан быть
многофайловым модулем с внешней зависимостью** — на одиночном файле без импортов
оба зелены, и шаг не доказал бы ничего. Это прямое следствие №531: там
предыдущая формулировка приёмки прошла бы мимо третьей причины.

## 4. Чего этот план НЕ делает

Не трогает манифест-режим (`nova-http`, `nova-tls`, `std`): у них корень назван
манифестом, правило rev-6 для них ничего не меняет — они и были эталоном, к
которому приложения теперь приводятся.
