## 1. Зачем (найдено 2026-06-22)

D282 rule 2 (`extern "C" fn`, [08-runtime.md:8285](../../spec/decisions/08-runtime.md)) — список C-ABI-совместимых
типов **занижен и местами неверен** относительно реального `std/net/ffi.nv`:

- **Туплы** (анон/именованные) из C-ABI-типов **уже используются**:
  `extern "C" fn socket_addr_parse(s str) -> (int, CSocketAddr)` ([ffi.nv:32](../../std/net/ffi.nv)) — это
  C-struct by-value (C-ABI-совместимо), но в списке D282 их нет.
- **`str`** (`{ptr,len}` value-record, D139) — C-ABI-совместим (POD-struct) и **используется** (`s str`), но D282
  ошибочно числит `str` как «ABI mismatch».
- **value-records / C-структуры** (`CSocketAddr`/`CTcpStream`/`CUdpSocket`/`CTcpListener`) используются, не в списке.
- скаляры минимальны: нет `f64`/`f32`/`i8`-`i64`/`char`.
- `Option[*T]` через NPO — C-совместим (bitwise 0 = NULL).

Плюс: у **fn-указательного ТИПА нет ABI-тега** — неясно, Nova-ABI это (`*fn`, Nova-типы ок) или C-ABI (для
C-callback нужны C-native типы).

## 2. Решение — переписать D282 rule 2 (тип-лист)

**Формальное определение** (рекурсивно):
```
C_ABI  ::= Scalar | RawPtr | FnPtr | Option[RawPtr] | Tuple[C_ABI…] | ValueRecord{ C_ABI… }
Scalar ::= int | uint | i8..i64 | u8..u64 | f32 | f64 | bool | char
RawPtr ::= *T | *() | CStr
FnPtr  ::= *extern "C" fn(C_ABI…) -> C_ABI    // C-ABI fn-указатель, §3
```
- **`uint`** — address-sized unsigned, C-тип `nova_uint` (`= uintptr_t`, size_t-аналог, D130) — **не** `uint64_t`; отделён от `u64` как `int`(≠`i64`).
- **value-records и туплы** (анон + именованные) — C-ABI, если **ВСЕ** поля C-ABI; by-value как C-struct (`str`=`{ptr,len}` подпадает). В **параметрах И возврате**.
- **`Option[X]`** — C-ABI **iff `X` — RawPtr** (любой указательный тип `*T`/`*()`/`CStr`; NPO: `None`=0, `Some(p)`=p). `Option[non-ptr]` / `Option[Option[*T]]` — НЕ C-ABI (нет NPO).
- **C-ABI fn-указатель** `*extern "C" fn(C_ABI…) -> C_ABI` — базовый случай (передача Nova-fn как C-callback: `qsort`/libuv); может быть **параметром/полем** другого `extern "C" fn`. Nova-ABI `*fn` (без тега) — **НЕ** C-ABI. Полностью — §3.
- **Циклический value-record** (`type Node value { val int, next *Node }`) — C-ABI: поле `*Node` = raw-ptr (базовый случай), рекурсия обрывается на указателе. Ключевое слово `value` обязательно (без него — heap GC-record, non-C-ABI).
- **Края:** `()` / unit / zero-field tuple **как тип параметра/элемента** → **запрещено** (`E_FFI_NON_C_ABI_TYPE`; в C нет unit). Top-level `-> ()` = `void` в C-сигнатуре — ок.

**Исключения** (→ `E_FFI_NON_C_ABI_TYPE`): GC-типы (`Vec`, heap-record-ссылки), closures-with-env, generic tagged unions (`Option[non-ptr]`, `Result`, прочие sum — теговый layout не C-ABI).

**Примеры.** ✅ `(int, CSocketAddr)` · `str` · `Node value {val int, next *Node}` · `Option[*u8]` · `uint`/`f64`/`char` · `*extern "C" fn(*u8, int) -> int`. ❌ `Vec[int]` · `Result[int,str]` · `Option[int]` · `()`/zero-field tuple · fn-с-env · Nova-ABI `*fn` как C-callback.

## 3. ABI у fn-указательного типа

- `*fn(...)` / `*unsafe fn(...)` — **Nova-ABI** captureless fn-ptr: Nova-типы в сигнатуре допустимы (Nova ABI их передаёт). «Captureless» — про отсутствие env, не про типы.
- **✅ РЕШЕНО (ABI-тег): `*extern "C" fn(...)`** — синтаксически параллельно объявлению `extern "C" fn`; тег на уровне типа; Nova-ABI (`*fn`, без тега) и C-ABI (`*extern "C" fn`) визуально различимы. Типы сигнатуры — C-ABI по §2.
- **Коэрция fn → `*extern "C" fn`** (S5): Nova `fn[A]->R` коэрцится в `*extern "C" fn[A]->R` **iff** (1) каждый `A`/`R` — C-ABI (§2), (2) функция captureless, **и (3) effect-free/total** — не объявляет **никакого** эффекта (ни `Fail`, ни `IO`/`Async`, ни custom algebraic). Иначе `E_FFI_NON_C_ABI_TYPE` / `E_CLOSURE_HAS_ENV` / эффект-гейт. **Обоснование (3):** C зовёт callback без Nova-handler-фрейма на стеке → любая effect-операция unsound; обобщает `Fail`-специфичный гейт D216 §10/§20 (`E_CALLBACK_THROWS_OVER_C_ABI`) на все эффекты. Nova-only типы в C-callback запрещены.

## 6. Критерии приёмки

1. D282 rule 2 отражает реальность: туплы (анон/имен) + `str` + value-records + полные скаляры + `Option[*T]` —
   допустимы в params и возврате; не-C-ABI типы → чистый `E_FFI_NON_C_ABI_TYPE`.
2. `std/net` (и прочий `extern "C"`-код) проходит без обходов; `str`-mismatch-ошибка снята.
3. fn-ptr ABI-тег = **`*extern "C" fn`** (РЕШЕНО §3); Nova-ABI `*fn` vs C-ABI `*extern "C" fn` различимы; коэрция fn→`*extern "C" fn` проверяет C-ABI типы.
4. **Без упрощений** (полный тип-лист, рекурсивная проверка, params+return).

## 10. M1 (parser + checker + coercion + error-index + dedup) — выполнено 2026-07-04

Код-фаза (реализация M0-спеки; §5 spec-first, §1 checker-канал, §6 чистая диагностика, без упрощений):

1. **Parser (D353) — `*extern "C" fn(...)` ABI-тег.** `TypeRef::Func` получил поле `extern_abi:
   Option<String>` (`Some("C")` = C-ABI, `None` = Nova-ABI `*fn`). Новый `KwExtern`-arm в `parse_type`
   (helper `parse_fn_type_signature`, общий с `KwFn`) распознаёт `*extern "C" fn(...)` и
   `*extern "C" unsafe fn(...)` (= `Pointer(Unsafe(Func{extern_abi:C}))`, зеркалит `*unsafe fn`); ABI ≠
   `"C"` на fn-ptr типе → ошибка. `*fn` остаётся дефолтом. C-representation обоих тегов идентична
   (function pointer) → codegen не различает (все `TypeRef::Func`-матчи через `..`, byte-identical).
   `render_type_ref` печатает `extern "C" fn(...)` для диагностик.
2. **Checker `E_FFI_NON_C_ABI_TYPE` (`check_ffi_c_abi_signatures`, types/mod.rs).** Рекурсивный C-ABI
   классификатор `ffi_c_abi_violation` по грамматике D282 rule 2 читает **структуру типа, не имена** (§3):
   scalars (вкл. `uint`), raw-ptr (`*T`/`*()`/CStr — любой pointee, рекурсия обрывается на указателе),
   `str`, value-record/named-tuple/anon-tuple (by-value iff **все** поля C-ABI; heap-record → non-C-ABI;
   generic-подстановка через `ffi_subst_apply`), циклический `Node value {next *Node}` (guard + обрыв на
   `*Node`), `Option[X]` C-ABI iff `X` — RawPtr (three-valued `ffi_ptr_ness`; unknown → conservative OK),
   `*extern "C" fn` (рекурсивно валидирует сигнатуру), `()` = `void` только top-level return. Non-C-ABI
   (`Vec`/`Result`/heap-ref/`Option[non-ptr]`/Nova `*fn`/bare fn-type/protocol) → чистый
   `E_FFI_NON_C_ABI_TYPE` (span+код). Валидирует **параметры И возврат**. Unresolved Named
   (generic-param/cross-module тип) → conservative C-ABI (verdict у defining-модуля) → 0 ложных срабатываний
   на std/net (проверено).
3. **Коэрция `fn → *extern "C" fn`** (cast-site в `check_unsafe_context_in_module`). Captureless
