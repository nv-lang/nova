# План 222.20 — Исследование эффект-поверхности Polaris и пакетов Nova

**Статус:** 📋 ЗАВЕДЁН по решению владельца (2026-07-26: «надо исследовать, что нужно
сделать эффектами в Поларисе и пакетах Нова»). **Родитель:** 222.
**Тип:** разведка/дизайн → решения владельцу; реализация — последующими волнами.

## 0. Зачем

Эффект-система — ядро языка, а фреймворк — её витрина. Поверхность эффектов polaris/http/
tls/compress росла органически (сигнатуры вида `main() Net Time Detach -> ()`, ws-хук
`fn(TcpStream) Net -> ()`, чистый `Handler`) — систематического дизайна не было. №113-энфорс
(`!!`→Fail) и D28-инференс показали: границы export/приватное задевают фреймворк напрямую.

## 0а. РАМКА (указание владельца 2026-07-26: «перечитай в спеке, что такое эффект»)

Нормативный критерий — 04-effects.md «Правило 4. effect vs protocol — критерий
resource-capability»: эффект описывает подменяемую handler'ом в скоупе resource-capability
(«хочется при тестировании другую реализацию — эффект»); протокол — «что умеет значение»
(реализация привязана к типу, подменять нечего); runtime-mechanic — ни то, ни другое.
КАЖДЫЙ протокол/замыкание-параметр polaris прогоняется через этот вопрос.

Кандидаты от владельца/фактов кода:
- **SessionStore → эффект** (мысль владельца; Db-класс: прод-хранилище vs in-memory в тесте
  — учебниковая подмена в скоупе; сейчас протокол + mut-параметр store через session_layer);
- now_fn/id_gen в auth.nv — задокументированный ОБХОД эффектов Time/Random замыканиями
  («Handler is a plain fn with NO effect row») — прямое следствие вопроса №2 ниже;
- log/panic-sink поля-замыкания (@emit, policy.panic_sink) — кандидаты Io/Log-капабилити;
- ratelimit-buckets store — тот же класс, что SessionStore.

## 1. Вопросы исследования

1. **Инвентарь**: полная карта эффектов по polaris / nova-http / nova-tls / nova-compress /
   std.net-семье: какие fn несут `Net`/`Time`/`Detach`/`Fail[..]`/`Io`, где пробрасываются
   effect-polymorphic (R5 D325), где глотаются with-обвязкой, где отсутствуют подозрительно.
2. **КЛЮЧЕВОЙ: Handler и пользовательские эффекты.** Сегодня `Handler = fn(ServerRequest) ->
   ServerResponse` — БЕЗ эффектов. Как пользователю писать хендлер с `Db`/`Net`/`Fail`/`Time`?
   Варианты: effect-polymorphic Handler (проброс эффектов через Router/serve — R5-форвардинг);
   ambient-эффекты через with-обвязку в serve; #default_handler (D431). Сверить с эталонами
   (axum: async-всё + tower; наш аналог — эффекты в типе). Решение — владельцу.
3. **main-канон**: `Net Time Detach` в каждом примере — минимален ли набор; правильно ли,
   что `Detach` из внутренностей serve протекает в подпись пользовательского main.
4. **Fail-политика API фреймворка**: где Fail уместен против Result (D325 R5); согласовать
   с №113-энфорсом и D28-границей export/приватное.
5. **Паника vs Fail в хендлерах**: recover-500/supervised-путь (D416) — довести до
   осознанной нормы (что ловится, что летит).
6. **strict-effects дыры**: №93 (линт эффект-исключение) и всё, что вскроет инвентарь.
7. **Эффекты TLS/compress**: этикетки Net/Io на терминации и кодеках — консистентность
   со std.net-семьёй (D407 byte-surface).

## 1б. Кандидат на будущее — Audit-эффект (мысль владельца вслух, 2026-07-26; НЕ к немедленному действию)

Аудит ≠ логирование (доказательная запись «кто-что-над-чем-когда-исход» vs операционная
телеметрия; полнота/append-only/fail-closed vs best-effort). По Правилу 4 — эффект
(подмена в тесте: прод-журнал ↔ in-memory с ассертами), ОТДЕЛЬНЫЙ от Log (противоположные
контракты потери). Эскиз: AuditEvent{principal, action, resource, outcome, ts, request_id};
точки — auth-middleware (вкл. отказы 401/403/503) + явные бизнес-события хендлеров; sink с
подтверждением + политика отказа. Вопросы формы к моменту взятия: fallible-опы эффекта
(Result в опе) для fail-closed; хендлер эффекта, требующий Time (композиция). Взять после
волн A/B/C и Q1-финала — отдельным решением владельца.
