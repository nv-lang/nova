# Plan 188 — Гетерогенные коллекции `[]any` (вынос 174.3 Ф.3)

**Статус:** 📋 PROPOSED 2026-07-10 (решение владельца — выделить в отдельный план).
**Зонт:** [174.3](174.3-any-type-and-is-downcast.md) (any-фундамент). **Приоритет:** P2 (не блокер; typed-errors P1-цель 174.3 уже достигнута Ф.1+Ф.2).
**Маркер:** `[M-174.3-heterogeneous-any]`.

## Что уже есть (174.3 Ф.1+Ф.2, влито)

`any` = fat-pointer `{data, vt=NovaTypeInfo{type_id, name}}`; upcast `T → any`
(явный `as any` + неявный D53), `x is T`, `x.try_as[T]() -> Option[T]`,
flow-narrowing `if x is T {…}`, `E_IS_NON_ANY`. `NovaTypeInfo` — per-type статик,
`type_id` из реестра Plan 61.

## Чего НЕ хватает (объём этого плана)

Гетерогенный контейнер `[]any` / `Map[K, any]`: хранить значения разных типов в
одной коллекции и работать с ними стёрто. Сейчас `any` живёт как одиночное
значение; коллекция `any` не покрыта — нужна связка с элемент-семантикой Vec.

## Дизайн (эскиз, sign-off нужен)

- **Boxing в контейнер:** элемент `[]any` = boxed `NovaAny` (16Б fat-pointer);
  `push(x)` авто-боксит `x → any` (тот же pre-box hook, что для `any`-параметра).
- **Расширение `NovaTypeInfo`** (Ф.3-вопрос из 174.3): для коллекций нужны
  thunk'и `Eq`/`Hash`/`Clone`/`Display` per-type — иначе `[]any` нельзя
  сравнивать/печатать/дедуплицировать. Решить: класть указатели на эти thunk'и
  в `NovaTypeInfo` (как Rust `dyn`-vtable / Go itab) при первом использовании
  типа в `any`-позиции; лениво, чтобы не раздувать бинарь на неиспользуемое.
- **Итерация:** `for x in items` где `items []any` → `x: any`, дальше `x is T` /
  `try_as`. Нет авто-downcast (явность D54).
- **Печать:** `${items}` → через `Display`-thunk каждого элемента (закрывает
  «печать стёртых значений» из мотивации 174.3).

## Фазы

- **Ф.1** Boxing-в-Vec: `[]any.push`/литерал `[a, b, c]any`, элемент = NovaAny;
  итерация + `is`/`try_as` на элементе. Тесты: смешанный `[]any`, downcast в цикле.
- **Ф.2** Thunk-расширение `NovaTypeInfo` (Display минимум) → `${[]any}` печатает.
  Eq/Hash — по необходимости (Map[_, any] / dedup).
- **Ф.3** Спека: амендмент D54/D53 (any-в-коллекции), новый D-блок если нужен
  (next-free на момент реализации).

## Гейты

conformance + твои pos (смешанный контейнер, downcast-в-цикле, печать);
zero-regression на существующем `any`-корпусе (174.3 фикстуры).

## Границы

Не reflection, не сериализация произвольного `any` (тип-теги — не schema).
`Map[K, any]` — после `[]any` (тот же boxing).
