**Задание:** (1) дыра-1 — терминал-1 co-miss: весь трафик `infer_method_level_return_for_sum`

### Класс 1 — static-вызовы на примитивах невидимы чекеру (шаг 1, `7e7068643`)

`str.from(x)` в теле замыкания (`o.map(|x| str.from(x))`) парсится в
`ExprKind::Path(["str","from"])` — примитивные имена типов не `Ident`. Оба
static-return арма `infer_expr_type` видели только `Member{obj:Ident}`-форму и
гейтились `self.types` (примитивов там нет) → `closure_arg_return_peek` не выводил
тип тела → residual-ветка продюсера B бейлилась → co-miss ОБОИХ каналов
(`resolved_types` + `node_substs` пишутся в одном блоке) → легаси. Фикс
(`types/mod.rs`): Member-арм расширен `is_primitive_type_name`; новый Path-арм
(single-static-overload либо arg-type-дизамбигуация по param0 — зеркало
instance-арма `~14382`) + Self-подстановка для `Result[Self,E]`-возвратов.

### Класс 2 — unwrap-семья: ретрактированные методы без деклараций (шаг 2, `fd3a93142`)

`unwrap`/`unwrap_or`/`unwrap_or_else` ретрактированы из prelude (D85/D86,
`[M-unwrap-twins-retraction]`) — деклараций в .nv НЕТ, но вызовы живут (conformance
`d119_*`/`m196_*`; desugar map-spread синтезирует `.get(k).unwrap()`) и обслуживались
ТОЛЬКО codegen-хардкодом B11q/B11r. Продюсер работает от деклараций → co-miss по
построению. Фикс: зеркало того же факта (`Option[T]→T`, `Result[T,E]→T`) в
NO-OVERLOADS-ветке `resolve_instance_method_return_arity` — НЕ язык-меняющее
(материализация уже-существующего поведения в канал), спек-амендмент не нужен.

### Класс 3 — `T.try_from(str)`: стёртый D77-интринсик (НЕ фикс, структурный остаток)

Остаток data (16 хитов Result.ok) = receiver `u64.try_from(a)` (semver). Это
codegen-интринсик D77 (emit_c `~37319`) с НАМЕРЕННО стёртой репрезентацией
`NovaRes_nova_int_nova_str*` (Ok кастится в nova_int; B12h-легаси возвращает
именно её). Чекер НЕ МОЖЕТ честно материализовать `Result[u64, ParseError]` —
разойдётся с фактическим эмитом (byte-parity сломан). Разблокируется только
mono-флипом Plan 59 Ф.7.5 D3 (typed Result producer) — вне объёма волны.

### Решение по терминалу-1

Покрытие трафика НЕ 100% (класс 3) → channel-first флип
`infer_method_level_return_for_sum` НЕ выполнен, снос НЕ выполнен (по заданию — только
при 0 легаси-выигрышей на всех корпусах). Легаси-функция остаётся рабочим fallback
для стёртой D77-зоны. После Plan 59 D3 повторный замер должен дать 0 → тогда снос.

## Дыра-2 — первопричина и фикс (`23b754b4b`)

**Диагноз Stage-C2 устарел наполовину:** после фиксов дыры-1 `D119Box.map` ДОХОДИТ до
B2 (`resolve_method_level_subst`, ctx=D119Box____nova_int.map) — «другой путь
диспетчеризации» из C1-гипотезы не подтвердился временной трассой (B3-диспетчер
D119Box не видел). Реальная дыра — продюсер-сторона: `resolved_types_buf` хранит
closure-литерал как `Func{[Named"T"], Named"U"}` — НЕподставленные спеллинги
generic-имён каллиси. `resolve_return_channel` брал этот тип как arg-кандидат,
`Ty::from_resolved` поднимал голый `Named{T}` как КОНКРЕТНЫЙ лист (ровно d119
spelling-hazard, от которого fresh-var дизайн солвера защищает), пара-unify
конфликтовал с уже связанным carrier-Var (`Var(T)=int` vs `Named{T}`) и атомарно
отбрасывался → `U` не связывался → `as_concrete_leaf=None` → producer B молчал для
ВСЕГО класса user-record method-generic.

**Фикс:** `.filter(rt_respells_names)` на arg-кандидате в `resolve_return_channel` —
значение, пере-спеллящее собственные generic-имена каллиси, отвергается как отрава;
поток падает в `closure_arg_return_peek` (params из собственного carrier-биндинга
солвера) — резолвит корректно. Новый хелпер `rt_respells_names` (рекурсивный обход
`ResolvedType` по vars-ключам).

**Подключение сайта:** B2 уже channel-first (Stage-C2 pre-seed + composed-early-exit
под гейтами «поздние Steps не перезаписывают занятые слоты»); дыра была в том, что
канал ПУСТ для этого класса. Теперь продюсер пишет (`producer=B-method-residual n=2`
для всех D119Box.map-сайтов), консюмер даёт hit:

```
до:    consumer=resolve_method_level_subst ctx=D119Box____nova_int.map fallback reason=miss
после: consumer=resolve_method_level_subst ctx=D119Box____nova_int.map hit n=1
```
