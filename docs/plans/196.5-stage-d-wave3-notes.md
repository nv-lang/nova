## Пункт 1 — B11ah: структурное доказательство (не только «0 сегодня»)

Арм повторно читал ту же пару `(resolved_types, expr.id)`, что диспетчер
`infer_expr_c_type` уже прочитал ПЕРЕД входом в `infer_call_ret_c` (тот же `&self`,
без записи между чтениями; `resolved_type_to_c` — чистая функция). Либо верхнее чтение
провалилось → повтор проваливается идентично (никогда не хитует), либо верхнее чтение
успешно-но-stub (`debt_is_generic_stub_c`, намеренный fallthrough) → арм вернул бы тот же
stub, которого fallthrough избегал (неверный ответ). Снос = REMOVED-комментарий по
образцу волны-1. Гейт зелёный, байт-в-байт база.

## Пункт 2 — две P67-паники (пре-существующие user-visible баги, zero-tolerance вход)

### 2а. `deserialize` (терминал B12q, серде-корпус)

`T.deserialize(d)` в generic-теле `[T Deserialize]` → парсер даёт
`ExprKind::Path(["T","deserialize"])` (любой PascalCase перед `.lowercase` → Path);
`T` не в `self.types`/`method_overloads` → ни один static-return путь чекера не видел
вызов → co-miss каналов → легаси-терминал B12q = паника. Фикс: новый Path-бранч в
f1_expr Call-арме (types/mod.rs ~7927): gate `parts[1]=="deserialize" &&
gs.contains(parts[0])`; возврат из ДЕКЛАРАЦИИ протокола `Deserialize`
(`TypeDeclKind::Protocol` → `methods["deserialize"].return_type` = `Result[Self, DeError]`),
`Self`→`T` (`subst_type_ref_pub`), гейт на residual method-generics; `T` канализируется
явным `TypeParam` — `resolved_type_to_c` подставляет из `current_type_subst` при эмиссии
mono-инстанса. Не хардкод: user-CU со своим Deserialize-протоколом получает свой возврат;
без протокола в CU — честный fall-through в легаси.

### 2б. `str.until` (терминал B11al, orm_decorators)

`rest.until(" WHERE ")`/`rest.after(" WHERE ")` не существовали нигде. Тест авторитетен →
методы добавлены в std (`runtime/string/search.nv`): `@until(sep) -> str` (до первого
вхождения; вся строка при промахе) + `@after(sep) -> str` (после; `""` при промахе) —
тотальная пара к `@split_once`, zero-copy на `@find`. D251-амендмент в спеке тем же
слиянием (язык-меняющее). Conformance-тест в d251_str_surface.nv (6 кейсов).

### Осушенные терминалы B12q/B11al — НЕ снесены (конвенция)

Оба 0 hit после фиксов. Это ТЕРМИНАЛЬНЫЕ паники (честные CC-ERROR-fallthrough'ы функции)
— по конвенции 196.2 (карве-аут panic/terminal/scaffold, census §3.1) не атомы: уходят
с финальным сносом `infer_call_ret_c`, не по-одному.

### Размаскированные пре-существующие дефекты orm_decorators (вне периметра)

Паника B11al прерывала кодоген; теперь файл доезжает до C-компиляции и падает CC-FAIL
на ДВУХ других пре-существующих классах:
1. closure-param-bind (census §1.5, `M-196.5-b3-closure-param-bind`): лямбда
   `log.filter(|e| !e.template...)` на `[]CapturedQuery` типизирует `e` как `nova_int`.
2. `with Detach = SyncDetach`: SyncDetach-хендлер отсутствует в std bootstrap
   (задокументировано в nova_tests/err173_2/detach_effect_ok_test.nv — «handler'а,
   которых нет в std bootstrap»); D50-фича, не атом волны.
