# Plan 172.14 — Value-ABI perf: авто by-ref / heap↔stack / copy-elision (P3)

**Статус:** 🟢 CORE LANDED 2026-07-10 (волна value-abi-172-14, см. «Итог волны» ниже) — Ф.1 авто by-ref для free-fn (>16Б C-ABI ro value-struct: NovaValue_/NovaTuple_/`[N]T`-inline) + Ф.3-дёшево (элизия temp) + фикс регрессии main «срез `[N]T`» (тип среза = `[]T`, копия диапазона). Остатки под маркерами: [M-172.14-methods-byref] (методы, ~6 http-сайтов), [M-172.14-view-descriptor-stack] (стек-дескриптор видов — по решению владельца НЕ slice-интринсик, а маршрутизация на .nv `@index(Range)` + общий callee-alloc→caller-stack), Ф.2 sum→стек не начат. Ранее: 🔬 разведка §7 завершена 2026-07-10 (blast-radius инструментом); было ⏸️ пауза владельца; было 📋 proposed 2026-07-04 (вынесено из [172.4](172.4-value-abi-auto-placement.md) Ф.4-Ф.6).

## Итог волны 2026-07-10 (value-abi-172-14)

**Ключевая коррекция карты разведки:** blast-radius считал размеры по
Nova-модели; по C-ABI keystone-кластеры выглядят иначе:
- `Path` = **16Б в C** (`Nova_Vec*` + `Nova_PathStyle*`) — ровно порог SysV,
  by-value уже оптимален → fs-кластер (~20 сайтов) НЕ кандидат. Замер
  подтвердил: бенч Path-пути 155мс→152мс (без изменений, ожидаемо).
- hmac `[32]u8` был `Nova_Vec*` (heap) — после value-класса `[N]T` (main
  06e89b80c) стал 32Б inline-структурой → НАСТОЯЩИЙ кандидат, закрыт Ф.1.
- Реальный класс кандидатов — str-несущие value-records (Cookie 32Б,
  HeaderEntry 24Б, SetCookie 80Б+) и `[N]T`-буферы >16Б.

**Сделано (коммиты 831654a43, 8a3bce80d, 161920cb0, 3458c3603):**
- **Ф.1 (free-fn):** классификация НА УРОВНЕ ТИПА — ro-параметр со
  value-struct C-типом >16Б → `T*`; одна карта (`build_free_fn_byref_map`,
  пре-пасс) для сигнатуры/тела (auto-deref через `ref_params`)/call-site
  (`RefArg`); rvalue → materialize-temp; мутабельный корень аргумента →
  принудительная копия (semantics-preserving); отравления: перегрузки,
  default-параметры, fn-как-значение (AST-скан). `[N]T`-inline структуры
  включены (hmac `constant_time_eq`/`verify` ×3).
- **Ф.3 (дёшево):** элизия второго temp при materialize свежего
  call-результата; остальное уже делает C-компилятор (sret-возврат,
  SROA копий tmp→binding на release) — аудит по сгенерённому C.
- **Фикс регрессии main (zero-tolerance, та же волна):** §18а-миграция
  hmac на срезы × value-класс `[N]T` дала CODEGEN-FAIL «slice on
  unsupported type»; чекер теперь типизирует `[N]T[a..b]` как `[]T`
  (рантайм-длина), codegen копирует диапазон в свежий `[]T`
  (`nova_fixarr_slice_copy`, форма-прецедент `nova_blob_copy`/D412).
- Фикстуры: `nova_tests/plan172_14/{byref_ro_params,view_descriptor_stack}.nv`.

**Замеры (release, медиана из 5; методика: тот же бенч на бинаре ДО/ПОСЛЕ):**
| Бенч | ДО | ПОСЛЕ | Комментарий |
|---|---|---|---|
| byref 32Б-параметр ×50M | ~349мс | ~360мс | в шуме: SysV-копия 32Б дешева; выигрыш растёт с размером |
| Path-путь ×20M | ~155мс | ~152мс | без изменений (16Б ≤ порога) — подтверждение карты |
| hmac ×3000 | ~602мс | **~151мс (≈4×)** | комбинированно: value-класс `[N]T` (main) + фикс среза + by-ref этой волны; на чистом main hmac не компилится |
| срез-виды ×20M | ~522мс | ~560мс | не менялись (см. маркер view-descriptor-stack) |

**Приёмка владельца (ro-виды, 2026-07-10):** payload видов zero-copy уже
сегодня; ДЕСКРИПТОР — heap (24Б `NovaArrHdr` на `nova_vec_slice_chk` /
`from_raw_parts`). Slice-специфичный интринсик стек-плейсмента был
реализован и УБРАН по поправке владельца (второе окно правды против .nv
`Vec[T] @index(Range)`); правильная форма — маршрутизация `v[range]` на
.nv-тело + ОБЩИЙ механизм callee-alloc→caller-stack — отдельная работа,
маркер [M-172.14-view-descriptor-stack]. `grep nova_vec_slice_stack_chk`
= 0 вхождений.

## Возобновление 2026-07-10 — реальный blast-radius (заменяет оценку 2026-07-04)

Инструмент `compiler-codegen/tests/plan172_14_blast_radius.rs` (permanent,
`#[ignore]`-тест — `cargo test --test plan172_14_blast_radius -- --ignored
--nocapture`) сканирует std/ + nova_tests/ + spec_tests/ (4031 файлов,
166 parse-failures — сложный синтаксис вне грамматики recon-парсера,
не блокер), строит whole-corpus type-decl registry (имя-keyed, флэт —
известное упрощение recon-инструмента, НЕ полный module-резолв) и
классифицирует КАЖДЫЙ non-receiver параметр по (a) режиму (`mut`/`consume`/
`variadic`/`const` — уже имеют свою ABI-историю, не трогаются Ф.1) и
(b) вычисленному C-размеру (`const_fn_eval::type_size_or_align_resolved`,
переиспользован из `size_of[T]()`).

**Реальные числа (заменяют оценку «~180» от 2026-07-04):**

| Категория | Кол-во |
|---|---|
| value-record деклараций | 217 |
| named-tuple деклараций | 54 |
| non-receiver параметров всего | 6564 |
| — `mut` (уже by-ptr, Р10) | 251 |
| — `consume` | 37 |
| — variadic/const | 96 |
| — scalar/pointer/type-param (не кандидат по конструкции) | 4528 |
| — размер известен, ≤16Б (SysV by-value, НЕ кандидат) | 1097 |
| — **размер известен, >16Б — Ф.1 КАНДИДАТ** | **66** |
| — размер неизвестен (generic type-param, гейт на 172.12 mono) | 19 |
| — размер неизвестен (recon-инструмент не резолвит — см. ниже) | 470 |

**Ключевая находка: кандидаты НЕ равномерно размазаны — концентрация в
keystone-типах**, в отличие от framing «keystone A6 ×180» (180 независимых
точечных правок). Из 66 подтверждённых:
- **~20** — `std/fs/fs.nv` (`path Path` параметр, 24Б) — ОДИН тип (`Path`),
  повторяющийся почти в каждой fs-функции. Фикс на уровне типа/сигнатуры
  закрывает пачку сайтов разом, не 20 независимых правок.
- **~6** — `std/http/{client,server,message,header,mime,body}.nv`
  (`Request`/`Response`/`HeaderMap`/`ContentType`/reader-типы, 24-112Б).
- **3** — `std/crypto/hmac.nv` (`[u8; N]`-подобные fixed-size буферы, 32Б).
- Остальные ~35 — рассеяны по `nova_tests`/`spec_tests` fixtures (tuple/
  value-record demo-типы, не production-hot-path).

**Вывод:** реальный blast-radius для Ф.1 в ~3 раза меньше исходной оценки
(66 подтверждённых vs ~180) и структурно проще (keystone-кластеры, не
равномерная россыпь) — НО «470 неизвестных» требуют уточнения инструмента
(вероятно newtype/alias-обёртки над примитивами, которые
`type_decl_size_or_align` не полностью резолвит — не проверено, followup
`[M-172.14-blast-radius-tool-refine]`) прежде чем финальное число можно
считать окончательным. Даже верхняя граница (66+470=536) — того же порядка,
не радикально больше исходной оценки.

**Осознанное решение НЕ начинать Ф.1-Ф.3 codegen в этой волне:** реализация
auto by-ref требует НОВОГО анализа «второго владельца» (обобщение
`escape_analyze.rs` на параметры — по конструкции похоже на chain-gating
фикс этой же сессии, где escape-анализ уже пришлось расширять на новые
формы receiver'а), materialize-temp на call-site для неадресуемых
аргументов, auto-deref в теле (можно переиспользовать `ref_params`
механизм — прецедент есть, см. Plan 184/172.5 codegen), и escape-доказательство
на каждом из 66+ сайтов. Это полноценный НОВЫЙ codegen-механизм, не
косметика — рашить его в хвосте той же сессии, где уже был найден и
исправлен один реальный soundness-баг (chain-gating), нарушило бы явное
требование методологии §2/§7 «не рашить крупный ABI в хвосте сессии».
Следующая волна: начать с Ф.1 keystone-кластера `Path` (std/fs) как
наименьшего по риску (один тип, ~20 сайтов, non-generic, не в hot-path
конкурентности) — де-риск ПЕРЕД масштабированием на http/generic случаи.

## Мотивация

172.4 закрыл КОРРЕКТНОСТЬ value-ABI (fluent, `==`, единый receiver-carrier). Осталась
ПРОИЗВОДИТЕЛЬНОСТЬ размещения/передачи — три P3-оптимизации, все behavior-changes с широким
blast-radius (замер 2026-07-04: value-record 117, value-параметры ~180, named-tuple 4).
Владелец (2026-07-04) развёл: correctness-core (owner-acceptance) закрыт в 172.4; perf —
самостоятельный измеренный focused-эффорт, НЕ автопродолжение в хвосте марафона.

## Фазы (перенесены из 172.4 §3 Ф.4-Ф.6 — детали там)

- **Ф.1 (=172.4 Ф.4) — авто by-ref передача параметров.** Большие value передавать указателем
  когда копия НЕ наблюдаема (закрывает ЗА-аргумент Q29 без `ref T`). Foundation: `escape_analyze.rs`
  (Plan 127) промоутит value-records на heap при escape — ОБОБЩИТЬ на by-ref-передачу (новый анализ
  «второго владельца»). **Blast-radius: ~180 param-сайтов** (сигнатура + call-site взятие-адреса +
  тело deref + escape-доказательство на каждый). Масштаб = keystone A6 ×180.
- **Ф.2 (=172.4 Ф.5) — авто heap↔stack placement, нерекурсивный sum→стек.** Нерекурсивные/
  перечислительные sum → tagged-union на стеке (как builtin Option/NovaOpt vs Result/heap).
  Детектор рекурсии есть (Plan 62.A.bis / 08-runtime); консервативно рекурсия→heap.
- **Ф.3 (=172.4 Ф.6) — copy-elision RVO/NRVO + move-on-last-use.** Свежие/уникальные value
  (escape доказал отсутствие второго владельца) строятся в слоте-назначении / move вместо memcpy.
  Прозрачно (value: копия ≡ move наблюдательно). БЕЗ нового синтаксиса. Маркер
  `[M-172.4-rvo-move-on-last-use]`. Обобщает D326 R7/R8.

## Методология (172.1/172.4-класс)

- §7 де-риск ПЕРЕД фаталом: detect-режим + blast-radius + карта сайтов (ultracode-разведка).
- Под-атомы с промежуточными зелёными гейтами (прецедент A1-A6): conformance + ПОЛНЫЙ nova_tests
  baseline на каждый атом; НЕ band-aid (§2.1); НЕ рашить крупный ABI в хвосте сессии (§2 soundness).
- Ф.1 (by-ref) — spec-first D-блок для порога «когда by-ref» если понадобится.

## Критерии приёмки

- 0 регрессий против чистого бинаря (полный, не сэмпл — §7.6); перф-выигрыш замерен (§2).
- Корректность НЕ меняется (value: копия ≡ move; by-ref прозрачен).
