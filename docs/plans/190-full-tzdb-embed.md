# Plan 190 — Полный вшитый tzdb (`#embed_tzdata`-флаг) (вынос из 175.1)

**Статус:** 📋 PROPOSED 2026-07-10 (решение владельца — отдельный план).
**Зонт:** [175.1](175.1-civil-time.md) Ф.4 (IANA tz-db). **Приоритет:** P3.
**Маркер:** `[M-175.1-full-tzdb-embed]`.

## Что уже есть (175.1 Ф.4, влито)

Гибрид OS-first + embedded fallback (как java.time/.NET). `load_timezone(name)
Fs, Os` = `$ZONEINFO` override → `/usr/share/zoneinfo` → fallback на embedded.
TZif-парсер RFC-8536 v1/v2/v3 ПОЛНЫЙ; Windows CLDR-map. Embedded-фолбэк —
**кураторский**: 4 зоны (NY/London/Moscow/Sydney) + rule-based 1996–2100.

## Проблема (объём этого плана)

На платформах БЕЗ OS-tzdata (Windows без CLDR-полноты, минимальные контейнеры,
статические сборки) доступны только 4 кураторские зоны — остальные → `UnknownZone`.
Полный офлайн-набор IANA-зон недоступен без ОС.

Это НЕ баг (дефолт «из ОС» разумен, как Go) — недостающая **opt-in** возможность
«вшить весь tzdb в бинарь», как `chrono-tz` (Rust) или `import _ "time/tzdata"` (Go).

## Мировой контекст

- **Go:** дефолт из ОС; `import _ "time/tzdata"` вшивает весь снапшот (~450КБ).
- **Rust `chrono-tz`:** крейт генерирует IANA-tzdb в бинарь на этапе сборки
  (embedded всегда).
- **JVM/ICU:** вшивают полный ICU tz.

## Ключевой факт про зоны (ответ на вопрос владельца 2026-07-10)

Владелец прав: «топ реальных зон по городам + остальные как пояса» — верный дизайн.
Числа:
- **~38 РАЗНЫХ UTC-смещений** в мире сейчас (от UTC−12 до UTC+14, есть :30/:45).
- **~350 канонических IANA-зон** (~600 с backward-алиасами).
- **Сейчас вшито: 4 зоны** с полными DST-правилами (New_York/London/Moscow/Sydney)
  + UTC. Остальное — только через OS-tzdata.

**Почему «зона» ≠ «пояс»:** IANA-зона (`Europe/Berlin`) несёт ВСЮ ИСТОРИЮ
DST-правил и сдвигов региона; фиксированный пояс (`+01:00`) — просто число.
Фиксированный пояс НЕ умеет DST. НО: DST соблюдают лишь ~60 зон (Европа, С.Америка,
части Ю.Америки/Австралии/NZ/Ближнего Востока) — **~2/3 населения мира DST НЕ
используют** (почти вся Азия, Африка, Россия с 2014, Китай, Индия). Для не-DST
региона фиксированный пояс — ТОЧЕН, не приближение.

**Отсюда трёхъярусный дизайн вшитого фолбэка (рекомендация):**
1. **Ярус A — топ ~30-50 DST-зон** по населению/использованию с ПОЛНЫМИ правилами
   (America/New_York, Europe/London/Paris/Berlin, Australia/Sydney, …) — покрывает
   почти всех DST-пользователей.
2. **Ярус B — фиксированные пояса** для остального (~38 смещений как `Fixed(off)`):
   для не-DST зон ТОЧНО (`Asia/Tokyo`=+09:00, `Asia/Shanghai`=+08:00 — DST не
   соблюдают), для редких DST-зон вне яруса A — приближение без DST (честно
   задокументировать `ApproxOffset`-флаг на зоне).
3. **Ярус C — `#embed_tzdata`** (полный снапшот ~450КБ) для тех, кому нужна
   историческая точность любой зоны офлайн.

Дефолт = ярусы A+B (компактно, покрывает мир), C — opt-in. Это лучше 4 зон и
дешевле полного tzdb.

## Дизайн (эскиз, sign-off нужен)

- **Флаг сборки `#embed_tzdata`** (или `nova.toml`-опция `[build] embed_tzdata =
  true`): при включении генерирует `static const` TZif-снапшот всех зон в бинарь
  (переиспользует `embed`-интринсик D412 / hex-blob 186 — снапшот как встроенный
  ресурс). `load_timezone` при miss в ОС идёт в этот полный embedded-набор, не в
  4 кураторские.
- **Источник снапшота:** vendored `tzdata`-релиз (версионированный, supply-chain
  пин как Cargo.lock у tls_shim) → генератор конвертирует в `.nv`/blob на сборке.
- **Размер:** ~450КБ в бинарь только при `embed_tzdata=true` (дефолт — off,
  бинарь тонкий).
- **Версия:** замораживается на дату сборки снапшота — задокументировать
  (`tzdata_version()` для интроспекции).

## Фазы

- **Ф.1** Генератор снапшота (vendored tzdata → blob) + `nova.toml`-опция.
- **Ф.2** `load_timezone` fallback-chain: OS → full-embedded (если вшит) →
  curated → `UnknownZone`.
- **Ф.3** Тесты: под `embed_tzdata` любая IANA-зона резолвится офлайн; без флага —
  прежнее поведение (4 зоны). `tzdata_version()`.

## Гейты

conformance; civil-time δ0 без флага (дефолт не тронут); под флагом — сэмпл
из ~20 зон резолвится офлайн + DST верен.

## Границы

Не меняет user API (`TimeZone.try_from` та же); только источник данных.
Leap-seconds по-прежнему игнор (175.1 D321).
