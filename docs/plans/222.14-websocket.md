# План 222.14 — WebSocket: `http.ws` (слой 1) + upgrade-extractor (слой 2)

**Статус:** ✅ РЕАЛИЗОВАН ~95% (ревизия 2026-07-31): кодек/handshake/сокет/extractor/РЕАЛЬНЫЙ hijack до живого сокета + пример 08. Остаток до тега: нагрузочный смок N параллельных сокетов (§6 Ф.3); устаревший комментарий в socket_echo_smoke про «hijack невозможен» — снять.
**Зависит:** 222.3 (`FromRequest` для upgrade-извлекателя), 222.7 (соединения/дедлайны).
**Основа:** RFC 6455 (протокол); **API-форма — Axum `WebSocketUpgrade`** (WS как обычный extractor).
**Родитель:** [222](222-http-framework.md) · [222.0](222.0-module-map.md).

## 1. Почему это ДВА слоя (проверка слоевого контракта 222 §0а)

Фрейминг и handshake — **слой 1** (протокол, не зависит от Router/extractors): им может
пользоваться кто угодно, включая не-Polaris потребителей. Извлекатель `WebSocketUpgrade` —
**слой 2** (зависит от `FromRequest`). Это первый реальный тест правила «слой N не импортирует
>N»: `http.ws` НЕ ИМЕЕТ ПРАВА импортировать Router/extract.

## 2. Слой 1 — `http.ws` (фрейминг + handshake)

```nova
export type OpCode enum Continuation | Text | Binary | Close | Ping | Pong

export type Frame value {
    priv fin     bool
    priv opcode  OpCode
    priv payload []u8
}
export fn Frame @fin() -> bool => @fin
export fn Frame @opcode() -> OpCode => @opcode
export fn Frame @payload() -> []u8 => @payload

/// Кодек кадров (маскирование клиент→сервер обязательно по RFC).
export fn Frame.decode(buf []u8) -> Result[(Frame, int), WsError]   // (кадр, сколько байт съедено)
export fn Frame @encode(mask bool) -> []u8

/// Handshake: проверка заголовков + вычисление Sec-WebSocket-Accept (SHA-1 + base64).
export fn ws_accept_key(client_key str) -> Result[str, WsError]
export fn is_upgrade_request(req ServerRequest) -> bool

export type WsError enum
    | BadFrame(str) | TooLarge(int) | UnmaskedClientFrame
    | BadHandshake(str) | ProtocolViolation(str) | Closed(u16)
```
**Зависимость:** SHA-1 для accept-key — проверить наличие в `std/crypto` на Ф.0; если нет —
это единственная новая крипто-нужда плана (SHA-1 здесь НЕ для безопасности, а как фиксированное
преобразование RFC — реализация тривиальна и безопасностью не нагружена).

## 3. Слой 2 — извлекатель и сокет

```nova
/// Извлекатель: подтверждает upgrade-запрос, отдаёт «обещание» соединения.
export type WebSocketUpgrade value { priv key str, priv protocols []str }
#impl(FromRequest)
export fn WebSocketUpgrade.from_request(req ServerRequest) -> Result[WebSocketUpgrade, HttpError]

/// Завершает handshake и передаёт управление обработчику сокета (fiber-на-соединение).
export fn WebSocketUpgrade consume @on_upgrade(h fn(WebSocket) -> ()) -> ServerResponse

/// Живой сокет. MUST-CONSUME (D133) — как `Body`: забыл закрыть → ошибка компиляции.
export type WebSocket consume { priv ... }
export fn WebSocket mut @send(m Message) Net -> Result[(), WsError]
export fn WebSocket mut @recv() Net -> Result[Option[Message], WsError]   // None = штатное закрытие
export fn WebSocket consume @close(code u16, reason str) Net -> Result[(), WsError]

export type Message enum Text(str) | Binary([]u8) | Ping([]u8) | Pong([]u8)
```

**Наше преимущество (записать в доке как differentiator):** `WebSocket consume` = компилятор не
даст забыть закрыть сокет — в Node/Go утечка WS-соединений классическая. Плюс fiber-на-сокет даёт
синхронный `recv()`-цикл без async-машинерии.

## 4. Автоматика протокола (не отдавать пользователю)

- **Ping/Pong** — отвечать автоматически (иначе прокси рвут соединение); `Ping` наружу отдаём
  только информационно.
- **Фрагментация** — собирать `Continuation`-кадры в целое `Message` до отдачи.
- **Лимит размера сообщения** — обязателен (иначе DoS); дефолт консервативный, настраивается.
- **Close-handshake** — корректный обмен, не просто закрытие сокета.

## 5. Границы V1

- `permessage-deflate` (сжатие) — НЕТ (можно позже, `compress` уже зависимость);
- субпротоколы (`Sec-WebSocket-Protocol`) — только эхо выбранного, без переговорной логики;
- WS-клиент — НЕТ (только сервер); клиентская сторона — отдельный заход.
