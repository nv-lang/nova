# Plan 172.13 — Constraint-based inference core

**Статус:** 🚧 in-progress (снята пауза 2026-07-10, [sonnet]). Ф.0 (инвентарь) + Ф.1 (ядро-скелет: unify/occurs-check/type-set, 16 юнитов) + Ф.2 (миграция пакета C — literal-coercion семья на Constraint/TypeSet/Solver, byte-parity подтверждён: conformance 91/0, err173* 5/5, nova_tests sample byte-identical, cargo test 939/939 non-pre-existing) — СДЕЛАНО, см. секции ниже. anon-RecordLit D55 — подтверждено codegen-эмиссионный гэп, вне охвата чекерного ядра ([M-d55-anon-recordlit-codegen-gap]). Ф.3 (снос остатка: Binary-Join/If-Match-Join/resolve-семья) — НЕ начато, следующая волна.
**Зонт:** [172-compiler-rework.md](172-compiler-rework.md)
**Порядок:** ПОСЛЕ [172.12](172.12-typed-ir-mono.md) (унификации нужны структурные типы повсюду).
**Ветка:** `constraint-core`

## Мотивация

Инференс Nova — набор ad-hoc продюсеров канала (`infer_expr_type`-армы +
expected-type коэрция + resolve-семейство). Симптом (эмпирика tally-марафона
172.1): каждый новый КОНТЕКСТ требует отдельного продюсера — closure-параметры
(C6a/C6b), method-generic `U` (arg-binding), flow-`None` (Channel 6i),
anon-RecordLit (D55), tuple-let. Эталоны (Go types2, Kotlin K2, Swift)
решают классом: unification/constraint-ядро.

## Цель

Констрейнт-ядро поверх готового канала: выражение порождает констрейнты
(equality/subtype-lite/member-of type-set), решатель унифицирует, канал
получает результат. Ad-hoc продюсеры вырождаются в генераторы констрейнтов.

Закрывает классом:
- **C6-полный** — bidirectional closures (Block-тела, let-без-аннотаций,
  NovaClos-параметры из использования);
- **anon-RecordLit** D55-expected в любых позициях;
- **flow-типизация** (`mut best = None` → из последующих присвоений);
- residual same-arity перегрузки (полноценный overload-resolution по
  констрейнтам аргументов, а не first-arg эвристика).

## Границы

- НЕ Hindley-Milner полного вывода: Nova объявляет типы на границах fn
  (D-семейство) — ядро локально (внутри тел + межвыражение).
- Type-set bounds (172.3) — источник member-of констрейнтов (D46-риск
  operator-overload снимается bound'ом — прецедент Binary-bounds 172.1).

## Фазы (эскиз)

- **Ф.0** Инвентарь продюсеров канала (26+ сайтов f1-преамбулы) → карта
  «какой констрейнт он выражает».
- **Ф.1** Ядро: constraint-типы + решатель (унификация ResolvedType с
  TypeParam-переменными — носитель уже есть с 172.1).
- **Ф.2** Миграция продюсеров пакетами (literal-coercion семейство → ctor →
  closures → flow), гейты 172.1-класса на пакет.
- **Ф.3** Снос ad-hoc остатка; d119-класс (загрязнение субституции)
  невозможен по построению (переменные, не имена).

## Критерии приёмки

- C6-классы (closures/anon-RecordLit/flow-None) закрыты ядром, не продюсерами.
- Ни одного нового `infer_expr_type`-арма для новых контекстов — только
  констрейнт-генерация.
- Гейты: conformance + полный nova_tests == baseline.

## Ревизия 2026-07-08 (батчи 1-4 чекер-волны)

Constraint-ЯДРО (Ф.1-Ф.3) НЕ строилось — батчи 1-4 работали ad-hoc
продюсерами (что этот план как раз предлагает заменить). Эмпирический
статус целевых классов плана (репро-прогон, батч 4):

- **flow-None** (`mut best = None` → тип из последующего присвоения +
  match) — **работает** (закрыто побочно волнами 172.1.x/172.13; репро
  компилируется и исполняется).
- **C6 block-body closure** (параметры лямбды из expected fn-типа,
  block-тело с let) — **работает** (закрыто побочно; вклад батча 3 —
  substituted-сигнатура в emit_lambda в mono-пути).
- **anon-RecordLit (D55)** в arg-позиции и return-позиции — **ОТКРЫТ**:
  `codegen error: anonymous record literal without spread not supported
  in codegen` (падает раньше чекерного канала — codegen-гэп).
  Остаётся мотивирующим кейсом ядра.
- **residual same-arity перегрузки** — частично закрыто U.3.1-U.3.4
  (arity+category-фильтр в чекере, unique-compat → Call-channel); полный
  constraint-based overload-resolution — остаток этого плана.
- **bound-forwarding** (новый контекст = отдельный продюсер, симптом из
  «Мотивации») — закрыт батчами 3-4 ([M-generic-bound-forwarding],
  current_fn_generic_names passthrough) — ещё один сработавший ad-hoc
  продюсер класса, который ядро дало бы по построению.

Вывод: план актуален как архитектурная замена продюсерного зоопарка;
полузакрытых собственных пунктов нет (Ф.0-Ф.3 не начаты — не начаты
целиком, а не наполовину). Приоритезация — за владельцем.

## Ф.0 инвентарь 2026-07-10 (снятие паузы, ветка `constraint-core`)

Обзор f1-преамбулы канала (`compiler-codegen/src/types/mod.rs`,
`f1_expr_inner` :7158-8628, + смежные семейства). Классификация каждого
сайта: **какой констрейнт он выражает** (Eq = равенство узел↔тип;
MemberOf = принадлежность type-set/гейт-предикату; Join = слияние двух

проекция контейнер→элемент; Resolve = полноценный overload/generic-mono
резолвер, вне контура ядра в этой волне) → **мигрируемость**.

## anon-RecordLit D55 — разграничение (репро 2026-07-10)

Подтверждено репро (`nova_tests/_d55scratch` временный, удалён после
проверки): анонимный record-литерал БЕЗ spread в позиции call-аргумента
(`takes({ x: 1, y: 2 })` где `takes(p Point)`) по-прежнему падает
`codegen error: anonymous record literal without spread not supported in
codegen`. Причина — `compiler-codegen/src/codegen/emit_c.rs:39613`: этот
codegen-путь читает ТОЛЬКО `current_fn_return_ty` (codegen-локальный
thread-local для функции-возврата), НЕ `resolved_types_buf` (чекер-канал,
который Ф.2 наполняет). Ф.2 (literal-coercion семья) пишет исключительно
в чекер-канал — эмиттер anon-RecordLit его не читает вовсе. Значит: **D55
anon-RecordLit — ЧИСТО codegen-эмиссионный гэп, ДО и НЕЗАВИСИМО от
чекерного канала**; ядро Ф.1/пакет Ф.2 его не закрывают И НЕ МОГУТ
закрыть без отдельного трека — эмиттеру нужно НАУЧИТЬСЯ читать
`resolved_types_buf`/`resolved_types` для anon-RecordLit (или получить
ожидаемый тип с call-сайта иначе), это отдельная задача кодогена, не
чекера. Маркер: **[M-d55-anon-recordlit-codegen-gap]** — остаётся
открытым, вне объёма этой волны; кандидат для отдельного codegen-трека
(не Ф.3 чекера).

**UPD 2026-07-10 (ветка `d55-hashmap-fix`, дёшевый checker-фикс):**
маркер РАЗДЕЛЁН на два подкласса по итогам целевого репро. **(A) HashMap
`#from_fields`/`#from_pairs` манифестация — ЗАКРЫТА.** Репро показало, что
для этого подкласса корень был НЕ в `emit_c.rs` (как предполагалось выше),
а в checker-annotator `MapLitAnnotator`/`MapLitCtx` (`types/mod.rs`): 4
места спуска AST (`Stmt::Assign`, вложенные поля `RecordLit`, элементы
`ArrayLit`, arg0 built-in `Some`/`Ok`/`Err`) вели `expected`-тип
безусловным `None`, из-за чего `inferred_map_v` не заполнялся. Починено
пробросом `expected` в этих 4 местах (+ новое поле `record_field_types` в
`MapLitCtx`) — `emit_c.rs` НЕ тронут, чисто checker-слой. См.
