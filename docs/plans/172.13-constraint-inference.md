# Plan 172.13 — Constraint-based inference core

**Статус:** ⏸️ ПАУЗА владельца 2026-07-10 (лимиты; запускался [opus] в ветке `constraint-core`, запушена, кода нет — репро-разведка). Целевые классы дополнены: [M-option-self-recursive-record-mono] + [M-result-direct-recursive-enum] закрыть ядром. Было 📋 proposed 2026-07-04 (из финализации 172.1)
**Зонт:** [172-compiler-rework.md](172-compiler-rework.md)
**Порядок:** ПОСЛЕ [172.12](172.12-typed-ir-mono.md) (унификации нужны структурные типы повсюду).
**Ветка:** TBD

## Мотивация

Инференс Nova — набор ad-hoc продюсеров канала (`infer_expr_type`-армы +
expected-type коэрция + resolve-семейство). Симптом (эмпирика tally-марафона
172.1): каждый новый КОНТЕКСТ требует отдельного продюсера — closure-параметры
(C6a/C6b), method-generic `U` (arg-binding), flow-`None` (Channel 6i),
anon-RecordLit (D55), tuple-let. Эталоны (Go types2, Kotlin K2, Swift)
решают классом: unification/constraint-ядро.

## Цель

Констрейнт-ядро поверх готового канала: выражение порождает констрейнты
(equality/subtype-lite/member-of type-set), решатель унифицирует, канал
получает результат. Ad-hoc продюсеры вырождаются в генераторы констрейнтов.

Закрывает классом:
- **C6-полный** — bidirectional closures (Block-тела, let-без-аннотаций,
  NovaClos-параметры из использования);
- **anon-RecordLit** D55-expected в любых позициях;
- **flow-типизация** (`mut best = None` → из последующих присвоений);
- residual same-arity перегрузки (полноценный overload-resolution по
  констрейнтам аргументов, а не first-arg эвристика).

## Границы

- НЕ Hindley-Milner полного вывода: Nova объявляет типы на границах fn
  (D-семейство) — ядро локально (внутри тел + межвыражение).
- Type-set bounds (172.3) — источник member-of констрейнтов (D46-риск
  operator-overload снимается bound'ом — прецедент Binary-bounds 172.1).

## Фазы (эскиз)

- **Ф.0** Инвентарь продюсеров канала (26+ сайтов f1-преамбулы) → карта
  «какой констрейнт он выражает».
- **Ф.1** Ядро: constraint-типы + решатель (унификация ResolvedType с
  TypeParam-переменными — носитель уже есть с 172.1).
- **Ф.2** Миграция продюсеров пакетами (literal-coercion семейство → ctor →
  closures → flow), гейты 172.1-класса на пакет.
- **Ф.3** Снос ad-hoc остатка; d119-класс (загрязнение субституции)
  невозможен по построению (переменные, не имена).

## Критерии приёмки

- C6-классы (closures/anon-RecordLit/flow-None) закрыты ядром, не продюсерами.
- Ни одного нового `infer_expr_type`-арма для новых контекстов — только
  констрейнт-генерация.
- Гейты: conformance + полный nova_tests == baseline.

## Ревизия 2026-07-08 (батчи 1-4 чекер-волны)

Constraint-ЯДРО (Ф.1-Ф.3) НЕ строилось — батчи 1-4 работали ad-hoc
продюсерами (что этот план как раз предлагает заменить). Эмпирический
статус целевых классов плана (репро-прогон, батч 4):

- **flow-None** (`mut best = None` → тип из последующего присвоения +
  match) — **работает** (закрыто побочно волнами 172.1.x/172.13; репро
  компилируется и исполняется).
- **C6 block-body closure** (параметры лямбды из expected fn-типа,
  block-тело с let) — **работает** (закрыто побочно; вклад батча 3 —
  substituted-сигнатура в emit_lambda в mono-пути).
- **anon-RecordLit (D55)** в arg-позиции и return-позиции — **ОТКРЫТ**:
  `codegen error: anonymous record literal without spread not supported
  in codegen` (падает раньше чекерного канала — codegen-гэп).
  Остаётся мотивирующим кейсом ядра.
- **residual same-arity перегрузки** — частично закрыто U.3.1-U.3.4
  (arity+category-фильтр в чекере, unique-compat → Call-channel); полный
  constraint-based overload-resolution — остаток этого плана.
- **bound-forwarding** (новый контекст = отдельный продюсер, симптом из
  «Мотивации») — закрыт батчами 3-4 ([M-generic-bound-forwarding],
  current_fn_generic_names passthrough) — ещё один сработавший ad-hoc
  продюсер класса, который ядро дало бы по построению.

Вывод: план актуален как архитектурная замена продюсерного зоопарка;
полузакрытых собственных пунктов нет (Ф.0-Ф.3 не начаты — не начаты
целиком, а не наполовину). Приоритезация — за владельцем.

## Ф.0 инвентарь 2026-07-10 (снятие паузы, ветка `constraint-core`)

Обзор f1-преамбулы канала (`compiler-codegen/src/types/mod.rs`,
`f1_expr_inner` :7158-8628, + смежные семейства). Классификация каждого
сайта: **какой констрейнт он выражает** (Eq = равенство узел↔тип;
MemberOf = принадлежность type-set/гейт-предикату; Join = слияние двух
известных типов в один результирующий; Project = деструктурирующая
проекция контейнер→элемент; Resolve = полноценный overload/generic-mono
резолвер, вне контура ядра в этой волне) → **мигрируемость**.

### A. Преамбула `f1_expr_inner` (13 узловых сайтов, строки 7174-7601)

| # | Узел | Констрейнт | Мигрируемость |
|---|------|-----------|----------------|
| 1 | `Ident` | Eq (копия из `infer_expr_type`) | высокая, ценность низкая (уже факт) |
| 2 | `SelfAccess` | Eq | высокая/низкая |
| 3 | `Index` (прямой + структурный мост Vec/Array/TypedPtr/Readonly) | Eq + **Project** (контейнер→элемент) | средняя — нужен вид Constraint::Project |
| 4 | `Member` (field-read) | Eq | высокая/низкая |
| 5 | `Range` литерал | Eq constant (`Range` всегда) | высокая/низкая |
| 6 | `RecordLit` (non-generic bare) | Eq constant (`Named{name}`) | высокая/низкая |
| 7 | `Block/If/IfLet/Path` (control-flow propagation) | Eq (копия дочернего) | высокая/низкая |
| 8 | `Path` numeric-const (`int.MAX`…) | Eq constant per-T таблица | высокая/низкая |
| 9 | `RecordLit` (generic-arg вывод по полям) | **настоящая унификация**: для каждого generic-параметра T решить T = infer(поле с декларированным типом T), all-or-nothing | ВЫСОКАЯ концептуальная близость к ядру, но риск — уже многослойно пропатчен (POISON 6630 audit); НЕ в этой волне |
| 10 | `TupleLit` (all-primitive) | Eq composite + MemberOf(primitive) на каждый элемент | средняя |
| 11 | `For/While/WhileLet/Loop` unit-type | Eq constant (`Unit`) | высокая/низкая |
| 12 | `ParallelFor` trailing → `Vec[T]` | Eq composite, T = infer(trailing) в расширенном scope | средняя (специфичный scope-seeding) |
| 13 | Литералы (`IntLit`/`FloatLit`/…/`HexBlobLit`) | Eq constant per-kind таблица | высокая/низкая |

### B. Матч-армы `f1_expr_inner` (строки 7602-8627, ~26 ветвей ExprKind)

Большинство — чистая рекурсия (`f1_expr`/`f1_block` без аннотации):
`TurboFish`, `MapLit`, `RecordLit`-поля, `TaggedTemplate`,
`InterpolatedStr`, `Spawn/Detach/Blocking/Supervised/Forbid/Realtime`,
`While/WhileLet/Loop`, `Select/Range/Throw/Interrupt/With/Forall/Exists/
HandlerLit/ProtocolLit`, `IfLet`(только priv-pattern check) — не
продюсеры, вне инвентаря.

Продюсерные ветви:

| Узел | Констрейнт | Мигрируемость |
|------|-----------|----------------|
| `Call` (closure-arg seeds из сигнатуры callee) | Eq (params ← expected из сигнатуры) | средняя — bidirectional-closure класс, C6-семья, вне этой волны |
| `Call` (`Some(x)` ctor) | Eq (`Option[infer(x)]`) MemberOf(не shadowed) | средняя, пересекается с C (literal-coercion) |
| `Call` (method-return channel, `infer_method_call_channel_type`) | **Resolve** | вне ядра (overload-return семья) |
| `Call` (static-ctor TurboFish, `size_of`/`align_of`) | Resolve / Eq constant | вне ядра |
| `As` | Eq (cast target, gs-gated) | высокая/низкая |
| `Is` | нет аннотации (только диагностика) | н/д |
| `Binary` (cmp/logical→Bool) | Eq constant | высокая/низкая |
| `Binary` (None-сторона `==`/`!=`) | Eq, MemberOf(Option[concrete]) | средняя |
| `Binary` (арифметика, `promote_arith_rt`) | **Join** (два numeric-типа → результирующий, включая TypeParam-bound случаи) | ВЫСОКАЯ концептуальная близость (естественный Join-примитив ядра), риск средний-высокий (горячий путь, многослойные POISON-фиксы) — кандидат для СЛЕДУЮЩЕЙ волны |
| `Unary` | Eq (op-aware: identity Neg/Not, delegate иначе), gs-gated | высокая/низкая |
| `Try`/`Bang` | Eq (unwrap carrier), gs-gated | высокая/низкая |
| `Coalesce` | Eq (delegate к `b`), gs-gated | высокая/низкая |
| `Member` (tuple-field мост из буфера) | **Project** (Tuple→элемент по индексу) | средняя |
| `Index` (range-retry, str-error, element-projection, structural-мост) | Eq + **Project** (Array/FixedArray/Vec/TypedPtr/Readonly→элемент) | средняя, дублирует сайт #3 |
| `If` (`infer_if_common_primitive`) | **Join** двух ветвей + MemberOf(primitive) | средняя |
| `Match` (`infer_match_common_primitive`) | **Join** N ветвей + MemberOf(primitive) | средняя |
| `ArrayLit` (первый Item) | Eq composite (`Vec[T]`) + MemberOf(primitive) | средняя |
| `TupleLit` | Eq composite (all-or-nothing) + MemberOf(primitive) | средняя |
| `ClosureLight` (zero-param) | Eq (`Func{[], ret}`), MemberOf(primitive, non-Unit), gs-gated | средняя, C6-периферия |
| `ClosureFull`/`For`/`ParallelFor` (delegate to `f1_fn_sig_body`/`f1_for_body`) | Resolve (sig-body / iter-elem) | вне ядра |

### C. Семейство literal-coercion / expected-type-coercion (ВЫБРАНО для Ф.2)

Самодостаточное семейство: `annotate_expected_concrete` (:11691),
`materialize_literal_coercion` (:11714, рекурсивный коэрсер),
`materialize_block_tail` (:11893), `materialize_returns_in_block/stmt/expr`
(:11904-11940ish), + 2 чистые структурные проекции `ctor_payload_expected`
(:14438) и `array_elem_type` (:14452). 4 сайта вызова (все DEFINITE —
committed context, не speculative-overload-probe): `f1_check_fn`
arrow-body + block-tail + все `return` (:6710/6712/6724/6727),
`f1_check_assign_let` let-binding (:8675), `f1_check_call` chosen-overload
arg × 2 (:9851 receiver-substituted, :10217 resolved_callees canonical).

Констрейнты внутри: Eq (IntLit ← expected sized-scalar), MemberOf
(sized-scalar-non-wide гейт на IntLit; concrete-generics-all гейт на
Some/Ok/Err ctor и на ClosureLight Func-annotation; primitive∨Str∨Bool
гейт в `annotate_expected_concrete`), рекурсивная декомпозиция через
`ctor_payload_expected`/`array_elem_type` (чистые Project-хелперы,
переиспользуемые как есть). Риск локализован (одно самодостаточное
семейство, документированные инварианты) — ПРИЧИНА выбора планом.

### D. Resolve/overload-семья (ВНЕ этой волны, Ф.3-остаток)

`resolve_generic_static_return`, `resolve_instance_method_return(+_arity)`,
`resolve_prefix_generic_method_return`,
`resolve_method_return_with_closure_args`, `resolve_instance_method`,
`resolve_vrt`, `resolve_call_params`, `overload_applicability` (:9571),
`check_instance_overload` (:9649) — residual-overload класс (частично
закрыт U.3.1-U.3.4). Не трогается в этой волне (объём — несколько волн).

### Итог инвентаря

~13 преамбула + ~20 продюсерных матч-арм + 1 самодостаточное
literal-coercion семейство (9 функций/4 сайта) + resolve-семья (9
