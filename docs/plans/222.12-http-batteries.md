# План 222.12 — батарейки nova-http: модульная раскладка внутри пакета

**Статус:** 📋 ДИЗАЙН, НЕ СОГЛАСОВАН (декомпозиция по запросу владельца 2026-07-23; вынесено из
[222 §7б](222-http-framework.md) отдельным файлом). Ждёт owner-go на отдельные модули.
**Приоритет:** после ядра 222 (222.1-222.7) — надстройка, ничего не блокирует.
**Родитель:** [222](222-http-framework.md) (зонтик). **Источник анализа:**
[docs/research/http-frameworks-gap.md §4г](../research/http-frameworks-gap.md).
**Зона:** пакет `nova-http` (внешний git-репо), только `.nv`; компилятор не трогается.

## 0. Решение владельца по структуре (2026-07-23) — зафиксировано

**Батарейки живут ВНУТРИ пакета `nova-http` отдельными МОДУЛЯМИ**, не отдельными пакетами.
Три факта, проверенных по коду, снимают спор:

1. **Ни одна батарейка НЕ требует новой внешней зависимости** (§2) — `compress` уже зависимость
   пакета (авто-декомпрессия клиента, 205 Ф.2), а `ReadFs`/`rate_limiter`/`jwt`/`hmac` **уже в std**.
   Главный аргумент за отдельные пакеты («не тащить лишнее») отпадает.
2. **Манифест не поддерживает optional-deps/features** (`Dependency` = name/source/forbid,
   `compiler-codegen/src/manifest.rs:52`) → отдельные пакеты всё равно «всё или ничего».
3. **Реестра/экосистемы нет** (требование владельца «батарейки из коробки») → отдельные пакеты
   некому обнаруживать.

**Плата за использование** — по импорту: CU включает только импортированные модули, поэтому
`import http.middleware.cors.{cors}` не тянет ни сжатие, ни статику.

## 1. Источники: семантика и форма — РАЗНЫЕ

- **Семантика (ЧТО делать) — `tower-http` (Rust).** Самый строгий/полный набор правил; сама
  семантика языко-нейтральна (CORS — RFC, сжатие — content-negotiation с q-values, статика —
  ETag/Range/If-Modified-Since).
- **Форма (КАК композировать) — Go/`chi`, НЕ tower.** Go-middleware = `func(http.Handler)
  http.Handler` — **один-в-один наш `fn(next Handler) -> Handler`** (222.4). tower-`Service`
  (generic по req/resp + `poll_ready` + backpressure) в нашу модель не переносится.
- **Эталонные реализации отдельных кусков — Go stdlib**: `http.FileServer` (ETag/Range/
  If-Modified-Since — тонкие места, вылизаны годами), `http.TimeoutHandler`, `httptest`.
- **Из Rust дополнительно:** `headers`-крейт (типизированные заголовки — кандидат-улучшение
  нашего `HeaderMap`), `axum-extra` (cookie-jar, typed-header extractors — формы для 222.13).

## 2. Раскладка модулей + готовность зависимостей (проверено 2026-07-23)

| Модуль | Семантика из | Нужно | Готовность |
|---|---|---|---|
| `http.middleware.cors` | `tower-http::CorsLayer` | чистая логика заголовков | ✅ ноль зависимостей |
| `http.static` | **Go `http.FileServer`** + `tower-http::ServeDir` | `ReadFs` | ✅ `std/fs/readfs.nv` (210 Ф.6б) |
| `http.middleware.compress` | `tower-http::CompressionLayer` | gzip/brotli | ✅ `compress` УЖЕ зависимость пакета |
| `http.middleware.log` | `chi/middleware.Logger`+`RequestID`+`RealIP` | время, вывод | ✅ std |
| `http.middleware.ratelimit` | `chi/middleware.Throttle`, `tower::limit` | токен-бакет | ✅ **`std/concurrency/rate_limiter.nv` УЖЕ ЕСТЬ** — обёртка, не реализация |
| `http.middleware.recover` | `chi/middleware.Recoverer`, `tower-http::CatchPanicLayer` | перехват паники хендлера | ⚠️ **открытый вопрос §4** |

## 3. Фазы (порядок = по ценности и по нарастанию риска)

- **Ф.1 `cors`** — самый частый и самый простой (чистые заголовки, ноль зависимостей). Полный
  preflight (`OPTIONS`), `Allow-Origin`/`-Methods`/`-Headers`/`-Credentials`/`Max-Age`,
  wildcard-vs-credentials-конфликт (RFC-ловушка: `*` + credentials запрещено).
- **Ф.2 `log`** — `RequestID` (генерация/проброс `X-Request-Id`), `RealIP` (`X-Forwarded-For`
  с осторожностью — доверять только за прокси), время ответа, статус. Форма — chi.
- **Ф.3 `static`** — поверх `ReadFs` (`DirFs` для dev, `EmbeddedDir` для prod — 210 Ф.6б уже
  даёт обе). ETag (сильный по содержимому), `If-None-Match`/`If-Modified-Since` → 304,
  `Range` → 206, mime по расширению, защита от `..`-escape (в `readfs` уже есть boundary-check).
  Смыкается с roadmap-пунктом `serve_static(mux, ReadFs)` (nova-http README).
- **Ф.4 `compress`** — `Accept-Encoding` с q-values, выбор gzip/br, порог по размеру (не жать
  мелкое), `Vary: Accept-Encoding`, НЕ жать уже сжатое (image/*, application/zip).
- **Ф.5 `ratelimit`** — тонкая обёртка над `std/concurrency/rate_limiter.nv`; ключ (IP/токен),
  `429` + `Retry-After`, конфигурируемое окно.
- **Ф.6 `recover`** — ПОСЛЕ решения §4.

## 4. Открытый вопрос — семантика паники в фибре (блокирует Ф.6)

`chi.Recoverer`/`CatchPanicLayer` ловят панику хендлера и отдают 500 вместо падения процесса.
**У нас неясно:** паника внутри фибры — что делает M:N-рантайм (роняет воркер? фибру? процесс?),
и есть ли механизм перехвата на границе хендлера. Нужна разведка ДО Ф.6 (родня `[M-187]`-семьи и
supervised-модели). Если перехвата нет — либо отдельный под-план в рантайме, либо честно
задокументировать «паника = падение, используйте Result» (что согласуется с D325: паника у нас —
для багов, а не для управления потоком; тогда Ф.6 может оказаться НЕ нужен вовсе).

## 5. Гейты

Каждая фаза: юнит-тесты модуля (мок-`ServerRequest`, без сокетов) + `nova test src` пакета δ0 +
интеграционный гейт зонтика (§9 плана 222 — флагман под `--strict-effects` + loadtest).
`static` дополнительно: фикстуры ETag/304/Range на `EmbeddedDir` (детерминированно, без ФС).
`compress`: round-trip через существующий `compress`-пакет.
