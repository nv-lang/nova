# План 209 — Multi-TU codegen: большой CU → N `.c`-единиц (параллельная компиляция)

**Статус:** 🚧 В РАБОТЕ. Ф.0 (рекон) + Ф.1 (codegen split) + Ф.2 (тулчейн) + Ф.3 (const-value
split fix, `30e9e6754`; conformance flag-ON = FAIL:0) ЗАКРЫТЫ и влиты (дефолт байт-идентичен,
флаг `NOVA_MULTI_TU` off; opt-in даёт ~16% на мега-CU). Ф.4 (part-size тюнинг)/Ф.5 (DCE-аудит)/
Ф.6 (default-on) — запланированы, не начаты. Владелец: «путь 2 — общая идея, не только conformance».
**Приоритет:** **P1** (блокирует надёжность/скорость ВСЕХ мега-CU гейтов — сейчас полный
`nova test spec_tests` зависает на codegen+компиляции 13-МБ `.c` из 963 файлов).

## Мотив

Codegen эмитит **один compile unit → один `.c`-файл**. Для большого CU (conformance: 963 файла →
**13 МБ `.c`**) это упирается в **суперлинейность** C-компилятора (clang/msvc на одной гигантской
translation unit) + медленный Rust-codegen гигантского буфера. Результат: полный гейт непрактично
долог/зависает. 187-волна добавила тестов → CU перевалил порог, время взорвалось.

**Ключ:** проблема — в ОДНОМ гигантском `.c`, НЕ в логическом CU. Логический CU (кросс-файловый
резолв имён, mono-коллектор, D307 folder-module) уже отработал ДО эмиссии. Значит **вывод** можно
резать на N translation units, СОХРАНИВ единый логический CU (полное кросс-файл-покрытие цело).

## Целевая картина

Codegen эмитит большой CU как:
- **1 общий заголовок** `<cu>_common.h` — все typedef'ы, forward-decl'ы, глобалы, схемы, extern'ы,
  runtime-includes. Эмитится ОДИН раз, инклудится каждым TU.
- **N `.c`-единиц** `<cu>_part0.c … <cu>_partK.c` — подмножества ОПРЕДЕЛЕНИЙ функций (каждая функция
  целиком в одном TU), каждая `#include "<cu>_common.h"`.
- Тулчейн: компилирует N `.c` **параллельно** (по числу ядер) → N `.o` → линкует в один бинарь.

Суперлинейный C-compile → почти линейный (N параллельных мелких TU). **Общий механизм** — не только
conformance: любой большой `nova build`/`test`-таргет выигрывает.

## Развилки / рабочий дизайн (рекон Ф.0 подтверждает file:line + безопасность)

1. **`static` через границу TU (ГЛАВНАЯ).** Функция/глобал с internal linkage, вызванный из ДРУГОГО
   TU → link-error. **РЕШЕНИЕ: снять `static` с cross-TU-символов** (→ внешняя линковка), их
   `extern`-декларации — в `_common.h`. Безопасно, т.к. codegen УЖЕ манглит имена **уникально внутри CU**
   (D381 collision-aware) → коллизий при промоушне нет. Проще граф-разбиения. **Fallback** (если
   рекон найдёт риск): держать взаимозависимые static-кластеры в одном TU (граф-партиция).
2. **Стратегия разбиения.** По накопленному **размеру-порогу** (~0.5–1 МБ/TU), идём по функциям в их
   текущем **детерминированном** порядке, новый TU при переполнении. **Каждая функция целиком** в одном
   TU. Детерминизм (тот же порядок → те же границы) → byte-stability результата + кеш.
3. **`_common.h` (пролог).** Всё из шапки `.c` → в общий заголовок: typedef'ы, определения структур,
   **forward-decl'ы всех функций**, extern-глобалы, схемы, NOVARES-typedef'ы, runtime-`#include`'ы.
   Инклудится КАЖДЫМ part'ом. Глобал с ОПРЕДЕЛЕНИЕМ (не extern) → в РОВНО один part + `extern` в `.h`
   (иначе multiple-definition при линковке).
4. **Порог включения.** Multi-TU только для CU выше порога (напр. >2 МБ / >200 функций) — мелкие
   остаются одним `.c` (оверхед split+link не окупается).
5. **Build-cache-ключ.** Порог+стратегия разбиения — часть ключа (смена инвалидирует кеш).

## Фазы (модель по [feedback-cheap-models])

- **Ф.0 Дизайн + развилки (opus-рекон, ИДЁТ):** разрешить static-cross-TU (промоушн vs граф),
  стратегию разбиения, формат `_common.h`, порог — с file:line-якорями. Карта Ф.1/Ф.2 для дешёвого
  исполнения. D-блок (codegen emission model) ТОЛЬКО если меняет наблюдаемое (имена символов при
  снятии `static` → внешняя линковка). Read-only. Гейт: карта на руках.
- **Ф.1 Codegen split (sonnet по карте):** вынести пролог в `_common.h`; резать определения функций на
  N буферов по порогу; снять `static` с cross-TU-символов (→ внешняя линковка). АДДИТИВНО за флагом (старый
  одно-`.c` путь — дефолт, пока не включим). Точечная верификация: мелкий CU → 1 `.c` (без изменений);
  большой → N `.c` + компилится. Мега-CU НЕ гонять — авторитетный гейт оркестратор.
- **Ф.2 Тулчейн (sonnet):** параллельная компиляция N `.c` → `.o` → линк (test_runner.rs + nova-cli
  build); порог-гейт (>2МБ → multi-TU). Верификация: линк без multiple-definition, бинарь бежит.
- **Ф.3 Включить для conformance (оркестратор-гейт):** полный `nova test spec_tests` быстрее+надёжнее;
  замер до/после; **байт-паритет РЕЗУЛЬТАТА** (тот же бинарь/вывод, меняется только раскладка `.c`).
- **Ф.4 Общий (sonnet/haiku):** включить для `nova build`/крупных std-таргетов; мелкие CU не задеты.

## Гейты
Полный conformance один-CU (теперь multi-TU) зелёный + БЫСТРЕЕ (замер); байт-паритет РЕЗУЛЬТАТА
(вывод программ идентичен — режем только раскладку `.c`, не семантику); линк без multiple-definition;
детерминизм (тот же split при тех же входах).

## Границы
Не меняет логический CU (кросс-файл-резолв/mono/D307 — как есть). Не меняет семантику программ.
Только физическая раскладка codegen-вывода (1 `.c` → `_common.h` + N `.c`) + параллельная компиляция.
Ортогонально Plan 200.1 (там папочные CU + кеш; здесь — split ОДНОГО CU).

## Прогресс (свод рабочих заметок Ф.0–Ф.2; сами notes-файлы удалены — история в git)

**Ф.0 рекон (opus, read-only).** Подтвердил: (а) все top-level символы уже CU-уникальны по манглу
(`nova_fn_<mod>_f<file_id>_<name>`, D381 collision-aware) ⇒ снятие `static` (→ внешняя линковка) безопасно,
граф-партиция НЕ нужна; (б) вывод копится в один `String` `self.out` + splice маркеров-плейсхолдеров
в finalize — «резать по строке начала тел» недостаточно, нужна классификация decl/def (→ выбран
пост-финализационный сегментатор, не dual-buffer); (в) сейчас ОДИН вызов компилятора `.c…→exe`
(драйвер не параллелит) ⇒ Ф.2 обязана сама компилировать `part_i.c→.o` параллельным пулом + линк.

**Ф.1 codegen split (sonnet) — влит.** `top_level_storage()`/`top_level_storage_inline()` хелперы +
поле `multi_tu_enabled` (env `NOVA_MULTI_TU`); ~60 top-level `static`-сайтов промоутнуты за флагом
(дефолт off = байт-идентичен, подтверждено эмпирически diff'ом на `getting_started.nv`). Новый модуль
`compiler-codegen/src/codegen/split_tu.rs` — сегментатор глубины-`{}` + классификатор decl/def +
auto-прототипы + дедуп + A3-инвариант уникальности имён (`Result::Err` на дубле). `emit_module_multi_tu`
back-compat обёртка (`emit_module` не тронут), порог-гейт (>2МБ / >200 fn). 2 постоянных inline-исключения
(`nova_typeid_user_name`, per-E throw fast-path).

**Ф.2 тулчейн (sonnet) — влит.** `compile_multi_tu_to_exe` (test_runner.rs): пишет `_common.h`+`_partK.c`,
компилирует части параллельно (`std::thread::scope`, без внешних crate), runtime-`.c` компилит один раз,
линк с идентичными флагами во всех TU (ABI-инвариант `-DNOVA_MAX_EFFECT_STORAGES=N`). Интегрирован в
`codegen_to_c`/`run_one` + `nova-cli cmd_build` (Split держится в памяти, не кешируется). Коммиты:
`11ca28768` (mono-gap fix), `c56069534` (тулчейн), `a6317dd8c` (3 бага сегментера + 4 теста).

### 3 бага сегментера split_tu (найдены при верификации Ф.2, ИСПРАВЛЕНЫ — a6317dd8c)
1. Имя юнита ловилось из `(` внутри ведущего doc-комментария → ложная коллизия с `main` → `find_first_real_paren`.
2. Cond-блок (`#ifdef _MSC_VER…#endif`) с ведущим `\n` не распознавался → резался по каждой `;` → skip также `\n`/`\r`.
3. Array-global (`_nova_strlit_<hash>_buf[]=`) терял имя → verbatim в `_common.h` → duplicate-symbol → `strip_trailing_array_brackets`.

### 2 пре-существующих дефекта, ВСКРЫТЫХ промоушном (не вызваны 209)
- **mono-gap embedded/delegated методов — ИСПРАВЛЕН (Ф.2 Task B, `compute_dead_decls_with`).** D39 embed-proxy
  синтезируется в codegen (не AST) → вызов `Nova_HashMap_method_merge_from` из proxy невидим для
  `collect_used_names` → под `static` маскировался DCE, при внешней линковке → undefined-symbol на линке. Фикс: пред-скан
  `embedded_type_names`, методы embed-типов кладутся в worklist reachable-by-name (over-keep, как concrete-slice).
- **D39 embed-delegation call-site НЕ-op — ОТКРЫТ (marker в backlog).** `Set.merge_from(b)` = no-op,
  `for v in set.values()` тело не исполняется. Воспроизводится в default (НЕ связан с 209). Отдельная волна.

## Ф.4 — тюнинг part-size (5-10 частей, не 26) + замер (владелец 2026-07-15)
26 частей (13МБ / 500КБ) — многовато; каждая часть инклудит весь `_common.h` → N перепарсов огромного
заголовка = главная накладная, съедающая выигрыш параллели. Поднять `MULTI_TU_PART_THRESHOLD_BYTES`
(`emit_c.rs:1967`) 500КБ → **~1.5-2 МБ** → 13МБ-CU даёт **~7-9 частей**. **Замер** `app_effect_basic_t8_1`
при 5-10 частях vs 26 (baseline: flag-OFF 115s / flag-ON@26 97s = 16%; целим БОЛЬШЕ за счёт меньшего
header-overhead). Гейт: FAIL:0 при новом part-size + число (побило ли 16%). «В идеале протестировать» (владелец).

## Ф.5 — DCE-аудит: multi-TU как прожектор скрытых codegen-багов (инсайт владельца 2026-07-15)

> **210-стык (ревью-3 2026-07-16):** блоб-статики (embed/embed_dir) сейчас рендерятся в ПРОЛОГ → в
> multi-TU попадут в `_common.h` → каждый part перекомпилирует массив (×5.3 текст-раздув). Требование:
> определения блобов — в ОДИН part, в common только extern; тест «большой блоб под NOVA_MULTI_TU=1».
**Идея:** multi-TU (всё `extern`, DCE выключен) заставляет эмититься тела ВСЕХ функций → тихо-битые тела
(missing/broken bodies = баги генерации) всплывают адресной link-error (undefined symbol / type-mismatch)
вместо того чтобы прятаться под dead-code-elimination. Так уже найдены **mono-gap · D39 · consume-cleanup ·
TlsVersion**. Значит 209 — не только скорость, но и **диагностический инструмент корректности codegen**.
**Два прожектора одного класса:** (1) multi-TU → **внутрипакетные** DCE-скрытые баги; (2) **cross-package
линковка** (функции внешнего пакета обязаны эмититься) → **межпакетные** (так нашлись consume-cleanup/TlsVersion
при линке echo_server/echo_client, даже без multi-TU).
**Состояние:** conformance-корпус УЖЕ multi-TU-чист (flag-ON = FAIL:0) → остаток класса живёт в **межпакетных
сценариях** (examples с nova-tls/http).
**Аудит-пасс:** (0) СПЕРВА определить, какие examples реально компилятся — **НЕ все** (некоторые broken/
experimental; **187-aggregator точно собирается** — владелец); (1) собрать компилящиеся (aggregator + cross-
package tls/http) под multi-TU + строгой линковкой; (2) перечислить ВСЕ оставшиеся DCE-скрытые баги РАЗОМ
(не по одному); (3) фиксить серийно (каждый — свой fix + marker). Гейт: полный список; закрытие серией фиксов.

## Ф.6 — multi-TU default-on (после Ф.5)
Когда класс DCE-скрытых багов вычищен (Ф.5) → always-promote безопасен (битых тел не осталось) → включить
multi-TU **по дефолту** выше порога БЕЗ two-pass (промоушн больше ничего не вскрывает). **Промежуточно**
(до завершения Ф.5): **opt-in `NOVA_MULTI_TU=1`** для мега-CU-гейтов/сборок — безопасно, ~16%, решение
владельца 2026-07-15 (static-промоушн не в дефолте → не трогает обычные сборки).
