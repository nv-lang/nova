# План 234 — побитовое семейство: `bit`-префикс + оператор `~`

**Статус:** 📋 СОГЛАСОВАН (владелец 2026-07-27: «полностью согласен, `~` делать
перегружаемым для пользовательских типов»). **Спека — УЖЕ ВНЕСЕНА** (D46-амендмент
в `spec/decisions/03-syntax.md`, тем же слиянием, что этот план).
**Маркер:** `[M-bitwise-operator-method-naming]`.
**Тема:** имена операторных методов + один новый оператор. Язык-меняющее.

## 0. Что решено (сводка амендмента D46)

**(A) Переименование** — RETRACT прежних имён:

| оператор | было | стало |
|---|---|---|
| `a & b` | `@and` | **`@bitand`** |
| `a \| b` | `@or` | **`@bitor`** |
| `a ^ b` | `@xor` | **`@bitxor`** |

**(B) Новый оператор** `~a` → **`@bitnot()`**, **перегружаемый пользовательскими
типами** (не только примитивы — решение владельца).

**`!a` → `@not()` НЕ меняется** и остаётся ЛОГИЧЕСКИМ.

## 1. Почему (обоснование, чтобы не переспрашивать)

**(A)** В Nova `&`/`|` — ЧИСТО побитовые: логические `&&`/`||` не перегружаются
вовсе (D46 Правило 2). Имена `and`/`or` читаются как логические — в прозе и в
большинстве языков. Rust (эталон архитектуры) префиксует ровно ради различения:
`BitAnd::bitand`/`BitOr::bitor`/`BitXor::bitxor`. **Цена сейчас ≈ ноль:**
реализаций прежних имён в `std` было **0** (первый потребитель —
`std/math/int128.nv`, заведён 2026-07-27).

**(B)** Побитового НЕ не существовало КАК ОПЕРАТОРА: `!` — логический (на `bool`
работает, на целых **нет** — проверено пробой), `~` отсутствовал. Единственный
путь — ширино-зависимый обход `x ^ 0xFFFF…`, **9 сайтов в std**:
`checksums/crc32.nv:74,103` · `crypto/md5.nv:196` (там комментарий `// ~B` —
автор *думает* «`~B`», а *пишет* маску) · `math/int128.nv` (1, `^ 0xFFFF…FF`) ·
остальные `^ 0xFFFFFFFF`. **Опасность:** при смене ширины типа (`u32`→`u64`)
маска МОЛЧА перестаёт быть дополнением — компилятор не ловит. `~x`
ширино-независим по построению.

## 2. Семантика `~` (нормативно, из D46-амендмента)

- `~x` — побитовое дополнение; на знаковых **дополнение до двух**: `~x == -(x + 1)`.
- **Переполнения не бывает** — trap-дефолт (D423) неприменим.
- Приоритет — **унарный**, как `!` и унарный `-`.
- Примитивы: `u8/u16/u32/u64`, `i8/i16/i32/i64`, `int`, `uint` — лоуэринг в C `~`.
- Пользовательские типы: диспетчеризация в `@bitnot()` тем же механизмом, что
  `@neg()` для унарного `-`.

## 3. Фазы

- **Ф.0 ✅ СДЕЛАНО** (это слияние): D46-амендмент в спеке + план + `std/math/int128.nv`
  переведён на `@bitand`/`@bitor`/`@bitxor`/`@bitnot` (первый и единственный
  потребитель; операторы на named-tuple всё равно не лоуэрятся —
  `[M-named-tuple-operator-overload-incomplete]`, поэтому методы зовутся по имени
  и переименование безопасно ДО фикса компилятора).
- **Ф.1 Компилятор — переименование диспетчера.** Таблица `BinOp → имя метода`:
  `"and"`→`"bitand"`, `"or"`→`"bitor"`, `"xor"`→`"bitxor"`. Сайтов немного, но их
  **два и более** (`emit_c.rs` ветка named-tuple ~33656 и соседняя ~33737 —
  см. маркер), нужен греп по всем.
- **Ф.2 Компилятор — оператор `~`.** Лексер (токен; `~` сейчас свободен —
  проверено грепом 2026-07-27), парсер (унарный, приоритет как `!`), чекер
  (резолв `@bitnot` для пользовательских типов), codegen (примитивы → C `~`;
  пользовательские → вызов `@bitnot`).

  **⚠ INTEGER PROMOTION — РЕШЕНИЕ ВЛАДЕЛЬЦА 2026-07-27: эмитить надёжный низкий
  уровень, как обход и делал.** В C `~` над узким типом сначала продвигает его в
  `int`, и в выраженческом контексте (сравнение, аргумент, цепочка) результат
  молча неверен. Таблица эмиссии (точная, по семантике продвижения C):

  | тип Nova | эмиссия C | почему |
  |---|---|---|
  | `u8`/`u16` | `x ^ 0xFF` / `x ^ 0xFFFF` | нулевое продвижение: старшие биты обоих операндов нули → результат корректен УЖЕ в `int`, каст не нужен (ровно то, что делал мигрируемый обход) |
  | `i8`/`i16` | `~x` голый | знаковое продвижение: `~5 = -6` — корректное значение в диапазоне типа; XOR-маска здесь была бы НЕВЕРНА без каста |
  | `u32`/`u64`/`i32`/`i64`/`int`/`uint` | `~x` голый | продвижения нет (ранг ≥ int) |

  Пин-тесты ОБЯЗАТЕЛЬНО в выраженческом контексте (не присваивание):
  `~(0xF0 as u8) == (0x0F as u8)`, `~(5 as i8) == (-6 as i8)`, то же `u16`/`i16`.

  **Приоритет — пин-тесты взаимодействий** (в плане было только «как `!`»):
  `~x.f()` разбирается как `~(x.f())` (постфикс сильнее унарного — как у `!`/`-`);
  `~x as u8` — зафиксировать фактический разбор пин-тестом; `~~x` (двойное
  применение) — легально, тождество `~~x == x` пин-тестом.
- **Ф.3 Миграция std.** 9 сайтов `x ^ 0xFFFF…` → `~x`. Не блокирует Ф.1/Ф.2, но
  она и есть доказательство пользы. **Гейт байт-паритета неприменим** — `~x` и
  `x ^ mask` дают тот же результат, но другой C; проверять поведенчески
  (`nova test std/src/checksums`, `std/src/crypto` — δ0 по значениям хэшей).

- **Ф.1а линт старых имён — НЕ НУЖЕН (решение владельца 2026-07-27):** Nova не в
  релизе, потребителей, знающих старые имена, не существует; `@and`/`@or`/`@xor`
  как ОБЫЧНЫЕ имена методов остаются легальны без предупреждений.

- **Ф.2а Compound-присваивания `&=` `|=` `^=` `<<=` `>>=` — ДОБАВИТЬ (решение
  владельца 2026-07-27: «мы просто забыли про них»).** Факты: `+=`/`-=`/`*=`/`/=`
  в лексере ЕСТЬ, сдвиги `<<`/`>>` как операторы ЕСТЬ — отсутствуют именно
  битовые compound-формы (`<<=`/`>>=` добавлены в состав по симметрии со
  сдвигами). Объём: 5 токенов лексера → парсер по образцу `+=` → десугар в
  `a = a <op> b`; отдельного операторного метода НЕТ — пользовательские типы
  диспетчеризуются тем же `@bitand`/`@bitor`/`@bitxor`/`@shl`/`@shr`.
  Тесты: примитивы (включая узкие ширины — таблица эмиссии выше действует и
  здесь) + пользовательский тип + `x <<= n` на знаковых/беззнаковых.
  Спека: дополнение (C) в D46-амендменте — внесено тем же слиянием, что эта
  редакция плана.

**Взаимодействие с `[M-named-tuple-operator-overload-incomplete]`:** тот маркер
чинит ветку named-tuple (`% & | ^ ! < > <= >=` не лоуэрятся). Ф.1/Ф.2 этого плана
должны попасть в ту же таблицу — разумно исполнять их **одной волной** с фиксом
маркера, иначе таблица правится дважды.

## 4. Гейты

Ф.1/Ф.2: фикстуры на каждый оператор — примитивы (все ширины, знаковые и
беззнаковые; для узких ширин — ОБЯЗАТЕЛЬНО выраженческий контекст, см.
integer-promotion выше) + пользовательский тип (запись И named-tuple) + neg
(тип без `@bitnot` под `~` → честная ошибка, не ICE). **Neg-список (решение владельца
2026-07-27: `~` только для целочисленных; заодно закрыть ВСЁ семейство унарных):**
`~true`, `~1.5`/`f32`/`f64`, `~"str"`, И ТУДА ЖЕ `-true`, `-"str"` (и прочие
неподдерживаемые комбинации унарных `!`/`-`/`~` × типы — пройтись единообразно
одной волной) — каждый даёт внятную ошибку чекера, НЕ доезжает до C (иначе
CC-FAIL с текстом clang вместо диагностики). Если какой-то из минус-случаев
сегодня уже даёт внятную ошибку — пин-фикстура; если CC-FAIL — чинится этой же
волной. `~` на знаковом: пин-тест `~x == -(x+1)`. Мега-CU conformance полным фильтром (язык-меняющее) +
флагман-examples. Ф.3: значения хэшей/CRC не изменились.
