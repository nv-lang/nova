## 1. Зачем (проверено по коду)

Дизайн supervision-as-effect (173.2) и сбора (173.1) опирается на свойства, которых **shipped-рантайм не даёт**:

## 2. Решения

1. **Per-slot retention ошибок:** заменить одно-слотовый `first_error_atomic` на **`child_error[idx]`-массив**
   (расширить существующий `fiber_error[]`, `fibers.h:198/1688`) — каждое падение хранится по индексу ребёнка.
2. **Сериализованный failure-decision loop на main-flow:** место, где по одному обрабатываются retained-падения
   **до** уничтожения `SpawnCtx` упавшего; с push'ем fail-frame на call-site (чтобы решение могло само throw'ить).
   Это hook, на котором 173.2 запускает `on_child_fail` (здесь — только инфраструктура, без самого эффекта).
3. **Пиннинг `SpawnCtx` на время scope**, когда присутствует супервизор/рестарт (расширить `ctx_pins`) — чтобы
   входы для рестарта/решения были живы.
4. **Закрыть multi-worker supervised-drain гонку** (координация с Plan 83.4.x/83.11): supervised корректен под
   реальным M:N, без костыля `NOVA_MAXPROCS=1`.

## 2. Главный риск-сайт (concurrency soundness) и pre-fatal детект

Два soundness-риска, ранжированы. Оба должны иметь tripwire, срабатывающий **до** фатала (AV/hang/silent-corruption), а не после.

### Риск R1 (HIGHEST) — pool-recycle aliasing SpawnCtx
Если при смерти supervisor-ребёнка НЕ подавить `nova_spawn_pool_release` (runtime.c:1128/1179/1855), буфер SpawnCtx уходит в P-local pool и **переписывается следующим spawn до** decision-loop → retained-указатель читает чужие captures. Тихая corruption, не крэш.
- **Detect до фатала:** в debug-сборке **poison** буфера при release (`memset(0xDD)`) + magic-canary в `NovaSpawnCtxBase`; decision-loop проверяет canary перед чтением и `abort("ctx recycled under supervisor")`. Плюс обязательный guard-assert `!base->_nova_parent_scope->has_supervisor` в самой `nova_spawn_pool_release`.

### Риск R2 (HIGH) — возврат torn-base при cross-worker записи в realloc'абельный `child_error[]` (жало §7.7)
`fiber_error[]/child_error[]` — plain realloc+swap (:571). Если Ф.2 remote-writer пишет по адресу, а parent параллельно `nova_scope_grow`'ит массив — та же исходная M-83.11 torn-base.
- **Инвариант-решение (предпочтительно, Option B — дешевле chunked):** capacity parent-scope **заморожена на spawn-фазе** — все дети заводятся `spawn_into` на main-thread ДО drain; во время drain grow'а нет. Writer (сам ребёнок) пишет свой слот **строго ДО** `nova_aint_dec(pending_remote)` (release-store); reader (main) читает **после** `pending_remote==0` (acquire на :2083). Тогда base стабилен и happens-before держится без chunked.
- **Detect до фатала:** debug-tripwire `assert(!scope->_drain_started)` внутри `nova_scope_grow` для supervised-scope — ловит ЛЮБОЙ grow-during-drain **до** того как он порвёт base. Плюс `assert(nova_aint_load(&pending_remote)==0)` перед первым чтением `child_error[]` в decision-loop.
- **Fallback (Option A):** если реальный grow-during-drain найдётся (напр. динамический spawn внутри supervised) — перевести `child_error[]` на тот же chunked stable-address приём, что `NovaSchedState` (:398-445). НЕ делать наивно.

### Риск R3 (MEDIUM) — marker clash в drain
Если оставлять `fiber_ctx[i]` non-NULL как способ retention, worker-owned check :1844-1849 (`base->_nova_parent_scope != NULL → alive++`) сочтёт мёртвого ребёнка живым → drain не завершится (**hang**).
- **Detect до фатала:** watchdog уже встроен (`NOVA_WATCHDOG_DUMP_SECS`, :2010-2033) — hang задампится за 5s. Но правильнее не допускать: retention ИСКЛЮЧИТЕЛЬНО через отдельный канал (`ctx_pins`/`child_ctx[]`), а `fiber_ctx[i]` всё равно обнулять :1834/:1937.

**Общий pre-fatal harness для всех трёх:** прогон целевых фикстур под `NOVA_WATCHDOG_DUMP_SECS=5` (hang→state-dump вместо вечного зависания) + TSAN-проход на Linux (закрывает заодно OPEN-followup `[M-83.11-f2-arm-tsan]`, simplifications.md:35605). Stress-итерации, НЕ single-shot (иначе P(false-good) высок, урок simplifications.md:35614).

## 5. Дробление на под-атомы (feasibility) — ДА, с промежуточными гейтами

План раздробляем и **должен** дробиться — каждый блок имеет свой гейт, keystone-порядок такой:

1. **Ф.1-D целиком** (A1.1→A1.3) — независим, code-noop, закрывает статусный долг сразу. Промежуточный гейт после каждого: review / G-STRESS.
