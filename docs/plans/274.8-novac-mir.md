# План 274.8 — MIR для Карины: одно понижение вместо шести дверей

**Статус:** 📝 ЗАВЕДЁН 2026-09-06 (слово владельца того же дня: «что-то мешает сейчас добавить MIR? если нет —
добавляй»), перепроверен `/plan-recheck` тем же днём (правки: раздел 1а «уже сделано», правило счёта дверей,
машинные критерии M0, база нового стража с сегодняшнего числа, полные пути, два вопроса). Кода ещё нет — критерии
первые, по правилу `/next`. **СДЕЛАНО:** ничего. **ОСТАЛОСЬ:** M0 (устройство в `novac-architecture.md` + модуль
`lower/ir.nv` + страж одной двери с базой), M1 (value-tail-цепочка в IR), M2 (операторы и блоки), M3 (эмиттер читает
только IR). Следующий шаг — M0, после пуша волны W4 плана 274.7.

## 0. Почему сейчас — трипвайр Э4 сработал, и это замер, а не ощущение

План 274 (этап Э4) откладывал MIR «до эффектов и `consume`» и ставил **машинный трипвайр** (решение владельца
2026-08-14): «эмиттер понижает одну и ту же форму во втором месте ИЛИ файл эмиттера упирается в лимит тысячи
строк». Оба признака измерены 2026-09-05…06:

- **Двойное понижение — трижды за сутки.** Форма «хвост-значение» понижалась отдельным армом в каждом месте, где
  она законна: хвост блока (`emit_c.nv`, цепочка `tail && j == last_branch`: match / if / кортеж / выражение), тело
  `=>` (`FnExprBody`: match / конструктор / кортеж / if-выражение / выражение), `return`, инициализатор биндинга,
  `??`. Волна W3 (№974) нашла две двери без кортежа, W4 — две без if-выражения и без подъёма построений; каждая
  чинилась «ещё одним армом» — ровно траектория, по которой вырос `emit_c.rs` оракула (274 §Э4).
- **Тысяча строк — упёрлись.** `novac/src/emit_c/emit_c.nv` = 998 строк на 2026-09-06 (лимит 1000, страж
  `check-novac-file-size`); `novac/src/emit_c/emit_expr.nv` = 878 (`wc -l`, тот же день). Следующая форма языка в
  хвосте не влезает без нового файла-арма.
- **«Шесть дверей» — правило счёта** (греп по `novac/src/emit_c/emit_c.nv` 2026-09-06): позиции, где ЭМИТТЕР сам
  решает, куда ложится значение, — (1) хвост блока: цепочка `tail && j == last_branch` — 5 армов (match, if,
  кортеж, выражение…); (2) тело `=>`: арм `NodeKind.FnExprBody` (строка 344) с четырьмя подармами (match,
  конструктор, if-выражение, выражение); (3) `k == NodeKind.RetStmt` (648) с подъёмом построений; (4)
  `@emit_bind` (937) — пять форм инициализатора (if, массив, кортеж, конструктор, выражение); (5) `@emit_coalesce`
  (532); (6) `@emit_if_value` (508) и значение арма match. Шесть позиций, ~17 армов; на каждую новую форму значения
  — по арму в каждую позицию, и это и есть трипвайр.
- Каналы 196 уже есть и работают как «черновик полей MIR» (274 §Э4): `resolved_types: NodeId→TyId`,
  `resolved_callees: NodeId→(target, subst, slots)`, `implicit` (274.7 B1b) — писатель один (`check`), читатели
  тотальны. То есть решения приняты ОДИН раз; чего нет — формы, в которой они лежат: эмиттер до сих пор ходит по
  зелёному дереву и переспрашивает канал на каждом узле, а «где стоит значение» (хвост, `return`, тело `=>`,
  инициализатор) решает сам, шестью дверями.

**Что мешало добавить раньше и мешает ли сейчас** (ответ владельцу 2026-09-06): технических блокеров нет —
конструкция берётся из референсов (274 §Э4, таблица), каналы готовы. Мешали порядок работы (план с критериями до
кода) и очередь 274.7 (ярус 0 самосборки). Решение: MIR заводится этим подпланом СЕЙЧАС, первая волна кода — сразу
после пуша W4; ярус 0 самосборки (W6 — свободные функции поданных модулей, многофайловая единица) идёт
ПАРАЛЛЕЛЬНО, потому что MIR его не блокирует и им не блокируется.

## 1. Что такое MIR здесь — и чего он НЕ есть

**Есть:** форма, в которой лежат УЖЕ ПРИНЯТЫЕ решения чекера, пригодная для одного понижения в C. Скелет —
rustc MIR (274 §Э4, референсы): функция = локалы + базовые блоки; блок = операторы + терминатор; оператор —
`Assign(local, rvalue)`; терминатор — `Goto`, `SwitchInt`/`SwitchTag`, `Return`, `Call{…, target}`; rvalue — то, что
сегодня печатает `emit_expr` (использование локала, литерал, бинарная/унарная операция, вызов, конструктор записи/
кортежа/варианта, поле, индекс, каст, интерполяция как последовательность вызовов строителя). Типы — `TyId`
интернера (уже есть); подстановка — `subst_type` (уже одна дверь); mono — уже отдельный проход (`novac/src/mono/mono.nv`),
IR строится ПОСЛЕ подстановки, инстанс за инстансом (как `Instantiation` сегодня).

**Не есть (границы этого подплана):** не оптимизатор (ни одного прохода над IR, кроме понижения); не новая
семантика (эффекты, `consume`, дропы — СЛОТЫ в терминаторе `Call` и в `Assign` заводятся с самого начала, но
заполняются волнами Э2-б3/Э4 позже, и это записано полями с `/// пусто до …`); не замена чекера (чекер решает,
`lower` читает канал и НИЧЕГО не выводит — тот же принцип, что у эмиттера сегодня, П13.5); не смена ABI (C тот же —
дифференциал обязан не сдвинуться ни на файл).

**Имя модуля** — `lower`: так его называет таблица рёбер §3 `docs/dev/novac-architecture.md` (строка 75: «`lower` —
понижение в бэкенд-агностик форму; **место будущего MIR**»; строка 142: `lower` → `syntax`, `sem`, `diag`; строка 143:
`emit_c` → `lower`, `mono` — «**только** пониженная форма… рёбер-импортов к `syntax`/`tree`/`check`/`names`/`types`
НЕТ»), и временные рёбра `until:E4` (строки 130, 141, 145–147) названы под него. Слово «MIR» — в документах и
разговоре; в коде — `ir` для типов формы и `lower` для прохода, чтобы не заводить третье имя.

## 1а. Уже сделано — не строить дважды (проверено 2026-09-06 чтением дерева)

- **Карта рёбер уже знает `lower`** — строки 75, 142, 143 таблицы §3 `novac-architecture.md`, и целевая строка
  `emit_c → lower, mono` записана; временные рёбра `emit_c → tree/lex/sem/types`, `mono → tree/types`,
  `pipeline → types` стоят с меткой `until:E4` (130, 141, 145–147). M0 НЕ добавляет строк рёбер — он заполняет
  существующие «что течёт» и заводит модуль по ним. Расхождение имён: таблица пишет `syntax`, дерево держит `tree`
  + `parse` + `lex` — вопрос владельцу (§5), умолчание — читать `syntax` как `tree`.
- **Каналы чекера (план 196) готовы и держатся стражем:** `novac/src/sem/channel.nv:208` `types []TyId` (resolved
  types), `callees` (record_callee/callee_of, с подстановкой и слотами), `:210` `implicit` (274.7 B1b); писатель
  один — `check-novac-channel-one-writer`. Это поля IR, уже с владельцем.
- **Инстансы — уже данными:** `novac/src/emit_c/emit_c.nv` `Instantiation { decl, row, subst, ptypes, ret_id, chan }`
  приходит из `mono` через `pipeline`; IR строится над ним, ничего нового про mono не решается.
- **Корни и владельцы (§3а):** таблица владельцев есть, корня «где размещается значение» в ней НЕТ — M0 добавляет
  строку: корень «размещение значения (хвост / `return` / тело `=>` / инициализатор / `??`)», владелец `lower`, дверь
  — терминаторы и `Assign` IR, дом `lower/`, держит `check-novac-arch-class-proofs` (читает таблицу) плюс новый
  страж M1.

## 2. Волны

- **M0 — устройство и пустая форма (½ дня).** `docs/dev/novac-architecture.md`: раздел «IR» — типы формы
  (`novac/src/lower/ir.nv`, модуль `novac.lower`: `Fn`, `Local`, `Block`, `Stmt`, `Rvalue`, `Terminator`), строки
  142–143 таблицы §3 получают колонку «что течёт» дословно по типам формы (страж `check-novac-edge-payload`),
  временные рёбра `until:E4` получают условие конца «M3» и строка корня в §3а (см. §1а). Никаких новых рёбер.
  **Критерии (машинные):** (1) `check-novac-deps` и `check-novac-edge-payload` зелёные на правленой таблице;
  (2) модуль СОБИРАЕТСЯ, а не лежит: держатель `novac/src/pipeline/lower_test.nv` импортирует `../lower` и строит
  пустой `Fn` — PASS в `check-novac-module-tests` (иначе неимпортированный модуль не компилируется вовсе и «собирается
  пустым» — слова); (3) `git diff --stat novac/src/emit_c` пуст — ни одна строка эмиттера не меняется; (4) новый
  страж `check-novac-lowering-one-door.py` заводится ЗДЕСЬ с базой = сегодняшнее число армов позиций значения
  (правило счёта §0, замер при заведении), храповик вниз — иначе, заведённый на M1 с базой 0, он покраснел бы на
  всей истории до M1 (правило команды `/plan-recheck` п.5). Почему не расширение существующих: `check-novac-second-door`
  ловит ДОСЛОВНЫЕ копии функций, `check-novac-one-door-export` — второй экспорт имени; ни один не считает «один
  `NodeKind` понижается в двух функциях» — это другое свойство, и у него нет дома.
- **M1 — value-tail-цепочка через IR (2–3 дня).** Понижаются ТОЛЬКО позиции значения, где сегодня шесть дверей:
  хвост блока, тело `=>`, `return`, инициализатор биндинга, `??`, значение `if`/`match` — в один `Terminator.Return`
  / `Assign(local, rvalue)` над одним `Rvalue`, и `emit_c` печатает IR этих позиций, а не дерево. Что доказывает:
  (1) дифференциал — contract/behavior БЕЗ сдвига (65/57 на 2026-09-06), фикстуры все, корпус байт-в-байт;
  (2) держатели 24/24 + новый `pipeline/lower_test.nv` (одна форма — один rvalue: кортеж/if/match/вызов в трёх
  позициях дают ОДИНАКОВЫЙ IR, различается только терминатор); (3) счётчик дверей: страж M0
  `check-novac-lowering-one-door.py` опускается до 0 тем же коммитом (в `novac/src/emit_c/emit_c.nv` не остаётся ни
  одной пары «`tail && … kind == X`»); (4) `novac/src/emit_c/emit_c.nv` ≤ 800 строк (замер, не цель ради цели:
  столько уходит с шестью дверями — проверяется `wc -l` в блоке волны); (5) обратная проба: одна из позиций
  возвращена на дерево → страж красный и держатель `lower_test` красный; (6) C до и после совпадает на всём корпусе:
  `novac emit` каждого файла `examples/` и `novac/fixtures/` до волны и после — `diff` пуст, число файлов и результат
  записываются в блок волны числом (скрипт волны; приёмка машинная, не глазами).
- **M2 — операторы и блоки (3–4 дня).** `if`/`while`/`for`/`match` как терминаторы и блоки, биндинги как локалы,
  присваивания как `Assign`; `emit_stmt` печатает блоки IR. Доказательства те же (дифференциал без сдвига,
  держатели, страж одной двери, дифф C пуст), плюс `novac/src/emit_c/emit_c.nv` уходит целиком в
  `novac/src/emit_c/emit_ir.nv` (печать IR) и `novac/src/emit_c/emit_decls.nv` (типы — они не понижаются).
- **M3 — эмиттер читает только IR (5+ дней, с охотами).** Временные рёбра `emit_c → tree/lex/names/sem` снимаются
  из таблицы §3 (условие конца исполнено), `emit_expr.nv` исчезает как модуль дерева; вторая цель эмиттера (план
  274 §12, libFirm/нативный) становится возможной по построению — IR один, печатей две. Охота `lower × К4`
  (второе вычисление решённого) и `emit_c × К3` до закрытия.

## 3. Приёмка каждой волны — форма §3 плана 274 целиком

Носитель байт-в-байт (корпус и фикстуры БЕЗ новых: MIR не добавляет форм языка, он их переносит), обратная проба
по двери, держатели, дифференциал, база корпуса не двигается (движение = регресс), плюс два новых
доказательства, характерные для переноса: (а) **C до и после совпадает** на всём корпусе, где эмиттер трогался —
`novac emit` до волны и после дают одинаковый файл (страж `check-novac-emission-size` держит объём; на M1 нужен
точный дифф C, не только объём — это снимается скриптом волны и записывается числом в блок); (б) **счётчик дверей**
понижения падает и держится храповиком.

## 4. Не делаем (границы)

Оптимизации над IR; эффекты и `consume` как семантика (только слоты); смена C-ABI и формы эмиссии (274 §7.0 разрешает
расходиться, но НЕ в волне переноса — сначала перенос без сдвига, потом улучшения отдельными волнами с
`novac-divergences.md`); LSP над IR; сериализация IR в файл.

## 5. Открытые вопросы (адресат · умолчание · срок)

- **Владельцу · гранулярность:** IR на функцию (как rustc `Body`) или на модуль сразу? Умолчание — на функцию (mono
  уже даёт инстансы функциями); срок — M0.
- **Владельцу · имя `syntax` в таблице §3:** строки 142–143 `novac-architecture.md` пишут ребро `lower → syntax`, а
  модуля `syntax` в дереве нет — есть `tree`, `parse`, `lex`. Умолчание — читать как `tree` (пониженная форма строится
  по дереву и каналу) и поправить таблицу на M0 с хроникой; срок — M0.
- **Номер подплана:** 274.8 выбран окном по прецеденту 274.5–274.7 (подпланы наследуют номер родителя, `/novac-recheck`:
  «подплан наследует номер (`NNN.N`)»); номер ВЕРХНЕГО уровня даёт интегратор — здесь его нет.
- **Владельцу · параллельность с 274.7:** одно окно ведёт и MIR (M1–M3), и ярус 0 самосборки (W6, многофайловая
  единица)? Умолчание — да, чередуя волнами и не смешивая коммиты; второе окно на одно из направлений ускорило бы
  вдвое. Срок — до M1.
- **Интегратору · номер строки реестра** под класс «шесть дверей позиции значения» как измеримый долг (носители
  №974, W4-находки) — или закрыть его самим M1 без строки; умолчание — без строки, M1 ссылается на этот подплан.
