## 1. Что такое MIR здесь — и чего он НЕ есть

**Есть:** форма, в которой лежат УЖЕ ПРИНЯТЫЕ решения чекера, пригодная для одного понижения в C. Скелет —
rustc MIR (274 §Э4, референсы): функция = локалы + базовые блоки; блок = операторы + терминатор; оператор —
`Assign(local, rvalue)`; терминатор — `Goto`, `SwitchInt`/`SwitchTag`, `Return`, `Call{…, target}`; rvalue — то, что
сегодня печатает `emit_expr` (использование локала, литерал, бинарная/унарная операция, вызов, конструктор записи/
кортежа/варианта, поле, индекс, каст, интерполяция как последовательность вызовов строителя). Типы — `TyId`
интернера (уже есть); подстановка — `subst_type` (уже одна дверь); mono — уже отдельный проход (`novac/src/mono/mono.nv`).
**IR полиморфный, на объявление, строится один раз** (rustc: `Body` строится по `DefId`, инстансы — пара `(DefId,
Substs)`, подстановка применяется при кодогене и при сборе моно-элементов, который ходит по MIR корней). Так требует
и таблица рёбер: строка 141 `mono → tree` помечена «коллектор ходит по ДЕРЕВУ, пока пониженной формы нет» — с приходом
`lower` коллектор инстансов читает IR, а эмиттер печатает IR инстанса, применяя `subst_type` к `TyId` при печати.
Первая редакция этого абзаца (2026-09-06, до перепроверки) писала «IR строится ПОСЛЕ подстановки, инстанс за
инстансом» — это расходилось и с донором, и со строкой 141; поправлено вопросом владельца того же дня «кто и по каким
случаям ходит в MIR».

**Не есть (границы этого подплана):** не оптимизатор (ни одного прохода над IR, кроме понижения); не новая
семантика (эффекты, `consume`, дропы — СЛОТЫ в терминаторе `Call` и в `Assign` заводятся с самого начала, но
заполняются волнами Э2-б3/Э4 позже, и это записано полями с `/// пусто до …`); не замена чекера (чекер решает,
`lower` читает канал и НИЧЕГО не выводит — тот же принцип, что у эмиттера сегодня, П13.5); не смена ABI (C тот же —
дифференциал обязан не сдвинуться ни на файл).

**Имя модуля** — `lower`: так его называет таблица рёбер §3 `docs/dev/novac-architecture.md` (строка 75: «`lower` —
понижение в бэкенд-агностик форму; **место будущего MIR**»; строка 142: `lower` → `syntax`, `sem`, `diag`; строка 143:
`emit_c` → `lower`, `mono` — «**только** пониженная форма… рёбер-импортов к `syntax`/`tree`/`check`/`names`/`types`
НЕТ»), и временные рёбра `until:E4` (строки 130, 141, 145–147) названы под него. Слово «MIR» — в документах и
разговоре; в коде — `ir` для типов формы и `lower` для прохода, чтобы не заводить третье имя.

  как блоки со структурными терминаторами, `seal` по-настоящему; `emit_callable` строит `Fn` целиком и печатает
  запечатанные блоки одним обходом — `emit_stmt` исчезает как диспетчер дерева (конструкция и срезы — §2а, там же
  находка, разделившая M2b на два среза). **M2c — имена временных по
  индексу** (`_novac_l${i}` вместо `_novac_if_t${u}`/`_novac_match_t${u}`/`_novac_tmp_t${u}`): C меняется
  ТОЛЬКО в именах временных — критерий: дифф C пуст после нормализации `_novac_[a-z_]+_t[0-9]+` → `T` обеими
  сторонами (скрипт волны, число файлов в блок), дифференциал без сдвига. Доказательства всех срезов те же
  (дифференциал, держатели, страж одной двери — база вниз, дифф C пуст или нормализованно пуст), плюс
  `novac/src/emit_c/emit_c.nv` уходит целиком в `novac/src/emit_c/emit_ir.nv` (печать IR) и
  `novac/src/emit_c/emit_decls.nv` (типы — они не понижаются). Фикстура из M1 («конструктор в хвосте ветви if»
  и «в арме match») в M2a НЕ заведена — замер 2026-09-06: `check` Карины отказывает по правилу подмножества
  «record constructor only as a binding initializer or a call argument» (честный отказ, ярус 2 плана 274.7);
  унификация M1 там спит, пока волна 274.7 не впустит форму, — фикстура едет с той волной. Тем же зондом найден
  ложный отказ парсера: поля записи через запятую в одну строку (`type Pt { x int, y int }`, форма законна и живёт в
  std) — «this is not a form of the language»; строка реестра (К2, novac) заводится отдельно, здесь не чинится.
- **M3 — эмиттер читает только IR (5+ дней, с охотами).** Временные рёбра `emit_c → tree/lex/names/sem` снимаются
  из таблицы §3 (условие конца исполнено), `emit_expr.nv` исчезает как модуль дерева; вторая цель эмиттера (план
  274 §12, libFirm/нативный) становится возможной по построению — IR один, печатей две. Охота `lower × К4`
  (второе вычисление решённого) и `emit_c × К3` до закрытия.

## 2а. M2b — конструкция, записанная до кода (2026-09-06, чтением emit_c.nv)

**Что переносится (счёт по `novac/src/emit_c/emit_c.nv:541–645`, `emit_stmt`).** Диспетчер дерева знает 11 видов
оператора; из них `Call`, `AssignStmt` и выражение-оператор уже идут через IR (M2a), `RetStmt` — через `place`
(M1). Остаются ветвления и циклы: `IfStmt` (с цепочкой `else if`), `WhileStmt`, `ForStmt` двух форм (диапазон —
здесь же, коллекция — `emit_for.nv`), `IfLet` (`emit_iflet.nv`), `MatchExpr` в позиции оператора
(`emit_match.nv`) — плюс три ЗНАЧЕНИЯ с собственным потоком: `emit_if_value`, `emit_match`, `emit_coalesce`.
C-печать в `emit_c.nv` сегодня — 56 вызовов `@body.append`, из них 14 в `emit_stmt`; после M2b в `emit_stmt`
их 0 (критерий ниже). `break`/`continue` в дереве Карины НЕТ (`grep -i break novac/src/tree/tree.nv` — только
слово «invariant break» в доках), так что `Loop.exit` до появления этих форм читает один принтер, а обратное
ребро тело → заголовок структурно и не записывается.

**Форма терминаторов** (донор — структурный поток WebAssembly: `if`/`block`/`loop` с явным выходом; скелет
rustc: блок = операторы + ровно один терминатор):

```
Terminator enum | Return | Goto(BlockId) | If(IfTerm) | Loop(LoopTerm) | Switch(SwitchTerm) | Unreached
IfTerm value     { cond Node, then BlockId, els BlockId, join BlockId }   -- если else нет: els == join
LoopTerm value   { head LoopHead, body BlockId, exit BlockId }
LoopHead enum    | While(Node) | Range(v str, lo Node, hi Node) | Each(...)  -- заголовок несёт форму
SwitchTerm value { scrutinee Local, arms []SwitchArm, join BlockId }       -- match: образец + блок арма
```

Цепочка `else if` — блок `els` без операторов, чей терминатор снова `If` с ТЕМ ЖЕ `join`; принтер печатает такой
блок словом `else if`, как `emit_stmt` печатает его сегодня рекурсией. Заголовок цикла несёт форму, потому что
C-принтер спеллит `while (c)` и `for (nova_int v = lo; v < hi; v++)` разными словами, а критерий волны —
побайтовый C; коллекционный `for` (`emit_for_call`, временные `len`/`get`) переезжает своим срезом.
`emit_block_stmts_fn(b, tail)` и `emit_block_value(b, t)` — две двери одного действия «операторы блока по
порядку, хвост — в место» — становятся одним `lower_block(b, dest Option[Local])`.

**Находка, разделившая M2b на два среза.** Печать сегодня ПОТОКОВАЯ: `lower_place` = запись + немедленная печать
(`emit_last_stmt`), и печать выражения (`emit_expr`) сама ПОНИЖАЕТ вложенные позиции значения: `emit_coalesce`
создаёт локалы (`@ir.named`/`@ir.temp`) и зовёт `lower_place` ВО ВРЕМЯ печати, то же if-значение и
match-значение внутри выражения. «Построить `Fn` целиком, потом напечатать» поэтому не делается одним шагом:
(а) временные вложенных позиций получают номера (`fresh_uniq`) в момент печати, и отложенная печать сдвинула бы
нумерацию — C изменился бы в именах, что критерий M2c, не M2b; (б) вложенная позиция внутри выражения требует
ссылки из дерева на локал (`Operand.Place` внутри выражения) — это понижение ВЫРАЖЕНИЙ, то есть начало M3.

печать пропадает совсем, поэтому промежуточное состояние НЕ проверяется корпусом,

записан выше, — нормализованные имена, а не байт-в-байт, потому что разделение
сдвигает ПОРЯДОК инкрементов `@fresh_uniq`, а не смысл.

**ОБЛАСТЬ M2c ИЗМЕРЕНА ДО ЕЁ КОДА: «по индексу» умеют не все временные (2026-09-08).**

M2c обещает имена временных по индексу (`_novac_l${i}`). Индекс у временной берётся из её
`Local` — то есть переименовать можно ТОЛЬКО то, у чего локаль есть. Замер грепом по телам:

| печатник | обращений к `@ir.temp`/`@ir.named` | что это значит для M2c |
|---|---|---|
| `@emit_coalesce` | 2 | локали есть — имя по индексу возможно |
| `@emit_array_lit` | 0 | локали НЕТ: имя `_novac_tmp_t${u}` живёт только в C |
| `@emit_record_ctor` | 0 | то же |
| `@emit_interp_build` | 0 | то же |

Все три «нулевых» ВОЗВРАЩАЮТ имя строкой, и печатник выражения подставляет её через
`@lit_tmp[id]`. У такой временной нет ни локали, ни индекса — значит **M2c переименовывает
не «все временные», а те, что суть локали**; остальные ждут M3, где выражения понижаются и
локаль появляется. Записано областью, а не обнаружено на середине волны: обещание «все
временные» звучало бы выполненным, пока кто-нибудь не грепнет `_novac_tmp_t` в выпущенном C.

**Читателей ИМЕНИ локали в эмиттере девять**, и все в двух файлах: `emit_flow.nv` (голова
цикла — переменная, индекс, коллекция) и `emit_place.nv` (объявление, чтение payload,
элемента, поля варианта, операнда и две ветви головы присваивания). Их правка и ЕСТЬ M2c.
Прочие `.name` в эмиттере локалям не принадлежат: `emit_decls.nv` читает имя ПОЛЯ варианта,
`emit_expr.nv` — имя строки арифметики; их M2c не касается, и это сказано, чтобы никто не
включил их «для полноты».

**КРИТЕРИЙ M2c БЫЛ НЕДОСТИЖИМ КАК ЗАПИСАН, И ЭТО ВТОРОЙ ТАКОЙ ЗА ДВА ДНЯ (найдено 2026-09-08, до кода M2c).**

Две фразы плана про M2c противоречат друг другу. Первая: имена временных становятся
`_novac_l${i}` по индексу. Вторая: «дифф C пуст после нормализации `_novac_[a-z_]+_t[0-9]+`
-> `T`». Шаблон требует `_t` перед цифрами — а новая схема его НЕ ИМЕЕТ. Проверено
регуляркой, а не чтением: семь нынешних префиксов (`if`, `match`, `tmp`, `qq`, `i`,
`matched`, `scr`) нормализуются, а `_novac_l0`, `_novac_l7`, `_novac_l42` — нет. То есть
сторона «до» дала бы `T`, сторона «после» — `_novac_l7`, и дифф не был бы пуст НИКОГДА:
критерий нельзя было выполнить ни правильной работой, ни неправильной.

**ИСПРАВЛЕННЫЙ ШАБЛОН:** `\b_novac_(?:[a-z_]+_t|l)[0-9]+\b`. Проверен обеими сторонами:
нормализует и `_novac_if_t3`, и `_novac_l7`; НЕ трогает `_novac_local`, `_novac_lit_pool`,
`_novac_l` без числа, `_novac_l7x`, `x_novac_if_t3`. Границы слова добавлены не для красоты —
без них `some_novac_l7x` совпадал подстрокой. Цикл приёмки волны исправлен тем же заходом.

**ВТОРОЙ ТАКОЙ КРИТЕРИЙ ЗА ДВА ДНЯ, и общее у них важнее каждого.** Первым был Ф.2(в) плана
284 («контрактные подпапки — FAIL: 0»), недостижимый с 2026-07-19 из-за чужой красноты под
`continue-on-error`. Оба писались ДО того, как кто-нибудь попробовал их выполнить, и ни один
не был проверен НА ВЫПОЛНИМОСТЬ — только на разумность. Отсюда правило, которое стоит
дороже обеих поправок: **критерий проверяется на выполнимость в момент записи** — прогоном,
если он дешёвый, или хотя бы регуляркой на бумаге, как здесь. Критерий, который нельзя
выполнить, хуже отсутствующего: он выглядит машинным и потому не вызывает подозрений.

**ДВА ПРЕДУСЛОВИЯ ШАГА (3б): ПОЛЕЙ НЕ ХВАТАЕТ, И НАЙДЕНО ЭТО КРИТЕРИЕМ, А НЕ ПРОБОЙ (2026-09-08).**

Критерий дали конвенции: «Если кодогену приходится РЕШАТЬ — это дефект: в канале не хватает
поля» (архитектура, 301-314). Применён к формам терминаторов, прочитанным дословно, ДО кода
обхода — и сразу дал два места, где обход был бы вынужден решать сам.

- **`IfTerm` не несёт, продолжает ли ветвление строку `} else `.** Форма сегодня —
  `{ cond, then, els, join }`. Обходу, чтобы напечатать голову без отступа (одна форма
  `else`, микросрез M2b-2-0), пришлось бы выяснять, не является ли блок теста этого `if`
  блоком `els` объемлющего, — то есть РЕШАТЬ по структуре графа. Лоуэринг это знает
  ТОЧНО: у него для этого отдельная дверь `begin_chained_if`, отличная от `begin_if`.
  Значит нужно поле (`chained bool`). **ПОПРАВКА ТОГО ЖЕ ДНЯ, ДО КОДА: ДВЕРИ ДЕЛЯТ ОДНУ ТОЧКУ СБОРКИ,
  поэтому «ставит его дверь» неверно.** `begin_if(cond, has_else)` состоит из двух строк:
  резервирует `join` и ЗОВЁТ `begin_chained_if(cond, has_else, join)` — терминатор `If`
  собирается ровно в одном месте (`ir.nv:466`), и внутри него по входной двери plain от
  chained не отличить. Значит `chained` протаскивается ПАРАМЕТРОМ общей внутренней функции,
  а публичных дверей остаётся две, каждая со своим значением. Записано до кода не ради
  точности формулировки: по прежней записи флаг вышел бы одинаковым у обеих форм, C
  разошёлся бы на отступе головы, и разбор стоил бы часа.
- **ВТОРАЯ ПОПРАВКА, И ОНА ОТМЕНЯЕТ ПОЛЕ `chained` (2026-09-08, после ошибки формы 1).** Поле «открыт как цепочка»
  обходу НЕ помогает, и это показала правка формы 1: цепочечный `if` и цепочечный `if let`
  открываются ОДНОЙ дверью `begin_chained_if`, то есть у обоих флаг был бы `true`, — а
  печатаются они РАЗНО (первый продолжает строку `} else `, второй стоит в скобках). Настоящий
  признак прочитан в `lower_else_tail`: печатает ли хвост СКОБКИ. Хвост-блок — да; хвост
  `if` — нет; хвост `if let` — да, потому что в C не бывает `else <объявление>`. Значит
  обходу нужен ОДИН бит на ВНЕШНЕМ `IfTerm` — **обёрнута ли ветвь `else` в скобки**, — и он
  известен в месте вызова: `lower_if` держит хвост как `kids[4]` и знает его вид ДО открытия
  ветвления, так что бит передаётся параметром `begin_if`/`begin_chained_if`, а не выводится
  внутри. Поле `chained` из предусловия СНИМАЕТСЯ: оно записывало факт, по которому нельзя
  печатать. Записано поправкой, а не переписано молча, потому что прежнее поле стояло в плане
  как решение, и следующее окно взяло бы его — а неверное решение в плане дороже
  отсутствующего.
- **`SwitchTerm` не несёт `uniq`.** Форма сегодня — `{ scrutinee, arms, join }`, а печать
  арма спеллит `_novac_matched_t${uniq}`, и голова печатает `_novac_scr_t${uniq}` внутри
  теста. Восстановить `uniq` обход может только РАЗБОРОМ ИМЕНИ локали-скрутинии — строковым
  парсингом того, что лоуэринг сложил из числа. Это худший вид «решить второй раз»: имя
  является данными для того, кто его составил, и загадкой для того, кто читает. Значит нужно
  поле (`uniq int`), и ставит его `begin_switch` — здесь оговорки нет: у него одна дверь и
  один вызывающий (`lower_match`), у которого `uniq` уже в руках.
- **ТРЕТЬЯ ДВЕРЬ, КОТОРУЮ ЭМИТТЕР ОТКРЫВАЕТ РУКАМИ (найдено 2026-09-08 сухой сверкой якорей перед
  применением предусловия).** Дверей, открывающих ветвление, ТРИ, а не две:
  `begin_if`, `begin_chained_if` и **`begin_else_if(outer, cond, has_else)`** (`ir.nv:484`),
  которая делает ровно `@begin_else(outer)` + `@begin_chained_if(cond, has_else, outer.join)`.
  **Эмиттер её НЕ ЗОВЁТ:** `lower_if` и `lower_if_let` открывают эту пару вручную, каждый у
  себя. Зовёт её только тест строителя — то есть дверь есть, а продукт идёт мимо.
  Это класс №991 в чистом виде: одно понятие, две реализации, и та, что мимо двери, не
  последует за правкой двери. Нашлось не чтением кода волны, а сухой сверкой якорей: тест
  вызвал функцию, которой я в строителе не знал.
  **Что с этим делает предусловие:** `lower_if` и `lower_if_let` переходят на `begin_else_if`,
  и тогда бит `els_braced` протаскивается через три двери, а рукописных пар не остаётся.
  Порядок событий при этом не меняется — дверь делает те же два вызова в том же порядке, что
  и рукописная пара, и это проверяется тем же критерием: C байт-в-байт.
- **`LoopTerm { head, body, exit }` самодостаточен** — `LoopHead` несёт и условие, и все
  локали трёх видов цикла. Поля не нужны, и это сказано, чтобы никто не добавил их «для
  симметрии».

**Порядок:** оба поля заводятся ДО кода обхода, отдельным шагом (3а-поля), с тем же
критерием — C байт-в-байт: поле, которое никто ещё не читает, печать не меняет. Тогда (3б)
остаётся чистой переменой МОМЕНТА печати, без единого решения в принтере.

**Почему это записано как находка, а не сделано молча:** оба поля — правка формы IR, то есть
радиус шире волны (их читают тесты строителя и будущие анализы). Названы здесь до кода,
чтобы решение о форме принималось на бумаге, а не в момент, когда обход уже написан и
проще «вычислить на месте».

**ЧТО СВЯЗЫВАЕТ ОБХОД (3б) ПО КОНВЕНЦИЯМ (прочитано 2026-09-08, факты сверены вызывающим).**

Читал агент по форме `/delegate`; каждый факт о дереве проверен здесь запуском или чтением —
выдача агента сырьё, а не основание. Пять пунктов связывают (3б):

- **Ребро законно, и это снимает главный риск замысла.** Таблица рёбер §3
  `docs/dev/novac-architecture.md`: `emit_c | lower, mono | **только** пониженная форма
  (несёт ДАННЫМИ интернированный канон типов И `DeclId`-пути…)`. Значит обход вправе читать
  `Fn`/`Block`/`Terminator`/`Stmt` как ДАННЫЕ. Отдельно строки 163-165: «`emit_c` (и будущий
  `backend_native`) не импортируют ничего выше `lower`» — держит `check-novac-deps.py`.
- **Match по терминаторам и по операторам — ИСЧЕРПЫВАЮЩИЙ, без `_`.** П21 п.3 конвенции
  novac: «диспетчер, обязанный РЕШИТЬ за каждый вариант — исчерпывающий, `_` запрещён»;
  «молчаливый `_` остаётся красным». Держит `check-novac-no-default-branch.py`. Для обхода
  это значит: ветка на КАЖДЫЙ вид терминатора, `Unreached` — явный `ice`, а не молчание.
- **Обход не выводит заново то, что решил лоуэринг.** Архитектура, строки 301-304 и 310-314:
  «Кодоген ПЕРЕВОДИТ уже принятые решения… Если кодогену приходится РЕШАТЬ — это дефект: в
  канале не хватает поля». Практический критерий для (3б): если обходу для печати чего-то не
  хватает, правильный ответ — ПОЛЕ в `Terminator`/`LocalDecl` (как `zero_init` в шаге 2), а не
  вычисление в принтере.
- **Счётчик инвариантов на раздел — часть приёмки** (274.1 §2б п.2; держит
  `check-novac-arch-invariants.py`). Значит (3б) обязана назвать и посчитать инварианты
  своего раздела, а не только показать зелёный дифф.
- **Потолок 1000 строк на файл, без базлайна и без исключений** (решение 12 плана 274, страж
  `check-novac-file-size.py`). Запас замерен 2026-09-08: `emit_c.nv` 811 строк (запас 189),
  `lower/ir.nv` 621, `emit_flow.nv` 228, `emit_match.nv` 247, `emit_place.nv` 261 — обход
  уместится, но если раздует `emit_c.nv` выше 1000, названный выход ОДИН: новый со-равный
  файл в `emit_c/` (план упоминает `emit_c/emit_ir.nv` как цель M2c/M3), а не исключение.

**Чего в конвенциях НЕТ:** правила, в какой ИМЕННО файл обязан лечь обход. Есть только
потолок размера и «папка = один модуль»; размещение решает план волны. Записано, чтобы
следующее окно не искало правила, которого нет.

**Противоречий не найдено.** Единственное похожее место разрешает себя дословно: строка 134
держит `emit_c -> tree, lex, diag, sem, builtins` как «временное until:E4» и сама говорит,
что при Э4 весь ряд снимается, а целевая строка 147 это уже запрещает — одна таблица,
называющая переходный период, а не спор двух документов.

**ШАГ (3) РАСЩЕПЛЁН НА ДВЕ ПОЛОВИНЫ, И ОДНА ИДЕЯ ПО ДОРОГЕ ОПРОВЕРГНУТА (2026-09-08).**

Шаг (3) — единственный в волне без зелёной промежуточной точки: как только печать уйдёт из
лоуэринга, C исчезает до готового обхода, и «обход неверен» становится неотличимо от «обход
недописан». Это не приемлемо на семи местах сразу, поэтому шаг расщеплён.

**ОПРОВЕРГНУТАЯ ИДЕЯ, записана чтобы следующее окно её не строило.** Замысел: обход печатает
в ТЕНЕВОЙ буфер, на `finish` его вывод сверяется с выводом интерливинга, и старая печать
снимается только после доказанного равенства. `StringBuilder` это позволяет (`@byte_len()`
меткой, `@truncate(mark)` откатом, `@to_str()[mark..]` срезом). **Не работает, и причина
измерена, а не выведена:** печать значения НЕ ИДЕМПОТЕНТНА — `build_value` (emit_place.nv)
делает `@fresh_uniq()`, `@ir.temp(...)` и зовёт `lower_match`. Второй проход напечатал бы
другие имена временных И записал бы в IR заново, мутируя граф, по которому идёт. Сверять
два прохода можно только там, где печать чиста.

**ЗАМЕР, УТОЧНИВШИЙ ГРАНИЦУ:** `emit_expr` ЧИСТ — ноль обращений к `@ir` и к `fresh_uniq` во
всём файле. Запутаны печать и лоуэринг ровно в ОДНОМ месте — в диспетчере форм значения,
то есть в том самом, что переносит волна. Это делает расщепление ниже не приёмом, а следствием.

- **(3а) ПЕЧАТЬ ЧИТАЕТ IR, А НЕ ДЕРЕВО — по одной форме, C байт-в-байт после каждой.**
  Печать остаётся на месте по времени (тот же момент, тот же порядок), но берёт данные из
  терминатора и операторов, а не из узлов. Форма за формой: `if`-оператор (носителей по дельте
  6), `while`, `for`-диапазон, `for`-коллекция (3), `if let` (39), `match` (11 значение + 12
  флаг), `??` (3). Критерий каждой — C корпуса идентичен (94 эмитируемых), плюс обратная проба
  ИМЕННО по этой форме с ОЖИДАЕМЫМ числом файлов из карты выше: «покраснело» без числа
  неотличимо от «покраснело не там».
- **(3б) ПЕРЕХОД НА ОБХОД по закрытым блокам.** Меняется только КОГДА печатается, потому что
  ЧТО уже читается из IR. Здесь и только здесь допустим сдвиг имён временных: порядок
  инкрементов `@fresh_uniq` меняется, смысл — нет; критерий — дифф после нормализации
  `_novac_[a-z_]+_t[0-9]+` -> `T`. Семь вызовов `@emit_last_stmt()` уходят здесь, не раньше.

**Что это стоит:** (3а) длиннее одного шага и не даёт ни одной строки нового C — она
переставляет источник данных печати. Плата за то, что каждая её форма доказуема отдельно и
откатывается отдельно; без неё вся волна доказывается одним диффом в конце, а он скажет
«разошлось» и не скажет, на какой из семи форм.

**КАРТА НОСИТЕЛЕЙ ДЛЯ ОБРАТНЫХ ПРОБ ШАГА (3) (2026-09-08, замером).**

Обратная проба, покрасневшая на НУЛЕ файлов, не доказывает ничего — замер волны M2b-1а: греп
по исходникам дал 19 носителей `else`, а среди эмитируемых не было ни одного. Поэтому носители
считаются ДО шага (3), и вот чем.

- **ЗНАМЕНАТЕЛЬ — 94, А НЕ 150.** `emit_corpus.sh` создаёт выходной файл ДО запуска novac,
  поэтому `.c` в снимке столько же, сколько файлов корпуса. Настоящую эмиссию несут **94**; в
  остальных 56 лежит JSON-диагностика отказа, одинаковая во всех снимках. Замаскировать правку
  она не может, но приписывает волне корпус, которого у неё нет. Вердикты шагов (0), (1) и (2)
  доказаны на 94 файлах — в их сообщениях стоит «из 150», и это ЗАВЫШЕНИЕ знаменателя, а не
  ошибка вердикта; цикл приёмки исправлен и печатает оба числа.
- **СЧИТАТЬ НАДО ВЫХОД, А НЕ СИНТАКСИС ИСХОДНИКА.** Инвентарь по исходникам дал `match`-значению
  ОДИН скомпилированный носитель (искалось `= match`), но эмиттер различает позиции приёмником:
  `match` в хвосте функции с не-unit возвратом идёт тем же путём. По выходу их **11** — временная

- **НО СТРУКТУРНЫЕ ПРИЗНАКИ В ВЫХОДЕ СЧИТАТЬ НЕЛЬЗЯ.** К каждому файлу приклеена оболочка
  `shell.tpl.c` со своим C: `examples/basics/hello.nv` (7 строк исходника) даёт 328 КБ, где 134
  `} else {`, 15 `while (` и 10 `for (nova_int` принадлежат ОБОЛОЧКЕ. Годятся только имена,
  которые генерирует сам novac (`_novac_*`): в выводе `hello` их ноль, в шаблоне оболочки —
  ноль. Для формы без собственного имени в C единственный честный счёт — САМА ОБРАТНАЯ ПРОБА:
  сломать печать и посчитать РАЗОШЕДШИЕСЯ файлы; дельта не зависит от того, что ещё в файле.

**Носители по имени (из 94 эмитируемых):** `match`-значение 11 · if-значение 5 · `??` 3 ·
if-let/головная временная 39 · индекс for-each 3 · флаг первого совпадения 12.
**Носители по дельте (замерены пробами этой волны):** форма `else` — 6 файлов (микросрез 0),
объявление результатной временной — 17 файлов и 28 строк (шаг 2).
**ТОНКИЕ КАНАЛЫ, названные заранее:** `??` и for-each — по 3 файла; `else if` — ОДИН
(`novac/fixtures/control_flow/pos_1.nv`). Проба по ним обязана называть ожидаемое число файлов,
иначе «покраснело» неотличимо от «покраснело не там».
**ФОРМА БЕЗ НОСИТЕЛЯ ВООБЩЕ:** голый `return` (без значения) — ноль во всём корпусе, включая
отказавшиеся файлы. Обратной пробой она недоказуема; если шаг (3) её трогает, нужна фикстура
`novac/fixtures/<форма>/pos_1.nv`, и это названо здесь, а не обнаружено в конце волны.

**РЕШЕНИЯ M2b-2, ЗАПИСАННЫЕ ДО КОДА (2026-09-08, чтением принтера).**

- **Что судит что, чтобы критерий не перепутать с чужим.** `check-novac-differential.sh` судит
  ПОВЕДЕНИЕ (исход `check`, stdout и код возврата смоука), не текст C. Байтовый критерий волны
  («C совпадает после нормализации имён») — её собственный, и держит его C-дифф корпуса волны,
  а не гейт; значит форма C — решение волны, и оно записывается здесь.
- **(0) Микросрез M2b-2-0 — ОДНА форма `else`, до волны.** Сегодня novac печатает `else` двумя
  формами: оператор-`if` — `    }` и `    else {` двумя строками (`emit_flow.nv:76`),
  if-значение и `??` — `    } else {` одной (`emit_c.nv:477, 507`). Оракул печатает `} else {`
  41 753 раза, а `else {` отдельной строкой — НОЛЬ (посчитано по записанному C
  `spec_tests/conformance/standalone/*.c`, 2026-09-08): двуформие — собственное novac, не
  интероп. Единому обходу две формы стоили бы флага в `IfTerm` «как печатать else» — то есть
  инварианта на честном слове (нормa `conventions-governance`, счётчик 274.1 §2б). Одна форма
  снимает флаг конструкцией. Критерий микросреза — как у г0: C-дифф корпуса пуст после
  нормализации ТОЛЬКО пробелов и переносов вокруг `else`; всё прочее байт-в-байт. Оракул здесь
  не донор (П25): его число — замер того, что двуформие не интероп, а не образец.
- **(1) `@emit_coalesce` первым переходит на двери IR при НЕИЗМЕННОЙ печати.** У него в IR
  есть всё: `Cond.IsSome`, `@take_payload`, `begin_if/begin_else/end_if`, `lower_place` — он ими
  не пользуется, а печатает `if (…) {`, `res = opt.value;`, `} else {`, `}` текстом
  (`emit_c.nv:503-512`). Переход байт-идентичен, и это измерено чтением, не надеждой:
  `emit_assign_head` печатает `Temp` как `        ${name} = ` (отступ 8, `emit_place.nv`), ровно
  как коалесценция печатает `        ${res} = ${opt}.value;` сегодня. `@emit_if_value` IR уже
  строит (`temp`, `begin_if`, `begin_else`, `end_if`) — у него уходит только печать.
- **(2) Точка объявления временного — `Stmt.Decl(Local)`.** В IR у локали нет позиции, а
  `T _novac_if_tN = (T){0};` должно стоять ПЕРЕД `if (`. Объявление становится оператором
  блока, записываемым в момент `temp()`; печатается `T name;` либо `T name = (T){0};` по
  `zero_init` (решение интегратора 2026-09-07). Донор: rustc MIR `StorageLive` — начало жизни
  локали как оператор тела, не как свойство таблицы локалей. Биндинги объявляются как сегодня —
  первым присваиванием (`T name = …`), `Decl` для них не пишется.
- **(3) `lit_tmp []str` ОСТАЁТСЯ.** Восемь мест чтения в `emit_expr.nv` подставляют ИМЯ
  поднятого временного; `Operand.Place` в дереве выражения — работа M3 (понижение выражений), и
  делать её «заодно» значило бы сдвинуть два среза в один дифф. Названо followup'ом.
- **Порядок волны (уточнён):** (0) микросрез `else` → C-дифф после нормализации пробелов пуст;
  (1) коалесценция на дверях IR → C байт-в-байт; (2) `Stmt.Decl` + `zero_init` с докстрокой,
  называющей ОБА клиента (`match`, if-значение) и причину (274.3/Ф29); (3) снятие семи
  `@emit_last_stmt()` и всех печатей структуры, `emit_callable` печатает `Fn` одним обходом →
  C совпадает после нормализации имён (`_novac_[a-z_]+_t[0-9]+` → `T`). Проба обеих сторон у
  (2): у двух форм `= (T){0}` остаётся, у прочих временных C байт-идентичен прежнему — иначе
  «занулять всё» и «занулять по полю» зелены одинаково.

**ПЕРЕПИСЬ МЕСТ ПЕЧАТИ И ОБЪЯВЛЕНИЕ РЕЗУЛЬТАТНЫХ ВРЕМЕННЫХ (2026-09-07).**

- **Перепись собрана грепом, не агентом** (`grep -n '@body\.append'` по пяти файлам
  `emit_c/`): **104 места печати** — emit_flow 20, emit_match 15, emit_place 24, emit_c 42,
  emit_destructure 3. Строк ровно столько же, сколько вхождений — проверено отдельно, потому
  что `grep -c` считает СТРОКИ. Разбор `emit_c.nv` по объемлющей функции (`awk`):
  `@emit_signature` 12, `@emit_callable` 4, `@emit_instance_protos` 1 — **вне тела** (17);
  `@emit_if_value` 8 и `@emit_coalesce` 5 — те самые позиции значения, которые волна понижает
  до печати (13); `@emit_record_ctor` 9 и `@emit_array_lit` 3 — операторы, уезжают дверью
  оператора (12). Число нужно волне как ПРЕДМЕТ: обход обязан воспроизвести ровно эти места, и
  «столько же строк C» — первая дешёвая проверка перед дифференциалом.
- **Результатные временные объявляются С ЗАНУЛЕНИЕМ, а `LocalDecl` про это не знает.**
  `LocalDecl` (`lower/ir.nv:52`) несёт ровно `ty`, `kind`, `name`. При этом сегодня и `match`
  (`emit_match.nv:57`), и `if`-выражение (`emit_c.nv:462-466`) печатают `T _novac_X_tN =
  (T){0};` — причина в коде названа (274.3/Ф29): `match` на `int` вправе не покрыть все
  значения, оракул отвечает там нулём, а неинициализированный временный отвечал содержимым
  стека. Обход печатает объявления из `Fn.locals`, где зануления НЕ ЗАПИСАНО.
- **РЕШЕНО (интегратор, 2026-09-07): `LocalDecl` получает поле `zero_init`, ставит его
  ЛОУЭРИНГ.** Довод архитектурный, а не вкусовой: зануление знает ПРИЧИНУ, и причину видит
  тот, кто видит форму. Принтер её не знает и узнать может лишь выведя заново — то есть
  «решить второй раз в другом месте», ровно то, против чего в оракуле заведён канал 196:
  решает знающий, потребитель ЧИТАЕТ. Вариант «занулять каждый `Temp`» отпадает замером:
  критерий волны разрешает нормализацию ИМЁН, а не инициализаторов, и разница существенна —
  имя не наблюдаемо в поведении, инициализатор наблюдаем. Вариант «обход выводит сам» вернул
  бы анализ потока данных в принтер через полтора шага после того, как M2b-1 §2а его оттуда
  убрал структурными терминаторами.
- **ДВА УСЛОВИЯ ПРИЁМКИ этого поля, названные вместе с решением.** (1) У поля докстрока,
  называющая ОБА нынешних клиента и причину (`match` на `int`, 274.3/Ф29): без неё через месяц
  поле поставят третьему месту «по аналогии», не зная, чему аналогия. (2) Проба показывает
  ОБЕ стороны: у этих двух форм `= (T){0}` остаётся, а C всех ПРОЧИХ временных байт-идентичен
  прежнему. Без второй половины «занулять всё» и «занулять по полю» выглядят одинаково
  зелёными — это главная ловушка развилки.
**Конструкция среза (г) — `match` как `Switch` (записано до кода, 2026-09-06, чтением `emit_match.nv`).** Сегодня
принтер спеллит `match` if-цепью с флагом: `T scr = <e>; [R res = (R){0};] int matched = 0;` и на каждый арм
`if (!matched && (<тест>)) { <биндеры>; [if (<guard>) {] <тело: res = …| оператор>; matched = 1; [}] }`. Форма
IR: `Switch { scrutinee Local, arms []SwitchArm, join BlockId }`, `SwitchArm { pat Pattern, guard Option[Node],
body BlockId }`, `Pattern = Lit(Node) | Variant(VariantRow, []VariantRow /*дизъюнкция*/) | Bind | Wild`. Флаг
`matched` — артефакт ПЕЧАТИ (эмуляция первого совпадения if-цепью), в IR его нет: семантика «первый подошедший арм»
принадлежит `Switch` по построению, и принтер печатает флаг сам. Биндеры — операторы в начале блока арма:
распаковка полей варианта — `Rvalue.VariantField(VariantRead { scr Local, vrow VariantRow, i int })` (третий
rvalue не из дерева, печать `scr->payload.<V>._<i>` по A4 — `.`/`->` по размещению суммы); простой биндер —
`Rvalue.Use(Operand.Place(scr))` — первое настоящее применение `Use`, печать имени локала. Guard — `If(Expr(g))`
внутри блока арма (тогда `matched = 1` и тело — в then-блоке, else — join). Позиция значения: тело арма кладёт
значение в результат-локал через `place` (как сегодня `emit_arm_value`), позиция оператора — тело как операторы.
Три позиции сегодняшнего вызова (`build_value` для значения, `emit_stmt` и хвост блока для оператора) идут в один
`lower_match(m, dest Local)` с `no_local()` для оператора. Пробы обе стороны: тест тега испорчен → носители
`match` (43 по переписи исходников, число эмитируемых — замер среза) расходятся; `end_switch` сброшен → ice.
Цена — самый большой срез M2b-1 (образцы четырёх видов, дизъюнкции, guard, две позиции): один рабочий день.
**Находка при записи конструкции (2026-09-06):** принтер `match` печатает биндеры арма, guard и `matched = 1`
с отступом 8 пробелов, а единый принтер присваиваний спеллит биндинг с отступом 4 (`    T name = …`) — как и
все прочие строки тел в C Карины (в `if`/`while` тела тоже на 4). Значит биндеры через `emit_assign` дали бы
C, отличный ПРОБЕЛАМИ, и побайтовый критерий среза упал бы не по существу. Решение: **микросрез (г0) — только
пробелы**, до (г): отступы в `emit_match.nv` приводятся к 4, критерий — дифф корпуса пуст после снятия ведущих
пробелов (`sed 's/^ *//'` обеими сторонами), дифференциал без сдвига, C собирается (смоук фикстур). Это смена
формы эмиссии, но только в пробелах C, поведения и имён она не касается — записана здесь, а не в
`novac-divergences.md` (там расхождения с оракулом, а C Карины оракулу не равен и не обязан).
После (г0) срез (г) снова судится побайтово.
**Что это делает с вопросом §5 о структурных терминаторах.** M2b-1 — первый терминатор с ветвлением; умолчание
(структурные, с `join`/`exit`) исполняется им, и строка §5 получает отметку «исполнено по умолчанию в M2b-1» тем же
коммитом. Ответ «плоские» после этого стоит переписывания принтера (релупер), и цена названа в §5.
## 3. Приёмка каждой волны — форма §3 плана 274 целиком

Носитель байт-в-байт (корпус и фикстуры БЕЗ новых: MIR не добавляет форм языка, он их переносит), обратная проба
по двери, держатели, дифференциал, база корпуса не двигается (движение = регресс), плюс два новых
доказательства, характерные для переноса: (а) **C до и после совпадает** на всём корпусе, где эмиттер трогался —
`novac emit` до волны и после дают одинаковый файл (страж `check-novac-emission-size` держит объём; на M1 нужен
точный дифф C, не только объём — это снимается скриптом волны и записывается числом в блок); (б) **счётчик дверей**
понижения падает и держится храповиком.

**Перепись носителей по веткам принтера (обобщение находки M2b-1а, предложено интегратором 2026-09-06; до M2b-2).**
Проба «испорчено написание `else`» сдвинула 0 из 92 эмитируемых файлов — форма перенесена, носителя под
побайтовой проверкой не было; нашлось случайно. Систематический вопрос тем же приёмом: для КАЖДОЙ ветки
принтера (каждый `@body.append` с литералом C в `emit_c/*.nv`) — испортить написание, пересобрать, снять
корпус, посчитать разошедшиеся файлы; 0 = ветка без носителя. Скрипт волны гонит это по списку литералов и
выдаёт таблицу «ветка → число файлов»; ветки с нулём получают фикстуру `novac/fixtures/<форма>/pos_N.nv` до
того, как волна M2b-2/M3 их тронет. Цена: одна пересборка novac (~10 с) и одна эмиссия корпуса (~2 мин) на
ветку — на ~60 литералов около двух часов машины, гонится частями в окнах; приёмка машинная — таблица в блок
волны, нулей после фикстур нет. Носитель считается только среди ЭМИТИРУЕМЫХ (список корпуса минус
`_refused.txt` снимка), не по грепу исходников.
**Замер 2026-09-06 (агент haiku, инвентарь):** точек печати `@body.append("…")` в `emit_c/*.nv` — 208 (emit_expr 63,
emit_c 32, emit_decls 28, emit_match 25, emit_flow 20, emit_place 19, interp 9, option 5, requires 4, destructure 3);
порча литерала с пересборкой на каждую — ~7 часов машины, дорого. **Дешёвый первый проход без пересборок**
(`scratch/print_site_carriers.py`, окно 274): у каждого литерала берутся постоянные фрагменты между `${…}` (не короче
4 непробельных знаков) и ищутся в ЭМИТИРУЕМЫХ единицах снимка корпуса, из которых вырезаны строки прелюдии
`shell.tpl.c` (иначе прелюдия «покрывает» любой типовой C). Первый прогон: 71 точка с информативным фрагментом,
61 покрыта, 10 без носителя — из них 8 ложные (многострочные фрагменты, чьи строки совпадают со строками
прелюдии и вырезаются построчно: `} else {`, `typedef enum {`, `#endif`…), 1 спорная (`while (` в lower_while на
снимке до фикстуры control_flow — strings.nv эмитируется и содержит `while`, значит построчное вырезание съело и
его строку) и 1 настоящая (`return NOVA_UNIT;` голого `return` в lower_return — носителя нет и сейчас); 137 точек
— пунктуация и короткие куски, им нужна проба порчей либо группировка по функции. Уточнение метода: вырезать
прелюдию блоком, а не построчно; остаток судить порчей по ФУНКЦИЯМ (около 40), не по литералам.
**Уточнённый прогон (агент sonnet, `scratch/print_site_carriers2.py`, тот же день):** прелюдия в единице — не префикс,
а `shell.tpl.c` целиком с двухстрочной вставкой на месте маркеров `/*__NOVAC_STRLITS__*/` + `/*__NOVAC_BODY__*/`
(строки 5593–5594; 5592 строк до и 806 после байт-в-байт во всех 92/94 единицах) — вырезание блоком снимает
все ложные «нет носителя» первого прохода: на снимке ДО фикстуры control_flow непокрытых информативных точек
1 (`while (` в lower_while), на текущем — 0 из 71; голый `return` покрыт (первый проход ошибался). Остаток —
137 тривиальных точек в 31 функции, из них у 24 функций есть покрытая информативная точка; СЕМЬ функций не
судятся этим методом вовсе (только пунктуация, ни одной информативной точки): bind_pair_temp, emit_bound_args,
emit_destructure_bind, emit_instance_protos, emit_store, lower_if, lower_if_let — им проба порчей по функции,
~7 × 2,5 мин машины вместо 7 часов. **Задача переписи ЗАКРЫТА и без этих проб (2026-09-07):** у каждой из семи
есть вызывающий (агент haiku выписал докстроки и вызовы; факт сверен окном — «нет вызывающих» у
`emit_instance_protos` было ложью МОЕГО брифа: он искал только форму `@имя(`, а вызов написан
`e.emit_instance_protos(insts)`, emit_c.nv:151), и форма, которая до неё достаёт, имеет носителей среди
эмитируемых: вызов с аргументами — 88 файлов из 92 (`emit_bound_args`), присваивание — 11 (`emit_store`),
`if` — 7 (`lower_if`), `if let` — 6 (`lower_if_let`), деструктурирующее связывание — 4
(`bind_pair_temp`, `emit_destructure_bind`), объявление с параметром типа — 4 (`emit_instance_protos`).
То есть ни одна ветка принтера не осталась без входа в корпусе; проба порчей нужна только тогда, когда
перепись назовёт форму БЕЗ носителя — как было с `else` до фикстуры `control_flow/pos_1`.

## 5. Открытые вопросы (адресат · умолчание · срок)

- **Владельцу · гранулярность:** IR на функцию (как rustc `Body`) или на модуль сразу? Умолчание — на функцию (mono
  уже даёт инстансы функциями); срок — M0. Исполнено по умолчанию в M0 (`Fn` на объявление).
- **Владельцу · терминаторы структурные, а не плоские (расхождение с эскизом §12 архитектуры):** эскиз называет
  «базовые блоки, терминаторы» по rustc, где поток — `SwitchInt` + `Goto` без точки слияния. Умолчание — структурные
  терминаторы (`If` с `join`, `Loop` с `exit`; блоки и один терминатор на блок сохраняются, см. M2): без названной
  точки слияния C-принтер должен восстанавливать `if`/`while` из плоского графа (релупер), и побайтовый C, на котором
  стоит вся приёмка переноса, недостижим. Цена умолчания: анализы владения/эффектов (К5, позже) читают `join`/`exit`
  как обычные рёбра — потоковый анализ на таком CFG тот же. Срок — до M2b (первый терминатор с ветвлением); ответ
  «плоские» означает релупер в принтере и отказ от побайтового критерия в пользу только дифференциала. **Исполнено по умолчанию в M2b-1а (2026-09-06):** `If { cond, then, els, join }` и `Loop { head, body,
  exit }` в `lower/ir.nv`, C байт-в-байт на корпусе — ответ «плоские» теперь стоит переписывания принтера.
- **Владельцу · имя `syntax` в таблице §3:** строки 142–143 `novac-architecture.md` пишут ребро `lower → syntax`, а
  модуля `syntax` в дереве нет — есть `tree`, `parse`, `lex`. Умолчание — читать как `tree` (пониженная форма строится
  по дереву и каналу) и поправить таблицу на M0 с хроникой; срок — M0.
- **Номер подплана:** 274.8 выбран окном по прецеденту 274.5–274.7 (подпланы наследуют номер родителя, `/novac-recheck`:
  «подплан наследует номер (`NNN.N`)»); номер ВЕРХНЕГО уровня даёт интегратор — здесь его нет.
- **Владельцу · параллельность с 274.7:** одно окно ведёт и MIR (M1–M3), и ярус 0 самосборки (W6, многофайловая
  единица)? Умолчание — да, чередуя волнами и не смешивая коммиты; второе окно на одно из направлений ускорило бы
  вдвое. Срок — до M1.
- **Интегратору · номер строки реестра** под класс «шесть дверей позиции значения» как измеримый долг (носители
  №974, W4-находки) — или закрыть его самим M1 без строки; умолчание — без строки, M1 ссылается на этот подплан.
- **Интегратору · нужно ли зануление результата `??` (вскрыто пробой M2b-2 шага 2, 2026-09-08).** Поле `zero_init` получили ТРИ формы, и
  причины у них разные: у `match`-значения и `if`-значения путь может не присвоить локаль (274.3/Ф29) — зануление
  ОБЯЗАТЕЛЬНО; у `??` обе ветви присваивают результат (`take_payload` в Some, дверь размещения в None — проверено
  чтением `emit_coalesce`), то есть зануление ЗАЩИТНОЕ и унаследовано от прежней рукописной печати. Замер: снятие
  инициализатора меняет 28 объявлений в 17 файлах корпуса, из них `_novac_qq` — 8. **Умолчание — оставить как
  есть:** критерий волны байт-в-байт, а снятие — поведенческое решение, которое нельзя принимать мимоходом внутри
  волны переноса. **Срок — после M2b-2**, отдельной правкой со своим диффом; если снимать, то доказывать надо не
  «обе ветви присваивают по чтению», а фикстурой, где результат читается на каждом пути.
