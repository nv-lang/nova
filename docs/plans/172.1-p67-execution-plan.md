### Как работает NOVA_U45_GAP / [U45GAP]

`NOVA_U45_GAP` — env-переменная, активирует **debug-only инструментацию** в `emit_c.rs`.
Работает **только в debug-build** (`#[cfg(debug_assertions)]`): в release-build код полностью
отсутствует, никакого оверхеда.

**Что логируется:** каждое выражение с `expr.id.is_set()` которое прошло через
`infer_expr_c_type` (wrapper над legacy). В stderr печатается строка:

```
[U45GAP] kind=<Kind> annotated=<bool> legacy=<C-тип> [rc=<bool>] [recv=<shape>]
```

- `kind` — вид AST-узла (Call, Member, Ident, Binary, If, Match, ...)
- `annotated` — `true` если checker записал `resolved_types[expr.id]` (= новый канал дал ответ)
- `legacy` — C-тип который вернул legacy (строка, например `nova_int`, `uint8_t`, ...)
- `rc` (только для Call) — есть ли `resolved_callees[expr.id]` (checker записал колли → codegen-gap; нет → checker-gap)
- `recv` (только для Call) — форма ресивера: `free`, `path`, `method.var`, `method.chain`, ...

**Что означает каждая строка:**
- `annotated=false` → выражение **НЕ аннотировано checker'ом** → codegen падает в legacy → это fall-through
- `annotated=true` → checker аннотировал, но codegen **всё равно вызвал wrapper** — это **техдолг**
  (по `compiler-conventions.md §0` wrapper не должен вызываться для уже-аннотированных выражений;
  codegen должен читать канал напрямую, без обёртки). `annotated=true` строки не учитываются в tally —
  они не идут через legacy — но их наличие означает что архитектура пока не чистая (вызов wrapper
  для всех выражений, не только неаннотированных).

**Два измеримых счётчика (оба должны стать 0):**

| Счётчик | Grep | Что означает | Конвенция |
|---|---|---|---|
| **type-tally** | `annotated=false` | выражение без типа в checker → тип берётся из legacy | §0: тип резолвится в checker'е |
| **callee-tally** | `kind=Call rc=false` | вызов без callee в checker → overload re-derive в codegen | §3: свободные fn + методы + перегрузки — один путь |

```powershell
# type-tally:
($out | Select-String "\[U45GAP\].*annotated=false").Count

# callee-tally (только Call-выражения):
($out | Select-String "\[U45GAP\].*kind=Call.*rc=false").Count
```

`rc=` логируется только для `kind=Call`. `rc=true` = checker записал callee в `resolved_callees[expr.id]`
→ codegen читает `fn_ret_by_span[span]` напрямую (строка emit_c.rs:36584). `rc=false` = checker не
записал → codegen делает overload re-derive в legacy — нарушение §3.

`annotated=true` строки в type-tally НЕ входят — тип идёт через новый канал. Но их наличие
означает что codegen всё ещё вызывает wrapper для всех выражений (техдолг — по §0 wrapper
не должен вызываться для уже-аннотированных).

**Запуск и замер:**
```powershell

$env:NOVA_U45_GAP="1"
.\target\debug\nova.exe test ..\spec_tests\conformance 2>&1 | Tee-Object -Variable out
($out | Select-String "\[U45GAP\].*annotated=false").Count   # → tally
```

**Разбивка по kind:**
```powershell
$out | Select-String "\[U45GAP\].*annotated=false" | ForEach-Object {
    if ($_ -match "kind=(\w+)") { $matches[1] }
} | Group-Object | Sort-Object Count -Descending
```

Для каждого D читаю какие конструкции он тестирует, нахожу код в `types/mod.rs` и `emit_c.rs`,

| # | Что проверяю | Применимо когда | Где смотреть | Нарушение |
|---|---|---|---|---|
| §0a | `resolved_types.insert(expr.id, rt)` рядом с каждым резолвом типа | D тестирует любое выражение | `types/mod.rs` — место где тип вычисляется | его нет → тип выброшен после валидации |

| §4 | нет `_ => return` без маркера `[M-*]` для конструкций D | любой D | `types/mod.rs` — ветки match для AST-узлов D | тихая дыра без маркера и backlog-записи |

> `unwrap_or("nova_int")` — системный баг int-collapse.

### Алгоритм: как определить, что D идёт через новый канал, а не через legacy

**Ключевое понимание:** тест PASS ≠ «на новом канале». Legacy тоже даёт правильный
результат — иначе тесты падали бы ещё до нашей работы. D-track и tally — это **одна цель
с двух сторон**: D-файлы наращивают корпус выражений; tally показывает сколько из этого
корпуса ещё идёт через legacy.

**Единственный объективный критерий «на новом канале»:** вклад файла в tally = 0.

Инструмент — `NOVA_U45_GAP=1` (debug-build). Логирует каждое выражение идущее через legacy:
`[U45GAP] kind=<Kind> annotated=false legacy=<C-тип>`

**Алгоритм проверки конкретного D-файла:**
```powershell
# 1. Замерить tally ВСЕГО CU:
$env:NOVA_U45_GAP="1"; .\target\debug\nova.exe test ..\spec_tests\conformance 2>&1 `
  | Select-String "U45GAP" | Measure-Object | Select Count   # → tally_all

# 2. Временно исключить файл D:
Rename-Item ..\spec_tests\conformance\d<N>_*.nv d<N>_*.nv.bak

# 3. Замерить tally БЕЗ файла D:
$env:NOVA_U45_GAP="1"; .\target\debug\nova.exe test ..\spec_tests\conformance 2>&1 `
  | Select-String "U45GAP" | Measure-Object | Select Count   # → tally_without

# 4. Вернуть файл:
Rename-Item ..\spec_tests\conformance\d<N>_*.nv.bak d<N>_*.nv

# 5. Вклад D в legacy = tally_all - tally_without
# Если 0 → D полностью на новом канале ✅
# Если > 0 → D частично на legacy, нужно чинить checker
```

**Для всего D-track:** не нужно проверять каждый D по отдельности.
Финальный gate один: `tally = 0` на полном conformance CU = все выражения во всех
D-файлах идут через новый канал. Это автоматически означает что весь D-track закрыт.
