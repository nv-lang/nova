# Модульный `ro`: порядок инициализации и затенение имени

Строки реестра 221.1 №1396 (порядок) и №1397 (затенение), найдены 2026-09-30: первая — окном Карины
(nova-94), вторая — помощником (nova-44) при проверке фикса первой. Файлы — улики
`.nv.txt` (правило №695): переименуй в `.nv`, каждый в свой каталог (каталог — один
модуль), собери `nova build <файл>` и запусти.

## 1. №1396 — порядок инициализации (`forward.nv.txt`, `cycle.nv.txt`, `selfref.nv.txt`)

- `forward` — `ro second = first + 1` объявлен ДО `ro first = three()`. Спека (D200,
  02-types.md:9319) требует топологический `nova_consts_init()`; оракул падает в
  кодогене: `INTERNAL-PANIC [E_CODEGEN_TYPE_UNKNOWN] Ident first not in var_types`.
  Ожидалось `three`, `4`, `3`.
- `cycle`, `selfref` — цикл и самочтение: тот же `INTERNAL-PANIC` вместо диагностики.

ИСПРАВЛЕНО в ветке `p-ro-topo-order` (амендмент D184 2026-09-30, `E_MODULE_INIT_CYCLE`).

## 2. №1397 — параметр, совпадающий по имени с модульным `ro`, читается как значение модуля (`shadow_param.nv.txt`, `shadow_closure.nv.txt`)

- `shadow_param` — `ro k = three()` и `fn plus_one(k int) -> int => k + 1`:
  `plus_one(10)` печатает **`4`** вместо `11` — параметр `k` прочитан как модульная `k`.
- `shadow_closure` — `ro xs = apply(|xs| xs + 1)`, `apply` вызывает `f(2)`: печатает
  **`1`** вместо `3` — параметр замыкания прочитан как ещё не вычисленная модульная `xs`.
- `check` и `build` зелёные — значение молча неверное.

Замер: бинарь ветки `p-ro-topo-order` (база `p1158-lazy-const`). По чтению кода
(`emit_c.rs`, чтение `Ident`: вопрос «ленивая ли константа» задаётся по имени и файлу,
без учёта локальной области) дефект старше обеих веток; перемерено бинарём `main` (сборка 11:58): `4` и `1`.
