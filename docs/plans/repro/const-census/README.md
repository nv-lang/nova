# Опись имён констант `novac` — улики к классу «идентичность есть голое имя»

**Заказ:** окно Карины, 2026-09-20, вопрос «насколько класс мешает ЖИТЬ». Снято
помощником; вердикт по числам вынесло окно Карины (дефект есть, блокером не
является) — здесь только замер и способ его повторить.

## Что здесь лежит

| файл | что делает / что показывает |
|---|---|
| `census-collisions.py` | имена `const` по `novac/src/**/*.nv` с модулем и признаком `export`; имена в ДВУХ и более модулях; попутно — повторяющиеся пути импорта |
| `census-cost.py` | цена дисциплины: сколько констант НЕ экспортировано, распределение по модулям, и обходы, ЗАПИСАННЫЕ в комментариях |
| `out-collisions.txt`, `out-cost.txt` | вывод обоих на дереве `main` за 2026-09-20 |

Повторить (из корня рабочего дерева, пути внутри скриптов абсолютные — поправь
корень, если дерево другое):

```sh
python docs/plans/repro/const-census/census-collisions.py
python docs/plans/repro/const-census/census-cost.py
```

## Числа на день замера

* объявлений `const` — **145**, РАЗНЫХ имён — **145**: каждое имя уникально по
  всему дереву;
* имён, встречающихся в двух и более модулях, — **0**;
* НЕ экспортировано — **110 из 145** (76%), и 89 из них в одном модуле
  `novac.check`; `novac.builtins` — единственный, у кого экспортированы все 35;
* обходов, названных в комментариях, — **11**;
* путей импорта — 154, из них в двух и более модулях — **32**.

## Почему ноль здесь НЕ значит «мерить нечего»

Первый прогон дал «столкновений 0», и этого мало: ноль бывает и у пустой мишени.
Мишень проверена ДО вывода — имена из поломки, с которой начался заказ, в дереве
есть (`B_LF` в `novac/src/lex/lex.nv`, `LF_BYTE` в `novac/src/check/check.nv`).
Значит ноль означает другое: **столкновения обходят переименованием**, и цена
класса — не «волна встанет», а «каждое новое имя стоит одной проверки».

Прямая улика цены — комментарий в `novac/src/check/strings.nv`: «NEWLINE and not
`B_LF`: `lex.nv` already declares a const of that name… `Nova_const_novac_lex_B_LF`,
undeclared in this translation unit».

## Что из этого оказалось важнее чисел (наблюдение окна Карины)

Одиннадцать обходов записаны в комментариях — то есть знание СУЩЕСТВОВАЛО в
дереве и не дошло до того, кто писал новую константу, пока он не упёрся дважды.
Это находка не про имена, а про то, как знание доезжает: комментарий в чужом
файле не виден тому, кто пишет свой.

## Граница замера — чего здесь НЕТ

* Не мерились константы, объявленные ВНУТРИ функций иначе, чем строкой `const`
  в начале строки: счёт идёт по форме объявления, а не по разбору.
* Не проверялось, ЧТО происходит при настоящем столкновении: сегодня их ноль,
  значит наблюдать нечего; поведение описано в комментарии-улике выше.
* Про импорты замер отвечает на «сколько путей повторяется», а НЕ на «нужна ли
  дедупликация при склейке»: расхождение с замером окна Карины (оракул повторный
  `import` терпит) оставлено ОТКРЫТЫМ — ни у кого нет проверки на настоящем
  масштабе, 22 файла модуля `check` в одной единице компиляции.
