# Пробы к строке реестра №1176 — два варианта с одним именем в одной сумме

Два файла, снятые 2026-09-20 окном `nova-78` бинарём `nova-cli/target/release/nova`
(сборка `--release`, тулчейн по умолчанию). Улики ЧИТАЮТ и при нужде запускают вручную;
суффикс `.nv.txt` держит их вне раннера (правило №695 п. 2).

| файл | команда | вердикт |
|---|---|---|
| `1-the-collision.nv.txt` | `nova check <file>` | `PASS: 1  FAIL: 0` — чекер молчит |
| `1-the-collision.nv.txt` | `nova build <file>` | `error: compiler error:` + `redefinition of enumerator 'NOVA_TAG_Rv_Pay'` + `duplicate member 'Pay'` — текст C-компилятора наружу |
| `2-control-distinct-names.nv.txt` | `nova build <file>` | `built: ...`, запуск печатает `rec 1pos 2` |

**Зачем контроль, а не одна проба.** Без второго файла отказ нельзя приписать именно
СТОЛКНОВЕНИЮ ИМЁН: падать мог бы сам набор форм (record-вариант рядом с позиционным) или
конструирование обоих вариантов в одной программе. Контроль отличается ровно одной буквой
в имени второго варианта — `Pos` вместо `Pay` — и зелен насквозь, вплоть до запуска.
Значит причина в имени, а не в формах.

**Что из этого следует для приёмки.** Дефект — не в мангле имён. Соблазн развести
`NOVA_TAG_Rv_Pay` суффиксом узаконил бы форму, в которой два варианта неразличимы и на
стороне Nova: `Rv.Pay { vec: 1 }` и `Rv.Pay(2)` — разные конструкторы под одним именем, а
рука `Pay { vec }` в `match` не отличима от `Pay(n)` ничем, кроме образца. Отвергать надо
ОБЪЯВЛЕНИЕ, и диагностика должна называть оба места.

**Чего эти пробы НЕ показывают** (названо, чтобы следующий не счёл проверенным): случай
двух одинаковых имён в РАЗНЫХ суммах одного файла здесь не снят — это соседний вопрос,
и у него своя родня в реестре (№136, №567, №658, №280 — резолвинг голого имени через
чужую сумму).
