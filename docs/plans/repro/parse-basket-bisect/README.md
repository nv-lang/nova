# Корзина парсера: адрес по ПОСТРОЕНИЮ, а не по первому отказу (2026-09-20)

## Зачем инструмент

Корзину «novac did not parse this» дважды вскрывали приёмом **«первый отказ
каждого файла»** — им же построена очередь остатка в 274.7 §Н. Помощник показал
его предел: **в четырёх семьях из восьми строка, на которую указывает корзина, в
одиночку читается**. То есть адрес правдоподобен и неверен.

Причина понятна из правила 274:3056: спаны после первого — мусор восстановления.
Но и ПЕРВЫЙ спан не обязан стоять там, где парсер сломался: восстановление
успевает уйти вперёд.

## Что делает `bisect_fallback.py`

Сужает **по построению**: берёт заголовок файла (`module`, `import`), затем
добавляет объявления верхнего уровня ПО ОДНОМУ и называет то, с чьим приходом
отказ появляется. Ответ — объявление, которое отказ ПОРОДИЛО, а не строка,
которую доложили первой.

```sh
BISECT_DIR=<пустой каталог> python docs/plans/repro/parse-basket-bisect/bisect_fallback.py novac/src/lex/lex.nv
```

## Предел самого инструмента, названный сразу

Сужение идёт **до объявления**, не глубже. Для `export fn lex` — функции в
несколько сотен строк — это всё ещё грубо: сказано «внутри этой функции», а не
«на этой форме». Внутрь объявления инструмент не ходит, потому что кусок функции
сам по себе не разбирается, и «убрать половину тела» не даёт валидной пробы.

То есть он заменяет ОДИН неверный адрес на ОДИН верный, но крупный. Для четырёх
файлов из четырнадцати этого достаточно, чтобы перестать искать не там; для
`lex.nv` нужна проба внутри функции, и она отдельная работа.
