# №1070 — коллекция ЗАПИСЕЙ не проходит через границу эффекта

Замер 2026-09-12, окно интегратора. Найдено при закрытии открытого вопроса плана
286 («переживает ли `Result[[]Row, DbError]` границу эффекта») — вопрос был
записан как решаемый пробой, а не словом, и проба ответила.

Бинарь: `nova-cli/target/release/nova.exe` (сборка 2026-09-09 21:30). Команда на
каждую пробу из корня репозитория:

```sh
./nova-cli/target/release/nova build <файл>.nv -o /tmp/probe.exe
```

(файлы лежат с расширением `.nv.txt`, чтобы их не подхватывал ни один прогон.)

## Таблица: ось — ЭЛЕМЕНТ коллекции, а не коллекция и не `Result`

| проба | что возвращает операция эффекта | исход |
|---|---|---|
| `a_vec_int.nv.txt` | `[]int` | ✅ `built`, печатает `n=3 second=2` |
| `b_single_record.nv.txt` | `Flat` и `Option[Flat]` | ✅ `built`, печатает `one=a@b.c` / `next=c@d.e` |
| `c_vec_record_flat.nv.txt` | `[]Flat` (поля — только скаляры) | ❌ `codegen error` |
| `d_vec_record_result.nv.txt` | `Result[[]Row, DbErr]` | ❌ `codegen error` |

Вердикт красных клеток, дословно:

```
codegen error: cannot infer type argument `T` for generic function
`copy_n_nonoverlapping` — appears in param `src` (#0), param `dst` (#1);
use turbofish: `copy_n_nonoverlapping[T](...)`
```

## Что проба ОТВЕРГЛА по дороге

Каждое из этих объяснений проверено и оказалось ложным:

* **«виноват `Result`»** — нет: `[]Flat` без `Result` падает так же (`c`);
* **«виноват литерал массива внутри тела обработчика»** — нет: массив,
  построенный ОТДЕЛЬНОЙ функцией и только возвращённый, падает так же;
* **«виноваты вложенные коллекции в полях записи»** — нет: `Flat` с полями
  `int` и `str` падает так же (`c`);
* **«коллекции вообще не проходят границу»** — нет: `[]int` проходит (`a`).

Остаётся ровно одно: **элемент-ЗАПИСЬ в коллекции, возвращаемой операцией
эффекта.**

## Почему это дорого

1. **Целевая форма плана 273 непостроима.** `docs/plans/273-…:291-301` объявляет
   `query(q Sql) -> Result[[]DbRow, DbError]` — ровно проба `d`.
2. **Это третья клетка класса №47**, закрытого 2026-07-24 «на уровне носителя»:
   тот же корень (вывод тип-аргумента считает `void*` нерезолвленным, не отличая
   «непрозрачен по замыслу» от «непрозрачен, потому что ещё обобщён»), та же
   диагностика. Вторая клетка — №1069 (статик по тип-параметру в цикле).
3. **Но у плана 286 есть выход, и проба его подтверждает:** одиночная запись и
   `Option[Record]` границу проходят (`b`), то есть курсорная форма
   `@next() -> Option[Row]` собирается уже сегодня. Списочная — нет. Форма,
   выбранная планом по соображениям стриминга, оказалась ЕДИНСТВЕННОЙ рабочей.
