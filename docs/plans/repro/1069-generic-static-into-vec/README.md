# №1069 — статик по тип-параметру внутри цикла, кладущийся в `Vec[T]`

Замер 2026-09-11, окно интегратора. Найдено не охотой, а при проверке примера кода
для владельца (объяснение к плану 286): показывать форму, не собрав её, нельзя.

Бинарь: `nova-cli/target/release/nova.exe` (сборка 2026-09-09 21:30).
Команда на каждую пробу, из корня репозитория:

```sh
./nova-cli/target/release/nova build <файл>.nv -o /tmp/probe.exe
```

(файлы лежат с расширением `.nv.txt`, чтобы их не подхватывал ни один прогон;
перед проверкой переименовать в `.nv`.)

## Таблица: красная РОВНО одна клетка из четырёх

Оси две — есть ли `for`-цикл и идёт ли в `push` результат статического метода,
вызванного ЧЕРЕЗ ТИП-ПАРАМЕТР (`T.from_row(r)`).

| проба | цикл | статик через `T` | исход |
|---|---|---|---|
| `a_no_loop_no_static.nv.txt` | нет | нет | ✅ `built` (4.46 s), печатает `5` |
| `b_no_loop_static.nv.txt` | нет | **да** | ✅ `built` (4.77 s) |
| `c_loop_no_static.nv.txt` | **да** | нет | ✅ `built` (4.62 s), печатает `2` |
| `d_loop_static.nv.txt` | **да** | **да** | ❌ `codegen error` |

Вердикт красной клетки, дословно:

```
codegen error: cannot infer type argument `T` for generic function
`copy_n_nonoverlapping` — appears in param `src` (#0), param `dst` (#1);
use turbofish: `copy_n_nonoverlapping[T](...)`
```

## Проба в обе стороны — на ОДНОМ файле

`d_loop_static.nv.txt` отличается от `b_no_loop_static.nv.txt` ровно циклом.
Убрать `for` — собирается; вернуть — падает. Разный исход на одном дереве и одном
бинаре, так что мерили именно форму, а не окружение.

## Чего проба НЕ показывает

* `T` здесь — `value`-запись (`type Account value { ro email str }`), НЕ newtype над
  `int`. Форма newtype над примитивом — это соседняя строка №895, и там другая
  диагностика (кодоген резолвит `int.from_idx`), так что строки не дублируют друг
  друга;
* эффект ни при чём: первое воспроизведение было с эффектом в строке
  (`fn[T FromRow] fetch(q str) Db -> []T`), но проба `d` эффекта не содержит вовсе и
  падает так же;
* инстанс-половина протокола не проверялась отдельно — упало на статике.

## Почему это важно за пределами примера

Это естественная форма «прочитать МНОГО строк в типизированные записи»:
`fn[T FromRow] fetch_all(q Sql) Db -> []T`. Сегодня она не собирается, и обойти
можно только развернув цикл или отказавшись от статика по тип-параметру. План 286
(этап Д2) строит на ней типизированный разбор строки.
