# Оракул выносит `??` из выражения перед всем выражением

Найдено облачной сессией `p274-carina-cast` 2026-10-02, шаг 8 (волна №1619). Строка реестра —
`№TBD` в `docs/plans/221.1-bug-sweep.md`; номер присвоит интегратор.

## Что видно

`prog.nv` — три строки с побочным эффектом (`mark` печатает своё имя). Справа — вывод оракула
(`oracle.out`) и Карины (`novac.out`), слева — норма.

| строка | норма | оракул | Карина |
|---|---|---|---|
| `mark("f", 1) + (maybe(mark("g", 2)) ?? 0)` | `eval f`, `eval g` | `eval g`, `eval f` | норма |
| `mark("l", 0) > 1 && (maybe(mark("never", 5)) ?? 0) > 3` | `eval l` и `false`; `never` НЕ вычисляется | `eval never`, `eval l` | норма |
| `mark("l2", 2) > 1 \|\| (maybe(mark("never2", 5)) ?? 0) > 3` | `eval l2` и `true`; `never2` НЕ вычисляется | `eval never2`, `eval l2` | норма |

## Норма

- Порядок вычисления слева направо и наблюдаем (F65: `spec/decisions` — левый операнд раньше
  правого; без `??` оракул сам держит этот порядок: `mark("p", 1) + mark("q", 2)` печатает `p`, `q`).
- Короткое замыкание `&&` / `||`: правый операнд вычисляется только когда левый не решил ответ.

## Класс

Оракул поднимает `??` (его Some-тест и запасное значение) в оператор ПЕРЕД всем выражением,
в котором тот стоит, — не учитывая ни левые операнды с эффектом, ни условность правой части
`&&`/`||`. Родня №685 (порядок аргументов), но предмет другой: здесь виноват подъём `??`, без
`??` порядок верен.
