# Пробы к №675 — char-литерал и сырой управляющий байт

Сняты интегратором 2026-09-18 при разборе очереди 274.10. **Вывод замера: строка
реестра в её прежней формулировке не воспроизводится**, и остаётся не дефект
компилятора, а пробел спеки. Пробы лежат здесь, чтобы следующее окно судило по
файлам, а не по пересказу.

Суффикс `.nv.txt` — по правилу этого каталога: улика живёт вне раннера и стражей.
Для прогона скопировать без `.txt` и звать `check` / `build` / запустить бинарь.

## Что замерено (бинарь `nova-cli/target/release/nova.exe`, 2026-09-18)

| проба | форма | `check` | запуск |
|---|---|---|---|
| `raw_tab.nv.txt` | сырой TAB (0x09) внутри `'…'` | ok | `code=9` |
| `raw_vt.nv.txt` | сырой 0x0B | ok | `code=11` |
| `raw_cr.nv.txt` | сырой CR (0x0D) | ok | `code=13` |
| `raw_lf.nv.txt` | **сырой перевод строки: литерал ПЕРЕСЕКАЕТ строку исходника** | ok | `code=10` |
| `backslash.nv.txt` | `'\\'` — экранированный бэкслеш | ok | `code=92` |
| `lone_bs.nv.txt` | `'\'` — одиночный бэкслеш | **FAIL** `expected closing ' in char literal` | — |
| `raw_in_str.nv.txt` | сырой 0x0B внутри СТРОКОВОГО литерала | ok | `byte_len()=3` |
| `control.nv.txt` | контроль: `'x'` и законный `'\n'` | ok | `a=120 b=10` |

**Главное, ради чего мерилось.** Носитель обхода в novac
(`novac/src/lex/lex.nv:235`) называет две вещи: `'\\'` «silently accepted and
MISCOMPILED» и сырой управляющий байт «silently accepted with garbage semantics …
even spanning lines». Сегодня **ни одна из шести форм не даёт неверного байта** —
включая ту самую, что пересекает строку. То есть половина «мискомпиляция» не
воспроизводится; остаётся только ПРИЁМ форм, про которые спека молчит.

**`lone_bs` — не дефект, а верный отказ.** По грамматике `'\'` не порождается ни
как `raw-char`, ни как `escape`: escape требует символа ПОСЛЕ бэкслеша. Строка
реестра числила этот отказ второй половиной дефекта — ошибочно.

## Норма спеки, проверенная чтением

Нормативной грамматики char-литерала **в `spec/decisions/` нет вовсе**.
Единственный текст — `spec/open-questions.ru.md`, раздел `Q-char-literals`
(помечен «✅ ЗАКРЫТО (2026-05-07)», оригинал «сохранён для истории»):

```
char-literal = "'" ( raw-char | escape ) "'"
escape       = '\' ( "'" | '"' | '\' | 'n' | 'r' | 't' | 'b' | 'f' | '0'
                   | 'u' hex4 | 'u{' hex+ '}' )
```

**Продукция `raw-char` не раскрыта** — алфавит сырого символа не определён ни
одной фразой. Значит запрета, который лексер нарушал бы, не существует: строка
судила по правилу, которого нет.

И там же расхождение двух документов о САМОМ СТАТУСЕ вопроса:
`spec/decisions/08-runtime.md:898` говорит «char-литералов (`'a'`) — ещё открытый
вопрос (Q-char-literals)», тогда как `Q-char-literals` помечен закрытым.

## Что нужно решить (владелец)

Разрешить сырой управляющий байт — то есть кодифицировать нынешнее поведение — или
ОТВЕРГАТЬ его диагностикой. Решение язык-меняющее в обе стороны. От него зависит
самоистекающее условие носителя: маркер `[LEGACY-#675]` погаснет, только если чекер
начнёт отвергать. До ответа обход в novac не снимать.
