// КОНТРОЛЬ к пробе №699, вторая редакция — и она ближе к предмету.
//
// Первый контроль объявлял тип с именем ИМПОРТИРОВАННОГО (`SerError`) и прошёл
// ЧИСТО: объявление в файле законно перекрывает импорт, а сам импорт получает
// лишь лint «unused». То есть контроль проверял законный случай, а не
// столкновение, — и молчание на нём ничего не доказывало.
//
// Здесь столкновение той же формы, что в строке №699: ДВА PEER-ФАЙЛА ОДНОГО
// МОДУЛЯ объявляют `Node` (D281 Rule C — все peer-файлы папки суть один
// модуль). Если и это пройдёт чисто, значит путь столкновений не работает
// вовсе, и «чисто» в основной пробе нельзя читать как ответ.
module p699probe

type Node { ro other int }

fn peer_touch() -> int {
    ro y Node = { other: 3 }
    y.other
}
