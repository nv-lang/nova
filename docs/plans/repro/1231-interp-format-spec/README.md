# Проба к реестру №1231 — debug-спецификатор `${expr:?}` в интерполяции

## Находка

Найдено помощником 2026-09-21, пятая строка таблицы 274.5 §5в
(`examples/tour/strings_tour.nv`). `novac/src/parse/expr.nv`'s разбор
`InterpStr`: цикл читал выражение слота и сразу ждал закрывающую `}` —
ветки на опциональный суффикс `:SPEC` (D229) между ними не было вовсе.

## Метод

Цикл интерполяции и все пять его потребителей (`check/exprs.nv`,
`check/type_of.nv`, `emit_c/emit_c.nv`, `emit_c/emit_expr.nv`,
`sem/node_questions.nv`) читают детей слота ПО ВИДУ узла (`is_expr_kind`,
фильтр на `StrFrag`), не по фиксированной позиции — значит два новых
листа (`Colon`, `Question`) между выражением и закрывающей скобкой не
требуют дверей-сканеров, как понадобилось if-let'у (№1259): существующие
потребители просто пропускают лист, вид которого им неизвестен.

## Фикс

Узко, ровно по форме V1 (D229): парсер (`expr.nv`) читает ИМЕННО пару
`Colon` `Question` как два листа слота, если она есть — любой другой
спецификатор (полный Rust-style мини-язык, D183) не трогается этим
фиксом и по-прежнему падает в прежний fallback. Чекер (`check/exprs.nv`)
получил ПРОВЕРКУ на позицию i+1 внутри цикла по слотам: если следующий
за выражением лист — `Colon`, слот отказан ИМЕНОВАННО (`INTERP_SPEC_MSG`,
`check/literal_rules.nv`) ДО обычного разрешения `Display` — иначе
программа с `:?` компилировалась бы молча и печатала значение НЕ в
debug-формате, что было бы неверным поведением, а не честным отказом.

**Ловушка со знаком доллара:** текст сообщения и текст пробы оба содержат
буквальное `${...}` — без экранирования `\$` оракул читает это как
настоящую интерполяцию СВОЕГО ЖЕ Nova-исходника (`literal_rules.nv`,
`check_test.nv`) и даёт `E_CONST_NOT_CONSTEXPR`/синтаксическую ошибку.
Экранировано `\${...}` в обоих местах.

## Замер ДО фикса

`novac.exe check` на `fn f(s str) -> str { "${s:?}" }` (изолированная
проба, `p1231.nv` в session scratch) — ДВА безымянных `E_NOVAC_SUBSET`
(«novac did not parse this ... narrowed form by form»), на позициях `:`
и `?`. Контроль `"${s}"` (без спецификатора) — чисто, `exit=0`.

Перепроверено ЖИВЬЁМ через временный откат `expr.nv` (`git checkout --`
на файл, пересборка, проба, `git apply` тем же патчем обратно,
пересборка) — красное состояние воспроизведено независимо, не только
процитировано из находки помощника.

## Замер ПОСЛЕ фикса

```
novac.exe check p1231.nv
-> {"code":"E_NOVAC_SUBSET", "message":"outside the subset: a format
   specifier in string interpolation (`${expr:?}`, D229) is not
   compiled yet (274.7 B1b, the Display family) -- write the value
   plain and format it by hand"}

novac.exe check p1231_ctrl.nv   (plain "${s}")
-> exit=0, чисто
```

Именованный отказ вместо fallback; контроль без регрессии.

## Гейты

## Оговорка

Приёмка не требует реализации самой семантики `Debug.@debug` — только
именованный отказ вместо fallback, той же меркой, что и №1264 (`?`
Try-оператор). Любой спецификатор ШИРЕ `:?` (D183, полный
Rust-style мини-язык) не разобран этим фиксом и остаётся прежним
поведением (fallback).
