# Зависит ли вердикт чекера от ПОРЯДКА ТЕЛ в единице компиляции — замер

**Заказ:** окно Карины, 2026-09-20: `unit_of` складывает тела в порядке, который
дал вызывающий, и без ответа нельзя ни сортировать (спрячет ответ), ни не
сортировать (вдруг важно). Снято помощником; вердикт вынесло окно Карины.

**ОТВЕТ: порядок тел на вердикт чекера НЕ влияет.**

```
parse   alpha=4  reverse=4  rotate=4    наборы (code,message): СОВПАЛИ
check   alpha=77 reverse=77 rotate=77   наборы (code,message): СОВПАЛИ
```

## Как мерилось

Единица собирается правилом из соседней пробы
(`../peers-one-unit/peers_probe.py`): одна строка `module`, затем импорты с
дедупликацией, затем тела — с добавленным параметром ПОРЯДКА файлов. Раскладок
ТРИ, а не две (слово заказчика): алфавит, обратный, поворот на один. Две точки
дают прямую через что угодно; третья отличает «зависимости нет» от «совпало».

Сравниваются МУЛЬТИМНОЖЕСТВА пар `(code, message)`, СМЕЩЕНИЯ ОТБРОШЕНЫ: при
перестановке тел они обязаны меняться, это арифметика, а не находка, и сравнение
по ним дало бы «различается всё» при пустом выводе. Число диагностик мерится
отдельно — одинаковое число при разном наборе было бы самым интересным случаем,
и виден он только так.

```sh
python docs/plans/repro/unit-body-order/order-of-bodies.py
python docs/plans/repro/unit-body-order/control-2-passed.py
```

## ГРАНИЦА ЗАМЕРА — мерился ЧЕКЕР, не эмиссия

Ответ относится к вердикту `novac check`. Про эмиссию C он не говорит НИЧЕГО.
Если работа поедет в эмиссию, вопрос открывается заново, и это будет НОВЫЙ замер,
а не ссылка на этот.

## Контроль, и первый из них ПРОВАЛИЛСЯ — он здесь намеренно

«Наборы совпали» ничего не стоит, пока не показано, что сравнение УМЕЕТ
расходиться.

* `control-1-failed.py` — убирает из единицы ПОСЛЕДНИЙ файл; разницы ноль. По
  этому результату сравнение выглядит слепым, и вывод выше был бы недействителен.
  Разбор показал другое: все четыре диагностики модуля `parse` приходят ИЗ ОДНОГО
  файла `parse.nv`, а выброшен был другой — контроль мерил не то, что обещал.
* `control-2-passed.py` — дописывает в единицу заведомо негодную строку: пар
  становится 5 против 4, расхождение названо. Сравнение видит.

Провалившийся контроль оставлен, потому что без него «разницы ноль» читается как
слепота инструмента. Отрицательный результат объясняют, а не прячут.

## Сила свидетелей неодинакова

`parse` — свидетель СЛАБЫЙ: 4 диагностики из ОДНОГО файла, переставляй как
хочешь — менять нечему. `check` — сильный: 77 диагностик из ШЕСТНАДЦАТИ файлов
(`calls.nv` 22, `exprs.nv` 18, `literal_rules.nv` 6, `return_rules.nv` 5,
`methods.nv` 4, `option_rules.nv` 4, `operators.nv` 3, `binds.nv` 2, далее
единицы). **Вывод держится на `check`**, а не на двух модулях поровну.

## Ловушка, пойманная на себе: правильный на вид ответ при сломанном замере

Первый прогон напечатал «диагностик 1, наборы совпали» — ответ, неотличимый от
настоящего. Причина: файлы единиц были названы по-русски
(`unit_parse_алфавит.nv`), и не-ASCII в пути сломал запуск МОЛЧА. Поймал это
только счётчик НЕРАЗБИРАЕМЫХ строк вывода: единственная строка не разобралась как
JSON.

**Правило, которое из этого следует** (формулировка окна Карины, третий случай за
сутки): у всякого замера обязан быть счётчик того, ЧТО НЕ РАЗОБРАЛОСЬ — ноль
непрочитанного есть часть вердикта, а не мелочь. Соседние случаи той же породы:
«2 из 70» (обрыв вывода после ICE, реестр №1168) и «62 файла» (прогон без
`NOVAC_SELF_PATH`).
