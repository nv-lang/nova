## Локализованный корень

В `novac/src/check/match_arms.nv`, `type_arm_block_value`, условие на строке 766:

```nova
if i == last && is_expr_kind(c.kind_of()) {
```

Хвостовой `if` внутри блока разобран как `IfStmt`, а не как `IfExpr`. Условие
не пропускает его в путь определения значения плеча: он проверяется как statement,
`out_t` остаётся `no_ty()`, на блоке не записывается тип результата.
`novac/src/lower/lower_match.nv:514–539` читает именно этот ответ из канала;
блок без записанного типа понижается без назначения значения в match-local.
Нулевой match-local в итоге возвращается без диагностики.

В собственной функции Карины
`novac/src/sem/mangle_instance.nv:344–350` это плечо `TkRecord`: обе строки
хвостового `if` должны стать значением `instance_arg_spelling`. В сохранённом
B.body.c:137981–137998 обе строки вычислены, но отброшены через `(void)`;
`_novac_l1` не назначается. Поэтому B, печатающая C, теряет суффикс record-типа
в имени экземпляра Vec. Это причинный носитель, не доказательство покрытия всех
83 ошибок C. Остальные сообщения, включая 9 undeclared identifier, ещё требуют
отдельной проверки после исправления класса.

Норма: D19 (block с хвостовым expression), D23 (последнее выражение — результат),
D40 (if/else — выражение), D44 (интерполяция имеет тип str). Цитата D23 из
`spec/decisions/03-syntax.md:695` сверена: «Последнее выражение тела — автоматически
результат». Изменения языка не требуется.

## Следующий ремонт и что не сделано

Исправлять решение «хвост блока плеча производит значение», не C-написание Vec и не
`instance_arg_spelling`. Сверить это решение с уже существующими дверями
`type_branch_value` и `lower_block_stmts_value`; проверить не только IfStmt, но
все допустимые хвостовые формы, контекст ожидаемого типа и выходы без значения.
Простая замена одного predicate без этой проверки ещё не доказана как достаточная.

Требуемая приёмка ремонта: поведенческие положительные фикстуры, отрицательная
фикстура проверки типов с line-pinned nova:expect, красно-зелёная порча условия,
затем свежая полная A→B→C, реальный C executable, relink B, оба сырых побайтных
IDENTICAL и саботаж сравнения. CI — на том же проверяемом кандидате.
