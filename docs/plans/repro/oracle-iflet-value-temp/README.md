# Оракул: временная под значение `if let` объявляется `nova_str` (2026-09-20)

**Дефект ОРАКУЛА**, найденный окном Карины при работе над строкой 1189 (хвостовой
`if let` в самой Карине). Суффикс `.nv.txt` — требование стража: пробы-улики не
попадают в корпус как исходники.

Запуск каждой: `./nova-cli/target/release/nova build docs/plans/repro/oracle-iflet-value-temp/<файл>.nv.txt -o <куда>`

## Носитель

```nova
fn g(o Option[int]) -> int {
    if Some(v) = o { v } else { 0 }
}
```

`nova check` молчит; сборка падает в Си:

```
error: assigning to 'nova_str' from incompatible type 'nova_int'
    _nv_if_let_490 = v;
error: initializing 'nova_int' with an expression of incompatible type 'nova_str'
    nova_int _nv_tmp_491 = _nv_if_let_490;
```

Временная объявлена **`nova_str`**, хотя ветви дают `int`.

## Шесть контролей, и они сужают причину до точки

| проба | форма | вердикт |
|---|---|---|
| `e` | `Option[int] -> int`, ветвь `Some` — голый `v` | **ПАДАЕТ** (`nova_str` ← `nova_int`) |
| `l` | `Option[bool] -> bool`, голый `v`, `else false` | **ПАДАЕТ** (`nova_bool`) |
| `m` | `Option[int] -> int`, голый `v`, `else` — ИМЯ, не литерал | **ПАДАЕТ** (`nova_int`) |
| `f` | `Option[str] -> str`, голый `v` | собирается |
| `k` | `Option[int] -> int`, ветвь `v + 0` | собирается |
| `i` | `Option[int] -> bool`, ветвь `v > 0` | собирается |
| `j` | `Option[str] -> int`, ветвь `v.byte_len()` | собирается |

**ОСЬ:** падает тогда и только тогда, когда ветвь `Some` — **САМ СВЯЗЫВАТЕЛЬ**, а
тип значения не `str`.

**ПОЧЕМУ `f` СОБИРАЕТСЯ — И ЭТО САМОЕ ВАЖНОЕ В ТАБЛИЦЕ.** Не потому, что строка
особенная, а потому, что временная объявлена `nova_str` ВСЕГДА, и в строковом
случае жёстко вписанный тип СОВПАЛ с настоящим. То есть «успешный» контроль
проходит по совпадению, а не по здоровью. Первая моя гипотеза была «всегда
`nova_str`» — её опровергла проба `i` (int→bool собирается), и только после
этого нашлась настоящая ось: дело в ФОРМЕ ветви, а не в типе.

## Чем это НЕ является

**Не строка №969.** Там обе ветви `return` (расходящаяся конструкция), временная
типа `nova_unit`, и класс — «лоуринг порождает временную для конструкции, из
которой нет выхода». Здесь обе ветви дают ЗНАЧЕНИЕ, выход есть, а тип временной
просто неверен. Общее у них одно — место (`_nv_if_let_NNN`), и починка одного
может не тронуть другого.

## Дифференциал: у Карины преимущество

`novac` компилирует носитель **верно** — обе ветви пишут в одну временную
правильного типа, и функция возвращает её:

```c
static nova_int novac_fn_p_e_g__Option_of_nova_int__to_nova_int(NovaOpt_nova_int o) {
    nova_int _novac_l1 = (nova_int){0};
    NovaOpt_nova_int _novac_l2 = o;
    if (_novac_l2.tag == NOVA_TAG_Option_Some) {
    nova_int v = _novac_l2.value;
        _novac_l1 = v;
    } else {
        _novac_l1 = ((nova_int)0LL);
    }
    return _novac_l1;
}
```

Поэтому носитель кладётся в `novac/divergences.allow` как «оракул не собирает
верную программу» — так же, как это сделано для №969.
