# Пробы к №967 — присваивание в биндинг с ВЫВЕДЕННЫМ типом не сверяется

Найдено окном 274 пробой по оракулу 2026-09-05; воспроизведено и расширено контролями
интегратором в тот же день.

`mut x = 1` даёт биндингу тип `int` по инициализатору. Следующее `x = "s"` чекер
пропускает молча, и отказывает уже сишный компилятор — координатой в сгенерированном
`main.c`, а не в файле пользователя.

## Как запускать

```sh
cp docs/plans/repro/967-assign-door-unchecked/<файл>.nv.txt /tmp/t.nv
nova-cli/target/release/nova.exe check /tmp/t.nv
nova-cli/target/release/nova.exe build /tmp/t.nv -o /tmp/t.exe
```

## Замер 2026-09-05 (`nova-cli/target/release/nova.exe`, main @ aeb4bcf0f)

| проба | форма | `nova check` | `nova build` |
|---|---|---|---|
| `assign_str_to_int` | `mut x = 1` затем `x = "s"` | **ok** | `error: assigning to 'nova_int' from incompatible type` |
| `ctrl_annotated_binding` | `ro x int = "s"` — КОНТРОЛЬ | `E7301` | отвергнуто |
| `ctrl_argument` | `sink("s")` при `sink(n int)` — КОНТРОЛЬ | `E7301` | отвергнуто |

## Что доказывают контроли

Одно и то же несовпадение (`str` там, где `int`), три двери:

```
аннотированный биндинг   ro x int = "s"    отвергнут   E7301
аргумент                 sink("s")         отвергнут   E7301
присваивание в выведенный биндинг   x = "s"   ПРИНЯТО -> отказывает Си
```

Правило есть и исполняется. Дверь присваивания в биндинг, чей тип ВЫВЕДЕН, его не
спрашивает. Это ровно форма №959 (там не спрашивала дверь возврата) и №957 (там одна
проверка не заходила в импортированные тела): **одно правило, несколько дверей, одна
молчит**.

## Чего проба НЕ утверждает

Не мерил: присваивание в поле записи, в элемент коллекции, через `@`-приёмник, и
числовые пары (те ведутся №926 отдельно — там своя причина, `cat_compatible_rt`
пермиссивен к паре int/float, а здесь молчание к НЕчисловой паре). Перечень форм —
часть приёмки строки реестра, а не этой пробы.
