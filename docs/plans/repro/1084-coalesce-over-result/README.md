# Пробы к строке реестра №1084 — `??` над `Result`

Три файла, снятые 2026-09-13 окном 274 бинарём `novac/target/novac.exe` из корня дерева.
Разделяют ТРИ вопроса, которые легко слить в один и получить неверный вывод об объёме волны.

| файл | команда | вердикт |
|---|---|---|
| `1-inference-blocks-construction.nv` | `novac check <file>` | `outside the subset: the type argument of this sum cannot be inferred from the payload -- its type is not decided here (E2-b3)` |
| `2-the-refusal-and-its-control.nv` | `novac check <file>` | РОВНО ОДИН отказ: `outside the subset: \`??\` unwraps an \`Option\`, and this left side is not one` |
| `3-control-alone-is-green.nv` | `novac check <file>` | пусто, `rc=0` |

**Зачем три, а не один.** Первая проба строила `Ok(7)` и была отвергнута за ВЫВОД ТИПА, а не
за `Result`: отказ нёс срок `(E2-b3)` и относился к соседнему вопросу. Если бы я остановился
на ней, вывод был бы «`Result` вне подмножества, волна зависит от другой волны» — и он неверен.

Вторая убирает конструирование вовсе (тип только в параметре) и держит КОНТРОЛЬНУЮ половину —
ту же форму над `Option`. Один отказ на два случая уже указывает на виновника, но не доказывает
его: отказ мог принадлежать контрольной строке.

Третья и доказывает — контроль ОДИН, плюс `Result` в позиции без `??`: зелено, `rc=0`.

**Что из этого следует для объёма волны:** `Result` в подмножестве novac ЕСТЬ как тип; сужен
ровно оператор `??`. Блокера «сначала внести Result в подмножество» не существует.
