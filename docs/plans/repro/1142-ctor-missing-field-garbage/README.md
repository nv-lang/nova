# Репро №1142 — конструктор записи без поля: собирается и печатает мусор

Строка реестра: [221.1 №1142](../../221.1-bug-sweep.md). Расхождение —
[274.12](../../274.12-novac-divergences.md), направление 1. Найдено пробой во время волны
[274.7 В14](../../274.7-subset-to-spec.md).

## Как повторить

Половины — в разных каталогах: папка в Nova есть один модуль.

```sh
./nova-cli/target/release/nova build <каталог>/probe.nv   # оракул
NOVA_STD_PATH="$PWD/std/src" ./novac/target/novac.exe check <каталог>/probe.nv
```

- [`bad.nv.txt`](bad.nv.txt) — `Point { x: 1 }` при объявленных `x` и `y`, печатает и `p.y`;
- [`ok.nv.txt`](ok.nv.txt) — то же с обоими полями.

## Что получилось (2026-09-16)

| | оракул | Карина |
|---|---|---|
| поле пропущено | **собирается без единой диагностики** | отвергает: «this record construction omits a declared field (D17)» |
| оба поля на месте | собирается | 0 диагностик |

**Запуск собранного оракулом бинаря** печатает `1` и мусор, РАЗНЫЙ при каждом прогоне:

```
run1: 1 1865325339888
run2: 1 2905450931440
run3: 1 2752327181552
```

Разные значения при одинаковой программе и есть доказательство, что читается
неинициализированная память, а не какое-нибудь умолчание.

## Почему это тяжелее соседних записей

Спека прямо: «Construction всегда требует все обязательные поля»
(`spec/decisions/02-types.md:152`). У №1121 и №1141 отказ хотя бы приходит — от `clang`, — и
сломанный артефакт наружу не выходит. Здесь **не приходит ниоткуда**, и артефакт выпускается.

И главное, чего не видно из самой пробы: **оракулом собирают Карину**. Носитель этой формы
в `novac/src` отравил бы бутстрап, а недетерминированный мусор читался бы как плавающая
ошибка Карины.

## Что проверено и чего проверка НЕ доказывает

Прогон `novac check` по всем 70 файлам `novac/src` (3302 диагностики, названо 68 файлов) дал
**0** носителей этой формы. Но прогон пофайловый, а проверка требует знать объявленные поля
типа: если тип объявлен в соседнем файле, она может не сработать вовсе. Поэтому «0» здесь —
не «их нет», а «этой меркой не видно». Прямым доказательством была бы проверка в чекере
оракула плюс негативная фикстура.
