# Литерал обработчика внутри тела операции другого литерала (Э.9 шаг 3)

Две пробы. Внутренний литерал (`Random`) захватывает `mut seen` функции `main`.
Внешний литерал (`ResourceTrace`) в `outer_reads` сам двигает `seen`, а в
`outer_silent` не трогает его вовсе.

| проба | оракул (`nova build`, main 30cc17793) | Карина (p274-m700, 2026-09-30) |
|---|---|---|
| `outer_reads.nv.txt` | НЕ СОБИРАЕТ: `_nova_handler_lit_2_ctx->_nv_fv__nova_handler_lit_2_seen = &seen;` — `seen` не локал функции операции | `a 41 7` / `b 142 7` / `202`, exit 0 |
| `outer_silent.nv.txt` | не собирает, та же строка | `a 7` / `b 7` / `200`, exit 0 |

Вывод Карины совпал с посчитанным вручную (аргументы `println` вычисляются слева
направо: `base + seen` раньше, чем `Random.u64()` сдвигает счётчик).

Почему это не фикстуры `novac/fixtures/with_lit/pos_*`: этап 2 дифференциала
сверяет поведение с оракулом, а оракул эти файлы не собирает. Когда дефект
оракула починят (строка реестра 221.1 — `№TBD`, заводит интегратор), обе пробы
переезжают в `novac/fixtures/with_lit/` под именами `pos_2.nv` и `pos_3.nv`.
Шапка `module with_lit.pos_2` / `pos_3` в них уже стоит.

Как Карина прогнана без оракула: `novac emit`, затем `clang` с флагами из кэша
смоука (`cflags-<ключ>.argv`, `link-<ключ>.argv`, `prelude-<ключ>.pch`), затем
запуск. В коде правку держит тест `pipeline/with_test.nv`: вложенный литерал —
захват захвата — проверяется счётом строк заполнения контекста.
