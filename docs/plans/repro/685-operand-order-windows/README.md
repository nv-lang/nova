# №685: операнды с эффектом вычисляются справа налево — на Windows и без всякого подъёма

Реестр 221.1, №685 (кодогенная половина). Замер помощника nova-88 2026-10-02, при работе
над №1627. Это НЕГАТИВНАЯ проба: вывод нарушает норму, и строка открыта.

## Норма

D484: порядок вычисления — слева направо, и он наблюдаем. Операнды бинарного
оператора и аргументы вызова вычисляются в порядке записи.

## Замер

`ord.nv.txt` (переименовать в `ord.nv`, собрать оракулом), `main` 0dfec1135,
Windows 11, clang 22.1.5, цель x86_64-pc-windows-msvc:

```sh
nova build ord.nv -o ord.exe && ./ord.exe
```

| строка | норма | оракул (`windows-clang.out`) |
|---|---|---|
| `mark("p", 1) + mark("q", 2)` | `p q 3` | `q p 3` |
| `add3(mark("a1", 1), mark("a2", 2), mark("a3", 3))` | `a1 a2 a3 6` | `a3 a2 a1 6` |
| `add3(mark("x1", 1) + mark("x2", 2), 0, 0)` | `x1 x2 3` | `x2 x1 3` |

В пробе нет ни `??`, ни `?`, ни `match`: оракул кладёт оба операнда в ОДНО выражение
C, а C порядок их вычисления не задаёт, и clang на этой цели берёт справа налево.
README пробы №1627 («без `??` порядок верен») мерил на Linux, где clang случайно
идёт слева направо; норма от платформы не зависит.

## Связь с №1627

№1627 чинит другой путь к тому же нарушению: форма, пишущая операторы (`??`, `?`,
`match`-значение), уходила ПЕРЕД всем выражением. После фикса №1627 эти три строки
печатают то же самое — они его предметом не являются. Клетки «два вызова в одном
выражении» перенесены сюда из фикстуры №1627 (решение интегратора 2026-10-02).
