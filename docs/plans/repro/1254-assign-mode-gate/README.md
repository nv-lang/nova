# Проба к реестру №1254 -- присваивание `ro`-привязке принималось молча

## Находка

НАЙДЕНО ОХОТНИКОМ 2026-09-21 (novac, клетка `check`×К4), отчёт
`docs/dev/hunts/novac/2026-09-21-check-k4.md`, раздел Н5. Приоритет
поднят до К1: молчаливо принятый код не просто неверно диагностирован --
он СОБИРАЕТСЯ И РАБОТАЕТ, нарушая гарантию иммутабельности языка.

## Минимальные репро, все четыре формы

`p1-simple.nv.txt`:
```nova
fn f() -> int {
    ro x = 1
    x = 2
    x
}
```

`p2-compound.nv.txt`:
```nova
fn f() -> int {
    ro x = 1
    x += 2
    x
}
```

`p3-param.nv.txt`:
```nova
fn f(x int) -> int {
    x = 5
    x
}
```

`p4-field.nv.txt`:
```nova
type Pt value { n int }

fn f() -> int {
    ro b = Pt { n: 1 }
    b.n = 2
    b.n
}
```

Оракул отказывает всем четырём (`E_LOCAL_NOT_MUT` на первых трёх,
`E_READONLY_FIELD` на четвёртой). novac принимал все четыре молча.

## Замер ДО фикса

`rc=0` на всех четырёх, ноль диагностик -- программа компилируется и
работает.

## Замер ПОСЛЕ фикса

```
p1-simple: "cannot assign to `x` -- it is bound `ro`, and only a `mut`
  binding may be reassigned; ... (D184, E_LOCAL_NOT_MUT)"
p2-compound: тот же код, тот же путь -- компонент лежит в ОДНОЙ двери
  с простым присваиванием (см. «Корень» ниже).
p3-param: тот же код -- параметр без `mut` связан РОВНО тем же образом,
  что и `ro`-локал (`params.nv:152`, `param_mode_at`).
p4-field: "cannot mutate through `b` -- it is bound `ro`, and the
  binding governs every field or index reached through it; ...
  (D175, E_READONLY_FIELD)"
```

Контроль (`mut x = 1; x = 2` и `mut b = Pt{...}; b.n = 2`) -- `rc=0`,
без изменений.

## Корень

Режим привязки (`ro`/`mut`/`consume`) записан у каждой привязки
(`scope.nv:131`, `Scope @mode_of_name`) и уже спрашивается на вызове
(`type_of.nv:129`, `class_of_binding`, кладёт режим в ключ вызова) --
но дверь присваивания (`assign_rules.nv`, `@assigned_operand_type` /
`@assigned_value_type`, «THE ASSIGNMENT DOOR») судила ТОЛЬКО тип
значения и ни разу не спрашивала режим цели.

## Фикс

Один новый гейт, `@report_if_assign_target_not_writable`, вызванный
ОДИН РАЗ на входе `@assigned_operand_type` -- общей точке для простого
(`Set`) и составного (`Update`) присваивания, поэтому формы 1 и 2 чинятся
одним вызовом. Гейт:

1. находит КОРЕНЬ цели -- имя под любой цепочкой полей/индексов
   (`b.n`, `arr[0].n`) через новую `assign_target_root`, рекурсивно
   спускаясь по `FieldAccess`/`Index` до `Name`; цель без связанного
   корня (результат вызова, чужой временный) не его вопрос;
2. если корень не связан в `@scope` -- не его вопрос (может быть
   модульная константа, другое правило);
3. если связан, но НЕ `ModeMut` -- отказ. Форма 3 (параметр без `mut`)
   попадает под ТОТ ЖЕ код, что форма 1 (простой локал), потому что
   параметр без `mut` связывается в `@scope` через `@bind` РОВНО тем
   же путём, что и `ro`-локал (`params.nv:152`).

Два текста сообщения, а не один -- то же расщепление, что у оракула
(Plan 124.8 / D175 amend, «binding dominates»): цель САМА есть имя --
`E_LOCAL_NOT_MUT`; цель ДОСТИГНУТА через поле/индекс -- `E_READONLY_FIELD`,
даже если само поле не помечено `ro` -- привязка домінирует над меткой
поля, ровно как у оракула.

**Что фикс НЕ делает** (оговорка про носителя из самой строки реестра):
не переносит оракульскую L2-механику (`ro T`/`mut T` content-view на
типе привязки, Plan 147/D246 R2-split) -- novac сегодня не разбирает
такой синтаксис вовсе, так что переносить нечего; когда/если он
появится в подмножестве, это отдельная волна на ТОЙ ЖЕ двери.
