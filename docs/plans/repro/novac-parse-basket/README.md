# Корзина парсера novac: из числа — в очередь форм

**Заказ:** окно Карины (nova-d0), 2026-09-20 14:19. Требовалось вскрыть замером
блок «novac did not parse this» в остатке самосборки: сколько в нём ФОРМ, а не
диагностик. Вердиктов здесь нет — только замер, пробы и контроли; что чинить и в
каком порядке, решает хозяин компилятора.

## 1. Замер: первый отказ каждого файла

Полная таблица — `first-refusal-per-file.txt` (там же команда и знаменатели).
Кратко: **диагностик всего 355; из них корзины 44 в 15 файлах; строк вывода вне
JSON — 0.**

**Расхождение с заказом названо, а не сглажено:** в задании стояло 38 отказов
корзины, у меня 44. Числа сняты разными прогонами и, возможно, с разным списком
файлов; я не устанавливал причину расхождения — знать её полезно, но это
отдельный замер, и выдавать одно число за другое нельзя.

Считается ПЕРВЫЙ отказ каждого файла: одна непрочитанная конструкция даёт
россыпь спанов восстановления, и счёт отказов мерит длину восстановления, а не
число форм.

Два файла исключены поимённо по указанию заказчика (на них ICE, а ICE обрывает
прогон и делает счёт функцией порядка аргументов): `emit_c/emit_place.nv`,
`lower/lowering.nv`.

## 2. Семьи форм: что показали пробы

У каждой пробы — КОНТРОЛЬ, соседняя форма, которая обязана приниматься. Проба
без контроля ничего не сужает: падать может не то, на что думаешь.

### ПОДТВЕРЖДЕНО: форма не читается (проба красная на разборе, контроль — нет)

| каталог | форма | контроль | где встречено |
|---|---|---|---|
| `postfix-question/` | `ro r = pick(x)?` | то же без `?` — чисто | resolve, defs, sem |
| `tuple-in-variant-pattern/` | `Some((first, cnt)) => …` | `Some(first) => …` — разбирается (падает уже на применённой сумме) | check/exprs, emit_c/emit_interp |
| `if-pattern-binding/` | `if Look.One(_) = got {` | `match got { … }` — чисто | resolve/resolve_test |
| `qualified-variant-record-ctor/` | `Node.Branch { id, kind }` | `Node.Leaf(v)` — на разборе чисто | tree/tree |

Оговорка к последней строке: у записи-варианта отказ стоит ДВОЙНОЙ — сама
объявленная форма названа как невкомпилированная («a record-form variant is not
compiled yet»), и поверх этого конструктор не разбирается. То есть починка
разбора одна эту семью не закроет.

### НЕ ВОСПРОИЗВЕЛОСЬ: строка из корзины сама по себе читается

| каталог | форма | что показала проба |
|---|---|---|
| `hex-literal-pattern/` | `0x7E => { … }` | и проба, и контроль ЧИСТЫ |
| `multiline-array-of/` | многострочный `[]int.of( … )` | чисто |
| `option-arm-binding/` | `Some(v) => v` | разбирается; отказ ДРУГОЙ — «`match` on an applied sum (`Option[int]`) … E2-b2» |
| `record-literal-field-call/` | `Tok { kind: 1, text: t }` в теле `=>` | чисто |

**Это и есть главный результат замера, а не пустая половина.** Первый отказ
корзины в файле НЕ ОБЯЗАН указывать на причину: в четырёх случаях из восьми
форма, стоящая в точке отказа, разбирается в одиночку. Значит для этих файлов
нужна проба С КОНТЕКСТОМ (что стоит выше по файлу), а не по строке.

Срезы `t[..2]` (literal_rules, mangle, parse) отдельной пробой не проверялись —
это известная строка реестра 1170, так указано в задании.

## 3. Чем куплены сами пробы

Три контроля в первой редакции НЕ ЧИТАЛИСЬ сами, и клетки не доказывали ничего.
Причины найдены сверкой с исходниками novac, а не по памяти:

* запись объявляется `export type Token {` — БЕЗ знака равенства (`lex/lex.nv:229`);
* `use` — занятое слово: функция с таким именем не разбирается, и это выглядело
  как отказ проверяемой формы;
* в пробе многострочного `[]T.of(` подводил не разбор, а отсутствие instance
  `Vec` для пользовательского типа в оболочке — с `int` форма чиста.
