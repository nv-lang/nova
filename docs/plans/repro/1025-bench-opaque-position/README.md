# №1025 — `bench.opaque` в не-трейлинг позиции роняет кодоген

Пробы перенесены сюда из `/tmp` 2026-09-07 по требованию интегратора, и требование верное:
проба, живущая во временном каталоге, исчезнет к утру, а строка реестра на неё ссылается.

**Компилятор:** ветка `p283-float-parse`, сборка после фикса №1020 (`self_return_lower` проведён
в бенч-драйвер), `cargo build --release` `EXIT=0`.

**Команда** (для каждого файла — переименовать `.nv.txt` → `.nv`):

```sh
nova-cli/target/release/nova.exe bench run <файл>.nv --samples 3 --warmup-ms 20 --time-budget 1
```

## Что показали пробы

| проба | форма | вердикт |
|---|---|---|
| `a_binding` | `ro _ = bench.opaque(s.to_f64())` в теле `for` | **ICE** `internal error at emit_c.rs:3439: [E_CODEGEN_TYPE_UNKNOWN] method call \`.opaque\` return type unknown; obj_ty="" obj=Ident(bench)` |
| `b_stmt` | `bench.opaque(s.to_f64())` последним выражением тела `for` | **ЗЕЛЕНО**, печатает `median:` |
| `c_int` | `ro _ = bench.opaque(i + 1)` в теле `for` | **ICE**, тот же вердикт |

**Что из этого следует, и это половина диагноза.** Пробы `a` и `c` различаются только ТИПОМ
аргумента — `Result[f64, ParseFloatError]` против `int`, — и падают одинаково. Значит дело НЕ в
типе аргумента. Проба `b` отличается от `a` только ПОЗИЦИЕЙ вызова.

**Уточнение до конца, замеренное на моём же бенче** (`bench/micro/parse_float.nv` до правки):
там `bench.opaque(acc)` стоял обычным оператором ПЕРЕД `bench.elements(1000)` — и падал так же,
хотя биндинга `ro _ =` не было. После перестановки (`elements` перед `opaque`, то есть `opaque`
стал последним выражением блока) прогон дал `rc=0` и все пять наборов чисел.

**Три формы, которые РАБОТАЮТ** (перечень нужен, иначе следующий будет искать заново):

1. последнее выражение своего блока — `bench/micro/hello.nv:6`, `bench.opaque(42)` внутри
   `measure { … }`;
2. правая часть присваивания — `bench/micro/arith.nv:9`, `acc = bench.opaque(acc + i)`;
3. последнее выражение тела `for` — проба `b_stmt` выше.

**Падает** позиция обычного оператора, за которым в блоке есть ещё что-нибудь.

## Чего пробы НЕ доказывают

Они не показывают, ЧЬЯ это половина — чекер не аннотирует тип выражения или эмиттер не
спрашивает. Вердикт называет `obj_ty=""` для `Ident(bench)`, то есть у самого объекта харнесса
нет типа в этой позиции; но какая из сторон обязана его поставить, пробами не определить, и
строка реестра поэтому говорит «чекер не аннотирует, эмиттер не спрашивает» как ДВА кандидата,
а не как установленный корень.
