# Репро №1141 — фигурный паттерн по несуществующему полю: `check` молчит, падает clang

Строка реестра: [221.1 №1141](../../221.1-bug-sweep.md). Расхождение записано в
[274.12](../../274.12-novac-divergences.md) направлением 1. Найдено пробой во время волны
[274.7 В14](../../274.7-subset-to-spec.md).

## Как повторить

Половины лежат в РАЗНЫХ каталогах намеренно: папка в Nova — один модуль, и два `main`
рядом столкнулись бы раньше предмета.

```sh
# оракул
./nova-cli/target/release/nova build <каталог>/probe.nv
# Карина
NOVA_STD_PATH="$PWD/std/src" ./novac/target/novac.exe check <каталог>/probe.nv
```

- [`bad.nv.txt`](bad.nv.txt) — `ro { nope, .. } = p` по записи без поля `nope`;
- [`ok.nv.txt`](ok.nv.txt) — то же самое с объявленным полем; отличие в одном имени.

## Что получилось (2026-09-16)

| | оракул | Карина |
|---|---|---|
| `{ nope, .. }` | **чекер молчит**, эмитит C, падает clang: `no member named 'nope' in 'struct NovaValue_Point'` | отвергает: «a brace destructuring binding names a field this type does not declare (D411)» |
| `{ x, .. }` | собралось | 0 диагностик |

## Почему это дефект, а не строгость Карины

D411 (`spec/decisions/03-syntax.md:12195`) описывает фигурный паттерн в биндинге как
match'евский: у паттерна не может быть поля, которого нет у типа. Отказ обязан приходить от
компилятора Nova и говорить о программе. Здесь он приходит от компилятора C и говорит о
структуре C — пользователь читает не про свой код, а про чужой.

## Границы этой пробы

Показана форма с `..` (частичный список полей). Полный список без `..` не пробовался,
носитель в `std` не искался. Фикс носителя приёмкой не считается: класс закроет проверка в
чекере оракула плюс негативная фикстура.
