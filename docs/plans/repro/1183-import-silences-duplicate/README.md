# №1183 — СВОЙСТВО названо: молчит не модуль, а ИМЯ, объявленное в импортированном модуле

**Заказ:** интегратор, 2026-09-20. В приёмку строки записано требование назвать
СВОЙСТВО, а не носитель: `std.encoding.serde` глушил отказ, а
`std.collections.vec` и `std.time.duration` — нет, значит дело в чём-то, что
есть у одного и нет у других. Мерилось ПЕРЕБОРОМ ПРИЗНАКОВ, код не читался.
Вердикт по строке — интегратора.

## Свойство

**Отказ `duplicate top-level name` пропадает, когда дублируемое имя объявлено в
ИМПОРТИРОВАННОМ модуле** — безразлично, импортировано оно поимённо или нет, в
основном исходнике модуля оно живёт или в его тестовом peer-файле. Имя, которого
в импортированном модуле нет, отказ сохраняет.

`serde` оказался не при чём: он выглядел особенным лишь потому, что первые пробы
дублировали `Node` и `IntBox` — а они объявлены в ЕГО тестовых peer-файлах, то
есть принадлежат модулю по D281 Rule C.

## Замеры

Ось «модуль × имя» (`matrix-module-x-name.py`); во всех случаях два peer-файла
потребителя объявляют один и тот же тип:

| импорт | дублируется | вердикт | проверено файлов |
|---|---|---|---|
| serde | `Node` (тестовый peer serde) | МОЛЧИТ | 1 из 2 |
| serde | `IntBox` (тестовый peer serde) | МОЛЧИТ | 1 из 2 |
| serde | `Zebra` (нигде) | **говорит** | 0 |
| vec / duration / без импорта | `Node`, `IntBox`, `Zebra` | **говорит** | 0 |

Ось «импортировано против объявлено» (`imported-vs-declared.py`), импорт один и
тот же — `std.time.duration.{Duration}`:

| дублируется | в модуле? | вердикт |
|---|---|---|
| `Duration` | да, импортировано поимённо | МОЛЧИТ |
| `DurationParts` | да, НЕ импортировано | МОЛЧИТ |
| `Monotonic` | да, НЕ импортировано | МОЛЧИТ |
| `Zebra` | нет | **говорит** |

Контрольная пара, снимающая «это про тестовые peer'ы»: `std.reflect` +
дублируемый `TypeShape` (объявлен В МОДУЛЕ) — МОЛЧИТ; тот же `std.reflect` +
`ReflPoint` — **говорит**, потому что `ReflPoint` живёт в `std/src/reflect_test.nv`,
а это ОТДЕЛЬНЫЙ модуль `std.reflect_test`, не peer. Правило выдерживает и этот
случай.

## Что это значит (границы, вердикт не мой)

* молчание — не «ошибки нет», а «проверен один файл из двух»: `PASS: 1` при двух
  файлах стоит в каждом глухом случае;
* `nova build` на том же дереве отказ ВЫДАЁТ — проверка и сборка расходятся в
  том, что считают ошибкой (замер в соседней пробе
  `../699-collision-positive-control/`);
* связь с №699 теперь измерима, а не предположительна: строка говорит об утечке
  ТЕСТОВОГО peer-файла импортированного модуля в единицу потребителя, и здесь
  видно, что имена импортированного модуля — включая объявленные в его тестовых
  peer'ах — гасят проверку peer-файлов ПОТРЕБИТЕЛЯ.
