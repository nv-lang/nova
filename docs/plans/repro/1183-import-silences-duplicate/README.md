# №1183 — СВОЙСТВО названо: молчит не модуль, а ИМЯ, объявленное в импортированном модуле

**Заказ:** интегратор, 2026-09-20. В приёмку строки записано требование назвать
СВОЙСТВО, а не носитель: `std.encoding.serde` глушил отказ, а
`std.collections.vec` и `std.time.duration` — нет, значит дело в чём-то, что
есть у одного и нет у других. Мерилось ПЕРЕБОРОМ ПРИЗНАКОВ, код не читался.
Вердикт по строке — интегратора.

## Свойство

**Отказ `duplicate top-level name` пропадает, когда дублируемое имя объявлено в
ИМПОРТИРОВАННОМ модуле** — безразлично, импортировано оно поимённо или нет, в
основном исходнике модуля оно живёт или в его тестовом peer-файле. Имя, которого
в импортированном модуле нет, отказ сохраняет.

`serde` оказался не при чём: он выглядел особенным лишь потому, что первые пробы
дублировали `Node` и `IntBox` — а они объявлены в ЕГО тестовых peer-файлах, то
есть принадлежат модулю по D281 Rule C.

## Замеры

Ось «модуль × имя» (`matrix-module-x-name.py`); во всех случаях два peer-файла
потребителя объявляют один и тот же тип:

| импорт | дублируется | вердикт | `PASS` |
|---|---|---|---|
| serde | `Node` (тестовый peer serde) | МОЛЧИТ | 1 |
| serde | `IntBox` (тестовый peer serde) | МОЛЧИТ | 1 |
| serde | `Zebra` (нигде) | **говорит** | 0 |
| vec / duration / без импорта | `Node`, `IntBox`, `Zebra` | **говорит** | 0 |

Колонка `PASS` оставлена ЧИСЛОМ и без толкования: как показано ниже, она считает
единицы проверки, а не файлы, и читать её как «сколько файлов осмотрено» нельзя.

Ось «импортировано против объявлено» (`imported-vs-declared.py`), импорт один и
тот же — `std.time.duration.{Duration}`:

| дублируется | в модуле? | вердикт |
|---|---|---|
| `Duration` | да, импортировано поимённо | МОЛЧИТ |
| `DurationParts` | да, НЕ импортировано | МОЛЧИТ |
| `Monotonic` | да, НЕ импортировано | МОЛЧИТ |
| `Zebra` | нет | **говорит** |

Контрольная пара, снимающая «это про тестовые peer'ы»: `std.reflect` +
дублируемый `TypeShape` (объявлен В МОДУЛЕ) — МОЛЧИТ; тот же `std.reflect` +
`ReflPoint` — **говорит**, потому что `ReflPoint` живёт в `std/src/reflect_test.nv`,
а это ОТДЕЛЬНЫЙ модуль `std.reflect_test`, не peer. Правило выдерживает и этот
случай.

## Что это значит (границы, вердикт не мой)

* молчание — не «ошибки нет», но и НЕ «проверен один файл из двух»: `PASS: 1`
  печатает и ЧИСТЫЙ пакет из двух и из трёх файлов, то есть это счёт единиц
  проверки, а не файлов (поправка к моему же прежнему утверждению). Молчит
  ИМЕННО отказ о дубле: ошибка другого рода в том же peer-файле выдаётся;
* `nova build` на том же дереве отказ ВЫДАЁТ — проверка и сборка расходятся в
  том, что считают ошибкой (замер в соседней пробе
  `../699-collision-positive-control/`);
* связь с №699 теперь измерима, а не предположительна: строка говорит об утечке
  ТЕСТОВОГО peer-файла импортированного модуля в единицу потребителя, и здесь
  видно, что имена импортированного модуля — включая объявленные в его тестовых
  peer'ах — гасят проверку peer-файлов ПОТРЕБИТЕЛЯ.

## ГРАНИЦА МОЛЧАНИЯ — выключается ОДНА проверка, а не обход peer-файлов

Заказ интегратора: различить «молчит отказ о дубле» и «peer-файл не разбирается
вовсе». Ответ — ПЕРВОЕ, и он лёгкий из двух.

| режим | что подсунуто | команда | вердикт дословно |
|---|---|---|---|
| check | в peer-файле ошибка ДРУГОГО рода (`no_such_name_here()`), БЕЗ импорта | `nova check <pkg>/src` | `peer.nv:2:30: error: undefined identifier`, rc=1 |
| check | то же, С импортом `duration` | `nova check <pkg>/src` | `peer.nv:2:30: error: undefined identifier`, rc=1 |
| check | дубль имени, ТРИ файла, БЕЗ импорта | `nova check <pkg>/src` | `peer.nv:2:1: error: duplicate top-level name`, rc=1 |
| check | дубль имени, ТРИ файла, С импортом | `nova check <pkg>/src` | ошибок нет, rc=0, `PASS: 1` |
| test | дубль имени, БЕЗ импорта | `nova test <pkg>/src` | ошибок нет, rc=0, `PASS: 0 FAIL: 0` |
| test | дубль имени, С импортом | `nova test <pkg>/src` | ошибок нет, rc=0, `PASS: 0 FAIL: 0` |

**Значит peer-файлы РАЗБИРАЮТСЯ И СУДЯТСЯ:** ошибка другого рода в том же файле
выдаётся и с импортом, и без. Молчит ровно проверка дублей.

**Трёх файлов хватает так же, как двух** — молчание не зависит от числа peer'ов.

**Третий режим расходится с обоими:** `nova test` НЕ сообщает о дубле ДАЖЕ БЕЗ
импорта, тогда как `check` без импорта отказывает, а `build` отказывает всегда.
То есть форм расхождения три, а не две.

## ЗНАМЕНАТЕЛЬ `PASS`, и он опровергает моё же прежнее утверждение

`PASS: 1` НЕ значит «проверен один файл». Замер: чистый пакет из ДВУХ файлов —
`PASS: 1`; чистый пакет из ТРЁХ файлов — тоже `PASS: 1`; с импортом и без —
одинаково. Число считает единицу проверки, а не файлы.

Отсюда прямое следствие, которое я обязан назвать сам: **моё наблюдение «`nova
check <каталог>` считает один файл из двух» было ВЫВОДОМ ИЗ НЕВЕРНО ПРОЧИТАННОГО
ЧИСЛА.** Факт, который остаётся: в выводе назван только `main.nv`. Вывод, который
снимается: «второй файл не проверялся» — он проверяется, что доказано ошибкой
другого рода в нём же.
