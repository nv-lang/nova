# №699 — положительный контроль найден, и вместе с ним случай, где он молчит

**Заказ:** интегратор, 2026-09-20. Новая приёмка №699 требует СНАЧАЛА показать,
что компилятор про столкновение имён вообще умеет говорить: без этого «нет
диагностики» неотличимо от «нечего сказать». Вердикт по строке — его.

## 1. Форма, на которой компилятор ГОВОРИТ (это и есть контроль)

Два peer-файла ОДНОГО модуля объявляют один и тот же тип:

```
src/main.nv:  module p699d   type Node { ro a int }   fn main() …
src/peer.nv:  module p699d   type Node { ro b int }   export fn touch() …
```

`nova check src` →
`src/peer.nv:2:1: error: duplicate top-level name `Node``, rc=1.

Форма проверена не в одиночку, а матрицей (`matrix.py`): дубль **метода**,
**свободной функции**, **типа** и **константы**, каждый — в одном файле и в двух
peer-файлах. **ГОВОРЯТ ВСЕ СЕМЬ.** Значит диагностика столкновения существует и
покрывает обе оси; отправная точка для №699 есть.

## 2. И ровно здесь нашёлся случай, где она МОЛЧИТ

Тот же дубль типа в тех же двух файлах, единственное отличие — строка `import`
в `main.nv` (`import-silences.py`):

| вариант | rc | PASS | что сказано |
|---|---|---|---|
| без импорта | 1 | 0 | `duplicate top-level name \`Node\`` |
| `import std.collections.vec` | 1 | 0 | `duplicate top-level name \`Node\`` |
| `import std.time.duration` | 1 | 0 | `duplicate top-level name \`Node\`` |
| **`import std.encoding.serde`** | **0** | **1** | **ошибок нет** |
| тот же случай, но `nova build` | 1 | — | `duplicate top-level name \`Node\`` |

**Глушит не «любой импорт», а именно этот** — два других std-модуля отказ
сохраняют.

**ПОПРАВКА 2026-09-20, и она снимает моё же утверждение:** здесь стояло, что
`PASS: 1` значит «проверен один файл из двух». ЭТО НЕВЕРНО. Замер: ЧИСТЫЙ пакет
из двух и из трёх файлов печатает то же `PASS: 1`, то есть число считает ЕДИНИЦУ
ПРОВЕРКИ, а не файлы. Что peer-файлы разбираются, доказано отдельно: ошибка
ДРУГОГО рода (необъявленное имя) в peer-файле выдаётся и при импорте, и без него.

**Проверка и сборка расходятся в том, что считают ошибкой:** `check` молчит,
`build` на том же дереве отказывает.

## 3. Что это даёт №699 (вердикт не мой)

Строка №699 — про утечку ТЕСТОВОГО peer-файла `std.encoding.serde` в единицу
потребителя. Здесь видно, что импорт того же самого модуля выключает у `check`
проверку peer-файлов ПОТРЕБИТЕЛЯ. Это может быть тот же механизм, а может быть
соседний; различить их — работа того, кто возьмётся чинить, и у неё теперь есть
обе половины: форма, на которой отказ ЕСТЬ, и форма, на которой он пропадает.

## 4. Границы замера

* мерился `nova check` и `nova build`; `nova test` в этой пробе не гонялся;
* бинарь `nova.exe` главного дерева, 19 444 736 байт, собран 02:17 2026-09-20 —
  два замера разными бинарями несравнимы, поэтому версия названа;
* почему молчит именно serde — НЕ выяснялось. Названо то, что измерено: импорт
  этого модуля меняет, судится ли peer-файл потребителя.

Запуск:

```sh
python docs/plans/repro/699-collision-positive-control/matrix.py
python docs/plans/repro/699-collision-positive-control/import-silences.py
```

Обе пробы берут бинарь из `NOVA=` и дерево из `NOVA_TREE=`, если заданы.
