# Улики окон: репро, пробы, замеры

Здесь лежит то, на что ссылаются реестр, спека и планы как на **доказательство**:
файл-репро дефекта, проба поведения, лог замера. Не тесты — их место в
`spec_tests/` и рядом с модулем; не чекпоинты хода работы — их место в
`docs/plans/wip/`.

## Правило (реестр №695)

1. **Улика, на которую есть ссылка из реестра/спеки/плана, живёт здесь** —
   в `docs/plans/repro/<номер-или-план>/…` или плоско с префиксом номера. Не в
   корне репозитория, не в `scratch*`, не в `probes-*`. Слово «scratch» в
   имени означает «удали меня»; спека, обосновывающая утверждение ссылкой на
   папку с таким именем, стоит на песке. Ровно так стояло D-утверждение о
   `consume`-передаче (`02-types.md`, «подтверждено эмпирически …
   `scratch465/probe1-3.nv`») — и обе половины реестра №457.
2. **Исходники Nova хранятся с суффиксом `.nv.txt`.** Суффикс несущий: он
   держит улику вне раннера, линта и стражей, которые ходят по `**/*.nv`
   (их восемь на 2026-08-16). Улика — не фикстура; фикстура обязана быть
   зелёной, улика обязана воспроизводить дефект и потому часто красная. Если
   улика становится тестом — она переезжает в `spec_tests/` и меняет суффикс.
2а. **ИСКЛЮЧЕНИЕ (2026-09-04, интегратор): проба, которую ЗАПУСКАЮТ по
   записанной команде, остаётся `.nv`.** П. 2 обоснован тем, что суффикс
   держит улику вне стражей, ходящих по `**/*.nv`. Пробу, вызываемую по
   явному пути (`sh scripts/tools/novac-e1-smoke.sh <проба>.nv`,
   `novac check <проба>.nv`), никто не подметает — её ЗАПУСКАЮТ, и smoke
   принимает только `.nv`. Требовать для неё `.nv.txt` значит сломать
   команду воспроизведения, то есть нарушить п. 3 ради буквы п. 2.
   Замер, из которого выросло исключение: строки реестра №892, №900, №901
   называют пути к `.nv` под `repro`, а №900 несёт готовую команду сборки —
   переименование обесценило бы все три.
   **Граница исключения:** оно про пробы, у которых команда ЗАПИСАНА (в
   строке реестра, в README каталога или в плане). Улика, которую только
   читают, остаётся `.nv.txt` — и таких большинство.
   **Механически это НЕ различается**, и сказано прямо: дешёвого признака
   «вызываемая проба против читаемой улики» в дереве нет — замерено
   2026-09-04 тремя способами (имя в README каталога — 8 из 57; путь назван
   где-либо вне каталога — 20 из 57; README в каталоге — 57 из 57, то есть
   признак бесполезен). Поэтому исключение — для ЧЕЛОВЕКА, а страж
   `check-repro-evidence-suffix` судит только РОСТ числа и допускает его со
   строкой-причиной, как это заведено у `accumulation.baseline`.

3. **Ссылка обязана указывать на существующий файл.** До этой записи в
   `docs/plans/wip/` было четыре ссылки на `docs/plans/repro/*.nv`, за которыми
   не стояло ни одного файла: окна ссылались на улику и не клали её. Ссылка
   без файла — не доказательство.
4. **Черновики окна, на которые никто не ссылается, в репозиторий не
   попадают.** Рабочее место окна — его worktree и `scratch-opencode/`
   (штатный, под `.gitignore`); корень репозитория — витрина (№607).

## Что держит правило

* `.gitignore`: `scratch*/`, `probes-*/`, `.p[0-9]*/`, `.gate-*.log`,
  `.conf-*.log` в корне — черновик окна не попадёт в индекс случайно; исключение
  — `scratch-opencode/` (документирован в `docs/dev/opencode-runbook.md`).
* `scripts/guards/check-repo-root-clean.sh` — с 2026-08-16 проверяет и
  **каталоги** корня по закрытому списку, не только файлы (до этого каталоги
  были ему невидимы: `grep -v '/'` — и через эту дыру прошли пять черновиков).

## Замер 2026-09-04: у правила нет механизма

Правило (п. 2) соблюдается НЕ ВЕЗДЕ, и это замерено, а не предположено: под
`docs/plans/repro/` лежат **57 файлов `.nv`** без суффикса `.txt` — больше всего в
`p274-6-v34-step0` (17), `p274-6-v32-step0` (7), `p274-6-v34b-step0` (6). Две из них
были моими (каталог `894-index-sugar-bypass/`), и переименовал я их только после
того, как соседнее окно сверило свои каталоги с моим.

**Стража у правила нет.** Проверено грепом по `scripts/guards/`: ни один страж не
судит суффикс улик.

**И заявленная правилом опасность сегодня НЕ ВОСПРОИЗВОДИТСЯ.** П. 2 обосновывает
суффикс тем, что «по `**/*.nv` ходят восемь стражей». Полный гейт 2026-09-04 прошёл
все свои ярусы при этих 57 файлах в дереве: те стражи ходят по `std/`,
`spec_tests/`, `novac/`, `examples/` — по названным каталогам, а не по дереву
целиком. То есть правило верно как ГИГИЕНА (улика не должна выглядеть фикстурой, и
переезд улики в тест обязан быть заметен переименованием), но его обоснование
описывает угрозу, которой в сегодняшнем дереве нет.

**Почему здесь замер, а не новый страж.** Заводить проверку под невоспроизводящуюся
угрозу — это цена в каждом прогоне гейта за защиту от того, чего не происходит;
конвенция стражей (`docs/dev/gate-guard-conventions.md`) прямо считает такую цену
долгом. Если правило нужно держать механизмом — страж дешёвый (один `find` плюс
база-храповик на нынешние 57), но заводить его должен тот, кто назовёт живую
причину. Пока причина одна: читателю легче отличить улику от фикстуры.

Запись оставлена, чтобы разрыв был ВИДЕН: правило без механизма и с 57
нарушениями выглядит соблюдаемым ровно до первой сверки.
