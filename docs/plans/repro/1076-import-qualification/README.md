# №1076 / №1077 — `import mod`: голое имя проходит, квалифицированный ТИП роняет C

Замер 2026-09-13, окно интегратора, по вопросу владельца («доступ к модулю должен
быть через `mod.func`, но сейчас в оракуле `func` доступен без `mod`; что говорит
спека?»). Спека отвечает прямо, и обе половины вопроса оказались верны.

## Что говорит норма

**D289** (`spec/decisions/07-modules.md`, «`import m` — last-segment qualified
namespace», amend option b, 2026-06-16), дословно:

> `import m` без `.{}` и без `as alias`… переопределить в qualified namespace —
> `import vec_iter` вводит имя `vec_iter` в scope, **доступ только через
> `vec_iter.Foo`**.

И тип там же, в примере самого D-блока: `import vec_iter` → `vec_iter.EnumerateIter`.
То есть `mod.Type` — **норма, а не отсутствующий синтаксис**.

## Пробы

Бинарь: `nova-cli/target/release/nova.exe`. Модуль-донор `lib_thing.nv.txt` кладётся
как `lib/thing.nv` рядом с пробой; команда из каталога пробы:

```sh
<repo>/nova-cli/target/release/nova build <проба>.nv -o /tmp/probe.exe
<repo>/nova-cli/target/release/nova check <проба>.nv
```

| проба | форма | `nova check` | `nova build` |
|---|---|---|---|
| `a_bare_name.nv.txt` | голое `make(7)` при `import lib.thing` | ✅ | ✅ `built` (7.26s) — **а по D289 доступ обязан быть только через `thing.make`** |
| `b_qualified_type.nv.txt` | `ro w thing.Widget = thing.make(7)` | ✅ **зелёный** | ❌ **падает C-компилятор** |

Вердикт пробы `b`, дословно:

## Что проба РАЗДЕЛИЛА, и это главное

Напрашивалось объяснение «квалифицированная форма просто не поддерживается». Оно
**неверно**: квалифицированный ВЫЗОВ работает — в том же файле `thing.make(7)`
сэмитился правильно, `nova_fn_3lib5thing4make`. Ломается ровно
**квалифицированный ТИП в позиции типа**: чекер его принимает, а эмиттер выпускает
имя `Nova_thing_Widget`, которого не объявлял никто.

Значит это не пробел грамматики, а **разрыв канала**: имя типа доезжает до эмиттера
в форме, которую тот не умеет отобразить в объявленный C-тип, и молча печатает её
как есть.

## Две разные строки, а не одна

* **№1076** — голое имя РЕЗОЛВИТСЯ там, где D289 требует квалификации. Компилятор
  **слабее** нормы: принимает больше, чем сказано. Цена — не косметика: код,
  написанный на голых именах, ломается в тот день, когда в другом модуле появится
  функция с тем же именем, и сломается он у ПОТРЕБИТЕЛЯ, а не у автора.
* **№1077** — квалифицированный тип даёт ЗЕЛЁНЫЙ `check` и красный `build`.
  Класс другой: не «норма против реализации», а «две половины реализации
  разошлись». Строки не дублируют друг друга и чинятся в разных местах.

## Для Карины (план 274.9 / 274.7)

Обе формы обязаны быть у Карины **с самого начала**, а не «как у оракула»:
голое имя при `import m` — отказ; `m.Type` в позиции типа — рабочая форма.
Иначе самохостинг унаследует оба дефекта, причём второй — в форме, которую
`novac check` не ловит по построению.
