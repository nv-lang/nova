# Пробы к строке реестра №1185 — `Option` над указателем теряет указательность

Три файла, снятые 2026-09-20 окном `nova-78` бинарём `nova-cli/target/release/nova`.
Улики ЧИТАЮТ; суффикс `.nv.txt` держит их вне раннера (правило №695 п. 2).

Команда одна на все три:

```sh
nova-cli/target/release/nova build --keep-artifacts <файл>
# затем грепнуть выпущенный C, ИМЕННО ЭТОГО файла (см. оговорку о методе ниже)
```

| файл | что в выпущенном C |
|---|---|
| `1-newtype-handle.nv.txt` | `nova_fn_take(NovaOpt_nova_int`, `nova_fn_take2(NovaOpt_nova_int` |
| `2-control-raw-pointer.nv.txt` | `nova_fn_takeraw(NovaOpt_nova_int` |
| `3-control-option-over-int.nv.txt` | `nova_fn_takeint(NovaOpt_nova_int` |

Дополнительно в первом файле: `typedef void* Nova_CHandle;` и
`typedef void* Nova_CHandle2;` — то есть САМИ ручки эмитятся верно. И `None` строится
как `{.tag = NOVA_TAG_Option_None}`, сравнение идёт по `a.tag` — обёртка с тегом на
месте, NPO не сработал.

**Что говорит норма.** D216 §7: «Nullable = `Option[*T]` только (NPO §7)», `None`
представляется как NULL, отдельной структуры не возникает. Сам блок числит `Ф.5 NPO
codegen (A19-A23)` в остатке работ — то есть отсутствие NPO новостью не является.
Новость в другом: (а) это касается и канона «непрозрачной ручки» из §3, и (б) полезная
нагрузка эмитится как `nova_int`, то есть потерян ТИП, а не только раскладка.

**Зачем три пробы, а не одна.** Первая — форма. Вторая снимает newtype вовсе: результат
тот же, значит указательность теряет `Option` при инстанциации, а не обёртка; без этого
контроля вывод звучал бы «newtype виноват», и чинили бы newtype. Третья (требование
интегратора) держит честным будущий ФИКС: правка, снёсшая обёртку у ВСЕХ `Option`,
прошла бы первые две и выглядела бы успехом — здесь структура с тегом законна и обязана
остаться.

**Оговорка о методе, и она куплена собственным промахом.** Первый прогон этих трёх проб
читал `ls -td …/build-*` — самый свежий каталог сборки, — и выдал ОДИН И ТОТ ЖЕ результат
для всех трёх файлов, включая имена функций из постороннего файла. Каталог был чужой:
проверка не мерила свой предмет. Правильный признак — искать C ПО ИМЕНИ пробы
(`…/build-*/<имя>.c`), а не по времени.

**Приёмка будущего фикса** (формулировка интегратора, принята): греп по выпущенному C
проверяет ОБА направления — что `NovaOpt_nova_int` у указательных форм ИСЧЕЗ и что на
его месте один указатель. Проверка только на «появился указатель» пройдёт и тогда, когда
рядом осталась старая структура.
