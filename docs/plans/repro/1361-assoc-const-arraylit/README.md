# Пробы к №1361 — assoc-const с массивным инициализатором не собирается

Заведено интегратором 2026-09-26 при разборе пути починки №701 (замена
обхода `builtins.nv` канонической формой `ro`/`const Type.NAME`, ЗАКРЫТ
2026-09-21 по registry 221.1 №701). Проба выполнена ПЕРЕД правкой
`builtins.nv`, не после — репро остановило работу до того, как код тронут.

Чекер зелёный, `nova build` падает. Контроль (МОДУЛЬНЫЙ, не ассоциированный
`const []T`) собирается и печатает верно — значит дело не в массивах вообще,
а именно в АССОЦИИРОВАННОЙ форме.

## Как запускать

Суффикс `.nv.txt` — улика вне раннера и стражей (см. README рядом,
`895-static-via-type-param`, тот же приём). Скопировать без `.txt` и вызвать:

```sh
cp docs/plans/repro/1361-assoc-const-arraylit/<файл>.nv.txt <файл>.nv
nova-cli/target/release/nova.exe check <файл>.nv
nova-cli/target/release/nova.exe build <файл>.nv -o <куда-нибудь>.exe
```

## Замер 2026-09-26 (интегратор, `nova-cli/target/release/nova.exe`)

| проба | что меняется | `check` | `build` |
|---|---|---|---|
| `assoc_const_array_scalars_fail.nv.txt` | `export const Box.NUMS []int = [1,2,3]` — ассоциированный const, массив СКАЛЯРОВ | ok | `codegen error: assoc const `Box.NUMS` codegen failed: non-constant expression in const declaration: ArrayLit(...)` |
| `assoc_const_array_records_fail.nv.txt` | то же, но массив ЗАПИСЕЙ (`[]Row`, поля-литералы) — форма, ближайшая к `builtins.nv`'s `universe` | ok | тот же класс отказа, тот же `ArrayLit(...)` |
| `module_level_array_ok.nv.txt` | КОНТРОЛЬ: `const NUMS []int = [1,2,3]` МОДУЛЬНЫЙ (не ассоциированный) | ok | собрано, печатает `3 2` |

**Что каждая доказывает.** `assoc_const_array_scalars_fail` и
`assoc_const_array_records_fail` дают БАЙТ-В-БАЙТ один и тот же класс отказа
независимо от типа элемента (скаляр или запись) — значит дефект не про
элемент, а про сам `ArrayLit` как форму RHS. `module_level_array_ok` отделяет
ось «массив» от оси «ассоциированный»: тот же массив-литерал на МОДУЛЬНОМ
уровне собирается штатно, значит рабочий путь эмиссии массивных констант уже
существует в компиляторе — просто не переиспользован для assoc-const.

## МЕСТО (прочитано, не правлено)

`compiler-codegen/src/codegen/emit_c.rs`, функция, лежащая рядом с
`ExprKind::Ident` (ссылка на другой const) и `ExprKind::Call` (явно
отвергается `E_CONST_NOT_CONSTEXPR`, комментарий цитирует
`[M-d200-assoc-const-composite-value]` — D200 расширил assoc-const ТОЛЬКО на
record-литералы, `emit_const_record_lit`, массивы туда не входили). У матча
нет ветки `ExprKind::ArrayLit` — она проваливается в safety-net `_ => Err(...)`,
общий для любой ещё не поддержанной формы.

## Почему не починено этим же окном

Фикс требует переиспользовать существующий (рабочий, судя по
`module_level_array_ok`) путь эмиссии массивных констант ДЛЯ assoc-const
контекста — сама ветка `_` не говорит, где тот путь лежит, и находка сделана
чтением, не полным прочтением всего модульного const-конвейера. Правка компилятора
(`compiler-codegen`, Rust) — не то, что стоит трогать в конце долгой смены;
доведено до найденного и точно расположенного дефекта, дальше — отдельным,
сосредоточенным заходом.
