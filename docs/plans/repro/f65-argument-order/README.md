# F65: порядок вычисления аргументов — посылка перепроверена (2026-09-20)

Волна 274.7 §Т стоит на замере от **2026-08-16**: оракул вычисляет аргументы
вызова СПРАВА НАЛЕВО, тогда как спека называет левый порядок нормативным и
наблюдаемым. Замеру месяц, и он определяет устройство правки — поэтому он
перепроверен, а не взят на веру.

## Проба

`order.nv.txt`: два аргумента — вызовы, каждый печатает свою метку.

```nova
fn take(a int, b int) -> int => a + b
fn main() { println(take(left(), right())) }
```

## Прогон оракулом, 2026-09-20

```
./nova-cli/target/release/nova build docs/plans/repro/f65-argument-order/order.nv.txt -o order.exe
./order.exe
```

Вывод:

```
right
left
3
```

**Порядок правый. Посылка держится.**

## Что это значит для волны

Снятие отказа F65 без подъёма аргументов во временные дало бы у Карины тот же
правый порядок (эмиттер печатает аргументы встроенно, а C порядок не
фиксирует) — то есть молча воспроизвело бы нарушение спеки.

Значит после починки **Карина и оракул разойдутся НАМЕРЕННО**, и правы будем мы:
строка в `novac/divergences.allow` плюс запись в 274.12. Это случай, которого в
реестре расхождений ещё не было: обычно там «оракул не собирает верную
программу», а здесь — «оракул собирает и выполняет НЕ В ТОМ ПОРЯДКЕ».

## Оговорка

Проба меряет ПОРЯДОК ПЕЧАТИ, то есть порядок ЭФФЕКТОВ, а не порядок вычисления
как таковой. Для наблюдаемости этого достаточно — спека говорит именно о
наблюдаемом порядке, — но если когда-нибудь понадобится отличить «вычислено» от
«напечатано», эта проба такого вопроса не закрывает.
