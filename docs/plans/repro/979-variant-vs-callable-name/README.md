# Пробы к №979 — имя варианта суммы и имя функции/константы сталкиваются

Найдено окном 274 (2026-09-05) при охоте по ИХ клетке `check × К2` в novac;
находка по ОРАКУЛУ передана мне и воспроизведена интегратором 2026-09-06 на
`main @ a080a2342` — копии их проб я не брал, написал свои с контролем.

## Что происходит

Чекер разрешает имя `Red` в ФУНКЦИЮ (типизирует результат как `int` — потому
сгенерированный Си и доходит до `nova_print_int`), а кодоген подставляет туда
КОНСТРУКТОР ВАРИАНТА.

```
error: passing 'NovaValue_Color' (aka 'struct NovaValue_Color') to parameter
       of incompatible type
```

## Как запускать

```sh
cp docs/plans/repro/979-variant-vs-callable-name/<файл>.nv.txt /tmp/t.nv
nova-cli/target/release/nova.exe check /tmp/t.nv
nova-cli/target/release/nova.exe build /tmp/t.nv -o /tmp/t.exe && /tmp/t.exe
```

## Замер 2026-09-06

| проба | форма | `check` | `build` | run |
|---|---|---|---|---|
| `variant_vs_fn` | `type Color enum Red \| Green` + `fn Red() -> int => 42` | **ok** | **ошибка Си** | — |
| `variant_vs_const` | то же, но `const Red = 5` | **ok** | **та же ошибка Си** | — |
| `ctrl_free_name` | `fn Crimson()` — имя не занято вариантом — КОНТРОЛЬ | ok | ok | `42` |

## Что доказывает контроль

Форма та же, отличается только имя. С незанятым именем программа собирается и
печатает `42`. Значит дело не в суммах и не в функциях по отдельности, а РОВНО
в столкновении имени варианта с именем другой сущности в той же единице
компиляции. И `const` показывает, что вызов ни при чём: достаточно любой
сущности, носящей имя варианта.

## Чем это ОТЛИЧАЕТСЯ от №962, и почему строка отдельная

У №962 кодоген выбирает не тот ВАРИАНТ (варианты разных сумм делят имя между
модулями), и её приёмка уже требует адресовать вариант парой «DeclId суммы +
индекс». Здесь кодоген выбирает не ту СУЩНОСТЬ — функцию против варианта, — и
адресация вариантов парой этого не решает: вопрос не «какой вариант», а «вариант
ли вообще». Корень общий (резолв по голому имени в кодогене), работа разная.

## Границы

Не мерил: столкновение имени варианта с именем ТИПА, с методом, с параметром;
и обратный порядок объявления (сперва `fn`, потом `type`). Не проверял, есть ли
у чекера намеренное правило старшинства — по симптому его нет, но чтения кода
под этим утверждением НЕТ.
