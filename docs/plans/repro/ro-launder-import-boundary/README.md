# Правило `ro`-launder не применяется за границей импорта (пробы к строкам реестра №TBD)

Найдено окном 274 (`nova-6e`) 2026-09-13, побочно: `nova check` отказал на собственном
исходнике `novac` (`novac/src/emit_c/emit_flow.nv:171`, `mut cur = at` при `at BlockId`), а
`nova build novac/src/main.nv` тот же файл собрал. Разбор расхождения вскрыл две вещи, и
вторая оказалась звучностью.

Номера присваивает интегратор; каталог назван по предмету, а не по номеру, чтобы не
изобретать его самому — переименовать под номер можно одной командой.

## Что здесь лежит

| файл | что показывает |
|---|---|
| `mod/g.nv` + `gmain.nv` | **дыра звучности**: проба G строки 72 реестра, поставленная за границу импорта, собирается и на прогоне меняет `ro`-значение вызывающего |
| `scalar.nv` | **ложный отказ**: голый `int` под исключение попадает, новотип над `int` — нет; одна и та же форма в двух функциях одного файла |

## Как воспроизвести

Бинарь — `nova-cli/target/release/nova` из корня дерева.

```sh
# (1) ЗВУЧНОСТЬ. Файл сам по себе отвергается -- правило работает:
nova check docs/plans/repro/ro-launder-import-boundary/mod/g.nv
#   => g.nv:21:13 E_READONLY_COERCE, PASS: 0 FAIL: 1   -- так и должно быть (строка 72)

# ...а через точку входа, которая его ИМПОРТИРУЕТ, та же форма собирается:
nova build docs/plans/repro/ro-launder-import-boundary/gmain.nv -o /tmp/gmain.exe
#   => built: /tmp/gmain.exe
/tmp/gmain.exe
#   => before=2 inside=3 after=3
#      Третье число и есть дефект: `v` связан у вызывающего как `ro`, а после вызова
#      его длина другая. Мелкая копия разделила кучевое поле -- ровно то, что строка 72
#      назвала дырой звучности и оставила neg.

# (2) ЛОЖНЫЙ ОТКАЗ. Две функции одного файла, одна форма:
nova check docs/plans/repro/ro-launder-import-boundary/scalar.nv
#   => единственная отметка -- scalar.nv:21:15, тело `wrapped` (новотип).
#      Строка 11, тело `bare` (голый `int`), не помечена.
```

## Чем это НЕ является

Не расхождением `novac` с оракулом: обе находки — целиком оракульские, `novac` здесь только
пострадавший (его собственный исходник получает ложный отказ). В
`docs/dev/novac-divergences.md` им поэтому не место.

Не дублем строки 72: та закрыта 2026-07-24, и закрыта верно — предикат
`is_fully_stack_value` написан и работает. Обе находки — о том, ГДЕ он спрашивается: не у
новотипа (ложный отказ) и не за границей импорта (дыра). Граница, которую строка 72
объявила критичной, держится ровно в одном из двух маршрутов компиляции.

## Оси, опровергнутые по дороге (чтобы их не проверяли заново)

Каждая называлась ДО прогона и оказалась ни при чём:

1. «краснеет корень без `main`» — нет: файл с `main` в корне тоже краснеет;
2. «краснеет импортированный новотип» — нет: и локальный краснеет, когда его файл корень;
3. «дело в форме метода против свободной функции» — нет: метод краснеет так же;
4. «дело в манифесте (`[lib] src`, `nova-version = "0.5"`)» — нет: пакет, повторяющий
   манифест `novac`, краснеет.

Верной оказалась пятая: **маршрут компиляции**. Форма отвергается, когда её файл назван
корнем, и не проверяется вовсе, когда файл приходит импортом.

Отдельным фактом, важным при чтении вердиктов: `nova check <точка входа>` печатает
`PASS: 1` — ОДИН файл. Импортированные модули он не проверяет. Зелень точки входа здесь
не вердикт о них, а его отсутствие.
