# №1599: результат `-> ro T` больше 24 Б уже возвращается через место у вызывающего

Реестр 221.1, №1599. Замер помощника nova-88 2026-10-02, до любой правки кодогена.

## Вопрос

D488 п.2: результат `-> ro T` больше трёх машинных слов (24 Б) передаётся
«указателем на место у вызывающего». Оракул выпускает value-запись как C-структуру
и возвращает её по значению (`NovaValue_X f(...)`). Нужен ли явный параметр
`_out`, чтобы выполнить правило?

## Замер

`abi.c.txt` — три функции: `make_big` возвращает 32-байтную структуру по значению,
`make_big_out` пишет её в явный `Big32 *out`, `make_mid` возвращает 24 Б. Три
вызывающих: инициализация из возврата, инициализация через `_out`, вызов внутри
выражения.

```sh
clang -O2 -S -o abi_win.s  abi.c --target=x86_64-pc-windows-msvc
clang -O2 -S -o abi_sysv.s abi.c --target=x86_64-unknown-linux-gnu
```

(clang 22.1.5; переименовать `abi.c.txt` в `abi.c`.)

## Что показал ассемблер

* `make_big` и `make_big_out` — **одно и то же тело** на обеих ABI: результат
  пишется по скрытому указателю (`%rcx` на Win64, `%rdi` на SysV) — у явной формы
  тот же адрес приходит вторым аргументом.
* Вызывающий в обоих случаях передаёт **адрес своего слота**:
  `leaq 40(%rsp), %rcx; callq make_big` против `leaq 40(%rsp), %rdx; callq make_big_out`.
  Копии после вызова нет: поля читаются прямо из слота.
* Вызов в выражении (`make_big(x).b`) — тот же слот у вызывающего.
* 24-байтная `make_mid` тоже возвращается через скрытый указатель (на Win64 так
  возвращается всё больше 8 Б, на SysV — больше 16 Б).

## Вывод

Требование D488 п.2 для результата выполнено C-ABI: структура больше порога уже
возвращается в место у вызывающего, и машинный код совпадает с явным `_out`.
Явный `_out` изменил бы только текст C. Цена при этом не нулевая: обёртки для
вызова в выражении (GNU statement expressions запрещены — MSVC) и второй путь
возврата. Строка закрыта по этому замеру (решение интегратора 2026-10-02).
