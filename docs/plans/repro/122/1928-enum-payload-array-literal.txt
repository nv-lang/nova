Evidence for registry 221.1 №1928 (found by task 122, 2026-10-26).

CLAIM: an array literal directly in an enum PAYLOAD position is materialized as
[]int and reinterpreted as []u8 instead of being converted element-wise — the
open №1015 class (lazy memory reinterpretation instead of conversion), through
a door that entry does not name. The same literal in a typed slot or in a
function-argument position converts correctly.

MEASUREMENT (Oracle compiler built from this worktree, main 3b13fd3c5 plus the
task branch, Windows, clang, dev mode). Probe package `bytesprobe` (scratchpad
of the task-122 session, not committed — sources below reproduce it anywhere):

nova.toml:
    [package]
    name = "bytesprobe"
    version = "0.0.0"
    license = "MIT OR Apache-2.0"

    [lib]
    src = "."

main.nv:
    module bytesprobe.main

    type SqlV enum
        | Bs([]u8)
        | Null

    type OutV enum
        | Bs([]u8)
        | Null

    fn conv(s SqlV) -> OutV {
        match s {
            SqlV.Bs(b) => OutV.Bs(b)
            SqlV.Null => OutV.Null
        }
    }

    fn take(b []u8) Io -> () => println("arg len=${b.len()} a0=${b[0]} a1=${b[1]} a2=${b[2]}")

    fn main() Io -> () {
        // (a) literal into a typed slot
        ro slot []u8 = [1, 2, 3]
        println("slot len=${slot.len()} s0=${slot[0]} s1=${slot[1]} s2=${slot[2]}")
        // (b) literal as a function argument
        take([1, 2, 3])
        // (c) typed variable into enum payload, then through the roundtrip
        ro v = conv(SqlV.Bs(slot))
        match v {
            OutV.Bs(b) => println("enum-var len=${b.len()} b0=${b[0]} b1=${b[1]} b2=${b[2]}")
            OutV.Null => println("enum null")
        }
        // (d) literal straight into enum payload (the failing door)
        ro w = conv(SqlV.Bs([1, 2, 3]))
        match w {
            OutV.Bs(b) => println("enum-lit len=${b.len()} b0=${b[0]} b1=${b[1]} b2=${b[2]}")
            OutV.Null => println("enum null")
        }
    }

`nova check .` — PASS 2 FAIL 0 WARN 0 (the wrong program type-checks; the harm
is silent, which is exactly the D65-amendment/№703 shape). `nova build` +
run, verbatim stdout:

    slot len=3 s0=1 s1=2 s2=3
    arg len=3 a0=1 a1=2 a2=3
    enum-var len=3 b0=1 b1=2 b2=3
    enum-lit len=3 b0=1 b1=0 b2=0

Reading of the bytes: the literal is stored as []int (8-byte elements:
01 00 00 00 00 00 00 00, 02 00 …, 03 00 …) and the payload is then read as
[]u8 of len 3, i.e. the first three BYTES of the first int — 1, 0, 0.

FOUND BY: the sqltag_test.nv fixture of this task failed on
`b[2] == 3` after `value_of(SqlValue.Bytes([1, 2, 3]))`; isolating it gave the
probe above. The fixture now binds the literal in a typed slot first (door (a),
correct) and says so in a comment.

Sister measurement — the `unused-import` warning does not count pattern-only
use of an imported sum type (`import ./helper.{OutV}` + only `OutV.Bs(b)` /
`OutV.Null` in match patterns warns "unused import `OutV`"; removing the import
compiles clean — pattern paths resolve through the scrutinee type). Reported to
the integrator as an observation, not filed as a separate row.
