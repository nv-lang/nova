# Пробы к №969 — `if let` с `else`, где ОБЕ ветви `return`, не собирается

Найдено окном 274 пробой по оракулу 2026-09-05 (их волна W1); воспроизведено
интегратором в тот же день на `main @ aeb4bcf0f`, изоляция подтверждена дословно.

`check` говорит `ok`, а сишный компилятор отказывает:

```
pp.c:5322:14: error: initializing 'nova_int' (aka 'long long') with an expression
                    of incompatible type 'nova_unit'
 5322 |     nova_int _nv_tmp_458 = _nv_if_let_457;
```

Ошибка Си НАЗЫВАЕТ ТИП ПРЯМО — `'nova_unit'`, — то есть `if let` со всеми расходящимися
ветвями лоурится как ВЫРАЖЕНИЕ типа unit и присваивается во временную типа возврата
функции. Это эмиссия, а не типизация: чекер формы не видит и прав — программа
корректна, из обеих ветвей есть выход.

## Как запускать

```sh

nova-cli/target/release/nova.exe build /tmp/t.nv -o /tmp/t.exe
```

| `iflet_else_both_return` | значение-функция, `if let … { return v } else { return -1 }` | **ok** | **ошибка СИШНОГО компилятора** |

## Что доказывают контроли

Два контроля вместе сужают причину до одной точки:

* **не сама форма** — в unit-функции тот же `if let` с `else` собирается;
* **не `if let` вообще** — без `else`, с хвостовым выражением, значение-функция
  собирается;
* значит дело в связке «`if let` с `else`, обе ветви расходятся (`return`), и всё это
  стоит в позиции ЗНАЧЕНИЯ функции».
* **и не в вызове:** с разбираемым-ПАРАМЕТРОМ (`ctrl_param_scrutinee`, файл окна 274,
  перемерен мной) падает дословно так же — значит фикс, нацеленный на временные от
  результата вызова, промахнётся мимо класса.

## Границы пробы

Не мерил: `match` с расходящимися ветвями в той же позиции, `if let` с `else`, где
расходится только ОДНА ветвь, и формы с `throw`/`panic` вместо `return`. Первое из них —
самый вероятный сосед по классу, и с него стоит начинать чинящему.

Диагноз причины взят из ТЕКСТА ошибки Си, который называет тип `'nova_unit'` буквально,
и подтверждён тремя контролями. Чтения эмиттера под ним всё равно нет, и в строке
реестра это помечено: чинящий начинает с кода, а не с этой страницы.
