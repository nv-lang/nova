# Улика к строке реестра №799 (К1)

**Что здесь.** Два файла одной формы, различающиеся ОДНИМ именем переменной.
Их пара — не «репро», а **изоляция**: она называет триггер, а не симптом.

| файл | что делает | замер 2026-08-31 |
|---|---|---|
| [collide.nv](collide.nv) | имя захваченной переменной СОВПАДАЕТ с именем параметра вызываемой функции | **CC-FAIL** `use of undeclared identifier 'policy'` |
| [control_no_collision.nv](control_no_collision.nv) | та же форма, имена РАЗНЫЕ (`pol` / `p`) | **собирается, печатает `ok 3`** |

Команды целиком, из корня репозитория:

```sh
nova-cli/target/release/nova.exe build docs/plans/repro/p799/control_no_collision.nv -o /tmp/p799_ctl.exe
/tmp/p799_ctl.exe                       # -> ok 3

nova-cli/target/release/nova.exe build docs/plans/repro/p799/collide.nv -o /tmp/p799_col.exe
# -> error: use of undeclared identifier 'policy'
#      NovaValue_Pol __nova_arg_src0 = policy;
```

**Зачем контроль, а не только падающий файл.** Без него строка читается как
«вызовы с параметрами-умолчаниями ломаются внутри `spawn`» — это НЕВЕРНО и
отправило бы следующее окно разбирать обработку умолчаний вообще. Контроль
показывает, что та же самая форма с умолчанием, тем же `supervised { spawn }`
и тем же каналом собирается и работает, стоит развести имена. Триггер —
**коллизия имени**, и больше ничего.

**Почему файлы лежат здесь, а не в `spec_tests/`.** Падающий файл — CC-FAIL,
то есть он не компилируется; фикстурой корпуса он сделал бы корпус красным.
Место улик заведено решением по строке №695 (`docs/plans/repro/`).

**История этого каталога.** Строка №799 с 2026-08-29 ссылалась на файл
`p799_default_in_spawn.nv`, которого в дереве НЕ БЫЛО — проба жила только в
прозе. Она пересобрана 2026-08-31 по описанию из самой строки; первая
реконструкция **не воспроизвела** дефект, потому что я развёл имена, и это
несовпадение и подсказало, что коллизия — суть, а не деталь.

**Что делать дальше — путь правки прочитан, но НЕ применён.** Механизм записан
в самой строке №799: `callnorm` (D102, план 46 Ф.2) в фазе 2 объявляет локаль с
ИМЕНЕМ параметра, а фаза 1 в том же блоке читает одноимённый захват;
переписыватель захватов плоский и областей не различает. Предлагаемый путь —
переименовывать локаль фазы 2 и её употребления ВНУТРИ собственного блока при
коллизии. Правка не сделана сознательно: `ExprKind` несёт 57 вариантов, и
переименовыватель по ним обязан быть исчерпывающим, а проход срабатывает для
КАЖДОГО вызова с умолчанием — такое не сдаётся без полного корпуса.
