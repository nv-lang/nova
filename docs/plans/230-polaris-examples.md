# План 230 — Примеры-приложения Polaris

**Статус:** 📋 УТВЕРЖДЁН владельцем (2026-07-25: «и отдельный план по примерам для Поляриса»).
**Репа-цель:** nova-polaris, каталог `examples/` (каждый пример — самостоятельный мини-пакет).
**Связи:** 229 (дока — сниппеты; примеры = следующий уровень: цельные программы), 222
(архитектура), флагман nova `examples/flagship/aggregator` (прецедент оформления и гейтов).

## 0. Отличие от доки (229)

Сниппеты доки показывают ОДИН приём и живут в `doc_samples_test.nv`. Примеры — **цельные
запускаемые приложения**: показывают, как приёмы складываются вместе (структура проекта,
композиция middleware, обработка ошибок end-to-end). Пользователь копирует пример как
стартовую точку.

## 1. Принципы (жёсткие)

1. **Каждый пример собирается `--strict-effects`** (конвенция examples 2026-07-13) и
   **запускается** (smoke: поднялся → ответил на 1-2 запроса → погасился; по образцу
   rt-смоуков polaris).
2. **Источник истины — код**: только фактический API (без roadmap-фантазий; после 222.3
   примеры обновляются отдельной волной — правило поддержания из 229 §4).
3. Каждый пример несёт **README.md + README.ru.md** (что показывает, как запустить, что
   покрутить) — коротко, полстраницы.
4. От простого к сложному, каждый следующий добавляет ОДНУ концепцию.
5. Общий smoke-раннер: `examples/run_smokes.(ps1|sh)` — собирает и прогоняет все примеры
   (гейт волны и будущий CI-крючок).

## 2. Состав (по нарастающей)

| # | Пример | Показывает |
|---|---|---|
| 01 | `hello/` | минимальный сервер: Router.new + один get + serve; «10 строк до работающего HTTP» |
| 02 | `routing/` | шаблоны `{name}`/`{*rest}`, MethodRouter (`get(h).post(h2)`), nest, fallback-404, typed-конфликты путей |
| 03 | `json-api/` | REST CRUD (in-memory todo): `req.json[T]`, `ServerResponse.json`, `#impl(Serialize/Deserialize)`, StatusCode-константы, коды ошибок |
| 04 | `middleware/` | свой middleware (`middleware(fn(req,next))`), `@then`, порядок layers, log+ratelimit батарейки |
| 05 | `auth/` | защита маршрутов: basic + bearer/JWT, session-cookie; публичная/приватная зоны через nest+layer |
| 06 | `static-site/` | polaris.static + fallback на index; кеш-заголовки |
| 07 | `sse-stream/` | StreamBody + sse_event: живой тикер |
| 08 | `websocket-echo/` | ws-upgrade hook, WebSocket.with_limit, echo-цикл |
| 09 | `graceful/` | ServerPolicy (лимиты/admission), BackgroundTasks, recover-500, graceful shutdown |
| 10 | `mini-service/` | «всё вместе» (уровень флагмана, компактнее): json-api + auth + middleware-стек + static + graceful — референс-структура реального сервиса |

## 3. Гейты волны

- `run_smokes` зелёный: 10/10 собираются `--strict-effects`, smoke-запрос отвечает.
- `nova test` реп-уровня — δ0 (примеры не ломают пакет; примеры вне `src/`, но собираются
  против локального polaris path-dep как обычные потребители — это заодно тестирует
  developer-experience подключения пакета).
- README-пары EN↔RU на каждый пример (счёт 10×2).
- Кросс-ссылки: каждый пример указывает разделы доки 229, которые иллюстрирует, и наоборот
  (в доке — «полный пример: examples/NN»).

## 4. Исполнение и порядок

Одна sonnet-волна в nova-polaris (ветка `p-examples`), ПОСЛЕ влития док-волны 229 (та же
репа — не плодить параллельные ветки; кросс-ссылки требуют готовой доки). Фазы: Ф.1 01-04 +
smoke-раннер → Ф.2 05-08 → Ф.3 09-10 + кросс-ссылки. Чекпоинт-коммит на фазу. Приёмка
интегратора: run_smokes + выборочный запуск 2-3 примеров руками.

## 5. Поддержание

То же правило, что 229 §4: волна, меняющая публичный API polaris, обязана прогнать
run_smokes и поправить задетые примеры в том же слиянии. После 222.3 — отдельная волна
«примеры на экстракторах» (обновить 02/03/10, дописать пример-раздел).
