## 1. Принципы (жёсткие)

1. **Каждый пример собирается `--strict-effects`** (конвенция examples 2026-07-13) и
   **запускается** (smoke: поднялся → ответил на 1-2 запроса → погасился; по образцу
   rt-смоуков polaris).
2. **Источник истины — код**: только фактический API (без roadmap-фантазий; после 222.3
   примеры обновляются отдельной волной — правило поддержания из 229 §4).
3. Каждый пример несёт **README.md + README.ru.md** (что показывает, как запустить, что
   покрутить) — коротко, полстраницы.
4. От простого к сложному, каждый следующий добавляет ОДНУ концепцию.
5. Общий smoke-раннер: `examples/run_smokes.(ps1|sh)` — собирает и прогоняет все примеры
   (гейт волны и будущий CI-крючок).
6. **«Красивые и технологичные» (требование владельца, 2026-07-26).** Пример — витрина
   языка/фреймворка для новых пользователей; обходы компилятор-багов в примерах — брак,
   не временная норма. Конкретно:
   - **Никаких compiler-workaround'ов в теле примера.** Если фичи не хватает — баг
     чинится в компиляторе (реестр 221.1), пример ждёт фикса или переносит функциональность
     на ту, что реально работает; ручная имитация того, что должен делать язык/serde/роутер
     (руками собранный JSON вместо `Serialize`, руками написанный dispatch вместо роутера
     и т.п.) — недопустима как явленный код примера, даже с комментарием-оговоркой.
     Прецедент-урок: `examples/03-json-api`'s `todo_json_line`/`todos_json` (ручная сборка
     JSON-массива в обход №111, `Vec[T Serialize]` ICE) — владелец: «неподготовленный
     пользователь может подумать, что так нужно формировать JSON»; исправлено окном №111
     (компилятор-фикс + пример переведён на `ServerResponse.json(items)` напрямую).
   - **Идиоматичный код**: каждый пример использует САМУЮ канон-форму на момент
     написания (цепочки методов, extractors, а не низкоуровневые формы — см. канон
     `Router.new().get(...)!!` из 2026-07-26 «так не лучше?», применённый ко всем 10).
   - **Гейт волны обязан включать самопроверку**: перед сдачей примера — явный вопрос
     «есть ли в этом коде что-то, что читатель мог бы принять за канон, но это обход
     бага?» — если да, это блокер приёмки, не пометка в README.
   - Существующий workaround-инвентарь (реестр №109/110/111 на момент этой правки) —
     закрывается компилятор-окнами, примеры мигрируют на идиоматичную форму тем же
     слиянием, что и фикс (не отдельной, отложенной волной).

### 6а. Декомпозиция по примерам (аудит интегратора 2026-08-02, все 12 прочитаны построчно)

Примеров уже **12** — `11-json-logs` и `12-https` добавлены после написания плана; в §2/§2а
их нет — таблицы дополняются этой волной (первоисточники: 11 → Go slog / Rust tracing /
Node pino; 12 → axum-server(rustls) / Go `ListenAndServeTLS` / Express https).

Формат: **гэпы паритета → действия · блокеры (№) · где лучше других**.

**01-hello.** Паритет с axum/Express полный, форма даже короче. Действия: README-паритет-
таблица + секция «проверь без сети» (направление 1) — hello как первый носитель TestClient.
Блокеров нет. Лучше: `--strict-effects`-строка (Net Time Detach в сигнатуре main — витрина).

**02-routing.** Паритет с axum/chi есть; конфликт маршрутов у нас **типизированный Err на
старте** — axum на дубле ПАНИКУЕТ: готовое «лучше», вынести в README первой строкой.
Гэпы: авто-405 показан только кастомным fallback — добавить строку про дефолт;
`MethodRouter` без `head/options` в примере — показать одну. Блокеров нет.

**03-json-api.** Самый нагруженный обходами (§1.6-нарушения, чинить волной):
(а) **same-path multi-method с общим захваченным состоянием падает НА РЕГИСТРАЦИИ** —
комментарий «filed upstream» БЕЗ №-ссылки: найти/завести № в 221.1, компилятор-окно;
до фикса цепная форма — вынужденный канон, после — упростить;
(б) ручной `#impl(Reflect)` для бандла — вынужден `[M-reflect-derive-generic-wrapper-
field-null-shape]` (P1): после фикса перейти на derive;
(в) три форвард-`#impl(FromPath/FromQuery/FromBody)` по 6 строк — против axum-derive
многословно: кандидат на дженерик-дефолт форварда в polaris (паритет эргономики axum
`#[derive(Deserialize)] + Path<T>`);
Лучше уже сейчас: бандл-экстрактор «каждое поле объявляет СВОЙ источник» + `/openapi.json`
из коробки (у axum — только сторонним utoipa; у FastAPI — есть, наш паритет-ориентир он).

**04-middleware.** Паритет с Express-цепочкой полный, порядок слоёв объяснён лучше
большинства док. Гэп против tower-экосистемы: батарей две (log, ratelimit) — добавить
в пример timeout- и cors-батареи (cors.nv в пакете ЕСТЬ, примера НЕТ — единственная
батарея без витрины); честная строка «tower-глубина (compression/trace) — дорожная карта».
Лучше: flat-форма `middleware(fn(req, next))` без Service/Layer-церемоний.

**05-auth.** Паритет axum-jwt/FastAPI-security есть (basic+bearer+jwt+session+зоны).
Гэпы: (а) `Random.secure()` CSPRNG — открытый вопрос спеки, пример честно на `seeded(42)`:
для V2-витрины это блокер продакшн-правдоподобия — поднять приоритет вопроса;
(б) фиксированный demo-клок объяснён хорошо, но README должен показать und продакшн-форму
(ambient Time) рядом. Лучше: `SessionStore` как ЭФФЕКТ с `with ... =` вокруг accept-цикла —
ни у одного первоисточника нет такой явной инъекции стора; показать мок-стор в тестах.

**06-static-site.** Разобран (§6-затравки): ссылки чинены `f980033`; mount-одной-строкой —
№109 (промпт p109-static-oom готов, вероятен путь A); `no-cache` на HTML; precompressed —
кандидат «лучше всех». Лучше уже сейчас: контент-ETag+304 на embed (сильнее Go embed и
axum) — показать 304 curl'ом в README.

**07-sse-stream.** Гэп против axum `sse`: у них ЖИВОЙ интервал-тикер и keep-alive; у нас
конечный счётчик без пауз — producer-замыкание `fn() -> Option[[]u8]` без Time-эффекта:
проверить, легален ли `Time.sleep` в producer (если нет — это API-гэп StreamBody,
завести №); добавить `retry:`/`Last-Event-ID` строку (реконнект — половина смысла SSE).
Лучше: pull-модель без каналов/tasks — проще axum'овского Stream+interval.

**08-websocket-echo.** Эхо-паритет есть. Гэпы: (а) локальная `ws` затеняет МОДУЛЬ ws →
E7401 — обход `mut w = sock` с комментарием в примере: завести № (резолв метод-вызова
не должен ломаться о теневой конфликт имени модуля), после фикса убрать обход;
(б) axum-канон включает broadcast-чат: добавить второй маршрут `/chat` (общий стейт
через каналы/#share — заодно витрина Vela; координация с §3-энфорсом mut-захватов).
Лучше: `consume`-владение сокетом (D133) — «забыть закрыть» не компилируется: ни у кого
из первоисточников нет, в README крупно.

**09-graceful.** САМЫЙ большой разрыв паритета: axum `graceful-shutdown` делает настоящий
shutdown (сигнал → стоп accept → дренаж соединений) — у нас его НЕТ вовсе (пример честно
показывает только policy-ручки+фон). Действия: (а) **stale-комментарий снять**:
«BackgroundTasks не исполняются» устарел — `[M-serve-router-background-tasks-not-drained]`
✅ ЗАКРЫТ 2026-08-01 (p-observability, run_request дренирует) — ретест `/work`→`/log` и
переписать банер (сейчас пример УЧИТ, что фича сломана, а она починена);
(б) настоящий shutdown блокирован `[M-supervised-cancel-no-interrupt-parked-accept]`
(P1, 222.22) — после фикса добавить Ctrl+C-путь (cancel-токен вокруг accept);
до фикса — честная строка «shutdown: план 222.22». Лучше: admission-политика
(`max_inflight`+503) из коробки — у axum это ручной tower-limit; витрина README.

**10-mini-service.** RealWorld-профиль сильно урезан: нет update/delete статьи, нет
per-user авторства (`author: "demo"` захардкожен — sub из JWT не читается!), пароль не
проверяется вовсе. Действия: (а) PUT/DELETE `/articles/{slug}` с проверкой автора по
claims (реюз `claims_at` из 05); (б) POST `/articles` — брать author из токена;
(в) пагинация — на typed `Query`-экстрактор (свяжет 03↔10); (г) `slugify` — на
канон-идиомы (П22-класс: chars().map/collect вместо ручного цикла — по факту наличия);
(д) сравнить с RealWorld-спекой и в README перечислить, ЧТО из профиля покрыто (честный
скоуп вместо «trimmed»). Блокер (а/б): тот же same-path-крэш, что в 03 (цепная форма
уже используется — не блокирует, но №-ссылку добавить). Лучше: весь сервис — один файл
147 строк со strict-effects; сравнение размера с минимальным RealWorld-axum уместно.
