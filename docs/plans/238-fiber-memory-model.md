## Решение владельца (зафиксировано в №150, здесь — операционная карта)

- **Send/Migrate-маркер НЕ заводить (YAGNI):** файберы мигрируют между ОС-потоками
  по построению рантайма, передачу владения закрывает consume; thread-affine
  FFI-ресурсы при появлении — аксиомой на конкретный тип.
- **Sync-сторона — тремя существующими кирпичами, без нового механизма:**
  1. `ro`/`mut` — неизменяемое разделяемо по построению (читатели без писателей);
  2. **линейность для mut** — замыкание/значение с mut-захватом = линейный ресурс
     ОДНОГО файбера; пересечение границы = ошибка той же машины D131/consume;
  3. **белый список синхронизированных** — share (D415), `Atomic*`, `Mutex`, концы
     каналов; разделение разрешено ТРАНЗИТИВНО по составу (запись разделяема ⇔
     каждое поле из (1) или (3)); ходьба по составу — существующий consume-реестр.
     `share` из «ничего не решает» становится элементом белого списка.
  - Оговорка звучности: «ro ⇒ разделяемо» держится ТОЛЬКО вместе с (2) — запрет
    второго mut-алиаса гарантирует отсутствие писателя за спинами читателей.
- **Транзитивные вызовы — три точки закрытия:**
  4. именованный граф вызовов — существующая эффект-машина (№131): «M:N-небезопасно»
     объявляется на листьях (extern-аннотации), `infer_effects` поднимает
     транзитивно, граница spawn/detach требует чистоты;
  5. vtable эффектов — схема статична, handler-тела после A-B9 обычные fn, точка
     `with` статически видна ⇒ проверка НА ОБРАБОТЧИКЕ в точке установки вокруг
     spawn-содержащего кода;
  6. стёртые fn-значения (Handler) — гейт в точке стирания (коэрсия fn→Handler,
     D52): стирание допускается только для M:N-чистых тел ⇒ fn-значение чисто ПО
     ПОСТРОЕНИЮ, spawn/detach доверяет не зная тела.

## Фазы окна

- **Ф.0 — вход: ✅ ЗАМЕР ГОТОВ 2026-07-30 (sonnet, read-only, 5 реп).** Итог:
  **28 живых сайтов (26 бесспорных + 2 спорных), и все — ОДИН идиом:**
  `mut флаг` в Fail-обработчике, установленном вокруг spawn-содержащего кода
  (родом из quickstart/language-tour; флагман ×3: `aggregate.nv` fetch_guarded,
  `live.nv` ×2; polaris ×1: `net/policy.nv` read_attempt — на каждом read
  сервера). nova-http/bigint/compress — ноль (конкурентности нет).
  Conformance-красный список энфорса: 8 файлов/~13 тест-блоков + 2 файла/8
  тестов std (перечень — SCALE150_MIGRATION.md в scratchpad сессии 2026-07-30).

  **Неопределённость замера ЗАКРЫТА пробой интегратора (тот же день):** вопрос
  «Fail-обработчик конкурентен или сериализован как on_child_fail?» решён
  измерением — 64 падающих ребёнка × 20 раундов, обработчик делает неатомарный
  `cnt = cnt + 1` рядом с AtomicInt-контролем числа вызовов: **потерянные
  обновления в 2 прогонах из 5 (2 и 1 на 1280 вызовов)**. Обработчик исполняется
  В ФАЙБЕРЕ падающей операции, конкурентно — все 26 сайтов настоящие нарушители.
  Малая частота + запись одинакового значения в флаг объясняют, почему идиом
  «казался рабочим». Проба: `fail_handler_conc_probe.nv` (scratchpad; в окне
  оформить фикстурой).

  **Решение по спорным (интегратор, по конвенции D416§2 — конвенция даёт ответ):**
  обработчики, которым машина ГАРАНТИРУЕТ сериализацию на drive-файбере scope'а
  (`Supervisor.on_child_fail`, D416§2 — 3 сайта polaris) — ЛЕГАЛЬНЫ, энфорс обязан
  их не флагать; гарантию сериализации запиннить отдельной фикстурой в этом же
  окне (иначе исключение держится на честном слове).

  **Чек-лист миграции 26 сайтов** (в порядке дешевизны): AtomicBool/AtomicInt
  вместо mut-флага (образец уже в коде ×2); возврат значения из with-выражения;
  канал (уже есть в 100% сайтов идиома). Доки quickstart/language-tour учат
  гоночному идиому — переписать ТЕМ ЖЕ слиянием.

  Репро `race150/` из ветки `p150-race-repro` — пиновая фикстура окна
  (в conformance НЕ носить до фикса).
- **Ф.1 — кирпич (2), ядро:** линейность mut-захвата на границах spawn/detach/
  parallel for/канал-send. Чекер-канал (§0/196), НЕ emit_c. Диагностика класса
