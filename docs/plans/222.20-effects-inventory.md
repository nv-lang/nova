# 222.20 Ф.1 — Инвентарь эффект-поверхности (polaris / http / tls / compress)

**Статус:** 📋 РАЗВЕДКА (Ф.1, sonnet) — данные для Ф.2 (дизайн, opus). Ничего не
реализовано, только карта + вердикты по критерию Правила 4.

**Метод:** export-поверхность (`export fn`/`export type`) четырёх репо
(`nova-polaris/src`, `nova-http/src`, `nova-tls/src`, `nova-compress/src`),
прочитана целиком по файлам, где грепом найдены эффект-токены
(`Net`/`Time`/`Detach`/`Fail`/`Io`/`Random`/`Db`/`Log`/`Blocking`/`Mem`/
`Trace`/`Async`) или `protocol`/`effect`-декларации. Приватные функции — только
где подозрительны (глушение/обход). compress: эффектов и protocol/effect-типов
НЕ найдено вообще (чистые байт-функции, D407) — в таблицу 1 не включён
отдельными строками, отмечен как факт ниже.

**Рамка (Правило 4, дословно, `spec/decisions/04-effects.md:2789`):** «Эффект
описывает resource-capability — нечто, что можно подменить handler'ом в
скоупе. Suspension и runtime-механизмы — не resource, а ambient mechanic,
общая для всех асинхронных операций; они НЕ эффекты.» Вопрос-тест: «может ли
это быть подменено в тесте?» — да → effect; нет → protocol (bound на тип) или
runtime mechanic (не существует в типах).

## Отчёт

**Модель:** sonnet (волна 222.20-Ф.1).

**Счётчики:**
- fn/метод с эффектами в сигнатуре по репам: polaris — 20 экспортных +
  ~8 приватных мест (`Net`/`Time`/`Detach`/`Io`-ambient); nova-http — 3
  (`real_http` + 2 приватных send-функции; `Http`-effect сам — точка отсчёта,
  не «функция с эффектом»); nova-tls — 2 экспортных (`connect`/`accept`) +
  структурные `@read`/`@write`/`@flush`/`@close` (Net изнутри); nova-compress
  — 0 (подтверждено — весь пакет чистый, D407).
- Кандидатов в эффекты (табл. 2, «ДА»-вердикт): **5** — `SessionStore`,
  `now_fn`→`Time`, `id_gen`→`Random`, `@emit`(×3 копии)→`Log`,
  плюс пограничный `ratelimit-buckets` (Ф.2-решение, не чистое «да»).
- Обходов Handler-класса (табл. 3, строки с реальным протаскиванием): **8**
  (4×`Time`/`now_fn`-семейство, 1×`Random`/`id_gen`, 3×независимые
  `Log`/`Io`-sink копии) + 1 пограничный (`MemorySessionStore` explicit-clock
  внутри протокола).

**Топ-5 рекомендаций (Ф.2-вход, не решения):**
1. **`SessionStore` → эффект**, а не protocol+mut-параметр — учебниковый
   Db-класс подмены (владелец уже предложил, теперь подтверждено Правилом 4
   формально, включая прямую параллель с `Db`/`Cache[K,V]` в decision-matrix
   спеки).
2. **Консолидировать 3 независимые ручные `Log`-sink копии
   (`background.nv`/`middleware/log.nv`/`net/config.nv`) в ОДИН `Log`-эффект**
   — самый явный сигнал избыточности во всём инвентаре; кандидат для
   немедленного Ф.2-дизайна независимо от исхода вопроса №2 (Handler).
3. **`now_fn`/`id_gen` → `Time`/`Random`** как только `Handler`/`Middleware`
   получат эффект-строку — 5 мест в auth.nv однозначно исчезают; `Log`
   (`middleware/log.nv`, `RateLimit`) УЖЕ доказывает рабочий паттерн
   («эффект в конструкторе middleware» — `Time -> Middleware`), можно
   обобщить на весь `require_jwt`/`session_layer`.
4. **Ключевой вопрос №2 плана (Handler effect-polymorphic) — самое дорогое
   решение с наибольшей отдачей**: 8 обходов табл. 3 схлопываются в один
   архитектурный шаг; `MockHttp`-триада (`Http`+`real_http`+`mock_http`,
   nova-http) — готовый рабочий образец формы «эффект + прод-хендлер +
   мок-хендлер», на неё стоит равняться при проектировании `SessionStore`/
   `Log`.
5. **TLS `@read`/`@write`/`@flush` — НЕ заводить отдельный эффект**
   (пограничный случай табл. 1/2 закрыт как «оставить как есть» с низкой
   уверенностью): TLS сознательно не имеет своего capability, мокается на
   уровне `Net`/`Http`; `StreamBody`/`upgrade`-hook/`background`-hook —
   тоже НЕ эффекты (runtime-mechanic/control-flow hand-off по Правилу 4), это
   единственные три «нет»-вердикта в табл. 2 кроме `FromRequest`/
   `IntoResponse` (протоколы, корректны как есть).
