## 0. Мотив

У сгенерированных страниц сайта (`/doc/`, `/spec/`, `/decisions/`) нет обратной связи
и указания источника: читатель не может ни поправить устаревание, ни сообщить о нём,
ни понять, насколько страница свежая. Сегодняшняя волна сняла три содержательных
устаревания руками интегратора — канал «читатель → issue/PR» удешевит это в будущем.
Образец UX — opencode.ai/docs (Edit this page / Found a bug? Open an issue / дата
обновления / переключатель языка). Переключатель RU/EN у нас уже есть.

## 0.1 Исполнитель и дисциплина

- **Исполнитель:** opencode (механика по готовой карте — конвенция «дешёвые модели

- `git add` только по именам; `git config` не трогать; греп конфликт-маркеров ОДНОЙ

- Гейты `npm run build/check/check:highlight` агент гоняет сам (лёгкие);
  авторитетную приёмку повторяет интегратор перед мержем.

## 1. Скоуп

1. **`site/scripts/sync-decisions.mjs`**: пробрасывать в frontmatter каждой
   сгенерированной страницы путь источника в репе nova (`docs/guide/<f>.md`,
   `spec/decisions/<f>.md`, …) и **дату последнего коммита источника**.
   **Механика дат (уточнено 2026-08-02):** НЕ per-file REST (rate-limit 60/час
   без токена — уже ловили транзиентные fetch-fail при сборке) — один-два
   GraphQL-батча на все пути ЛИБО дешевле: **кэш дат в репе www**
   (`site/src/data/source-dates.json`, обновляется при успешном синке;
   сеть/лимит упали → рендер из кэша, страницы дату не теряют). CI кэш-файл
   назад НЕ коммитит — освежение кэша происходит в ручных волнах, это норма. Для ru-пар
   (`*.ru.md`) дата берётся от СВОЕГО файла, не от en-источника. Дата сборки
   как fallback ЗАПРЕЩЕНА — ложный сигнал свежести хуже отсутствия даты:
   нет даты коммита ни в ответе, ни в кэше → блок даты не рендерить.
2. **Компонент подвала** контент-страниц (en+ru тексты):
   - guide-страницы → «Edit this page», URL-форма `…/nova/edit/main/docs/guide/<f>.md`
     (открывает fork-flow редактора);
   - spec/decisions → «Source on GitHub» БЕЗ приглашения редактировать, URL-форма
     `…/nova/blob/main/<путь>` (спека нормативна, изменения — через D-блоки решением
     владельца; «Edit» соберёт шумные PR);
   - везде → кнопка обратной связи с предзаполненным заголовком (путь страницы);
     **цель ссылки зависит от A-R3 (221 Ф.4):** ДО включения Issues (= до релиза)
     вести в GitHub Discussions (текущий канал сообщества из футера), ПОСЛЕ —
     переключить на Issues; сделать целью ОДНУ конфиг-константу, чтобы
     переключение при релизе было однострочным. Нюанс prefill: у Discussions
     URL `…/discussions/new` требует `?category=<slug>&title=…` — слаг категории
     положить в ту же константу;
   - дата: «Last updated <дата коммита источника>».
3. **Рукописные страницы** (главная, /install/, …): ссылка на партиал в репе www
   (+ кнопка обратной связи); дата — ВСЕГДА по локальному `git log -1 --format=%cI
   -- <партиал>` (сборка идёт из клона www — это бесплатно; оговорка «если дёшево»
   снята 2026-08-02).
4. **Discord НЕ добавлять** (решение владельца 2026-08-02: до v0.1 сообщество =
   GitHub Discussions, уже в футере).

1а. **Фазовость для opencode-исполнителя (добавлено 2026-08-02):** сначала СПАЙК —
   подвал на ТРЁХ страницах (по одной каждого типа: guide / spec / рукописная),
   полная приёмка п.3 на них; затем раскатка на всё. Красный спайк → СТОП-отчёт,
   не раскатывать.

## 2. Не-скоуп

- Переезд на docs-first движок (Starlight и т.п.) — не нужен, всё добавляется в

- Комментарии/реакции на страницах, аналитика.

## 3. Приёмка

- `npm run build` + `npm run check` + `npm run check:highlight` — зелёные;
  check-links чист.
- en/ru синхронны; релиз-нейтральность; «синк не тянет docs/dev/» (стоячая проверка).
- «Edit»/«Source»-ссылки кликнуты на 2-3 реальных страницах каждого типа — файл
  существует в nova main (не 404).
- Даты выборочно сверены с `git log -1` источника — ОБЯЗАТЕЛЬНО и в CI-сборке
  (страницы задеплоенного превью/артефакта), не только локально: depth-ловушка
  checkout проявляется только в CI.
- Отчёт по-русски: модель, хеши, вердикты гейтов дословно, список страниц/лейаутов.
