# 274.6 — Кортеж есть запись на стеке: свести бухгалтерию к одной

**Статус:** 🚧 В РАБОТЕ с 2026-09-03 (подплан [274](274-novac-self-hosted-compiler.md),
номер унаследован от родителя по конвенции подпланов; интегратор вправе переименовать).
Время — окна 274 в счёт месяца novac (плану 274 месяц отдан владельцем);
чужих окон и оракульих волн план не занимает.

**Требование владельца (2026-09-02, о `novac/src/emit_c/emit_tuple.nv`):** «ты
нагородил второе окно для кортежей, хотя кортежи это те же записи на стеке; это
нарушение, это приведёт к двойной бухгалтерии, т.к. у кортежей так же как и у записей
есть перегруженные операторы, методы и т.п.» → «убрать отдельную бухгалтерию для
кортежей под ноль». Дополнения того же дня: «кортежи могут быть и именованые, тогда не
будет f0»; «у кортежей могут быть параметры со значением по умолчанию, также как у
функций, поэтому это всё одно окно». Уточнение устройства 2026-09-03: у записи заводится
внутренняя характеристика-перечисление `Record | ValueRecord | NamedTupleRecord |
AnonymousTupleRecord`, где `Record` — на куче, остальные на стеке; `ValueRecord` —
отдельная форма языка (`type X value { ... }`), не синоним кортежа.

**ЦЕЛЕВОЕ УСТРОЙСТВО ЖИВЁТ НЕ ЗДЕСЬ**, а в архитектуре:
[docs/dev/novac-architecture.md](../dev/novac-architecture.md), раздел «4б. Форма
записи — одно перечисление». Там написано, КАК ДОЛЖНО БЫТЬ. Этот документ — про то, как
сейчас неправильно, и что сделать, чтобы стало как там.

Документ самодостаточен: замеры, разбор и критерии — здесь; читать переписку не нужно.

## 0. Правило слова (владелец, 2026-09-03) — усиление, судит страж

Дословно по смыслу: «слово tuple может встречаться в комментариях и в
`Record | ValueRecord | NamedTupleRecord | AnonymousTupleRecord`, больше нигде;
конструктор по созданию кортежа это и есть его декларация, т.е. обычная функция
со всеми обычными возможностями, в том числе параметры по умолчанию; если
хочешь завести слово tuple в имени файла или в коде — только при моём
согласовании; всё, что касается сейчас tuple, должно быть удалено».

Из этого следуют три вещи, и все три уже механизированы:

1. **Особой сущности «кортеж» в коде нет.** Не только «нет второго окна
   эмиссии» — нет идентификаторов, видов узлов (`TupleExpr`, `TupleBind`),
   видов типов (`TkTuple`), дверей (`is_tuple`, `mono_tuple_name`,
   `@tuple`-интернер) и файлов со словом tuple. Знание о форме несут ровно два
   имени вариантов перечисления. Это МЕНЯЕТ волны В1–В3 ниже из «свести двери»
   в «удалить сущность»: `TkTuple` уходит в `RecordShape.AnonymousTupleRecord`
   на строке декларации, `TupleExpr`/`TupleBind` растворяются в обычных узлах
   конструктора-вызова и биндинга.
2. **Конструктор кортежа = его декларация = обычная функция.** `type Pair(x
   int, y int = 5)` регистрирует конструктор-функцию `Pair` с обычными
   слотами D102 (умолчания, именованные аргументы, режимы) — никакой своей
   механики построения. `Pair(1)` законен, как законен вызов функции с
   умолчанием. Это упрощает В2: не «научить путь записи скобочной форме», а
   «декларация рождает функцию, дальше всё уже умеет резолвер вызовов».
3. **Новое слово tuple — только с согласования владельца.** Механизм: страж
   (ниже) держит рост красным, так что согласование не на честном слове —
   без правки базы слово физически не заводится, а правка базы видна в диффе.

**Страж усилен тем же днём** (v2): правило СЛОВА по всему `novac/src` — строка
кода (не комментария) со словом `tuple` в любом регистре вне двух разрешённых
идентификаторов, плюс имена файлов. База переснята прогоном: **101** (100 строк
в 23 файлах + `emit_c/emit_tuple.nv`), крупнейшие носители: `sem/mangle.nv` 15,
`emit_c/emit_c.nv` 12, `check/typing.nv` 9, `types/types.nv` 8. Храповик вниз,
цель 0; закрытие плана = `tuple_words=0` и строка стража «цель достигнута».

## 1. Как сейчас неправильно — четыре замера 2026-09-02/03

**1.1. Второе окно эмиссии существует и названо.** `novac/src/emit_c/emit_tuple.nv` —
три двери (`@emit_tuple_typedefs`, `@emit_tuple_lit`, `@emit_tuple_bind`), то есть
typedef, конструктор и деструктуризация; ровно то, что путь записи уже умеет
(`@emit_record_decl` в `emit_decls.nv`, `@emit_record_ctor` в `emit_c.nv:850`).
Построчно разница между `@emit_tuple_lit` и `@emit_record_ctor` сводится к двум вещам:
имя поля (`f{i}` против настоящего) и выбор стек/куча, которого у кортежа нет.

**1.2. Объявленная кортеж-форма молча превращается в НЬЮТАЙП.** Замер:

```nova
type Pair(x int, y int)
fn main() {
    ro p = Pair(1, 2)
    println(p.x)
}
```

Оракул собирает и печатает `1`. novac отказывает:

```
outside the subset: constructing a newtype takes exactly one argument -- its representation
unknown name: nothing with this name is bound at this point
```

То есть `Pair` для novac — ньютайп над `int`: оба имени полей и второе поле отброшены.
Трасса (делегированный агент, сверено запуском):

1. `parse/parse.nv:499-518` — хвост объявления типа уходит в `@type_ref()`; ветки на
   скобочную форму `type X(...)` НЕТ вовсе;
2. `parse/type_ref.nv:114-126` — `@type_ref` читает `(x int, y int)` как один плоский
   прогон листьев, без единого узла `Field`;
3. `sem/slots.nv:361-383` (`shape_of_decl`) — без `Field`-детей классифицирует
   объявление как `ShapeNewtype`, а не `ShapeRecord`;
4. `sem/slots.nv:432-471` (`repr_of_decl`) — берёт ПЕРВЫЙ резолвящийся тип в хвосте
   (`int`) как представление; имя `x` игнорируется как «слово без типа», поле `y`
   теряется целиком;
5. `sem/sem.nv:515-531, 579-645` — `ctx.fields` для `Pair` остаётся пустой навсегда;
   `TypeDef` окончательно `kind: TkNewtype`.

**Первая точка потери — шаг 1.** Починка начинается там.

**Оговорка к замеру, важная для доверия к цифрам.** В первой редакции этой записи были
процитированы другие тексты отказа («unknown field», «#812 names a field the type does
not declare») — они сняты с ФИГУРНОЙ формы `Pair { x: 1, y: 2 }`, а не с канонической
вызов-формы. Неточность нашёл агент-трассировщик, сверка запуском подтвердила. Форму
проверяют `build`, а не `check`: у оракула `check` пропускает то, что валит кодоген.

**1.3. Флаг `by_value` не выражает того, что нужно.** Он двоичный («на стеке или на
куче»), а различать надо ЧЕТЫРЕ формы. Правило счёта: `grep -rn "by_value\|is_value_record"
novac/src --include=*.nv` — 34 строки в 11 файлах (2026-09-03; включая импорты,
сиды-константы и тесты). Из них ПРЯМОЕ чтение поля одно — `sem/mangle.nv:191`,
тело `is_value_record`; перенос значения между проходами один (`sem/sem.nv:616`);
форму по источнику определяют два места (`sem/sem.nv:519`, `sem/harvest.nv:175`,
оба через `decl_is_value`); остальное — вопросы к двери. Значит переход стоит:
одно тело двери + два места классификации + сиды-константы.

**1.4. Мнимый блокер, снятый разбором.** Разведка подала как непреодолимое: у кортежа
`head_id` — это АРНОСТЬ, ключ структурного интернирования (два равных по составу
кортежа — одна строка типа, D123), «значит декларации у него быть не может»
(`types/types.nv:218-224`, `sem/sem.nv:272-279` — `decl_head_of` для `TkTuple` это ICE
по построению). Это смешение ТОЖДЕСТВА и ПРЕДСТАВЛЕНИЯ. Тождество остаётся в интернере
нетронутым; представление переезжает в строку декларации. Невозможна смена тождества, а
не заведение представления.

классификации по источнику начинают различать четыре формы вместо двух.

**Дыра, найденная перепроверкой 2026-09-03, закрывается ЭТОЙ же волной:**
позитивного держателя value-записи НЕТ нигде — `NovaValue_` не ассертится ни

позитивный держатель: `value`-запись через `compile_to_c` (diags == 0 с
конструированием) плюс суд ЧЕРЕЗ ДВЕРЬ — `is_value_record(ctx, P) == true`.
Не по тексту C: P24 запрещает читать C-имя обратно, а
`check-novac-mangling-one-way` отказывает Nova-приставкам в ассертах тестов —
формулировка «по тексту C» первой редакции сама бы покраснела стражом
(поймано при заведении держателя).

**Приёмка:** сборка novac зелёная; `nova test novac/src/pipeline` зелёный,
включая НОВЫЙ позитивный держатель value-записи; корпус-контроль дифф-раннера ==

один `match` не забыт; **реверс**: в теле `is_value_record` арм `ValueRecord`
временно отвечает `false` (как `Record`) — новый позитивный держатель краснеет;
восстановить — зеленеет. (Реверс первой редакции — «заглушить
`NamedTupleRecord`» — не мог покраснеть ВООБЩЕ: в В1 этот вариант ещё никем не
порождается; найдено перепроверкой.)
**Замер до/после:** число прямых чтений поля (сейчас 1) и число мест, различающих форму
(сейчас 2).

### В2 — ЗАМЕР НЕПОДВИЖНОЙ ТОЧКИ (шаг 0, 2026-09-03) переформатирует объём

Правило «форму проверяют build, не check» применено к трём формам оракулом
(артефакты C прочитаны):

1. **Именованный кортеж-тип СОБИРАЕТСЯ.** `type Pair(x int, y int)` +
   `Pair(1, 2)` + `p.x`/`p.y` → оракул печатает `1`/`2`. Компилируется как
   ОБЫЧНАЯ запись с полями x, y и позиционным конструктором — ровно
   «конструктор есть функция».
2. **Умолчания конструктора СОБИРАЮТСЯ.** `type Complex(re f64 = 0.0,
   im f64 = 0.0)` + `Complex()` → `0`, `Complex(re: 3.5)` → `3.5`. Обычная
   семантика D102 (умолчание + именованный аргумент).
3. **Позиционный кортеж-тип НЕ собирается — дефект ОРАКУЛА.**
   `type Pt(int, int)` (и `Point(f64, f64)`) + `Pt(1, 2)` + `p.0` → оракул
   валится в C: `error: unknown type name '_NovaTuple_2_8_nova_int_8_nova_int'`.
   Форма законна по D215 (позиционные поля `.0`/`.1`), а кодоген оракула её не
   несёт — тот же класс «принято check, валит codegen», что мы чиним в novac.
   Замер обеих проб (int и f64) 2026-09-03, окно 274.

**Что из этого следует для объёма В2:**

- В2 берёт ТОЛЬКО именованную форму (`type Pair(x int, y int)`, с умолчаниями)
  — она оракулом поддержана, и это дом `RecordShape.NamedTupleRecord`. Это
  запись с именованными полями и функцией-конструктором; всё уже почти умеет
  путь записи, недостаёт разбора скобочного ОБЪЯВЛЕНИЯ и вызов-формы
  конструктора.
- ПОЗИЦИОННАЯ форma (`type Point(f64, f64)` + `.N`) из В2 УХОДИТ: раз оракул её
  сам не собирает, novac по дифф-правилу не обязан её компилировать, и
  «байт-в-байт» тут значило бы повторить сбой сборки. Форма переезжает в В3
  (`AnonymousTupleRecord`-территория) с ОГОВОРКОЙ, что сперва нужен вердикт по
  дефекту оракула (запись в реестр 221.1 заводит интегратор, заготовка ниже).

**Заготовка интегратору для реестра 221.1** (номер даёт он; страж не пускает
TBD в гейт — потому заготовка живёт здесь, как №850): **ОРАКУЛ НЕ СОБИРАЕТ
ПОЗИЦИОННЫЙ КОРТЕЖ-ТИП.** `type Pt(int, int)` + `Pt(1, 2)` + `p.0` — `nova
build` даёт C-ошибку `unknown type name '_NovaTuple_2_8_nova_int_8_nova_int'`;

### В2 разделена по шву «читать» / «конструировать»

Объём В2 оказался двумя связными половинами, и вторая требует машинерии
хойстинга: конструкция-вызовом строит структуру НЕСКОЛЬКИМИ операторами
(временная + присваивания по полям), то есть узел `Call` с ктор-вызываемым
должен хойститься, как `RecordCtor`. Это отдельная механика, а не хвост
разбора, — потому шов:

- **В2а — форма ЧИТАЕТСЯ** (парсер + sem): скобочное объявление даёт узлы
  `Field`, классификатор видит запись, поля попадают в таблицу, форма
  `NamedTupleRecord`. Фигурная конструкция при этом ОТКАЗЫВАЕТСЯ по имени.
- **В2b — конструкция ВЫЗОВОМ** (`Pair(1, 2)`): чекер типизирует позиционные
  аргументы против полей по порядку (умолчания — слоты D102), эмиттер строит
  структуру через хойст во временную.

#### В2а. СДЕЛАНО 2026-09-03 (окно 274)

Разбор: ветка `LParen` в `@type_decl` (parse.nv) читает поля тем же парным
разбором «[режим] имя + `@type_ref()`», что фигурная ветка, плюс умолчание
`= expr` той же формой, что параметр функции; запятая — тривия объявления.
Классификация: `shape_of_record_decl` различает три формы одним сканом
(VALUE_MARKER → ValueRecord, лист `LParen` → NamedTupleRecord, иначе Record).

**Фигурная конструкция отказана НАМЕРЕННО, и это замер, а не вкус:** оракул
принимает `Pair { x: 1, y: 2 }` своим `check` и валится в C
(`undeclared identifier 'Nova_Pair'`), то есть эмитить её значило бы придумать
конструкцию, которой у неподвижной точки нет. Отказ по имени называет рабочую
форму: «constructed by call -- `Pair(1, 2)`».

**ПОБОЧНАЯ НАХОДКА, и её нашёл СТРАЖ СЛОВА:** первая редакция В2а завела
дверь `is_named_tuple_record` — страж покраснел ростом 107 > 101, потому что
имя несёт запрещённое слово. Переименование в `is_paren_form_record` оставило
102: лишний +1 был ВТОРЫМ исчерпывающим match по виду типа, то есть второй
дверью с той же заставой (P18). Свёрнуто в ОДНУ дверь `shape_of(ctx, t) ->
RecordShape`, а обе булевых стали её чтениями — счёт вернулся к 101, и
архитектура стала честнее. Правило слова окупилось третий раз за смену.

**ВТОРАЯ НАХОДКА ВЛАДЕЛЬЦА, того же дня:** первая редакция решала форму по
листу `LParen` — «скобка значит именованный». Это неверно: `type Point(f64,
f64)` тоже открывается скобкой. Сегодня оно было право ПО СЛУЧАЙНОСТИ (парсер
читает только именованные поля, позиционная форма узлов `Field` не рождает и до
двери не доходит) — то есть перестало бы быть правым ровно в В3, когда
позиционная форма начнёт читаться. Признак теперь честный: скобка говорит
СЕМЕЙСТВО, а первое поле — ЧЛЕНА (имя перед типом → `NamedTupleRecord`, только
тип → `AnonymousTupleRecord`). Класс — «правильно по совпадению»: проверка,
которая верна лишь потому, что до неё не доходит другой случай.

**Приёмка В2а:** держатель `pipeline_test` — объявление читается (0
диагностик), форма подтверждена дверью `is_paren_form_record`, фигурная
конструкция отказана по имени; РЕВЕРС — ветка `LParen` отключена, держатель
краснеет, восстановлена — зелёный; `nova test` pipeline и sem PASS;
корпус-контроль 50/42 == база; страж слова 101 == база.

**Замер до/после:** `type Pair(x int, y int)` до В2а классифицировался как
НЬЮТАЙП над `int` (оба имени полей и второе поле терялись молча) — теперь это
запись формы NamedTupleRecord с двумя полями в таблице.

### В2b. Конструкция вызовом — СДЕЛАНО 2026-09-03

**Ваше правило сэкономило всю механику.** Конструктор зарегистрирован обычной
строкой таблицы функций (`register_paren_ctors`, sem.nv), поэтому арность,
именованные аргументы, умолчания и коэрсия — ответы СУЩЕСТВУЮЩЕГО резолвера;
волна не написала для них ни строки. Отказ на `Pair(1)` вышел ТОЧНЕЕ оракулова:
он называет пропущенный параметр («this call omits `y`, a parameter with no
default value»), а оракул говорит «expects exactly 2 arguments».

**Три структурных риска решены замером, а не выбором:**

1. Строка конструктора заводится ПОСЛЕ `collect_types_with`: `own_cnt`
   фиксируется его последней строкой (sem.nv:886), и строка, добавленная
   внутри, отвечала бы `compiles_body == true` — то есть врала бы, что у неё
   есть тело. Снаружи она честно отвечает false, и эмиттер по этому признаку
   печатает конструкцию, а не вызов.
2. В `defs` конструктор НЕ пишется: там одно плоское пространство с
   last-put-wins, и запись под именем типа вытеснила бы сам тип. Резолв вызова
   этого и не требует — `FnIndex` строится напрямую из `fns.rows`
   (resolve.nv:85-101). Оба факта сверены мной по коду.
3. Записывается `CalleeFn(row)`, а не `CalleeCtor(type)` — потому что
   конструктор ЕСТЬ функция, и эмиттеру нужна СТРОКА, чтобы прочитать значения
   умолчанных слотов. Первая проба `Complex()` иценула ровно на этом. Инвариант
   «тип в позиции вызова — не вызов функции» (type_of.nv) снят: он и был тем,
   что правило владельца отменяет; арм отвечает возвращаемым типом строки.

**Эмиссия — форма неподвижной точки:** составной литерал одним выражением,
`((NovaTuple_Pair){((nova_int)1LL), ((nova_int)2LL)})`, снят с C оракула. Хойст
не нужен (в отличие от фигурного конструктора, который строится по полям через
временную) — прежняя редакция карты его планировала зря.

**Приставка `NovaTuple_` — цитата ABI оракула, одной константой.** Наша эмиссия
линкуется в его оболочку, переименовать имя нельзя (P25). По P5 оно живёт в
`builtins` как данные (`PAREN_RECORD_C_PREFIX`), читает дверь манглинга. База
слова 101 → 102 поднята ОКНОМ и помечена ОТМЕНЯЕМОЙ: правило владельца
защищает от собственных сущностей со словом, а не от цитаты чужого ABI (тот же
класс `_NovaTuple_` уже в базе); при вето строка снимается вместе с эмиссией.

**Приёмка:** носитель `examples/basics/named_tuple.nv` (`Pair(1, 2)`,
`Complex()`, `Complex(re: 3.5)`) — смоук байт-в-байт с оракулом
(`1|2|0|3.5`); держатель В2b в `pipeline_test` (чекер принимает все три формы,
отказ называет пропущенный слот); **РЕВЕРС** — арм конструктора в эмиссии
заглушён: novac печатает вызов несуществующей C-функции и носитель не
собирается. Корпус-храповик 50/42 → 51/43; surface builtins 32 → 33 с
летописью; `nova test` pipeline и sem PASS; линт 8 файлов 0 находок.

**НАЙДЕНО РЕВЕРСОМ И НАЗВАНО В ДЕРЖАТЕЛЕ:** модульный держатель НЕ судит
эмиссию — `compile_to_c` не компилирует C, поэтому заглушка арма оставляет его
зелёным. Эмиссию держит носитель через смоук. Обе стороны названы прямо в
тексте держателя, чтобы его не прочитали шире, чем он судит.

Читать скобочную форму объявления тем же парным разбором «имя + `@type_ref()`», что уже
есть у фигурной ветки (`parse/parse.nv:467-498`), рождая узлы `Field`. Дальше
классификатор сам даст `ShapeRecord`, поля попадут в таблицу полей, и всё пойдёт путём
записи без единой новой двери.

**Приёмка:** носитель `examples/basics/named_tuple.nv` (`type Pair(x int,
y int)`, `Pair(1, 2)`, `p.x`, `p.y`) — смоук `novac-e1-smoke.sh` байт-в-байт с
оракулом (печатает `1`/`2`); второй носитель — умолчание `type Complex(re f64 =
0.0)` + `Complex()`/`Complex(re: 3.5)` (оракул `0`/`3.5`); **негатив** —
`Pair(1)` отказывается по имени про арность/слот; **реверс** — ветка разбора
скобочного ОБЪЯВЛЕНИЯ заглушена, оба носителя краснеют; корпус-храповик сдвинут
тем же слиянием. ПОЗИЦИОННАЯ форма (`.0`/`.1`) — НЕ здесь (шаг 0: оракул её сам
не собирает), она в В3.
**Замер до/после:** самодистанция — строка `self-distance=M/N` дифф-раннера
(`scripts/tools/novac-diff-corpus.sh`; N раннер считает сам, на 2026-09-03 это
64/65), и число отказов класса «constructing a newtype takes exactly one
argument» — греп этого текста по пачечному `novac check` всех novac/src.

### В3. Анонимный кортеж и снос второго окна

Синтезированная строка декларации (имя от мангла по D123, поля `f0..fN`) РЯДОМ с
тождеством, которое остаётся в интернере нетронутым. `emit_tuple.nv` удаляется, три его
двери растворяются в дверях записи, ветки по `TkTuple`/`is_tuple` в эмиттере уходят.

Имена файлов-носителей в `examples/` со словом tuple
(`tuple_pair_projection.nv` и ещё пять) — ВНЕ правила слова: страж судит
`novac/src`, а язык кортежи сохраняет; носители не переименовывать.

**Приёмка:** база `scripts/guards/novac-tuple-doors.baseline` опускается до `tuple_words=0`, и
страж подтверждает строкой «цель достигнута»; три существующих носителя корпуса
(`tuple_pair_projection`, `tuple_ctor_effect_order`, `tuple_mixed_pair_typedef`) остаются
байт-в-байт; файла `emit_tuple.nv` физически нет; **реверс** — возврат любой двери
краснит стража ростом.

## 3. Механизм, который держит результат

`scripts/guards/check-novac-tuple-no-second-door.py` заведён 2026-09-02, ДО работ.
Считает двери второго окна: (A) объявление функции с `tuple` в имени внутри `emit_c/`,
(B) ветка по `TkTuple`/`is_tuple` там же, (C) своя механика умолчаний у кортежа вне
`sem/`. Не запрещены и названы: спеллинг имени (`sem/mangle`, D123) и структурное
тождество (`types/`). Храповик ВНИЗ: база 6 на день заведения, рост красный сразу, цель
0 — и именно ноль в базе, а не ощущение, закрывает В3.

**Урок первого прогона, вписан в базу:** первая редакция стража искала границы слова и
насчитала НОЛЬ дверей при трёх существующих — подчёркивание словесный символ, и внутри
`emit_tuple_lit` границы слова нет; зелёный страж врал бы. Самотест держит этот случай
отдельной строкой; он же чуть не испортил живую базу (копия снималась на каждом вызове)
— исправлено, копия одна и до всего.

## 4. Не делаем (границы)

* **Тождество анонимного кортежа НЕ переводим в номинальное** — D123 называет его
  структурным, и это ключ таблицы типов, а не бухгалтерия.
* **Грамматику выражения `(a, b)` в `parse/` не трогаем** — В2 добавляет разбор
  ОБЪЯВЛЕНИЯ `type X(...)`, а не выражения.
* **Методы и перегруженные операторы на кортежах** в эти три волны не входят: они и есть
  то, ради чего окно сводится в одно, но приезжают своей волной после В3.

## 5. Открытые вопросы

1. Позиционному кортежу нужны имена полей в таблице полей: брать `f0..fN` (**умолчание**,
   совпадает с нынешним спеллингом эмиссии) или хранить поля без имён с доступом по
   индексу? Адресат — владелец; срок — старт В3; при молчании принимается умолчание.
2. **ABI-спеллинг `_NovaTuple_...`** — C-имя структуры анонимного кортежа,
   которым его называет ОРАКУЛ (снято с его вывода; линковка в оболочку идёт по
   этому имени). Правило слова его не милует: строки мангла с этим литералом
   сидят в базе стража и давят вниз, но переименовать их нельзя — имя не наше.
   Варианты: (а) ваша санкция на слово в ОДНОЙ двери мангла как названный
   интероп («уходит с собственной прелюдией») — тогда база останавливается на
   этом остатке до Э5; (б) без санкции — ноль достижим только вместе с
   собственной прелюдией. Адресат — владелец; умолчания НЕТ (правило говорит
   «только при моём согласовании»); срок — старт В3, до него ноль не нужен.
