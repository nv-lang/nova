# План 206.1 — Trap для `div`/`mod`/`neg` (подплан [206](206-arithmetic-overflow-policy.md))

**Статус:** ✅ РЕАЛИЗОВАН 2026-07-16 (ветка `p206-1-divtrap`, worktree `nova-2061`; Ф.0-Ф.3 завершены,
точечно верифицированы — чекпоинт волны удалён при закрытии, см. git-историю; полный `spec_tests/conformance`
гейт — у оркестратора). **Часть:** [206](206-arithmetic-overflow-policy.md)
(та же философия «арифметика = always-on safety, перф — Z3-элизией»). **После:** 206 Ф.1b (sized-trap) —
тот же лоуэринг-механизм бинопов. **Приоритет:** **P1** (div-by-zero сейчас = неконтролируемый крэш).

## Мотив (найдено при ревью 206, 2026-07-15)

`Div`/`Mod` лоуэрятся в **сырые C `/`/`%` БЕЗ guard** (`emit_c.rs` ~8204/~28047). Следствия:
- **Деление на ноль = UB** → на x86 `#DE` → **SIGFPE, неконтролируемый крэш процесса**, а НЕ чистая
  паника Nova с сообщением. Это крэш-вектор, а не just-UB — частая ошибка, роняет без диагностики.
- **`INT_MIN / -1` = overflow-UB** (частное `-INT_MIN` не влезает в тип).
- **`neg(INT_MIN)` = overflow-UB** аналогично (унарный минус).

206-примитив `@overflowing_*` сюда НЕ применим напрямую — у `div`/`neg` нет `__builtin_*_overflow`
(деление проверяется иначе: делитель≠0 и не `(MIN,-1)`). Поэтому — отдельный подплан, но той же школы.

## Дизайн (always-on trap + Z3-элизия, как 206)

- **`a / b` / `a % b` (все Ints):** перед делением — always-on guard:
  - `b == 0` → **паника** «division by zero» (ВСЕГДА, во всех режимах; это не overflow, а домен-ошибка).
  - signed `(a == T.MIN && b == -1)` → **паника** «division overflow» (частное вне диапазона).
  - иначе — обычное `/`/`%`.
  Guard — обычный код (не `requires`), как bounds в slice.nv (194 Ф.3). `optimized` Z3-элизия снимает
  доказуемо-безопасные (напр. `b` — ненулевая константа, `b` доказано ≠0/≠-1).
- **`-x` (унарный neg, signed):** `x == T.MIN` → **паника** «negation overflow»; иначе `-x`.
- **`.nv`-методы-обёртки** (по образцу 206, `fn[T Ints]`): `@checked_div(rhs) -> Option[T]`
  (`None` при b==0 или MIN/-1), `@checked_rem(rhs) -> Option[T]`, `@checked_neg() -> Option[T]`,
  `@wrapping_neg() -> T` (`neg(MIN)` → `MIN` модульно), `@wrapping_div`/`@wrapping_rem` (где осмысленно).
  Unsigned div: только `b==0`-guard (overflow невозможен).

## Фазы
- Ф.0 Спека: D-амендмент (div-by-zero/div-overflow/neg-overflow = always-on trap; методы). Ссылка из 206.
- Ф.1 Codegen: guard-лоуэринг `Div`/`Mod`/унарный-neg (все Ints); интринсик-хелперы
  `nova_<T>_checked_div`/`_rem`/`_neg` в `effects.h`; Z3-элизия по `index_site_elided`-аналогу.
- Ф.2 std: `.nv`-бланкеты `@checked_div`/`@checked_rem`/`@checked_neg`/`@wrapping_neg` на `fn[T Ints]`.
- Ф.3 Тесты: div-by-zero → паника (не SIGFPE); `INT_MIN/-1` → паника; `neg(INT_MIN)` → паника; методы
  на границах; unsigned div (только zero-guard); const-делитель → Z3-элизия guard'а (optimized).

## Гейты
conformance + фикстуры паник (div0, div-overflow, neg-overflow — текст стабильный, пиновый);
байт-паритет обычного `/`/`%`/`neg` вне граничных случаев; std δ0.

## Границы
Только целочисленные div/mod/neg. f64-деление (IEEE: /0 = inf/nan, не trap) НЕ трогаем. Retag из
backlog `[M-div-neg-overflow-trap]`.
