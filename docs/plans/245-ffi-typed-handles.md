# План 245 — Типизированные ручки на границе FFI (миграция std)

> **Статус:** 🆕 ЗАПЛАНИРОВАН 2026-08-02. Дефект — [№288](221.1-bug-sweep.md).
> Канон и первый образец — план [244](244-channel-in-nova.md) (ДО тега);
> миграция существующих мест std — ПОСЛЕ тега.

## Зачем

Ни одно объявление `extern "C"` в std не принимает типизированную обёртку:
все параметры — примитивы и сырые `*()`/`int` (проверено грепом 2026-08-02).
Следствие: дескриптор файла можно передать туда, где ждут дескриптор
каталога; сторону записи — туда, где ждут сторону чтения; компилятор не
возразит, потому что с его точки зрения везде один и тот же `int` или
`void*`.

Решение владельца 2026-07-09 требовало обратного (маркер
`[M-ffi-handle-newtype]`: «FFI-хендлы не гуляют по модулю голым
int/указателем — заворачивать в типизированную обёртку»), но канон не
сложился: маркер получил приоритет P3 «после лимитов» и не всплывал.
Слово владельца 2026-08-02: «это недоработка, которую надо исправить».

## Что доказано (проба интегратора 2026-08-02)

Механизм есть и работает без единой доработки компилятора:

```nova
type ChanTx(*())
extern "C" fn probe_take(h ChanTx, n int) -> int
```

порождает в C:

```c
typedef void* Nova_ChanTx;
nova_int r = probe_take(h, ((nova_int)1LL));
```

Обёртка прозрачна — уходит как `void*` через typedef, значение передаётся
напрямую. **`unsafe` для такого вызова НЕ требуется** (проба дала
`E_UNSAFE_UNUSED` — «в блоке нет небезопасных операций»): небезопасность
возникает от работы с сырыми указателями, а не от самого перехода границы.

## Объём миграции

| Зона | Что сейчас | Что должно стать |
|---|---|---|
| `std/src/fs/ffi.nv` | `fs_open(...) -> int`, `fs_scandir_open(...) -> int`, дескриптор гуляет голым `int` | `type Fd(int)` / `type ScanDir(int)`; остаток маркера `[M-ffi-handle-newtype]` («хендл пересекает Fs-эффект») разбирается здесь |
| `std/src/net/ffi.nv` | сырые `*()` между приватными функциями | типизированные ручки сокета/адреса |
| `std/src/encoding/compress/` | сделано частично (BrotliDec) — `int` только на границе внутри методов | довести до общего канона |
| прочие `extern "C"` | 116 объявлений — сплошная ревизия | ручка → своя обёртка |

Порядок: сначала ревизия-инвентаризация (какие символы вообще принимают
ручки), затем зона за зоной, каждая — отдельным слиянием с гейтом.

## Связанное ограничение (проверить, не блокер)

`[M-newtype-receiver-method-dispatch]` — методы на newtype-ресивере
регистрируются по имени и могут диспатчиться на чужой одноимённый метод в
том же compile-unit. В `brotli` это обошли прямыми вызовами типизированных
внешних функций. Если миграция добавляет методы на ручках — сначала
проверить, закрыт ли этот дефект; если нет, ручки остаются без методов
(типобезопасность параметров это не отменяет).

## Приёмка

Полный гейт после каждой зоны; каноны без сдвига; `nova lint` 0;
негативная фикстура на зону: передача чужой ручки в функцию → ошибка типов
(сегодня такой код компилируется молча). Маркер `[M-ffi-handle-newtype]`
закрывается последним слиянием.
