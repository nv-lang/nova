# План 289 — регулярные выражения: свой движок RE2-семьи, довести `std/text/regex.nv`

**Статус:** ОТКРЫТ 2026-09-15, ни одна фаза не начата. Решение владельца 2026-09-15 по
исследованию [2026-09-15-regex-engine.md](../dev/research/2026-09-15-regex-engine.md): чужую
библиотеку (PCRE2, RE2, Oniguruma) в std не интегрировать; развивать собственный движок на Nova.
Спека прежде реализации (Ф.0), std следом.

## Откуда план

Вопрос владельца: какую библиотеку регулярок используют Rust, Go, Swift, Kotlin, JS, Python, PHP
и какую брать нам. Ответ исследования: две семьи движков, и для Nova подходит только RE2-семья —
линейное время на любом шаблоне (пользовательский шаблон не может повесить процесс), никакой
C/C++-зависимости для Карины, парсер шаблона исполним компилятором для проверки тега `regex`
при компиляции (D48). В std уже лежит такой движок (NFA Томпсона, 683 строки, тесты зелёные),
но без захватов, флагов и Unicode-классов, и с API вне канона имён.

## Границы — «Не делаем»

- Backrefs `\1`, lookaround `(?=…)`/`(?<=…)`, атомарные группы, possessive-квантификаторы —
  **никогда**: математически требуют отката, ломают гарантию линейного времени. Кому нужны —
  PCRE2 пользовательским пакетом через `extern "C"`, не std.
  **Не путать с захватами:** скобки `(…)`, `group(1)`, `$1` в замене — есть (Ф.2); нет только ссылки
  на группу ВНУТРИ шаблона. Сравнение частей входа между собой делается кодом после совпадения —
  так и записать в D48 (рецепт, не запрет).
- Grapheme-семантика по умолчанию (Swift) — нет; единица — кодовая точка, как у Go/Rust.
- JIT — нет.
- `@comptime` — не этот план (D48: v2); Ф.5 ждёт его.

## Диалект (нормативно, войдёт в D48-амендмент Ф.0)

RE2-синтаксис в объёме Go `regexp/syntax`: литералы и экраны; `.`; классы `[…]`, `[^…]`,
`\d \w \s \D \W \S`, `\p{L}`/`\P{…}` по общим категориям Unicode; якоря `^ $ \A \z`, `\b \B`;
квантификаторы `* + ? {n} {n,} {n,m}` и нежадные `*? +? ?? {n,m}?`; группы `(…)`, `(?:…)`,
именованные `(?P<name>…)` и `(?<name>…)`; альтернация; флаги `(?i)`, `(?m)`, `(?s)`, `(?U)` и
области `(?i:…)`. Гарантия: время `O(len(input) × len(pattern))`, память ограничена размером
автомата. Семантика совпадения — leftmost-first (как Go/Rust/Perl), не POSIX leftmost-longest.

## Фазы

### Ф.0 — спека и статус (до кода)

- Амендмент D48 (`03-syntax.md`): диалект выше, гарантия линейности, «две двери» — тег
  `` regex`…` `` для константных шаблонов и `s.to_regex()` для динамических; чего не будет
  никогда. Страницы `syntax.md`/`syntax.ru.md` — обе языковые версии.
- `std/src/STATUS.md`: снять устаревшие записи `:107`, `:173`, `:370` (regex check-fail) — модуль
  проходит `nova check` и `nova test` на 2026-09-15.
- **Приёмка:** D48-амендмент датирован; `grep regex std/src/STATUS.md` не содержит «check-fail».

### Ф.1 — API по канону (решения владельца помечены)

| сегодня | канон | норма |
|---|---|---|
| `Regex.compile(s str) -> Result[Regex, CompileError]` | `fn str @to_regex() -> Result[Regex, RegexError]` | конверсия из значения — метод на источнике (D54 амендмент 2026-09-05, стиль §1а); статик из значения — снятая дверь `str.parse_*` |
| `CompileError` | `RegexError enum …` с полем `at int` у каждого варианта | D325 `<Domain>Error`; позиция как в `ParseIntError.InvalidDigit { at }` |
| `@find -> Option[(int, int)]` | `@find -> Option[Match]`, `Match { start int, end int, text str }` | кортеж без имён теряет читателя при появлении групп |
| `@find_all -> [](int, int)` | `@find_all -> []Match`; `@find_iter` — Ф.2 | то же |
| `@matches(text) -> bool` | оставить | — |

Оба переименования (`to_regex`, `RegexError`) — **решение владельца**; план записан под
рекомендацию. **Приёмка:** `nova test std --filter regex` PASS; `grep -rn "Regex.compile\|CompileError"`
по дереву — ноль в коде; `W_STATIC_CONVERSION` на модуле не поднимается.

### Ф.2 — захваты

PikeVM с нитями захватов (Russ Cox, «Regular Expression Matching: the Virtual Machine Approach»):
слоты позиций на нить, приоритет нитей = leftmost-first. API: `Match @group(i int) -> Option[str]`,
`@group(name str)`, `@groups() -> []Option[str]`; `Regex @captures(text) -> Option[Match]`;
`@replace(text, with str) -> str` с `$1`/`${name}`; `@replace_all`; `@split(text) -> []str`;
`@find_iter(text) -> RegexIter`. **Приёмка:** тесты на вложенные и повторяющиеся группы
(последняя итерация побеждает, как Go), пустые совпадения в `find_iter` не зацикливаются
(`a*` на `"baaa"` даёт 4 совпадения), `replace` с `$0`/`$$`; линейность сохранена — тест
`(a+)+b` на 10^5 `a` укладывается в бюджет времени теста.

### Ф.3 — синтаксис до диалекта

Нежадные квантификаторы, `{n,}`, `\b \B \A \z`, флаги и области флагов, `(?i)` через
`std/unicode` simple case folding, `\p{…}`/`\P{…}` по `general_category`, класс `[[:alpha:]]`
(ASCII, как Go). Ошибки парсера — все варианты `RegexError` с позицией. **Приёмка:** портированное
подмножество Go `regexp/syntax` тестов (`parse_test`, `re2-exhaustive` не берём) в
`regex_test.nv`; на каждую неподдерживаемую конструкцию (`\1`, `(?=`) — тест на
`RegexError.Unsupported { at, what }`, не тихий разбор.

### Ф.4 — скорость

Литеральный префильтр (обязательный префикс/подстрока через `str.find`), затем lazy DFA с
кэшем состояний и откатом на PikeVM при переполнении кэша (Rust `regex-automata` hybrid).
**Приёмка:** `std/bench.nv` — три шаблона (литерал, класс+квантификатор, альтернация) на 1 МБ
текста; DFA-путь не медленнее PikeVM ни на одном, быстрее ≥5× на литеральном; корректность —
дифференциал DFA против PikeVM на всём тестовом корпусе.

### Ф.5 — тег `regex` (зависит от `@comptime`)

`` regex`\d+` `` → `Regex` с проверкой шаблона при компиляции тем же парсером Ф.3; ошибка
шаблона — ошибка компиляции с позицией внутри литерала. **Приёмка:** pos-фикстура с тегом,
neg-фикстура `EXPECT_CC_ERROR` на `` regex`(` ``. До `@comptime` — тег как обычная функция D48 с
рантайм-`Result`.

## Followups

- Grapheme-режим как флаг (`(?g)`) — если появится запрос; Swift-прецедент.
- Совместимый с PCRE2 пользовательский пакет `regex_pcre` — вне std, при первом носителе: три-четыре
  extern-функции (`pcre2_compile`, `pcre2_match`, `pcre2_match_data_create`, `pcre2_code_free`), тип с
  `consume`-освобождением, ОБЯЗАТЕЛЬНО `match_limit`/`depth_limit` по умолчанию — экспоненциальный шаблон
  падает ошибкой, не вешает процесс. Портировать PCRE2/Oniguruma на Nova — нет: десятилетия граничных
  случаев Perl-семантики и свои Unicode-таблицы, третий движок навечно.
- Если backrefs понадобятся в std — путь Rust `fancy-regex`: ограниченный backtracker НАД PikeVM только
  для шаблонов с `\1`/lookaround, остальное линейно. Отдельный план после 289, при носителе. **Это НЕ совместимость с PCRE2:** fancy-regex — RE2-диалект плюс backrefs, lookaround и атомарные группы; нет условных групп, рекурсии `(?R)`, `\K`, глаголов `(*SKIP)`; `\w`/`\d` там Unicode по умолчанию, в PCRE2 — ASCII без `UCP`. Чужие Perl/PHP-шаблоны как есть — только `regex_pcre`.
- Строка реестра: `std/src/STATUS.md` содержит записи о check-fail модулей, которые сегодня
  зелёные (`regex`, вероятно и другие) — STATUS не проверяется машиной; кандидат на скрипт-страж.
