# План 289 — регулярные выражения: свой гибридный движок, довести `std/text/regex.nv`

**Статус:** ОТКРЫТ 2026-09-15, ни одна фаза не начата. Решения владельца: 2026-09-15 — чужую
библиотеку (PCRE2, RE2, Oniguruma) в std не интегрировать, развивать собственный движок на Nova
(исследование [2026-09-15-regex-engine.md](../dev/research/2026-09-15-regex-engine.md));
**2026-09-17 — движок гибридный сразу:** линейное ядро RE2-семьи плюс откат-надстройка по образцу
Rust `fancy-regex` для backrefs, lookaround и атомарных групп; константный шаблон — тегом
`` re`…` ``; PCRE2 — отдельный модуль со своим тегом, когда-нибудь. Спека прежде реализации (Ф.0),
std следом.

## Откуда план

Вопрос владельца: какую библиотеку регулярок используют Rust, Go, Swift, Kotlin, JS, Python, PHP
и какую брать нам. Две семьи движков: Perl-линия (полнота, экспоненциальный худший случай) и
RE2-линия (линейное время, без backrefs). Для Nova — своё: линейное ядро как гарантия для
пользовательских шаблонов и для Карины без libc; парсер шаблона исполним компилятором для проверки
тега при компиляции (D48). В std уже лежит ядро (NFA Томпсона, 683 строки, тесты зелёные), но без
захватов, флагов, Unicode-классов, с API вне канона имён. Владелец 2026-09-17: «сделать сразу
аналог fancy-regex» — откат не откладывать до носителя, а построить в этом плане над ядром.

## Границы — «Не делаем»

- Совместимость с PCRE2 (условные группы `(?(1)…)`, рекурсия `(?R)`, `\K`, глаголы `(*SKIP)`,
  callouts, ASCII-семантика `\w` без `UCP`) — нет. Перенос чужих Perl/PHP-шаблонов как есть —
  **отдельный модуль** поверх PCRE2 через `extern "C"`, со своим тегом (рабочее имя `` pcre`…` ``),
  когда появится носитель; в std не входит.
- Grapheme-семантика по умолчанию (Swift) — нет; единица — кодовая точка, как у Go/Rust.
- JIT — нет.
- `@comptime` — не этот план (D48: v2); Ф.6 использует его, когда появится.

## Диалект (нормативно, войдёт в D48-амендмент Ф.0)

**Линейная часть** — RE2 в объёме Go `regexp/syntax`: литералы и экраны; `.`; классы `[…]`, `[^…]`,
`\d \w \s \D \W \S`, `\p{L}`/`\P{…}` по общим категориям Unicode; якоря `^ $ \A \z`, `\b \B`;
квантификаторы `* + ? {n} {n,} {n,m}` и нежадные `*? +? ?? {n,m}?`; группы `(…)`, `(?:…)`,
именованные `(?P<name>…)` и `(?<name>…)`; альтернация; флаги `(?i)`, `(?m)`, `(?s)`, `(?U)` и
области `(?i:…)`. Гарантия: `O(len(input) × len(pattern))`. Семантика — leftmost-first.

**Откат-часть** (fancy-regex): backrefs `\1`…`\9`, `\k<name>`; lookahead `(?=…)`, `(?!…)`;
lookbehind `(?<=…)`, `(?<!…)` в т. ч. переменной длины; атомарные группы `(?>…)`; possessive
`*+ ++ ?+`. Исполняются откатом с **бюджетом шагов** (по умолчанию 1 000 000, как fancy-regex);
куски шаблона без этих конструкций гонятся линейным ядром как подпрограммы. Гарантия линейности
на такие шаблоны **не распространяется** — это и есть цена, и она видна в двух местах: в тексте
шаблона и в `backtracking: true` у динамической двери.

## Две двери и одно правило

| откуда шаблон | запись | что принимает |
|---|---|---|
| константа в коде | `` re`(\w+) \1` `` (тег D48; имя `re` — решение владельца 2026-09-17, амендмент D48 с `regex` на `re`) | весь диалект; с `@comptime` — проверка при компиляции, до него — рантайм-`Result` как у любого тега |
| динамический (ввод, конфиг) | `s.to_regex()` | **только линейная часть**; `\1`/`(?=` → `Err(RegexError.Backtracking { at })` |
| динамический, автор согласен на откат | `s.to_regex(backtracking: true)` | весь диалект, бюджет шагов по умолчанию; `steps:` — переопределить |

Правило одно: **шаблон с откатом появляется в программе только там, где автор его видит** — в
литерале или за явным аргументом. Пользовательский ввод без согласия автора остаётся линейным.

### В.1 подробно — умолчание `backtracking` и исчерпание бюджета

Вопрос владельца 2026-09-17: «`backtracking: true` — по умолчанию включённым?». Умолчание и
поведение при исчерпании бюджета шагов связаны жёстко: динамический шаблон приходит из ввода, и
если откат включён по умолчанию, `(a+)+\1` от пользователя упрётся в бюджет на обычной строке.

| умолчание `to_regex()` | при исчерпании бюджета | итог |
|---|---|---|
| **выключен**, `backtracking: true` явно | panic с шаблоном и позицией (D13: контракт «откат-шаблон укладывается в бюджет» нарушен автором) | безопасно по умолчанию; API поиска без налога — `bool`, `Option[Match]`; риск принимается одним аргументом там, где он реален. Прецедент: Go, Rust — линейный дефолт |
| включён | panic | **крах сервера от строки пользователя** — тот же DoS, только вместо зависания. Исключено |
| включён | все методы поиска → `Result[…, RegexError]` с `BacktrackLimit` | безопасно, `\1` из ввода работает; налог — `!!`/`?` на каждом `matches`/`find`, включая литералы, у которых сбой невозможен. Это дизайн fancy-regex (`is_match -> Result<bool>`). Прецедент дефолта: .NET — наследие, линейный режим добавлен флагом |

Третьего пути («включено и без налога») нет: каналу отказа у поиска нужно быть либо у всех
методов, либо ни у кого; разделить типы по содержимому строки без `@comptime` нельзя.

**Рекомендация окна — первая строка.** План записан под неё. Выбор третьей строки меняет
сигнатуры Ф.2 (`@matches -> Result[bool, RegexError]`, `@find -> Result[Option[Match], RegexError]`,
`@find_iter` — `Iter[Result[Match, RegexError]]`) и снимает `Backtracking { at }` из Ф.1.

- `std/src/STATUS.md`: снять устаревшие записи `:107`, `:173`, `:370` (regex check-fail) — модуль

- **Приёмка:** D48-амендмент датирован; `grep regex std/src/STATUS.md` без «check-fail».

### Ф.1 — API по канону

| сегодня | канон | норма |
|---|---|---|
| `Regex.compile(s str) -> Result[Regex, CompileError]` | `fn str @to_regex(backtracking bool = false, steps int = 1_000_000) -> Result[Regex, RegexError]` | конверсия из значения — метод на источнике (D54 амендмент 2026-09-05, §1а); статик из значения — снятая дверь |
| `CompileError` | `RegexError enum … { at int }` у каждого варианта, плюс `Backtracking { at }` (конструкция отката без согласия) и `Unsupported { at, what }` | D325 `<Domain>Error`; позиция как в `ParseIntError.InvalidDigit { at }` |
| `@find -> Option[(int, int)]` | `@find -> Option[Match]`, `Match { start int, end int, text str }` | кортеж без имён теряет читателя при появлении групп |
| `@find_all -> [](int, int)` | `@find_all -> []Match`; `@find_iter` — Ф.2 | то же |
| `@matches(text) -> bool` | оставить | — |

Именованные аргументы с умолчаниями — по D88. **Приёмка:** `nova test std --filter regex` PASS;
`grep -rn "Regex.compile\|CompileError"` по дереву — ноль в коде; `W_STATIC_CONVERSION` на модуле
не поднимается.

### Ф.2 — захваты (линейное ядро)

PikeVM с нитями захватов (Russ Cox, «Regular Expression Matching: the Virtual Machine Approach»):
слоты позиций на нить, приоритет нитей = leftmost-first. API: `Match @group(i int) -> Option[str]`,
`@group(name str)`, `@groups() -> []Option[str]`; `Regex @captures(text) -> Option[Match]`;
`@replace(text, with str) -> str` с `$1`/`${name}`; `@replace_all`; `@split(text) -> []str`;
`@find_iter(text) -> RegexIter`. **Приёмка:** вложенные и повторяющиеся группы (последняя итерация
побеждает, как Go); пустые совпадения в `find_iter` не зацикливаются (`a*` на `"baaa"` — 4
совпадения); `replace` с `$0`/`$$`; линейность — `(a+)+b` на 10^5 `a` в бюджете времени теста.

### Ф.3 — парсер всего диалекта

Нежадные квантификаторы, `{n,}`, `\b \B \A \z`, флаги и области флагов, `(?i)` через
`std/unicode` simple case folding, `\p{…}`/`\P{…}` по `general_category`, `[[:alpha:]]` (ASCII, как
Go). **Откат-конструкции разбираются в AST уже здесь** (`NBackref`, `NLookahead`, `NLookbehind`,
`NAtomic`, possessive как `NAtomic(NRepeat)`) — до Ф.5 они дают `RegexError.Backtracking { at }`
без `backtracking: true` и `Unsupported` с ним. **Приёмка:** портированное подмножество Go
`regexp/syntax` тестов в `regex_test.nv`; на каждую откат-конструкцию — тест разбора в AST и тест
отказа без согласия; PCRE2-только конструкции (`(?(1)`, `(?R)`, `\K`, `(*SKIP)`) →
`Unsupported { at, what }` с текстом «PCRE2-only; see the pcre module».

### Ф.4 — скорость линейного ядра

Литеральный префильтр (обязательный префикс/подстрока через `str.find`), затем lazy DFA с
кэшем состояний и откатом на PikeVM при переполнении кэша (Rust `regex-automata` hybrid).
**Приёмка:** `std/bench.nv` — три шаблона (литерал, класс+квантификатор, альтернация) на 1 МБ
текста; DFA не медленнее PikeVM ни на одном, быстрее ≥5× на литеральном; дифференциал DFA против
PikeVM на всём тестовом корпусе.

### Ф.5 — откат-надстройка (fancy-regex)

Разбиение AST на «сложные» узлы и максимальные линейные поддеревья; линейные поддеревья
компилируются ядром Ф.2 и вызываются как подпрограммы; сложные — интерпретатор отката с явным
стеком, счётчиком шагов и слотами захватов, откатываемыми вместе с позицией. Lookbehind
переменной длины — обратный прогон линейного поддерева. Превышение бюджета — по решению владельца
(раздел выше). **Приёмка:** тесты на `(\w+)\s+\1` (повтор слова), `(["'])(.*?)\1`, lookahead-пароль
`^(?=.*\d)(?=.*[a-z]).{8,}$`, lookbehind `(?<=\$)\d+`, атомарная `(?>a+)b` не матчит `aab`…;
дифференциал против Rust `fancy-regex` на общем корпусе (внешний оракул, не зависимость);
`(a+)+\1` на 10^4 `a` — упирается в бюджет предсказуемо, не висит; шаблон без откат-конструкций
с `backtracking: true` идёт линейным путём (замер: те же `nova_idx`-счётчики/время, что без флага).

### Ф.6 — тег `re` (зависит от `@comptime`)

`` re`\d+` `` → `Regex` с проверкой шаблона при компиляции парсером Ф.3; ошибка шаблона — ошибка
компиляции с позицией внутри литерала; шаблон с откат-конструкциями — предупреждение
`W_REGEX_BACKTRACKING` (видимость цены), не ошибка. **Приёмка:** pos-фикстура с тегом,
neg-фикстура `EXPECT_CC_ERROR` на `` re`(` ``, фикстура с предупреждением на `` re`(\w+) \1` ``.
До `@comptime` — тег как обычная функция D48 с рантайм-`Result`.
