# Plan 196.5 — closure-lowering fix (два codegen-дефекта волны producers-widen)

**Ветка:** `closure-lowering-fix` (worktree `nova-174`), база `f07cd0991`.
**Задание:** фиксы двух дефектов из 196.5-producers-widen-notes.md §closure-lowering-gap
и §B11x (попутная находка record_schemas).

## ДЕФЕКТ-1: erased лямбда-сигнатура — ПОЧИНЕН

**Симптом:** `d30cr_ror_from_closure(true, || 7, "boom")` — mono-имя вызова
специализируется верно (`____nova_int`), но `nova_lambda_N_body` эмитится с
erased-возвратом `Nova_T*` → CC-FAIL (`returning 'const nova_str' from a function
with incompatible result type 'Nova_T *'`).

**Первопричина (checker-продюсер, НЕ emit_c):** `f1_check_call` (types/mod.rs)
в арг-цикле материализовал literal-coercion против СЫРОГО объявленного типа
параметра (`f fn() -> T`). Арм `ClosureLight` в `materialize_literal_coercion`
(~12558) гейтится `ConcreteNamedNoArgs`, который ПРОПУСКАЕТ голый `Named("T")`
(любое имя без args) → в `resolved_types[closure_id]` штамповался ЛОЖНЫЙ
`Func{ret: Named("T")}`. На эмите channel-first `closure_channel_ret_c`
(emit_c.rs ~46303) читает канал ПЕРЕД legacy body-walk → `Nova_T*`.

**Фикс (в правильном месте — продюсер не должен лгать):** types/mod.rs
`f1_check_call`: (1) resolved subst вызова (producer-A unify + turbofish overlay)
захватывается в `arg_subst`; (2) в арг-цикле параметр, упоминающий generics
callee, субституируется ПЕРЕД материализацией; residual/отсутствующий subst →
материализация ПРОПУСКАЕТСЯ (отсутствие честно — потребители падают на legacy
body-walk; erased-штамп — ложь). Не-generic параметры — byte-identical legacy.

**Верификация:** `spec_tests/conformance/d30_closure_return_generic.nv` (новый,
из docs/plans/196.5-producers-widen-d30-closure-return-gap.nv — gap-файл удалён);
лямбды в C теперь `static nova_int nova_lambda_0_body` / `static nova_str
nova_lambda_1_body`; test-build PASS.

**Флак (НЕ этой волны):** точечный test-build любого conformance-файла мерцает
RUN-FAIL ~1/3 прогонов И НА БАЗЕ без нового файла — обрыв вывода после
d158-теста; сигнатура идентична известному мерцающему c_keyword_ident_mangling.
Точечный ре-ран зелёный. Не чинилось (per задание).

## ДЕФЕКТ-2: record_schemas-гэп `Vec[T].new()` в prefix-generic теле — ПОЧИНЕН

**Симптом:** `Vec[T].new()` внутри тела `fn[T] []T @method` → `codegen error:
anonymous record literal: expected struct 'Vec____Nova_T_p' not in record_schemas`.

**Первопричина (backtrace-доказательство, NOVA_D2_TRACE):** `emit_fn` (emit_c.rs
~22947) для array-ext методов ПРОВАЛИВАЛСЯ в legacy erased-эмит тела (один раз, без
subst) — В ДОПОЛНЕНИЕ к per-elem mono-инстансам (Plan 101.1). В erased-контексте
turbofish `Vec[T].new()` лоуэрит `T` → `Nova_T*` и регистрирует erased-инстансы:
generic-ТИП `Vec____Nova_T_p` (drain-гард типов его отсекает → нет в record_schemas)
+ МЕТОД `..._static_new` через `register_mono_method_instance` (placeholder-гард там
проверяет только fn_decl.generics — у Vec.new они пусты, T принадлежит шаблону
ТИПА → гард молчит). Drain mono_worklist эмитит тело static_new → record-литерал
ждёт `Vec____Nova_T_p` → loud Err. Erased-символы instance prefix-generic методов
(`Nova_NovaArray_nova_int_method_*`) в CU НИКЕМ не вызываются (пруф: count=1 по
полному C, только определение) — мёртвый груз.

**Фикс (mono = фаза, не побочный эффект):** emit_c.rs `emit_fn` — INSTANCE
prefix-generic slice-ext метод (`fn[T] []T @m`, элемент ресивера = объявленный
prefix-параметр) больше НЕ эмитится erased; тела только из mono-конвейера.
STATIC-семейство (`fn[T] []T.m(...)`) сохраняет erased-базу — она несущая
(call-site `Vec[int].echo2` линкуется на `Nova_NovaArray_nova_int_static_echo2`,
slice_static_generic_method.nv; без неё undefined symbol). Конкретные ресиверы
(`fn []int @max`) и method-own generics (`fn[U] []int @m`) не тронуты.

**Верификация:** `spec_tests/conformance/d145_prefix_generic_vec_construct.nv`
(int+str элементы) PASS.
