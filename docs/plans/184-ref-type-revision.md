# План 184 — Ревизия D326: `ref T` как ограниченный тип (черновик на проверку владельцу)

> **Статус:** ЧЕРНОВИК-РЕВИЗИЯ (обсуждение 2026-07-06, дизайн надиктован владельцем).
> Реализация НЕ начата. По «ок» владельца — амендмент D326 + реализация.
> **Маркер:** `[M-184-ref-type-revision]`.

## 1. Суть (решения владельца)

`ref T` — **валидный тип** (аналог C++ `T&`), но **ограниченный позициями**:
параметры, возвраты, локальные переменные. Мотивация-первопричина: легализовать
тип приёмника — `@` это всегда `ref Self` (для стековых), `-> @` — тоже.

## 2. Правила

- **(Р1) Позиции.** `ref T` легален: параметр (`mut x ref T` / `ro x ref T`),
  возврат (`-> ref Self` — де-сахар `-> @` для value-типов), локал
  (`ro y ref T = x.a.b` — именованный алиас). ЗАПРЕЩЁН: поля, коллекции,
  суммы, Option (ссылка на стек не должна утекать в долгоживущую кучу).
- **(Р2) mut.** В `mut x ref T` слово `mut` = право ПИСАТЬ через ссылку в цель.
  Сама ссылка непереселяемая (как C++ `T&`: связал — навсегда).
- **(Р3) Синтаксис параметра.** `ro|mut ИМЯ ref T` (ref в типовой позиции).
  Старая форма `mut ref x T` (D326-R2) — ретрактится с миграцией.
- **(Р4) МАРКЕР ВЫЗОВА УДАЛЁН.** Вызов везде `f(x)` — без `ref x`.
  Обоснование владельца: кучевые объекты и так мутируются без маркера —
  маркер на стековых давал ложное чувство «нет ref = нет мутации».
  Следствие: пара перегрузок `f(x T)` и `f(mut x ref T)` неразличима на
  вызове — ЗАПРЕЩЕНА (уточнение осей D84: E_OVERLOAD_REF_AMBIGUOUS).
- **(Р5) Автоконверсия.** `ref T -> T` автоматически (чтение = разыменование).
  `T -> ref T` на месте вызова автоматически для адресуемых аргументов
  (неадресуемый аргумент к mut-ссылке — ошибка, как сейчас).
- **(Р6) Нормализация над кучей.** Для кучевого `H`: `ref H` ≡ `H`
  (значение уже handle; ссылка на handle не вводится). Важно для
  обобщённых `f[T](mut x ref T)` при `T = H`.
- **(Р7) Типизация приёмника.** Стековый (value) тип: `mut @` = `mut ref Self`,
  `ro @` = `ref Self`/копия по размеру (невидимо), `-> @` = `-> ref Self`.
  Кучевой: `@` = `Self`, `-> @` = `-> Self`. Магия D181-R7/R8 («heap алиас /
  value копия-с-распадом») ЗАМЕНЯЕТСЯ этими типами.
- **(Р8) Безопасность без лайфтаймов.** Висячие ссылки исключаются связкой:
  запрет утечки в кучу (Р1) + существующий escape-анализ с авто-промоутом
  (D216 §4: убегающий источник поднимается в кучу) + запрет захвата ссылок
  замыканиями (как сейчас E_REF_ESCAPE_CAPTURE).
- **(Р9) Эксклюзивность/адресуемость/FFI** — без изменений (узкая
  E_REF_ALIAS_OVERLAP; на extern-границе только сырые `*`/`*mut`).

## 2а. Ревизия раунда 2 (обсуждение 2026-07-06, решения владельца)

- **(Р10) `ref` исчезает из сигнатур параметров вовсе:**
  - `ro`: `f(x T)` — представление (копия ≤~16Б / скрытая ссылка) выбирает компилятор
    по размеру; ненаблюдаемо (с оговоркой Р12). Явный `ro ... ref` в параметре — убрать.
  - `mut`: **`f(mut x T)` ≡ in-out ссылка ВСЕГДА** (унификация со стеком/кучей: на куче
    приватной мутируемой копии и так нет). Локальная копия — явным локалом `mut y = x`.
    Неоднозначность перегрузок исчезает по построению (форма одна).
  - `consume`: `f(consume x T)` — владение; представление считает компилятор.
  - `ref` остаётся: тип приёмника (`@` = `ref Self`), `-> @` (= `-> ref Self` у value),
    локальные алиасы (форму локала уточнить: `ro y ref T = ...`).
- **(Р11) Аудит-миграция mut-параметров.** Семантика `mut x T` меняется
  (была приватная копия → станет in-out): перед реализацией grep-аудит всех
  mut-параметров std/тестов, кто полагался на приватность — переписать на локал.
- **(Р12) Расширение узкой эксклюзивности (упущение, найдено на ревью).**
  ro-автопредставление наблюдаемо при алиасинге ro×mut в ОДНОМ вызове
  (`f(a, a)` c `f(x Big, mut y Big)`: ссылка vs копия дают разное чтение x после
  записи y). E_REF_ALIAS_OVERLAP расширяется с пар mut×mut на пары
  mut×(любой параметр того же root-пути) — тот же синтаксический критерий R9.
- **(Р13, испр. по поправке владельца) Перегрузка по режиму параметра — ЛЕГАЛЬНА,
  по прецеденту ресивера.** Ось «изменяемость ресивера» уже существует (план 135,
  10-overloading.md:180: `fn T @m()` vs `fn T mut @m()` — разные символы, диспатч по
  изменяемости биндинга). Для параметров — то же правило: `f(x T)` vs `f(mut x T)`
  различаются изменяемостью аргумента-биндинга; mut-аргумент предпочитает
  mut-перегрузку, иначе ro (приоритет как у ресивера).

- **(Р14, обобщение владельца) `@` — форма параметра; единая тройная ось режима.**
  Ресивер = нулевой параметр. Ось диспатча {`ro`, `mut`, `consume`} едина для
  ресивера и параметров: различимы `@func` / `mut @func` / `consume @func` И
  `f(x T)` / `f(mut x T)` / `f(consume x T)`. Сегодня consume в оси НЕ описан
  (10-overloading.md его не упоминает; пар mut/consume одного имени в std нет) —
  расширение чистое. Правило выбора (предложение, утвердить):
  ro-аргумент → только ro-версия; mut-биндинг → mut-версия приоритетнее ro
  (прецедент ресивера, план 135); consume-версия участвует в резолве ТОЛЬКО
  когда аргумент в последней точке использования (consume-чекер это уже
  вычисляет) — тогда она специфичнее mut; иначе исключена. Это даёт
  детерминизм без молчаливого потребления живого биндинга.

## 3. Что меняется в существующем

- Амендмент-ревизия D326 (переворот Р1-старого «режим, не тип»; Q29-история
  уточняется: отвергался НЕограниченный ref-тип).
- Парсер: форма Р3; удаление маркера вызова; локалы-ссылки.
- Чекер: тип Ref(T) в носителе (для 172.12 — ResolvedType::Ref), Р4-запрет
  перегрузок, Р6-нормализация, эскейп-правила для локалов.
- Миграция: 13 файлов тестов inout_ref + примеры спеки (мелко).
- D181/R7/R8 — упрощающий амендмент (типы вместо эвристик).

## 4. Фазы (после «ок»)

Ф.0 амендменты спеки (D326-ревизия, D84-ось, D181-упрощение) → Ф.1 парсер
(форма+локалы+снятие маркера) → Ф.2 чекер (Ref-тип, нормализация, запреты,
эскейп) → Ф.3 кодогенератор (локалы-ссылки; параметры уже by-pointer) →
Ф.4 миграция+тесты (позитив: локал-алиас, цепочки на value; негатив: поле-ссылка,
утечка, неоднозначная перегрузка) → Ф.5 закрытие.
