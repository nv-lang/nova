# План 184 — Ревизия D326: `ref T` как ограниченный тип (черновик на проверку владельцу)

> **Статус:** ✅ ЗАКРЫТ 2026-07-08 (Р1-Р14 реализованы; D326-ревизия в спеке) (обсуждение 2026-07-06, дизайн надиктован владельцем).
> **Маркер:** `[M-184-ref-type-revision]`.

## 1. Суть (решения владельца)

`ref T` — **валидный тип** (аналог C++ `T&`), но **ограниченный позициями**:
параметры, возвраты, локальные переменные. Мотивация-первопричина: легализовать
тип приёмника — `@` это всегда `ref Self` (для стековых), `-> @` — тоже.

## 2. Правила

- **(Р1) Позиции.** `ref T` легален: параметр (`mut x ref T` / `ro x ref T`),
  возврат (`-> ref Self` — де-сахар `-> @` для value-типов), локал
  (`ro y ref T = x.a.b` — именованный алиас). ЗАПРЕЩЁН: поля, коллекции,
  суммы, Option (ссылка на стек не должна утекать в долгоживущую кучу).
- **(Р2) mut.** В `mut x ref T` слово `mut` = право ПИСАТЬ через ссылку в цель.
  Сама ссылка непереселяемая (как C++ `T&`: связал — навсегда).
- **(Р3) Синтаксис параметра.** `ro|mut ИМЯ ref T` (ref в типовой позиции).
  Старая форма `mut ref x T` (D326-R2) — ретрактится с миграцией.
- **(Р4) МАРКЕР ВЫЗОВА УДАЛЁН.** Вызов везде `f(x)` — без `ref x`.
  Обоснование владельца: кучевые объекты и так мутируются без маркера —
  маркер на стековых давал ложное чувство «нет ref = нет мутации».
  Следствие: пара перегрузок `f(x T)` и `f(mut x ref T)` неразличима на
  вызове — ЗАПРЕЩЕНА (уточнение осей D84: E_OVERLOAD_REF_AMBIGUOUS).
- **(Р5) Автоконверсия.** `ref T -> T` автоматически (чтение = разыменование).
  `T -> ref T` на месте вызова автоматически для адресуемых аргументов
  (неадресуемый аргумент к mut-ссылке — ошибка, как сейчас).
- **(Р6) Нормализация над кучей.** Для кучевого `H`: `ref H` ≡ `H`
  (значение уже handle; ссылка на handle не вводится). Важно для
  обобщённых `f[T](mut x ref T)` при `T = H`.
- **(Р7) Типизация приёмника.** Стековый (value) тип: `mut @` = `mut ref Self`,
  `ro @` = `ref Self`/копия по размеру (невидимо), `-> @` = `-> ref Self`.
  Кучевой: `@` = `Self`, `-> @` = `-> Self`. Магия D181-R7/R8 («heap алиас /
  value копия-с-распадом») ЗАМЕНЯЕТСЯ этими типами.
- **(Р8) Безопасность без лайфтаймов.** Висячие ссылки исключаются связкой:
  запрет утечки в кучу (Р1) + существующий escape-анализ с авто-промоутом
  (D216 §4: убегающий источник поднимается в кучу) + запрет захвата ссылок
  замыканиями (как сейчас E_REF_ESCAPE_CAPTURE).
- **(Р9) Эксклюзивность/адресуемость/FFI** — без изменений (узкая
  E_REF_ALIAS_OVERLAP; на extern-границе только сырые `*`/`*mut`).

## 2а. Ревизия раунда 2 (обсуждение 2026-07-06, решения владельца)

- **(Р10) `ref` исчезает из сигнатур параметров вовсе:**
  - `ro`: `f(x T)` — представление (копия ≤~16Б / скрытая ссылка) выбирает компилятор
    по размеру; ненаблюдаемо (с оговоркой Р12). Явный `ro ... ref` в параметре — убрать.
  - `mut`: **`f(mut x T)` ≡ in-out ссылка ВСЕГДА** (унификация со стеком/кучей: на куче
    приватной мутируемой копии и так нет). Локальная копия — явным локалом `mut y = x`.
    Неоднозначность перегрузок исчезает по построению (форма одна).
  - `consume`: `f(consume x T)` — владение; представление считает компилятор.
  - `ref` остаётся: тип приёмника (`@` = `ref Self`), `-> @` (= `-> ref Self` у value),
    локальные алиасы (форму локала уточнить: `ro y ref T = ...`).
- **(Р11) Аудит-миграция mut-параметров.** Семантика `mut x T` меняется
  (была приватная копия → станет in-out): перед реализацией grep-аудит всех
  mut-параметров std/тестов, кто полагался на приватность — переписать на локал.
- **(Р12) Расширение узкой эксклюзивности (упущение, найдено на ревью).**
  ro-автопредставление наблюдаемо при алиасинге ro×mut в ОДНОМ вызове
  (`f(a, a)` c `f(x Big, mut y Big)`: ссылка vs копия дают разное чтение x после
  записи y). E_REF_ALIAS_OVERLAP расширяется с пар mut×mut на пары
  mut×(любой параметр того же root-пути) — тот же синтаксический критерий R9.
- **(Р13, испр. по поправке владельца) Перегрузка по режиму параметра — ЛЕГАЛЬНА,
  по прецеденту ресивера.** Ось «изменяемость ресивера» уже существует (план 135,
  10-overloading.md:180: `fn T @m()` vs `fn T mut @m()` — разные символы, диспатч по
  изменяемости биндинга). Для параметров — то же правило: `f(x T)` vs `f(mut x T)`
  различаются изменяемостью аргумента-биндинга; mut-аргумент предпочитает
  mut-перегрузку, иначе ro (приоритет как у ресивера).

- **(Р14, обобщение владельца) `@` — форма параметра; единая тройная ось режима.**
  Ресивер = нулевой параметр. Ось диспатча {`ro`, `mut`, `consume`} едина для
  ресивера и параметров: различимы `@func` / `mut @func` / `consume @func` И
  `f(x T)` / `f(mut x T)` / `f(consume x T)`. Сегодня consume в оси НЕ описан
  (10-overloading.md его не упоминает; пар mut/consume одного имени в std нет) —
  расширение чистое. Правило выбора (предложение, утвердить):
  ro-аргумент → только ro-версия; mut-биндинг → mut-версия приоритетнее ro
  (прецедент ресивера, план 135); consume-версия участвует в резолве ТОЛЬКО
  когда аргумент в последней точке использования (consume-чекер это уже
  вычисляет) — тогда она специфичнее mut; иначе исключена. Это даёт
  детерминизм без молчаливого потребления живого биндинга.

## 3. Что меняется в существующем

- Амендмент-ревизия D326 (переворот Р1-старого «режим, не тип»; Q29-история
  уточняется: отвергался НЕограниченный ref-тип).
- Парсер: форма Р3; удаление маркера вызова; локалы-ссылки.
- Чекер: тип Ref(T) в носителе (для 172.12 — ResolvedType::Ref), Р4-запрет
  перегрузок, Р6-нормализация, эскейп-правила для локалов.
- Миграция: 13 файлов тестов inout_ref + примеры спеки (мелко).
- D181/R7/R8 — упрощающий амендмент (типы вместо эвристик).

## 4. Фазы (после «ок»)

Ф.0 амендменты спеки (D326-ревизия, D84-ось, D181-упрощение) → Ф.1 парсер
(форма+локалы+снятие маркера) → Ф.2 чекер (Ref-тип, нормализация, запреты,

### Заход 3 — return-позиция беглой value-цепочки ([M-184-mut-chain-return-position], 2026-07-07)

Приоритет захода — концевой P1-дефект Р7-лоуэринга: беглая цепочка `mut @setter(v) -> @`
на `value`-типе в **return-позиции** (`fn build() -> Rec { Rec.new().a(1)…d(4) }`, глубина 4).
Р7 задаёт value-record `-> @` = `ref Self` (`NovaValue_X*`); потребитель беглого указателя в
return-позиции был не согласован с let/arg-потребителями (заход-2) — инициализация value-слота
из указателя (`NovaValue_Rec _nv_tmp = Nova_Rec_method_d(...)`) давала жёсткий **CC-FAIL**
(«initializing NovaValue_Rec with NovaValue_Rec* — dereference with *»).

**Корень:** три return-позиционных потребителя эмитили значение БЕЗ деref беглого указателя.
Воспроизведено на глубине 4 (trailing И explicit `return`).

**Фикс (сквозной, тот же общий предикат `is_fluent_value_ptr_for_target`):** деref беглого
value-ptr в трёх return-сайтах `emit_c.rs` — auto-конверсия `ref T -> T` (Р5):
- `emit_block_stmts` (осн. путь fn-тела, ~20849) — trailing/implicit-return;
- `emit_block_stmts_trailing` (~25789) — вариант trailing-блока;
- `Stmt::Return` (~21770) — явный `return`.
Все три в lockstep с let-decay (~21061) и arg-деref (`deref_fluent_value_args`) через ОДИН
`is_fluent_value_ptr_for_target`. Предикат срабатывает ТОЛЬКО когда ret_ty — value-struct (не
ptr) И выражение — Call value-record `-> @` метода (`fn_ret_{T}_{m}` == `{ret_ty}*`); для
`-> @` fn (ret_ty = ptr, `fluent_self_ret`) он no-op — конфликта нет.

**Регресс-безопасность (обоснование):** этот паттерн ДО фикса ВСЕГДА давал CC-FAIL (ptr в
value-слот не компилится) — значит ни один ранее-зелёный тест его не исполнял; фикс может
только чинить ранее-падавшее. Подтверждено: fluent/chain-сэмпл (plan77/plan123/plan138_2/
cgfix_fluent_tail_if + оба заход-2 акцепта) зелёный; conformance без изменений.

**Тест:** `nova_tests/inout_ref/p184_defect_c_return.nv` (depth-4 trailing + explicit return,
обе мутации-по-полю проверены). Маркер `[M-184-mut-chain-return-position]` — ✅ FIXED
(в задачнике маркер как отдельная запись не заводился; закреплён здесь + якорями в `emit_c.rs`).

**Точка возобновления после захода 3:** пункты «Заход 3+» ниже В СИЛЕ ЦЕЛИКОМ (in-out `mut x T`,
тип `Ref(T)`, `E_REF_TYPE_POSITION`, Р6/Р8/Р12/Р13/Р14, ref-локалы). Ключевой блокер порядка:
полная in-out-семантика требует ABI-правки value-параметров в `emit_c` (передача by-pointer +
деref в теле + address-of на call-site — как у ресивера `@`), что выходит за «минимальный
emit_c / лоуэринг только п.5» этого захода; плюс широкая миграция (4 Категория-A + десятки
call-site-реджектов). Это следующий выделенный заход с явно расширенной emit_c-зоной.

### Заход 4 — in-out `mut x T` ABI (Р10) + категория-А + E_MUT_ARG_NOT_MUTABLE (2026-07-07)

Приоритет захода — keystone-ABI: `mut x T` параметра **значимого/примитивного** типа
становится in-out ссылкой (by-pointer, как value-ресивер `@`), а не приватной копией.
Ключевое наблюдение (снизившее риск): почти все `mut`-параметры std — **кучевые/протокольные/
типовар** (`mut w Write`, `mut s S`, `mut d D`, `mut it T`, `BoxIter`), которые по **Р6**
(`ref H ≡ H`) НЕ меняют ABI (значение уже handle, мутация и так достигает вызывающего). Реально
ABI-флипаются только value-типизированные `mut`-параметры — во всём репозитории их **три**:
`d32_bump(mut x int)`, `d228_clobber(mut v D228Vec3)` (оба — free-fn, conformance) и
`ServeMux @dispatch(mut req ServerRequest)` (метод, std/http). Метод мигрирован в Category-A →
единственная оставшаяся by-ptr-поверхность — **free-fn**, что позволило обойтись одним
call-site-хуком без правки метод-диспетчера.

**Кодоген (emit_c.rs):**
- `param_is_inout_ptr(p, ty_c)` — предикат by-pointer (is_mut & !consume & value-тип & !unit & !ptr;
  переиспользует `is_value_type`).
- `params_c` — сигнатура `T*` для таких параметров (рядом с legacy `MutRef`).
- `emit_fn` — регистрация в `ref_params` → авто-деref `name`→`(*name)` в теле (тот же путь, что
  у legacy `mut ref` — переиспользован, не дублирован).
- `emit_call` (вершина) — `synthesize_inout_refargs` оборачивает совпадающие позиционные
  аргументы **free-fn** в `RefArg` (эмит `(&(place))`); один хук покрывает ВСЕ downstream-ветви

## Дополнение к заходу-5 (вопрос владельца, 2026-07-07): ref в тип-аргументах

`size_of[ref T]()` вскрыл недоговорённость Р1: тип-аргументы дженериков (turbofish,
`size_of[...]` и любые `f[...]`) — запрещённая позиция для `ref` НАРЯДУ с полями/
коллекциями/суммами/Option → `E_REF_TYPE_POSITION`. Мотив: ref нехраним и не имеет
«размера как тип» — только ABI-деталь передачи; разрешить его в тип-аргументах = код,
зависящий от режима передачи. Для кучевых вопрос снимается нормализацией Р6 (ref H ≡ H
ДО проверки позиций — `size_of[ref H]` легален и равен `size_of[H]`).
Приёмка захода-5: негатив `size_of[ref T]` (value T) → E_REF_TYPE_POSITION; позитив
`size_of[ref H] == size_of[H]` (heap). Р1-текст в спеке дополнить «тип-аргументы
дженериков» при исполнении.


## Дополнение к заходу-5 (вопрос владельца, 2026-07-07): &ref-цель и автопромоут

`fn func(a ref T) *T => &a` (эквивалент для живой поверхности: `fn T @addr() -> *T => &@`
на value-ресивере): автопромоут D216 §4 НЕ применяется — промоутится только СВОЁ значение
(локал), а ref указывает на чужое хранилище (промоут копии тихо меняет семантику; промоут
исходного места функции недоступен). Правило Р8 уточняется:
- `&<ref-цель>` эскейпящий НАРУЖУ (return/захват/поле) → реджект E_REF_ESCAPE с подсказками
  (consume-владение + промоут своего; либо явная локальная копия);
- `&<ref-цель>` ВНИЗ по стеку (аргумент вызова, ffi out-параметр) → легален без промоута
  (заём короче исходного) — это действующий канон nova_str_parse_f64(s, &v);
- адрес КУЧЕВОГО содержимого через ресивер (Vec @ptr => @data) — легален, не путать.
Приёмка захода-5: негатив `fn T @addr() -> *T => &@` (value T) → E_REF_ESCAPE; позитив
downward `&v` в ffi-вызове (уже покрыт parse_f64-путём — закрепить явным тестом).

### Заход 6 — Р13/Р14: режим параметра {ro, mut, consume} как ось перегрузки (2026-07-07, ЗАВЕРШЁН)
