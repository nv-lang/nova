## Зачем — одной фразой и одним замером

Собственная дверь диагностики называет СЕБЯ, а не виновника. Живой носитель: у `novac`
функция `ice()` строит JSON-отчёт с пустой позицией — `"primary":{"file":"","start":0,"end":0}`
(`novac/src/diag/diag.nv`), и её же docstring в `novac/src/main.nv` признаёт причину
дословно: «`ice()` cannot [name the file and line], because a wrapper reports its own body».
То же у любого прикладного `expect`/`require`-хелпера. У `assert` и контрактов локация
есть — её проставляет кодоген; пользовательскому коду этого канала нет.

## Что делаем (решения приняты, здесь не пересматриваются)

Все четыре — решения владельца 2026-09-02, разбор в D468:

1. атрибут **`#track_caller`** на функции — «место вызова протекает через меня насквозь»;
2. встроенная **`caller_loc()`** — читает его; категория та же, что у `size_of`/`align_of`
   (признаётся резолвером без объявления);
3. тип результата — **`type CallerLoc(file str, line int)`** в прелюдии (поле `file`, а не
   `filename`: так называется во всех наших записях, и в нём ПУТЬ, а не короткое имя);
4. три правила семантики: Р1 в помеченной функции — место вызова этой функции; Р2 в
   непомеченной — собственная строка; **Р3 цепочка** — помеченная через помеченную
   доносит исходного вызывающего.

## Как это читается — на коде (разъяснение, обязательное к сохранению)

Таблица в D468 верна, но читается неоднозначно; здесь то же правило на примерах, и
ИМЕННО ОТСЮДА пишутся фикстуры. Формулировка владельца 2026-09-02 после разбора: правило
одно, и различие не в вызываемой функции, а в ВЫЗЫВАЮЩЕМ.

**Правило одной фразой.** Функции, которой нужна локация, её ПЕРЕДАЁТ вызывающий:
непомеченный передаёт свою строку вызова, помеченный — то, что дали ему самому.
Пометка на функции значит «не вини меня, вини того, кто позвал меня».

**Пример 1 — цепочка обёрток (правило Р3).**

```nova
1  #track_caller
2  fn ice(msg str) -> never { ... }
3
4  #track_caller
5  fn ensure(ok bool) -> () { if !ok { ice("bad") } }
6
7  fn app() -> () {
8      ensure(false)
9  }
```

- `app` НЕ помечена → передаёт `ensure` строку **8** (свою);
- `ensure` помечена → отдаёт `ice` НЕ свою строку 5, а полученную — строку **8**;
- паника из `ice` печатает строку **8**, настоящего виновника.

Снять `#track_caller` с `ensure` — и `ice` получит строку **5**, внутренность обёртки.
Это и есть содержание фикстуры `neg/track_caller_all_report_caller_neg.nv` и её пробы
красноты: снятая пометка обязана сдвинуть ответ с 8 на 5.

**Пример 2 — контракт, атрибут НЕ нужен.**

```nova
1  fn half(n int) -> int
2      requires n > 0
3  { n / 2 }
4
5  fn app() -> () { half(-1) }
```

- сегодня паника печатает строку **2** — объявление `half`, бесполезно (замер 2026-09-02);
- после волны — строку **5**, место вызова, и это работает у ЛЮБОЙ функции с контрактом,
  помечать ничего не надо.

Отсюда фикстура `neg/contract_names_caller_neg.nv`, а её контроль в том же файле —
`assert` в теле НЕпомеченной функции по-прежнему называет себя.

**Тогда зачем атрибут контрактам.** Только чтобы смотреть СКВОЗЬ обёртку: если `half`
помечена и её зовут из помеченной обёртки, контракт назовёт вызывающего обёртки, а не
строку внутри неё. Обратный случай стоит помнить как ловушку: помеченная обёртка + НЕ
помеченная `half` дают строку ВНУТРИ обёртки — и это верно, потому что обёртка могла сама
исказить аргумент.

**Оба места в сообщении.** Строка отказа несёт сначала место вызова, в хвосте — где
физически сработала проверка:

```
caller.nv:8: assert failed: text (cond) [in ice at diag.nv:129]
```

## Не делаем (границы)

Отсутствие каждого пункта — РЕШЕНИЕ, а не забывчивость:

- **колонку не вводим.** Только файл и строка; колонка добавляется полем в `CallerLoc`,
  когда появится потребитель. Именованный кортеж выбран ровно ради этой возможности;
- **стек вызовов целиком — не эта задача.** Здесь МЕСТО, а не трасса; трасса
  распространения ошибок уже существует отдельно (`[M-173-error-return-trace]`, закрыт);
- **формат записи отказа D462 не меняем.** Поле `site` остаётся; меняется лишь то,
  насколько точно оно указывает, когда дверь помечена;
- **`novac` в этом плане не участвует.** Атрибут заводится в ОРАКУЛЕ: носитель (`ice()`)
  компилируется оракулом, и польза наступает сразу. Появление `#track_caller` в
  подмножестве `novac` — работа трека Carina, отдельным решением;
- **функция-значение не открывается.** `ro g = ice` отвергается по имени (D468); шим,
  как у Rust, — возможный будущий амендмент, но не эта волна.

## Как это реализовать — механизм

Проверено чтением кодогена 2026-09-02, и это главный факт всей волны: **три двери,
печатающие локацию, УЖЕ принимают файл и строку аргументами-литералами**:

| дверь | нынешний вызов | адрес |
|---|---|---|
| `assert` | `nova_assert_loc(cond, text, "file", line, msg)` | `emit_c.rs:40394` |
| контракт | `nova_contract_violation(kind, fn, src, "file", line, msg)` | `emit_c.rs` (`emit_contract_check`) |
| `?` | `nova_throw_trace_push("file", line)` | `emit_c.rs:37533, 37586, 37664` |

Значит волна меняет **ЧТО туда передаётся**, а не заводит новую машинерию: ни одной новой
рантайм-функции, ни одного нового формата. Это и есть причина, по которой работа
подъёмная.

### 1. Кому нужен скрытый параметр (множество «needs-loc»)

Считает ЧЕКЕР — свойство ЛОКАЛЬНОЕ, обход графа не нужен:

- функция несёт `#track_caller`; **либо**
- функция несёт `requires`/`ensures` (контракт называет вызывающего всегда).

### 2. Что добавляется в подпись эмитированного C

Два скалярных параметра в ХВОСТ: `const char* _nova_loc_file, int _nova_loc_line`.

Не структура `CallerLoc` в подписи — потому что (а) все три существующие двери уже ходят
парой скаляров, и структура потребовала бы распаковки на каждом сайте; (б) новый C-тип в
подписи трогает ABI шире, чем нужно. `CallerLoc` материализуется ТОЛЬКО там, где вызвана
`caller_loc()`.

**Манглинг не меняется:** скрытый хвост НЕ входит в имя. Он не ось перегрузки (D84), а
служебный параметр; иначе одна и та же функция получила бы разные C-имена от того,
объявлен ли у неё контракт.

### 3. Что передаёт вызывающий на каждом сайте

Решает чекер, эмиттер исполняет:

- **вызывающий помечен `#track_caller`** → передаёт СВОИ полученные `_nova_loc_*`;
- **иначе** → литералы места вызова (то, что эмиттер подставляет и сегодня).

Отсюда ровно то правило, что записано в разъяснении выше: контракт-несущая, но НЕ
помеченная функция локацию ПОЛУЧАЕТ (для своего контракта), но дальше НЕ форвардит —
своим вызываемым она передаёт литералы.

### 4. Где значение потребляется

Подстановкой `_nova_loc_file`/`_nova_loc_line` вместо литералов в те же три двери, плюс:

- `caller_loc()` → сборка `CallerLoc` из этой пары (в непомеченной функции без контракта —
  из литералов текущей позиции, правило Р2);
- хвост сообщения `[in <fn> at <file>:<line>]` — ЛИТЕРАЛЫ физической точки, эмиттер знает
  их всегда; именно поэтому хвост ничего не стоит.

### 5. Канал чекера, а не догадка эмиттера (правило плана 196)

Два канала, оба заполняются чекером и ЧИТАЮТСЯ кодогеном:

- `fn_needs_caller_loc` — по спану объявления: нужен ли функции скрытый хвост;
- `call_site_loc_mode` — по `ExprId` вызова: `Literal` или `Forward`.

Эмиттер не переспрашивает синтаксис «а есть ли тут атрибут» — это ровно класс О-1
(реестр №716), из-за которого заведён канал.

### 6. Отказы — в чекере

`[E_TRACK_CALLER_ON_EXTERN]` и `[E_TRACK_CALLER_AS_VALUE]` (D468). Оба на этапе Э1, до
того как появится хоть один скрытый параметр.

### 7. Ловушки, названные ЗАРАНЕЕ

- **Снимок `novac/src/emit_c/shell.tpl.c` протухнет.** Он — снимок ЭМИССИИ оракула, а мы
  меняем подписи контракт-несущих функций `std`; страж `check-novac-shell-freshness`
  покраснеет на CI, а не локально. Прецедент ровно этот: 2026-08-31, фикс №799 сдвинул
  эмиссию и шаблон пришлось перегенерировать (строка в `novac-time-ledger.md`).
  **Перегенерация — часть волны, а не отдельная авария.**
- **`#stable` и ABI `std`.** Экспорт с контрактом меняет C-подпись. Проверить грепом, нет
  ли внешних потребителей, завязанных на точную сигнатуру (FFI-обёртки, `extern`-объявления
  в пакетах).
- **Методы.** Скрытый хвост идёт ПОСЛЕ обычных параметров; ресивер (параметр №0, план 273)
  не трогается.
- **Рекурсия.** Обычный вызов: помеченная функция, зовущая себя, передаёт себе полученное
  значение — то есть место внешнего вызова. Проверяется фикстурой (открытый вопрос 3).
- **Цена на happy-path.** Два лишних аргумента у контракт-несущих функций — измерить на
  ярусе, не предполагать (этап Э4).

### 8. Порядок внутри волны

Э1 (имя атрибута, отказы) → Э2а (каналы чекера + скрытый хвост в подписи, БЕЗ смены
потребителей: значения передаются, но никто их не читает — эмиссия обязана остаться
собираемой) → Э2б (три двери переводятся на полученные значения) → Э2в (`caller_loc()` и
`CallerLoc`) → Э3 (носитель) → Э4 (цена).

Разделение Э2 на три — не бюрократия: после Э2а дерево обязано быть ЗЕЛЁНЫМ при
неизменном поведении, и это единственная точка, где можно отделить «параметр протянут
неверно» от «потребитель читает не то».

## Этапы и приёмка

Приёмка машинная везде, где это возможно; где нет — сказано «приёмка глазами, потому что …».

### Э1. Атрибут признаётся и отвергается там, где не работает

Заводится имя `#track_caller` в списке известных атрибутов, проверка применимости и две
диагностики: `[E_TRACK_CALLER_ON_EXTERN]` и `[E_TRACK_CALLER_AS_VALUE]`.

- **Команда:** `nova-cli/target/release/nova.exe test spec_tests --filter track_caller --full`
- **Строка-доказательство:** `PASS: 3  FAIL: 0` при трёх фикстурах — `neg/track_caller_on_extern_neg.nv`
  и `neg/track_caller_as_value_neg.nv` (обе line-pinned `nova:expect`), плюс
  `standalone/track_caller_accepted_pos.nv` (атрибут на обычной функции принят, программа
  печатает результат).
- **Проба красноты:** снять условие отказа для `extern` — негативная фикстура обязана
  покраснеть `NEG-NO-ERROR`, а позитивная остаться зелёной; на ОДНОМ бинаре.
- **Контроль на непокрашенное:** `nova test spec_tests/conformance --full` одним CU без
  роста красных против известного списка.

### Э2. `caller_loc()` возвращает верное место — три правила порознь

- **Команда:** `nova-cli/target/release/nova.exe test spec_tests --filter caller_loc --full`
- **Строка-доказательство:** `PASS: 3  FAIL: 0` при трёх фикстурах-по-правилу:
  `standalone/caller_loc_marked_pos.nv` (Р1: печатает строку ВЫЗОВА, не тела),
  `standalone/caller_loc_unmarked_pos.nv` (Р2: печатает собственную строку),
  `standalone/caller_loc_chain_pos.nv` (**Р3, главная**: две обёртки, печатается исходный
  вызывающий — ровно требование приёмки №683).
- **Как фикстура проверяет НОМЕР строки, не завися от своей длины:** ожидаемое значение
  вычисляется в самом тесте от известной точки (`assert(loc.line == expected)`), а не
  пишется константой в `EXPECT_STDOUT`; иначе любая правка комментария вверху файла
  красит тест и его начнут «чинить» сдвигом константы.
- **Проба красноты:** сломать проброс в цепочке (передавать своё место вместо полученного)
  — `caller_loc_chain_pos` обязана покраснеть, две другие остаться зелёными. Это и есть
  доказательство, что Р3 проверяется отдельно от Р1.
- **Четвёртая фикстура — единое правило под атрибутом:**
  `neg/track_caller_all_report_caller_neg.nv` — в ОДНОЙ помеченной функции нарушенный
  `requires`, сработавший `assert` и `panic` называют ОДНУ И ТУ ЖЕ строку вызова. Три
  механизма в одном файле не для краткости: единое правило доказывается их СОВПАДЕНИЕМ, а
  порознь каждый зелен и при расщеплённом правиле.
- **Пятая фикстура — контракт БЕЗ атрибута:** `neg/contract_names_caller_neg.nv` —
  нарушенный `requires` НЕпомеченной функции обязан назвать место вызова, а не строку
  своего объявления (вторая половина решения владельца, универсальная). Контроль в том же
  файле: `assert` в теле НЕпомеченной функции по-прежнему называет себя — иначе фикстура
  докажет «всё поехало», а не «поехали контракты».
- **Шестая фикстура — хвост сообщения:** `standalone/track_caller_both_places_pos.nv` —
  человекочитаемая строка несёт СНАЧАЛА место вызова, в хвосте физическую точку проверки
  (`[in <fn> at <file>:<line>]`). Без неё цена единого правила остаётся неоплаченной: баг
  самой обёртки перестанет быть находимым.
- **Правка существующих фикстур — часть волны, не регресс.** Замер 2026-09-02 с явным
  правилом счёта: `grep -rl "requires failed" spec_tests/ --include=*.nv` → **33** файла
  упоминают контрактную панику; из них `grep -rn "EXPECT_RUNTIME_PANIC.*requires failed"`
  → **4** пинуют её текст в маркере — у этих меняется номер строки. Ни одна КОНТРАКТНАЯ
  фикстура не пинует явную пару `файл:строка`.
- **НО одна фикстура в корпусе такую пару пинует, и она задета:**
  `neg/f2b_cleanup_does_not_steal_site.nv` — маркер
  `EXPECT_RUNTIME_PANIC f2b_cleanup_does_not_steal_site.nv:24 (throw site)`. Найдена
  перепроверкой плана; первая редакция этого пункта говорила «ни одна», потому что регулярка
  искала только контрактную форму. Задета она потому, что `?`-сайт эмитит ОБЕ метки одной
  строкой кода: `nova_throw_trace_push("{f}", {l}); nova_throw_site_mark("{f}", {l});`
  (`emit_c.rs:37533`).

### Э3. Носитель: `ice()` называет виновника

- **Команда:** `nova-cli/target/release/nova.exe build novac/src/main.nv -o <tmp>` плюс
  прогон бинаря на файле, вызывающем внутреннюю ошибку.
- **Строка-доказательство:** в JSON-отчёте `ice` поле `"file"` НЕ пустое и указывает на
  файл вызывающего, а не на `diag.nv`.
- **Приёмка глазами, потому что** носитель — чужой трек (Carina), и правка `ice()` под
  атрибут принадлежит окну 274; здесь фиксируется только то, что механизм оракула это
  позволяет. Машинная половина — на их стороне.
- **Оговорка:** фикс носителя приёмкой НЕ считается (правило строки №683): без Э2 с его
  цепочкой этот шаг ничего не доказывает.

### Э4. Цена и её ратчет

- **Команда:** `bash scripts/gate.sh` (ярус loop) до и после волны.
- **Строка-доказательство:** бюджет яруса не вырос сверх базы; `arch-ratchet` не сдвинут
  либо сдвинут с летописью.
- **Что мерить отдельно:** размер эмитированного C для непомеченной функции обязан
  остаться ПРЕЖНИМ — платят только помеченные (решение D468). Проверяется сравнением
  эмиссии одного файла до и после (`nova build --emit-c` либо снимок в фикстуре).

## Цена и за чей счёт

Работа **оракульская**, и это надо назвать прямо: месяц отдан плану 274 (Carina), а оракул
по решению 274 §1.4 получает только блокеры тега и работы плана 221. Строка №683
блокером тега НЕ помечена. Значит план 280 исполняется **по слову владельца** (2026-09-02
«пиши план + спеку»), а не по остаточному принципу, и время берётся у оракульской очереди
221.1 — то есть в эти окна не двигаются другие открытые строки реестра. Если приоритет
изменится, план останавливается на границе этапа, а не посередине.

## Инвентарь мест — собран ДО первой строки кода

Снят по образцу двух уже реализованных атрибутов и встроенных `size_of`/`align_of`.

**Правило счёта — иначе числа ниже нечем проверить:** «место» = отдельная строка в дереве,
где имя атрибута встречается как ЧАСТЬ МЕХАНИЗМА (лексер, парсер, AST, чекер, кодоген,
спека, дока, фикстура, декларация в `std`), а не как слово в комментарии. По этому правилу
у `#realtime` вышло 25 мест, у `#blocking` — 16 (обход агента 2026-09-02; расхождение
цифры с сегодняшним деревом обнаружится на первом же шаге, потому что каждый адрес
проверяется грепом).

**Что сверено лично, а что нет.** Интегратор перепроверил построчно ЧЕТЫРЕ адреса
(`lexer/mod.rs:754`, `parser/mod.rs:1874`, `types/mod.rs:36793`, `emit_c.rs:40394`) — они
верны. ПЯТЫЙ, `ast/mod.rs`, был назван агентом неверно (497 — это `sync_class`) и исправлен
на 412 при перепроверке плана; урок записан, потому что он общий: выдача агента годится
как карта, но каждый адрес перед употреблением сверяется.

**Атрибут (`#track_caller`) — семь слоёв:**

| слой | место (по образцу `#realtime`) |
|---|---|
| лексер: ключевое слово | `lexer/mod.rs:754` — `"realtime" => TokenKind::KwRealtime` ✔ сверено |
| лексер: вариант токена и display | `lexer/token.rs:163` и `:327` |
| парсер: разбор самого атрибута | `parser/mod.rs:2198` (`parse_realtime_attr`) |
| парсер: общий цикл сбора атрибутов перед `fn` | `parser/mod.rs:1832-1918` — сюда добавляется поле |
| парсер: отказ «только перед `fn`» | `parser/mod.rs:1874` ✔ сверено |
| AST: поле в `FnDecl` + реестр `ContractAttrs` | `ast/mod.rs:412` (`pub realtime_attr: RealtimeAttr`; :415 — `blocking_attr`), `parser/mod.rs:41-60` |
| чекер и кодоген | `types/mod.rs` (применимость, отказы), `codegen/emit_c.rs` (скрытый параметр) |

**Встроенная (`caller_loc()`) — семь мест той же категории:**

| слой | место (по образцу `size_of`) |
|---|---|
| резолвер: имя признаётся без объявления | `types/mod.rs:36793` — `if name == "size_of" \|\| name == "align_of" { return true; }` ✔ сверено |
| чекер: тип результата | `types/mod.rs:11146` (там `size_of` типизируется как `int`; наш — `CallerLoc`) |
| кодоген: эмиссия | `codegen/emit_c.rs:36827` (там `sizeof`/`_Alignof`; наш — подстановка места вызова) |
| спека и дока | D468 (написан), `docs/guide/` — по образцу `docs/guide/size-of-align-of.md` |

**Урок из инвентаря, который план обязан не повторить:** у `#blocking` **нет ни одной
страницы пользовательской документации** — асимметрия с `#realtime`, замеренная тем же
обходом. Поэтому гайд входит в Э2 как часть приёмки, а не «когда-нибудь потом».

**Что инвентарь показал про novac:** он ЧИТАЕТ `#realtime` (`novac/src/builtins/builtins.nv:90`)
и ничего не проверяет — задокументированное решение. Значит `#track_caller` в подмножестве
novac ведёт себя так же: имя признаётся, поведение — работа Carina (см. «Не делаем»).
