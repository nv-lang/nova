# План 180.1 — serde: паритет с Rust serde + где мы можем быть лучше

**Статус:** 🟡 IN PROGRESS 2026-07-22 — **Ф.1 (field-attributes) + Ф.7 (strict-by-default
unknown-field) + Ф.10 (wire-contract валидация) ПРИЗЕМЛЕНЫ** (ветка `p180-serde-field-attrs`,
D435/D436). rename/rename_all/skip/skip_serializing_if/default/alias/deny_unknown_fields/
allow_unknown — потреблены на record-типах; `flatten` — грамматика+валидация есть, синтез
честно гейтнут (`[M-180-serde-flatten]`, самый сложный item, единственный не закрытый в Ф.1).
Ф.2–Ф.6, Ф.8, Ф.9 — ещё PROPOSED (не начаты). **Приоритет:** P2 — после релиза
v0.1 (record-DTO round-trip работает, флагман JSON гоняет; ничего здесь не блокер тегов).
**Родитель:** [180](180-serde-derive.md) (✅ record-path + sum externally-tagged + JSON-backend
+ Ф.6 attribute-инфра/internal+adjacent). **Эталон:** Rust serde (GOLD STANDARD), zod
(path-rich ошибки), schemars (schema-gen), Swift Codable (compiler-synth).

## 0. Аудит паритета: Rust serde → Nova (что есть / чего нет)

| Возможность serde | Nova сейчас | Действие |
|---|---|---|
| `#[derive(Serialize, Deserialize)]` | ✅ `#impl(Serialize+Deserialize)` | — |
| Enum tagging external/internal/adjacent | ✅ все три (D345/D382) | — |
| Enum tagging **untagged** | 🔴 GATED `[M-180-untagged-codegen-mono]` (синтез корректен, компилятор-баг mono-ordering) | **Ф.4** |
| `rename` / `rename_all` | 🔴 грамматика есть, синтез игнорирует | **Ф.1 (главная дыра)** |
| `skip` / `skip_serializing_if` | 🔴 нет | **Ф.1** |
| `default` / `default = path` | 🔴 нет | **Ф.1** |
| `alias` (миграции схем) | 🔴 нет | **Ф.1** |
| `flatten` | 🔴 нет (гейтнут) | **Ф.1 — ПАРИТЕТ record+map (владелец 2026-07-24): и `#serde(flatten)` на вложенной записи, И идиома `extra: HashMap`/map-flatten для «всех прочих полей» (как Rust serde + `additionalProperties`); companion fields-only synth + рекурс known-names** |
| `deny_unknown_fields` | 🔴 нет | **Ф.1 + Ф.7 (мы строже by default)** |
| `with = "module"` (кастомный кодек поля) | 🔴 нет | **Ф.5** |
| Data-model: узкие скаляры в контейнерах (`Option[i32]`) | 🔴 typed-error `[M-180-container-narrow-scalar]` | **Ф.2** |
| Data-model: `char` | 🔴 typed-error `[M-180-char-serde]` | **Ф.3** |
| Data-model: `i128`/`u128` | 🔴 typed-error | Ф.3 (вместе с char) |
| API `from_str::<T>` / `to_string` | 🟡 free-fn `json_decode`/`json_encode`; namespace-форма не мономорфизируется `[M-180-namespace-static-generic-mono]` | **Ф.6** |
| Streaming `from_reader`/`to_writer` | 🧊 scope-out `[M-180-streaming]` | 🧊 |
| Zero-copy `borrow` | 🧊 scope-out (нужна lifetime-модель) | 🧊 |
| Форматы TOML/YAML/binary | 🧊 scope-out (JSON — единственный backend) | 🧊 |
| Schema-gen (schemars — отдельный крейт) | ❌ нет | **Ф.9 (можем лучше: встроенно)** |
| Path-rich ошибки (serde_path_to_error — отдельный крейт) | 🟡 typed `DeError` без пути | **Ф.8 (можем лучше: встроенно)** |

**Где Nova УЖЕ лучше serde** (сохранить и не растерять при доработках):
- **typed-ошибки** `DeError{Syntax|MissingField|UnexpectedType|LossyInteger}` вместо stringly;
- **depth-guard обязателен** (D346) — у serde_json лимит опционален, DoS-класс закрыт по умолчанию;
- **lossy-integer guard на обеих сторонах** (`SerLossyInteger`/`is_exact_int`) — serde_json молча
  роняет точность на f64-границе;
- **non-string map-keys → compile-error** (у serde — runtime);
- **cycle-detection compile-time** (`E_SERDE_DERIVE_CYCLE`) — serde переполняет стек;
- **неизвестный атрибут → `E_SERDE_BAD_ATTRIBUTE`**, не молчок.

## Фазы

- **Ф.1 — field-attributes: потребление** (главная дыра паритета). **✅ ПРИЗЕМЛЕНО
  2026-07-22 (D435, ветка `p180-serde-field-attrs`) — кроме `flatten`.** Синтез читает
  `serde_attrs` полей: `rename`, `rename_all` (на типе: camelCase/snake_case/kebab/SCREAMING —
  все 5 конвенций), `skip`, `skip_serializing_if` (общая predicate-форма, не только `is_none`),
  `default`/`default = fn`, `alias` (несколько wire-имён на чтение — миграции, has_field-based
  fallback-цепочка). Каждое — pos (`std/encoding/serde/field_attrs_test.nv`, assert на wire-
  строку, не только round-trip) + подтверждено через 16 neg-фикстур (Ф.10). `flatten` —
  грамматика+статическая валидация есть, СИНТЕЗ честно гейтнут (`[M-180-serde-flatten]`,
  единственный не закрытый item — нужен companion "fields-only" synth-вариант, структурное
  расширение, не body-правка). Record-типы only v1 (sum-variant record-полей — вне scope,
  `[M-126-sum-*-rich]`). **Без этого реальный REST-DTO
  (camelCase wire ↔ snake_case поля) не смапить** — самая частая претензия к текущему состоянию.
- **Ф.2 — узкие скаляры в контейнерах.** `Option[i32]`/`Vec[i32]`/`HashMap[str,i32]`/tuple.
  Корень — primitive-method mono внутри generic-контейнера (компилятор). Снимает
  `[M-180-container-narrow-scalar]`; `Option[i32]` в DTO — обыденность.
- **Ф.3 — `char`/`i128`/`u128` канон.** Решить wire-маппинг (`char` → 1-символьная строка,
  как JSON-канон; `i128`/`u128` → строка, как serde_json arbitrary_precision-политика),
  спек-амендмент, снять typed-error. Снимает `[M-180-char-serde]`.
- **Ф.4 — untagged.** Разгейтить после починки mono-collection-ordering
  (`[M-180-untagged-codegen-mono]` — компилятор, не serde).
- **Ф.5 — `#serde(with = ...)`** — кастомный кодек поля (обёртка вокруг чужого типа,
  RFC3339-варианты дат, base64-варианты). Паритет serde.
- **Ф.6 — namespace-API `Json.decode[T](s)` / `Json.encode(v)`.** Чинит
  `[M-180-namespace-static-generic-mono]` (turbofish на namespace-static generic). Эргономика
  уровня `serde_json::from_str::<T>`; free-fn остаются как низкий уровень.

## Где можем быть ЛУЧШЕ оригинала (главная ценность плана)

- **Ф.7 — strict-by-default для неизвестных полей.** serde по умолчанию **молча игнорирует**
  неизвестные поля (`deny_unknown_fields` — opt-in) — классический источник тихих багов
  («опечатался в имени поля, конфиг молча не применился»). Nova: **строгость по умолчанию**
  (неизвестное поле → typed `DeError{UnknownField{name, path}}`), opt-out `#serde(allow_unknown)`
  для forward-compatible API. Это в духе Nova (no-magic, AI-first: LLM-опечатка ловится сразу).
  **✅ РЕШЕНИЕ ВЛАДЕЛЬЦА ПРИНЯТО 2026-07-22: «согласен» — И ПРИЗЕМЛЕНО В ТОЙ ЖЕ ВОЛНЕ (D436).**
  `build_unknown_field_check` сканирует `d.map_keys()` до чтения полей записи; `deny_unknown_fields`
  (старый opt-in ключ) остаётся принимаемым no-op-синонимом нового дефолта (конфликт с
  `allow_unknown` на одном типе → `E_SERDE_UNKNOWN_FIELD_POLICY_CONFLICT`). **Миграция:** аудит
  ВСЕГО дерева (`std`/`spec_tests`/`nova_tests`/`examples` вкл. флагман aggregator) — НОЛЬ
  существующих типов декодирует hand-written wire с полем вне своей схемы (флагманские DTO,
  `examples/flagship/aggregator/src/api/{report_json,main}.nv`, — `#impl(Serialize)`-only,
  никогда не декодируются обратно) → миграция не потребовалась, кроме новых pos-фикстур.
- **Ф.8 — path-rich ошибки из коробки.** В Rust нужен отдельный `serde_path_to_error`; у нас
  `DeError` уже typed — добавить путь (`$.user.addresses[0].zip`) в каждую ошибку декодирования.
  Уровень DX zod. Требует протаскивания «курсора пути» через Deserializer (стоимость — поле в
  контексте, не аллокация на успешном пути).
- **Ф.9 — schema-gen встроенно.** JSON Schema из типа (`nova doc`-подобная подкоманда или
  `#[derive]`-компаньон). В Rust — отдельный крейт schemars с дублированием атрибутов; у нас
  компилятор уже знает и типы, и `#serde`-атрибуты → схема генерируется **без второго
  источника правды**. Сильный аргумент для API-first разработки.
- **Ф.10 — compile-time валидация wire-контракта.** **✅ ЧАСТИЧНО ПРИЗЕМЛЕНО 2026-07-22 (D435,
  вместе с Ф.1)** — после `rename`/`rename_all` проверяется: коллизии wire-имён полей
  (`E_SERDE_WIRE_NAME_COLLISION`, incl. alias-vs-primary и alias-vs-alias), `skip`+`rename`
  (`E_SERDE_SKIP_RENAME_CONFLICT`), `flatten`+strict-default несовместимость
  (`E_SERDE_FLATTEN_DENY_CONFLICT`/`_UNSUPPORTED`), misplaced-ключи
  (`E_SERDE_ATTRIBUTE_MISPLACED`/`_ON_SUM_UNSUPPORTED`), unknown-policy-конфликт
  (`E_SERDE_UNKNOWN_FIELD_POLICY_CONFLICT`). **НЕ покрыто** (вне периметра этого захода —
  относится к sum-тегированию, не к record field-attrs): «дубли tag-значений вариантов» —
  Ф.5/Ф.4 sum-tagging область, отдельный followup если/когда там появится custom
  per-variant tag-value (сейчас tag-значение = имя варианта, уникальность уже гарантирована
  парсером sum-объявления). serde часть этого ловит в runtime или не ловит
  вовсе. Зеркалит уже существующий `E_SERDE_BAD_ATTRIBUTE`-подход.

## Порядок и зависимости

Ф.1 (сам по себе) → Ф.10 (валидация имён — после rename) · Ф.2/Ф.3/Ф.4/Ф.6 — независимые
компилятор-фиксы (могут параллельно) · Ф.5 после Ф.1 (общая attribute-механика) · Ф.7/Ф.8 —
дизайн-решения владельца, реализация после Ф.1 · Ф.9 — последняя (нужны финальные атрибуты).

## Гейты (каждая фаза)

pos+neg-фикстуры на каждый атрибут/режим · round-trip `decode(encode(v)) == v` · conformance
мега-CU без регрессий · flagship aggregator (реальный JSON API) собирается и держит loadtest ·
D-амендменты в том же слиянии (attribute-семантика, strict-by-default — язык-меняющее).
