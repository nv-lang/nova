# Plan 194 — Модель исполнения контрактов: `#debug` + переопределение `--contracts`

**Статус:** 📋 PROPOSED 2026-07-10 (дизайн ПОДТВЕРЖДЁН владельцем — вариант 2 `#debug`-префикс). **Приоритет:** P1 (язык-семантика; разблокирует vrange-роутинг).

## Решение владельца (2026-07-10)

Контракты — **безопасность/корректность, а не опциональная оптимизация**.
Никакого глобального «выключить проверки» (footgun как C `NDEBUG`).

### 1. По умолчанию все контракты ВСЕГДА работают

`requires` / `ensures` / `invariant` / `assert(...)` + проверки памяти
(границы массива, null) — исполняются в рантайме ВСЕГДА. Не элидируются
никаким флагом (кроме доказуемо-избыточных — sound-элизия компилятором).

### 2. `#debug`-префикс — единый маркер «только в dev-сборке»

Для РЕДКОГО дорогого контракта (например O(n)-проверка на каждый вызов) —
префикс `#debug` (ЕДИНООБРАЗНО, вариант 2 владельца; НЕ зоопарк `debug_requires`):

```nova
fn binary_search(arr []int, x int) -> int
    #debug requires is_sorted(arr)    // O(n) — только dev, в релизе убрано
    requires arr.len() > 0            // дёшево — ВСЕГДА
{
    #debug assert(invariant_holds())  // тело: dev-only
    ...
}
```

- `#debug requires <e>` / `#debug ensures <e>` / `#debug invariant <e>` — клаузы.
- `#debug assert(<e>)` — statement-форма (зеркало `assert`, всегда → `#debug assert`, dev-only).
- `#debug` — общий атрибут-модификатор (стиль `#cfg`/`#stable`), одно правило на все
  контракт-формы. Расширяем при нужде на другие dev-only-конструкции.

### 3. `--contracts` ПЕРЕОПРЕДЕЛЁН: уровень = роль SMT-движка (Z3), НЕ вкл/выкл

Было: `enforce|off`. `enforce` — Z3 гоняется на КАЖДОЙ сборке (доказанные
элидируются, недоказанные → runtime); `off` — элидировать ВСЁ (footgun).
Проблема: Z3 на каждой dev-пересборке = медленно; `off` = дыра безопасности.

Стало: **три уровня, каждый = роль SMT-движка** (Z3/crosscheck; backend по
`NOVA_SMT_BACKEND`):

| Значение | Движок | Рантайм | Компиляция | Когда |
|---|---|---|---|---|
| **`checked`** | НЕ вызывается | все не-`#debug` + `#debug` проверки работают | БЫСТРАЯ (нет Z3) | dev-дефолт — быстрая перекомпиляция |
| **`optimized`** | ОПТИМИЗАТОР: доказать-избыточные → sound-элизия | недоказанные не-`#debug` работают; `#debug` убраны | медленная (Z3 на всё) | release-дефолт — быстрый+безопасный рантайм |
| **`verified`** | ВЕРИФИКАТОР: доказать ВСЕ не-`#debug` или **compile-error** | доказанные убраны; runtime-зависимые остаются | медленная | opt-in — высокая гарантия (формальная верификация) |

- **`off` УДАЛЁН** (footgun). Локальный отказ от обязательной проверки в горячем
  месте — `unsafe`/`get_unchecked` (явно, локально, под ответственность автора).
- **Дефолт по профилю сборки:** dev → `checked` (Z3 НЕ гоняется → быстрее нынешнего
  `enforce`), release → `optimized`. `verified` — явный opt-in.
- `nova verify-contracts` (существующая команда, SMT JSON-диагностика) остаётся
  ортогональным dev-инструментом «проверить контракты статически без сборки»;
  `--contracts=verified` — то же как build-гейт.

## Следствие: vrange-роутинг (закрывает [M-172.14-vrange-nv-route])

Проверка границ среза (`@index(Range)`) = **безопасность памяти, всегда включена**
(не `requires`, который элидируется). Значит:
- `v[a..b]` роутится через `.nv Vec[T] @index(Range)` — ЕДИНЫЙ источник, codegen-магия
  (`nova_vec_slice_chk`-интринсик) снимается (принцип «без второго окна правды»).
- Bounds-check в `@index` — always-on safety-проверка (новая форма, не `requires`).
- `_nochk`-элизия (пропуск при доказанной in-range) — оптимизационный проход в
  `--contracts=optimized`, не спец-codegen.
- Пиновые panic-тесты (`plan96/neg_slice_*`) обновляются на текст `@index`.

## Фазы

- **Ф.0 Спека** — D-амендмент (новый D-блок): модель исполнения, `#debug`-семантика,
  переопределение `--contracts`, bounds-check=safety-не-contract, ретракция `off`.
- **Ф.1 Parser** — `#debug`-префикс на requires/ensures/invariant/assert (statement-attr).
- **Ф.2 Semantics/codegen** — эмиссия: не-`#debug` всегда; `#debug` под dev; флаг
  `checked|optimized` (build_cache-ключ обновить, `off` убрать); sound-элизия избыточных
  в optimized.
- **Ф.3 vrange-роутинг** — `v[a..b]` → `.nv @index`; always-on bounds-check; снять
  интринсик; обновить пиновые тесты; `_nochk` как оптимизация.
- **Ф.4 Миграция** — существующие `--contracts=off`-сайты (тесты/CI/build_cache) на новую
  модель; грепнуть корпус.

## Гейты

conformance + новые фикстуры (`#debug` on/off под checked vs optimized; bounds-check
always-on под обоими; vrange через @index); байт-паритет рантайм-поведения не-`#debug`
контрактов; err173 δ0; nova check std δ0.

## Границы

Не меняет ЧТО проверяется (та же семантика contract), меняет КОГДА оптимизируется и
как маркируется dev-only. `assert(...)`-builtin остаётся; `#debug assert` — dev-вариант.
