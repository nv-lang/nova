## Архитектура «нового пути» (проверено по коду — куда мигрируем)

Чекер наполняет `resolved_types_buf` (в `type_check_ctx`, `types/mod.rs`) → лифтится в `ModuleEnv.resolved_types`
(`types/mod.rs:1895`). Дополнительно `resolved_callees: ExprId → Span` (`emit_c.rs:876`, ставит `main.rs:512`).

Диспетчер `infer_expr_c_type` (`emit_c.rs:48903`) читает каналы в порядке, legacy — LAZY-fallback:
1. **Пред-канальные спец-кейсы** (ДО каналов): `try_as[T]` (48911); **`infer_generic_static_ctor_ret`** (48958) —
   stub-wrapper mono ctor.
2. **Канал 1** (48963): `resolved_callees[id]` → `fn_ret_by_span[span]` — тип возврата Call от выбранного чекером callee.
3. **Канал 2** (48987): `resolved_types[id]` → `resolved_type_to_c` — тип любого выражения (вкл. closure-Func 49001).
4. **Legacy-fallback:** `infer_call_ret_c` (46311, зона волны-1) + сиблинги — срабатывают, когда каналы пусты.

**Миграция сиблинга = заставить чекер записать `resolved_callees`/`resolved_types` для соответствующей формы →
канал выигрывает → сиблинг недостижим → удалить (или panic для shared с волной-1).** Проверка: byte-parity + 95/0.
