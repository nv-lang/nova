## ЗАДАЧА — три носителя одного класса

### Носитель 1 — №617: алиас импорта виден всему CU

ФАКТ (найден окном p576 при подготовке фикстуры к №536): `import X as a` в
одном файле делает `a` видимым по всему CU — алиасы столкнулись с несвязанными
локальными именами в других файлах (например `a.compare(b)` в
`std/src/collections/vec/access.nv`).

НЕ УСТАНОВЛЕНО: даёт ли утечка ТИХИЙ выбор не того имени или только громкую
коллизию. ПЕРВОЕ ДЕЙСТВИЕ — предъяви носитель с ИСХОДОМ: два файла в одном CU,
в первом `import m as a`, во втором локальная переменная `a` (или функция);
покажи, что происходит — коллизия, тихая подмена или верный скоуп. Приёмка —
алиас виден ТОЛЬКО в своём файле; фикстура из двух файлов, где одноимённые
сущности не мешают друг другу.

### Носитель 2 — №618: быстрый путь `[single] => *single` без арности

ФАКТ (назван окном p576 в «что не сделано»): в резолве квалифицированного
вызова (`f1_check_call`, ветка `Member{obj: Ident(prefix)}`) при РОВНО ОДНОМ
кандидате своего модуля срабатывает предсуществующий быстрый путь — арность не
сверяется, ошибка утекает сырым CC-FAIL. Разрыв предсуществующий, «gap, not
wrong».

ЧТО СДЕЛАТЬ: проверка арности (и вообще применимости) в этой ветке, с чистой
диагностикой `E_NO_MATCHING_OVERLOAD` (или точнее — по образцу соседней ветки).
Затем ГРЕП по резолву: перечисли ВСЕ места `[single] => …` / аналогичные
быстрые пути и для каждого скажи, что он пропускает. Это и есть оговорка
записи: «перечислены ВСЕ быстрые пути, и для каждого сказано, что он
пропускает».

### Носитель 3 — остаток №534: захват `spawn` по голому имени

ФАКТ: локальная `fn routes() -> Router`, вызванная ВНУТРИ тела `spawn`, даёт
`CC-FAIL: use of undeclared identifier 'routes'` — анализ захвата добавляет в
контекст файбера поле `routes` (это ВЫЗОВ, не переменная) с ЧУЖИМ типом
`[]RouteInfo` от одноимённого ПАРАМЕТРА в другом модуле. Репро:
`nova-polaris/src/rt/handle_connection_smoke.nv` при наличии в наборе
`polaris.openapi`.

Возможно, фиксы p576 (скоуп по `file_modules`) это уже закрыли — ПРОВЕРЬ
первым делом на минимальном репро (двухфайловый CU: параметр `routes []T` в
одном модуле, локальная fn `routes` в `spawn` другого). Если закрыто — фикстура
и честное «закрыто фиксом №536»; если нет — чини тем же приёмом: анализ
захвата обязан резолвить в СКОУПЕ файла, а не по CU-широкой таблице.
