# Черновик D-амендмента: `break`/`continue` — выражения типа `never`

Куда: `spec/decisions/04-effects.md`, раздел «`never` — почему `throw` совместим
с любым типом» (там же живут `throw`/`panic`/`interrupt`). НЕ в D86: правило
про `??` тогда не меняется ни на слово — форма выпадает из него сама.

Номер амендмента присваивает интегратор при слиянии.

---

## Что измерено ДО того, как писать

Все четыре формы прогнаны на одном бинаре 2026-08-19:

| форма | вердикт сегодня |
|---|---|
| `x ?? throw Err{...}` | **работает** |
| `x ?? panic("...")` | **работает** |
| `x ?? return R` | парсится, чекер ВСЕГДА отвергает — `E_COALESCE_RETURN_FALLBACK` |
| `x ?? continue` / `?? break` | не доходят до чекера: парсер, «unexpected `continue` in expression» |

Причина различия названа в самом D86: fallback законен, если его тип совместим
с `T` **или равен `never`**. `throw` и `interrupt` чекер типизирует как `never`
(`types/mod.rs`, арм `ExprKind::Throw` → `prim_ref("never", …)`).
`continue`/`break` не выражения вовсе, поэтому до типового правила не доходят.

**`return` отклонён не за тип.** AMEND 2026-07-23 ретрактировал его потому, что
для проброса есть лучший канон (`X?`, `.ok()?`, `.map_err(..)?`, `.ok_or(..)?`).
Для «пропустить итерацию, если `None`» такого канона НЕТ — заменой служит только
явный `match`/`if let`. Довод, закрывший `return`, сюда не переносится.

---

## Поправка к вводной владельца, найденная замером

Владелец предупредил: «break может вернуть значение из loop, учитывай это».
**Такой формы в Nova сегодня нет:**

* грепом по `spec/decisions/*.md` — ни одного `break <значение>`;
* парсер: `TokenKind::KwBreak => { self.bump(); Ok(Stmt::Break(start)) }` —
  ключевое слово съедается, значение не читается;
* AST: `Break(Span)` — поля значения нет.

Правило ниже сформулировано так, чтобы **остаться верным, если форму введут**:
`never` относится к МЕСТУ `break`, а не к циклу. В Rust ровно так: `break value`
имеет тип `!` в точке разрыва, а значение уходит в тип самого цикла. Поэтому
введение `break value` позже НЕ потребует править этот амендмент.

---

## Предлагаемое правило

> **`break` и `continue` — выражения типа `never`**, наравне с `throw`, `panic` и
> `interrupt`.
>
> 1. **Тип.** В точке, где стоит `break`/`continue`, выражение имеет тип
>    `never`. Значит оно совместимо с любым ожидаемым типом — как `throw`.
> 2. **Позиция не ослабляется.** `never`-типизация НЕ отменяет правила «только
>    внутри цикла»: `break`/`continue` вне цикла остаются ошибкой, и проверка
>    этого — отдельная, прежняя.
> 3. **Значение цикла (на будущее).** Если когда-нибудь появится `break <expr>`,
>    значение уходит в тип ЦИКЛА, а не в позицию, где написан `break`; тип
>    самого `break`-выражения остаётся `never`. Настоящее правило от этого не
>    меняется.
> 4. **Следствие для D86 — БЕЗ правки D86.** `x ?? continue` и `x ?? break`
>    становятся законными по существующему правилу «fallback типа `never`».
>    Никакой новой оговорки при `??` не заводится.
> 5. **`return` остаётся ретрактированным при `??`** (AMEND 2026-07-23). Это НЕ
>    противоречие: `return` отклонён не по типу, а потому что для проброса есть
>    канон. Оговорку стоит перенести в текст явно, иначе два правила выглядят
>    несогласованными.
> 6. **Что становится законным сверх `??`:** `if c { continue } else { v }`,
>    `match … { A => continue, B => v }` — любая позиция, где `never` уже
>    допустим для `throw`.

---

## Цена реализации, названная честно

Это НЕ правка одной ветки парсера. Сейчас `break`/`continue` — `Stmt`, а не
`ExprKind`. Введение `ExprKind::Break`/`ExprKind::Continue` означает новый
вариант перечисления, а по `ExprKind` в дереве десятки исчерпывающих `match` —
каждый потребует арма (чекер, три драйвера кодогена, обходчики эффектов,
consume-анализ, fiber-safety). Плюс:

* кодоген: `never`-выражение в позиции значения обязано порождать переход, а не
  значение — у `throw` этот путь есть, для `break`/`continue` его надо завести;
* исчерпаемость и поток: арм `match`, кончающийся `continue`, не даёт значения —
  проверка ветвей обязана это понимать, иначе появятся ложные
  «несовместимые типы веток»;
* радиус: измерить прогоном конформанса и std ДО приземления.

**Поэтому амендмент и реализация обязаны идти ОДНИМ слиянием** (правило проекта:
язык-меняющее слияние не пушится без D-амендмента в том же слиянии). Текст выше
готов; вписывать его в спеку без реализации нельзя — спека начнёт описывать то,
чего в компиляторе нет.
