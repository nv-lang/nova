# Plan 268, Ф.0 — пооперационная проработка API (`Os`/`Fs`/`Net`)

Основание — [D456](../../spec/decisions/04-effects.md#d456-граница-эффекта--публичный-api-на-nova-а-не-таблица-системных-вызовов-план-268-владелец-2026-08-11)
и [план 268](../268-effect-boundary-reform.md), фаза Ф.0. Документ пишется ДО
кода: код не менялся, ничего не собиралось и не гонялось. Источники — сами
файлы `std/src/os/effect.nv`, `std/src/os/os.nv`, `std/src/os/mock.nv`,
`std/src/os/ffi.nv` и парные для `Fs`/`Net`, прочитаны целиком.

Правило для каждой строки: колонка «что нарушено» — конкретный пункт списка
D456 (п.1–8) или прямая цитата из плана 268 (для случаев вне восьми пунктов,
например «тип обещает возврат, которого не бывает»). Колонка «мок-автор» —
не форма, а последствие: что автору мока придётся знать/делать до и после.

Пометка **†** у сигнатуры — форма зависит от [вопроса 1](#вопросы-владельцу)
(проходит ли `Vec[T]` через vtable эффекта как Ok-payload). Пока это не
проверено пробой, таблица даёт сигнатуру-намерение и в тексте под таблицей —
запасной вариант на основе уже ДОКАЗАННОГО рабочим прецедентом (`Net.lookup`,
`(array_base, count)`).

## 1. `Os` — 17 операций

| # | было | стало | нарушено | что меняется у автора мока |
|---|---|---|---|---|
| 1 | `arg_count() -> int` | *(операция удаляется — слита в №2)* | п.3, п.6 | — |
| 2 | `arg_at(i int) -> str` | `args() -> []str` † | п.3 (обход по индексу: `arg_count`+`arg_at` — ровно пример из D456), п.6 (счётчик рядом с данными) | Сегодня мок обязан держать `arg_count()` синхронным с диапазоном `arg_at(i)` — это два метода, которые ОБЯЗАНЫ согласиться. Завтра — один метод, возвращающий список; рассинхронизации не существует физически. |
| 3 | `env_get(key []u8) -> Option[str]` | `env_get(key []u8) -> Option[[]u8]` | п.7 (шапка файла прямо признаёт: «string getters return raw bytes verbatim» — в `str` кладутся байты без гарантии UTF-8) | Мок сегодня отдаёт `str` через `to_str_unchecked` — обязан помнить, что это не настоящая строка. Завтра отдаёт `[]u8` напрямую, никакого "почти-строкового" типа, который врёт компилятору. |
| 4 | `env_has(key []u8) -> bool` | *(операция удаляется)* — `has_env()` в `os.nv` вычисляется через `env_get(key).is_some()` | не входит в 8 пунктов буквально, но тот же принцип, что п.3: два метода эффекта (`env_get`/`env_has`), которым мок обязан верить ОБА и одинаково | Сегодня мок пишет `mem_env_has` независимо от `mem_env_get` — ничто не мешает им разойтись (например, забыть обновить одно при правке другого). Завтра — одна операция, `has_env` не существует на границе вообще. |
| 5 | `env_set(key []u8, val []u8) -> int` | `env_set(key []u8, val []u8) -> Result[(), IoError]` | п.1 (0/-errno) | Мок сегодня обязан знать, что `0` = успех и отрицательное число = «POSIX errno» (`0 - 22` для EINVAL и т.п., см. `real_os`). Завтра — `Ok(())`/`Err(IoError...)`, без знания errno-номеров. |
| 6 | `env_remove(key []u8) -> int` | `env_remove(key []u8) -> Result[(), IoError]` | п.1 | То же самое, что №5. |
| 7 | `env_len() -> int` | *(операция удаляется — слита в №9)* | п.3, п.6 | — |
| 8 | `env_key_at(i int) -> str` | *(операция удаляется — слита в №9)* | п.3, п.7 | — |
| 9 | `env_val_at(i int) -> str` | `vars() -> []EnvEntry` †, где `EnvEntry` — байт-первый эффект-уровневый record (`key []u8, value []u8`; НЕ путать с публичным `EnvVar{key str, value str}` из `os.nv`, тот строится СНАРУЖИ границы) | п.3 (это буквально пример из D456: «`env_len`+`env_key_at`+`env_val_at`… мок отдаст пять ключей и четыре значения — и не покраснеет НИЧЕГО»), п.7 | Сегодня `MockOs` держит ТРИ параллельных массива (`env_keys`/`env_vals`/`env_live`) и обязан вручную поддерживать их согласованность построчно (`@nth_live`, тombstone-логика). Завтра — один метод, отдающий список пар; внутреннее хранение мока может остаться каким угодно, но ГРАНИЦА больше не требует трёхстороннего согласия. |
| 10 | `cwd() -> str` | `cwd() -> Result[[]u8, IoError]` | п.2 (пустая строка = ошибка — sentinel), п.7 (путь как `str`, тогда как `Fs` уже несёт пути как `[]u8`; несогласованность между `Os` и `Fs` для одной и той же сущности «путь») | Сегодня мок обязан возвращать `""`, чтобы просигналить ошибку — ничем не отличимо от «текущая директория — пустая строка» (гипотетически). Завтра — `Err(...)` явно, `Ok(bytes)` — данные без совмещённого смысла. |
| 11 | `set_cwd(path []u8) -> int` | `set_cwd(path []u8) -> Result[(), IoError]` | п.1 | Как №5. |
| 12 | `temp_dir() -> str` | `temp_dir() -> []u8` | п.7 (документировано как никогда не пустое — здесь **не** п.2, ошибки не бывает по контракту; но байты пути всё ещё должны быть `[]u8`, не `str`) | Мок отдаёт сырые байты пути напрямую, не обязан гарантировать их валидный UTF-8, чтобы удовлетворить сигнатуру. |
| 13 | `home_dir() -> str` | `home_dir() -> Option[[]u8]` | п.2 (пустая строка = «нет дома»), п.7 | Сегодня «нет домашней директории» кодируется пустой строкой — неотличимо от результата `home_dir()` НА платформе, где путь пуст (гипотетически, но тип это не запрещает). Завтра — `None` прямым текстом. |
| 14 | `exit(code int) -> int` | `exit(code int) -> ()` | вне восьми пунктов — прямая цитата плана: «тип обещает возврат, которого не бывает» (см. [вопрос 3](#вопросы-владельцу): выбор между `()` и гипотетическим bottom-типом) | Возврат сегодня ВСЕГДА игнорируется с обеих сторон (`real_os` физически не возвращается; `mock_os` возвращает `0`, вызывающая сторона делает `ro _ = Os.exit(code)`). Автору мока сегодня приходится выдумывать бессмысленное число для возврата; завтра — нечего выдумывать. |
| 15 | `pid() -> int` | без изменений | — (не нарушение: `int` здесь легитимные ЧИСЛОВЫЕ ДАННЫЕ, не хендл, нигде не передаётся туда, где ожидается что-то другое) | — |
| 16 | `hostname() -> str` | `hostname() -> Result[str, IoError]` | п.2 (пустая строка = ошибка) | Мок сегодня для ошибки обязан вернуть `""`; в остальном hostname — легитимно текстовые ASCII-данные (DNS-имя), поэтому `str`, а не `[]u8`, оправдан. Завтра — `Err(...)` явно. |
| 17 | `process_run(program []u8, argv []u8, argc int, env []u8, envc int, use_env bool, cwd []u8) -> (int, int)` | `process_run(req ProcessSpawnRequest) -> (int, int)`, где `ProcessSpawnRequest { program []u8, argv []u8, argc int, env Option[[]u8], envc int, cwd Option[[]u8] }` | п.8 (семь позиционных параметров + два счётчика + один флаг-переключатель — ровно эталонный пример D456, там же D453) | Сегодня мок обязан помнить порядок из семи параметров и смысл булева `use_env` (включает или выключает соседний параметр `env`) и пустых-байт-как-«наследовать cwd». Завтра — одна запись; `env`/`cwd` — `Option`, само наличие `Some`/`None` заменяет отдельный флаг и sentinel-пустоту разом. `argc`/`envc` остаются как счётчики NUL-блоба — см. [вопрос 1](#вопросы-владельцу): именованное исключение, пока не закрыт Q1. |

**Итог по `Os`:** было 17 операций, предлагается 14 (три слияния: 1+2→1,
4→удалена, 7+8+9→1).
