# Окно p248-copyflip — исследование поворота умолчания копирования

**Модель:** sonnet. **Только исследование**, компилятор/std/спека/полярис не тронуты
(правки — только в `scratch/probe1/` внутри этого worktree, для проб).

## Переформулировка постановки (важно, читать первым)

Задание стартовало как «запретить копирование непримитивов», но координатор
переформулировал ДО начала измерений (сообщение получено после начальной
разведки): владелец смотрит не на запрет, а на **унификацию** — связывание
(`ro b = a`) всегда должно означать одно и то же (второе имя на то же
значение), явная копия — всегда через `.clone()`, согласие на дешёвую
implicit-копию — пометкой для мелких стековых значений (образец — `Duration`).
Мотив: сегодня одна и та же запись `ro b = a` означает противоположные вещи в
зависимости от того, как объявлен тип (`value`-запись — копия, обычная
запись — второе имя), и это узнаётся только по объявлению типа, возможно в
другом файле.

**Главный результат разведки, найденный ДО всех измерений и определивший
всё остальное:** то, что владелец описывает как желаемое умолчание, **уже
реализовано в компиляторе** — не как единый флип, а как узкий, чтением кода
и пробами подтверждённый механизм (`M-ro-launder-via-mut-binding`, D246-
амендмент 2026-07-23 + field-launder канал 2026-08-01 + `is_fully_stack_value`
§72 + `Clone`-протокол D230). Секции A-E ниже сравнивают ПОЛНЫЙ флип не с
гипотетическим статус-кво, а с этим уже существующим механизмом и его
измеренными дырами — иначе сравнение было бы нечестным.

## 0. Что уже есть в компиляторе — установлено чтением кода и пробами

**Три уже работающих куска, все найдены чтением `compiler-codegen/src/types/mod.rs`
и подтверждены пробами (не рассуждением):**

1. **`D230` — протокол `Clone`** (`spec/decisions/02-types.md:13852`). Явный
   `.clone()` — санкционированная дверь для независимой копии; auto-derive по
   `#impl(Clone)` либо явный `fn T @clone() -> T`. Это ровно то, что владелец
   просит как «единый способ получить копию».

2. **`M-ro-launder-via-mut-binding`** (D246-амендмент, 2026-07-23,
   `02-types.md:11099-11218`). Правило: `ro`-связанный источник (голый
   `ro a = …` ЛИБО параметр без `mut`, D176-дефолт) **не может** быть
   пере-связан в `mut`-цель, если тип не «полностью стековый» —
   `E_READONLY_COERCE`, дверь для независимой копии — `.clone()` (D230).
   Применяется **ко ВСЕМ типам без исключения по классу хранения** (сам текст
   амендмента: «проба G доказала, что value-тип ⇒ безопасно ЛОЖНО в общем
   случае»). Это ровно та развилка, о которой говорит координатор: сегодня
   `ro b = a` для НЕ-полностью-стекового типа с mut-целью уже требует либо
   исходной `mut`-инициализации, либо `.clone()` — то есть частично
   унифицировано уже.

3. **`is_fully_stack_value`** (`compiler-codegen/src/types/mod.rs:3202-3261`,
   §72). Рекурсивный предикат: тип «полностью стековый» (можно копировать без
   церемонии), если это скаляр, `str`, `Unit`, `Tuple`/`FixedArray` из таких же
   полей, либо `value`-запись/`NamedTuple`, ВСЕ поля которых рекурсивно
   полностью стековые. Один кучевой указатель на глубине (`Vec`/`HashMap`/
   `Set`/heap-record) на любом уровне вложенности — дисквалифицирует ВЕСЬ тип.
   **Это и есть неявный аналог `#copy`** — но выводится компилятором
   структурно, без единой пометки автора. `Duration`, `Date`, `Complex`,
   `i128`, `CasRaw*`, `Point{x,y}` — все квалифицируются автоматически.

4. **Field-launder канал** (`M-router-handler-mut-capture-escape-soundness`
   §2, owner decision 2026-08-01, `types/mod.rs:11086-11120`) — тот же запрет,
   но для **проекции поля**: `mut x = @field` (self-поле в ro-методе) и
   `mut x = obj.field` (bare-Ident `obj`, `ro`). Комментарий сам документирует
   границу: «глубже (`a.b.field`) — задокументированный, звучный
   false-negative, здесь не чинится».

5. **`#share`-исключение (D415)** — типы с `#share` **намеренно** exempted из
   пп. 2/4: «копия `#share`-типа — САНКЦИОНИРОВАННАЯ форма разделения; запись
   через копию — и есть смысл (`fetch_add` на общей ячейке), а не побег из
   заморозки» (`types/mod.rs:11102-11109`). То есть `#share` уже работает как
   «пометка допустимого разделения» — именно то, что нужно для `AtomicInt`.

### Пробы, подтверждающие механику (все в `scratch/probe1/main.nv`, откатано)

| сценарий | форма | результат |
|---|---|---|
| bare `ro a = handle; mut b = a` (tuple-форма, БЕЗ `#share`) | локал | ❌ `E_READONLY_COERCE` |
| то же, `#share`-помеченный tuple-тип | локал | ❌ `E_READONLY_COERCE` (не освобождает bare-локал!) |
| bare `ro c = HandleRecord{…}; mut d = c` (record-форма, `{}`, `#share`) | локал | ❌ `E_READONLY_COERCE` — **т.е. смена скобок `()` → `{}` НЕ снимает ошибку** |
| `mut counter = cfg.counter`, `cfg` ro-параметр, `counter` — `#share` tuple-хэндл (буквально сценарий №337/№334) | field-projection | ✅ компилируется — **намеренное исключение по `#share`, не дыра** |
| то же, но хэндл **БЕЗ `#share`** (`UnvouchedHandle(*())`) | field-projection | ❌ `E_READONLY_COERCE` — непомеченный хэндл **уже блокируется** |
| `mut items = box.items`, `box` value-запись с полем `Vec[int]` | field-projection, 1 hop | ❌ `E_READONLY_COERCE` (есть готовый conformance-тест `m_ro_launder_m_field_launder_ident_neg.nv`, EXPECT_COMPILE_ERROR, зелёный) |
| то же, но поле объявлено сахаром `[]int` вместо `Vec[int]` | field-projection, 1 hop | ✅ компилируется, **и это РЕАЛЬНАЯ утечка** — см. ниже |
| `mut counter = cfg.inner.counter` (2 хопа, хэндл без `#share`) | field-projection, 2 hops | ✅ компилируется — задокументированный в коде false-negative, подтверждён живьём |

**Новая находка, эмпирически подтверждённая build+run (не только `check`):**
`[]T`-сахар не распознаётся `is_fully_stack_value`/field-launder так же, как
`Vec[T]`, хотя это синтаксический алиас одного типа
(`reference-nova-slice-vec-alias.md`). Проба:

```nova
type Boxed value { data []int }        // сахар — НЕ Vec[int] явно
type Holder2 { boxed Boxed }
fn fresh2(cfg Holder2) -> int {
    mut d = cfg.boxed      // компилируется БЕЗ ошибки
    d.data.push(99)
    d.data.len()
}
// main: ro h = Holder2{ boxed: Boxed{ data: [] } }; fresh2(h)
```

Собрано и запущено (`nova build` + прямой запуск exe, toolchain clang):

```
after fresh2: local copy len=1, original cfg.boxed.data.len()=1
```

**Мутация через «независимую копию» видна в оригинале.** Это ЖИВАЯ,
эксплуатируемая дыра сегодня — шире, чем №337 (которая была намеренным
`#share`-исключением, не дырой), и не привязана к 23 разделяемым хэндлам:
она бьёт по **любой** `value`-записи с полем `[]T`, а таких в корпусе
десятки (см. §B).

## A. Что закрывает унификация — относительно уже существующего, не относительно нуля

| дефект | закрыт СЕГОДНЯ (пп.0) | закрывает полная унификация | закрывает целевая узкая правка (см. E) |
|---|---|---|---|
| №337 (`ro` не защищает то, на что указывает; `#share` не обязателен) | **В основном ДА** — 1-hop проекция непомеченного хэндла уже блокируется (проба выше). Открыт только: 2+ hops (задокументированный false-negative) и «должен ли `#share` быть обязательным» (косметика — незабытый `#share` не даёт МЕНЬШЕ безопасности, чем есть, скорее наоборот блокирует копию) | закрывает полностью (нет цепочки — нет копии вообще, alias всегда) | закрывает полностью (расширить обход `Member` до N хопов — локальная правка того же канала) |
| **найденная в этом окне дыра `[]T` vs `Vec[T]`** | ОТКРЫТА, эмпирически подтверждена build+run | закрывает полностью (structural — не нужно распознавать сахар, alias всегда) | закрывает полностью (нормализовать `[]T`→`Vec[T]` перед проверкой в `is_fully_stack_value` — однострочная правка) |
| №341 (M:N не видит замыкание, ушедшее через `return`, не `spawn`) | не закрыт, другой механизм (граф вызовов, план 238) | **НЕ закрывает** — вопрос не про копирование, а про достижимость через файбер | не закрывает (не тот класс) |
| №348 (Mutex/RwLock/ReentrantMutex текут — нет деструктора) | не закрыт, это ресурс, нужна линейность | **НЕ закрывает** — нужна обязанность освобождения, копи-семантика этого не даёт | не закрывает (план 248 уже отдельно признал: Группа 2 требует линейности, не унификации) |
| №325-класс (линейность наследуется контейнером) | закрыт (К1, слияние Ш.2) | ортогонален — про потребление, не про копирование | ортогонален |
| «нужна точка слабее аффинности: нельзя копировать, но не нужно потреблять» (Ф.6/p248-nocopy, окно 2026-08-05) | **уже покрыто по факту `is_fully_stack_value` + `#share`-исключением** — именно эта пара УЖЕ даёт «нельзя копировать без vouch, потреблять не нужно» | унификация делает это ЯВНЫМ умолчанием без специального синтаксиса вообще | целевая правка ничего не меняет тут — вопрос уже закрыт существующим механизмом, просто не был так прочитан |

**Главный вывод раздела A:** искомая «одна новая сущность» из Ф.6 плана 238
(«копировать нельзя, потреблять не нужно») **уже существует** как побочный
эффект `is_fully_stack_value` + `#share`-vouch, просто была прочитана как
два разных механизма (D246-coercion и D415-share), а не как одна семья.
Единственные два ДЕЙСТВИТЕЛЬНО открытых дефекта, найденных этим окном
(N-hop chains, `[]T`-сахар), — узкие, локальные, чинятся в существующем
канале без миграции корпуса.

### B.2 Оценка: сколько из них дисквалифицируются от implicit copy сегодняшним предикатом

Ручная классификация 21 `value`-типа `nova-http` по видимой сигнатуре полей
(строки объявления получены грепом, `nova-http/src/*.nv`):

- **Безопасны для implicit-copy уже сегодня** (`is_fully_stack_value` даёт
  `true`, все поля — скаляры/`str`): `HeaderKV`, `HeaderOp`, `Cookie`, `Mime`,
  `Param`, `StatusCode`, `HeaderName` — **7 из 21 (33%)**.
- **Дисквалифицированы уже сегодня** (поле `[]T`/`Vec[T]`/вложенный
  дисквалифицированный тип): `MockHttp{routes []MockRoute}`,
  `HeaderValue{bytes []u8}`, `HeaderEntry` (транзитивно через `HeaderValue`),
  `HeaderMap{entries []HeaderEntry}`, `BodyReader{chunks [][]u8}`,
  `ContentType{params []Param}` — **6 из 21 (29%) точно**, плюс
  многострочные (`HttpClient`, `HttpClientBuilder`, `RequestBuilder`,
  `MockResponse`, `ParsedResponse`, `SetCookie`, `Url` — 7 штук, тела не
  разбирались построчно, оценка: учитывая домен (HTTP-клиент держит буферы
  заголовков/тело), **скорее всего тоже дисквалифицированы** — не измерено).

**Оценка (не измерено построчно для всех 21):** реалистично 60-70% доменных
`value`-типов в пакетных репах уже сегодня НЕ проходят `is_fully_stack_value`
— то есть для НИХ разница «unification vs текущее устройство» **уже почти
нулевая**: копия и так не была «дешёвой независимой» (частично шарит
кучевые поля — см. находку `[]T` в §0), а с чинкой сахара станет либо
честно alias (унификация), либо честно потребует `.clone()` (текущий
механизм + правка сахара).

| `examples/` | 1 (`TaskStatus.Cancelled` — это доступ к варианту enum, не полю; ложное срабатывание паттерна) |
| `spec_tests/conformance` | 5 (из них **4 — сами conformance-фикстуры под этот механизм**, `d104_doc_comment_syntax.nv` — 2 арифметических, не относится) |
| `nova-http/src` | 1 (`SameSite.Lax` — тоже enum-вариант, ложное срабатывание) |
| `nova-tls/src` | 0 |
| `nova-compress/src` | 0 |
| `nova-bignum/src` | 0 |

**Вывод: реальных, не-enum, не-фикстурных сайтов — порядка 6-8 во всём
измеримом корпусе.** Это ГРУБЫЙ синтаксический прокси (не ловит: запись
через существующую `mut`-переменную без нового `mut X =`, индексацию
(`arr[i].field`), многохоповые цепочки, аргументы вызова) — но даже с учётом
кратного занижения счёт на порядки меньше, чем 67 мест из измерения
плана 248 Ф.1 для линейности (там считались ВСЕ связывания хэндлов, здесь —
только пере-связывания ro→mut).

**Честно: это НЕ то же самое число, что «сколько мест сломает унификация».**
Унификация меняет умолчание для КАЖДОГО связывания (не только ro→mut), в том
числе `mut a = Type{…}; mut b = a` (оба mut — сегодня легально и НЕ проходит
через `E_READONLY_COERCE` вообще, коэрсия проверяет только направление
ro→mut). Именно эти сайты (mut-источник → mut-цель, независимая копия
действительно используется) **не измерены** — грубая оценка ниже.

### B.4 Неизмеренное — честно

- Сколько мест `mut b = a` (оба уже `mut`, никакого coercion-предупреждения
  сегодня нет) реально ПОЛАГАЮТСЯ на физическую независимость `b` от `a`
  после этого — то есть сломались бы молча под unification, если тип `a` не
  получит `#copy`. Не измерено: нет способа отличить «полагается» от
  «случайно никогда не мутируется» через grep; нужен по-настоящему семантический
  проход (не выполнен, effort budget).
- Сколько из ~209 non-std value/tuple типов в пакетных репах **обязаны**
  получить `#copy`, чтобы не потребовать `.clone()` по всему корпусу
  builder-цепочек (`mut @method() -> @`). Оценка в D.2 ниже, не измерение.

## C. Сравнение языков — ось «сколько смыслов у обычного связывания»

| язык | GC | непримитив по умолчанию | явная копия | **сколько смыслов у `x = y`** |
|---|---|---|---|---|
| **Rust** | нет | move (владение переходит); `Copy`-типы — implicit bitcopy | `.clone()` (`Clone`) | **один** (move) + opt-in bitcopy для `Copy`, неразличимо по эффекту от move для POD |
| **Swift 6** | нет (ARC) | `struct`/`enum` — value (COW, копия ленивая до первой мутации, **БЕЗ `.clone()`** — implicit); `class` — reference | не нужна для value-типов (COW сам копирует при записи); `~Copyable` — новый некопируемый режим | **два**, выбор — по ключевому слову типа (`struct` vs `class`), как в Nova сегодня |
| **C#** | да | `struct` — value (стек/inline, implicit bitcopy); `class` — reference (куча, alias) | не нужна для struct (implicit); `MemberwiseClone`/`ICloneable` для class | **два**, тот же выбор по ключевому слову типа — Nova сегодня устроена ИДЕНТИЧНО этой оси (`value`/`{}`) |
| **Go** | да | struct/array — value (shallow bitcopy, **тот же баг класс, что найден в §0**: копия структуры со slice-полем шарит backing array); map/slice/chan/ptr — reference | нет встроенного `.clone()`, ручной deep copy | **два**, выбор НЕ по ключевому слову типа, а по тому, «структура вообще или map/slice/ptr» — знаменитая go-gotcha, прямой аналог найденной в §0 дыры |
| **Java** | да | ВСЁ, кроме 8 примитивов — reference (records Java 16+ — тоже reference, просто immutable) | `.clone()` (`Cloneable`, печально известный своей кривизной) либо copy-конструктор | **один** (alias) для всех непримитивов — нет value-типов вовсе |
| **Kotlin** | да (JVM) | как Java — reference по умолчанию; `value class` (inline, 1 поле) — unboxed copy | `.copy()` на data class (не deep — shallow copy с изменёнными полями) | **один** + узкая лазейка (`value class`) — аналог `#copy` для одного поля |
| **Pony** | да (per-actor) | способность (`iso`/`val`/`ref`/`box`/`trn`/`tag`) **встроена в тип**; связывание — функция способности, единого умолчания нет вовсе | зависит от способности; `.clone()`-подобные методы у `ref`/`val` есть, `iso` — только `recover`/consume | **столько же смыслов, сколько способностей** (6) — самый высокий уровень церемонии из всех сравниваемых |

### Главный вопрос секции: есть ли GC-язык, где копирование НЕПРИМИТИВА запрещено по умолчанию (нужен явный `.clone()` для value-семантики)?

**Нет ни одного.** Каждый язык со сборщиком, где вообще ЕСТЬ value-типы
(Swift-hybrid, C#, Go, Kotlin inline) даёт implicit-копию БЕЗ `.clone()` —
цена копии считается приемлемой, раз тип согласился быть value. Языки, где
`.clone()`/эквивалент обязателен, — это языки, где **value-типов нет вовсе**
(Java, Kotlin по умолчанию, JS, Python, Ruby) — не потому что копирование
запрещено, а потому что копировать нечего, всё уже reference.

**Значит предложенная унификация не воспроизводит ни одну существующую
модель — она комбинирует «выбор value/reference по типу» (C#/Swift-ось,
которая у Nova УЖЕ ЕСТЬ) с «требованием `.clone()` даже для того, что
выбрало value» (черта языков БЕЗ value-типов). Комбинация этих двух черт
вместе — не встречена ни в одном из шести проверенных языков.** Это не
довод «нельзя», но довод «непроверенная территория» — сравнивать не с чем,
придётся исследовать эргономику с нуля, а не переносить чужой опыт.

## D. Реальные фрагменты — что станет многословнее

### D.1 `fresh_id`/`AccessLog` (`nova-polaris/src/middleware/log.nv:151-155`, №334/№337)

```nova
fn fresh_id(cfg AccessLog) -> str {
    mut counter = cfg.counter
    ro n = counter.fetch_add(1) + 1
    "req-${n}"
}
```

Сегодня (и после узкой правки E) — компилируется как есть, `#share`
разрешает копию-как-разделение. **Под полной унификацией — тоже компилируется
как есть**, если `AtomicInt` остаётся «alias-по-умолчанию без `#copy`»
(что и есть его настоящая семантика — разделяемая ячейка). Этот фрагмент
**не меняется ни в одном варианте** — приведён, чтобы показать: самый
разрекламированный пример плана 248 на самом деле НЕ требует `.clone()` ни
при унификации, ни при узкой правке, потому что `AtomicInt` и так —
концептуально reference-тип; проблема была не в этом фрагменте.

### D.2 Builder-цепочка (`nova-polaris/src/middleware/cors.nv:67-105`)

```nova
export fn Cors mut @allow_origin(origin str) -> @ { @origins.push(origin) }
export fn Cors mut @allow_any_origin() -> @ { @any_origin = true }
...
fn Cors @middleware() -> Middleware { ... }
```

`Cors` — `value priv` запись с полями-векторами (`origins []str`, …) —
**дисквалифицирована `is_fully_stack_value`** (содержит `[]str`). Сегодня
цепочка `Cors.new().allow_origin("x").allow_method("GET")` работает без
`.clone()` где-либо, потому что `mut @`-ресивер уже пишет по адресу
временного значения (D246 R8, `@` не эскейпит указателем внутри одного
выражения) — копия происходит только на границе связывания финального
результата, и на rvalue-цепочке это не наблюдаемо.

**Под унификацией без `#copy` на `Cors`:** то же самое выражение продолжает
работать (временный объект, единственная ссылка). **Но если где-то в коде
одна база форкается на два варианта:**

```nova
mut base = Cors.new().allow_method("GET")
mut strict = base.allow_origin("example.com")     // сегодня: независимая копия base
mut permissive = base.allow_any_origin()          // сегодня: тоже независимая копия
```

сегодня (и под узкой правкой) — `strict`/`permissive` физически независимы
от `base` (copy на связывании, `Cors` — а `mut`→`mut` не бьёт по
`E_READONLY_COERCE`). **Под унификацией без `#copy`** — `strict` и
`permissive` стали бы ОДНИМ объектом с `base` (сама mut-переменная —
alias), и `base.allow_origin(...)` мутировал бы то же хранилище, на которое
уже смотрит `strict` — молчаливая порча. Требовалось бы:

```nova
mut strict = base.clone().allow_origin("example.com")
mut permissive = base.clone().allow_any_origin()
```

**Не найдено ни одного реального сайта такого форка в проверенных пяти
репах** (grep на паттерн «одна `mut`-переменная типа builder используется
дважды после первого вызова `with_*`/`allow_*`» не дал совпадений в
`nova-polaris`/`nova-http`) — но это НЕ доказательство отсутствия (см. B.4),
только что явных случаев в текущем корпусе не нашлось.

### D.3 `Boxed`/`[]T`-утечка обобщается на реальный тип (`nova-http/src/header.nv:41`)

```nova
export type HeaderValue value { priv bytes []u8 }
```

Реальный тип с ровно той структурой, что вскрыла проба в §0. Сегодня, если
где-то в `nova-http` написано (гипотетический, но правдоподобный код):

```nova
fn tweak(entry HeaderEntry) -> HeaderValue {
    mut v = entry.value      // entry — ro-параметр, value — HeaderValue{bytes []u8}
    v.bytes.push(0)          // ПО ФАКТУ мутирует entry.value.bytes — утечка как в §0
    v
}
```

это компилируется сегодня (поле — `HeaderValue`, дисквалифицировано, но
field-launder уже ловит ЭТОТ случай — `HeaderValue` не через `[]T`-сахар
напрямую, а `HeaderEntry.value` типа `HeaderValue`, что рекурсивно тянет за
собой disqualification через record-arm предиката, а НЕ Array-arm — эта
проверка судя по всему проходит правильно, дыра именно в самом
Array/`[]T`-arm предиката, не в рекурсии типов). Под унификацией — `v` стал
бы честным alias, `.clone()` потребовался бы явно при желании независимости
— **эргономически то же самое количество ceremony**, что и правка предиката
(E), но унификация делает это универсальным правилом, а правка — почини
конкретного бага.

### D.4 Контрпример — где унификация ничего не меняет (домен `time`)

```nova
export type Duration value { ... }   // std/src/time/duration/core.nv:72
ro d1 = Duration.from_secs(5)
mut d2 = d1                          // сегодня: implicit copy, is_fully_stack_value=true
d2 = d2.add(Duration.from_secs(1))
```

`Duration` — полностью стековый (числовые поля). И сегодня, и под
унификацией с `#copy`-пометкой этот код **не меняется вообще** — ноль
дополнительных символов. Это и есть образец владельца, и он подтверждается:
для генуинно-POD типов (весь `time/civil/*`, `Complex`, `i128`, `CasRaw*`,
большая часть DTO из `serde_*_test.nv`) цена унификации — **одна строка
`#copy` на объявление типа, ноль правок на местах использования**.

## E. Альтернатива — что чинить прицельно (пересмотрено пробами)

**Изначальная формулировка задания предлагала сравнить унификацию с «почини
23 разделяемые ручки» (сменить `()` на `{}`).** Пробой это опровергнуто как
неэффективный вариант: смена скобок `()` → `{}` для `HandleRecord{ptr *()}`
**не убирает `E_READONLY_COERCE`** на bare-локале (см. таблицу в §0, строка 3)
— то есть переклассификация в heap-record НЕ ЯВЛЯЕТСЯ рабочим прицельным
фиксом, потому что то, что расшаривается у `AtomicInt`, — это pointee
(объект, на который указывает поле), а не сама обёртка; расшаривание
идентично в обеих формах.

**Правильная прицельная альтернатива, выведенная из чтения кода checker'а и
подтверждённая пробами — три маленьких, локальных правки в существующем
канале, без миграции корпуса:**

1. **Расширить field-launder обход с 1 хопа до N** (`types/mod.rs:11098`,
   `ExprKind::Member { obj, .. }` — сегодня проверяется только
   `obj` = bare-Ident/`@self`; расширить до рекурсивного `Member`-разбора
   цепочки). Закрывает задокументированный false-negative, из-за которого
   `cfg.inner.counter` (2 хопа) проходит без ошибки, а `cfg.counter` (1 хоп)
   — уже нет.
2. **Нормализовать `[]T` к `Vec[T]` в `is_fully_stack_value`
   (`types/mod.rs:3202-3261`)** до классификации поля. Закрывает
   ЭМПИРИЧЕСКИ ПОДТВЕРЖДЁННУЮ (build+run) утечку из §0 — которая шире №337,
   бьёт по любой `value`-записи с полем `[]T` в любой из пяти пакетных
   реп (десятки кандидатов по B.1/B.2).
3. **(косметика, по желанию)** линт «`type X(...)`, все поля которого —
   голые указатели, без `#share`/иной пометки — подозрительно похоже на
   непровожаемый хэндл»; не обязателен, поскольку п.0 показал, что
   непомеченный хэндл и так блокируется на копировании (это уже
   консервативнее, не опаснее).

**Что это даёт:** закрывает СТРОГО БОЛЬШЕ подтверждённого, живого риска
(находка `[]T`, которая шире 23 хэндлов), чем и «унификация», и
первоначальная «23 хэндла → линейность» ветка плана 248, — при на порядки
меньшей цене: ноль миграции корпуса, ноль нового синтаксиса, два локальных
патча в уже существующем, покрытом conformance-тестами канале (образец
масштаба — сам `m_ro_launder_m_field_launder_ident_neg.nv`, который уже
зелёный для 1-хопового случая).

**Что это НЕ даёт**, в отличие от полной унификации:
- не убирает саму двусмысленность `ro b = a` для типов, которые ПРОХОДЯТ
  `is_fully_stack_value` (там копия по-прежнему тихая, просто она и
  сегодня безопасна — независимость гарантирована структурно, а не
  дисциплиной автора, так что это не тот же риск, что у `[]T`-дыры);
- не даёт единого «одно правило без исключений» нарратива для документации/
  обучения — вместо этого остаётся объяснение «здесь дешёвая implicit-копия,
  потому что тип полностью стековый, а здесь эту копию заблокирует чекер»,
  что требует знания предиката, а не одной фразы «связывание = второе имя».

## ВЕРДИКТ

**Не унифицировать (не делать полный флип умолчания). Сделать прицельную
правку из §E: расширить field-launder до N хопов + нормализовать `[]T` в
`is_fully_stack_value`.**

**Почему.** Ключевой факт, ради которого затевалось это окно, оказался
неверным как посылка: искомая «единая унификация» **уже в основном
реализована** — не как декларативный флип, а как работающий, покрытый
conformance-тестами механизм (`D230` Clone + `M-ro-launder-via-mut-binding`
+ `is_fully_stack_value` + `#share`-исключение). Пробы показали, что
непомеченный разделяемый хэндл через прямую field-projection **уже
блокируется сегодня** — сценарий №337/№334 не дыра в компиляторе, а
намеренное `#share`-исключение, работающее как задумано. Реальных, ныне
эксплуатируемых дыр этим окном найдено ДВЕ, обе узкие и обе НЕ про 23
хэндла: цепочки длиннее одного хопа (задокументированный
false-negative) и рассинхрон `[]T`-сахара с `Vec[T]` в предикате
(эмпирически подтверждён build+run — реальная утечка мутации через
«копию»). Обе чинятся точечно в уже существующем, специально для этого
написанном канале.

Полная унификация, в свою очередь, стоила бы дорого по трём независимо
подтверждённым основаниям: (1) сравнение языков (§C) не даёт НИ ОДНОГО
прецедента GC-языка, комбинирующего «выбор value/reference по типу» с
«обязательный `.clone()` даже для value» — придётся проектировать
эргономику с нуля, без чужого опыта; (2) население типов, которые пришлось
бы аудировать на `#copy`, — не 23, а ~317 деклараций по всему корпусу
(§B.1), из которых заметная доля (§B.2, оценка 60-70% в доменных пакетах) —
уже сегодня НЕ проходят implicit-copy безопасно, то есть унификация не
столько даёт новую безопасность для них, сколько переносит СУЩЕСТВУЮЩУЮ
(правкой предиката получаемую бесплатно) защиту в другую форму синтаксиса;
(3) риск для эргономики builder-цепочек (`mut @` идиома, §D.2) реален по
конструкции языка, хотя ни одного живого случая форк-паттерна в пяти
проверенных репах не найдено — это не нулевой риск, а неизмеренный (см. §B.4).

**Чего не хватило измерить, честно:**
- Сколько сайтов `mut b = a` (оба уже `mut`, вне ro→mut-коэрсии) реально
  полагаются на физическую независимость `b` — нужен семантический проход
  (типизированный AST-грепп или патч чекера с телеметрией), не выполнено
  из-за бюджета окна.
- Точная доля из ~209 non-std `value`/tuple деклараций, дисквалифицированных
  `is_fully_stack_value` — посчитано вручную только для 21 типа `nova-http`
  (13/21 определённо или вероятно дисквалифицированы), для `nova-polaris`
  (60 типов) и `nova-bignum`/`nova-compress` — не разобрано построчно.
- Причина, ПОЧЕМУ парсер/резолвер типов представляет `[]T`-сахар иначе, чем
  `Vec[T]` для целей `is_fully_stack_value` конкретно (эмпирически показано
  ЧТО происходит, не установлено чтением кода резолвера ГДЕ именно `[]T`
  сворачивается/не сворачивается в каноническую форму до предиката —
  для реализации фикса это нужно будет найти, для вердикта — не требовалось).
