# 172.15 Ф.1 — фикстуры периметра `__sret` и пробы «подсунь негодное»

Набор из окна `p172-sret` (ветка `p172-sret`). Держится здесь, а не в
`spec_tests/conformance`, по прямой причине: **conformance проверяет поведение
и не видит ABI** — `bytes()` работал правильно и медленно, и ни один тест
этого не замечал (формулировка плана 172.15, Ф.3). Превращение этого набора в
постоянного стража — предмет **Ф.3, которая идёт ПОСЛЕ тега**. До тех пор
набор воспроизводим руками.

## Запуск

```sh
bash docs/plans/wip/172.15-f1-sret-probes/check.sh
```

Скрипт собирает каждую фикстуру (`--keep-artifacts`), читает сгенерированный
`.c` и печатает строку `PASS: N FAIL: M`. Пути к компилятору/GC внутри
скрипта — от worktree `nova-p172sret`; в другом worktree поправить `NOVA` и
`NOVA_GC_*`.

## Что изолирует каждая фикстура

| Фикстура | Ось | Что обязано быть в `.c` |
|---|---|---|
| `f_bytes.nv` | **приёмка владельца** | `bytes__sret`; слот `Nova_Vec____nova_byte _nv_tmp_N = {0}` в кадре вызывающего; проброс `_out` в `[]u8.new`; НИ ОДНОЙ `nova_alloc` в цепочке |
| `f1_alias.nv` / `f2_vec.nv` | алиас `[]T` ≡ `Vec[T]` | оба спеллинга дают `Src @view` с `__sret` и **побайтно один** `.c` |
| `f5_unsafe.nv` | прозрачность `unsafe { }` | тело под `unsafe` получает `__sret` и пробрасывает `_out` |
| `f_record.nv` | имя C-типа | НЕ-`Vec` кучевая запись (`Pair`) получает `__sret` и пишет по месту |
| `CONTROL` (внутри `f_bytes`) | контроль | прежний `Leaf`-сайт `Vec[T] @index(r Range)` жив — он работал и ДО 172.15 |

`f2_vec.nv` даёт 2 находки `W_VEC_SPELLING` — это НЕ дефект фикстуры: она
существует ровно затем, чтобы доказать, что запрещённый линтом спеллинг
`Vec[...]` порождает тот же C, что канонический `[]T`.

## Пробы «подсунь негодное» (результаты 2026-08-08)

Каждая проба ломает ОДНУ часть предиката, компилятор пересобирается, `check.sh`
прогоняется, правка откатывается (`git diff` пуст). Базовая линия — `PASS: 13
FAIL: 0`.

| Проба | Что сломано | Итог | Покраснело |
|---|---|---|---|
| P1 | `sret_tail_expr`/`sret_unwrap_tail` — блок НЕ прозрачен | `PASS: 8 FAIL: 5` | `UNSAFE-1/2` + `ACCEPT-1/3/4` (тело `bytes()` и есть `unsafe { … }`) |
| P2 | `sret_canonical_type_name` — алиас неизвестен | `PASS: 6 FAIL: 7` | `ALIAS-1` (спеллинг `[]T`) при зелёном `ALIAS-2` (`Vec[T]`) + зависимые |
| P3 | `sret_phase1_type_admits_out` — назад к `Nova_Vec____` | `PASS: 11 FAIL: 2` | ровно `TYPE-1/2`, всё прочее зелено |
| P4 | `sret_tail_writes_out` — назад к форме `Self { … }` | `PASS: 4 FAIL: 9` | все сайты, добытые свойством; `CONTROL` (прежний `Leaf`) зелен |

`CONTROL` зелен во всех четырёх пробах — каждая ломала то, что метила.
