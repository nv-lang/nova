## Фиксы — первопричины

### B10a (коммит `0ce70bfa2`)

Продюсер: `println`/`print`/`assert`/`debug_assert` — always-Unit компилятор-интринсики
(`extern "nova" fn ... -> ()` в std/prelude/runtime.nv, но `#no_prelude` модули её не
видят — `[panic-assert-intrinsic]`). Материализация Unit в `resolved_types` безусловно
(зеркало codegen-хардкода emit_c ~32213 + panic-assert-intrinsic доктрины).

**Снос НЕ выполнен** — второй, структурно отдельный источник (2 hit, conformance CU):
`assert(...)` в теле `effect Supervisor { on_child_fail(idx, err) { ... } }`
(spec_tests/conformance/standalone/supervisor_escalate_test.nv:77-78). Корень: `f1_expr`'s
`ExprKind::With { bindings, body }` арм рекурсирует ТОЛЬКО в `body`, никогда в
`bindings[i].handler` — НИ ОДИН expr внутри ЛЮБОГО handler-метода не проходит через
`f1_expr` → никогда не попадает в `resolved_types_buf`. Пробел канала для ВСЕХ
handler-literal тел (не B10a-специфичный, потенциально шире 4 интринсик-имён) — новая
ось, вне узкого intrinsic-scheme задания. Documented replay-комментарием у арма.

### B12c (коммит `b0582fe7a`)

ДВА дефекта в цепочке:
1. **Продюсер отсутствовал:** `ChanReader.close_after(Duration)` — компилятор-интринсик
   без .nv декларации (ChanReader вообще не имеет .nv type-decl, определён в nova_rt/*.h).
   Path-форма чекером не аннотировалась. Фикс: `Named{"ChanReader"}` в Channel 2.
2. **Консюмер маскировал продюсер:** `debt_is_generic_stub_c` (emit_c) классифицировал
   `Nova_ChanReader*` как FALSE-POSITIVE «unresolved generic-param stub» — ChanReader
   отсутствует ВО ВСЕХ регистрах, которые функция проверяет (record_schemas/sum_schemas/
   generic_types/opaque_ffi_types), хотя genuinely конкретен. Замер подтвердил: без второго
   фикса продюсер писал верный Channel-2 hit, но консюмер ВСЁ РАВНО проваливался в легаси
   (2→2). Добавлен `RUNTIME_NATIVE_CONCRETE_TYPES` allowlist (зеркало function-local
   `BUILTIN_RUNTIME_TYPES` из emit_module forward-decl skip). После обоих: 2→0.

### B11ag (коммит `<pending>`)

Трафик разложился на ДВА под-класса, оба материализованы:
1. **Instance extern с implicit-Unit возвратом** (`extern "nova" fn Once mut @call_once(...)`
   — без `->`): `resolve_instance_method_return_arity` бейлил на `f.return_type.as_ref()?`
   (None для implicit-Unit). Фикс: `if f.return_type.is_none() { if f.is_external { return
   Some(Unit) } ... }` — гейт на `is_external` для узкого blast-radius.
2. **D289 module-qualified static** (`raw_mem.RawMem.alloc_uncollectable(8)` — nested
   `Member{Member{Ident(mod), Type}, method}`): `infer_method_call_channel_type` бейлил —
   `mod.Type` это namespace, не значение (infer_expr_type=None → нет receiver). Фикс:
   nested-Member арм в f1_expr → `resolve_generic_static_return(Type, method, &[], span)`
   (пустой turbofish; builtins non-generic → `type_args.len()==recv.generics.len()==0`).

### B10c — диагноз (НЕ строится; per-mono-instance ось)

**Задание:** «диагностируй, что value-aware путь знает, чего канал не несёт; фикс=продюсер
→ делай; новая ось → диагноз, НЕ строить».

**Что знает value-aware путь (codegen B10c, `infer_call_ret_c` ~49808 + fn_param_sigs
re-derivation ~32655):** для локально-связанного unannotated light-closure `ro f = |v| v`,
вызванного `f(args)`, при actual-arg типах ≠ nova_int — переинферит ТЕЛО замыкания с
param-override'ами на actual arg C-типы (`|v| v` с uint-аргом → `nova_uint`, не
signed-collapse в int). Источник тела — `unanno_light_clos[name]` (param_names + body).

**Чего канал не несёт и ПОЧЕМУ это новая ось (не продюсер):**
1. **Чекер СОЗНАТЕЛЬНО не аннотирует param'ные unannotated замыкания.** f1_expr
   ClosureLight-арм (types/mod.rs:8861): «param'ные замыкания НЕ аннотируются (гадание
   params=int — ложь)» — только zero-param `|| body` получает Func-тип. Без call-site
   контекста типы параметров неизвестны → чекер честно молчит.
2. **Value-awareness = per-MONO-INSTANCE, а чекер — PRE-MONO пасс.** Ключевое
   (документировано `[M-196.5-b3-unanno-clos-stale]`, emit_c.rs ~32663): re-derivation
   бежит во время эмиссии МОНОМОРФИЗИРОВАННОГО тела метода (`emit_monomorphized_method`,
   lazy worklist-drain). ОДНО исходное call-site `f(x)` внутри generic HOF даёт РАЗНЫЕ
   closure-возвраты для РАЗНЫХ mono-инстансов (U=int vs U=str vs U=uint — по элемент-типу
   инстанса). Чекер видит ТОЛЬКО стёртое (erased) generic-тело ДО мономорфизации — он
   структурно не знает concrete элемент-тип конкретного инстанса.
3. **Канал `resolved_types` keyed по AST `ExprId` — ОДНА запись на исходный call-site,
   общая для ВСЕХ mono-инстансов** объемлющего generic. Он структурно не может нести
   per-(ExprId × mono-instance)-расходящиеся возвраты. Нужна ось
   per-(call-site × mono-instance) — это POST-mono композиция (W1-класс,
   `resolve_instance_call_subst`-территория), ровно «продюсер mono-клонов», который
   задание волны выносит за скобки («ядро НЕ трогать; за волной продюсера mono-клонов»).

**Дополнительно (побочный риск, не строим):** сам codegen-путь B10c уже
хрупок/known-buggy — `unanno_light_clos` keyed ТОЛЬКО по bare-имени параметра ГЛОБАЛЬНО
на весь compile (не per-call-site, не per-mono), перезаписывается последним связыванием
того же имени → наблюдалась тихая miscompilation (`.map()` подхватил stale-entry,
мистипизировал `w.name` U=str как receiver-тип). Гейт `sig_looks_like_bootstrap_default`
её лишь ограничивает. Реплицировать это в чекер = реплицировать баг ИЛИ строить
корректную per-mono-instance инфраструктуру (= новая ось).

**Вердикт:** B10c оставлена. Закрывается вместе с продюсером mono-клонов (W1 POST-mono
композиция), когда Stage-D дойдёт до `resolve_instance_call_subst`-зоны. НЕ строил (по
заданию).

## Инфра-инцидент сессии (для будущих волн)

Машина под тяжёлой конкуренцией (несколько агентов). Симптомы: фоновые (`&`/
run_in_background/nohup) прогоны nova ПАДАЛИ — детач-контекст не мог spawn'ить
clang (uv_spawn EPERM) → nova крашился за <20с; накопилось **11 осиротевших
nova.exe из nova-174**, съедавших CPU и державших lock на `nova.exe` (ломая
пересборку). Диагностика: `wmic process where name='nova.exe' get ProcessId,
ExecutablePath`; лечение: `taskkill //F //PID <pid>` ТОЛЬКО по своим PID (НЕ
`//IM nova.exe` — убьёт чужих агентов, напр. nova-s2s). Урок: полный conformance
гонять ТОЛЬКО в foreground (блокирующий Bash-вызов, ≤10мин таймаут); фоновый
детач для долгого nova в этом окружении не работает.
