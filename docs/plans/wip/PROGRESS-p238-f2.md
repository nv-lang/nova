# p238-f2 — Ф.8-НОВАЯ, фаза 2: энфорс на границах параллельности

**Окно:** p238-f2, sonnet, ветка `p238-f2`, worktree `d:/Sources/nv-lang/nova-p238f2`.
**Задача:** план 238, раздел «Ф.8-НОВАЯ» — реализовать ЭНФОРС поверх бирки,
которую фаза 1 (`p238-f1`, влита) уже вычисляет для каждой функции/метода:
на точках посева (`spawn`/`detach`/`parallel for`) вызов функции с биркой
Unsafe/Undecided — диагностика; косвенные вызовы — консервативно; диагностика
с обходом назад.

---

## 1. Объём — что покрыто

**Покрыто полностью** (не половинчато — прямые И косвенные вызовы, как
просил бриф):

1. **Точки посева** — `spawn`, `detach`, `parallel for`. `supervised` САМ по
   себе НЕ отдельная точка (измерено: он лишь оборачивает `spawn`-узлы,
   которые уже сеют детей — `parallel for` десугарится в `supervised { for
   { spawn { body } } }`, подтверждено в `types/mod.rs` комментарием на
   месте чек-обхода). Обход — `find_seeds_block`/`find_seeds_expr`
   (`compiler-codegen/src/types/fiber_safety.rs`) — full-tree walk КАЖДОГО
   `Item::Fn`/`Item::Test` тела, находит `Spawn`/`Detach`/`ParallelFor`
   ГДЕ УГОДНО (не только на верхнем уровне), включая вложенные посевы (у
   каждого — своя независимая проверка).
2. **Прямые вызовы.** На каждом посеве — `collect_seed_calls_*` собирает
   ВСЕ вызовы, достижимые СИНХРОННО в теле посева (останавливается на
   ВЛОЖЕННОМ посеве — тот проверяется отдельно, как `own_fiber_call_names_
   expr` уже делает для `#thread_affine`). Резолв цели — через
   `resolved_callees` (канал §0/196, методы покрывает), тег — из карты
   Ф.1. Не-`Safe` → `E_FIBER_UNSAFE_CALL`.
3. **Косвенные вызовы** — консервативно, БЕЗ обхода потока (по букве
   Ф.8-НОВОЙ): нет записи в `resolved_callees` → `E_FIBER_INDIRECT_CALL`,
   безусловно (кроме двух явных, принципиальных исключений ниже —
   белый список каналов и name-фоллбэк, ОБА обоснованы, не «глушение»).
4. **Диагностика — обход назад.** `render_chain`/`chain_terminal_reason`
   следуют по `detail_span` через `calls_unsafe`/`calls_undecided`-звенья
   до терминальной причины (`unguarded_mutation`/`no_body`/`generic`/
   `extern`/`fn_param_in_sig`/`cross_module_callee`), печатают полную
   цепочку `` `A` → `B` → `C` `` — по образцу `E_THREAD_AFFINE_IN_FIBER`.

**Не сужено** — весь запрошенный объём (посев + косвенные + диагностика)
реализован ОДНОЙ волной, без деления на «потом добавим косвенные».

## 2. Ф.2-рефайнменты бирки Ф.1 — обязательные, без них энфорс неюзабелен

Первый прогон энфорса «в лоб» (перевёрнутое умолчание П.2 + транзитивный
граф) дал **катастрофический ложняк**: `nova check std/src` — 33 FAIL
(против базовых 26), `examples/flagship/aggregator` — 37 находок в
маленькой программе, `nova-polaris/src` — **PASS: 0 FAIL: 55** (одна
находка в `background.nv` каскадом ронял ВСЕ 55 файлов, поскольку
`background.nv` транзитивно импортирован почти всюду).

Разобрал КАЖДЫЙ класс до корня (не глушил, чинил ПРИЧИНУ в Ф.1-бирке —
ровно то, что бриф требует: «ложное → уточнить бирку»):

1. **`resolved_callees` не покрывает generic-blanket-методы на примитивах
   и `__array::Elem.new(...)`-конструкторы** (`[]u8.new()`, `1.to_millis()`)
   — измерено: 124 «indirect» на `std/src`, из них РЕАЛЬНО индиректных —
   2. Фикс: name-фоллбэк (`name_index`, уникальное имя) + receiver-aware
      фоллбэк (`type_method_index`, для `Vec[T].new`-формы — при НЕОДНОЗ-
      НАЧНОСТИ идентичности, но ЕДИНОГЛАСНОМ вердикте всех кандидатов,
      берём его; при расхождении — консервативно остаётся indirect).
      124 → 7 (оставшиеся 7 — ГЕНУИННО косвенные, напр. `race2[T](a, b)`).
   - Канал `send`/`recv`/`try_send`/`try_recv`/`close_after`/`tick_every`
     — компиляторные builtin'ы БЕЗ `Item::Fn` вообще (подтверждено грепом
     — `ChanReader.close_after`'s собственный комментарий: «via compiler
     builtin, not via this fn»). Узкий allowlist
     (`is_builtin_channel_or_timer_op`) — прямая реализация D446-белого
     списка «концы каналов», а не обход.
2. **`build_fn_index` не мержил `external_registry::builtin_sig_modules()`**
   (в отличие от `build_type_decls`, который это УЖЕ делал для типов) —
   методы `Atomic*`/`Mutex`/`CancelToken` из `sync.nv` были невидимы для
   графа Ф.1 вообще → «belongs to a DIFFERENT compile unit» ДАЖЕ на
   `std/src` сам на себя. Фикс — зеркалю `build_type_decls`'ый мердж.
3. **`no_body` extern-метод на `#share`-верифицированном ресивере
   (`CancelToken.cancel`/`.is_cancelled`) блинкет-Undecided** — белый
   список D446 брика 3 существовал НА ТИПЕ, но никогда не спрашивался у
   его extern-методов. Фикс — `is_mut_alias_safe` на ресивер-тип для
   `no_body` INSTANCE-методов → `Safe("share_verified_extern")`.
4. **`no_body` receiverless/STATIC extern с безопасной сигнатурой
   (`assert(cond bool)`, `SocketAddr.loopback(port u16) -> Self`)** —
   блинкет-Undecided, хотя у него НЕТ `@` вообще (нечего проверять на
   `#share`) или это STATIC-конструктор (не `@`, а namespaced free fn).
   Фикс — args-safety проверка (`is_alias_read_safe` — НЕ `is_mut_alias_
   safe`, см. п.6) на все параметры + возврат; `Self`/`never` — отдельные
   тривиальные случаи (см. п.6).
5. **Generic-функция блинкет-Undecided ДАЖЕ когда тело — чистый арифметический
   лист** (`fn[T Ints] T @to_millis() -> Duration => { nanos: (@ as i64)*
   1_000_000 }`) — самый частый живой паттерн в `std` (вся семья `Duration`-
   конструкторов). Фикс — УЗКИЙ: анализирую тело generic-функции, и ТОЛЬКО
   если ZERO touches И ZERO local_callees (T — инертные данные, ни разу не
   диспетчеризуется) → `Safe("generic_leaf_no_op")`. Функция с ЛЮБЫМ
   вызовом внутри остаётся Undecided — bound-sensitivity НЕ реализована
   (сознательно, план сам называет её «работой первой волны после
   измерения» — не этого окна).
6. **`is_mut_alias_safe` — НЕПРАВИЛЬНЫЙ предикат для параметров, передаваемых
   ПО ЗНАЧЕНИЮ.** Это D415-проверка «безопасно ли АЛИАСИТЬ этот `mut`-
   БИНДИНГ» — фиксирует `Access::Mut` БЕЗУСЛОВНО, из-за чего ЛЮБОЙ голый
   скаляр (`bool`/`str`/`int`) отказывался («a writable scalar cell aliased
   across fibers IS the race» — комментарий `share_check.rs`), даже когда
   это ordinary by-value параметр без всякого алиасинга (`assert(cond
   bool)`). Правильный предикат — `is_alias_read_safe` (`Access::Read`) —
   он уже существует в `share_check.rs`, просто не был здесь применён.
   `mut T`-параметр исключён вручную (share_rec's `TypeRef::Mut`-ветка
   ПРОЗРАЧНО пробрасывает `access`, не смотрит на обёртку САМА — семантика
   mut/ro там приходит от БИНДИНГА на месте захвата, а не от аннотации
   сигнатуры, так что для параметров это надо решать отдельно).
7. **`record_call_edge` не различал «touch на `@`/mut-param» (наблюдаемо
   извне) от «вызов mut-метода на ЛОКАЛЬНОМ, не-эскейпящем значении»**
   (`Path.join_path`'s `out.push(...)`, где `out` — чисто локальный `mut`-
   аккумулятор) — Pass B УЖЕ исключает прямое присваивание такому
   аккумулятору из touch («местный mut-аккумулятор — не touch», модуль-док
   Ф.1), но НЕ исключал METHOD CALL на нём — `Vec.push`'а собственная
   бирка (Unsafe, т.к. трогает СВОЙ `@`) транзитивно ядовила КАЖДОГО
   вызывающего, у кого receiver ПРОВЕРЕННО локален. Фикс — при
   `place_root(obj) == None` (не `@`/не mut-param) И резолвнутый target —
   `mut @method` в ЭТОМ ЖЕ модуле, ребро НЕ добавляется в `local_callees`.
8. **`touch_share_ok` знал только брик 3 (`#share`-синхронизация), не
   брик 2 (`consume`-линейность)** — `mut`-параметр LINEAR-типа
   (`TcpStream`/`TlsStream` — оба явно `consume`, D415's собственные
   примеры) трогающий СВОЙ `@` (`.read()`/`.write()`) блинкет-Unsafe —
   хотя единоличное владение (D131/consume) — РОВНО то, что делает
   пересечение fiber-границы безопасным в первую очередь (это то, что
   санкционирует `spawn consume c { .. }`). Фикс — `touch_share_ok`
   ДОПОЛНИТЕЛЬНО принимает `td.consume == true` на именованном базовом
   типе (не только `#share`).

**Измеренный эффект рефайнментов** (`std/src` — тот же файл-набор):
до Ф.2-рефайнментов — `E_FIBER_UNSAFE_CALL`=322 `E_FIBER_INDIRECT_CALL`=124,
33 FAIL; после — `E_FIBER_UNSAFE_CALL`=151 `E_FIBER_INDIRECT_CALL`=7,
**29 FAIL** (3 сверх базовых 26 — см. §4). `examples/flagship/aggregator`
— 37 → 36 находок (остаток — п.9 ниже, ОТДЕЛЬНЫЙ, неисправленный класс).

## 3. Незакрытый (честно) класс — `mut []T`/`mut`-скретч-буфер параметр

`nova-tls`'s `flush_out(mut tcp TcpStream, session CTlsHandle, mut scratch
[]u8)` — `tcp` теперь безопасен (п.8 выше), но `scratch []u8` — ОБЫЧНЫЙ
изменяемый массив-параметр, НЕ linear, НЕ `#share`. Тип-система НЕ даёт
статического доказательства, что этот конкретный `scratch` — эксклюзивно-
владеемый per-fiber буфер (а не разделяемый) — это соглашение
использования, а не свойство типа. Это НАСТОЯЩИЙ, ожидаемый предел
модели (Ф.8-НОВАЯ П.3 буквально требует один из трёх брикс — здесь их нет
ни одного), а НЕ имплементационный баг — чинить его значило бы придумывать
ЧЕТВЁРТЫЙ брик (что-то вроде «эксклюзивно-владеемый scratch-буфер»), чего
план НЕ просил и что рискует незвучностью, если сделано наспех. Остаётся
как измеренная, задокументированная граница — кандидат для Plan 248 или
отдельного будущего окна.

**Полностью аналогичный класс** — генерик-функции-«диспетчеры», принимающие
ПРОИЗВОЛЬНОЕ вызываемое от caller'а (`race2[T](a fn()->T, b fn()->T)` в
`std/src/concurrency/cancellation.nv`; `background.nv`'s task-queue
(`task()` на элементе очереди); `examples/flagship`'s route-dispatch
(`handler(raw)`)). Это ИМЕННО D446 §4 «непрямые вызовы» — target
ПРИНЦИПИАЛЬНО не определим статически без типизированного брика
безопасности НА параметре (план 248, ещё не реализован). Ловится
корректно (`E_FIBER_INDIRECT_CALL`) — но у СТАРОГО кода, который эти
диспетчеры уже используют, нет пути стать «доказуемо безопасным» без
Plan 248.

> **D446 §5 (Ф.2-амендмент).** Энфорс на точках посева (`spawn`/`detach`/

> поле функционального типа — `E_FIBER_INDIRECT_CALL`, безусловно (D446

> терминальной причины.

> потока» — Ф.6 п.4), ЛИБО отдельного брика «эксклюзивно-владеемый scratch»
> — ни то ни другое не реализовано этим окном.
