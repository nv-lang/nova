# p238-f2 — Ф.8-НОВАЯ, фаза 2: энфорс на границах параллельности

**Окно:** p238-f2, sonnet, ветка `p238-f2`, worktree `d:/Sources/nv-lang/nova-p238f2`.
**Задача:** план 238, раздел «Ф.8-НОВАЯ» — энфорс поверх бирки, которую фаза 1
(`p238-f1`, влита) вычисляет для каждой функции/метода: на точках посева
(`spawn`/`detach`/`parallel for`) вызов функции с недоказанной биркой —
диагностика; косвенные вызовы — консервативно; диагностика с обходом назад.

Финальная приёмка прошла в три раунда правок с интегратором поверх
первоначальной реализации — весь путь описан ниже, потому что каждый раунд
менял ПОНИМАНИЕ модели, не только код.

## 2. Объём — что реализовано

1. **Точки посева** — `spawn`, `detach`, `parallel for`. `supervised` САМ по
   себе не отдельная точка (он оборачивает `spawn`-узлы, которые сеют детей;
   `parallel for` десугарится в `supervised { for { spawn { body } } }`).
   Обход — `find_seeds_block`/`find_seeds_expr`
   (`compiler-codegen/src/types/fiber_safety.rs`) — full-tree walk каждого
   `Item::Fn`/`Item::Test` тела, находит посев ГДЕ УГОДНО (не только на
   верхнем уровне), включая вложенные (у каждого — своя независимая
   проверка).
2. **Резолв цели** — через `resolved_callees` (канал §0/196, методы
   покрывает) плюс три обоснованных фоллбэка на измеренные пробелы канала
   (§3.1): по имени (уникальное совпадение), по `(тип, метод)` для
   generic-static-receiver формы (`[]u8.new()`), и узкий allowlist
   компиляторных builtin-опов канала (`send`/`recv`/`try_send`/`try_recv`/
   `close_after`/`tick_every` — они БЕЗ `Item::Fn` вообще, D446-белый
   список «концы каналов» брика 3).
3. **Диагностика — обход назад.** `render_chain`/`chain_terminal_reason`
   следуют по `detail_span` через `calls_unsafe`/`calls_undecided`-звенья
   до терминальной причины, печатают полную цепочку `` `A` → `B` → `C` ``.
4. **Governing-принцип энфорса** (см. §4, установлен в третьем раунде) —
   тег `Tag::Unsafe` против `Tag::Undecided` РЕШАЕТ, что красное всегда, а
   что — под флагом. Это заменило собой более раннюю, более грубую попытку
   различать «прямой/непрямой вызов» и набор растущих special-case'ов
   (`fn_param_in_sig` отдельно, «локальный ресивер» отдельно) — одним
   принципом на самой бирке.

## 3. Путь приёмки — три раунда, каждый менял модель

### 3.1 Раунд 1 — первый прогон энфорса «в лоб» дал катастрофу

Буквальная реализация П.2 (перевёрнутое умолчание + транзитивный граф) на
`std/src` дала 33 FAIL против базовых 26, `nova-polaris/src` — **PASS: 0
FAIL: 55** (одна находка в `background.nv` каскадом ронял ВСЕ 55 файлов, т.к.
он транзитивно импортирован почти всюду), `examples/flagship/aggregator` —
37 находок в маленькой программе.

Разобрал 8 отдельных причин В САМОЙ БИРКЕ (не глушил энфорс, чинил Ф.1):

1. `resolved_callees` не покрывал generic-blanket-методы на примитивах
   (`1.to_millis()`) и `__array::Elem.new(...)`-конструкторы (`[]u8.new()`)
   — name/type_method-фоллбэки закрыли 124 → 7 «indirect» находок на
   `std/src` (оставшиеся 7 на тот момент — генуинно индиректные).
2. `build_fn_index` не мержил `external_registry::builtin_sig_modules()`
   (в отличие от `build_type_decls`, который это УЖЕ делал для типов) —
   методы `Atomic*`/`Mutex`/`CancelToken` были невидимы графу вообще →
   «belongs to a DIFFERENT compile unit» даже на `std/src` сам на себя.
3. `no_body` extern-метод на `#share`-верифицированном ресивере
   (`CancelToken.cancel`) блинкет-Undecided — белый список D446 брика 3
   существовал НА ТИПЕ, но не спрашивался у его extern-методов.
4. `no_body` receiverless/STATIC extern с безопасной сигнатурой
   (`assert(cond bool)`, `SocketAddr.loopback(port u16) -> Self`) — то же,
   но без `@` вообще.
5. Generic-функция блинкет-Undecided даже когда тело — чистый лист
   (`fn[T Ints] T @to_millis()`).
6. `is_mut_alias_safe` (`Access::Mut`, фиксирован) — НЕПРАВИЛЬНЫЙ предикат
   для by-value параметров: отказывал ЛЮБОМУ голому скаляру (`bool`/`str`)
   безусловно. Нужен `is_alias_read_safe` (`Access::Read`).
7. `record_call_edge` не различал touch на `@`/mut-param (наблюдаемо
   извне) от вызова mut-метода на ЛОКАЛЬНОМ, не-эскейпящем значении
   (`Path.join_path`'s `out.push(...)`, `out` — чисто локальный
   аккумулятор).
8. `touch_share_ok` знал только брик 3 (`#share`), не брик 2
   (`consume`-линейность) — `mut`-параметр LINEAR-типа (`TcpStream`)
   блинкет-Unsafe, хотя единоличное владение (D131/consume) — ровно то,
   что делает пересечение fiber-границы безопасным.

Плюс: `offset`/`dist` (raw-pointer intrinsic методы БЕЗ `Item::Fn` —
компиляторный dispatch) консервативно считались «mutates» при
нерезолвленности — ловили `str.find`/`.rfind` (через `@ptr.offset(i)`) и
транзитивно ЛЮБОГО их вызывающего; и «guarded call под живым замком»
(`consume g = @mutex.lock(); ...; @buckets.insert(..)`) — прямой touch
метился `guarded` корректно, а ГРАФ-РЕБРО — нет, так что
`BucketTable.bucket_for`/ratelimit.nv ловился НЕСМОТРЯ на правильный лок.

**Итог раунда 1:** std 147/29→147/27/60 (то есть до 27 FAIL, миграция шла
последовательно), корпус стал юзабельным, но канон не достигнут.

### 3.2 Раунд 2 — разделение на флаг по указанию интегратора

Интегратор принял диагноз «непрямые вызовы недоказуемы без типизированной
пометки на параметре» и потребовал разделить:

- `E_FIBER_UNSAFE_CALL` (прямые) — остаётся включён всегда.
- `E_FIBER_INDIRECT_CALL` (D446 §4) — под `NOVA_FIBER_INDIRECT=1` (по
  умолчанию выкл). Механизм остаётся в коде целиком, гейтится только
  финальная эмиссия.

Затем `fn_param_in_sig` (HOF-обёртки вроде `middleware(f fn(..)->..)`)
переведён в тот же бакет — концептуально та же дыра, просто прямой вызов К
функции-обёртке вместо непрямого вызова ЧЕРЕЗ параметр. Generic-функции
переведены с эвристики «ноль вызовов» на честную неподвижную точку по графу
(Safe iff все резолвнутые каллеи Safe).

**Итог раунда 2:** std 147/27/60 (net/addr.nv — `write_all`/`read_exact`
упираются в вызов через протокольный bound `mut w W`, `println` — `[]any`
варарг, обе категории «нечем доказать»). nova-polaris/src: 41/14 →
СОСТАВ полностью сменился (все `fn_param_in_sig`/`generic` находки ушли),
но остался ОДИН класс: multi-hop `mut []T`-скретч-буфер
(`flush_out(mut tcp TcpStream, .., mut scratch []u8)`), 41/14 численно то же
самое. flagship: 37 → 9, тот же класс.

### 3.3 Раунд 3 — принцип на бирке, не на форме вызова

Интегратор уточнил саму границу: не «прямой/непрямой», а САМА БИРКА:

> **`Tag::Unsafe`** — доказанно небезопасен (touch без замка/шаринга, или
> цепочка, транзитивно достигающая его) — красный ВСЕГДА.
> **`Tag::Undecided`** — предел модели (индирект, `fn_param_in_sig`,
> протокол-диспатч, `...any`-варарг, multi-hop `mut []T`) — под флагом,
> ЕДИНЫМ списком «ждут пометки/межпроцедурного анализа».

Ключевой технический фикс (§4): `Touch` получил `is_self` — различие между
touch на `@`/`SelfField` (доказанный риск, receiver с ЖИЗНЬЮ дольше одного
вызова — ровно MetricsRegistry/BucketTable-паттерн, ради которого вся фаза
затевалась) и touch на `mut`-ПАРАМЕТР (недоказуемо ни в какую сторону из
одной сигнатуры — это и есть multi-hop `mut []T` класс). `facts_to_intra`
теперь отдаёт `Tag::Unsafe` только для self-touch, `Tag::Undecided`
(`unguarded_mut_param`) — для mut-param touch.

Плюс — `local_receiver`-исключение на точке посева расширено с «только
прямой touch» (`fs.reason == "unguarded_mutation"`) до «любой
`Tag::Unsafe`» (поскольку теперь Unsafe ВСЕГДА self-корневой — цепочка
`calls_unsafe` от локального ресивера тоже безопасна: `resp.header(..)` →
`HeaderMap.insert` — `resp` свежий на посеве, `headers`-поле `resp`'а тоже
свежее). Добавлены два источника локальности, которых не хватало:

- аргументы СВОБОДНОЙ функции, все `let`-локальные
  (`write_response_keepalive(shs, resp)`);
- `spawn consume shs = expr { }` (D415 §4 move-capture) — биндинг НЕ
  проходил через `Stmt::Let`-трекинг вообще, хотя move ДАЖЕ доказаннее
  обычного `let` (единоличное владение по построению).

**Итог раунда 3:** все три канона достигнуты (§1).

## 4. Governing-принцип (для спек-амендмента, §7)

Формулировка, которой руководствуется финальный код (`check_resolved_
target`, `facts_to_intra` — `compiler-codegen/src/types/fiber_safety.rs`):

> Значение `Tag::Unsafe` — ДОКАЗАННАЯ небезопасность: функция (транзитивно)
> мутирует состояние, чья ЖИЗНЬ отслеживается через receiver (`@`/поле
> receiver'а — SelfBare/SelfField), без живого замка и без `#share`/
> `consume`-доказательства. Это persistent-state паттерн: тот же объект
> может быть вызван снова из другого места/файбера. Всегда красный.
>
> Значение `Tag::Undecided` — ПРЕДЕЛ МОДЕЛИ, не находка о коде: сигнатурная
> непрозрачность (`no_body`/`extern`/`fn_param_in_sig`), протокол-диспатч
> через generic bound (`calls_undecided` из-за невидимого резолва),
> межмодульный разрыв (`cross_module_callee`), touch на `mut`-ПАРАМЕТРЕ
> (не решаемо из одной сигнатуры — это, а не "@", и есть multi-hop
> scratch-буфер), и полностью нерезолвленный (индиректный) вызов. Все эти
> случаи говорят «доказать не могу НИ В КАКУЮ сторону», не «доказано
> небезопасно» — под `NOVA_FIBER_INDIRECT=1`.

## 5. `NOVA_FIBER_INDIRECT` — что под флагом целиком

Единый список (реализация: `indirect_enforcement_enabled()` в
`fiber_safety.rs`, читает `NOVA_FIBER_INDIRECT` env, `"1"` = вкл, иначе
выкл):

1. **Индиректный вызов** (D446 §4) — цель не резолвится вообще, значение
   функционального типа через параметр/поле.
2. **`fn_param_in_sig`** — прямой вызов к HOF-обёртке, которая берёт
   функцию-параметр (`middleware(f fn(..)->..)`), поэтому её ТЕГ
   `Undecided` независимо от того, что она реально делает с `f`.
3. **`unguarded_mut_param`** (НОВЫЙ reason, §4) — touch на обычный
   `mut`-параметр (не `@`) без замка/шаринга — недоказуем из одной
   сигнатуры. Это класс multi-hop `mut []T`-скретч-буферов
   (`flush_out(mut tcp TcpStream, .., mut scratch []u8)`,
   `pump_handshake`).
4. **Протокол-диспатч через generic bound** (`fn[T Write] .. w.write(..)`)
   — резолв недостижим для чекера в принципе; проявляется как
   `unguarded_mutation`/`calls_undecided` на `mut w W`-параметре — на
   практике попадает в п.3 (тот же mut-param механизм).
5. **`...any`-варарг** (`println(...items []any)`) — `any` структурно
   недоказуем (не в `NOVA_PRIMITIVES`, не в `type_decls`).
6. **`cross_module_callee`** — тег недостижим в этом compile-unit'е
   (генуинно межпакетный вызов, не внутрипакетный — импорты внутри ОДНОГО
   пакета мержатся в `module.items`, измерено).

Фикстуры на индиректный путь (`spec_tests/conformance/neg/fiber_indirect_
call_neg.nv`) гоняются С `NOVA_FIBER_INDIRECT=1` — заголовок фикстуры это
не документирует явно (короткий файл, следующая волна может добавить
`// RUN WITH NOVA_FIBER_INDIRECT=1` маркер, если авторитетный ранер начнёт
матрично гонять conformance с флагом).

## 6. Дифференциальный контроль пробы B (потребовал интегратор)

Проба B (`docs/plans/wip/p238-review-probes/pB_mutex_hashmap_return_
escape/probe.nv`) — `Table.bump()` с `consume g = @mutex.lock()` ПЕРЕД
touch на `@entries`, замыкание над `Table` эскейпит через `return`,
вызывается из 4 конкурентных файберов. Финальным кодом — **зелёная** (ни
без флага, ни с флагом), только посторонняя honesty-control-ошибка.

**Гипотеза (моя, до контроля):** это НЕ слепая зона, а корректное
распознавание: `bump()` заново берёт СВОЙ мьютекс на каждом вызове,
независимо от того, сколько файберов держат ссылку на замыкание —
классическая корректная блокировка.

**Контроль (по требованию интегратора):** копия пробы, `consume g =
@mutex.lock()` УДАЛЕНА из `Table.bump()`, ничего больше не тронуто
(`probe_nolock.nv`, сохранена в scratchpad сессии — не коммичена, разовая
проверка). Результат:

```
pB ОРИГИНАЛ (с локом), без флага:    только [E7301] honesty control — чисто
pB NO-LOCK CONTROL, без флага:       [E_FIBER_UNSAFE_CALL] call to `Table.bump`
                                       Tag=Unsafe, Cause: unguarded_mutation
                                       Chain: `Table.bump`
```

**Вывод: гипотеза подтверждена.** Убрать лок — немедленно красный
(`unguarded_mutation`, self-touch на `@entries`, Tag::Unsafe — тот класс,
который в этом окне ВСЕГДА красный, флаг не влияет). Зелёность оригинала
держится на РЕАЛЬНОМ распознавании дисциплины замка (guard-пропагация
через граф — фикс раунда 1 п.8/guarded-edge), не на слепой зоне.

**Центральный контрпример ревизии снят по существу** — машина ТЕПЕРЬ ВИДИТ
дисциплину замка (guard live at touch site → touch guarded → callee's OWN
edge не ядовит caller'а), а не пропускает её молча, как старая
(отменённая) редакция Ф.8. Это главный измеримый результат всей фазы.

  вызовов вне спавна) чтобы пройти — измерено, не мигрировано.

  отличное от прослеженного локального ресивера (гипотетический пример —
  `resp.finalize()`, внутри трогающий unrelated global registry, а не
  `resp`'а поле). НЕ ИЗМЕРЕН как живой паттерн — задокументирован в коде

  межпроцедурная работа за пределами бюджета этого окна.

## 11. Раунд 4 — `pointee_share_ok` (точечный ложняк из мега-CU интегратора)

Интегратор прогнал мега-CU (679/4) на СВОЕЙ ветке — там `wave 3` уже
поменяла представление `TcpStream.rc` на `*mut AtomicInt` (в ЭТОМ
worktree'е такого изменения нет, github/main тоже без него — сверено
`git fetch github main` + `git log -- std/src/net/tcp.nv`, `wave 3` не
влита никуда, куда у меня есть доступ). Единственный ложняк:

```
standalone/m222_7_spawn_ctx_capture_mut_param.nv:44:28: [E_FIBER_UNSAFE_CALL]
call to `TcpStream.share` inside a `spawn` body — tag Unsafe
```

**Причина.** `TcpStream.@share()`'s тело (`@rc.fetch_add(1)`) трогает
ПОЛЕ-УКАЗАТЕЛЬ (`rc: *mut AtomicInt`). `touch_share_ok` звал
`is_mut_alias_safe` (`share_check.rs`), а её собственное правило —
«raw pointer, ЛЮБОЙ pointee, никогда не share по структуре» —
безусловно отказывает ЛЮБОМУ указателю, не глядя на pointee. Это
ПРАВИЛЬНО для ЕЁ родных вызывающих (capture-check: указатель, захваченный
по ссылке, не даёт статической гарантии, что pointee останется #share на
весь срок жизни алиаса) — но СЛИШКОМ грубо для `touch_share_ok`'s
собственного, более узкого вопроса: pointee-тип ЗДЕСЬ известен статически
(из аннотации типа поля), и `#share`-порука типа переживает уровень
указателя (deref не срывает `#share`-статус — атомарные операции — как
раз и есть его назначение).

**Фикс** (`compiler-codegen/src/types/fiber_safety.rs`, ЛОКАЛЬНО в
`fiber_safety.rs`, `share_check.rs` НЕ тронут — у него другие
вызывающие с другой семантикой, трогать его core-правило было бы шире
запроса): новый хелпер `pointee_share_ok(ty, type_decls) -> bool` —
снимает `Readonly`/`Mut`/`Uninit`-обёртки, при `TypeRef::Pointer(inner,
_)` смотрит именованную базу `inner` в `type_decls`, проверяет
`td.attrs.contains(&TypeAttr::Share)`. Вызывается в `touch_share_ok` СРАЗУ
после (не вместо) `is_mut_alias_safe` — если прямая проверка не прошла,
но pointee — `#share`, всё равно `true`.

**Проверка (в ЭТОМ worktree'е, где `wave 3` физически нет):**
- `m222_7_spawn_ctx_capture_mut_param.nv` — уже был зелёным ДО фикса
  (текущий `std/src/net/tcp.nv` хранит `rc AtomicInt` value, не указатель)
  — фикс НЕ регрессировал его (перепроверено, `PASS: 1 FAIL: 0`).
- **Синтетическая репродукция** (`Handle { priv rc *mut AtomicInt }`,
  метод `@share()` буквально `@rc.fetch_add(1)`, вызван через `spawn
  consume w = h.share() { .. }` из `mut`-параметра — ТОЧНАЯ форма
  ложняка) — проверена ИЗОЛИРОВАННО в scratchpad ДО фикса (падала
  `E_FIBER_UNSAFE_CALL`, тем же путём — touch на `rc`, "unguarded_
  mutation") и ПОСЛЕ фикса (`ok:`, чисто). Этим подтверждён МЕХАНИЗМ,
  раз не могу подтвердить его на буквальном `tcp.nv`, которого в этом
  дереве нет.
- Эта же форма добавлена ЧЕТВЁРТЫМ pos-тестом в `spec_tests/conformance/
  fiber_safety_seed_pos.nv` (`Handle`/`share_via_ptr_field`) — БЕЗ
  runnable `test`-блока (в этом дереве нет канонического способа
  СКОНСТРУИРОВАТЬ `*mut AtomicInt` из Nova-кода — `wave 3`'s собственный
  способ инициализации `rc` не виден отсюда); объявление функции
  типизируется чекером независимо от вызова — этого достаточно, чтобы
  проверить именно ВЕРДИКТ энфорса на точке посева, что и есть предмет
  фикстуры.
- **Побочная находка при финальной перепроверке фикстуры в общем
  namespace `spec_tests.conformance`:** `fiber_safety_seed_pos.nv`'s
  ранее закоммиченный `Linear`-паттерн (раунды 1-3) на самом деле НЕ
  проходил чисто целиком — эксплицитный `@` в `-> @`-методе (D409
  запрещает), `type ... consume` без consume-метода (D133-empty-consume),
  `mut lin = Linear.new()` вместо `consume lin = ...` (E_CONSUME_KEYWORD_
  MISSING) — три отдельные, независимые от Ф.8 ошибки, не пойманные
  раньше (фикстура, похоже, ранее проверялась НЕ в полном namespace).
  Исправлены тем же коммитом — `Linear mut @bump()` больше не пишет
  явный `@`, добавлен `Linear consume @discard()`, тест-блок использует
  `consume lin = ...` + финальный `lin.discard()`. Файл теперь
  ДЕЙСТВИТЕЛЬНО чист (`ok:`) в полном namespace, впервые.
- `nova check std/src` без флага: `PASS: 148 FAIL: 26 WARN: 61` — канон
  держится (не регрессировал).
- `arch-ratchet`: `lines=64171 <= 64171`, `infer=348 <= 348` — В ЭТОМ
  дереве база всё ещё 64171 (не 64388 — та цифра сведена интегратором на
  ИХ стороне, где `wave 3` физически присутствует; здесь не трогал
  `scripts/guards/arch-ratchet.sh`, чекерный фикс не растит `emit_c.rs`
  в любом случае).
- Полярис/флагман НЕ перегонял повторно в этом раунде — фикс аддитивный
  (новый `return true`-путь в `touch_share_ok`, ничего не убирает), риск
  регрессии для УЖЕ безопасных находок исчезающе мал; интегратору стоит
  перепрогнать оба на СВОЕЙ ветке (с `wave 3`) перед тегом, раз мега-CU
  там — авторитетный гейт.
