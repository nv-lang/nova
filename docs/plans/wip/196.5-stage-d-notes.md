## 1. Терминал 1 — `infer_method_level_return_for_sum` — ИЗМЕРЕНО, НЕ ТРОНУТО

**Гипотеза задания:** заменить тело на channel-first (`node_substs`/`resolved_types`) с
CC-ERROR fallback'ом, снять caller-ветки при 0 расхождений.

**Что сделано:** добавлена ВРЕМЕННАЯ channel-first преамбула (pre-seed `subst_slots` из
`node_substs[call_id]`, early-exit при полном покрытии всех `fn_decl.generics`, зеркалируя
Stage-C2 B2-паттерн) + временный трейс `NOVA_TRACE_MLRFS_CHANNEL`. Прогон debug-бинаря по
ВСЕМ 4 корпусам (conformance + std/src/collections + std/src/data):

```
[MLRFS-HIT] sum=Option method=unwrap resolved=false
[MLRFS-HIT] sum=Option method=map    resolved=true
[MLRFS-HIT] sum=Result method=unwrap resolved=false
[MLRFS-HIT] sum=Result method=ok     resolved=true   (std/src/data)
```

**[MLRFS-CHANNEL-HIT] — 0 (ноль) на всех 4 прогонах**, для ВСЕХ traffic-троек. `node_substs`
никогда не покрывает ни один сайт, реально достигающий этой функции.

**Структурное объяснение (почему 0, не просто «сегодня 0»):** любой вызов, доходящий до
`infer_call_ret_c` (и значит, до `infer_method_level_return_for_sum`), уже провалил
Channel-2 (`resolved_types[call.id]`) на уровне диспетчера `infer_expr_c_type` — тот же чекер-
пасс и тот же гейт-условие (`callee.generics` полностью резолвлены) пишет ОБА канала
(`resolved_types` и `node_substs`) в ОДНОМ блоке (196.5 §6.2). Если `resolved_types` не написан
для call-site — `node_substs` для него тоже не написан почти наверняка (тот же subst, та же
причина отказа). Попадание в этот легаси — само по себе доказательство, что канал НЕ мог
помочь именно здесь.

**Решение:** код-правка ОТКАЧЕНА (`git checkout --`), рабочее дерево вернулось к базе БЕЗ
изменений (соответствует методологии Stage-C/Stage-C2: измерить временной инструментацией,
откатить при неподтверждённой гипотезе). Caller-ветки (B11q/B11r) НЕ трогались — реальный,
живой трафик (Option.map/unwrap, Result.unwrap/ok) идёт через легаси-тело, снятие сломало бы
рабочий код. Функция остаётся полностью легаси (как и задокументировано в
`196.5-perd-d52-verification.md`), не read-only регион на будущее.

## 3. Терминал 3 — трейс-свип `infer_call_ret_c` (реестр 196.2)

### 3.1 Метод

`NOVA_TRACE_ICR=1`, debug-бинарь, по 4 корпусам (conformance, std/src/collections,
std/src/data, std/src/net — как требует задание для 0-hit определения; гейт после каждого

line-decrease per атом; НЕ трогались. Остаётся **14 реальных кандидатов**.
