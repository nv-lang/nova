# [M-boehm-large-buffer-retention-fiber-reuse] — диагноз + дизайн фикса

**Роль волны:** разведка с доказательным диагнозом (opus). Worktree
`d:/Sources/nv-lang/nova-boehmret`, ветка `p-boehmret`. В main НЕ мёржить.

## TL;DR

- **Гипотеза «conservative false-positive через переиспользуемые fiber-стеки»
  ОПРОВЕРГНУТА** дискриминирующим экспериментом (числа ниже).
- **Настоящий корень — РЕАЛЬНАЯ (не консервативная) утечка в net-слое:**
  `NovaNet2Stream` (и `NovaNet2Listener`/`NovaNet2Udp`) аллоцируются через
  `nova_alloc_uncollectable` и **никогда не освобождаются**
  (`nova_free_uncollectable` в `net.c` отсутствует вовсе). Uncollectable-память
  Boehm — это **постоянный сканируемый GC-рут**. Стрим хранит указатели на
  ПОСЛЕДНИЕ буферы ввода-вывода: `s->read_ptr` (буфер читателя, `net.c` read-путь)
  и `s->write_req.bufsml[].base` (libuv кладёт туда указатель буфера в `uv_write`).
  Пока стрим жив (а он живёт вечно), эти КБ-буферы удерживаются → рост кучи
  ∝ размеру буфера. Тот же механизм объясняет TLS-slope ∝ TLS_CHUNK
  (TlsStream оборачивает тот же `NovaNet2Stream`).
- **Фикс (прототип, доказан):** обнулять `s->read_ptr` после чтения и
  `s->write_req` после записи (op завершён — libuv буфер больше не нужен).
  **NET-LARGE slope 86740 → ~4820 байт/итер (−94%, 18×), 3 прогона стабильно.**
- Зона задания (`fiber_arena.c` + `alloc_boehm.c`) была выбрана под опровергнутую
  гипотезу — реальный фикс в `net.c` (платформо-нейтрален, `fiber_arena_win.c`
  не тронут).

## Репро (TLS-free, сохранён)

`docs/plans/wip/boehmret-repro/boehmret_slope.nv` — точная калька структуры
`nova-tls/src/stream_leak_test_slow.nv` (supervised + 2×spawn + Channel +
least-squares slope `gc.heap_size()` после `gc.collect()`), но TLS-раунд-трип
заменён на СЫРОЙ TCP-loopback с передачей КРУПНОГО `[]u8` буфера. По контролю
самого маркера («TCP без крупных буферов = плато») дискриминирующая переменная —
РАЗМЕР БУФЕРА, не TLS: нужен только `std.net` (libuv), без mbedTLS-шима.

Три теста: `COMPUTE-LARGE(16384)` (без net), `LARGE(16384)` (TCP-loopback),
`SMALL(64)` (контроль). Прогон на WSL Ubuntu (libgc 1.5.6 + libuv системные),
дерево `~/nova-appeffect-wsl` (spawnctx-fix + libuv), бинарь
`~/nova-appeffect-target/release/nova`, `NOVA_RT_DIR` → патченный nova_rt.
Скрипты прогона — рядом (`wsl_*.sh`).

|---|---|---|---|
| baseline (whole-stack push) | ~600 (плато) | **86740** | ~−8500 |
| `NOVA_GC_STACK_SCAN_KB=2048/256/32/8` | — | 86744/86742/86750/86744 (**без изменений**) | — |
| `NOVA_GC_STACK_SCAN_KB=1` | — | CRASH (пропущены живые руты) | — |

| `NOVA_AUTOARM=0` (кооперативно, без M:N) | −27118 (плато) | **68563** (утечка ЖИВА) | −17926 |

| `NOVA_MAXPROCS=8` | 556 (плато) | **86670** | −9969 |

### Что это доказывает

1. **Fiber-stack/whole-stack-overscan гипотеза ОПРОВЕРГНУТА.** Обрезка
   whole-stack-пуша (терминов а/б/в в `_nova_gc_push_other_roots`) до верхних
   8–2048 КиБ живого окна НЕ меняет slope; лишь на 1 КиБ падает (crash =
   пропущены реально живые руты — значит knob РАБОТАЕТ, но стейл-указатель на
   буфер НЕ в глубокой мёртвой части стека).
2. **Утечка НЕ M:N-специфична и НЕ в стеках воркеров/драйвера.** Под
   `NOVA_AUTOARM=0` (кооперативный режим, нет пула воркеров и их native-стеков,
   нет отдельного драйвер-потока) утечка ЖИВА (68563). Значит термин (б)
   (native-стеки) — не канал.
3. **Утечка требует net-пути.** Compute-only (та же fiber+buffer+GC-форма, но без
   сокет-ввода-вывода) — ПЛАТО во всех конфигурациях. Значит канал — net-слой.
4. **Фикс подтверждает механизм:** обнуление удерживаемых стримом указателей на
   буферы убирает 94% роста.

## Механизм (файл:строка)

- `net.c:421/572/683/1083` — `nova_alloc_uncollectable(sizeof(NovaNet2*))`:
  стрим/листенер — постоянный сканируемый GC-рут.
- `net.c` — **ноль** `nova_free_uncollectable`: структуры не освобождаются никогда
  (`_nn2_stream_close_cb`, `net.c:671`, лишь ставит stage=CLOSED и будит
  ждущих — НЕ free).
- `net.c` read-путь: `s->read_ptr = buf` (перед чтением) НЕ обнуляется после
  завершения (`_nn2_read_cb` пишет только `read_n`) → стрим-рут держит буфер
  читателя.
- `net.c` write-путь: `uv_write(&s->write_req, …, &ubuf, 1, …)` — libuv копирует
  указатель буфера в `s->write_req.bufsml[]`; после `_nn2_write_cb` не очищается →
  стрим-рут держит буфер писателя. Комментарий в коде прямо предполагает «caller
  keeps the buffer alive on its fiber stack» — но стрим переживает кадр и держит
  указатель.

Итог на итерацию (клиент+сервер): 2 стрима × (read-буфер + write-буфер) ≈
4 × 16 КиБ ≈ 64 КиБ + накладные ≈ наблюдаемые ~86 КБ/итер.

## Варианты фикса

### (a) [РЕКОМЕНДАЦИЯ, ПРОТОТИП] Обнулять удерживаемые буфер-указатели по завершении op
`s->read_ptr = NULL` после чтения; `memset(&s->write_req, 0, sizeof)` после записи.
- **Цена:** 2 строки + один memset(≈сотни байт) на op. Ноль на hot-path чтения.
- **Риск:** низкий. Op завершён (park вернулся, callback отработал) — libuv req/буфер
  больше не нужен; следующий op переинициализирует поля. Полный-дуплекс не задет
  (read/write — независимые поля/латчи).
- **Эффект (доказан):** NET-LARGE 86740 → ~4820 (−94%), 3 прогона, без крашей,
  передачи работают.
- **Остаток ~4820/итер** — НЕ buffer-scaling: это утечка самих never-freed
  uncollectable-СТРУКТУР (стрим+листенер на соединение). Отдельный вопрос (b).

### (b) [ПОСЛЕДУЮЩИЙ] Освобождать NovaNet2Stream/Listener на close
`nova_free_uncollectable(s)` в teardown после того, как все ждущие дочитали `s`.
- **Цена:** протокол времени жизни (refcount): `_nn2_stream_close_cb` будит
  ждущих, которые ЧИТАЮТ `s->stage` ПОСЛЕ close_cb — наивный free = use-after-free
  (ровно класс §9 mn-conventions: указатель на структуру пересекает границу
  потока/очереди → counter-based lifetime-wait).
- **Риск:** средний/высокий (гонки close/wake). Нужна аккуратная приёмка.
- **Эффект:** убирает остаточные ~4820/итер (фикс-структурная утечка).

### (c) [АРХИТЕКТУРНО] Сделать NovaNet2Stream COLLECTABLE
`nova_alloc` вместо `nova_alloc_uncollectable`, держа Nova-side handle живым весь
lifetime стрима (иначе GC соберёт под libuv → use-after-free).
- **Цена:** пересмотр модели владения net-хендлами (почему выбран uncollectable:
  «live uv handle must survive GC», `net.c:11`). Крупнее (a)/(b).
- **Риск:** высокий. Не рекомендуется без отдельного плана.

### Не-варианты (проверено)
- Обрезка whole-stack GC-скана (`fiber_arena.c`) — БЕЗ эффекта (гипотеза
  опровергнута). Knob `NOVA_GC_STACK_SCAN_KB` оставлен как диагностика.
- Отключение interior-pointers (`alloc_boehm.c`) — крашит (Nova-срезы зависят).
  Knob `NOVA_GC_NO_INTERIOR` оставлен как диагностика.
- `GC_malloc_atomic` для байт-буферов — не помогло бы: буферы удерживаются
  РЕАЛЬНЫМ рут-указателем (не через свои содержимое-как-указатели); atomic влияет
  на скан СОДЕРЖИМОГО, не на удержание объекта.

## Рекомендация

Применить **(a)** как немедленный фикс buffer-scaling-утечки (доказан, дёшев,
безопасен, Windows-нейтрален). Завести follow-up на **(b)** (остаточная
структурная утечка never-freed стримов) с lifetime-протоколом по §9
mn-conventions. Маркер переименовать по существу (утечка net-слоя, НЕ
fiber-reuse conservative scan).

## Диагностический инструментарий (env-gated, ноль оверхеда по умолчанию)

- `NOVA_GC_STACK_SCAN_KB=N` (`fiber_arena.c`) — обрезка whole-stack GC-пуша до
  верхних N КиБ (диагностика overscan; выявила, что он НЕ канал).
- `NOVA_GC_NO_INTERIOR=1` (`alloc_boehm.c`) — off interior-pointers (диагностика
  амплификации; крашит на срезах).

Оба §12-совместимы (env читается раз, кешируется; default = историческое
поведение).
