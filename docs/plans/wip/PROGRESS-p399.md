# PROGRESS — p399-test-guard (реестр 221.1 №399)

**Окно:** p399-test-guard, worktree `d:/Sources/nv-lang/nova-p399`, ветка `p399-test-guard`, sonnet.
**Задача:** машинный исполнитель для двух самых дорогих правил конвенции тестирования
(`docs/dev/test-conventions.md`, §«Нормы плана 231»): Правило 5 (neg-фикстура на новый
`E_*`/`W_*`-код) и Правило 1 (регресс-фикстура на каждое закрытие строки реестра 221.1) +
бонус — расхождение реестра 221.1 и `backlog-followups.md` по одному и тому же маркеру.

## Что сделано

1. **`scripts/guards/check-test-fixture-coverage.sh`** — новый страж, три проверки:
   - **rule5** (блокирует гейт): в диффе `diff-base..рабочее дерево` по
     `compiler-codegen/**`+`nova-cli/**` ищет НОВЫЕ строковые литералы `"E_*"`/`"W_*"`
     (код считается новым, если его НЕТ в дереве `diff-base` по тем же каталогам — `git grep`
     против diff-base, не просто «встретился в добавленных строках», чтобы не ловить
     переезды/рефакторы). Для каждого нового кода ищет `EXPECT_COMPILE_ERROR`/
     `EXPECT_COMPILE_WARNING`-маркер с этим ТОЧНЫМ кодом в `spec_tests/**`/`std/**` рабочего
     дерева. Нет — красный, печатает имя кода.
   - **rule1** (блокирует гейт): в диффе `docs/plans/221.1-bug-sweep.md` ищет строки
     таблицы, которые СТАЛИ закрытыми (✅ появился в добавленной версии строки, которого не
     было в убранной версии ТОЙ ЖЕ строки по номеру — т.е. именно момент перехода
     открыт→закрыт, а не повторная правка уже закрытой строки). Для каждой такой строки
     проверяет наличие ссылки на файл фикстуры (паттерн `...путь.nv` прямо в этой же
     строке). Нет — красный, печатает номер строки реестра.
   - **registry_backlog_divergence** (БОНУС, №399 п.в; НЕ роняет гейт — WARN): маркер
     `[M-...]`, который в 221.1 — ПЕРВИЧНЫЙ маркер строки со статусом `✅ ЗАКРЫТ...`, а в
     `backlog-followups.md` — ПЕРВИЧНЫЙ маркер записи с биркой `**OPEN` (без закрывающего
     слова в той же строке/шапке). Field-based разбор по позиции в таблице (не substring-грep
     по всему тексту — см. «Находка» ниже).
2. **Селфтест** `scripts/guards/selftest/test-check-test-fixture-coverage.sh` — доказывает
   ВСЕ 6 заявленных свойств: rule5 ловит/не лжёт (A1/A2), rule1 ловит/не лжёт (B1/B2), бонус
   ловит/не лжёт на мимоходном упоминании/на согласованном закрытии (C1/C2/C3). Части
   rule5/rule1 строят временную git-репу во `$TMPDIR` (не трогают настоящую репу); часть
   bonus — обычные файлы без git (проверка не diff-based).
3. **Подключение**: `scripts/gate.sh` — новый шаг между doc-examples и циклом самотестов,
   `diff-base = HEAD~1` (тот же приём, что `DOC_GUARD_BASE` для doc-conventions). Явный вызов
   стража + явный вызов его селфтеста (плюс страж всё равно попадает в общий цикл
   `selftest/test-*.sh`, как и соседи).
4. `bash scripts/guards/check-guard-wiring.sh` подтверждает: страж документирован
   (содержательная шапка + ссылка на реестр 221.1 №399), подключён (виден в `gate.sh`),
   покрыт селфтестом.

## Находка при вводе стража (важно для доверия к бонус-проверке)

Первая версия бонус-проверки (наивный `grep -oE '\[M-...\][^|]*✅'` через оба документа
целиком) дала **~30 «расхождений» на чистом main** — все ложные: `backlog-followups.md`
годами не чистится по своей же lifecycle-норме («закрыт → убрать строку»), и маркер,
закрытый в 221.1, у него часто просто МИМОХОДОМ упомянут в описании СОВСЕМ ДРУГОЙ,
самостоятельной backlog-записи (пример: `[M-hashmap-index-style-backing]` не имеет
собственной закрытой строки в 221.1 вообще — упомянут только в тексте статуса чужой строки
№319). Разобрался через `awk -F'|'` с позиционным разбором (маркер обязан быть ПЕРВЫМ полем
после номера/категории; статус — СЛЕДУЮЩИМ полем сразу за ним) — это убрало все ложные
совпадения. Итоговая версия при том же прогоне на чистом main находит **4 РЕАЛЬНЫХ
расхождения** (не проверка сломана — проблема настоящая):

- `[M-fn-type-expected-any-bypass]` — 221.1 №45 `✅ ЗАКРЫТ 2026-08-05`, backlog **OPEN
  2026-07-23** (первичная запись, без слова о закрытии).
- `[M-gc-lib-not-bundled-clean-install]` — 221.1 №269 `✅ ЗАКРЫТ 2026-08-02`, backlog **OPEN
  2026-08-02**.
- `[M-time-vtable-typedef-redefinition-standalone-cu]` — 221.1 №277 `✅ ЗАКРЫТ 2026-08-02`,
  backlog **OPEN 2026-08-02**.
- `[M-vec-of-fn-newtype-codegen]` — 221.1 №47 `✅ ЗАКРЫТО 2026-07-24`, backlog **OPEN
  P2 2026-07-23**.

Решение: сделал бонус-проверку **WARN, не FAIL** (не роняет `fail`/exit code стража).
Причина — по заданию «Никакого baseline-файла с долгом, если сможешь без него», а
жёсткий FAIL здесь либо перманентно красит `gate.sh` для ВСЕЙ репы (нарушая
«красный=стоп»), либо провоцирует слепой baseline=4 с чужим долгом (прямо запрещено
заданием). Правильный вердикт по каждому из четырёх маркеров («221.1 был прав, backlog
устарел» ИЛИ «закрытие было ложным, как №224») требует ручного триажа конкретного бага —
это решение интегратора/владельца, не механики стража. WARN держит сигнал видимым на
каждом прогоне гейта без блокировки. **Список передаю владельцу как есть — не трогал ни
одну из четырёх записей.**
