## 1. B1 — `resolve_mono_type_args_ch` (`emit_c.rs` ~19475)

Новый хелпер `compose_mono_type_args_ch` (рядом с функцией): для каждого `fn_decl.generics`
имени — сначала канал per-name (`node_substs[call_id]`, лоуэренный `resolved_type_to_c`, который
УЖЕ сам консультирует `current_type_subst` для residual `TypeParam`/`Named`), иначе — позиционный
turbofish-ref, лоуэренный `type_ref_to_c` (тот же `resolved_named_to_c`/`current_type_subst`
consult, `emit_c.rs` ~3809/~3384). Composed-результат принимается ТОЛЬКО если byte-identical
`legacy_pairs` (уже вычисляется безусловно в начале функции) — гейт не снят.

Закрывает класс R1 почти полностью (turbofish внутри generic-тела, `alloc_buf[T]`/
`copy_n_nonoverlapping`/`null_buf`/`new_buckets`), остаток (99+67+27=193) — вызовы БЕЗ
turbofish, нуждающиеся в Source 2+ (arg-type/closure/structural-bound inference), которые
композиция намеренно не покрывает (не изобретать новый инференс).

## 2. B2 — `resolve_method_level_subst` (`emit_c.rs` ~20227)

Два аддитивных изменения внутри той же функции (не отдельный хелпер, т.к. нужен `&mut self`
для `current_type_subst`-свопа):
1. Pre-seed слотов из `node_substs[call_id]` per-name ПЕРЕД Step 1 (частичный канал-хит больше
   не выбрасывается целиком).
2. Composed-hit early-exit СРАЗУ ПОСЛЕ Step 1 (non-closure структурный arg-bind, уже под
   `receiver_subst`-контекстом): если ВСЕ method-generics резолвнуты — возврат немедленно.
   Байт-идентично by construction: Steps 2/2f/3 НИКОГДА не перезаписывают уже занятый слот
   (`is_none()`-гейт всюду), так что ранний возврат = то же самое значение, что дал бы полный
   прогон легаси.

Закрывает класс R2 (`append[S AsSlice[T]](other S)`-форма, `S` только из arg) почти
полностью. Истинный остаток (~22) — C1 (closure-return-bound, нужен Step 2) и другие формы,
требующие Steps 2f/3.

## 3. B5 — `rt_slots_from_call` (`emit_c.rs` ~2695) — БЕЗ сдвига

Добавлен `rt_slots_seed_turbofish` на ОДНОМ дополнительном call-site (static `Vec[<elem>]`
ext-method mono, ~34357) — safe, но 0 сдвига на измеренных 3 корпусах (сайт не задействован
в этом корпусе). Остальные 4 из 6 `rt_slots_from_call`-сайтов (~35498/36092/36808/37594)
entangled с `self.current_method_turbofish` — этот transient уже `mem::take`'ится ВНУТРИ
самого B2-вызова (`resolve_method_level_subst`), который в этих же match-arm'ах вызывается
РАНЬШЕ, чем `rt_slots_from_call` — то есть к моменту вызова turbofish уже пуст. Безопасное
расширение потребовало бы: захватить `explicit_tf` ДО его consumption в B2 и пронести в
RT-форме до `rt_slots_from_call`, либо переупорядочить вызовы — оба варианта трогают уже
устоявшийся B2-код и несут риск регрессии, не оправданный в этой волне (B2 уже даёт ~97%
composed-hit для той же СТРОКОВОЙ формы — предельный выигрыш от доп. RT-seed на этих сайтах
низкий, RT-slots используются только для inner-closure-param seed, не для основного
`type_subst`). Оставлено как задокументированный остаток (не Stage-D — уточнение для
будущей волны, если появится метрика, показывающая реальную ценность).

## 4. Класс C1 (closure-peek) — диагноз для D119Box.map (0/7 из Stage-C notes)

**Эмпирика:** изолированная сборка `d119_method_level_type_params.nv` с
`NOVA_NODE_SUBSTS_TRACE=1` показывает: `resolve_method_level_subst` (B2) трассирует
`Result.map`/`Vec____nova_*.append` (прелюдия), но **НИ ОДНОГО** `ctx=D119Box...` — ни hit,
ни fallback, ни miss. Значит `.map`-вызовы на `D119Box[T]` НЕ доходят до B2 вообще —
диспетчеризуются через ДРУГОЙ путь (скорее всего инлайн B3-движок, `emit_c.rs` ~35200, или
ещё более ранняя generic-record-type ветка — не зафиксировано точно в рамках этой волны).

**Вывод:** «D119Box.map 0/7» из `196.5-stage-c-notes.md` — НЕ демонстрация того, что
`closure_arg_return_peek` (`types/mod.rs:14954`, checker-side) не справляется с формой
`fn(T)->U` + `str.from(x)`-телом (структурно эта форма ДОЛЖНА резолвиться тем же
механизмом, что успешно резолвит `Result.map`/`Option.map` — 52/2 и 2/3 hit/miss
соответственно). Разрыв — в ДИСПЕТЧЕРИЗАЦИИ (call routing), не в форме тела closure. Правка
`closure_arg_return_peek` не потребовалась бы (фикс НЕ локален там) — по заданию, при
диагнозе вне `closure_arg_return_peek`, чинить не стал, репортирую диагноз.

**Что нужно для Stage-D:** точечная временная трассировка САЙТА, куда реально попадает
`D119Box.map` (аналог снятой B3-пробы из Stage-C), чтобы подтвердить: (a) инлайн-B3-движок
и его СОБСТВЕННАЯ (не `closure_arg_return_peek`) closure-return-инференс, либо (b) отдельная
generic-record-ctor/method ветка, ранее не описанная в 196.5-доке.
