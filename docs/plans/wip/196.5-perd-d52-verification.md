## 0. TL;DR

- **Все 5 целевых файлов дают 0 (ноль) вызовов `infer_method_level_return_for_sum`.** Грепом по каждому файлу
  на ЛЮБОЙ dot-call (`\.[a-zA-Z_]+\(`) — **0 совпадений во всех пяти** (см. §1, метод). Функция достижима
  ИСКЛЮЧИТЕЛЬНО из двух call-сайтов внутри `infer_call_ret_c` (`B11q_novaopt_methods`/`B11r_result_like_methods`,
  `emit_c.rs:49363`/`49389`), которые срабатывают только на `.method()`-вызове на `NovaOpt_*`/`Result`-like
  ПОЛУЧАТЕЛЕ — а ни один из пяти файлов вообще не вызывает МЕТОД (ни на Option/Result, ни на своём
  user-enum) — только `as`-cast, конструкторы, `match`, `??`(`Coalesce`), свободные функции.
  **Вердикт по всем 5: N/A по конструкции** (тот же класс, что d30_try_op_unwrap_pair/d85_question_return/
  d85_result_payload_width* в 196.5-perd-d30-verification.md §3) — не «пробел канала», а отсутствие трафика.
- **Структурная находка (важнее самого нулевого трафика).** `infer_method_level_return_for_sum` берёт
  `sum_name: &str` как параметр, но **ОБА** её реальных вызова в кодовой базе жёстко передают литерал
  `"Option"` (49363) или `"Result"` (49389) — НИ ОДНОГО вызова с именем пользовательского enum (`d407T`,
  `D406Color`, `D406Shape`, `D52Color`, …). Значит функция **структурно НЕ МОЖЕТ** обслуживать
  «user-enum»-часть своего собственного тег-имени в матрице строки 42 (`{Option, Result, user-enum,
  sized-payload}`) — user-enum-методов у неё просто нет ни одного достижимого сайта, независимо от корпуса.
  Это расходится с описанием в трекере/картах (`196.3-wave2-d-driven.md:42`, `196.wave2-progress.md:52`,
  `196-one-truth-closeout.md:168` — «методы sum (Option/Result/enum)») — реальность кода: Option/Result-ONLY.
- **Функция сама — ПОЛНОСТЬЮ легаси** (перечитано по коду, `emit_c.rs:45026-45101`,
  `infer_method_level_return_for_sum_inner`): ни `self.node_substs`, ни `self.resolved_types` НИГДЕ в теле не
  упоминаются — весь резолв идёт через `self.infer_expr_c_type`/`self.infer_type_param_binding`/

- **Оба caller'а — ВНУТРИ текущей замороженной зоны волны-1**, `infer_call_ret_c` (сейчас
  `emit_c.rs:47843`–`49963` — диапазон СДВИНУТ/сжат от исторической метки `46293`-`48883` в комментариях

- **Полнокорпусный трейс** (не solo-per-file — см. п.3 задания, folder-CU ловушка): `nova.exe test
  --positive --compile-error ../spec_tests/conformance` (БЕЗ `--jobs`), debug-бинарь, ОБА трейса разом.

  ответ (0 dot-calls ⟹ 0 возможных вызовов) — per-file solo-изоляция добавила бы только количественное

  per-file-изоляция кластера потребовала бы временно выносить остальные ~220+ файлов `spec_tests/conformance/`

## 3. Структурная находка: функция — Option/Result-only, не «sum general»

По коду (`emit_c.rs`, грep всех вызовов `infer_method_level_return_for_sum(`):

```
45021:  let result = self.infer_method_level_return_for_sum_inner(sum_name, method, args, receiver_subst);
49363:  if let Some(resolved) = self.infer_method_level_return_for_sum(
49364:      "Option", method.as_str(), args, &[("T".to_string(), elem_ty.clone())])
49389:  if let Some(resolved) = self.infer_method_level_return_for_sum(
49390:      "Result", method.as_str(), args, ...)
```

Оба реальных сайта (49363 — ветка `obj_ty.starts_with("NovaOpt_")`, `icr_trace("B11q_novaopt_methods")`;
49389 — ветка `Self::is_result_like(&obj_ty)`, `icr_trace("B11r_result_like_methods")`) жёстко передают
литерал `"Option"`/`"Result"`. Сигнатура функции (`sum_name: &str`) ОБЩАЯ, и внутри она честно ищет
`self.generic_type_methods.get(sum_name)` — карта, которая ПОПУЛЯРНО заполняется для user-типов тоже
(`generic_type_methods` — общая HashMap для ВСЕХ типов с объявленными методами, не только builtin). Но раз
единственные два вызывающих сайта её не передают ничего кроме `"Option"`/`"Result"`, user-enum-ветка НИКОГДА
не активируется НИ ПРИ КАКОМ входном корпусе — это структурный (design-time), а не корпус-зависимый факт.
D406/D407 (реальные user-enum типы кластера) физически не могут пройти через эту функцию, даже если бы их
conformance-файлы вызывали методы на своих enum-значениях (а они не вызывают — см. §2).

**Вывод:** маппинг «D52/D407/D406 методы sum (`infer_method_level_return_for_sum`)» в
`196.3-wave2-d-driven.md:42` / `196.wave2-progress.md:52` / `196-one-truth-closeout.md:168` («Option/Result/
enum») ТОЧЕН насчёт Option/Result-части, но НЕТОЧЕН насчёт «enum»-части — ни один текущий caller не
обслуживает user-enum sum-методы через эту функцию. Если у user-enum когда-нибудь появятся методы с
method-level generics (сейчас — не появились: ни D406, ни D407 деклараций с `fn @method[U](...)` не содержат;
собственно, СЕЙЧАС в языке даже нет проверенного примера user-enum-метода с method-level generic в
conformance), потребуется ТРЕТИЙ вызывающий сайт с `sum_name = <имя user-типа>` — которого сегодня нет.

## 7. Рекомендация оркестратору

- **НЕ флипать D52/D407/D406 в трекере** — но не из-за пробела покрытия ФАЙЛОВ (их 0-трафик — не дефект,
  функция им попросту не нужна для того, что они тестируют), а из-за того, что сама целевая функция
  (`infer_method_level_return_for_sum`) остаётся ПОЛНОСТЬЮ легаси и её caller'ы — внутри замороженной зоны
  волны-1 (SHARED, как и было классифицировано в `196.wave2-progress.md:52`). Работа над самой функцией НЕ
  входила в регион этого захода (read-only) и НЕ начата в коде.
- **Возможный follow-up (вне этого захода):** маппинг «D52/D407/D406» → `infer_method_level_return_for_sum`
  в трекере/картах стоит сузить до «D52/D407 (Option/Result-часть D30/D85-класса, НЕ user-enum)» — user-enum
  часть тега («D406») у этой функции физически не покрыта НИ ОДНИМ сайтом кода (§3), и если/когда появится
  user-enum-метод с method-level generic, для него потребуется новый (третий) caller, которого сегодня нет —
  то есть текущая матрица строки 42 («возврат метода sum × {Option, Result, user-enum, sized-payload}») шире
  того, что функция вообще способна обслужить.
- Реальное покрытие Option/Result-method-level-generic-класса (та часть, для которой функция ДЕЙСТВИТЕЛЬНО
  что-то делает) уже верифицировано в `196.5-perd-verification.md` (d119_method_level_type_params,
  d119_option_result_method_level_generic — 🔶 ЧАСТИЧНО, closure-return-bound класс в fallback, см. Класс 1
  того отчёта) — этот заход её не переоткрывает, только подтверждает, что d52/d406/d407/d85_result_payload_width
  — НЕ входят в эту часть корпуса.
