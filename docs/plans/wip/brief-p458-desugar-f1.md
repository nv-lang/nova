## ЗАДАЧА — узкий скоуп, прочитай внимательно

**Ф.1 НЕ убирает старые пути резолва методов/функций — это Ф.2/Ф.3, будущие
окна.** Ф.1 делает РОВНО одно: даёт `@` право стоять в ПОЗИЦИИ ТИПА, не меняя
ничего в существующем поведении. Критерий приёмки — **побайтово идентичный
СИ-выход** на корпусе (мега-CU + `std`) ДО и ПОСЛЕ: если хоть один существующий
файл начал генерировать другой C — это регресс этой фазы, а не «тоже
корректно».

### Что добавить

1. **Парсер: `@` легален внутри выражения типа функции**, в позиции параметра
   и (только когда `@` уже связан параметром) в позиции возврата:

   ```nova
   fn(mut @Type, a int) -> @              // легально — тип
   fn(@Type, a int) -> Option[@]          // легально — тип
   fn(mut @Type, a int) -> @ = Type.@job  // легально — аннотация let-binding
   ```

   Сегодня (проверь пробой, прежде чем менять) `Type.@job` уже типизируется
   БЕЗ `@` — как `fn(mut Type, int) -> int` (получатель просто первый
   параметр, без метки). Ф.1 добавляет ВТОРУЮ легальную запись ТОГО ЖЕ типа —
   С `@`. Само значение `Type.@job` и его РЕАЛЬНОЕ поведение не меняются;
   меняется только то, что теперь МОЖНО написать более точную аннотацию.

2. **`fn(mut @Type, a int) { … }` / `=> …` КАК ОБЪЯВЛЕНИЕ — запрещено**, с
   именованной ошибкой и fix-it:

   ```
   E_D458_COMPILER_FORM_IN_SOURCE: compiler form used as a declaration —
   write `fn Type mut @job(a int) -> @` instead
   ```

   Гейтится на грамматической позиции ОБЪЯВЛЕНИЯ (`fn <headers>(...) { }` /
   `=> expr`), НЕ на встрече `@` внутри типа вообще — иначе она ложно
   сработает на аннотации из пункта 1. Сахарная форма (`fn Type mut @job(...)`)
   парсится и работает КАК СЕГОДНЯ, без изменений.

3. **`x.(f)(5)` — вызов значения метода, чей тип несёт `@`.** Проверь на
   столкновение в грамматике с существующими формами (`.0` на кортеже,
   `.name` на поле, вызов лямбды `f()`) — это утверждение парсера, не мой:
   если коллизия есть, остановись и доложи, не выбирай сам.

   ```nova
   ro f = Purse.@bump           // тип: fn(mut @Purse, int) -> @  (НОВАЯ запись типа)
   ro r = x.(f)(5)              // вызов значения через точку-скобки
   ```

4. **`x.(f)` БЕЗ вызова — ошибка компиляции**, не частичное применение
   (решение владельца 2026-08-12). Подсказка в тексте: «допиши аргументы:
   `x.(f)(…)`».

5. **Явный каст между `@`-типом и обычным типом функции запрещён в обе
   стороны.** `Purse.@bump as fn(mut Purse, int) -> int` (стирание `@`) и
   обратное — обе формы дают именованную ошибку с подсказкой «используй
   лямбду» (`fn(mut q Purse, k int) -> int => q.bump(k)`).
