# Промт-задание: единая поверхность «скаляр → строка» (str.from → @to_str) + прямо-в-sink

> Готовый промт для агента-исполнителя. Модель: **sonnet** (архитектура типов/резолва —
> сверяться с целевым; НЕ haiku). Родитель: 174.1 (parse/bytes/domains → to_*) + 152.7.2/D419
> (Fmt-контекст, прямо-в-sink). Это ДОСЛЕДОВАНИЕ обратного направления, которое 174.1 не тронул.

## Исследование (факты, проверено по коду 2026-07-13/14)

**Что уже мигрировано на `to_*`-методы (174.1, D73/D77-ретракция, D410):**
- Парс `str→примитив`: `str @to_int(radix)`/`@to_i64`/`@to_u64`/`@to_f64` ✅.
- Байты: `str.from_bytes*` РЕТРАКТ → `[]u8 @to_str()` ✅.
- Домены: `Version.from(s)`→`@to_version()`, `Url.parse`→`@to_url()` и т.д. ✅.

**Что НЕ мигрировано — обратное направление «примитив → строка»:**
- `str.from(int/f64/f32/bool)` — живы как `export extern "nova"`:
  `std/src/runtime/string/from_scalar.nv:23/26/29/32` (bool/f64/f32/int),
  `std/src/runtime/char.nv:25` (char), `char.nv:35` (from_codepoint).
- **Асимметрия:** только `char` получил обёртку `char @to_str() => str.from(@)`
  (`std/src/runtime/char.nv:32`). У `int`/`f64`/`f32`/`bool` метода `@to_str()` НЕТ —
  наружу торчит только `str.from(scalar)`.
- **~56 вызовов** `str.from(scalar)` по std (файлы: data/semver, encoding/serde/json,
  encoding/url, encoding/json, io/error, time/civil/*, text/markdown_minimal,
  runtime/defaults, runtime/string/transform, _experimental/crypto, prelude/* и др.).
- **Внутри тел `@display` примитивов:** `fn int @display(mut w Write) => w.write(str.from(@))`
  (`std/src/prelude/protocols.nv:547/552/567` для int/f64/bool) — АЛЛОКАЦИЯ промежуточной
  `nova_str` на каждый вывод (претензия владельца).
- **Движок интерполяции:** `"${x}"` для примитива лоуэрится через `str.from`-путь
  (`emit_c.rs::emit_interpolated_str` ~2428 и окрестности).

**Почему выжил (документировано, не забыто):** D73-ретракция ЯВНО оставила
`str.from(v)`/`str.from_debug(v)` как «точку расширения Display/Debug и интерполяции».
Т.е. это осознанное решение эпохи — но оно противоречит цели владельца «всё через `@to_str()`»
и оставляет две болячки: (1) непубличный по смыслу движок торчит публичным API;
(2) аллокация в `@display`.

**Рантайм-хелперы для прямого-в-sink УЖЕ есть (152.7-B):** `nova_int_to_str` (nova_rt.h),
`nova_bool_to_str`/`nova_char_to_str`/`nova_f64/f32` (conv.h ~144-228), полноформатные
`nova_fmt_int_body`/`nova_fmt_f64_body` (conv.h:508/570). Т.е. писать в sink без промежуточной
`str` МОЖНО существующими средствами.

## Требуется решение владельца (спросить ДО кода, если не задано в передаче)

1. `str.from(scalar)` — **совсем убрать из языка** ИЛИ **оставить приватным движком**
   под капотом `@to_str()`/интерполяции (не-`export`, недоступен пользователю)?
   Рекомендация исполнителю по умолчанию (если владелец не уточнил): **приватный движок** —
   меньше blast-radius, интерполяция и Display-default продолжают опираться на него внутренне,
   но публичная поверхность = только `@to_str()`.

## Объём (пошагово, каждый шаг — коммит; ГЛАВНЫЙ ГЕЙТ conformance полный без --jobs после каждого)

1. **Добавить `@to_str()` примитивам:** `int`/`f64`/`f32`/`bool` — тонкие методы
   `fn int @to_str() -> str => <engine>` рядом с существующим `char @to_str()`
   (from_scalar.nv / соответствующие runtime-файлы). Спека: если это меняет язык
   (новый публичный метод-канон) — D-амендмент к 174.1/D410 в ТОМ ЖЕ слиянии.
2. **Прямо-в-sink в `@display` примитивов:** тела `fn int @display(mut w Write)` переписать
   с `w.write(str.from(@))` на прямую запись через рантайм-хелпер (без промежуточной `nova_str`)
   — закрывает `[M-152.7.2-interp-direct-primitives]`. Проверить: интерполяция `${x}` примитива
   тоже идёт прямо-в-sink (emit_c interp-путь), а не через `str.from`.
3. **Мигрировать ~56 потребителей** `str.from(scalar)` в std на `.to_str()` — механическая
   правка (это подошло бы **haiku по списку файлов**, НО запрет на main-репу: делать в worktree
   sonnet'ом ИЛИ haiku с явной картой файлов и запретом трогать что-либо вне списка).
   Список файлов — в исследовании выше (grep `str.from(` по std/src, минус определения/тесты).
4. **По решению владельца (п.1):** либо снять `export` со `str.from(scalar)` (сделать внутренним),
   либо удалить из языка целиком (тогда интерполяция/Display-default перевести на прямой хелпер,
   а не на `str.from`). Негатив-тест: пользовательский `str.from(5)` → ошибка/недоступность
   (если приватизирован).
5. **Обновить D73/174.1/D410-тексты:** «str.from(scalar) больше не публичная точка расширения;
   канон = `@to_str()`; движок приватен». Q/маркеры: закрыть `[M-152.7.2-interp-direct-primitives]`.

## Гейты
- conformance ПОЛНЫЙ без --jobs — база на момент старта (сейчас 468/0+7..12skip; свериться первым
  прогоном); мега-CU ~450с — прогон фоном/дроблением, финальный полный обязателен.
- `nova test std/src/encoding` + `std/src/time` + `std/src/data` (плотные потребители str.from) — δ0.
- byte-parity НЕ требуется (поведение то же, аллокация убрана — .c меняется законно), но
  существующие тесты зелёные.
