## Форма решения (три развилки — уже решены, см. D419)

- (а) второй опциональный метод `@display_fmt(mut f Fmt)`; `Fmt` — **тот же** `@write`,
  что и `Write` (НЕ `@write_str` — задание ошибочно называло другое имя; `@write`
  сохраняет «Fmt поверх Write» буквально верным).
- (б) `@display`/`@debug` сигнатуры не тронуты.
- (в) типу — только `alternate`/`precision`; width/fill/align — пост-обработка
  у вызывающего; radix — без изменений.

## ABI / codegen — ключевые находки (не очевидны из спеки, для следующего агента)

1. **`Fmt` эрайзится к `Nova_FmtCtx*`** ТЕМ ЖЕ приёмом, что `Write` → `Nova_StringBuilder*`
   (это НЕ vtable/dyn-протокол — hardcode в 3 местах `emit_c.rs`):
   - `resolved_named_to_c` (главная C-type таблица) — добавлена ветка `"Fmt" => "Nova_FmtCtx*"`.
   - `debt_lowered_is_stub`-подобная функция (~emit_c.rs:2962) — `"Fmt"` добавлен в список
     «не generic-stub».
   - `extract_protocol_type_name` (E7201) — `"Fmt"` исключён (иначе `f.write()`/
     `f.alternate()` внутри `@display_fmt` тела дают E7201).
   Без этих трёх правок `Fmt`-параметр эрайзился бы в generic `NovaBox_Fmt`
   (protocol-boxing путь, нефункциональный для этого V1).

2. **DCE-грабли (нашёл эмпирически через smoke-тест с `fn main()`):** реестр
   `all_methods`/`method_table` тут ни при чём — ловушка в
   `compiler-codegen/src/lints.rs::collect_used_names`, ветка `ExprKind::InterpolatedStr`.
   Там ручной seed-list имён, которые «невидимы AST» (инжектятся десугаром интерполяции):
   `StringBuilder`/`append`/`into_str`/`cap`/`display`/`debug`/`from`/`from_debug`/`to_str`.
   Т.к. `Nova_FmtCtx_static_new(...)` и `Nova_<T>_method_display_fmt(...)` — тоже
   ручной raw-C emit (не AST Call), их имена НИКОГДА не появляются синтаксически в
   пользовательском коде → reachability-DCE (Plan 159 Ф.1) резал `FmtCtx`'ы методы и
   любое пользовательское `@display_fmt` тело в **fn-main-исполняемых** программах (linker:
   `undefined symbol: Nova_FmtCtx_static_new` / `Nova_<T>_method_display_fmt`).
   Фикс: добавлены seeds `FmtCtx`/`new`/`display_fmt`/`alternate`/`precision`/`write`
   в тот же список (lints.rs). **NB:** `test { }`-блоки (без `fn main`) НЕ триггерят DCE
   вообще (`compute_dead_decls_with` рано возвращает `default()` без `main`) — поэтому
   штатный `nova_tests`/`spec_tests` корпус этот баг НЕ ловит; ловится ТОЛЬКО через
   `fn main()`-программу. Держать в уме при похожих будущих hand-emit call-сайтах.

3. **Double precision-apply баг (нашёл через собственный smoke-тест, пофиксил в той же
   волне):** `emit_format_spec_value` считает `core` (расширенный на @display_fmt-ветку),
   а ХВОСТ функции (после if/else) БЕЗУСЛОВНО применяет `nova_fmt_str_precision` + `nova_fmt_pad`
   поверх `core`. Если `@display_fmt` уже сам «съел» `.precision()`, внешняя truncation
   резала результат ВТОРОЙ раз (`"hi:3"` → truncate-to-3 → `"hi:"`, не `"hi:3"`).
   Фикс: `core` стал `(core, precision_consumed)`; хвост пропускает
   `nova_fmt_str_precision` когда `precision_consumed == true`, но `nova_fmt_pad`
   (width/align/fill) применяется ВСЕГДА одинаково — проверено тестом `${t:>4}`.

4. **`nova test` дефолт = только positive.** `--full` (или `--compile-error`) обязателен
   чтобы raннер вообще увидел `neg/`-файлы — потратил время на «0 найдено» пока не
   вспомнил про `--positive`/`--compile-error`/`--full` флаги (`nova test --help`).

## Не сделано / follow-up

- **П.4 (движок интерполяции «прямо-в-sink» для ПРИМИТИВОВ)** — сознательно НЕ в этой волне.
  User-type Display/Debug УЖЕ пишет прямо в sink (Plan 175 Ф.3(d), проверено в существующем
  коде). Примитивная быстрая тропа (`nova_int_to_str`/`nova_f64_to_str`/... внутри
  `emit_interpolated_str`) всё ещё аллоцирует промежуточную `nova_str` (`nova_alloc(32)` и
  т.п. в `nova_rt/conv.h`) перед копированием в `StringBuilder` — двойная копия на фрагмент.
  Реальный фикс требует новых C-рантайм хелперов, пишущих прямо в `Nova_StringBuilder*`
  (`nova_rt/conv.h` + call-site в `emit_c.rs`) — низкий риск сам по себе, НО: (1) тот же файл-
  регион, что активно правит параллельный Plan 196 (явное предупреждение задания), (2) не
  верифицировано лично — отдельная короткая волна, маркер `[M-152.7.2-interp-direct-primitives]`
  (docs/plans/backlog-followups.md, docs/dev/simplifications.md, spec/open-questions.ru.md).
