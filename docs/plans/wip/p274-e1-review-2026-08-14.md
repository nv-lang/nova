## 1. Каскад на верхнем уровне парсера — против собственного правила

`parse.nv:47`: каждый посторонний токен верхнего уровня — отдельный Err-ветвь;
файл `1 2 3` даст ТРИ диагностика на одну причину. В `fn_decl` (строки 71-82)
тот же случай уже собран в один panic-бакет. Нужен такой же бакет в цикле
`parse()` + негативная фикстура «мусор на верхнем уровне» под
`check-novac-no-cascade.sh`.

## 2. `Cursor.take` не сдвигается на Eof — дверь для будущего зависания

`parse.nv:28-32`: на Eof возвращает лист, не двигая курсор. Сегодня все вызовы
ограждены `at_eof`; первый неогороженный цикл повиснет, а повторный take Eof
задвоит хвостовую тривию в ресериализации. Сдвиг с клампом либо ассерт на
повторный take.

## 3. `tree.@kind_of`: Leaf → `NodeKind.Err` — лист не ошибка

`tree.nv:61-66`: лист с добротным токеном классифицируется как Err; будущий
обход по kind'ам молча посчитает листья ошибками. Честный ответ: отдельный
kind для листа либо Option[NodeKind].

## 4. Незакрытая строка остаётся `StrLit` — правдоподобно-неверное принятие

`lex.nv:128-137`: скан дошёл до EOF без закрывающей кавычки — kind всё равно
StrLit. По духу вашего же K7-отказа это ErrorTok. Рядом: экранированное `\${`
тоже взводит `has_interp` (`lex.nv:131-132` — после пропуска backslash
проверяется УЖЕ экранированный байт). Пере-отказ — безопасная сторона, но
контракт неточен; фикстуры на оба случая.
