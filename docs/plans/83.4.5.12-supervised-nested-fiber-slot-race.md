## Симптом
Вероятностная гонка fiber-scheduler'а на **вложенных `supervised`** (HTTP-сервер флагмана:
`supervised { spawn accept-loop; per-connection spawn под тем же supervised }`). **Единственный** запрос
к свежему процессу — 100% надёжен; на **2-3-м последовательном** запросе сервер **виснет НАВСЕГДА**
(curl не возвращается). `NOVA_RUNTIME_DUMP` показывает **застрявший слот**. Смягчено на 187-прогоне А,
НЕ закрыто.

## Репро
```
cd d:/Sources/nv-lang/nova
nova build examples/flagship/aggregator/src/main.nv -o aggregator   # (env как для nova test)
./aggregator &                                                       # слушает http://127.0.0.1:8187/
curl -s 127.0.0.1:8187/ ; curl -s 127.0.0.1:8187/ ; curl -s 127.0.0.1:8187/   # 2-3-й часто виснет
```
Гонка вероятностная → повторять серии по N запросов; `NOVA_RUNTIME_DUMP=1` для state-dump застрявшего слота.

## Зона фикса
`compiler-codegen/nova_rt/fibers.h` — slot-state машина M:N: per-child `_nova_parent_slot`
(NovaSpawnCtxBase), arena-слоты, CAS-guards resume (прецедент 83.4.5.7). Подозрение — STALE-slot /
порядок resume/park при вложенном supervised (второй заход переиспользует слот, чьё состояние не
сброшено предыдущим циклом). Точный корень — за реконом (state-dump алгоритм из case-study).

## Findings (opus, 2026-07-15)

### Репро
`nova build examples/flagship/aggregator/src/main.nv -o aggregator` (env: worktree
`NOVA_RT_DIR` по умолчанию → правка runtime используется; libuv-submodule скопирован в
worktree без .git; `NOVA_GC_LIB_DIR/INCLUDE_DIR` → main-repo vcpkg). Сервер слушает
`127.0.0.1:8187`. Серия `curl --max-time 7` по эндпоинтам (`/api/events`/`/api/run`
глубже всего: `aggregate()`'s parallel-for + `fetch_guarded`'s `supervised(deadline:)`).
**Стабильно виснет НАВСЕГДА на ~14-м последовательном запросе** (иногда 2-7-м); «успешные»
перед зависанием тянулись 4-8с вместо budget≈1.2с (late-unblock по дедлайну). После hang'а
сервер полностью wedged (все последующие curl = timeout). Гонка вероятностная, но deadlock
в пределах серии — детерминированный.

### State-dump (шаблон case-study)
Watchdog на worker-тредах отключён (`_watchdog_enabled = !_nova_on_worker_thread()`), поэтому
вложенный per-connection scope на worker'е дампа не пишет. Диагностически временно: включён
watchdog на worker-тредах + добавлен dump `yielded_count`. Дамп застрявшего состояния:
```
[w.0.fiber.s1] mco_status=3 (SUSPENDED) parked=0 pstate=0 hdl=0 stop_cb=0 ⚠ STUCK_ALIVE_NOT_PARKED
[w.0.yielded] count=1 head=0
```
Фибр приостановлен (SUSPENDED), НЕ запаркован (parked=0, pstate=NIL, нет handle/stop_cb), НЕ в
runq/runnext/global (нет строки `[w.0.deque]`) — сидит в **yielded-FIFO** worker 0.

### Корень (runtime.c, НЕ fibers.h)
`nova_runtime_worker_pump_scope` (вызывается из `nova_supervised_run_impl` когда вложенный
`supervised` крутится на worker-треде и ждёт `pending_remote==0`) дренировал runnext + runq +
global-overflow, но **НЕ `_worker_yielded_pop`**. При этом pump на шаге (4a) резюмит фибр инлайн
через `_worker_run_one_fiber`, а тот при кооперативном вытеснении (Plan 44.7 sysmon-preemption /
`runtime.yield`) пушит фибр в yielded-FIFO (`runtime.c:1980`). Пока worker застрял в
nested-pump-цикле, он НЕ возвращается в `_worker_main` (`runtime.c:890`), где yielded-FIFO
дренируется штатно → вытесненный дочерний фибр ТОГО ЖЕ pump'ящегося scope black-hole'ится →
`pending_remote` не декрементируется → цепочка supervised виснет навсегда. Тот же класс, что
задокументированный global-overflow «black-hole» в `_worker_main` — yielded-FIFO в pump-пути был
пропущен. **НЕ** STALE-slot из case-study (тот fix present/корректен): отдельный дефект того же
семейства «фибр жив, но застрял в очереди, которую текущий drain не обслуживает».

### Фикс (минимальный, +13 строк)
`compiler-codegen/nova_rt/runtime.c`, `nova_runtime_worker_pump_scope`: добавлен
`if (!co) co = _worker_yielded_pop(w);` между runq и global-overflow. Порядок дренирования теперь
зеркалит `_worker_main` ровно: runnext → runq → yielded → global. Инварианты не тронуты
(TLS-race 83.10.4, per-slot child_error 173.0, slot-lock/CAS/atomic fiber-state — без изменений;
правка чисто в выборе источника фибра). Non-matching yielded-фибр (шаг 4b) перекладывается в runq
(тоже дренируется).
