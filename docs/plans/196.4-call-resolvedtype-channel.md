## 1. Проблема — УТОЧНЕНИЕ Q5 по коду (канал ЕСТЬ, дыра в ПОКРЫТИИ, не в отсутствии)

Q5 сформулировала: «чекер аннотирует `resolved_types` для Ident/SelfAccess/Index/Member/Range/RecordLit,
но для `ExprKind::Call` — НИ ОДНОЙ записи». **Разведка 196.4 это уточняет (по коду):** записи для Call ЕСТЬ, и
их несколько путей. Точная граница Tier-1/Tier-2 не «Call не ключуется», а **«Call ключуется концкретным типом
только когда subst полностью разрешается на чек-тайме; иначе чекер помечает residual-`TypeParam` и откладывает
subst в codegen (`resolved_type_to_c` + `current_type_subst`), ЛИБО не аннотирует вовсе → codegen падает в
легаси `infer_call_ret_c` (зона волны-1)»**.

Существующие продюсеры Call-аннотации (`compiler-codegen/src/types/mod.rs`):
- **`f1_check_call`** (`~10200`–`10494`): резолвит однозначный callee (free-fn single/multi-compat,
  `Type.method`, module-fn) → `resolved_callees[call_id]` + аннотирует `resolved_types_buf[call_id]`:
  - non-generic возврат (гейт `!typeref_mentions_any`) — прямо (`10450`);
  - `-> Self` static — subst `Self`→receiver-тип через `subst_type_ref_pub` (`10433`–`10451`);
  - **free-fn generic возврат** (`10452`–`10492`): ВЫВОДИТ type-args из АРГУМЕНТОВ через
    `const_fn_trampoline::unify_type` + `subst_type_ref_pub` → материализует КОНКРЕТНЫЙ `Result[[]int,str]`;
    гейт «только при полном разрешении (нет residual)».
- **`f1_expr_inner` Call-арм** (`~7854`–`7929`): `infer_method_call_channel_type` (instance-метод возврат) →
  `mark_type_params(from_type_ref, gs)` → `resolved_types_buf[e.id]`; плюс fallbacks: TurboFish-static-ctor
  (`infer_expr_type`), `size_of/align_of` (→int), `Some(x)` (→`Option[type-of-x]`).
- **`check_instance_overload`** (зовётся из `10347`) — instance-overload → `resolved_callees` + канал.

Потребление codegen — `infer_expr_c_type` (`emit_c.rs:48686`), порядок:
1. спец-кейсы (`try_as[T]`, generic-wrapper-ctor mono → `infer_generic_static_ctor_ret`);
2. **Канал-1** (`48746`): `resolved_callees[id]`→`fn_ret_by_span[span]`, НО `!debt_is_generic_stub_c` — любой
   generic-возврат `Result[T,E]`/`Option[T]` лоуверится при регистрации в стаб → **пропускается**;
3. **Канал-2** (`48770`–`48795`): `resolved_types[id]`→`resolved_type_to_c` — ЭТО и есть канал Call-expr
   ResolvedType; если чекер аннотировал КОНКРЕТНЫЙ тип — codegen читает здесь и НЕ идёт в легаси;
4. промах → легаси `infer_call_ret_c` (`46405`, зона волны-1 `46293`–`48883`) → `resolve_result_option_ret`
   / `resolve_result_te` / `infer_static_method_ret` / `infer_method_level_return_for_sum` перевыводят.

**Вывод:** канал (Канал-2) уже существует и авторитетен. Tier-2 заблокирован НЕ отсутствием канала, а тем, что
**чекер не кладёт в него полностью-подставленный конкретный `ResolvedType` для класса «generic-возврат вызова,
subst которого приходит из method-level generics / sum-обёртки / static-generic, а не из уже-покрытых
receiver-carrier / free-fn-arg»**. Где чекер помечает residual-`TypeParam` (`mark_type_params`) и отдаёт subst в
codegen — это и есть остаток «codegen перевыводит», подлежащий переносу в фазу-коллектор (кроме законно-erased
тел, см. §7).

## 2. Как чекер СЕЙЧАС заполняет `resolved_types_buf` (recon-1)

`f1_expr` (`7152`) = обёртка: `f1_expr_inner` (walk, тот же поведенческий обход) + опциональная IDE-запись. Общий
паттерн продюсера: для ExprKind вызывается `infer_expr_type(e, scope)` (синтаксический TypeRef-инференс) →
`ResolvedType::from_type_ref` → `resolved_types_buf.insert(e.id, rt)`. Ключ ВСЕГДА `e.id` (`ExprId`), значение —
`ResolvedType` (перечень в `types::ResolvedType`: `Scalar/Float/Bool/Str/Unit/Ptr/Named{name,module,args}/
Tuple/Func/TypeParam/…`).

Покрытые ExprKind (все в `f1_expr_inner`, преамбула `7249`–`7717`):
- **Ident** (`7249`), **SelfAccess** (`7266`), **Index** (`7279`, + 172.1.2 контейнер→элемент через
  `project_channel`), **Member** (`7308`), **Range** (`7324`, всегда `Named{Range}`), **RecordLit**
  (`7332`/`7462`, гейт non-generic), **HandlerLit**/**ProtocolLit** (`7350`/`7373`), **Block/If/IfLet/Path**
  (`7394`), numeric-const `T.MAX` (`7423`), Tuple all-primitive (`7608`), loop→Unit (`7626`), ParallelFor→`Vec[T]`
  (`7637`), литералы (`7688`).
- **Call** — арм `7718`–`7930` (см. §1): аннотация через `infer_method_call_channel_type` / static-ctor /
  size_of / Some(x), с `mark_type_params`-гейтом. Плюс `f1_check_call` (`10200`+) даёт callee+прямой канал.

Где Call пропускается (нет концкретной аннотации → codegen в легаси): (а) instance/static-возврат, чей
type-param выводится из method-level generics или sum-обёртки, а `resolve_instance_method_return_arity` не
разрешает; (б) когда `mark_type_params` оставляет residual (erased-тело — законно; concrete-caller — дыра); (в)
0-или-≥2 compat overload (`_ => return`, «gap, not wrong»).

## 3. Где чекер УЖЕ вычисляет подставленный тип результата вызова (recon-2)

Машинерия subst на чек-тайме УЖЕ существует и переиспользуема (это ключ к минимальности Stage-1):
- **`const_fn_trampoline::unify_type(param_ty, arg_ty, generic_names, &mut subst)`** — структурный унификатор:
  сопоставляет объявленный параметр с выведенным типом аргумента, накапливает `subst: HashMap<String,TypeRef>`.
  Тот же унификатор, что `build_recv_subst` применяет к ресиверам. Используется в `f1_check_call` для
  free-fn generic-возвратов.
- **`const_fn_trampoline::subst_type_ref_pub(ty, &subst)`** — применяет `subst` к `TypeRef` (T→конкрет).
- **`build_recv_subst(receiver, recv_ty)`** — строит subst из receiver-carrier (T контейнера → элемент из
  инстанс-типа ресивера).
- **`resolve_instance_method_return_arity`** (`13589`) / **`resolve_instance_method_return`** (`13579`) —
  возврат instance-метода с carrier-subst.
- **`resolve_method_return_with_closure_args`** — method-level generic (`map[U]`) из closure-аргумента при
  известном carrier-subst (`closure_arg_param_seeds` `14053` сеет типы closure-параметров из
  СУБСТИТУИРОВАННОЙ сигнатуры callee).
- **`mark_type_params(rt, gs)`** — помечает residual-параметры явным `ResolvedType::TypeParam`; лоуэринг:
  codegen `resolved_type_to_c` + receiver-instance-map/`current_type_subst`.

**Итог recon-2:** чекер уже умеет: (1) receiver-carrier subst, (2) free-fn-arg subst, (3) method-level generic
из closure-арга. НЕ покрыто концкретной аннотацией (класс Tier-2): method-level generic из НЕ-closure арга,
sum-обёртка возврата (`infer_method_level_return_for_sum`), static-generic не-ctor, и общий случай, где
`resolve_instance_method_return_arity` возвращает residual → `mark_type_params` откладывает в codegen. Канал
Stage-1 = **достроить subst этих форм на чек-тайме и класть КОНКРЕТ в `resolved_types_buf[call.id]`**, а НЕ
плодить новый IR.
