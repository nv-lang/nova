## Реализовано

### Ф.1 — Codegen guard-лоуэринг (`compiler-codegen/`)

**`nova_rt/effects.h`** — новые хелперы (mirror `nova_<T>_checked_add/sub/mul`, D423):
- `nova_int_checked_div/_rem/_neg` (для безграничного `int` = `intptr_t`, `INTPTR_MIN`).
- `NOVA_DEFINE_CHECKED_SIGNED_DIVMODNEG(NAME, CTYPE, MINVAL)` → `nova_{i8,i16,i32,i64}_checked_
  div/_rem/_neg` (полный guard: `b==0` + MIN/-1 для div/rem; `x==MIN` для neg).
- `NOVA_DEFINE_CHECKED_UNSIGNED_DIVMOD(NAME, CTYPE)` → `nova_{u8,u16,u32,u64,uint}_checked_div/
  _rem` (ТОЛЬКО `b==0`-guard — MIN/-1-ветка структурно отсутствует, не «условно false»; нет
  `_neg`-варианта для unsigned вообще — raw `-x` не трогается).

**`src/codegen/emit_c.rs`** — 5 сайтов лоуэринга:
1. `sized_checked_helper` (было Add/Sub/Mul-only) расширен на `BinOp::Div → "div"` /
   `BinOp::Mod → "rem"` — покрывает ОБА call site, которые уже вызывали эту функцию
   generically (`emit_expr`'s `else if lty == rty` ветка + literal-coercion gap ветка, ~29783-29820).
2. Новая `sized_checked_neg_helper(ty_c)` — signed-only (`None` для unsigned/non-Ints).
3. Главный `Binary`-арм `emit_expr` (`nova_int`-хардкод-ветка, ~29768) — добавлены
   `BinOp::Div => nova_int_checked_div`, `BinOp::Mod => nova_int_checked_rem`.
4. Главный `Unary`-арм `emit_expr` (~29994 fallback до этого правки) — новый guard-блок перед
   `op_str`-fallback: signed `nova_int`/sized → `nova_<T>_checked_neg`, unsigned/non-Ints —
   без изменений (raw `-x`).
5. `emit_expr_with_target_type`'s `Unary{Neg}`-арм (~28424) — тот же guard через
   `sized_checked_neg_helper(target_ty_c)` (гарантированно sized здесь, `nova_int` уже
   исключён верхним guard'ом функции).
6. `Stmt::Assign` compound-assign (~27573) — `AssignOp::Div` добавлен в `checked_helper`-match
   (нет `%=` в языке — только `Div`-вариант `AssignOp`), плюс во внутренний `sized_checked_helper`
   dispatch-match.

Z3-элизия (`overflow_site_elided`) подключена на ВСЕХ новых сайтах (тот же span-based hook,
что Add/Sub/Mul) — но `verify/pipeline.rs::prove_int_overflow_sites` фильтрует на
`BinOp::Add|Sub|Mul` (жёсткий `matches!`, ~4379), div/mod/neg-сайты туда НЕ попадают → guard
всегда emit'ится (элизия — честный no-op, не silent gap). Followup `[M-206.1-div-neg-z3-elision]`.

**НЕ тронуто (сознательно, объяснено в отчёте/спеке):**
- `emit_const_expr_typed` (~8488, file-scope `const`-инициализаторы) — компилируется C-компилятором
  на этапе C-сборки, не Nova runtime; div-by-zero там уже ловится `E_CONST_FN_DIV_ZERO`
  (`const_fn_eval.rs`) ДО достижения этого codegen-пути в типичном случае — другой risk-профиль,
  не SIGFPE-вектор.
- `expr_to_display` (~54685) — diagnostic-only text rendering контрактных сообщений, никогда не
  эмитит исполняемый код.
- Frozen-зоны НЕ тронуты: `infer_call_ret_c` (46293-48883), 164 Ф.3 (~37700-37900), callnorm/argbind.

### Ф.2 — `.nv`-бланкеты (`std/src/prelude/protocols.nv`)

`@checked_div`/`@checked_rem` → `Option[T]`, `@wrapping_div`/`@wrapping_rem` → `T` (паникуют
на `/0`, wrap только MIN/-1 — Rust-прецедент), `@checked_neg`/`@wrapping_neg` — ВСЕ ОДИН
`fn[T Ints]` бланкет (не split SignedInt/UnsignedInt), как и договорено планом.

**Реализационная находка (см. D426 §R4, задокументировано честно):** прямая signed-only
проверка (`rhs == -1`) НЕ компилируется для unsigned-члена `Ints`-моно (D227 Rule 4 — негативный
литерал в unsigned = hard error), а прямая `x == T.MIN`-ветка для `checked_neg` ИНВЕРТИРОВАНА
между signed/unsigned (не «схлопывается», как `saturating_*` в D423). Решение — reformulation
через уже-корректный (per D423) `@overflowing_sub`-флаг:
- div/rem MIN/-1-детект: `rhs.negate() == 1` вычисляется как `(rhs - rhs).overflowing_sub(rhs)`
  (receiver `rhs-rhs` вместо cast, см. ниже) — для unsigned провably `(1, false)` никогда не
  бывает (unsigned `checked_neg` успешен только на 0) → лишний guard математически no-op.
- `checked_neg`/`wrapping_neg`: `(0).checked_sub(x)`-эквивалент как `(x-x).overflowing_sub(x)` —
  ОБА случая (signed MIN, unsigned non-zero) корректны из ОДНОГО hardware-флага.

Попутно найден и обойдён pre-existing ICE (НЕ specific для div/neg, шире уже задокументированного
в D423 «Известные разрывы» частного случая): вызов ОДНОГО hand-written `.nv`-generic-blanket
(`@checked_sub`) ИЗНУТРИ ДРУГОГО generic-blanket-тела падает в
`[P67-LEGACY] method call return type unknown` НЕЗАВИСИМО от вида receiver'а (Ident/Cast/self —
все падают одинаково, эмпирически проверено). Обход — звать ТОЛЬКО компиляторный интринсик
`@overflowing_sub` напрямую (тот же вызов, что уже делают `@checked_sub`/`@wrapping_sub`/
`@saturating_sub`), никогда другой hand-written `.nv`-бланкет. Followup
`[M-206.1-nested-blanket-call-p67]` — отдельная волна (checker/codegen generic-return-type-
inference gap, не div/neg-specific).

## Границы / известные gaps (честно, followups)

- `[M-206.1-div-neg-z3-elision]` — Z3-сторона доказательства div/neg-safety не реализована
  (`prove_int_overflow_sites` фильтрует на Add/Sub/Mul); guard всегда emit'ится (корректно
  консервативно, не perf-оптимально).
- `[M-206.1-duration-div-neg-dedup]` (P3, opportunistic) — Duration `checked_div_i64`/`div_or_trap`/
  `checked_neg_i64`/`neg_or_trap` НЕ мигрированы на новые generic-бланкеты (уже D317-корректны,
  СВОИ panic-сообщения — миграция ради чистого dedup рискует поменять message-текст без
  функциональной необходимости; НЕ было явно в объёме плана, в отличие от 206 Ф.3 который явно
  называл Duration add/sub).
- `[M-206.1-nested-blanket-call-p67]` — nested `.nv`-blanket-в-blanket call ICE (см. Ф.2 выше),
  отдельная checker/codegen волна.
- Полный corpus-wide скан на латентные div-сайты (аналог 206's «Ф.2 раунд-2» находки для
  overflow add/sub/mul в vec/hash/etc) НЕ проводился этой волной — по инструкции (полный
  conformance = гейт оркестратора). Если оркестраторский полный прогон вскроет corpus-сайты,
  где деление могло молча зависеть от div-by-zero НЕ трапящего (маловероятно — раньше это был
  SIGFPE-крэш, а не тихое поведение, так что живого кода, ЗАВИСЯЩЕГО от старого UB, скорее всего
  нет) — см. прецедент `206-progress.md` Ф.2/Ф.3 раундов для методологии фикса.
