**Статус:** ✅ ЗАКРЫТ 2026-07-13 (D420; Ф.1-Ф.3 влиты — `00c0d085f`+`1e14481b8`: [replace]-секция + W_DEP_PATH_NO_RELEASE + lock-семантика (replace не течёт в lock); nova-http на git-форме v0.1.0 с lock в репе).
**Спека:** Q-dependency-versioning (open-questions.md); D-блок (07-modules/09-tooling) —

## Мотив

Межпакетные зависимости сегодня — только `{ path = "../..." }`: нет версии, нет источника
истины, сборка не воспроизводима вне машины автора. Взрослые экосистемы сходятся в одном
законе: источник (реестр/git) + семвер + lock-файл; path — только dev-режим
(Cargo запрещает публикацию с path-dep; Go решает это `replace`-директивой).

## Схема (школа Go/SwiftPM — реестра нет, версии по git-тегам)

- Релизная форма: `tls = { git = "https://github.com/nv-lang/nova-tls", version = "0.1" }`
  → теги `v0.1.x`, caret-семантика по умолчанию.
- Dev-override: `[replace]`-блок (`replace tls = { path = "../nova-tls" }`); голый path-dep
  вне replace при публикуемой сборке — диагностика.
- `nova.lock`: точный тег + commit-хэш; коммитится; манифест⁄lock-расхождение — ошибка.

## Фазы

### Ф.1 — манифест и резолвер
`[dependencies]` c `{git, version}`; фетч в кеш (`~/.nova/deps/<name>/<ver>` или
`target/deps`), выбор максимального совместимого тега; `[replace]` перекрывает источник.
Диагностики: нет тега, несовместимая версия, path вне replace.

### Ф.2 — nova.lock
Генерация при первом резолве; чтение — приоритетно (сборка по lock, не по диапазону);
`nova update [dep]` — пересчёт; проверка соответствия манифесту.

### Ф.3 — транзитивные зависимости
Резолв дерева; выбор версии: MVS (go-минимальная достаточная) — предлагаемый дефолт,
проще и детерминированнее unify; конфликт мажоров — ошибка с деревом причин.

### Ф.4 — миграция потребителей + D-блок
nova-http → git-форма на nova-tls (+ lock в репе); examples/флагман — replace для локальной
разработки; D-блок в спеку тем же слиянием; 203-пометка «до 204» снимается.

### Вне объёма
Реестр пакетов; checksum-база (аналог go.sum) — отдельным продолжением; публикация
(`nova publish`) — после реестра.

## Гейты
conformance полный; cross-package сборка nova-http по git-форме с чистого клона (без
сиблинг-папки nova-tls — докажет, что фетч работает); повторная сборка по lock байт-стабильна.
