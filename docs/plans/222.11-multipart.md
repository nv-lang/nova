# План 222.11 — модуль `polaris.multipart`: формы и загрузка файлов

**Статус:** ✅ РЕАЛИЗОВАН ЦЕЛИКОМ (ревизия 2026-07-31): Part/Multipart/лимиты (сверх плана — проводка через ServerPolicy), RFC 7578 парсер, base64, тесты.
222.7 (body-size limit — приземлять ВМЕСТЕ, иначе загрузка = DoS-вектор).
**Основа:** Axum `extract::Multipart` (форма API) поверх `multer`; RFC 7578 (multipart/form-data).
**Родитель:** [222](222-http-framework.md) · [222.0](222.0-module-map.md).

## 1. Зачем

Без multipart нет **HTML-форм и загрузки файлов** — базовая веб-функция, есть у всех
(это одна из немногих дыр, где Axum нас обгоняет: у него в коробке).

## 2. Типы

```nova
/// Одна часть формы.
export type Part value {
    priv name         str
    priv filename     Option[str]      // Some — это файл, None — обычное поле
    priv content_type Option[str]
    priv data         []u8
}
export fn Part @name() -> str => @name
export fn Part @filename() -> Option[str] => @filename
export fn Part @content_type() -> Option[str] => @content_type
export fn Part @bytes() -> []u8 => @data
export fn Part @text() -> Result[str, HttpError]      // UTF-8 декод с типизированной ошибкой

/// Разобранное тело multipart/form-data.
export type Multipart value { priv parts []Part }

#impl(FromRequest)
export fn Multipart.from_request(req ServerRequest) -> Result[Multipart, HttpError]
// boundary из Content-Type; отсутствие/битый boundary → HttpError{Protocol}

export fn Multipart @parts() -> []Part => @parts
export fn Multipart @field(name str) -> Option[Part]     // первое поле с именем
export fn Multipart @fields(name str) -> []Part          // все (чекбоксы/множественный выбор)
export fn Multipart @file(name str) -> Option[Part]      // только с filename
```

## 3. Лимиты (обязательны, не опция)

```nova
export type MultipartLimits value {
    priv max_parts     int    // по умолчанию 256
    priv max_part_size int    // байт на часть
    priv max_total     int    // суммарно (сверх body-limit 222.7)
}
export fn MultipartLimits.new(...) -> MultipartLimits   // + property-сеттеры mut @x(v) -> @
```
Превышение → `413 Payload Too Large` типизированной ошибкой. **Дефолты обязаны быть
консервативными** — иначе загрузка файлов становится DoS-вектором (прямое следствие аудита 222.6:
«безлимитное тело — единственный DoS-вектор»).

## 4. Границы V1

- **Только буферизованный разбор** (тело уже в памяти по 222.7) — потоковая загрузка на диск
  без буфера = отдельный заход, требует стриминг-тела;
- `Content-Transfer-Encoding: base64` — поддержать; экзотические кодировки — нет;
- вложенный `multipart/mixed` — нет (RFC разрешает, практика не использует).

## 5. Фазы

- **Ф.1** парсер boundary + разбор частей (чистые юниты на байтовых фикстурах, без HTTP).
- **Ф.2** `#impl(FromRequest)` + лимиты + 413.
- **Ф.3** аксессоры `@field`/`@file`/`@fields` + `@text()`.

## 6. Гейты

Юниты на фикстурах (в т.ч. злонамеренные: без финального boundary, part без имени, превышение
лимитов) + `nova test src` δ0 + интеграционный гейт зонтика. **Модель:** sonnet (парсер —
нетривиальная семантика, легко ошибиться на границах).
