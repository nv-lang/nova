# Возможности Claude Code — шпаргалка (для владельца)

> Заметка «на будущее»: что умеет Claude Code сверх обычного чата, и как этим
> пользоваться. Пользователю НЕ нужно знать синтаксис — всё вызывается
> **обычными словами**, инструменты вызывает ассистент под капотом.
> Составлено 2026-07-09 после знакомства с Artifact.

## Как этим пользоваться (главное)

Ты не вызываешь инструменты сам — **просишь словами**, ассистент делает.
Никакого синтаксиса, никаких команд в терминале. Просто говоришь, что хочешь.

---

## 1. Artifact — опубликовать HTML/Markdown как веб-страницу

**Что:** берёт самодостаточный `.html`/`.md` файл → заливает копию на claude.ai →
даёт ссылку (`claude.ai/code/artifact/<id>`). Рендерит и хостит сервер Anthropic,
НЕ твой компьютер.

**Как просить:** «сделай артефакт», «опубликуй как страницу, дай ссылку»,
«покажи в браузере, а не текстом», «обнови тот артефакт», «покажи мои артефакты».

**Важно:**
- Файл должен быть самодостаточным (весь CSS/JS внутри; внешние ссылки на
  шрифты/скрипты блокируются политикой безопасности).
- Правка файла на диске НЕ меняет страницу — нужен повторный вызов (тот же путь →
  та же ссылка перезаписывается).
- Копия уходит на сервер Anthropic; по умолчанию приватная (кнопка Share на
  странице — чтобы поделиться).
- В новом разговоре по умолчанию создастся новая ссылка; чтобы обновить старую —
  дай ассистенту её URL.

**Где полезно для Nova:** граф зависимостей планов, диаграмма эффектов/D-блоков
для nv-lang.org, прогресс-дашборд статуса планов, демо-мокапы фич языка.
*(Пример: `docs/research/assets/15-showcase-mockup.html` — флагманское демо.)*

## 2. Workflow — многоагентная оркестрация

**Что:** детерминированный скрипт, разворачивающий десятки агентов параллельно
с верификацией (fan-out → проверка → синтез).

**Как просить:** «используй workflow», «оркеструй это агентами», «пройдись
агентами по всем модулям».

**Где полезно для Nova:** massive-аудит (все std-модули / conformance разом),
миграции (net-sweep, Result-everywhere по всему коду), review с состязательной
верификацией (найти баги → независимо перепроверить).

**⚠️ Осторожно:** жрёт МНОГО токенов (у нас лимиты). Только под крупную задачу,
осознанно. Требует явного согласия («ultracode» или прямая просьба).

## 3. Скиллы (/команды) — готовые процедуры

- **/code-review** — ревью текущего диффа на баги (в тему нулевой толерантности;
  поймал бы codegen-баг вроде `Option[Node]` мис-мономорфизации).
- **/verify** — проверить, что изменение реально работает end-to-end (не только
  компилится). Для Nova — через C-codegen.
- **/simplify** — чистка кода (реюз, упрощения, без охоты на баги).
- **/deep-research** — многоисточниковое исследование с проверкой фактов
  (для research-доков вроде сравнения языков).
- **/security-review** — security-ревью изменений.

## 4. Автоматизация

- **Хуки** (settings.json) — «каждый раз при X делай Y» (напр. авто-`git diff
  --cached --stat` перед коммитом). Просить: «настрой хук, чтобы …».
- **/schedule** — регулярные задачи по cron (облачные агенты по расписанию).
- **/loop** — гонять prompt/команду на интервале (мониторинг CI, статуса).

## 5. Фоновые агенты и параллелизм

Несколько независимых задач разом (`run_in_background`, worktree-изоляция).
У нас уже есть свод правил в памяти (git stash запрещён при конкурентных
worktree, checkpoint-прогресс, resumeFromRunId при rate-limit и т.д.).
Модели по карте: haiku=механика, sonnet=исполнение, opus=разведка/архитектура.

## 6. Память

Персистентная файловая память ассистента (`~/.claude/.../memory/`) — переживает
сессии. Просить: «запомни это». Туда идёт durable feedback/reference, НЕ
plan-статус (source of truth = docs/plans/README.md, simplifications.md,
nova-private).
