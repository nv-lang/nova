# Conventions governance — изменения и отклонения ТОЛЬКО по согласованию

Этот файл управляет **всеми** конвенционными документами проекта Nova. Он нормативен и
сам подчиняется правилу ниже (правка этого файла — тоже по согласованию).

## Конвенционные документы (нормативные)

Обязательны для любого контрибьютора, включая AI-агентов:

- [dev-workflow.md](dev-workflow.md) — процесс разработки + **жёсткие операционные правила** (worktree-модель, никакого `git stash`, `git add` по именам файлов, коммит на задачу). Онбординг-вход для агентов — `AGENTS.md`; в порядок чтения добавлен в [promts/read-project.md](promts/read-project.md).
- [compiler-conventions.md](compiler-conventions.md) — разработка компилятора (front-end + codegen).
- [test-conventions.md](test-conventions.md) — написание и запуск тестов.
- [nv-coding-style.md](nv-coding-style.md) — стиль кода на Nova (`.nv`).
- [perf-conventions.md](perf-conventions.md) — производительность компилятора.
- [bench-conventions.md](bench-conventions.md) — бенчмарки.
- [lsp-conventions.md](lsp-conventions.md) — языковой сервер (наследует compiler-conventions).
- [project-philosophy.md](project-philosophy.md) — принятие дизайн-решений языка.
- [naming-conventions.md](naming-conventions.md) — продуктовые имена (Nova/Polaris/…) и имена артефактов (планы, маркеры, коды диагностик, ветки, фикстуры) · согласовано 2026-07-23.
- `spec/decisions/` (D-блоки) — нормативная семантика языка (spec-first).

## Главное правило

> **Конвенции НОРМАТИВНЫ. Любое ИЗМЕНЕНИЕ конвенционного документа и любое ОТКЛОНЕНИЕ от
> конвенции — ТОЛЬКО по явному согласованию с владельцем проекта. Не править и не
> отклоняться самовольно.**

Конкретно:

- **Изменение текста конвенции** (правка/добавление/смягчение/ужесточение правила) — сначала
  согласовать с владельцем, потом править. Коммит правки конвенции упоминает согласование. Дата
  согласования проставляется **ИНЛАЙН** у самого пункта (`· согласовано YYYY-MM-DD`) — отдельный
  changelog НЕ ведём (он дублировал бы и дрейфовал — §0-анти-паттерн самих конвенций). Аудит-трейл =
  git-история (каждый коммит правки упоминает согласование) + инлайн-дата у пункта.
- **Отклонение в коде/тестах** от конвенции — только как **согласованное исключение**,
  задокументированное на месте (комментарий + маркер `[M-*]`, где уместно) со ссылкой на причину.
- **Нашёл ошибку / противоречие / устаревание** в конвенции — НЕ чинить молча. Вынести владельцу
  с конкретным предложением (что не так + варианты + рекомендация), получить решение, затем править.
- **Конвенция vs реализация инструмента** (напр. `test-conventions.md` ↔ `test_runner.rs`): перед
  правкой конвенции проверить, что она не противоречит фактическому поведению инструмента;
  расхождение — повод согласовать, какую сторону менять.
- **Спека (`spec/decisions/`)** — spec-first: поведение решается в D-блоке по согласованию, потом
  кодируется (compiler-conventions §5).

## Конвенция не существует, пока не проверяется автоматически (· согласовано 2026-07-07)

Опыт: правило без механического гейта дрейфует (примеры: `to_bytes` вместо вида — 124
злоупотребления; старый синтаксис сумм — 65 файлов; явные `return @`). Поэтому:

> **Новая конвенция принимается ВМЕСТЕ с проверкой** — линт компилятора, greppable-инвариант
> (точная команда в тексте конвенции) или запрет на уровне языка (лучший вариант — неправильное
> невыразимо). Конвенция без проверки — пожелание, а не норма.

Свод машинных проверок принятых правил — план [185-nova-lint](plans/185-nova-lint.md). При
согласовании нового правила владельцем — сразу фиксировать и вид проверки.

## Один дом для каждого правила (· согласовано 2026-07-07)

Каждое правило живёт ровно в ОДНОМ нормативном месте; все прочие упоминания — **только
ссылкой**, без пересказа (пересказ = будущий рассинхрон):

| Что | Дом |
|---|---|
| семантика языка | `spec/decisions/` (D-блок) |
| стиль `.nv`-кода | `nv-coding-style.md` |
| процесс разработки компилятора | `compiler-conventions.md` |
| тесты / перф / бенчи / LSP | профильные `*-conventions.md` |
| статус плана | `**Статус:**`-строка в `docs/plans/NNN-*.md`; сводка — сгенерированный `docs/plans/STATUS.md` |

Нашёл пересказ-дубль — сворачивать в ссылку (это НЕ содержательная правка конвенции и
согласования не требует; менять формулировку правила при этом нельзя).

## Статус плана — только пофайлово, ручная сводная таблица запрещена (· согласовано 2026-07-15)

Статусы планов ведутся **ТОЛЬКО пофайлово** — строка `**Статус:**` в `docs/plans/NNN-*.md`.
Сводный обзор — **ТОЛЬКО** сгенерированный `docs/plans/STATUS.md` (регенерация:
`bash scripts/gen-plan-status.sh`).

> **Рукописная сводная индекс-таблица статусов планов (в README или где-либо ещё) ЗАПРЕЩЕНА** — она
> дублирует пофайловый статус и неизбежно дрейфует. Прецедент: индекс-таблица `docs/plans/README.md`
> застряла на редакции 2026-07-03, занижая статусы 180/202/203/204/205/206 (обнаружено git-сверкой
> 2026-07-13). Обзор — только через генератор.

Машинный страж: [`scripts/check-no-manual-status-table.sh`](../scripts/check-no-manual-status-table.sh)
греплет `docs/plans/README.md` на сигнатуру статус-реестра (строки вида
`| N | [файл](...) | ... | эмодзи-статус |`); при обнаружении ≥3 таких строк падает с ошибкой,
указывающей на этот раздел. Звать в приёмке правок `docs/plans/README.md` (кандидат на включение в
`nova lint`/CI — см. правило «конвенция не существует, пока не проверяется» выше).

## Почему

Конвенции — единый источник правды процесса. Самовольная правка/отклонение их форкает: разные
агенты следуют разным версиям, фикстуры/код дрейфуют, теряется доверие к документу. Согласование
держит конвенции консистентными и авторитетными.
