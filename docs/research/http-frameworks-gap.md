# nova-http (пост-222) vs FastAPI / Express / Axum — где хуже, где лучше, где некрасиво, где можем круче всех

**Дата:** 2026-07-22. **Автор:** оркестратор (opus), по запросу владельца.
**Предмет:** гипотетическое состояние `nova-http` ПОСЛЕ полного выполнения зонтика
[222](../plans/222-http-axum-parity.md) (Router с нуля + extractors + IntoResponse + middleware +
serde field-атрибуты (180.1) + run-loop hardening 222.7). Сверено с кодом пакета 2026-07-22.
**Это research-заметка, НЕ план.** Порождённые планы: 222.8 (compile-time OpenAPI),
222.9 (validation-derive) — см. §5.

## 1. Где мы ХУЖЕ

| Дыра | У кого есть | Оценка |
|---|---|---|
| **OpenAPI/Swagger** — нет вообще | FastAPI: генерит из типов + Swagger-UI бесплатно | 🔴 главный разрыв — у FastAPI это фича №1 продажи |
| **Валидация ЗНАЧЕНИЙ** (serde проверяет только типы) | Pydantic: `min_length`/`regex`/`ge`/`le`/кастом → 422 с путями полей | 🔴 «int» ≠ «int в 1..100»; каждый REST-API пишет руками |
| **Multipart / file upload** | все | 🔴 вне 222; без него нет форм/загрузок |
| **CORS, статика, сжатие, логирование, rate-limit** | Express (тысячи middleware), FastAPI/Starlette (в коробке) | 🔴 экосистемы нет — всё писать самим |
| **Auth-блоки** (OAuth2/JWT-скелеты, sessions) | FastAPI `Security`, Express passport | 🟠 есть только `cookie.nv` (10 экспортов) |
| **WebSocket** | все | 🟠 явно вне 222 |
| **Background tasks** | FastAPI `BackgroundTasks` | 🟢 `spawn` есть, http-обёртки нет |
| **Зрелость / боевые часы** | годы прода | — объективно |

## 2. Где мы ЛУЧШЕ

1. **must-consume `Body`** — компилятор не даст забыть закрыть тело (D133). Go течёт этим
   повсеместно, Node — забытые стримы. **Ни у кого нет.**
2. **Эффекты в сигнатуре хендлера** — на уровне типа видно, ходит ли он в сеть/время/ФС; мок —
   `with Net = mock_net()`. **Ни FastAPI, ни Axum такого не имеют в принципе.**
3. **Синхронный код без async-раскраски** (M:N-фибры) — FastAPI страдает `def` vs `async def`
   (sync-хендлер уезжает в threadpool; легко словить блокировку event-loop'а).
4. **State через замыкания, проверенные компилятором** — Axum `State<T>` паникует в рантайме,
   FastAPI `Depends()` резолвится в рантайме; у нас забыл зависимость → **ошибка компиляции**.
5. **Конфликт маршрутов = типизированная ошибка регистрации** (222.1) — Axum **паникует**,
   Express молча затеняет.
6. **Нулевая рантайм-рефлексия** — Pydantic валидирует обходом объектов в рантайме; у нас всё
   синтезировано компилятором (`auto_derive.rs`).
7. **Result-everywhere** (D325) — ошибки в типах, не летящие исключения.

## 3. Где НЕКРАСИВО (честно, о себе)

1. **`req.data.field`** — каждый хендлер начинается с распаковки обёртки. FastAPI отдаёт модель
   **сразу параметром**, Axum деструктурирует в сигнатуре. Наша форма — самая шумная из трёх.
2. **Арность-перегрузки 0..4** (222.3) — рукописное закрытое семейство с произвольным потолком.
   Пахнет как Rust-макросы для tuple-impl'ов, только без макроса.
3. **Двойная дверь регистрации** — сырой `Handler` + extractor-перегрузки (план сам отмечает
   D9-напряжение).
4. **Type-erasure посередине** — типизация extractors схлопывается в
   `fn(ServerRequest)->ServerResponse` и разворачивается обратно. Шов.
5. **Статус голым `int`** в конструкторах (`ServerResponse.text(200, …)`), хотя `StatusCode`
   типизирован (status.nv:14) — внутреннее противоречие.
6. **Рассинхрон роут↔хендлер — рантайм**: маршрут `/users` + хендлер с `Path[T]` = 500 на первом
   запросе (см. §4.2 — здесь же и возможность).

## 4. Где можем сделать КРУЧЕ ВСЕХ (следствия компилируемости)

### 4.1 OpenAPI, сгенерированный компилятором → **план 222.8**
Полная типовая информация есть на компиляции: маршруты — строковые литералы, extractors — типы,
serde-атрибуты — известны. Спека эмитится **как артефакт сборки**, всегда синхронна с кодом,
нулевая рантайм-цена, **без единой аннотации**. FastAPI делает это рефлексией в рантайме; в
компилируемом мире (Rust `utoipa`/`aide`) — руками, дублирующими аннотациями. Мы можем первыми
сделать это бесплатно.

### 4.2 Проверка «маршрут ↔ хендлер» на компиляции → **план 222.8** (родня 4.1)
`"/users/{id}"` — литерал; `Path[UserParams]` — тип с известными полями. Компилятор может сверить:
параметр `{id}` объявлен? поле `id` есть? тип парсится из строки? **Этого нет ни у кого** —
ни FastAPI, ни Axum, ни Express. Ловит целый класс 404/500-ошибок до запуска.

### 4.3 Валидация как compiler-derive → **план 222.9**
`#validate(min=1, max=100)` рядом с `#serde` — Pydantic-паритет, но синтез на компиляции, 422 с
путями полей из структурного `DeError`. Плюс: невалидный атрибут (`min` на `str`) → внятная
компиляторная диагностика, а не рантайм-сюрприз.

### 4.4 Тест-клиент уже бесплатен — **оформить, а не строить**
`Handler` = функция `fn(req)->resp`; тест = вызов функции, без сокета. FastAPI гордится
`TestClient` как фичей; у нас это следствие дизайна — надо задокументировать и показать в примерах.

### 4.5 Типизированный reverse-routing — кандидат, не план
Из тех же литералов генерить функции построения URL (`url_user(id)`), чтобы ссылки не били по
строкам. Ценность средняя, стоимость средняя — держать в уме после 222.8.

## 4а. Как ЭТИ ЖЕ дыры решает сам Axum (вопрос владельца 2026-07-23)

Важно для исполнителей под-планов: где Axum — годный ориентир, а где он сам пустой.

| Дыра | Решение Axum | Годится ли нам как образец |
|---|---|---|
| **OpenAPI** | **в коробке НЕТ.** `utoipa` — руками `#[utoipa::path(...)]` рядом с хендлером (дублирование, разъезжается с кодом); `aide` — параллельный API (`ApiRouter`/`api_route()`) | ❌ обе — «пиши дважды»; **ниша, где мы можем принципиально лучше** (222.8) |
| **Валидация** | **НЕТ.** Клей из трёх: serde → крейт `validator` (`#[validate(length(min=1))]`) → **свой** extractor `ValidatedJson<T>`, сцепляющий их (либо `axum-valid`) | ❌ три слоя; наш один derive (222.9) чище |
| **Multipart** | ✅ `axum::extract::Multipart` (feature-gate, поверх `multer`) — обычный extractor | ✅ **копируем форму** (222.11) |
| **CORS/static/gzip/логи/rate-limit** | ✅ `tower-http`: `CorsLayer`/`ServeDir`/`CompressionLayer`/`TraceLayer`/`TimeoutLayer`/`RequestBodyLimitLayer` | ⚠️ **это НЕ Axum, это tower** — см. §4б |
| **Auth/sessions** | НЕТ. `tower-sessions`/`axum-login`/`jsonwebtoken` + свой extractor, отдающий `Claims` | ⚠️ паттерн копируем, код пишем сами (222.13) |
| **WebSocket** | ✅ `WebSocketUpgrade` — тоже extractor | ✅ **копируем форму** (222.14) |
| **Background tasks** | НЕТ — «зови `tokio::spawn`» | нейтрально (у нас `spawn` так же) |

**Как Axum решает то, что у нас «некрасиво» (§3):** распаковка — паттерн в сигнатуре
(`Json(payload): Json<T>`, у нас такого нет → наш `.data` объективно шумнее); арность —
макрос `all_the_tuples!` до 16 (**та же проблема, спрятанная в макрос**); двойная дверь — у Axum
тоже две (`route`/`route_service`); **статус — `StatusCode` типизирован ВЕЗДЕ, кортеж
`(StatusCode::OK, Json(x))` реализует `IntoResponse` → здесь Axum ЧИЩЕ нас** (наш §3.5);
роут↔хендлер — рантайм-400, **compile-time сверки нет ни у кого**.

## 4б. Главный архитектурный ход Axum (и почему мы его НЕ повторим)

Axum **сознательно не строил middleware-слой** — он принял `tower::Service` как **общий
межфреймворковый стандарт**: один `CorsLayer` работает в Axum, tonic (gRPC), hyper-клиенте. Axum
выглядит тонким, но оснащён — он **арендует** экосистему, а не растит свою.

**У нас tower-эквивалента нет и не предвидится** (наш middleware — `fn(next Handler) -> Handler`,
222.4). Практическое следствие, которое исполнителю 222.12 надо принять сразу: **батарейки придётся
писать самим; ссылка «посмотри как в Axum» тут НЕ помогает** — у Axum их тоже нет, они у tower.

## 4в. Был ли выбор Axum за основу правильным (стратегическая оценка 2026-07-23)

**Да — для того слоя, к которому мы его применили; нет — как потолок амбиции.**

**Что взято верно** (языко-нейтральное, лучшее в классе): модель роутинга (trie/precedence/nest/
MethodRouter — у Axum от `matchit`), **extractor-паттерн** (типы параметров управляют извлечением),
`IntoResponse`, Handler-как-функция. Это скелет фреймворка — и он у Axum действительно хорош.

**Чего Axum не мог дать в принципе:** экосистему (она у tower), OpenAPI, валидацию. Ждать этого от
Axum — категориальная ошибка, а не промах выбора.

**Где форма Axum нам ДОРОГО обходится** — она оптимизирована под ограничения Rust, которых у нас нет:
паттерн-деструктуризация в сигнатуре (нет → шумный `.data`), макро-арность (нет макросов → рукописные
0..4), tower (нет → батарейки свои), async (у нас фибры — здесь мы, наоборот, ВЫИГРЫВАЕМ).
Три из четырёх пунктов нашего §3 «некрасиво» — прямое следствие копирования формы Axum.

**Реальная ошибка была не в выборе образца, а в НАЗВАНИИ ПЛАНКИ.** «Паритет с Axum» звучит как
«догнали Axum = готово», тогда как Axum — это скелет, а продуктовую планку задаёт **FastAPI**
(OpenAPI + валидация из типов). Правильная формула:
> **скелет — по Axum; продуктовая ценность — по FastAPI; механизм — наш (синтез на компиляции,
> а не рантайм-рефлексия Pydantic и не дублирующие аннотации utoipa).**

**Свежая проектная мысль, порождённая этим сравнением (кандидат в 222.8):** для compile-time
верификации «маршрут ↔ хендлер» **FastAPI-модель ко-локации** (декоратор `@app.get("/users/{id}")`
ПРЯМО НАД функцией) удобнее Axum-модели (регистрация отдельно от определения). У нас есть атрибуты
(`#impl`/`#serde`) — форма `#route(get, "/users/{id}")` над хендлером дала бы компилятору путь и
сигнатуру В ОДНОМ МЕСТЕ, что делает сверку тривиальной. Оценить в 222.8 как альтернативу/дополнение
к императивной регистрации (не вместо — императивная нужна для динамики).

## 5. Вывод

После полного 222 nova-http **сильнее Express и Axum по гарантиям** (must-consume, эффекты,
compile-time state, типизированные конфликты маршрутов) и **наравне по эргономике**; но
**заметно слабее FastAPI по продуктовой части** — OpenAPI, валидация значений, батарейки.

Ключевое наблюдение: **три из пяти пунктов §4 достижимы именно потому, что мы компилируемый язык
с синтезом** — и ни один из них в 222 не был запланирован. Отсюда два новых под-плана:
- **222.8** — compile-time OpenAPI + route↔handler-верификация (§4.1 + §4.2, одна инфраструктура);
- **222.9** — validation-derive (§4.3).
