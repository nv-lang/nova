# Research: print/println полностью на nv — `[M-println-lowering-onto-nv-print-str]`

**Статус:** исследование к GO-решению владельца (маркер ЗАМОРОЖЕН — реализация только по
явному GO; этот док — подготовка решения, не реализация). 2026-08-01, интегратор.

## 1. Что есть сейчас (инвентарь сносимого)

- `print`/`println` — `extern "nova" fn (...items []any)` в прелюдии (`prelude/runtime.nv:70,82`),
  но вариадик **фиктивен**: компилятор special-case'ит вызов ДО обычного пути
  (`emit_c.rs:37896`) и печатает каждый аргумент отдельно.
- `emit_println` + `make_print_call` + `infer_print_helper` (`emit_c.rs:45067..45150`) —
  **~190 LOC** компиляторного диспетча по `infer_expr_c_type` на 6 rt-хелперов.
- rt-семейство (`nova_rt.h:481-498`): `nova_print_int/f64/f32/bool/str/char/newline` — 7 функций.
- **Дефекты статус-кво** (лечатся предлагаемым переносом):
  1. fallback `_ => nova_print_int` — **юзер-тип печатается как `%lld`-мусор** (адрес/каст) —
     тот же класс, что закрытый D229-баг интерполяции; `println(user)` молча врёт, тогда как
     `println("${user}")` либо зовёт Display, либо даёт честную ошибку.
  2. `char`-ПЕРЕМЕННАЯ печатается code-point'ом (`%lld`), не UTF-8 (AD3 «deferred», комментарий
     в самом `infer_print_helper`) — `println(c)` ≠ `println("${c}")`.
  3. Параллельный диспетч = вечный дрейф от интерполяции (f64-расхождение `%g` уже чинили
     Plan 180-заплаткой в rt).

## 2. Находка, меняющая дизайн: мокабельный stdout УЖЕ СУЩЕСТВУЕТ

`std/io/console.nv` (Plan 176, D322 §3c): **эффект `Io`** с опами `write_out(data []u8)` /
`write_err` / `read_in`, `#default_handler` → `real_io()` (fd-хуки), `mock_io(cap)` **капчурит
stdout/stderr в тестах** с нулевым изменением тестируемого кода. То есть «крошечное ядро
print_str» из эскиза маркера **не нужно как новый extern** — ядро печати уже есть:
`Io.write_out(s.bytes())`.

## 3. Целевая архитектура (путь A — рекомендация)

`println(a, b, …)` лоуэрится компилятором как **синтез интерп-строки** и переиспользует
`emit_interpolated_str` целиком:

```
println(a, b)  ≡компилятор≡  print_str("${a}${b}\n")
```

- Аргументы → `InterpStrPart::Expr` (spec = None/Display), `"\n"` — финальный `Lit` (только println).
- Весь диспетч/рендер — **уже существующий .nv-движок** (`*_display_spec`-семья, Plan 208;
  юзер-типы → `@display`; девиртуализация примитивов; честная `E_INTERP_NO_DISPLAY`).
- Финальный вывод — ОДИН вызов ядра печати (см. §4) со строкой из StringBuilder.
- Сносится: ~190 LOC `emit_println`-семьи → ~15 LOC синтеза; 6 из 7 rt-хелперов
  (остаётся только байтовый вывод).

**Путь B (отвергнуть):** «честное» .nv-тело `fn println(...items []any)` с dyn-Display по any —
требует боксинга каждого аргумента + vtable-dispatch на горячем пути; вариадик-гетерогенность
через any = аллокации там, где A обходится статикой. Маркер путь A и описывает.

## 4. Эффект-статус — ЦЕНТРАЛЬНЫЙ вопрос к GO (три варианта)

| вариант | как | плюс | минус |
|---|---|---|---|
| **(а) ambient extern** (статус-кво-минимум) | ядро = `extern print_str(s str)` поверх `nova_print_str`, без эффекта | ноль изменений для пользователей | вывод НЕ мокается; вторая дверь мимо `Io` |
| **(б) оп `Io` явный** | `println` получает `Io` в сигнатуре | честно по D62/№131 | **вирус**: `Io` расползается по каждой сигнатуре с println — под `--strict-effects` заражает всё |
| **(в) оп `Io` через `#default_handler`, ambient-статус как у `Log`** ⭐ | печать идёт в `Io.write_out`, default → stdout, подписи не заражает | **тесты капчурят println бесплатно** (`mock_io`); одна дверь вывода; Log/Fs-прецедент D431 уже в проде | нужен пин: ambient-оп против №131-энфорса (у `Stdin @read` `Io` ЯВНЫЙ — согласовать статусы) |

Рекомендация — **(в)**: главный продуктовый выигрыш переноса — не «минус LOC», а
**перехватываемая печать** (капчур stdout в тестах без процесс-обвязки), и он достаётся
только через `Io`. Пин Ф.0: как D431-механика сочетается с №131 «Io now explicit» —
возможно, печать станет вторым легальным ambient-ом рядом с `Log` (решение владельца).

## 5. Behavior-changes (все — к лучшему, но фиксировать пин-тестами)

| было | станет |
|---|---|
| `println(user_type)` → `%lld`-мусор | Display-вызов либо честная ошибка компиляции |
| `println(char_var)` → code-point числом | UTF-8 символ (паритет с интерполяцией) |
| `println(a, b)` → N syscall-ов (по хелперу на арг) | один write целой строки (лучше и для конкурентного вывода — строка атомарнее) |
| f64/f32 | без изменений (rt уже на shortest-движке Plan 180 — Ф.0-сверка байт-паритета) |

## 6. Перф-заметка

Сейчас `println("x")` = 1 `fwrite`; путь A наивно даст StringBuilder-аллокацию на каждый вызов.
Митигация — peephole: единственный аргумент типа `str` (и без `\n`-склейки — или со склейкой
через второй write) → прямой вызов ядра без SB. Для мульти-аргументов SB оправдан (сейчас там
N вызовов + printf-форматирование).

## 7. Фазы (после GO)

- **Ф.0 пины:** (1) синтез `InterpStrPart`-списка из аргов + переиспользование
  `emit_interpolated_str` — техпроба; (2) эффект-статус (§4, решение владельца); (3) байт-паритет
  f64/f32/bool печати (`nova_f64_shortest` rt vs `f64_display_spec` .nv — один ли движок);
  (4) `spread` в println (сейчас `Err`) — оставить Err или поддержать; (5) судьба `print` без
  аргументов / `println()` (голый newline).
- **Ф.1:** ядро по решению §4 (в), синтез-лоуэринг, peephole §6.
- **Ф.2:** снос `emit_println`-семьи + 6 rt-хелперов; фикстуры-паритет по таблице §5
  (снапшот вывода ДО/ПОСЛЕ по всем типам; интенциональные изменения — отдельными пинами).
- **Гейт:** мега-CU + флагман (println — везде); вывод-снапшоты.
