# Канон записи sink/мутируемых параметров: `mut w Write` vs R2-split (`ro w mut Write`)

**Дата:** 2026-07-16
**Тип:** исследование с рекомендацией (правок кода нет)
**Повод:** архивное обсуждение D374 — «строже даже вторая [форма] — она честнее
выражает намерение "пишу в sink, но не подменяю его"; канон std/спеки, тем не менее,
`mut w Write` (D374)».
**Ветка:** `research-mut-canon` (worktree `nova-mutcanon`); бинарь main-репо
(`nova-cli/target/release/nova.exe`) для микропроб.

---

## 0. Короткий ответ

**Оставить канон `mut f Fmt` / `mut w Write`.** Для sink R2-split (`ro f mut Fmt`)
честнее по букве, но не добавляет реальной защиты: sink — всегда **кучевой handle**,
поэтому единственное, что R2-split запрещает сверх статус-кво — переприсваивание
биндинга (`f = other`) — для handle **локально и невидимо вызывающему** (не footgun),
а value-тип-in-out-опасность («переприсвоил → записал сквозь») к sink не применима
вовсе. Взамен R2-split облагает 2 лишними токенами САМУЮ частую сигнатуру языка
(каждый `@display`/`@debug`) навсегда и требует lock-step миграции декларации
протокола + синтезатора авто-derive. Рекомендация: закрепить чтение намерения одной
строкой в `nv-coding-style §18` + короткий уточняющий аменд к D374/D422; R2-split —
санкционированное, но НЕ канонное строгое написание.

## 1. Фактическая семантика по спеке

### 1.1 D246 — три оси мутабельности (источник «R2-split»)

`spec/decisions/02-types.md:9672` — `## D246. Три оси мутабельности: L1 binding /
L2 view / L3 pointee`. Оси (`:9691-9695`):

- **L1 — binding**: переприсваиваемость имени (`x = …`); маркер `ro`/`mut` ПЕРЕД именем.
- **L2 — view**: транзитивный ro/rw по owned-графу значения (`.field`/`[i]`), стена на
  каждом `*`; маркер `ro`/`mut` ПЕРЕД типом.
- **L3 — pointee**: запись за `*`; постфикс `*T`(ro)/`*mut T`(mut).

«R2-split» — это именно D246, раздел `### R1 vs R2` (`:9806-9811`):

> - **R1 (transitive-ro)** = закон L2: `-> ro Value` морозит owned-граф.
> - **R2-split** = явный opt-in пары (L1,L2): `ro r mut Point` / `mut r ro Point`
>   (см. P6). Голый `ro r` = freeze (P7).

Таблицы истинности (знаки = ЗАПИСЬ):

Локальные биндинги (`:9748-9751`):
| Форма | reassign (L1) | `.field`/`[i]` (L2) |
|---|---|---|
| `ro a T` | ❌ | ❌ (P7 freeze) |
| `mut a T` | ✅ | ✅ |
| `ro a mut T` | ❌ | ✅ (**R2-split**) |
| `mut a ro T` | ✅ | ❌ (**R2-split**) |

Параметры (ro по умолчанию, D176) (`:9757-9759`):
| Форма | `v = x` | `.field`/`[i]` write |
|---|---|---|
| `v T` ≡ `ro v T` | ❌ E_LOCAL_NOT_MUT | ❌ E_READONLY_CONTENT |
| `mut v T` | ✅ | ✅ |
| `mut v ro T` | ✅ | ❌ E_READONLY_CONTENT |

Итак «пишу в sink, но не подменяю его» = **content✅ / reassign❌** = форма
`ro w mut Write` (строка «`ro a mut T`» из таблицы биндингов, R2-split). Для параметра
она валидна (L1 `ro` явный снимает дефолт-редундантность, L2 `mut` — не freeze).
P6 (`:9792-9793`): `ro r mut Point` (reassign❌/content✅) — «разрешает
[M-138-binding-type-mut-conflict]».

### 1.2 D326-ревизия (Plan 184) — что такое `mut x T`-параметр СЕЙЧАС

`spec/decisions/02-types.md:14312` — `## Ревизия D326 (Plan 184): ref T —
ограниченный тип` (🟢 РЕАЛИЗОВАНО ПОЛНОСТЬЮ, Р1–Р14).

- **Р3/Р10** (`:14357-14368`, `:14418-14421`): `f(mut x T)` ≡ **in-out ссылка ВСЕГДА**
  (унификация стека/кучи). Приватной копии больше нет; локальная копия — явным
  `mut y = x`. Слово `ref` из сигнатур параметров удалено.
- **Р2** (`:14353-14355`): в `mut`-контексте ссылки `mut` = право ПИСАТЬ через ссылку в
  цель; сама ссылка **непереселяема** (C++ `T&`: связал — навсегда).
- **Р11** (`:14423-14427`): семантика `mut x T` сменилась (была приватная копия → стала
  in-out) — предписан grep-аудит std/тестов на тех, кто полагался на приватность копии.

Это и есть премисса владельца: `mut a Job` для параметра работает как ref (мутация
видна вызывающему), для стекового значения — мутирует оригинал.

### 1.3 D374 / D422 — sink-протоколы

`spec/decisions/02-types.md:13162` — `## D374. Write-sink протокол`. Исторический текст
(`:13182-13193`): `protocol Write { mut @write_str(s str) }`,
`@display(mut w Write)`, `@debug(mut w Write)`. AMEND ×2 (D422, `:13164-13171`):
sink `Write`→**`Fmt`** (Fmt embeds Write через `use`, D145), `@write_str(str)`→
`@write(bytes []u8)`. Текущее std-состояние (`std/src/prelude/protocols.nv`):
- `:228-229` `export type Write protocol { mut @write(bytes []u8) -> () }`
- `:252` `export type Fmt protocol { … use Write … }`
- `:397` `export type Display protocol { @display(mut f Fmt) -> () }`
- `:431` `export type Debug protocol { @debug(mut f Fmt) -> () }`
- `:342` `export fn FmtCtx mut @write(bytes []u8) -> () { @sink.write(bytes) }`

ABI (D422, `:15062-15065`): `Fmt` эрайзится к `Nova_FmtCtx*` тем же приёмом, что `Write`
к `Nova_StringBuilder*` — **оба sink суть кучевые handle-типы (C-тип с суффиксом `*`)**.

## 2. Фактика по коду (кодоген)

`compiler-codegen/src/codegen/emit_c.rs`:

- **`param_is_inout_ptr`** (`:49509-49515`): `mut x T` лоуерится в by-pointer in-out
  (`T*`) ТОЛЬКО если `is_mut && !consume && ty_c != nova_unit && !ty_c.ends_with('*') &&
  is_value_type(ty_c)`. То есть **только value/примитив**. Для handle-типа (C-тип уже
  `…*`, напр. `Nova_FmtCtx*`/`Nova_StringBuilder*`) → false: handle передаётся как есть.
- Тело fn (`:24168-24180`): для `mut`-параметра, прошедшего `param_is_inout_ptr`, имя
  вносится в `ref_params` → чтения/записи авто-дереференсятся (`name` → `(*name)`).
  Отсюда: для value-типа `x = v` компилируется в `*x = v` = **сквозная запись**
  (видна вызывающему).
- Регистрация call-site inject address-of (`:13913-13928` `free_fn_inout_params`;
  `synthesize_inout_refargs`).
- Ось режима параметра — часть overload-ключа (Р13/Р14, `param_modes`,
  `narrow_by_param_mode` `:15914`), но C-символ получает mode-суффикс ТОЛЬКО при
  коллизии одинаковых `param_c_types` (кучевой случай Р6) — существующие символы
  byte-identical.

**Вывод по кодогену.** Для sink (handle) `mut w Write` / `mut f Fmt`:
- content-запись (`w.write(...)`) идёт через shared handle → **видна вызывающему**
  (то, что нужно sink);
- переприсваивание биндинга (`w = other`) — обычный локальный ре-байнд указателя,
  **невидим вызывающему** (handle НЕ в `ref_params`);
- value-тип-in-out-эффект («reassign пишет сквозь») к sink **не относится** — sink
  никогда не value-тип.

### Расхождение спеки, попутно найденное

Таблица D246 для параметра (`:9758`) даёт `mut v T` → `v = x` ✅ с пометкой «reassign
локальной копии (не виден снаружи)». Для VALUE-типа это **устарело** после Plan 184:
`mut x T` — in-out `T*`, `x = v` → `*x = v` (видно снаружи), приватной копии нет
(Р3/Р10). Для handle пометка верна. Строку 9758 стоит согласовать с Р2/Р10
(документ-долг, не блокер).

## 3. Инвентарь текущего употребления (std после Plan 208)

Grep `mut \w+ Write | mut \w+ Fmt` по `std/src`: **45 совпадений в 10 файлах**, из них
2 — локальные биндинги (`std/src/runtime/write_buffer.nv:51,78`
`mut wb WriteBuffer = {…}`), НЕ параметры. Остальные ~43 — исключительно параметры
`@display`/`@debug` (+ 2 декларации протокола):

- `std/src/prelude/protocols.nv` — примитивы `int/f64/f32/bool/char/str`,
  `Option[T]`/`Result[T,E]` (`:655-806`), протоколы `Display`/`Debug` (`:397,431`);
- `std/src/collections/vec/protocols.nv:201,213` — `Vec[T]`;
- `std/src/encoding/json.nv:907` — `JsonValue @display(mut f Fmt)`;
- ещё на `mut w Write` (НЕ мигрированы на Fmt): `std/src/time/duration.nv:667,673`,
  `monotonic.nv:161,168`, `timestamp.nv:144`, `civil/format.nv:278-303` (7 шт).

Тела **все** — чистый sink-write вида `w.write(@to_iso().bytes())` /
`f.write("${@}".bytes())`. **Ни одного переприсваивания sink-параметра
(`w = …`/`f = …`).** Риск-класс, который R2-split запретил бы, в std **отсутствует
полностью** (0 мест).

> Примечание: остаток `mut w Write` в `time/*` — это незакрытый хвост миграции
> Write→Fmt (D422 Ф.3/Ф.4), ортогональный вопросу канона режима (`mut` vs `ro _ mut`).

## 4. Микропробы (main-репо `nova check`, синхронно)

Тип `Pt value { x int }`, вызов через `${p}` / generic `render[T Display]`.

| Проба | Сигнатура | Тело | Результат |
|---|---|---|---|
| A | `Pt @display(f Fmt)` (bare, дефолт-ro) | `f.write(...)` | **PASS** |
| B | `Pt @display(ro f mut Fmt)` (R2-split) | `f.write(...)` | **PASS** |
| C | `Pt @display(mut f Fmt)` | `f = f; f.write(...)` | **PASS** (reassign легален) |
| D | `Pt @display(f Fmt)` + `render[T Display]` | — | **PASS** |

Выводы:
1. **`mut` на sink-параметре функционально НЕ load-bearing.** Bare `f Fmt` (проба A)
   компилируется и вызывает `mut @write` — хотя `@write` объявлен `mut @`
   (`protocols.nv:229`), а `nv-coding-style §18` (`:543-545,561`) обещает
   `E_PARAM_NOT_MUT` при вызове mut-метода на bare-параметре. Для protocol-типизированного
   handle-sink эта проверка **не срабатывает** — латентная леность чекера (см. §6).
2. **R2-split (`ro f mut Fmt`) — валидная форма параметра** и работает как sink (проба B).
3. **Переприсваивание mut-handle-параметра легально** (проба C) — но, по §2, локально.
4. **Conformance ЛЕНИВ к режиму параметра** (проба D): impl `@display(f Fmt)` удовлетворяет
   `T Display`, хотя декларация — `@display(mut f Fmt)`. То есть смешанные режимы
   сосуществуют без слома bound (снижает миграционный риск, но сам по себе — вероятный
   латентный gap: impl-сигнатура «должна» совпадать с протоколом).

## 5. Сравнение кандидатов канона

| Критерий | (а) `mut w Write` / `mut f Fmt` (статус-кво) | (б) R2-split `ro w mut Write` / `ro f mut Fmt` | (в) bare `w Write` / `f Fmt` |
|---|---|---|---|
| Честность намерения | среднее: `mut` = «пишу, видно вызывающему» — верно; но `mut` даёт и право ре-байнда, конфлатит «пишу в» и «могу подменить» | **высшая**: L1 ro = «не подменяю», L2 mut = «пишу в содержимое» — ровно намерение | низшая: читается как чистое чтение, СКРЫВАЕТ, что sink пишется |
| Реальная защита для sink (handle) | — | **≈ноль**: запрещает лишь локальный невидимый ре-байнд; value-in-out-опасность к sink неприменима | отрицательная (полагается на леность чекера) |
| Миграционная цена | **0** (уже канон) | ~43 сигнатуры std + декл. `Write`/`Fmt`/`Display`/`Debug` + синтезатор авто-derive (`auto_derive.rs` эмитит `mut f Fmt`) + примеры + аменд D374/D422 + nv-coding-style | 0 по коду, но противоречит §18 и рискует сломаться при ужесточении чекера |
| Совместимость с протоколом (#impl == декл.) | согласовано (декл. и impl оба `mut`) | требует lock-step смены декларации + синтезатора, иначе декл.≠impl (хоть conformance и ленив — канон должен быть когерентным) | декл. `mut` vs impl bare — расхождение |
| Эффекты/чекер | без изменений | без изменений семантики эффектов; но чекер сейчас не enforce-ит L1/L2-различие на protocol-sink (проба B) — гарантия декларативная | зависит от лености |
| Вербозность на самой частой сигнатуре языка | минимальная (`mut f`) | +2 токена на КАЖДЫЙ `@display`/`@debug` навсегда | минимальная |

Отвергнутые формы: `consume w Write` — передаёт владение (sink переживает вызов у
вызывающего) — не подходит; `mut w ro Write` — reassign✅/content❌ = ровно наоборот
(запрещает саму запись) — бессмысленно для sink.

**Ключевой аргумент против R2-split как канона.** Единственное, что R2-split
добавляет к статус-кво для sink — бан `f = other`. Но sink — всегда handle, и этот
ре-байнд локален и невидим вызывающему (§2): не footgun, а максимум смелл для линта.
Опасность, которая ДЕЙСТВИТЕЛЬНО мотивирует осторожность с `mut`-параметром
(value-тип in-out: `x = v` пишет сквозь), к sink не возникает по построению. То есть
R2-split платит вербозностью на самой частой сигнатуре языка и lock-step-миграцией
ради ≈нулевой выгоды по безопасности. Плюс сам чекер сейчас L1/L2-различие на
protocol-sink не enforce-ит (проба B прошла при L1=ro) — «честность» R2-split пока
декларативна.

## 6. Рекомендация

**Оставить `mut f Fmt` / `mut w Write` каноном.** Это кратчайшая форма, честно
сигналящая «сюда пишут», совпадающая с декларацией протокола (impl матчится по
построению) и с нулевой миграционной ценой. Вместо смены канона — **зафиксировать
чтение намерения** и санкционировать R2-split как опциональное строгое написание:

- одна строка в `docs/dev/nv-coding-style.md §18`: для sink-параметров (`Write`/`Fmt`)
  `mut` означает «в него ПИШУТ» (видимо вызывающему), НЕ «его можно подменить»;
  переприсваивание sink-параметра — смелл (в std не встречается); если нужна
  самодокументирующая строгая форма — санкционировано `ro f mut Fmt` (R2-split,
  D246-P6), но это НЕ канон;
- короткий уточняющий аменд-абзац к D374/D422 с тем же текстом + cross-ref на D246
  (R2-split) и Plan 184 Р2/Р10 (почему для handle-sink ре-байнд невидим).

### Черновик аменда (в `nv-coding-style §18`)

> **Sink-параметры (`Write`/`Fmt`) — режим `mut`.** Канон:
> `fn T @display(mut f Fmt)`, `fn T @debug(mut f Fmt)`, любой приёмник sink —
> `mut w Write`. Здесь `mut` читается как «в sink ПИШУТ» (append, виден вызывающему),
> НЕ «sink можно подменить». Sink — кучевой handle: переприсваивание биндинга
> (`f = other`) локально и невидимо вызывающему — избегать (смелл). Если требуется
> самодокументирующий строгий запрет подмены, санкционирована R2-split-форма
> `ro f mut Fmt` (D246-P6: L1 ro = не ре-байндится, L2 mut = пишется в содержимое) —
> но каноном она НЕ является: `mut f Fmt` короче и совпадает с декларацией протокола.
> Bare `f Fmt` для sink ЗАПРЕЩЁН (скрывает запись; см. также латентную леность чекера,
> §leniency).

### Черновик аменд-абзаца к D374 (после AMEND ×2)

> **AMEND (2026-07-16, канон режима sink-параметра).** Режим sink-параметра
> `@display`/`@debug`/приёмников `Write` — **`mut`** (`mut f Fmt` / `mut w Write`).
> `mut` тут = «пишу в sink» (Plan 184 Р10: для кучевого sink `mut` не вводит in-out
> `T*` — sink уже handle, `param_is_inout_ptr`=false; запись идёт через shared handle,
> видна вызывающему; ре-байнд биндинга локален/невидим, Р2). Строгая
> самодокументирующая альтернатива `ro f mut Fmt` (D246 R2-split, content✅/reassign❌)
> — санкционирована, но НЕ канон (вербозна на самой частой сигнатуре языка; сам чекер
> L1/L2-различие на protocol-sink пока не enforce-ит). Bare `f Fmt` запрещён конвенцией
> (`nv-coding-style §18`).

### Оценка миграции рекомендации

- Код Nova: **0 правок** (канон уже действует).
- Документация: 1 абзац в `nv-coding-style §18` + 1 аменд-абзац в D374 (02-types.md).
  Оба — язык-НЕ-меняющие (фиксируют существующее поведение) → отдельный D-аменд для
  push не требуется по правилу lang-change (поведение не меняется).
- Опционально (не в этой волне): согласовать устаревшую строку таблицы D246 `:9758`
  (value `mut v T` reassign) с Plan 184 Р2/Р10.

## 7. Что осталось решить владельцу

1. **Принять рекомендацию** (канон = `mut f Fmt`, R2-split — опция) — или
   всё же переключить канон на R2-split (тогда: lock-step миграция ~43 сигнатур +
   деклараций протоколов + синтезатора авто-derive `auto_derive.rs` + аменд D374/D422;
   выгода — декларативная честность, безопасность ≈0 для handle-sink).
2. **Два латентных наблюдения чекера** (не блокеры, но объясняют, почему «честность»
   R2-split сейчас не enforce-ится) — чинить отдельной волной или зафиксировать как
   ожидаемое:
   - bare `f Fmt` вызывает `mut @write` без `E_PARAM_NOT_MUT` (проба A) — леность
     mut-receiver-проверки для protocol-типизированного handle-параметра, тогда как
     `nv-coding-style §18` обещает `E_PARAM_NOT_MUT`;
   - impl `@display(f Fmt)` удовлетворяет `T Display` при декларации `mut f Fmt`
     (проба D) — conformance не сверяет режим параметра с протоколом.
3. **Документ-долг D246 `:9758`** — согласовать «`mut v T` reassign = локальная копия»
   с Plan 184 (для value-типа теперь in-out сквозная запись) — чинить сейчас или пометить.
4. **Хвост Write→Fmt** в `time/*` (7 `mut w Write`) — ортогонален канону режима, но если
   трогать эти файлы под рекомендацию — заодно домигрировать на `mut f Fmt` (D422 Ф.3/Ф.4).
