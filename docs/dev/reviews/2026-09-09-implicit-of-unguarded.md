# Охота (novac): тотальная дверь `implicit_of` спрашивается без стража, и множества у чекера с принтером РАЗНЫЕ

**Кто:** интегратор, 2026-09-09, по заданию владельца «поиск дыр в реализации
Карины». **Метод:** чтение, без запусков (машина у окна 274).

**Наводка окна 274, по которой шёл поиск, — их формулировка:** искать не «где
канал пуст», а **«где потребитель ОДИН и он знал форму заранее»**: там вопрос
никогда не задавался, и пустота невидима.

## Находка одной фразой

`@implicit_of` объявлена **TOTAL** и на дыре падает ICE, у неё **два**
потребителя — и один из них спрашивает её **без стража**, при том что условия, по
которым чекер пишет в эту таблицу, **уже́ и не совпадают** с условием, по которому
принтер её читает.

## Что прочитано, дословно и с адресами

**Дверь** (`novac/src/sem/channel.nv:449`):

```
/// The implicit call recorded at this node. TOTAL, like `callee_of`: ask
/// `has_implicit` first.
export fn CheckOut @implicit_of(id NodeId) -> CalleeRef
```

Докстрока прямо велит: **спроси `has_implicit` сначала.**

**Потребитель 1 — соблюдает** (`novac/src/mono/mono.nv:335-336`):

```
if is_node(id) && out.has_implicit(id) {
    if mark_ref(out.implicit_of(id), ...)
```

**Потребитель 2 — НЕ соблюдает** (`novac/src/emit_c/emit_interp.nv:84`):

```
None => {
    // A DECLARED type with its own `@display` (274.7 B1b-1): the
    // checker recorded the call the slot MAKES in the channel's
    // implicit table ...
    ro row = @out.implicit_of(c.id_of()).callable_row()
```

**Единственный писатель** (`novac/src/check/exprs.nv:355-371`) пишет **только**
при двух условиях сразу:

1. `@ctx.tys.kind_of(st) != TypeKind.TkApp` — обобщённый экземпляр (`Box[int]`)
   отсекается раньше: `@report_first_leaf_of(...); return`;
2. `@display_row_of(@display_key_of(st))` вернул `Some(row)` — иначе снова
   `report; return`.

**А принтер входит в свою ветку по ДРУГОМУ условию:** `None` от
`prim_row_of(@ctx.tys, slot_t)`, то есть «тип слота — не примитивная семья».

## Почему это дыра, а не придирка

Множество «не примитив» **шире** множества «не-обобщённый тип, у которого есть
`@display`». Разница видна прямо: **обобщённый тип с `@display`**. Чекер на нём
отказывает и НИЧЕГО не пишет; принтер на нём получает `None` от `prim_row_of`,
входит в ту же ветку и зовёт тотальную дверь — то есть ICE
`«implicit_of on a node with nothing recorded — a hole in the channel»`.

**И самое дорогое здесь — не сам ICE, а куда он показывает.** Сообщение обвиняет
КАНАЛ, а чинить надо ветку принтера. Ровно тот класс, за которым мы охотимся вторые
сутки: инструмент отвечает не на тот вопрос, который ему задан.

Комментарий в принтере утверждает «the checker recorded the call» — это верно для
ПЕРЕСЕЧЕНИЯ множеств, а стоит над веткой, которая шире пересечения. Гарантия
названа шире той, что выполняется.

## Чего я НЕ утверждаю

**Не проверял запуском, достижима ли эта ветка сегодня.** По чтению — вероятно
нет: чекер на обоих отказах печатает диагностику (`INTERP_TYPE_MSG`), а файл с
диагностикой до эмиссии не доходит. То есть сегодня безопасность держится на
СВОЙСТВЕ КОНВЕЙЕРА (отказ останавливает сборку), а не на устройстве самой ветки.

Это и делает находку стоящей записи: свойство конвейера меняется волной, о
которой никто не вспомнит про это место. Достаточно, чтобы эмиссия однажды пошла
по дереву с диагностиками — LSP, режим «продолжать после ошибки», отладочный
прогон, — и `${box_of_int}` уронит ICE с обвинением в адрес канала.

## Что предлагается (решает окно 274)

Дёшево и по образцу соседа: спросить `has_implicit` перед вызовом, а на пустоте
падать со своим сообщением, называющим ЭТО место и форму, а не канал. Тогда
неверная ветка обвиняет себя, и следующий читатель не идёт в `sem/channel.nv`.

Правильнее по существу: сузить условие входа в ветку до того же, по которому
пишет чекер, — тогда множества совпадут по построению, а не по совпадению.
