# Аудит TLS-слотов рантайма — чек-лист

> Рабочий чек-лист, не норма Канона. Составлен 2026-11-16 после исправления
> потери эффект-обработчиков при миграции волокна (ветка
> `fix/effect-handler-tls-migration`, коммит `2d1ecd134`). Само правило живёт
> в комментарии у аксессоров и в строке реестра `221.1`. Ссылки на файлы —
> относительные; номера строк со временем плывут, ориентируйтесь на имена.

## Зачем

`_nova_handler_<E>` и другие переменные состояния волокна объявлены
`__declspec(thread)` / `__thread`, то есть принадлежат **потоку ОС**. Волокно
Nova может приостановиться внутри вызова эффекта и возобновиться на другом
worker'е. Рантайм восстанавливает **значения** в слоты нового потока
(`nova_effect_snapshot_restore`, `_nova_resume_restore_ctx_tls`), но если
оптимизатор закэшировал **адрес** старой TLS-ячейки через точку возможной
приостановки, код читает пустой (или чужой) слот прежнего потока. Именно так
detached-волокно хаба умирало с `unhandled effect Journal.write` / `Link.ack`.

Класс шире обработчиков: это любое per-fiber состояние, живущее в TLS. `volatile`
не помогает: адрес TLS-переменной остаётся инвариантом цикла, и clang законно
выносит `lea reg,[tls_block+offset]` из цикла (замерено на clang 22).

## 1. Инвентаризация

- [ ] Полный список:

  ```sh
  grep -rn "__declspec(thread)\|__thread\|NOVA_THREAD_LOCAL" \
    compiler-codegen/nova_rt --include=*.c --include=*.h
  ```

- [ ] Исключить чужое: `nova_rt/libuv/`, `nova_rt/gc/`, `minicoro.h`,
  `nova_msvc_compat.h`. Отдельным списком — «наше, но не состояние волокна»
  (`bench.h` NOVA_THREAD_LOCAL, libuv-состояние).
- [ ] Для каждого имени найти: определение, все `extern`-объявления, все чтения
  и записи, включая взятие адреса (`&slot`, `slot[i]`, передача в регистрацию
  GC-корней).
- [ ] Проверить сгенерированный C: `_common.h` и `_part*.c` содержат те же
  переменные и инлайн-функции заголовков (`effects.h`, `channels.h`,
  `fibers.h`); инлайн-функция не является барьером для выноса адреса.
- [ ] Проверить, не объявлен ли слот ещё раз в другом заголовке (дубль
  `extern` с другим типом — отдельный дефект).

## 2. Классификация каждого слота

- [ ] **Владелец:** процесс / worker-поток / главный поток / волокно.
- [ ] **Семантика:** если волокно переезжает на другой поток, значение обязано
  переехать с ним? Обработчики, fail-top, interrupt-top, scope/slot,
  error-state, стек финализаторов — да. Loop, preempt-указатель,
  park-unlock — нет, они потоковые.
- [ ] **Восстановление:** кто и где кладёт правильное значение в слот нового
  потока (`nova_effect_snapshot_restore`, `_nova_resume_restore_ctx_tls`,
  `nova_resume_fiber`)? Если никто — это уже дефект, а не вопрос кэша.
- [ ] **Использование:** сгенерированный код, инлайн-функции заголовков,
  рантайм. Перечислить все пути.
- [ ] **Точка приостановки рядом:** между вычислением адреса и использованием
  есть вызов, который может усыпить волокно? См. список ниже.
- [ ] **Адрес берётся явно?** Взятие адреса означает, что адрес может быть
  вычислен заранее и переиспользован после вызова.
- [ ] **GC:** слот зарегистрирован корнем? Реестр потоковый? Что происходит при
  миграции и при выходе потока (`nova_effect_roots_publish/retract`)?
- [ ] **Multi-TU:** слот `extern` в `_common.h`, определение в одной части;
  аксессор не должен давать дублирующийся внешний символ.

Точки, после которых возможна миграция: `nova_preempt_check`, любой dispatch
эффекта (обработчик может спать или парковаться), `Time.sleep`, `send/recv/select`
каналов, `spawn/detach/supervised`, park/wake, join scope.

## 3. Опасный паттерн

- [ ] В C: адрес TLS-переменной инвариантен циклу и вынесен из цикла или за
  вызов. Признаки: `&_nova_handler_X`, чтение `_nova_..._tls` один раз до цикла.
- [ ] В ассемблере: `lea reg,[tls_block+off]` до цикла, затем `mov reg,[...]`
  внутри, после `call`, который может приостановить волокно.
- [ ] В инлайн-функциях: тело разворачивается в caller, адрес считается в
  caller'е и переиспользуется через вызовы.
- [ ] Сравнить release (`-O2`) и dev (`-O0`): разница — признак выноса.
- [ ] Не считать `volatile` защитой: он перечитывает значение, не адрес.

## 4. Решение по каждому слоту

- [ ] **Не состояние волокна** (worker/main): зафиксировать комментарием;
  проверить только, что значение перечитывается после миграции, если оно
  используется через yield.
- [ ] **Состояние волокна, горячий путь:** доступ через
  `static inline NOVA_NOINLINE`-аксессор адреса (образец — обработчики в
  [effects.h](../../compiler-codegen/nova_rt/effects.h) и
  [emit_c.rs](../../compiler-codegen/src/codegen/emit_c.rs)) либо перенос в
  контекст волокна.
- [ ] **Состояние волокна, редкое** (finalizer-stack, iframe): минимум — тот же
  аксессор; лучше — в контекст волокна.
- [ ] **Целевое решение класса:** один `NovaFiberContext` на волокно; указатель
  берётся один раз непрозрачным вызовом и живёт на стеке волокна. Адрес
  контекста при миграции не меняется — его кэшировать безопасно; адрес
  TLS-ячейки — нельзя.
- [ ] Для исправленного слота — комментарий с правилом и ссылкой на строку
  реестра.

## 5. Проверка

- [ ] Фикстура реально мигрирует волокно: волокон больше, чем worker'ов,
  sleep внутри эффекта, `ENV NOVA_MAXPROCS=4`. Образец —
  `spec_tests/conformance/standalone/handler_tls_after_migration.nv`.
- [ ] Красное до фикса и зелёное после на одном сценарии; желательно 10/10 в
  обе стороны.
- [ ] Контроли: `NOVA_MAXPROCS=1` (миграции нет) и dev-сборка (нет выноса).
- [ ] Затронутые наборы: effect, fail, handler, spawn, fiber, supervised, chan,
  detach, closure.
- [ ] Multi-TU: `NOVA_MULTI_TU=1` на большом CU — сборка, линковка, запуск.
- [ ] По сгенерированному C/ассемблеру: адрес слота больше не используется
  через вызов.

## 7. Текущий инвентарь и статус

По состоянию на `2d1ecd134`. «Восстанавливается» — про значение в слоте
нового потока, а не про адрес.

| Слот | Владелец | Восстанавливается на resume | Статус |
|---|---|---|---|
| `_nova_handler_<E>`, `Fail`, `Fail_any`, `Time`, `Fail_<E>` | волокно | да (snapshot / переустановка) | исправлено аксессорами |
| `Fail_<E>` в snapshot | волокно | нет (GC-only реестр) | OPEN, находка в реестре |
| `_nova_fail_top`, `_nova_interrupt_top` | волокно | да (`_nova_resume_restore_ctx_tls`) | аудит прямых обращений |
| `_nova_current_handler_iframe` | волокно | нет в restore-хуках | высокий риск, проверить `Nova_Fail_fail` |
| `_nova_active_scope`, `_nova_active_slot` | волокно | да | аудит прямых обращений |
| `_nova_error_state_p` | волокно | да | аудит |
| `_nova_active_finalizer_stack` | волокно | нет в restore-хуках | высокий риск для `Application` через yield |
| `_nova_effect_registry` | поток | n/a (реестр адресов потока) | аудит: не кэшировать `&registry` через yield |
| `_nova_effect_root_self` | поток | n/a | GC-колбэки, низкий риск |
| `_nova_preempt_ptr` | worker | n/a (потоковый) | проверить перечитывание |
| `_nova_park_unlock_fn/arg` | поток/волокно, транзиент | n/a | проверить окно park → resume |
| `_nova_current_loop` | worker | n/a | проверить использование после yield |
| `_nova_test_frame` | главный/тест | n/a | вне фиберов |
| `bench.h` NOVA_THREAD_LOCAL | поток | n/a | вне класса |

## 8. Порядок аудита

1. Обработчики — сделано (все формы).
2. `_nova_current_handler_iframe` и `_nova_active_finalizer_stack` — сейчас не
   восстанавливаются; сначала проверить сценарий с приостановкой внутри
   handler-arm и внутри `with Application`, затем решать: аксессор или контекст
   волокна.
3. `_nova_fail_top`, `_nova_interrupt_top`, `_nova_active_scope/slot`,
   `_nova_error_state_p` — восстановление есть; искать только кэш адреса.
4. Per-E `Fail[E]` — расширить snapshot или восстановление; отдельная строка
   реестра.
5. Потоковые (`preempt_ptr`, `current_loop`, `park_unlock`) — проверить, что
   после yield значение перечитывается; адрес не кэшируется.
6. Реестр GC и `root_self` — аудит колбэков, миграция не участвует.

## Границы

Чек-лист не покрывает TLS в `libuv/`, `gc/`, `minicoro.h` и в сторонних
библиотеках; не заменяет приёмку и не объявляет поведение нормой языка. Он
описывает, как искать и закрывать класс «per-fiber состояние в TLS», а не
конкретный дефект.
