# Проба: оракул МОЛЧА выбирает перегрузку там, где спека требует отказа

**Трек:** oracle. **Найдено:** окно 274, 2026-08-31, по ходу разбора владельца о
специфичности режимов. **Строку реестра заводит держатель трека** — здесь только
проба, замер и команда.

## Что утверждается

Амендмент D84 «Ось режима {ro, mut, consume}» (Plan 184 / D326-Р13/Р14,
`spec/decisions/10-overloading.md`) про набор с ПРОТИВОПОЛОЖНОЙ вариацией режима
двух параметров говорит: «диспатч **реджектит** вызов как ambiguous с
перечислением кандидатов … — **молчаливого выбора нет**».

Оракул на такой паре компилирует и печатает один из двух ответов.

## Как воспроизвести

Каждый файл — САМОСТОЯТЕЛЬНЫЙ модуль, и класть его надо в ПУСТОЙ каталог: папка
есть один модуль, поэтому три файла рядом склеятся в один и дадут «duplicate
top-level name» вместо предмета пробы.

```sh
# из корня рабочего дерева
for p in ambiguous control_single swapped; do
    rm -rf /tmp/ovl && mkdir -p /tmp/ovl
    cp docs/dev/hunts/oracle/probes/2026-08-31-overload-ambiguity/$p.nv /tmp/ovl/m.nv
    ./nova-cli/target/release/nova.exe build /tmp/ovl/m.nv -o /tmp/ovl/m.exe && \
        printf '%-16s -> ' "$p" && /tmp/ovl/m.exe && echo
done
```

## Замер 2026-08-31

| файл | оракул | чего ждала бы спека |
|---|---|---|
| `ambiguous.nv` | компилирует, печатает **2** | отказ `ambiguous overload` с перечислением кандидатов |
| `control_single.nv` | печатает **42** | принять (кандидат один и он годен) |
| `swapped.nv` | печатает **2** | отказ, как у `ambiguous.nv` |

**Контроль обязателен и вот зачем:** `control_single.nv` доказывает, что
consume-кандидат ДЕЙСТВИТЕЛЬНО годен для этого набора аргументов. Без него
«оракул выбрал второго» объяснялось бы проще — первый просто не подходит, и
тогда никакой неоднозначности нет. `swapped.nv` снимает вторую простую гипотезу:
выбор делается не по порядку объявлений.

## Чего проба НЕ утверждает

Она не называет ПРАВИЛО, по которому оракул выбирает: перестановка объявлений
исхода не меняет, значит правило своё, но какое — не измерено. Это вопрос к
тому, кто будет чинить, и здесь он оставлен открытым намеренно.

## Как это выглядит с другой стороны

В novac та же форма чинилась сравнением специфичности **по позициям** вместо
суммы: кандидат побеждает, если не хуже в каждой позиции и строго лучше хотя бы
в одной, всё прочее — несравнимо и отвергается. Сумма ловит неоднозначность
только при СЛУЧАЙНОМ совпадении чисел: `f(consume a, ro b, ro c)` = 2 против
`f(ro a, ro b, mut c)` = 1 суммы разводит и назовёт победителя, хотя ни один не
специфичнее по всем позициям. Решение владельца, 2026-08-31; в novac закрыто
коммитом `69a7bf1bd`.
