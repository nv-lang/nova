# F — `check-ratchet-moves.sh` краснеет на ДОПИСАННОМ ПЕРЕВОДЕ СТРОКИ: «сдвинут храповик» при неизменном числе

Класс: К4 (страж считает добавленные строки вида `имя=число`, а печатает
«сдвинуто чисел» — соседний вопрос).
**Носитель был живым на настоящем дереве nova 2026-09-16 в час замера; транскрипт — `F-ratchet-moves-newline-false-red/live-carrier.txt`. Через час соседнее окно закоммитило свои правки, и страж на том же дереве стал зелёным — второй замер в том же транскрипте подтверждает вживую ещё и пробу A.**

## 1. Вердикт дословно

> `check-ratchet-moves: FAIL — храповик сдвинут без причины В ТОМ ЖЕ диффе (файлов 1):`
> `  scripts/guards/registry-routes.baseline: сдвинуто чисел 1, добавленных строк-причин 0`

## 2. Что читает физически

`check-ratchet-moves.sh:82-89` — построчный разбор диффа:

```
'+'*)
    body="${line#+}"
    if printf '%s' "$body" | grep -qE '^[a-z_]+([ =])[0-9]+$'; then
        NUMS=$((NUMS+1))
    fi
```

Считается ДОБАВЛЕННАЯ СТРОКА нужной формы. Сравнения старого значения с новым
нет нигде. Строка, добавленная без изменения значения, считается сдвигом.

## 3. Расхождение

Живой замер на настоящем дереве (read-only, `git diff` без правок):

```
-blockers=73
\ No newline at end of file
+blockers=73
```

Число 73 не изменилось; изменился только завершающий перевод строки —
то самое исправление, которого ТРЕБУЕТ `check-baseline-newline.sh`
(«Чинить: дописать перевод строки в конец файла»). `check-ratchet-moves`
читает это как сдвиг храповика без причины и валит шаг `loop` гейта
(`scripts/gate.sh:595`).

Изолированное воспроизведение — `F-ratchet-moves-newline-false-red/cmd.sh`,
`output.txt`: своя репа, база `blockers=73` без перевода строки в коммите,
единственная правка — дописанный `\n`.

| состояние | значение | `check-baseline-newline` | `check-ratchet-moves` |
|---|---|---|---|
| до правки | 73 | `FAIL` | `ok: сдвигов храповиков в диффе нет` |
| после правки (только `\n`) | 73 | `ok` | **`FAIL — сдвинуто чисел 1`** |

Два стража на одном дереве требуют противоположного: пока база без перевода
строки — красен первый, как только перевод дописан — красен второй, и починить
второго можно только дописав строку-причину к сдвигу, которого не было.

## 4. Что это добавляет к семье №1118

Тот же корень, другая сторона: там страж читал рабочую копию и был зелен про
испорченный коммит, здесь — читает рабочую копию и краснеет про коммит, в
котором ничего не сдвинуто. Обе половины держатся на одном допущении, которое
никем не утверждается: «дифф рабочей копии = то, о чём я говорю».
