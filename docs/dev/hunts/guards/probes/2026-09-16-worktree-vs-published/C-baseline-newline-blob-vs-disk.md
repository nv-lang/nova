# C — `check-baseline-newline.sh`: список из git, содержимое с диска

Класс: К4. Семья: реестр №1118.

## 1. Вердикт дословно

Шапка, `scripts/guards/check-baseline-newline.sh:2-3`: «каждый файл-база
оканчивается переводом строки». Зелёные строки (49 и 62):

> `check-baseline-newline ok: судить нечего — баз не найдено`
> `check-baseline-newline ok: баз N, все оканчиваются переводом строки`

Вред, ради которого страж существует, назван в шапке: «Оболочечный `read` не
отдаёт последнюю строку без `\n`, и она молча уходит из проверки». Этот вред
достаётся ТОМУ, КТО ЧИТАЕТ БАЗУ ИЗ КЛОНА — гейту на CI в первую очередь.

## 2. Что читает физически

`check-baseline-newline.sh:33-45`:

```
for f in $(cd "$DIR" && git ls-files | grep -E '\.baseline$'); do
    p="$DIR/$f"
    [ -f "$p" ] || continue
    ...
    last=$(tail -c 1 "$p" | od -An -c | tr -d ' ')
```

Список путей — из git (индекс). Содержимое — `tail -c 1` по файлу на ДИСКЕ.
Два объекта, и совпадение их никем не утверждается.

## 3. Расхождение

`C-baseline-newline-blob-vs-disk/cmd.sh`, `output.txt`. Коммит содержит
`demo.baseline` БЕЗ завершающего перевода строки:

| состояние | коммит | диск | вердикт |
|---|---|---|---|
| 1 | без `\n` | без `\n` | `FAIL` (верно) |
| 2 | **без `\n`** | `\n` дописан, **в индекс не добавлен** | `ok: баз 1, все оканчиваются переводом строки` |
| 3 | без `\n` | файла нет (удалён в дереве) | `ok: судить нечего — баз не найдено` |

Состояние 2: в клоне и на CI база по-прежнему обрезана, `while read` по-прежнему
теряет её последнюю строку — страж зелен и отчитывается числом «баз 1».
Состояние 3: опубликованная и сломанная база не судится вовсе, причём вердикт
звучит как замер («баз не найдено»), а не как отказ.
