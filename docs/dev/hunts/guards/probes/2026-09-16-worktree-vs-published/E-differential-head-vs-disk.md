# E — `check-novac-differential.sh`: «числа могут только расти» сверяет HEAD с диском, а гейт запускается только при HEAD == диск

Класс: К4 / К7 (замер, у которого по построению нет входа).
Семья: реестр №1118.

## 1. Вердикт дословно

Комментарий-обоснование, `scripts/guards/check-novac-differential.sh:194-197`:

> Храповик сверял ПРОГОН с файлом и ни разу — файл с его историей. Значит откат
> делался в одну строку... Ратчет, который можно отпустить рукой, — не ратчет.
> **Сравниваем с версией файла в HEAD; допускается только рост.**

Отказ (строка 211): «база ОПУЩЕНА рукой: `$key` было `$was`, стало `$now`
(§10.4: числа могут только расти)».

Утверждение — об ИСТОРИИ базы, то есть об опубликованной последовательности
коммитов.

## 2. Что читает физически

`check-novac-differential.sh:198-199`:

```
BFILE="$ROOT/scripts/guards/novac-corpus.baseline"
HEAD_B=$(git -C "$ROOT" show "HEAD:scripts/guards/novac-corpus.baseline" ...)
```

Одна сторона — блоб из HEAD, другая — файл с диска. Разойтись они могут только
пока понижение лежит НЕЗАКОММИЧЕННЫМ.

## 3. Расхождение

Два факта, оба снимаются пробой `E-differential-head-vs-disk/cmd.sh`
(read-only, ничего не создаёт и не правит):

1. на настоящем дереве прямо сейчас `HEAD:novac-corpus.baseline` и файл на диске
   — **побайтово одинаковы**: сравнение сравнивает файл сам с собой;
2. это не случайность дня. `scripts/tools/push-after-gate.sh:55-60` отказывается
   запускать гейт на грязном дереве (`DIRTY=$(git diff --name-only HEAD | wc -l)`),
   то есть санкционированный порядок работы гарантирует HEAD == диск в момент
   проверки.

Следствие: понижение, уже попавшее в коммит, сравнивается само с собой и
проходит НАВСЕГДА. Правило «числа могут только расти» держится ровно на окне
между правкой и `git commit` — и только у того, кто в этом окне запустил гейт
вручную. Ровно та же подмена объекта, что в №1118: утверждение об истории,
замер по незакоммиченной правке.
