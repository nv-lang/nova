# D — `check-tree-matches-push.sh`: «отправляется то, что проверено» замеряется как «мой чекаут чист»

Класс: К4 в чистом виде — соседний вопрос, прочитанный как заданный.
Семья: реестр №1118 (родня названа в самой шапке стража: №635).

## 1. Вердикт дословно

Шапка, `scripts/guards/check-tree-matches-push.sh:3`: «Отправляешь НЕ ТО, что
проверял». Строка 20: «Гейт судит РАБОЧЕЕ ДЕРЕВО, CI судит КОММИТ».
Зелёная строка (79):

> `check-tree-matches-push ok: отслеживаемых изменений вне коммитов нет`

Отказ (62): «ОТПРАВЛЯЕТСЯ НЕ ТО, ЧТО ПРОВЕРЕНО».

## 2. Что читает физически

`check-tree-matches-push.sh:59`:

```
DIRTY=$(git -C "$ROOT" status --porcelain --untracked-files=no | grep -v '^??')
```

Это «рабочее дерево против МОЕГО HEAD». **Отправляемый объект стражу не
передаётся вообще.** Хук его знает и выбрасывает: `scripts/githooks/pre-push:31-36`
читает `while read -r _lref _lsha rref _rsha`, берёт только `rref` (для ответа
«это main?») и теряет `_lsha` — sha, который реально уезжает.

## 3. Расхождение

`D-tree-matches-push-ignores-pushed-sha/cmd.sh`, `output.txt`. Репа: `main` = c2,
окно сидит на ветке `work` = c1, дерево чистое.

| состояние | что уезжает в main | вердикт |
|---|---|---|
| 1-2. чистый чекаут `work`, пуш `main` (c2) | c2, который не видел ни один гейт | `ok: отслеживаемых изменений вне коммитов нет`, хук exit=0 |
| 3. черновая правка в чекауте, пуш ТОГО ЖЕ main (c2) | **тот же самый c2, байт в байт** | `FAIL`, хук exit=1 |
| 4. дерево грязное, но файла стража в ЭТОМ чекауте нет | c2 | хук exit=0, **проверка молча не выполнена** |

Состояния 2 и 3 отличаются только состоянием чужого по отношению к пушу
чекаута; отправляемый объект в них ОДИН И ТОТ ЖЕ. Вердикт разворачивается —
значит он о чекауте, а не об отправляемом.

Состояние 4 — отдельная строка: `scripts/githooks/pre-push:40-41` написан как
`if [ -f "$TREE_GUARD" ]; then ... fi` без `else`. Отсутствие файла стража в
пушащем дереве = проверка не выполнена и никто об этом не сказал. Это ровно
случай №635, который страж и заводился ловить: тогда файл стража существовал
только в рабочей копии одного дерева.

## 4. Второй адрес того же расхождения (прочитан, пробой не снят)

`core.hooksPath` в этом репозитории задан АБСОЛЮТНЫМ путём в главное дерево
(сам путь здесь не выписан — №698; смотреть `git config core.hooksPath`)
(абсолютный путь в ГЛАВНОЕ дерево, а не относительный `scripts/githooks`, как
ставит `scripts/guards/install-guards.sh:75`). Конфиг общий для всех worktree,
поэтому соседнее дерево исполняет тело хука из главной рабочей копии — в том
числе незакоммиченное, — а `REPO_ROOT` и путь к стражу разрешает у себя.
Тело хука и проверяемый им страж приезжают из РАЗНЫХ деревьев.
