# Охота: храповики и базы x К5 (2026-09-05)

Трек `guards`. Цель окна: стражи, у которых рядом в `scripts/guards/` лежит
`<имя>.baseline`, класс К5 — «правило держится шапкой, а код спрашивает более
узкое, и потому вердикт зелен по неверной причине либо красен на законном».

Пробы: `docs/dev/hunts/guards/probes/2026-09-05-ratchets-k5/`. Каждая — свой
каталог с `cmd.sh` и `verdict.txt` (замер дословно). Все `cmd.sh` запускаются
из ЛЮБОГО cwd и сами находят корень репы вверх по дереву; корень можно задать
первым аргументом. В `verdict.txt` заменён только машинный префикс временного
каталога — на `<tmp>`; остальное байт в байт.

Ни один файл вне `docs/dev/hunts/guards/` не тронут. Ни одна база не сдвинута.
Вердиктов не выношу: что из перечисленного дефект — решает окно.

## Перечень: что вообще есть в клетке

- `check-*.{sh,py}` в `scripts/guards/` — **181** (замер 2026-09-05:
  `ls scripts/guards/check-*.sh scripts/guards/check-*.py | wc -l`).
- Файлов `*.baseline` — **61**.
- Из них **58** читает страж; распределены они по **57** стражам
  (`check-novac-differential.sh` держит две: `novac-corpus`,
  `novac-iteration-cost`).
- **3 базы без стража-владельца**, их читает шаг гейта:
  `mega-cu-skip.baseline`, `mega-cu-time.baseline` — `scripts/gate.sh`;
  `novac-gate-budget.baseline` — `scripts/gate-novac.sh`. Проверить их
  «четырьмя пробами» нечем: у шага гейта нет отдельного входа.
- **Шов входа есть у всех, кроме одного.** Проверено грепом по
  `sys.argv[1]` / `${1:-}` / `NOVA_*`-override: единственный страж с базой,
  который НЕ принимает корень ни аргументом, ни переменной, —
  `arch-ratchet.sh`. Он резолвит цель путём, относительным cwd. Это и стало
  находкой №6.

Пробами разобрано **7 стражей** (14 каталогов проб — по паре «нарушение /
контроль» на каждую находку). Прочитаны шапка + код у **30**; у остальных —
только шапка либо ничего, список в «Что обошёл».

**1. Где в строке находки стоит имя пробы — поле 4 или поле 5.**
