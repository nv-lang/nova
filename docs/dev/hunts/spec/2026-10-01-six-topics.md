## С7: на чьей стороне компилятор

Оракул — `main` `0b296258b` с ветками №1559/№1556/№1572 (на этих формах они ничего не меняют).

- `d47-whole-reexport-example` — `nova check lib.nv` -> `[E_REEXPORT_GLOB] export import std.time re-exports the entire module`.
- `d457-no-pub-vs-pub-field` — `nova build` -> собирается, печатает `1` (поле `pub id int` принято).
- `d34-ro-before-ctor-in-cond` — `nova build` -> собирается, печатает `u 3` (`if ro Some(user) = ... && ...` принято).
- `d157-ro-consume-ctor-in-cond` — `nova build` -> собирается, печатает `4` (`if ro consume Some(t) = opt` принято).
- `int-literal-over-float` — `nova build` -> собирается, печатает `10 0` (образец `1` над `f64` совпал с `1.0`).
- `d54-suffix-literal-examples` — `nova build` -> `[E_STMT_SEP_MISSING]` на `300u32` (суффикс не литерал).

Три формы, которые D486 запрещает (`ro`/`ro consume` перед конструктором в условии, целый литерал над `f64`), компилятор ПРИНИМАЕТ и исполняет — то есть либо текст D486, либо компилятор неверен, и молча: выбор стороны — за владельцем. Две формы, которые показывают примеры старых блоков (реэкспорт целиком, суффиксный литерал), компилятор отвергает — там неверен пример. `pub`-поле компилятор принимает — D457 «слова `pub` в языке нет» с ним расходится.

## Что обошёл и почему

- **С4 (решения в планах)** — проверено частично: планы 172.14/172.15 (размещение) — перенесены в D488; 282 (конверсии) — совпадает; по видимости, вариантам и `-> @` планы грепом не перебраны (`77-fluent-return.md`, `273-one-form-...md`, `269-package-visibility.md` — первые в очереди следующей охоты).
- **С6 (пары .md/.ru.md)** — сверены только абзацы тем: syntax (видимость, setter `-> @`, передача параметров, образцы), conversions (таблицы сужения). Пары overview, effects, revolutionary целиком не сверялись — механизм С6 (страж) ниже в плане трека.
- **Кандидаты, снятые как закрытые указателем**: D32 (mut-параметр «приватная копия»; «by reference в managed heap»; «строки и суммы уже указателем»), D326 (Р3 «`mut` — не `inout`» против Р10 «in-out всегда»; Р6 у кучевого типа против D488 «`mut` всегда указателем»): у обоих блоков стоит «где расходится с D488, действует D488». Это НЕ значит, что тексты согласны, — значит, что спор разрешён старшинством. Чистка тел — работа автора D488, не находка.
- **Сомнения читателей, не взятые в находки**: D55 `Maybe`/`Just` (не объявлен нигде, возможно — учебный тип примера); `\` как начало комментария в примерах D478; `throw` вне перечня позиций D478; таблица D55 «generic после конкретизации — ⛔ ещё нет» против амендмента 2026-08-04; D157 «`consume` ТОЛЬКО внутри single-arg tuple-variant» против D486; nova.ungrammar против D486 §1 (снимок парсера Карины, не D-блок).
- **Попутно, не спека**: пользовательский тип с именем `Acc` ломает сборку внутри std (`std/src/collections/vec_iter/core.nv:647` — `[E_PREFIX_SHADOWS_NAMED_TYPE] fn[Acc] ... shadows named type Acc`): имя верхнего уровня программы протекает в проверку модуля std. Передано интегратору отдельной находкой оракула.
