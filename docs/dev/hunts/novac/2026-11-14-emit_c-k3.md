# Охота: посайтные C-протоколы волны supervised-значения — emit_c × К3

КЛЕТКА | emit_c | К3

## 1. Находки

Охота назначена окном-интегратором по свежей поверхности волна supervised-значения
(дифф 200753ea6..HEAD=5f2de461c); территория — `novac/src/emit_c/` и `novac/src/lower/`
(emit_supervised.nv, emit_closure.nv, emit_place.nv, emit_c.nv, ir.nv, ir_control.nv,
lowering.nv, lower_coalesce.nv, emit_literals.nv, lower_print.nv — последние три
проверены как чистые переезды текста). Эталон — написанная архитектура (К3: «C-имя и
репрезентация — функция от интернированного канона: один канон ⇒ ровно одно имя и одна
репрезентация») плюс оракул как неподвижная точка ПОВЕДЕНИЯ (0.1.3 от 11-10, основное
дерево). Инструмент — `novac/target/novac.exe` этого дерева (пересборка не потребовалась);
CC-свидетель — clang -fsyntax-only с заголовками рантайма; поведенческий —
`scripts/tools/novac-e1-smoke.sh` из ОСНОВНОГО дерева с `NOVAC_BIN` этого ворктри
(в ворктри смоук не собирает оракул: нет сабмодулей gc/libatomic_ops). Пробы:
`probes/2026-11-14-emit_c-k3/<имя>/cmd.sh <корень>`; exit 0 = свидетели на месте,
exit 1 = якорь потерян. Рабочее дерево охота не меняла (изменения `docs/plans/221.1-bug-sweep.md`
и `scripts/guards/carina-seed-drift.baseline`, видимые в `git status`, сделаны окном ДО
охоты и не тронуты).

Проверено и держится (контрольные пробы, инвариант на новых формах; каждая — exit 0):

* **Одна нумерация C-имён** (`control-numbering-stress`): value → bare → value →
  statement-with-args, bare ВНУТРИ тела value, value ВНУТРИ `while` — все объявленные
  `NovaFiberQueue _novac_q<N>` различны, у каждой ссылки `_novac_qdl/_novac_qprev` есть
  объявление, clang без undeclared/redefinition; поведение байт-в-байт с оракулом
  (smoke). Механизм `FnBuilder.seeded` + `@body_builder/_done/_resume` + interlock
  `@fresh_uniq`↔`@frames_now` на этих формах инъективен. r2-коллизия `two_bare_scopes`
  не возвращается.
* **ABI-каст on_timeout-хендлера** (`control-handler-abi`): value-форма с record-типом
  и БЛОЧНЫМ телом хендлера, statement-позиция с отброшенным не-unit результатом — каст
  всюду называет собственный тип хендлера из записанной сигнатуры (`@sup_handler_ret_c`),
  ложного `nova_unit(*)` нет, сигнатура тела совпадает с кастом; поведение идентично
  оракулу. Строка реестра 221.1 (handler-ABI) на новых формах держится. Захватывающий
  хендлер (`on_timeout: |_e| fallback`) — тоже идентично (замер 2026-11-14).
* **D432-временная выхода** (`control-d432-exits`): `return` поверх bare-скоупа
  печатает значение в temp, затем disarm → supervised_run → restore active scope →
  `return <temp>` (протокол живой, не мёртвый); `break` из цикла через bare-скоуп и
  `return` из with-области — поведение идентично оракулу (носитель d5). Три двери
  значения выхода (`@lower_return`, `?? return`, `?`) в областях БЕЗ split согласованы:
  голый `return` и `?? return` печатят протокол до терминатора.
* **Ранний дедлайн при нескольких областях** (`control-numbering-stress` +
  фикстуры pos_1..pos_6): токен на каждой очереди свой, disarm на success-пути и на
  sgfail-метке; вложенные дедлайны (pos_4) и таймаут-с-хендлером (pos_2/pos_3) —
  дифференциал зелёный.

## 2. Что обошёл и почему

* **Класть `@closure_clos_value` в аргумент `on_timeout:`-имени (не литерал).**
  Обошёл сознательно: чекер отказывает по имени (CLOSURE_LIT_POSITION_MSG,
  with_typing.nv:461-466) — носителя нет.
* **`throw`/`!!` внутри split-тела.** Это выход через fail-кадры, а не через
  return-место: C-протокол value-формы имеет обе кадры (sotf/sg), longjmp попадает в
  sgfail — корректный путь, понижение не участвует. Носителя расхождения не искал
  глубже проб формы (проверено чтением emit_sup_end_ok/sgfail).
* **Вложенный supervised value В ХВОСТЕ другого** (не non-tail). Позиция
  «оракул сам не собирает» открыто записана в фикстуре pos_4 («an oracle body-local
  read from the TAIL is the open registry class»); дифференциал по ней мерил бы
  известный оракулевый дефект, не Карину. Обошёл, cited pos_4.
* **emit_literals.nv / ir_control.nv / lower_print.nv как переезды.** Сверил с
  удалённым текстом emit_c.nv/ir.nv/lowering.nv в диффе — перенос буквальный, новых
  посайтных решений нет; отдельные пробы не писал.
* **`cancel:` (D441).** Отказан по именованной дверью (SUPERVISED_CANCEL_MSG) на обеих
  позициях — носителя нет.
* **Единый `module probe.p` у двух носителей находки 1.** Каждый компилируется ОТДЕЛЬНО
  (cmd.sh зовёт emit по одному файлу); риск «папка как модуль меряет сумму» снимается
  тем, что каждый файл — законченная программа со своим `main`, и оба прошли независимо.
* **Смоук из ворктри.** Не работает (сабмодули gc/libatomic_ops не вынесены в
  worktree); поведенческие замеры гонялись смоуком ОСНОВНОГО дерева с `NOVAC_BIN`
  ворктри — пути записаны здесь, воспроизведение на другой машине потребует того же
  расположения деревьев.
* **Побочное наблюдение вне клетки (check, не К3):** оракул отказывает длинную форму
  поля при совпадении имени (`Pt { x: x }` → «D52 §2 требует shorthand»), novac её
  принимает. Замечено на носителе h1 при подготовке контроля; не мерил глубже, клетка
  не та.
