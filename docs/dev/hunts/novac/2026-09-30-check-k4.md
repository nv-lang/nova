# Охота: подсистема `check` × К4 (трек novac, 2026-09-30)

КЛЕТКА | check | К4

**Клетка назначена окном Карины** перед сдачей веток `p274-m700`/`p274-e9s4`: долг охоты
трека novac на их вершине — 2052 строки поверхности при бюджете 1500 (`check-hunter-debt`).
Охотник — агент `defect-hunter` (opus), 53 пробы. Дерево `nova-p274-e9s3`, вершина
`b447505fa`, бинарь novac 19:45; оракул — `main` с №1415. Находки заведены в реестр 221.1
строками №1430–№1436 (номера выдал интегратор), №1430, №1432, №1433 закрыты коммитом
`580db7f02` той же ветки.

**Живое подозрение окна** (четыре):
1. правило полноты (`check/match_arms.nv`, теперь `check/exhaustive.nv`) заново читает
   ТЕКСТ головы образца, хотя привязка ветки уже решила, чем голова является;
2. полнота судится двумя путями — оператор и значение;
3. «это захват?» решают и чекер (`@note_if_capture`), и эмиттер (`@capture_source`);
4. `@is_mut_alias_safe` судит по `TypeDef.share` уже решённого типа привязки.

**Запуск пробы:** `ROOT=<repo> NOVA=<oracle nova.exe> sh docs/dev/hunts/novac/probes/2026-09-30-check-k4/<имя>/cmd.sh`.
Проба печатает `novac check` и `nova check`; с `RUN=1` в `cmd.sh` — ещё собирает и запускает
обоими компиляторами через `scripts/tools/novac-e1-smoke.sh`; с `EMIT=` — грепает `novac emit`.

**Ответ по подозрениям.** (1) подтверждено и шире: `true`/`false` в образце для дверей формы
и имени — связыватель, для правила полноты — литерал; рядом ещё три пары двойного суждения.
(2) подтверждено: пустой match оператора проходит на кортеже и записи. (3) по семи формам
захват отмечается верно; не отмечается `@`-поле получателя в теле операции. (4) второго
вычисления не найдено; найдено другое — `#share` на своём типе до правила не доходит.

### 1. `true`/`false` в образце (№1430, закрыт `580db7f02`)

Первое вычисление — `sem/pattern.nv` `pattern_shape`: `true` приходит узлом имени и
получает `Bind`; за ним — привязка (`@scope.bind("true", bool)`), предикат позиции,
проверка ветки и связыватель понижения. Второе — правило полноты по тексту
(`is_bool_literal`/`is_true_literal`, добавлено `4790119be`). Свойство проверено в шести
синтаксисах (корень ветки, пейлоад, кортеж, условие, дизъюнкция, корень условия).

### 2. Проверка ветки по корню (№1431, открыт; тихая порча)

Чекер судит все узлы образца (`check/pattern_position.nv:45`, литерал на любой глубине
принят), понижение — только корень (`lower/lower_match.nv:131-154`; литералы вложенных узлов
отброшены `:179`, `:207`, `:301`, `:318`). Замер: `tuple-lit-arm` 22 против 12,
`tuple-variant-arm` 107 против 0, `variant-int-payload-lit` 2 против 1; контроль
`array-lit-arm` совпал. Носителей в `novac/src` вне тестов — 0.

### 3. Покрытие числом голов (№1432, закрыт `580db7f02`)

`covered += 1` на каждую голову и `covered >= vcnt`; шапка файла утверждала обратное.
`dup-arm-count`, `dup-disj-count`: novac rc=0, оракул отказ.

### 4. Пустой match оператора (№1433, закрыт `580db7f02`)

`EMPTY_MATCH_MSG` был только в двери значения; общее правило молча выходило на кортеже и
записи. `empty-stmt-match-tuple`, `empty-stmt-match-record`; контроль
`empty-value-match-tuple` — отказ у обоих.

### 5. Квалификатор в дизъюнкции (№1434, открыт)

Одиночная голова сверяет `pattern_qualifier` с суммой, `@bind_disj_pattern` и понижение
читают только голову. `disj-wrong-qualifier`, `disj-unknown-qualifier`: rc=0; контроль
`single-wrong-qualifier` — отказ. Оракул принимает все три (класс №962).

### 6. `@`-поле в теле операции (№1435, открыт)

`@note_if_capture` вызывается только из Name-ветки. `cap-self-field`: `ctx = NULL`, а
функция операции читает `_novac_self`. Прочие формы захвата (`cap-method-recv`,
`cap-assign-only`, `cap-for-iter`, `cap-interp`, `cap-cond-loop`, `cap-match-scr`,
`cap-param`) — байт-в-байт.

## Проверено, находок нет

Захваты `cap-shadow-inner-lit`, `cap-with-body-in-op`, `cap-held-lit-in-op`,
`cap-op-param-inner-lit`; `ro x = x` в теле операции (`shadow-nested-block-control`);
литерал с `mut`-захватом, покидающий кадр, — отвергнут во всех четырёх позициях
(`lit-escape-*`); `spawn-assign-only`, `spawn-method-recv`; `A =>` для варианта с
пейлоадом и `mut A =>`.

## Вне клетки

- `#share` на своём типе отвергается с ложной причиной (`spawn-share-record`) — №1436.
- Запись поля в `spawn` (`spawn-field-assign`): novac `E_CONCURRENT_MUT_CAPTURE`, оракул rc=0 —
  решается по 06-concurrency §2.
- Алиас `type Num alias int` → «undeclared type name» — ложная причина (`alias-minimal`).
- `println("${pick([]int.of(5, 2))}")` → ICE «array literal in expression position was never
  hoisted» (`array-literal-arg-ice`).
- `A =>` над `int` при варианте A в области: novac WRONG_SUM_ARM_MSG, оракул rc=0
  (`int-arm-foreign-variant-name`).
- Дефекты оракула: C не собирается у `cap-shadow-inner-lit`, `cap-held-lit-in-op`,
  `cap-op-param-inner-lit`, `cap-self-field` (класс №1421).
