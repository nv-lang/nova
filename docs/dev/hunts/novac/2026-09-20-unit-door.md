### Н1 + Н2 — таблица юнита отдаёт пару «файл + смещение», которой не существует

Реестр: **№1193**.

Ошибка в `a_broken.nv` (незакрытое тело `fn`), а единица обвиняет ровесника:

```
SUBJECT   {"code":"E_NOVAC_SUBSET","primary":{"file":"b_fine.nv","start":9,"end":9}, …}
CONTROL 1 {"code":"E_NOVAC_SUBSET","primary":{"file":"a_broken.nv","start":43,"end":43}, …}
CONTROL 2 rc=0   (обвиняемый файл САМ ПО СЕБЕ чист)
```

Вторая форма хуже первой: у ровесника **нулевой длины** диагностика указывает на
`start:1` — смещение, которого в файле физически нет, потому что `unit_of`
дописывает перевод строки после каждого тела. Сломан не «какой файл», а сам
контракт пары `(путь, смещение)`: редактор получит указание подсветить
несуществующий байт.

**Существующий тест это поведение БЛАГОСЛОВЛЯЕТ** — `unit_test.nv:203` («past the
last body is still the last body») закрепляет `file_of_offset(…, 9000) == 2`, и ни
одна клетка не проверяет, что полученное смещение лежит ВНУТРИ файла. Это не дыра
в покрытии, а покрытие, зафиксировавшее неверное.

### Н3 — одна разница в написании разделителя, и модуль молча распадается надвое

Реестр: **№1194**.

`same_dir` сравнивает байты до последнего разделителя. `sub\mod\a.nv` и
`sub/mod/b.nv` — один каталог для файловой системы и **разные** для этой функции,
поэтому два ровесника собираются в разные единицы и вызов из одного в другой
отвергается:

```
CONTROL (одинаковые разделители)  rc=0, чисто
SUBJECT (первый путь через «\»)   E_NOVAC_SUBSET «this name is not a callable novac knows»
```

**Шапка функции обещает обратное** (`pipeline.nv:148-150`): «BOTH separators,
because the CLI receives the path exactly as it was typed and this compiler is
built on Windows as much as anywhere else». Обещание выполнено только для
ПОСЛЕДНЕГО разделителя. Существующий тест (`unit_test.nv:86-91`) меряет путь с
ОДНИМ разделителем — то есть зелен при сломанном механизме.

### Н4 — текст отказа о столкновении имён называет «один файл», а файлов два

Реестр: **№1195**. Код и позиция верны; ложна проза: «declared twice in one file»,
когда в каждом из двух ровесников по одному объявлению. Читатель откроет названный
файл и второго объявления не найдёт. Слабее трёх предыдущих, но с включением
юнита по умолчанию такое сообщение станет массовым.

### Н5 — `unit_of` теряет строку `module` ровесников, и потеря зависит от порядка

Реестр: **№1196**, и **поведенческого следствия сегодня НЕТ** — охотник это
доказал, а не предположил: `novac emit` файла с `module m` и его копии без этой
строки дают побайтно одинаковый C. Имя модуля в novac сейчас инертно.

Записано потому, что оракул за ту же ошибку отвечает жёстко
(`E_D78_MODULE_PATH_MISMATCH`), и потому что утверждение `main.nv:418` «the order
of bodies does not change the checker's verdict (measured 2026-09-20)» **верно для
вердикта и неверно для ТЕКСТА единицы**: замер, на который оно ссылается, проверял
не то.

## Противоречия в дереве (выбор не охотника)

**П1.** `main.nv:417-419` утверждает независимость от порядка файлов;
`pipeline.nv:307-311` делает содержимое единицы функцией того, кто оказался
первым. Оба места про одно и то же и отвечают по-разному.

**П2.** `pipeline.nv:148-150` обещает равноправие обоих разделителей;
`pipeline.nv:194-198` сравнивает их как разные байты везде, кроме последней
позиции.

## Что обошёл и почему — раздел охотника, приведён без сокращений

* **`novac emit` в режиме юнита** — его нет (`main.nv:455`), поэтому «один
  исходник одним файлом против многих» мерилось только через `check`;
* **строка `import `/`module ` в столбце 0 внутри тела** — зазор назван, носителя
  не нашлось: блочных комментариев в языке нет, сырой перевод строки в литерале
  запрещён;
* **файл в двух единицах** — группировка помечает файл использованным, не находка;
* **дубли `fn` между ровесниками** — принимаются молча, но так же молча
  принимаются и в одном файле: это более широкая дыра, не клетка двери юнита;
* **порядковая зависимость ВЕРДИКТА** — искал целенаправленно, контрпримера не
  нашёл;
* **собственный промах, снятый и названный:** первые полчаса мерил без
  `NOVAC_UNIT=1` и получал «юнит не помогает» — это был не результат, а
  неработающий замер.
