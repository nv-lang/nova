**Что обошёл и почему**

- p03-fence-in-instance (`[]T` в теле экземпляра `two[Color]`): Карина честно отказывает подмножеством —
  `E_NOVAC_SUBSET` «in the instance of `two`: outside the subset: novac does not know this element type yet
  (274.5 P3)». Не находка; ограда через массив в экземпляре этим не проверена.
- p07-newtype-fence (`Color(s)` — значение newtype обратно в носитель): честный `E_NOVAC_SUBSET` «a type in call
  position constructs a value, and novac compiles that only for a newtype». Заменена пробой p07b.
- Сумма, огороженная только в функции, недостижимой от входа (оракул печатает всё, Карина — достижимое): пул
  единицы интернирует типы всех проверенных тел, поэтому расхождения не ожидаю, но пробой не мерил.
- Перегрузка/экземпляр оболочки, огораживающий сумму программы (ограда, рождённая в C оболочки, а не в пуле
  единицы): не построена.
- Поведение под оракулом в режиме программы с несколькими модулями, где ограду ставит только тело экземпляра
  ДРУГОГО модуля, — частично p03b; отдельная проба без опции не строилась (p03 упёрлась в подмножество).
- Время и память второго обхода — не мерились этой охотой (цифра задачи: эмиссия 24 → 23 с).

**Противоречия**

- Нет между документами. Внутреннее противоречие кода названо в первой находке: шапка `is_value_sum`
  (`novac/src/sem/mangle.nv:83-96`) — «The rule is the ORACLE's… unfenced», комментарий `note_fences`

  огораживаются одним правилом, у Карины для суммы оболочки ответов два (оболочки и единицы).
