# Охота: check × К4 — второе вычисление уже решённого суждения

**Трек:** novac · **Дата:** 2026-09-04 · **Модель охотника:** opus
**Пробы:** `probes/2026-09-04-check-k4/` — 20 цитируемых каталогов из 36
построенных (18 пар «точечная форма ↔ форма через `@`»), по файлу в каждом.
**Проверено окном запуском** дымом из дерева: `p_mut_recv_dot` — ok;
`p_mut_recv_at` — novac отказывает «this type has no such method in the
declarations novac was handed» (две диагностики); `p_mode_overload_at` — stdout
расходится, novac печатает `tag = 1` против `tag = 2` оракула; обратная проба
`p_ro_overload_at` — ok. ПОДТВЕРЖДЕНО.
**Наводка окна:** незакрытое наблюдение того же дня — `mut`-метод через `@` на
`mut`-получателе отказывается по имени, точечная форма проходит; парсер
2026-09-04 стал строить для `@name(args)` тот же узел `MethodCall`, что для
`x.m(args)`.

## Свойство класса — ОДНО на находки Н1–Н4

**Свойство:** «какого КЛАССА этот получатель» (место `ro` · место `mut` ·
владеемый временный · обещанный `consume`) решается ДВАЖДЫ. Один ответ —
**режим биндинга из области видимости** (`scope.mode_of_name`), другой —
**умолчание по СИНТАКСИЧЕСКОЙ ФОРМЕ выражения**. Пути расходятся ровно там, где
форма не попала в таблицу из трёх видов узлов.

**Двери-ответчики.** `novac/src/check/type_of.nv:87-103`, функция `arg_class`:

```
if k == NodeKind.Name { ... return match scope.mode_of_name(nm) { ... } }   // 89-98
if k == NodeKind.Paren { return arg_class(branch_children(e)[1], scope) }   // 100
if k == NodeKind.FieldAccess { return ArgClass.ArgRo }                      // 101
ArgClass.ArgOwnedTemp                                                       // 102 — всё остальное
```

Получатель, записанный как `@`, — узел `NodeKind.SelfExpr`
(`novac/src/parse/expr.nv:576-583`), и он падает в строку 102: **«владеемый
временный»**. Между тем режим приёмника ИЗВЕСТЕН и лежит в области видимости под
символом `@`: `novac/src/check/typing.nv:227-229` связывает `RECV_BINDING` с
`@ctx.fns.params[rfd.param_off].mode`. То есть второй ответчик не «не знает» —
он не спрашивает.

Дальше решение уходит в `mode_admits` (`novac/src/sem/binding.nv:146-153`):
`ModeMut` НЕ принимает `ArgOwnedTemp`, `ModeConsume` — принимает. Отсюда обе
стороны расхождения: `mut`-метод через `@` ОТКАЗАН, `consume`-метод через `@`
ПРИНЯТ.

**Синтаксисов носителя — ТРИ, и это не одна функция** (правило «класс называется
свойством, а не конструкцией»):

1. `@m(...)` — получатель `SelfExpr` в слоте ноль (Н1, Н2);
2. `f(@)` — тот же `SelfExpr` в позиции ОБЫЧНОГО аргумента (Н3): ключ строит та
   же `arg_class` через `typed_args` (`type_of.nv:65`), а сообщение об отказе
   приходит уже от свободного вызова и называет НЕ ту причину («столько
   аргументов»);
3. `(@).m(...)` — `Paren` рекурсивно возвращается в `SelfExpr` (Н3b): греп по
   `SelfExpr` рядом с `MethodCall` этой формы не находит.

Искал ЧЕТВЁРТУЮ форму — `@f.m()`, где получатель `SelfField`: она тоже падает в
строку 102, но парная ей `x.f.m()` падает в строку 101 (`ArgRo`), и обе формы
`mut`-метод отвергают. Зазор назван, двухформенного носителя на нём НЕТ (проба
`p_field_recv_*`).

**Размер класса в дереве:** в `novac/src/**/*.nv` объявлено **152** метода вида
`fn T mut @name(...)`, и они зовутся через `@name(...)` сотнями сайтов
(`@take(` — 152 сайта, при этом `@take` объявлен `fn Cursor mut @take()` —
`novac/src/parse/parse.nv:133`; `@emit_expr(` — 57; `@report_first_leaf_of(` —
126). Класс блокирует компиляцию novac'ом собственного исходника.

**Свойство находки Н5 — другое** и описано у самой находки: порядок «читатель
раньше писателя» для типа `match`-инициализатора.

## Адреса — по два ответчика на суждение

**Н1–Н4 «какого класса получатель».**

* Ответ А (по РЕЖИМУ): `novac/src/check/type_of.nv:94` — `return match scope.mode_of_name(nm) { ModeRo => ArgClass.ArgRo; ModeMut => ArgClass.ArgMut; ModeConsume => ArgClass.ArgConsume }`.
* Ответ Б (по ФОРМЕ): `novac/src/check/type_of.nv:102` — `ArgClass.ArgOwnedTemp` как остаток; сюда попадает `SelfExpr`, и через строку 100 — `(@)`.
* Место, где режим `@` УЖЕ ЗАПИСАН и его никто не читает: `novac/src/check/typing.nv:227-229` — `@scope.bind(RECV_BINDING, ..., @ctx.fns.params[rfd.param_off].mode)`.
* Единственный потребитель режима: `novac/src/check/scope.nv:131` (`fn Scope @mode_of_name`) — вызывается ровно из `type_of.nv:94` и больше ниоткуда (греп по дереву).
* Где класс входит в ключ: `novac/src/check/type_of.nv:42` (слот ноль, `typed_call_key`) и `novac/src/check/methods.nv:58` (`@method_arity_key`); для позиции аргумента — `novac/src/check/type_of.nv:65` (`typed_args`).
* Где ключ превращается в вердикт: `novac/src/sem/binding.nv:146-153` (`mode_admits`) → `novac/src/check/methods.nv:127-128` (текст отказа) и `novac/src/check/calls.nv:89-90` (текст отказа для позиции аргумента).
* Форма узла `@name(args)`: `novac/src/parse/expr.nv:576-583`.

**Н5 (p_armcall_dot / p_armcall_at2) «кто решает тип `match` и когда».**

* Ответчик А — ВЫВОДИТ: `novac/src/check/type_of.nv:324-345` — арм `MatchExpr` спускается в тело ПЕРВОГО арма и зовёт `type_of(body, ...)`; для `MethodCall` это `novac/src/check/type_of.nv:203-207`, где пустой канал = ICE.
* Ответчик Б — РЕШАЕТ и записывает: `novac/src/check/match_arms.nv:83` (`fn Checker mut @type_match`).
* Порядок ПРАВИЛЬНЫЙ (решатель раньше): `novac/src/check/typing.nv:357` — `@type_match(c)`, и только затем `novac/src/check/typing.nv:364` — `ro t = type_of(c, @ctx, @scope, @chan)`.
* Порядок ОБРАТНЫЙ (читатель раньше): `novac/src/check/binds.nv:176` — `ro vtype = type_of(init, @ctx, @scope, @chan)`, и только затем `novac/src/check/binds.nv:178-179` — `if ik == NodeKind.MatchExpr { @type_match(init) }`.
* Вопрос, на который эти два места отвечают по-разному: **«кто первым узнаёт тип `match` — тот, кто его решает, или тот, кто его читает?»** В теле-выражении — решатель, в инициализаторе биндинга — читатель.

* `p_default_arg_dot` / `p_default_arg_at` — опущенный параметр с умолчанием: обе формы зелены.
* `p_ro_overload_dot` / `p_ro_overload_at` — ОБРАТНАЯ проба Н2 со снятым ОДНИМ рычагом (приёмник объявлен `ro`, не `mut`): обе формы зелены и обе совпадают с оракулом. Это и доказывает, что рычаг — режим приёмника, а не наличие перегрузки.
* `p_matcharm_dot` / `p_matcharm_at` — первая, НЕ очищенная от конфаунда пара по арму `match`: выглядела расхождением ФОРМ, при снятии рычагов поодиночке (`p_armcall_dot2` / `p_armcall_at2`) оказалась расхождением ПОЗИЦИЙ. Форма была ложным подозреваемым.

* `p_arity_dot` / `p_arity_at` — лишний аргумент: novac отказывает одинаково в обеих формах (хотя и НЕ той причиной — «нет такого метода» вместо «лишний аргумент»). Расхождение нашлось у ОРАКУЛА, см. побочные наблюдения.

## Побочные наблюдения (НЕ находки клетки; каждое с командой)

1. **ICE novac на законной Nova: метод, возвращающий запись в скобочной форме `=> { ... }`.** Обе формы. Оракул собирает обе.
   `sh scripts/tools/novac-e1-smoke.sh $P/p_recordret_dot/p_recordret_dot.nv` → `internal compiler error (novac bug, not yours): main.nv:357: assert failed: sem: no type recorded for this node — a hole in the checker's channel (is_ty(t))`.

2. **novac отказывает в `mut`-методе на получателе-поле, оракул собирает.** `novac/src/check/type_of.nv:101` судит поле консервативно как `ArgRo`, и `mut` через поле недостижим ни одной формой. `sh scripts/tools/novac-e1-smoke.sh $P/p_field_recv_dot/p_field_recv_dot.nv` → `outside the subset: this type has no such method…`; оракул печатает `m = 1`.

3. **ОРАКУЛ выдаёт невалидный C на `@take(1, 2)`** — арность на пути `@` не проверяется, на точечном проверяется по имени. Это К4 в ОРАКУЛЕ; клетка не эта, но неподвижная точка поведения здесь сломана (novac обе формы отказывает).
   `./nova-cli/target/release/nova.exe build $P/p_arity_at/p_arity_at.nv -o /tmp/a.exe` → `error: too many arguments to function call, expected 2, have 3` / `5345 | return Nova_Box_method_take(nova_self, ((nova_int)1LL), ((nova_int)2LL));`
   `./nova-cli/target/release/nova.exe build $P/p_arity_dot/p_arity_dot.nv -o /tmp/a.exe` → `error: слишком много позиционных аргументов: ожидалось 1, передано 2`

## Что обошёл и почему

* **Перегрузка по режиму АРГУМЕНТА (не получателя)** — пробы упёрлись в D84 («duplicate definition … with same signature»): режим не входит в различающую сигнатуру у оракула, корректную пару перегрузок построить не успел.
* **`mut`-метод через `@` из `consume`-метода** — обе пробы вышли невалидными (`p_mutfromconsume_*`); гипотеза «режим объемлющего метода ни при чём» НЕ проверена запуском.
* **Путь операторов** (`novac/src/check/operators.nv:127-128`) — там класс обоих операндов зашит константой `ArgClass.ArgRo`, то есть ТРЕТИЙ ответчик на то же суждение. Пробу под `@equal`-перегрузку не построил: образца объявления `@equal` пользовательским типом в корпусе не нашёл, а выдумывать синтаксис запрещено.
* **Индекс как получатель** (`v[0].m()`) — узел `Index` тоже падает в строку 102; пары не строил.
* **`@` внутри дженерик-метода / инстанса** (`record_instance_method`, `novac/src/check/methods.nv:209`) — не трогал вовсе.
* **`novac check` как мера** — по брифу мерил ТОЛЬКО дымом; `check`/`emit` напрямую использовал лишь там, где оракул отказывает и дым судить не может (Н4, наблюдение 3).

## Противоречия

**1. Комментарий парсера утверждает полную взаимозаменяемость форм, чекер её не держит.**

`novac/src/parse/expr.nv:561-570`, дословно:

> THE SAME NODE SHAPE AS `x.m(args)`: [receiver, mark, name, '(', args,
> ')'], so the readers that index a MethodCall's children by position --
> eight of them across check/ and emit_c/ -- work unchanged, and both
> spellings of one form arrive as one node. […] No reader of SelfExpr looks at
> the leaf's text (measured: emit prints RECV_C_NAME, check binds by
> RECV_BINDING, type_of reads the channel), and the diagnostic position is the
> same `@`.

`novac/src/check/type_of.nv:75-102`, дословно (док-комментарий и остаток тела):

> /// WHAT this argument is, for rule P14: a place, a temporary, or a promise.
> ///
> /// The classes are decided by the SHAPE of the expression and, for a name, by
> /// how it was bound -- which is why the scope carries the mode.
> […]
> `    ArgClass.ArgOwnedTemp`

Первое место говорит «оба написания приходят одним узлом, читатели работают без изменений». Второе решает класс ПО ФОРМЕ выражения, и форма `SelfExpr` в его таблице отсутствует — то есть один из восьми читателей как раз работает по-другому. Выбирать между этими местами не развилка охотника.

**2. Комментарий `binds.nv` объявляет обратный порядок НАМЕРЕННЫМ; `typing.nv` делает наоборот, и оба про один и тот же `match`.**

`novac/src/check/binds.nv:71-74`, дословно:

> // A plain expression initializer is verified before it is typed. A match
> // initializer is NOT: the emitter decides its type before the arms bind
> // their binders, and that order is what makes "a match whose first arm
> // uses its binders" a refusal of the subset rather than a silent success.

`novac/src/check/typing.nv:352-357`, дословно:

> // The tail MATCH is a value (274.5 wave B5): typed by the
> // value door -- the fold demands the arms agree -- and its
> // type recorded for the emitter […]
> // The SAME mark as the tail call above, for the same
> // reason (#902): a refused arm leaves a node the lattice
> // cannot answer about, and asking anyway is an ice.
> `                    @type_match(c)`

Второе место называет ровно ту причину («asking anyway is an ice»), которую первое место своим порядком создаёт. Что здесь норма, а что дефект, решает окно, не охотник.

## Что решило окно, принимая отчёт (2026-09-04, окно 274)

* Противоречие 1 решается в пользу комментария парсера: `@` есть получатель с ИЗВЕСТНЫМ режимом, и `arg_class` обязан спросить область под `RECV_BINDING` — тем же ответчиком (А), что у имени. Это фикс класса, не носителя; он идёт первым в следующей волне 274.5, потому что 152 `mut`-метода собственного исходника ждут ровно его.
* Противоречие 2 — строка реестра с обоими адресами; норма — «решатель раньше читателя» (так делает тело), комментарий `binds.nv` снимается фиксом или доказывается пробой.
* Побочное наблюдение 3 — дефект ОРАКУЛА, зарегистрирован с меткой `(novac)` как найденный охотником этого трека; чинит окно интегратора (чекерный канал).
