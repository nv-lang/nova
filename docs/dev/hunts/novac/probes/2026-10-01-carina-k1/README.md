# Пробы ветки `p274-carina-k1` (№1520, №1521), 2026-10-01

Облачная сессия вела очередь окна Карины по двум строкам К1 охоты
`2026-10-01-mono-k1`. Это не новая охота, а замеры приёмки: пробы охотника лежат
рядом (`../2026-10-01-mono-k1/`), здесь только добавленные. Общее тело —
`../2026-10-01-mono-k1/run-probe.sh`, его зовёт каждый `cmd.sh`.

**Запуск на Linux** (тело писано под Windows): из корня репозитория
```sh
NOVAC=$PWD/novac/target/novac NOVA=$PWD/nova-cli/target/release/nova NOVA_CLANG=clang \
  sh docs/dev/hunts/novac/probes/2026-10-01-carina-k1/<проба>/cmd.sh
```
В `run.out` пути машины заменены на `<repo>`, `<scratch>`, `<tmp>`.

## Мера 0.2 и двойная сборка

`NOVAC_UNIT=1 NOVAC_SELF_PATH=novac/src novac check <исходник Карины без _test>`:
база `8405e5fcd` — **145**, ICE 0; после ветки — **145**, ICE 0. Ни один из 145 отказов не
стоит в теле экземпляра (`grep -c 'in the instance of'` = 0): форма, которой №1521 бил по
мере 0.2 (`priv-module-line`), на этой базе уже закрыта. **№1521 на базе 145 мест меры не
снимает.** Двойная сборка: предусловие `123/143` и у базового бинаря, и у нового.

## №1521: почему правки нет (развилка)

Тело экземпляра резолвит свободные имена через ОДНУ таблицу имён единицы, и этой
таблице нужного имени не дают:

- `sem/harvest.nv`, `harvest_fn`: переданная свободная функция, имя которой уже объявил
  компилируемый файл, **не регистрируется** (тень D125, `if is_free && !defs.def_of(mname).is_none() { return }`).
  В `hygiene-helper-fn` приватного `helper` модуля `hp.geo` в таблице нет вовсе — тело
  находит `helper` модуля `hp`. Без тени (`ctl-hygiene-no-shadow`) строка есть.
- `sem/harvest.nv`, `harvest_consts` / `harvest_types`: приватные константы и типы чужого
  модуля не регистрируются (D281 со стороны файла) — `SCALE` тела берётся у вызывающего.
- `DefTable` (`defs`) ключуется голым именем: две константы `SCALE` двух модулей в ней не
  уживаются, сколько бы экземпляр ни знал свой модуль.
- `check/run.nv`, `check_instance`: индекс строится `FnIndex.build(ctx.fns)` — без
  импортов файла тела и без его модуля (`@sees` молчит).

То есть «экземпляр несёт модуль и файл, двери их спрашивают» закрывает функции
(частично), диагностику и C-имя, но НЕ константы и типы: для них дверь спрашивать
нечего, пока имена хранятся одной плоской таблицей на единицу. Два пути с ценой — в
отчёте ветки `REPORT-carina-k1.md`.

## Оракул

`diag-wrong-file-module`: оракул отвергает `println(@len())` в теле `export fn Vec[T] mut
@mark() -> @` модуля `hp.geo` как `undefined identifier println` (`geo.nv:4:5`), хотя
`println` — прелюдия (07-modules.md, «Prelude — without import»). Возможный дефект
оракула; Карина на базе принимает и печатает `3`.
