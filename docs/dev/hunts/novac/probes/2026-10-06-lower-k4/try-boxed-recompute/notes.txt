Вопрос, на который места A и B обязаны отвечать одинаково:
  «каким путём ошибка e операнда x? (Result[T, E]) попадает в Result[U, E'] тела —
   E' == E (передаётся как есть), E' == any (упаковка), E' — сумма, оборачивающая E (D55)?»

A. check/try_rules.nv:119-124 @try_result_pair_ok — решает это по трём ветвям
   (have == want / is_any_ty(want) / @sum_wraps_error), на типах, пропущенных через
   @concrete (подстановка параметров экземпляра), и возвращает ТОЛЬКО bool «допущено».
   Какая из ветвей сработала — не записывается никуда (нет @record вида пары).
B. lower/lower_coalesce.nv:142-144 @lower_try — вычисляет ответ ЗАНОВО, своей формулой:
   boxed = is_any_ty(E') && !is_any_ty(E), на типах БЕЗ @concrete (rt — тип места
   возврата, ot — записанный тип операнда). Ветви «сумма» в формуле нет: всё, что не any,
   печатается как Err(e) без обёртки.
C. emit_c/emit_flow.nv:481-485 — третий ответ на соседний вопрос «упакован ли e в any»:
   Failure(e) для очистки упаковывает e в any ВСЕГДА (@any_box_of), без проверки
   is_any_ty(E); ErrOf (emit_place.nv:191) — по флагу B.

Где ответы расходятся (по коду, не по запуску):
 1) сумма-расширение D55: A сейчас отказывает по имени подмножества (TRY_ERROR_SUM_WRAP_MSG,
    проба try-sum-wrap-subset это показывает), значит до B не доходит. В день, когда A
    начнёт допускать эту ветку (комментарий A прямо называет её «legal»), B ответит
    boxed=false и вариант Err тела получит e типа E вместо значения суммы — неверный C или
    неверное значение. Ничто не заставит править B вместе с A: решение не передаётся.
 2) E == any: A — «fits» (have == want). B — boxed=false (верно). C — упаковывает any ещё
    раз (двойная упаковка в Failure(e)). Сейчас недостижимо: оболочка не несёт ни одного
    экземпляра Result[_, any] (пробная программа с Result[int, any] снята и удалена:
    Карина отказала по имени «carries no `Result` instance for NovaRes_nova_int_void*»).
 3) обобщённое тело: A смотрит через @concrete, B — нет. На Result[int, int] расхождения
    нет (проба try-generic-same-error: SAME stdout), потому что для не-any ошибок обе
    формулы дают «как есть»; разойтись могут только при any-подстановке параметра, а она
    недостижима по п.2.

Итог: носителя с неверным поведением СЕЙЧАС нет — «зазор назван, носитель латентен».
Это второе вычисление уже решённого суждения (К4) в форме: чекер решает трёхзначный
вопрос и отдаёт один бит, понижение восстанавливает два значения из трёх своей формулой.
