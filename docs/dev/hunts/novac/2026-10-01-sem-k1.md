# Охота: подсистема `sem` × К1 (трек novac, 2026-10-01)

КЛЕТКА | sem | К1

**Клетка назначена интегратором** (2026-10-01, ~05:35): долг охоты трека novac на `main`
`37c9bfc33` — 1459 строк поверхности при бюджете 1500 (`check-hunter-debt`), следующее
слияние волны Карины переполнило бы его. Поверхность — волна Э.10 (274.11): раздельная
компиляция по единицам — `sem/interop.nv` (`InteropTable @add_module/@has_module`,
`Ctx @in_program`), `sem/mangle.nv` (имя вызываемого берёт модуль СТРОКИ, шаг 1
`49cd7b64e`), регистрация newtype чужого модуля (`fill_handed_newtypes`/`repr_of_decl`,
`3504ea170`). Класс К1 — молча неверный результат: Карина принимает программу и печатает
не то, что оракул. Охотник — фоновый агент интегратора по правилам `defect-hunter`
(opus), 21 проба. Субъект — novac, собранный оракулом в worktree `nova-hunt-novac` с
`37c9bfc33`; оракул — `nova.exe` главного дерева на том же `main`.

**Как выражена клетка.** Многомодульная программа подаётся Карине так же, как её
собственная самосборка Э.10: пакет во временном каталоге, `NOVAC_SELF_PATH=<pkg>/src`,
`novac emit src/main.nv`. Отдельная единица по-честному не линкуется, если зовёт тело
чужого модуля (названное упрощение шага 2а: «the program emitter makes the C whole»), —
поэтому К1 достижим только там, где единица линкуется сама: имя чужого символа совпало
с СВОИМ (находка 1) или чужой тип совпал по имени с типом шелла (находка 2).

**Ответ.** Подозрение подтвердилось двумя механизмами К1.

1. **Имя вызываемого не инъективно.** `c_callable` склеивает модуль строки и имя одним
   `_` (`sem/mangle.nv:213-214`, `:631-632`; модуль — `module_path_c`,
   `sem/file_shape.nv:42`, тоже через `_`), а `_` — буква идентификатора. Своя `geo_f`
   модуля `hp` и `f` модуля `hp.geo` получают ОДИН символ `novac_fn_hp_geo_f__to_nova_int`;
   вызов чужой `f` линкуется к своему телу. Метод `Meters @double` модуля `hp.geo` и своя
   `geo_double(m Meters)` — то же (получатель — параметр ноль, `mode_tag` пуст). Требование
   записано тут же: «two modules declaring `helper` must differ» (`mangle.nv:624`, 274
   §9.1d п.1). Символы шелла для std (`c_free_symbol`, `mangle.nv:503`) — с префиксом
   длины и инъективны; символы программы — нет.
2. **Тип чужого модуля регистрируется по голому имени в одной плоской таблице, первая
   декларация выигрывает** (`sem/harvest.nv:160`: `if defs.def_of(tname).is_some()
   { continue }`) — std (включая ПРИВАТНЫЕ типы) идёт раньше модулей программы, импорт не
   спрашивается. Запись программы `Permissions { read_only bool, mode u8 }` становится
   value-записью std `Permissions { read_only bool, mode int }`: копия вместо псевдонима,
   `int` вместо `u8`. Свою декларацию с тем же именем Карина честно отвергает
   (`check/literal_rules.nv:309`, «the interop shell already declares a struct under this
   name»), чужую — не судит. **Носитель есть в исходнике самой Карины:** `novac.lex.Token`
   против приватного `Token enum` в `std/src/encoding/json.nv:342` — три конструкции
   `Token { kind: .. }` в `parse/parse.nv:157,180,183` отвергаются в мере 0.2 как «names a
   field the type does not declare (#812)».

Вне К1, тем же заходом: имена тегов и конструкторов суммы чужого модуля решаются по
модулю ВЫЗЫВАЮЩЕГО (`mangle.nv:563`, `:573-574`) — шаг 1 перевёл на модуль строки только
вызываемые; типы чужого модуля проходят `check`/`emit`, а C единицы их не определяет.
Свободная функция чужого модуля (и std) вызывается без импорта.

Не подтвердилось (совпало с оракулом): компилируемый файл сам лежит под
`NOVAC_SELF_PATH` — перегрузки, обобщение, метод (`ctl-self-file-in-self-path`); свой
newtype рядом с одноимённым чужим (`ctl-own-newtype-vs-foreign`).

**Запуск проб:** `sh docs/dev/hunts/novac/probes/2026-10-01-sem-k1/<проба>/cmd.sh` из
корня репозитория (или `ROOT=<repo>`; `NOVAC=`/`NOVA=` переопределяют бинари). Проба —
пакет в `<проба>/pkg/` (`.nv.txt`, `nova.toml.txt`); общее тело `run-probe.sh` копирует
его во временный каталог с настоящими именами и делает: сборку и запуск оракулом;
`novac check` и `novac emit` с `NOVAC_SELF_PATH=<pkg>/src` (строки C по образцу
`GREP`); компиляцию и линковку C Карины флагами оракула из кэша
`scripts/tools/novac-e1-smoke.sh` и сравнение stdout. `self-build-token` — свой
`cmd.sh` над `novac/src/parse/*.nv` (`NOVAC_UNIT=1`). В `run.out` пути машины заменены на

## Что обошёл и почему

- **Модульные значения и константы чужого модуля** (`novac_mv_<имя>` без модуля,
  `mangle.nv:491`): `export ro` оракул не импортирует, `export const` Карина отвергает
  «unknown name» — коллизия ячеек не выражена.
- **Обобщение чужого модуля** — отвергается по имени (calls.nv:597-603), экземпляр не
  строится; коллизия с экземпляром своего обобщения не проверялась.
- **Вызов чужой функции без прототипа** (`ctl-foreign-call`): C компилируется с неявным
  объявлением `int f()`; при возврате `str` clang отказывает («passing 'int'»), при `f64`
  — пройдёт с неявным преобразованием. Сегодня это кончается ошибкой линковщика; когда
  единицы начнут линковаться (шаг 2б), неявный `int` станет неверным ABI. Не проба на
  тихий результат — линковщика единиц нет.
- **Две записи программы с одним именем в разных модулях** — тот же корень, что
  находка 2, но C не собирается (записи чужого модуля в единице не определены), до
  поведения не доходит.
- **Наблюдения об ОРАКУЛЕ (трек закрыт, не находки):** модуль программы с именем `a`
  ломает сборку в `std/src/collections/vec/access.nv:208` («no function `compare` in
  module `a`», `oracle-module-named-a`); `@ + @` в методе newtype другого модуля —
  линковщик «undefined symbol: Nova_Meters_method_plus» (`oracle-newtype-op-in-method`).

## Противоречия

1. Импорт имени, совпадающего со своей функцией. Оракул на импорт из модуля программы:
   «[E_IMPORT_NAME_CONFLICT] imported function `label` (from `./geo`) has the same name as
   a function declared in this module» (`import-conflict`); на импорт из std того же вида
   — принимает и печатает `true` (`import-conflict-std`). Карина принимает оба. Код
   `E_IMPORT_NAME_CONFLICT` в `spec/` не найден (греп по `spec/`), норма для выбора между
   двумя поведениями оракула мне неизвестна.
