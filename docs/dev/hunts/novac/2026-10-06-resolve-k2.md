# Охота: вызов через bound и реестр протоколов (`resolve` × К2) (трек novac, 2026-10-06)

КЛЕТКА | resolve | К2

**Клетка назначена окном** задачи #14 (разрешение интегратора 2026-10-06 08:14; долг охоты трека novac 1637
строк поверхности с якоря `0435b8f4d` при бюджете 1500). Предмет — новая поверхность ветки задачи (коммит
`332202454`): реестр протоколов `sem/protocols.nv` (протоколы std в реестре, `def_of` по имени), предикат
соответствия `resolve/resolve.nv` (`missing_sig_of`, `@method_mode_for`, подстановка приёмника generic-кандидата,
режим приёмника D209), фильтр bound `check/bounds.nv`. Свойство К2 для клетки: ответ «удовлетворяет ли тип bound»
берётся по ГОЛОМУ ИМЕНИ (протокола, метода) из плоской таблицы и путается, когда одно имя значит разное.

**Охотник** — агент `defect-hunter` (модель sonnet, 8 проб, суб-агентов нет). Субъект — Карина, собранная из
дерева ветки на `332202454`; оракул — `nova.exe` главного дерева. Пробы перенесены окном в
`probes/2026-10-06-resolve-k2/` (пять, по одной программе на каталог), каждая повторно прогнана окном.

**Запуск:** `sh docs/dev/hunts/novac/probes/2026-10-06-resolve-k2/<проба>/cmd.sh` из любого места внутри
репозитория; `NOVAC=`/`NOVA=` переопределяют бинари.

**Ответ одной фразой.** Два расхождения: протокол программы с именем протокола прелюдии (`Display`) Карина
принимает, а оракул отвергает ошибками в std — и за этим у Карины стоит реестр протоколов по голому имени; метод с
другим типом возврата оракул засчитывает в bound (проверка проходит, сборка падает в C), Карина отказывает по D72.

## Находки

НАХОДКА | К2 | resolve | shadow-proto | (№1759) программа объявляет `type Display protocol { @display() -> str }`, тип с
`fn Pt @display() -> str` и `show[T Display]`: Карина принимает без диагностик; оракул отвергает восемью
`E_IMPL_SIGNATURE_MISMATCH` на `std/src/prelude/protocols.nv` (`int @display` … `Result @display`) — сверяет `#impl(Display)`
std с протоколом ПРОГРАММЫ. По Plan 62 / D125 прелюдия затеняется программой («user-wins», `W_PRELUDE_SHADOW`) — в её
коде, а не в std. У Карины тот же класс в другой форме: `harvest_protocols` (`novac/src/sem/protocols.nv`) пропускает
протокол std, если имя уже занято, и `ProtoTable.def_of` отвечает одним протоколом на имя для ВСЕХ вопросов —
bound, написанный в теле std (`[T Display]`), судился бы контрактом программы.

НАХОДКА | К2 | resolve | ret-type-mismatch | (№1758) `type Sizer protocol { @size() -> int }`, `fn Bx @size() -> str`,
`show_sizer[T Sizer](Bx{..})`: Карина отказывает «`Bx` is missing: size() -> int (E_BOUND_NOT_SATISFIED, D72)»;
оракул `nova check` проходит, `nova build` падает в clang («1 error generated») — метод засчитан в bound по имени без
сверки типа возврата. Норма — D72 («Concrete K … must implement all bound methods»): Карина по норме, расхождение
направления 1.

## Что обошёл и почему

- generic-тип-приёмник `Box[T]` против `Box[int]` под bound — проба упёрлась в отказ подмножества раньше механики
  bound (`p4`, не перенесена);
- режимы приёмника у generic-метода протокола и bound на собственном параметре метода — не дошёл (бюджет проб);
- перегрузки `@size` на одном типе (`overload-same-name`), метод того же имени у другого типа
  (`other-type-same-name`), свободная функция того же имени, протокол после использования (`proto-after-use`) —
  обе стороны согласны;
- известное №1742 (режим приёмника у bound) воспроизведено (`p8`) и находкой не считается.
