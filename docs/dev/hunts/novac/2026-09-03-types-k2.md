## Свойство 1: ОДНА плоская строковая таблица на четыре рода сущностей, last-wins

Пять форм: вариант×вариант, тип×вариант, тип×функция, вариант×функция,
тип×константа.

* `sem/defs.nv:111` — `DefTable @add`: `@names.put(name, @rows.len())`,
  «LAST PUT WINS»;
* `sem/sem.nv:831` — имя ВАРИАНТА кладётся в то же пространство `NsDefs`, что и
  имя типа;
* `check/exprs.nv:89` — `Sum.Variant` резолвится по ГОЛОЙ строке `vt.text`,
  затем `:94` сверяет `vd.sum_id == head_t` — и если строка вернула вариант
  чужой суммы, единственный исход — отказ на `:111`;
* `sem/defs.nv:200` — `@type_decl(name)`: `DefVariant/DefFn/DefConst => None`,
  то есть вытесненный тип становится «не типом»;
* `sem/sem.nv:350` — `ice("sem: a name in TYPE position that the registry does
  not hold")`: место, где вытеснение превращается в ICE.

**Нарушенное правило.** Порядок старшинства `AGENTS.md`: оракул — авторитет
поведения, программа, которую он компилирует и запускает, не может быть ложно
отказана. Плюс собственная норма: идентичность — id, не имя
(`novac/src/names/names.nv:8`, П2), а здесь идентичность варианта есть ИМЯ, и
пары (сумма, вариант) в ключе нет.

**Соседний модуль тот же класс уже решил:** `resolve/resolve.nv:181-217`
(`FieldIndex`) держит цепочку одноимённых рядов и различает их по `owner_id`
целым числом. Расходятся не правила, а два места.

## Свойство 2: C-имя склеено из РАЗНЫХ пространств через разделитель, легальный внутри частей

* `sem/mangle.nv:652` — тег примитива = ABI-имя (`nova_int`);
* `sem/mangle.nv:654` — тег записи = объявленное имя, БЕЗ префикса;
* `sem/mangle.nv:541-546` — `s.append(fd.name)` и следом `s.append("__")`.

Две наблюдаемые формы: подмена ABI-имени примитива объявленным именем
(`p_prim_name_shadow`), поглощение разделителя `__` именем функции
(`p_fn_name_sep`). Обратная проба на один рычаг: `p_prim_name_ctl` — та же пара
перегрузок с переименованной записью — зелёная.

Класс был назван КОНСТРУКЦИЕЙ («имя не несёт параметров», `mangle.nv:508-511`),
а свойство — «строка не инъективна», и у него есть ещё минимум две формы.

## Противоречие в дереве — выбор не охотника и не окна

`sem/defs.nv:104-110`:

> A CHAIN OF SAME-NAMED ROWS WAS BUILT HERE AND REMOVED THE SAME HOUR … with
> the foreign types entering first, the chain was UNOBSERVABLE … A construction
> nobody can see the effect of is the K7 class this plan refuses.

`check/exprs.nv:104-106` — тот же класс, соседний модуль, комментарий В КОДЕ,
который цепочка и обслуживала бы:

> // A variant of ANOTHER sum under this type's name: not this type's value;
> // refused as a non-variant of the head right below.

Первое место говорит «ненаблюдаемо», второе признаёт наблюдаемость отказом.
Замер (четыре пробы выше) стоит на стороне второго.

## Подозрения без пробы

* `mono_tuple_name` инъективно, КРОМЕ ньютайпа: `c_type` ньютайпа равен
  написанию носителя (`mangle.nv:269`). Проба `p_tuple_newtype_name` даёт ОДИН
  typedef на два типа, но наблюдаемого расхождения нет по построению (макет
  ньютайпа = макет носителя);
* ключ интернера `bucket_of` инъективен, пока `TYPE_KIND_COUNT == 8`, но проход
  по цепочке (`types/types.nv:179-182`) сравнивает ТОЛЬКО аргументы, не
  перепроверяя вид и голову: цена рассинхрона константы и перечисления — не
  отказ, а МОЛЧАЛИВОЕ слияние. Носителя сегодня нет;
* столкновение своего и ПЕРЕДАННОГО объявления (`defs.nv:118-127`) — шестая
  форма свойства 1, требует второго файла, бриф держал в одном.
