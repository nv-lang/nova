## Что обошёл и почему

- `emit_interp.nv:66` — жёсткий `(nova_int)` для не-строкового слота интерполяции: форма К3 налицо, но носителя нет — `check/exprs.nv:302` держит слот множеством `{str_id, int_id}` по идентичности id, всё иное отклоняется по имени. **Владелец 2026-09-05 признал это упрощением вне спеки** (спека: `Into[str]`) — см. 274 §1.3а.
- `emit_match.nv:125-128` — суффикс `LL` у литерального образца собран на месте; носитель не построен: беззнаковый литерал шире `int` отклоняется раньше (`p09-u64-print`).
- `emit_c.nv:704-708` — переменная `for`-диапазона всегда `nova_int`; проба `p07-range-u8` совпала на узких границах, разводящий вход упирается в отказ по литералу. **Владелец: не по спеке (D58)** — 274 §1.3а.
- `emit_c.nv:384` — хвостовой `return (nova_int)0LL` только при `ret == prims.int_id`: форма #910, провал не построен.
- `p15-user-type-named-set` — не находка: оракул сам отказывает (конфликт с типом std).
- `p18`, `p19`, `p09` — именованные отказы подмножества, не дефекты; перечислены как граница поиска.
- Оракульскую эмиссию C не смотрел — только поведение через дым (П25/П27).
- Гейт, `nova test`, мега-CU, cargo не запускались; дерево не менялось; стражи не тронуты.
