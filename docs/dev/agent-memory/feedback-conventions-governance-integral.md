`docs/conventions-governance.md` — **неотъемлемая, нормативная часть конвенции** (мета-документ над ВСЕМИ конвенц-доками: compiler-conventions, test-conventions, dev-workflow, nv-coding-style и т.д.). НЕ «лесер/процессный» — связывающ так же, как §-правила. Мета-правила про процесс/governance — там, и они полноценная конвенция.

**Why:** в сессии 2026-06-26 я (а) назвал его «скорее процесс, чем compiler-tech» (недооценил), (б) ТРИЖДЫ перекладывал на владельца решение, которое конвенция уже давала (§1 soundness-в-чекере исключал codegen-вариант; §0 указывал целевую форму vs интерим-патч) — владелец каждый раз толкал меня к ответу, который был в конвенции.

**How to apply:** нормативность = конвенция ДАЁТ ответ, не только запрещает. Когда §-правила однозначно указывают путь — следуй и ДЕЙСТВУЙ, не оформляй как «развилку для владельца». Развилка владельцу = ТОЛЬКО когда конвенция реально не решает: приоритизация (что раньше/стоит ли сейчас), продуктово-семантическое (spec-first D-блок), ресурсы, или внутреннее противоречие конвенций. Технический выбор с конвенционным ответом — решай сам. Связано: [[feedback-test-conventions-strict]] (конвенции нормативны, правка по согласованию + инлайн-дата), [[feedback-maximize-nv-sourcing]].
