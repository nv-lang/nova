Никогда не передавать текст с обратными апострофами (`), бэкслешами (`\(`) или
не-ASCII через `python - <<'PY'` / `python -c` в bash. Только Write-скрипт файлом,
затем `python <файл>`, затем grep-самопроверка результата.

enforcement: гейт — `scripts/guards/check-no-mojibake.sh` (ловит порчу UTF-8→CP1251
храповиком, реестр №637); срез «assert упал до записи» держится только
самопроверкой после скрипта — немашинное для этой половины, причина: порчу
до записи гейт увидеть не может, её ловит только grep результата.

**Why:** наступил ЧЕТЫРЕ раза за смену 2026-08-16 (после двух 2026-08-08):
(1) assert на строке с бэктиками упал ДО записи — коммит-сообщение обещало
текст, которого в файле не было; (2) `\(` в sed-регулярке внутри python
через heredoc → SyntaxWarning + AssertionError; (3) кириллица «не в
репозитории, см. оговорку» через heredoc → mojibake в строке реестра №457,
поймал `check-no-mojibake` (145 > 144); (4) `—` в комментарии стража →
assert. Каждый раз страж/assert ловил, но стоил перезапуска гейта.
Порча UTF-8 → CP1251 бывает и когда heredoc в кавычках `<<'PY'` — дело не в
подстановке, а в кодировке stdin для python на Windows.

**ЕЩЁ ТРИ РАЗА 2026-08-19, И ХУДШИЙ ВИД — ТИХИЙ.** Двойной бэкслеш `\\n`
схлопывается в НАСТОЯЩИЙ перевод строки по дороге через оболочку:
(1) якорь `w("dup_verdict=-1\\n…")` не совпал — assert упал ДО записи, это
видно; (2) `printf 'rows=0\\n'` превратился в двухстрочную команду — работает,
но уродливо; (3) ХУДШЕЕ: питон внутри heredoc в самотесте стал синтаксически
неверным (`newline='` + перевод строки), фикстура НЕ переписалась, и тест
«упал» по причине ПРЕДЫДУЩЕГО случая — выглядит как настоящий провал и уводит
диагностику в сторону. Полчаса на ложный след.

**ЧЕТВЁРТАЯ ФОРМА, 2026-08-19 вечером — БЭКТИК СРАБАТЫВАЕТ НЕ ПРИ ЗАПИСИ, А ПРИ
ЗАПУСКЕ.** Файл записан Write'ом ПРАВИЛЬНО, порчи нет, грепом всё на месте — и
всё равно ломается. Причина: правился `scripts/guards/check-ci-status.sh`, а он
сам встраивает python как `python -c "…"` в ДВОЙНЫХ кавычках. Имя задания в
бэктиках, вписанное в python-КОММЕНТАРИЙ внутри этого блока, оболочка выполнила
как команду: `crate-tests: command not found` при каждом запуске стража.
Комментарий — не защита: внутри двойных кавычек нет «комментариев», есть текст.
Правило шире прежнего: **прежде чем писать бэктик в файл, посмотри, не окажется
ли этот текст внутри двойных кавычек ЧУЖОГО скрипта.** Для shell-стражей со
встроенным python — не писать бэктики и `$` вообще, брать имена в кавычки-ёлочки
или без разметки.

**How to apply:** правило абсолютное: не-ASCII/бэктики/бэкслеши = файл.
Даже одну строку. Даже «быстренько». Write → python file.py → grep -c.
Если бэкслеш всё же нужен внутри строки — собирай его кодом: `BS = chr(92)`,
переводы строк `LF = chr(10)`. Литерал не переживает дорогу.
Для консольного вывода кириллицы из python: писать в файл и читать Read'ом
(консоль cp1251 роняет `→` и подобные).
И после правки shell-стража — ЗАПУСТИТЬ его, а не только его самотест:
самотест звал стража и был зелёным, а ошибка оболочки видна только в живом
прогоне.
