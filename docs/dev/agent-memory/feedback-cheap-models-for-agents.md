Владелец (2026-07-06, повторно закреплено): «оптимизируй работу агентов под дешёвые модели и запускай их автоматически»; «запиши паттерн, чтобы в будущем всегда использовал автоматически».

**ПАТТЕРН (применять с первого запуска каждой сессии, без напоминаний):**

1. Перед КАЖДЫМ запуском Agent — классифицировать задачу и выбрать `model`:
   - `haiku` — механика по точному списку: правки файл:строка, готовые sed/команды, грепы-инвентари, журнальные правки, сбор чисел. Задание = список + команды + гейт с ожидаемыми числами.
   - `sonnet` — исполнение по готовой карте/рецепту: корень известен, файлы/сигнатуры/шаги расписаны; тесты по образцу; миграции по таблице; спека по фактам; классификация по чётким критериям.
   - `opus` — ТОЛЬКО неизвестные: разведка корней, архитектурные атомы, новые дизайны, состязательные проверки. Выбор opus мысленно обосновывать.
2. Конвейер: opus-разведка → детальная карта (Ф.0-стиль: таблицы, точные пути/строки/сигнатуры) → sonnet/haiku-исполнение по карте. Чем дешевле модель — тем детальнее задание.
3. В отчётах владельцу ВСЕГДА указывать модель каждого агента: «[haiku]», «[sonnet]», «[opus]».

**Подтверждённый выигрыш (сессия 2026-07-06):** haiku ~8 мин/34k токенов против часа+ у opus; sonnet ~32 мин/232k против 2-4ч/300-740k — при равном качестве на задаче-по-рецепту (sonnet даже нашёл настоящий дефект стеночных часов). Цена — время на детальный рецепт, окупается многократно.

**Ловушки:** haiku без точного списка промахивается — не давать ему свободы; sonnet на разведке вязнет — не давать «разберись сам»; если по ходу дешёвый агент упёрся в неизвестное — не мучить, поднять до sonnet/opus следующим заходом.

**ЗАКРЕПЛЕНО ПОВТОРОМ 2026-07-08 (5-й раз, формула владельца):** «готовь план более
детальный под более дешёвые модели» — инвестировать в карту, чтобы исполняла дешёвая
модель; haiku — ЯВНЫЙ запрет заходить в main-репу в каждом промпте; настраивать на
checkpoint-сохранение прогресса и МОНИТОРИТЬ (server rate-limit валит фоновых — резюм
SendMessage «оцени git log/status, продолжай с места», подтверждено спасениями этой
сессии: ICE-охотник и A8 реанимированы после обрывов); модель КАЖДОГО агента писать
в отчётах. Практика 2026-07-08: sed-травмы haiku-волны (недопереименованные
record-литералы, покалеченные `ro _ =`, @map._buckets за generic-дырой чекера) →
для haiku-переименований в задание ВКЛЮЧАТЬ пункт «греп по СТАРОМУ имени после
правки = 0 (включая record-литералы `{ имя: ... }`, shorthand `имя,`, доступы
`@x.имя`)» и запрет трогать легальные `_`-формы (`ro _ =`, `_pad`).

**УРОК 2026-07-21 (эпидемия фонового ожидания — 6+ случаев за день, sonnet тоже):** агенты
запускают прогон run_in_background и «ждут уведомления», которое НИКОГДА не придёт (фон
умирает с завершением хода агента). Формулировка «никаких фоновых» НЕ работает. В брифы
писать ЖЁСТЧЕ: «run_in_background ДЛЯ ТЕБЯ НЕ СУЩЕСТВУЕТ; каждый Bash-вызов обязан вернуть
результат в ТОМ ЖЕ вызове (timeout до 600000); если ждёшь уведомление о фоне — ты уже
ошибся, перезапусти синхронно». При зависании агента в «жду нотификацию» — SendMessage
с перезапуском синхронно, или забрать финализацию себе (коммит готового + гейт за мной).
