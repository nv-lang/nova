Владелец 2026-08-08, дословно: «конечно, никогда не копи» — в ответ на
предложение разобрать больше десятка старых веток с несведённой работой
(`p-fmtdirect` 237 коммитов, `p-consume-soundness` 208, `p-coalesce` 177 и др.),
накопившихся до релиза.

enforcement: немашинное — разбор накопленного есть суждение о том, что считать
накоплением (живая параллельная ветка неотличима от брошенной по метаданным
git). Частично машинизируемо и заведено отдельно: №472 (проба окна попадает в
постоянный корпус) и №475 (страж без предела времени) — оба про конкретные виды
накопления, у обоих в приёмке страж. Общее правило остаётся привычкой.

**Why:** накопленное не дешевеет со временем, а дорожает. Ветка на 200 коммитов,
отведённая полгода назад, перестаёт сливаться; забытая проба окна попадает в
постоянный корпус и роняет авторитетный гейт (случай №472); 52 незапушенных
коммита превращают любой красный гейт в блокер всего сразу. Плюс накопленное
невидимо: пока никто не спросил, оно не числится ни в одном плане и не имеет
владельца.

**How to apply:** как только замечено накопление — разбирать в том же сеансе, не
записывая «сделаем до релиза». Разбор не обязан быть исполнением: дешёвое окно,
собирающее ФАКТЫ по каждому элементу (от чего отведено, что содержит, сливается
ли), уже снимает невидимость — решение по каждому принимает владелец. Не
спрашивать разрешения на сам разбор, если он дешёвый; спрашивать только по
решениям, которые из него следуют. Относится не только к веткам: незакрытые
дефекты, отложенные фазы, «вернусь потом» — тот же класс.
