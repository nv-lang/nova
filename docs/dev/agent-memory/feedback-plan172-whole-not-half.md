Для Plan 172 (и подобных больших многофазных планов) цель = **весь план закрыт ЦЕЛИКОМ**, а НЕ выполнение какого-то конкретного пункта. Половинчатое решение / фокус на одном атоме владельца НЕ интересует. Путь выполнения строить так, чтобы привести к закрытию ВСЕГО плана **как можно быстрее**.

**Why:** владелец повторял это многократно (2026-06-27) и явно отметил, что я застревал на отдельных пунктах (sync-каскад) и половинил вместо движения к полному закрытию. «Половинчатое ≡ переделываемое» (= §0 docs/compiler-conventions.md «целевая форма vs интерим-патч»).

**How to apply:**
- Выбирай **keystone-путь**: атом/единый источник, который СИСТЕМНО разблокирует максимум остального, а не per-item патчи. Для 172 это U.4.5 (единый структурный typed-IR: codegen потребляет из канала, не re-derive) — снимает целый КЛАСС codegen-re-derive багов (sync/net/Option-erasure/dispatch) разом + это §10-предусловие sync-removal + headline-критерий. Per-bug grind глубокого каскада (sync) = анти-§0 «накопление заплат».
- **Продолжай автономно**, не спрашивай по мелочам. Развилки/вопросы сперва проверяй по docs/compiler-conventions.md — часто снимаются сами (напр. coexistence load_builtins+import = уже §0/§3-запрет, новой конвенции не нужно). Останавливайся и согласуй ТОЛЬКО на: (а) настоящей развилке, которую конвенция не резолвит (напр. 172.3 type-set syntax — языковое решение); (б) если хочешь добавить/изменить docs/compiler-conventions.md.
- Не путать «выполнил пункт плана» с «двигаю к полному закрытию» — мерило прогресса = ближе ли ВЕСЬ 172 к закрытию по fastest-пути.
- Связано: [[feedback-no-external-memory-for-project-state]] (source of truth — docs/plans), [[feedback-codegen-dce-verification]] (§7 верификация против чистого бинаря).

«если добро — запускаю X» ЗАПРЕЩЕНО, когда X внутри мастер-директивы (172-185) —
запускать сразу. Дифф-вопросы владельца отрабатывать параллельно работающим волнам,
а не вместо них: перед ответом на вопрос проверить «есть ли активная волна; если
нет — запустить следующую из очереди».
