Владелец 2026-08-08, вместе с «используй opencode для задач агентам там, где это
возможно»: **«Для механического исполнителя нужны очень точные команды, точный путь
внутри проекта, явный список запретов и образец строки результата».**

enforcement: немашинное — самопроверка перед запуском opencode: пройти бриф по
четырём пунктам ниже и убедиться, что каждый закрыт буквально.

**Why:** механический исполнитель не достраивает контекст. Формулировка «прогони
раннер точечно» для Claude-агента работает, для opencode — нет: он не знает пути к
бинарю, не выберет фильтр и отдаст отчёт в произвольной форме, который придётся
разбирать руками. Мой промпт на аудит раскладки тестов провалился ровно по двум из
четырёх пунктов (не было команд целиком и не было образца результата) — поймано до
получения отчёта.

**How to apply — четыре обязательных блока в каждом брифе opencode:**

1. **Команды целиком, копируемые.** Не «собери и прогони», а
   `cd d:/Sources/nv-lang/nova && nova-cli/target/release/nova test --filter X 2>&1 | tail -20`.
   С путём к бинарю, с редиректом, с ограничителем вывода.
2. **Точный путь внутри проекта.** Не «раннер», а `nova-cli/src/<файл>.rs`; не
   «конвенции», а `docs/dev/test-conventions.md`. Папка без файла — уже
   недоформулировано.
3. **Явный список запретов, отдельным блоком.** Что НЕ трогать, НЕ коммитить, НЕ
   запускать (мега-CU, полный `nova test`), чего НЕ создавать. Разбросанные по тексту
   запреты не считаются — нужен список.
4. **Образец строки результата.** Показать буквально, как должна выглядеть строка
   вердикта, с подставленными значениями. Без образца формат отчёта будет свой.
