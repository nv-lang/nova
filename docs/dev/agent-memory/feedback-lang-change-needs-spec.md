Владелец (2026-07-10): «слияние, меняющее язык, не пушится без спек-амендмента».

**Why:** волна 174.5 добавила 9 методов указателей + ретракцию операторных форм, но
агент честно оставил spec-амендмент D216 в OPEN-остатке — я как интегратор влил и
запушил код БЕЗ спеки. Владелец поймал вопросом «где в спеке?». Spec-first (§5
compiler-conventions) требует обратного: спека — источник истины, код следует.

**How to apply (правило приёмки интегратора):**
- Слияние, меняющее ЯЗЫК (новый синтаксис/оператор/метод-интринсик/ретракция формы/
  новый E_*/D-семантика), НЕ пушится, пока в том же слиянии нет spec-амендмента
  (D-блок или амендмент существующего) в spec/decisions/.
- Проверка перед push: `git diff <base>..HEAD --stat` — если задет parser/lexer/
  emit_c-интринсик/types-диагностика И нет правки spec/decisions/*.md → СТОП,
  дописать амендмент, только потом push.
- Если агент оставил спеку в «OPEN-остатке» — интегратор дописывает сам ПЕРЕД push
  (как D216-амендмент 59f7edc2a постфактум), либо возвращает агенту.
- Не относится к: чистый std/тесты/perf-рефактор без изменения наблюдаемого языка
  (172.14 value-ABI — поведение то же, спека не нужна; но новый E_* — нужна).
