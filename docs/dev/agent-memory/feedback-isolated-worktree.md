Когда пользователь говорит «работай изолированно» / «делай работу по плану X изолированно» / задача занимает много фаз — **сразу же** создать свой постоянный worktree (например `../nova-planNN/`) на отдельной ветке (`planNN-main`) и **всё** делать там: и реализацию, и мержи между sub-phases.

**Why:** пользователь работает в основном worktree (`D:/Sources/nv-lang/nova/`) в VS Code. Любой `git switch` в нём — это файлы меняются прямо у него под рукой, ломает его сессию. Даже если я возвращаюсь обратно через несколько секунд, это всё равно вмешательство.

**Конкретный анти-паттерн (что я сделал во 2026-05-18 Plan 62):** агенты-исполнители работали в изолированных worktree (правильно), но fast-forward мерджи в локальный `main` я делал из основного worktree пользователя, переключаясь `git switch main` → `git merge --ff-only` → `git switch plan-67`. Пользователь это заметил, потребовал откатить main и перенести работу в отдельную папку.

**How to apply:**
- Первая команда при «изолированной» задаче: `git worktree add -b planNN-main ../nova-planNN <base-ref>`.
- Все дальнейшие действия — внутри `../nova-planNN/`. Основной worktree не трогать вообще, даже для `git switch`.
- Sub-agent'ы с `isolation: worktree` или явными worktree-папками — потомки моего worktree, не пользовательского.
- Мерджи sub-phase → my-main делать в `../nova-planNN/`, никогда не в пользовательском.
- Финальный merge моей ветки в реальный `main` — только после явного approval'а пользователя.
- Если пользователь сам работает на `main` — это финальный merge **тем более** требует подтверждения.
