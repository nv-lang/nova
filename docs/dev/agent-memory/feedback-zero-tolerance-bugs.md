Владелец (2026-07-06, по поводу возможного гэпа перегрузки статического метода по арности): «исправить, введи конвенцию — нулевая толерантность к багам».

**Why:** маркер-отложка и обходы маскируют дефекты, они копятся и расползаются как псевдо-конвенции; владелец хочет, чтобы каждый найденный дефект компилятора немедленно получал разведку и фикс.

**How to apply:**
1. Дефект найден (мной или агентом) → в ту же волну назначить разведку [opus] или фикс по карте [sonnet]; не «в очередь на потом».
2. Маркер [M-*] — только как ссылка на уже назначенную/идущую работу.
3. Обход дефекта в std/тестах — запрещён; зависимая правка приостанавливается до фикса.
4. Зафиксировано в docs/compiler-conventions.md §4а. Связано: [[feedback-conventions-governance-integral]], [[feedback-cheap-models-for-agents]].

**ЗАКРЕПЛЕНО ПОВТОРОМ 2026-07-12 (ТОТ ЖЕ класс — generic-static ctor `Vec.new`, из-за которого конвенция и
родилась 2026-07-06!):** я нарушил её же — отложил `[M-vec-new-cap-default-arg-backfill]`, навесив маркер,
спихивающий в ЧУЖОЙ план (196.2), вместо работы над самим багом. Владелец поймал 4× за сессию. Ужесточённый
чек-лист баг-фикса (держать САМОМУ, не ждать ловли владельцем):
- **Маркер ссылается на работу над САМИМ багом**, НЕ на смежный/чужой план «там как-нибудь починится».
  Спихнул в чужой план = скрытый обход.
- **Фикс = КОРЕНЬ, сходимость на СУЩЕСТВУЮЩИЙ путь; НЕ новый сайт/окно** даже для точечного (§0/§3). Новая
  точка резолва «если X → …» = заплатка на не-едином окне. Не можешь без нового сайта → архитектурный вопрос
  владельцу, не тихая заплатка (тут стоп ОПРАВДАН — см. [[feedback-dont-stop-to-ask-proceed]]).
- **Регресс-тест на ТОЧНОЕ пересечение, что породило баг** (здесь: generic-static + default-арг + кросс-модуль),
  в conformance по D-блоку; ОБЯЗАН быть red-на-до-фикс-бинаре / green-на-фиксе (иначе не сторожит). Баг
  проскочил ИМЕННО потому, что это пересечение не было покрыто — не повторять упущение. [[feedback-test-conventions-strict]].
