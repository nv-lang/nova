Не делать два прохода: сначала `head -5` / `limit: 5` для статуса, потом повторный Read для деталей. Это вдвое увеличивает время.

**Why:** пользователь явно указал что это медленно и неэффективно.

**How to apply:** при проверке статуса плана — читать файл целиком сразу (или достаточно большой limit). При проверке нескольких файлов — запускать все Read параллельно в одном сообщении.

**Applies also к `nova test` output:** запускать через `nova test ... 2>&1` БЕЗ grep — потом `cat` весь output одним заходом. Если в output есть FAIL — детали error уже там, не делать второй заход через `nova check <single_file>`. Пользователь повторно отметил это как медленно (2026-05-18).
