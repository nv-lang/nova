Когда пользователь указывает на баг или просит что-то исправить — не делать предварительный "разведочный" проход (Read → понять структуру → второй проход с Edit). Это удваивает время.

**Why:** Пользователь явно указал: двухшаговый подход медленный и раздражает.

**How to apply:**

1. Если файл уже читался в этой сессии — сразу делать Edit/fix без повторного чтения.
2. Если файл не читался — использовать Grep для точного поиска строки/контекста, затем сразу Edit. Не читать весь файл ради одного фрагмента.
3. Для ошибок в коде/синтаксисе, которые пользователь описал явно — делать fix немедленно, без предварительного "а давайте посмотрим что там".
4. Если нужно понять контекст вокруг строки — использовать Grep с `-C 3` (context lines), а не Read всего файла.

**Алгоритм для исправления бага на сайте:**
```
1. Grep точной строки с ошибкой → получаем file_path + line context
2. Edit сразу с правильным вариантом
3. git add + commit + push
```

**Алгоритм для исправления по описанию пользователя:**
```
1. Пользователь говорит "строка X неверна, должно быть Y"
   → сразу Edit: old_string=X, new_string=Y
   → не нужно читать файл заново
```
