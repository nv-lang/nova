Владелец (2026-07-06, ревью std/http): «почему Response.of? больше подходит Response.new».

**Правило именования конструкторов в Nova std:** `.of(...)` зарезервирован за вариадик-конструкторами коллекций («из этих элементов»: `Vec[T].of(a,b,c)` — см. [[feedback-vec-of-not-from-in-tests]]). Обычный конструктор типа из аргументов = **`.new(...)`**.

**Why:** `.of` семантически = «коллекция из перечисленных элементов»; для записей/value-типов это читается неверно, плюс возникает асимметрия внутри модуля (было `Request.new` vs `Response.of` в std/http — устранено, коммит в main 2026-07-06).

**How to apply:** при написании/ревью .nv-конструкторов — `Type.new(...)`; `.of` только когда параметры = элементы создаваемой коллекции. Проверять агентские поставки grep'ом на `.of(` вне коллекций.
