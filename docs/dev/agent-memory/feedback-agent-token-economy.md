Владелец (2026-07-08): «3-4 дня — очень много, у меня не хватит лимитов. Оптимизируй
работу агентов по минимальному использованию лимитов».

**Why:** токен-бюджет — реальное ограничение проекта; скорость без экономии бесполезна.
Факт сессии 2026-07-08: sonnet-волны съедали 300-500k токенов каждая — в основном на
(а) чтение конвенций/доков целиком, (б) широкие тест-прогоны с длинными выводами,
(в) самостоятельную разведку вместо готовой карты.

**How to apply (режим экономии, ПОВЕРХ [[feedback-cheap-models-for-agents]]):**
1. haiku — дефолт для ИСПОЛНЕНИЯ. В промпт ВСТАВЛЯТЬ выдержки конвенций/карт (не
   «прочти docs/...» — чтение доков агентом = тысячи токенов каждый раз). Точные
   file:line, готовые sed/команды, ожидаемые числа гейтов.
2. sonnet — только где нужен вывод по ходу (нетривиальные переписывания). opus — по
   умолчанию ЗАПРЕЩЁН; только после того как haiku→sonnet дважды упёрлись, и с
   максимально суженным контекстом задачи.
3. Гейты гоняет ГЛАВНАЯ сессия через Bash (grep-сжатые выводы), НЕ агенты: агентам —
   только targeted-проверка своей правки (1 юнит), полная приёмка у меня.
4. Агентам в промпт: «файлы целиком не читать без необходимости; работать точечно по
   списку; отчёт — краткий список чисел/хешей, без прозы».
5. Меньше волн — крупнее батчи: фикс-оверхед агента (чтение контекста) амортизировать
   на 10-20 однотипных правок, а не 3-5.
6. Обрывы: НЕ перезапускать с нуля (теряет весь прогретый контекст) — резюм с места.
7. Приоритизация под бюджет: P0/P1 и решения владельца — вперёд; полировка (lint-план,
   журналы, приборка) — только на остатке лимитов.

Связано: [[feedback-cheap-models-for-agents]], [[feedback-workflow-agents-checkpoint-progress]].

**ЗАКРЕПЛЕНО 2026-07-21 (двойное слово владельца в релизный день):** «уменьши количество
агентов вдвое» + «нужно экономить лимиты» — ЖЁСТКИЙ ЛИМИТ: ≤2 параллельных агентов;
очередь волн — строго последовательно по сходу. Интеграторские гейты — ПАЧКАМИ (один
мега-CU+флагман на несколько влитых веток), не по-волново. Не запускать «на всякий
случай» проверочные волны — сначала дешёвый собственный греп/прогон.
