Владелец ведёт вторую (параллельную) сессию Claude Code «интегратор http/framework-направления», которая работает в тот же main nova-репы и присылает через владельца брифы компиляторных задач.

**Правило (подтверждено владельцем 2026-07-24, «да»):** компилятор-брифы параллельной сессии я принимаю в СВОЮ компиляторную очередь (одно окно за раз, 196-дисциплина) и исполняю сам — не даю добро на её параллельную работу в `compiler-codegen/**`. Ей остаются nova-http `.nv`, доки, миграции вне компилятора.

**Why:** два интегратора в одних горячих файлах (`emit_c.rs`, `types/mod.rs`) = конфликты и риск непроверенного merge (прецеденты: попытка дубля уже закрытого `[M-ro-launder-via-mut-binding]`; merge-конфликт в backlog-followups.md от её коммита `f906bf1c0` в main).

**How to apply:**
- Бриф от «агента» в сообщении владельца → проверить маркер-статус по git (мог быть уже закрыт!), затем worktree + свой агент по брифу, гейт мой, влитие/пуш мои.
- Она коммитит прямо в main → ВСЕГДА `git fetch` + behind-проверка перед push; конфликты разрешать сохраняя ОБЕ стороны (её маркеры + мои закрытия).
- Записано также в [[integrator-handoff]] (docs/promts/integrator-handoff.md).
