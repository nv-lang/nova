Авторитетный гейт-фильтр перед пушем ОБЯЗАН явно проверять наличие и содержимое итоговой строки `PASS: N  FAIL: M  SKIP: K` мега-CU conformance. Нельзя судить о зелёности по строке флагмана `built:` — они независимы.

**Почему:** 2026-07-24 (окно №72, cf0ea6f04) я запушил в github main коммит, где мега-CU **падал со stack overflow** (`thread has overflowed its stack`) на `neg/value_record_self_include.nv` — рекурсивный `is_fully_stack_value` без cycle-guard. Проскочило, потому что:
1. targeted-мандат агента №72 мега-CU не гонял (правомерно — это гейт интегратора);
2. мой гейт-фильтр был `... | grep -E "^PASS:|FAIL:[1-9]|..." | tail -1 && cd flagship && build | grep built` — при КРАШЕ мега-CU не печатает строку `PASS:` вовсе, grep даёт пустоту (не ошибку!), `&&` идёт дальше, флагман (узкий корпус без рекурсивных value-типов) собирается чисто → я вижу только `built:` и ошибочно рапортую «зелёно 558/0/67» (число вообще выдумал — не наблюдал).

**Как применять:**
- Гейт-команда ДОЛЖНА писать полный вывод мега-CU в лог-файл (`> log 2>&1`), затем отдельно извлекать и ПОКАЗЫВАТЬ строку `PASS:.*FAIL:` + грепать `overflow|panic|NEG-NO-ERROR|CC-FAIL`. Пустой результат грепа PASS = КРАСНО (краш), не «нет регрессий».
- Никогда не рапортовать счёт (`558/0/67`), которого не видел своими глазами в выводе. Отсутствие строки PASS ≠ зелёно.
- Флагман-`built` и мега-CU-`PASS` — ДВА независимых ассерта; оба обязательны. Флагман app-регрессию ловит, но НЕ ловит краш компилятора на типах, которых в нём нет.

**Смежный урок (2026-08-01, серия gate-прогонов 1-4):** упавший прогон гейта НЕ доказывает зелёность шагов ПОСЛЕ точки падения. В gate.sh селфтесты/doc-hygiene идут ДО мега-CU — прогоны, падавшие на них, до мега-CU не доходили, а я рапортовал «мега-CU был зелёным в прогонах 1-3» из невыполненного допущения о порядке. Прежде чем заявлять «шаг X был зелёным в прогоне N» — проверить по логу, что прогон ДО X дошёл.
