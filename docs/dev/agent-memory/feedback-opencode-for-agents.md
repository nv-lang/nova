Владелец (2026-07-31, в блоке стоячих правил): «используй opencode для задач агентам там, где это возможно».

enforcement: немашинное — выбор инструмента запуска агента делает интегратор в момент
постановки задачи; хук это не перехватит (решение до любого tool-вызова).

**Факт:** `opencode` установлен (v1.18.10, в PATH). С ~конца июля по 2026-08-07
молча падал при КАЖДОМ вызове (нулевой вывод, 0-байтные логи) — npm-обёртка
вычисляла базовый каталог через `cygpath -w`, который обрезал кириллический путь
`C:\Users\Евгений\...` до `C:\Users\`. Интегратор починил 2026-08-07: обёртка
заменена на POSIX-путь без конвертации (оригинал рядом: `opencode.bak-2026-08-07`).
Урок: «инструмент молчит» ≠ «инструмент мёртв» — разобрать причину, а не тихо
пересаживать задачи на Claude-агентов (так opencode и выпал из оборота на неделю).

**Why:** экономия лимитов Claude-агентов — оффлоуд механических задач на внешний
агент-CLI; дополняет линию [[feedback-cheap-models-for-agents]] (haiku=механика,
sonnet=карта, opus=разведка).

**ДЕТАЛИ ПОСТАНОВКИ ЗАДАЧИ (замерено 2026-08-08, владелец: «пиши задачу более
детально, особенно для opencode»):** opencode РАБОТАЕТ (проверено функционально:
прочитал файл, записал результат, exit 0), но у него СВОЯ система разрешений:
- **запись за пределы каталога проекта БЛОКИРУЕТСЯ** (`permission requested:
  external_directory` → отказ). Путь результата ОБЯЗАН быть внутри репы; scratchpad
  в `%TEMP%` ему недоступен — первое задание провалилось именно на этом;
- **сбрасывает рабочий каталог** в корень проекта (`Shell cwd was reset to ...`);
- вызов: `opencode run "<текст>"`, есть `-m provider/model`, `--agent`, `-c/--continue`.
Бриф для него писать КАК ДЛЯ МЕХАНИЗМА: точные команды дословно, абсолютный путь
результата внутри репы, ОБРАЗЕЦ заполненной строки таблицы, нумерованные шаги,
явный список запретов (git не трогать вовсе; не менять существующие файлы; создать
РОВНО ОДИН файл; не собирать), инструкция «не пропускать трудные пункты, писать
"не установлено"», и требование писать файл ПОСТЕПЕННО (устойчивость к обрыву).

**Граница haiku ужесточена (2026-08-08, ВТОРОЙ случай):** haiku-окно на чисто
перечислительной задаче (инвентарь 98 точек `abort()`) **зависло на 600 с с нулём
коммитов** — worktree создан, работы ноль. Первый такой случай был 2026-08-07.
Вывод: haiku не тянет не только классификацию ([[feedback-haiku-not-for-classification]]),
но и ДЛИННЫЕ перечисления. Механику такого рода отдавать opencode либо делать
самому: перечисление — это грепы, интегратору дешевле выполнить, чем ставить задачу.

**How to apply:** при запуске исполнителя сначала оценить, потянет ли задачу
opencode (механика по детальной карте: миграции по списку, sweep'ы, фикстуры по
образцу); Claude-агенты — для задач, требующих контекста репы/конвенций/гейтов.
Правила брифов те же: свой worktree (haiku/opencode — запрет main-репы),
суб-агентов не спавнить, UTF-8, греп конфликт-маркеров одной командой с коммитом,
CPU-дисциплина (мега-CU не гонять), чекпоинты прогресса, модель/инструмент
указывать в отчёте и при запуске.
