Владелец (2026-07-12, дословно «жёсткое правило»): греп маркеров конфликта — ОБЯЗАТЕЛЬНЫЙ шаг между
разрешением конфликта и коммитом, и он идёт **В ТОЙ ЖЕ команде**, что и `commit` (не отдельным проходом,
который легко забыть/пропустить).

**Why:** забытый conflict-маркер (`<<<<<<<`/`=======`/`>>>>>>>`) уезжает в историю и ломает сборку; отдельный
«проверю потом» теряется под потоком задач.

**How to apply:** шаблон, применяемый и мной, и в КАЖДОМ задании агента:
`git add <конкретные-файлы> && { git diff --cached | grep -nE '^\+(<<<<<<<|>>>>>>>|=======$)' && echo КОНФЛИКТ-СТОП; } || git commit -m ...`
— grep нашёл маркер (exit 0) → `echo` срабатывает, `commit` НЕ выполняется; grep пусто (exit 1) → `commit` идёт.
