Коммит — по ВЕХЕ, и вехи разбиваются по ТИПУ задачи. Не сваливать в один коммит
разнородное: правка компилятора, правка гейта/стражей, конвенция, план — это
разные типы, значит разные коммиты, даже если сделаны подряд.

**Why:** атомарная читаемая история; каждый коммит — самостоятельная
ревьюируемая единица, которую можно откатить, не задев чужой тип работы.
Уточнено владельцем 2026-08-19: не «после каждой большой задачи», а «по вехам,
разбивая на типы задач».

**How to apply:** взял веху → довёл до зелёного гейта → коммит конкретными
файлами (см. [[feedback_git_add_specific]]). Смешалось два типа в одном дереве —
два коммита подряд, каждый со своим префиксом (`sem(#274):`, `gate(#274):`,
`conv:`, `plan(#274):`). Сочетается с работой по фазам плана.

enforcement: немашинное — «одна веха одного типа» не проверить скриптом; частично
держат check-commit-hygiene (язык, маркеры, авторство) и check-novac-commit-donor
(строка донора при правке novac/src).
