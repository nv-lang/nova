Владелец 2026-08-10, после трёх случаев порчи чужой работы: **«твои правки вносят
проблемы, не делай так»**.

enforcement: немашинное — самопроверка перед каждой правкой файла в
`d:/Sources/nv-lang/nova`: «я в общем дереве или в своём worktree?»

**Why.** Столкновения были НЕ между окнами — окна работают каждое в своём
worktree и вливаются слиянием. Столкновения были между **двумя интеграторами**,
которые оба коммитили прямо в `d:/Sources/nv-lang/nova`. Индекс git один на
рабочее дерево, поэтому `git add` любого из них забирает чужие несведённые файлы.

**Прямые правки в общем дереве делает ТОЛЬКО ОДНА сторона** — та, чья работа и
есть слияния, авторитетный гейт и реестр. Второй стороне это не нужно: она вполне
может работать в своём worktree и вливаться слиянием, как обычное окно.

**Мой конкретный механизм ошибки (назван прямо):** в коммите переименования я
запустил `git add -u`. Он стейджит ВСЕ изменённые отслеживаемые файлы, то есть
гарантированно захватывает чужие несведённые правки. Это же нарушает давнее
правило «`git add` только по именам файлов, никогда `-A`/`.`» — `-u` из той же
семьи и запрещён так же.

**How to apply:**
1. Своя работа — в своём worktree (`d:\Sources\nv-lang\nova-<имя>`), вливать
   слиянием. Не редактировать файлы в общем дереве «потому что так быстрее».
2. `git add` — ТОЛЬКО перечислением имён. Ни `-A`, ни `.`, ни `-u`.
3. Перед коммитом — `git diff --cached --stat`: если там файл, который я не
   называл, значит захватил чужое.
4. Исключение — только когда роль требует общего дерева (слияние, гейт, реестр по
   договорённости), и тогда всё равно по именам.
