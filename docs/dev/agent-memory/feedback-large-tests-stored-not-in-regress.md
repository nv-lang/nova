**ТРЕБОВАНИЕ (hard): компиляция И выполнение дефолтного регресса (`nova test` / CI) должны быть БЫСТРЫМИ.** Это критерий качества тест-сьюта, не пожелание. Любой тест, заметно замедляющий компайл или прогон регресса, не должен быть в дефолтном пути.

Следствие: большие тесты (полные conformance-наборы, объёмные individual-тесты) **НУЖНЫ и ХРАНЯТСЯ в репозитории**, но **НЕ запускаются в дефолтном `nova test` / CI**.

**Why:** дефолтный регресс не должен раздуваться — огромный тест (напр. 50000 пар collation, ~5 мин компайл) замедляет каждый прогон без пропорциональной пользы; но сам большой тест ценен (ловит краевые баги, что малый сэмпл пропускает — реально поймал surrogate-баг + 4/200 провальных чанка в collation).

**How to apply:**
- Дефолтный `nova test` / CI = только **малый репрезентативный коммит-сэмпл** (uniform-spread, напр. **1500** для conformance) — быстро компилируется И выполняется.
- **Полный/большой набор хранится в репо** рядом (отдельная папка/маркер), помечен **opt-in**, прогоняется **вручную/out-of-band при приёмке** (G0 «без упрощений» доказывается этим прогоном).
- НЕ выкидывать большие тесты; НЕ коммитить их в обычный test-discovery путь, который сканит `nova test`.
- Прецедент Unicode-conformance: коммит 1500, out-of-band полный (normalization 19965, words 1826, sentences 512, collation 227800).
- Механизм исключения из дефолт-прогона — `[M-test-runner-large-test-lane]` (см. backlog): нужна конвенция (папка `_slow/`/`_conformance_full/` или маркер `// EXPECT_SLOW`), которую `nova-codegen test-all` скипает по умолчанию, прогон через флаг `--include-slow`.
