Субагент НЕ получает нотификаций своих фоновых задач после завершения хода: его
«completed»-финал со словами «жду уведомления от фонового прогона» = агент мёртв
навсегда, пока интегратор не реанимирует SendMessage'ем. 2026-08-02 так зависли
ЧЕТЫРЕ окна разом (w1b, 221-revision, bigint-tuple, docs-extractors) — часы простоя.

**Why:** task-notification «агент завершился» приходит РОДИТЕЛЮ; сам агент после
завершения хода не живёт и ничего не ждёт.

**How to apply:** в КАЖДЫЙ бриф субагенту: «фоновые прогоны жди СИНХРОННО
(run_in_background: false) либо проверяй результат в том же ходе по файлу вывода;
ЗАПРЕЩЕНО завершать ход словами про ожидание нотификации». Реанимация зависшего:
SendMessage «не жди — проверь фон руками, продолжи». Связано:
[[feedback-agent-stall-1h-restart]] (30-мин надзор ловит таких).

enforcement: немашинное — брифы пишутся свободным текстом в промптах агентов,
хук их не видит; машинная страховка второй линии = cron-будильник 30-мин надзора
(коммит+mtime), который и поймал все четыре случая; требование продублировано в
docs/dev/promts/integrator-handoff.md (раздел «СТОП-правило»).
