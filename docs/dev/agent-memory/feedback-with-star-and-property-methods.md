Владелец (2026-07-06): подтвердил конвенцию `with_*` и напомнил про любимый стиль «одноимённые методы-свойства для чтения и записи полей» (я его не знал и не применял — теперь записан в docs/nv-coding-style.md).

**УТОЧНЕНИЕ (2026-07-06, аргумент владельца):** with_* легален ТОЛЬКО для честной копии (value-типы / полная замена полей). Для КУЧЕВЫХ записей поверхностная копия делит кучевые поля со старым объектом — «независимый экземпляр» это иллюзия → канон: мутирующее беглое свойство `mut @x(v) -> @`.

**ДОПОЛНЕНИЕ (2026-07-23, владелец): «по максимуму цепочные вызовы — это в нашей конвенции».** Fluent-цепочки (`ServerPolicy.new().max_inflight(16).max_body_bytes(8192)`) — канон, ради него сеттеры возвращают `@` (D409). Обходы «цепочка → промежуточный локал», сделанные из-за компилятор-багов (класс [M-http-props-mut-chain-argpos-value-ptr-mismatch] / №16 detach-вариант), — временные: после фикса бага разворачивать ОБРАТНО в цепочки.

**Правила:**
1. `with_*` — НИКОГДА не мутирует: конструктор с параметром (`with_capacity(n)`) или копия приёмника с заменённым полем (`with_extension(e)`). Мутатор так не называть.
2. Доступ к полям — **одно имя, перегрузка по арности** (D84): `@x() -> T` чтение, `mut @x(v T) -> @` запись (бегло; с D409 возврат приёмника автоматический). НЕ get_x/set_x.
3. **Сеттер обязан возвращать `@`** (D117 AMEND-2): `-> @` — умолчание; `-> ()` только с обоснованием; fallible-установка — не свойство, а операция с Result/эффектом.
4. **Цепочки по максимуму** — и в новом коде (агентские брифы: «конфиг/строители — fluent-цепочкой»), и при ревью (развёрнутые в локалы цепочки без причины — замечание).

**How to apply:** в заданиях агентам на .nv-код указывать правила 1-4; проверять поставки грепом `get_[a-z]|set_[a-z]` и мутирующих `with_`; после закрытия fluent-chain-багов — сигнал агентам вернуть цепочки на местах обходов.
