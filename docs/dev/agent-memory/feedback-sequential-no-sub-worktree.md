Когда у меня есть постоянный изолированный worktree под план (например `nova-planNN`) и я работаю над фазами **последовательно** (одна фаза → merge → следующая) — не создавать sub-worktree под каждую фазу. Запускать агента прямо в основной worktree плана, коммитить в его ветку напрямую.

**Why:** sub-worktree даёт изоляцию только когда нужно — для **параллельной** работы или для возможности полного отката отдельной ветки. При последовательной работе sub-worktree лишь добавляет overhead:
- `git worktree add` копирует 1000+ файлов на каждую фазу.
- Каждый агент тратит время на `cargo build` с нуля (target/ не разделяется между worktree).
- vcpkg_installed/, libuv submodule приходится переносить из родительского worktree.
- Merge между sub-branch → main_branch и cleanup — лишние шаги.

Пользователь явно сказал «почему не делаешь всё в nova-plan62» и выбрал «работать прямо в основном worktree» вместо «sub-worktree под каждую фазу».

**How to apply:**
- В постоянном worktree плана (`nova-planNN/`) запускать агентов с `cwd: D:/Sources/nv-lang/nova-planNN/` напрямую.
- Коммитить в ту же ветку (`planNN-main`), линейная история.
- Sub-worktree создавать **только** когда:
  - 2+ агента работают параллельно над независимыми частями (редко).
  - Нужна возможность полного отката отдельной фазы без касания других (если конкретно ожидаешь высокий риск).
  - Эксперимент с большим scope, где может потребоваться merge --abort.
- Для одиночной последовательной фазы — НЕТ.
