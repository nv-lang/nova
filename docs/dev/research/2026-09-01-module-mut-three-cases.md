# Предложение: модульное изменяемое состояние — три случая

> **Статус: ПРЕДЛОЖЕНИЕ** (решение за владельцем). Выделено 2026-09-02 из
> [2026-09-01-mn-safety-via-effects.md](2026-09-01-mn-safety-via-effects.md) §8:
> тема самостоятельная — снятие части запрета `E_MUT_AT_MODULE_LEVEL` — и сцеплена
> с M:N только носителем (Vela). Понадобится свой D-амендмент; нужное множество
> типов уже определено D415 §1 (mut-alias-safe).

### Блокер для Vela-на-Nova: у `#share` нет внутренней изменяемости

Замер (проба внутри дерева, файлы удалены):

```nova
ro c = AtomicI64.new(0)
c.fetch_add(1)
// [E_LOCAL_NOT_MUT] local-binding `c` не помечен `mut`,
// но вызывается mut-метод `fetch_add` (тип `AtomicI64`)
```

Мутаторы атомиков объявлены с **`mut`-приёмником** — таких подписей в
`std/src/runtime/sync.nv` **59**. Внутренней изменяемости нет.

**Следствие: сегодня Vela-на-Nova написать нельзя.** Модульного `mut` нет
(`E_MUT_AT_MODULE_LEVEL`), а глобальное состояние рантайма — счётчики, реестр воркеров,
флаги готовности — требует именно его: `ro`-биндинг на атомик мутировать не даёт.

**Первая редакция рекомендовала «`#share` подразумевает внутреннюю изменяемость» —
отозвано владельцем 2026-09-01.** Довод возражения сильнее моего: `ro` в Nova означает
ровно одно — «read-only view, ничего через него не пишется», — и одинаково для
приёмника, параметра и поля. Исключение «кроме типов, которые сами разрешили» ломает
однородность трёхосевого режима ради одного случая. Плохой размен.

### Три случая модульного изменяемого состояния

| что на модуле | чем безопасно |
|---|---|
| `mut counter = 0` | ничем — **остаётся запрещено** |
| `mut workers = AtomicI32.new(0)` | синхронизация внутри типа: `#share` |
| `mut active_scope FiberQueue` (`#per_thread`) | по копии на поток — делить нечего |

**Второй случай — не новая политика.** D415 §1 уже определяет это множество дословно:
«**mut-alias-safe** — безопасно алиасить для МУТАЦИИ: **ТОЛЬКО внутренняя
синхронизация** — audited `#share`-vouch». То есть «изменяемое, которое можно трогать
из нескольких файберов» = «тип с `#share`» уже записано и уже проверяется на границе
`spawn`. Модульный `mut`, ограниченный такими типами, — та же норма в другой позиции.
`ro` при этом не трогается вовсе.

**Третий случай — не разделяемое, а неразделяемое.** У каждого потока своя копия,
гонки нет по построению; `#share` тут ни при чём. Безопасность держится на эффекте:
всякая функция, трогающая такую переменную, несёт `SameThread`, и `spawn` её не
пропустит.

**Что остаётся под запретом:** модульный `mut` обычного типа — настоящий
несинхронизированный глобал. Диагностика сохраняет работу, меняется текст: не «на
модуле `mut` нельзя», а «на модуле `mut` только у типа с `#share` либо под
`#per_thread`». M:N-рассказ становится точнее: **несинхронизированного глобального
изменяемого состояния нет**, а синхронизированное и per-thread — есть, и оба видны в
объявлении.
