# 16 — consume-паттерны payload сумм: авто-перенос и два варианта освобождения от маркера

Research-записка под будущее решение владельца (D157/D180-амендмент).
Повод: пример `nova-postgres/examples/smoke/src/main.nv:37` —
`Ok(consume s) => s` внутри `consume stream = match TcpStream.connect(…)`.
Все факты ниже — замеры свежим бинарём оракула (2026-09-24), не чтение.

## Замеренные факты

1. **Норма сегодня (записанное решение).** Амендмент consume-волны А
   (`spec/decisions/05-memory.md:1070`): решение владельца 2026-07-18,
   **вариант А «enforce по букве»** — философия D180 «visible ownership
   transfer на КАЖДОМ binding-site». Plain `Ok(x)` на must-consume payload
   (`Result`/`Option`, D156-пропагация) — ошибка `E_CONSUME_PATTERN_REQUIRED`
   с machine-applicable suggestion «insert consume». Проба: `Ok(s) => { s.close() }`
   на `Result[TcpStream, NetError]` — отказан.
2. **Чистый перенос с маркером работает:** `Ok(consume s) => Ok(s)` — check ✓.
3. **Generic-эрозия.** `Result[T, E]` объявлен БЕЗ `[T consume]` бáунда
   (`std/src/prelude/core.nv:37`), generic-тело `map_err`
   (`match @ { Ok(v) => Ok(v), … }`) — silent-ignore по backward-compat D156.
   `connect().map_err(…)` на `Result[TcpStream, NetError]` работает ЦЕЛИКОМ
   (check ✓ build ✓ run ✓ — stream переживает перенос, write+close чисто):
   корректность держится на поведении мономорфизации, а не на правиле.
4. **Расхождение check↔emit на mode-only перегрузках с consume-аргументом
   (свежий дефект, родня #309).** Две перегрузки `f(TcpStream)` /
   `f(consume TcpStream)`, вызов `f(s)` с consume-биндингом:
   чекер разрешает в **consume**-версию («s отдано consume-вызовом»,
   `s.close()` после — D131), рантайм исполняет **view**-версию
   (печатает "view", поток молча утекает). Контроль: только view-перегрузка
   → честный D133-not-consumed. Завести в реестр и починить ДО любой
   ступени ниже (оба варианта полагаются на согласованность tiebreak'а).
5. **Протоколы vs эффекты (ортография, для потомков):** `@read`/`mut @`/
   `.static` — протокольные оси (D458/D143); декларация эффекта — С `fn`
   (D459); handler-литерал — БЕЗ (проба оракула).

## Вариант 1 — авто-consume только для чистого авто-переноса

Биндинг payload-паттерна без маркера легален IFF использован **ровно один
раз** в позиции форсируемого move: аргумент конструктора (тип может
меняться — запись by-value), хвост арм'а/возврат. Всё остальное (вызовы
функций, view-использования, множественные использования, замыкания) —
по-прежнему с маркером; нарушение формы — та же
`E_CONSUME_PATTERN_REQUIRED`.

- **Философия:** оговорка с принципом, не ломание — «маркер документирует
  РЕШЕНИЕ; там, где грамматика форсирует переноз, решения нет».
  Точный прецедент — **D409** (`-> @` авто-возврат): автоматика форме с
  одной семантикой, класс ошибок исчезает по построению. Видимость
  переезжает с пая на точку решения (`consume stream = …` остаётся
  маркированным; smoke-строка читается `Ok(s) => s`).
- **Эргономика:** закрывает сантехнику (std-комбинаторы `Ok(v) => Ok(v)`,
  smoke-форма). НЕ покрывает идиому «распаковал и потребил»
  (`Ok(s) => s.close()` — маркер остаётся); это главный проигрыш.
- **Machinery:** локальная shape-проверка в чекере; резолвер не трогается.
  Generic-эрозия закрывается НОРМАТИВНО (форма синтаксическая, не
  зависит от знания T — правило работает в generic-телах структурно).

## Вариант 2 — авто-consume биндинг + принудительный переноз на использованиях

Любой payload-биндинг must-consume типа — авто-consume; вызовы разрешаются
естественно: consume-методы — существующим диспетчером получателя
(`Ok(s) => s.close()` без маркера), свободные перегрузки — существующим
tiebreak'ом (чекер УЖЕ предпочитает consume-версию для consume-аргумента).

- **Философия:** переоткрывает письмо решения 2026-07-18 (вариант А) и
  идёт против течения D133/D180/№667/№672 — обязательство невидимо
  везде, диагностика объясняет ненаписанное. Контраргумент, которого не
  было в июле: generic-эрозия делает «букву» неприменимой к generic'ам
  принципиально; «биндинг следует природе типа» — симметрия с D157.
- **Эргономика:** максимальная — маркер исчезает со всех паттерн-сайтов.
- **Machinery:** опора на mode-tiebreak → сначала обязателен ремонт
  расхождения факта №4; диагностика невидимых обязательств.

## Сравнительная таблица (критерии)

| Критерий | В1: только переноз | В2: авто-consume принуждает переноз |
|---|---|---|
| Легализует | `Ok(s) => s`, `Ok(s) => Ok(s)` | + `Ok(s) => s.close()`, `Ok(s) => f(s)` |
| Маркер остаётся | где есть выбор интерпретации | нигде на паттерне |
| Новая machinery | локальная shape-проверка | + согласованный tiebreak (факт №4) |
| Резолвер | не трогается | формально тот же, после ремонта |
| Generic-эрозия | закрыта нормативно | закрыта полнее (в т.ч. `Ok(v) => f(v)`) |
| Философия | оговорка по прецеденту D409 | переоткрытие решения владельца |

## Вердикт (рекомендация окна nova-kim, 2026-09-24)

  D180; нормативное закрытие эрозии; нулевое влияние на резолвер;

  обеих сторон (smoke-форма без маркера; `Ok(s) => s.foo()` — с маркером).
- **Вариант 2 — НА ПОДУМАТЬ**: отложенный оцениваемый второй шаг. Условия:
  (а) расхождение факта №4 починено и покрыто фикстурами; (б) владелец
  переоткрывает решение 2026-07-18; (в) после практики с В1 (накопятся ли
  обходы в std, останется ли идиома «распаковал и потребил» болезненной).
- **Независимо от выбора:** факт №4 — дефект #309-семейства, завести
  строку реестра и починить до любой ступени.
