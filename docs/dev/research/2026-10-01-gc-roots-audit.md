# Аудит корней GC в `nova_rt` под `GC_set_no_dls(1)` — к №1461

**Кому:** интегратору и облачной сессии, которая воспроизводит №1461 на Linux.
**Когда и кто:** 2026-10-01, помощник nova-88. Опись мест — агент на sonnet
(чтение `compiler-codegen/nova_rt/`, кроме `libuv/`, `gc/include/` и `test_*.c`);
суждение и сверка ключевых строк по коду — моя. **Рантайм не правился.**

**Чего отчёт НЕ утверждает.** Корень №1461 чтением однозначно НЕ найден.
Ниже — места, где указатель на объект кучи GC может жить в памяти, которую
Boehm не сканирует, с вердиктом, лежит ли каждое на пути Карины. Решит стенд.

## 1. Правило, от которого считается всё остальное

`nova_gc_init` зовёт `GC_set_no_dls(1)` (`alloc_boehm.c:172`). Следствие записано
там же (152.4, №1420): статические и BSS-данные программы НЕ корни, TLS-блок
НЕ корень — для главного потока это замерено на Linux; у воркера статический TLS
случайно лежит внутри его просканированного блока стека pthread. Корнями служат:
стеки зарегистрированных потоков; занятые слоты арены файберов, которые
проталкивает колбэк `GC_set_push_other_roots` (`fiber_arena.c`, posix, и
`fiber_arena_win.c`, Windows); память, выделенная самим GC (`nova_alloc`,
`GC_malloc_uncollectable`); явные `GC_add_roots`. Явный `GC_add_roots` в
`nova_rt/` один — массив `_workers` (`runtime.c:2024`). Эмиттер оракула
регистрирует корнем только `_nova_const_*_value` (`emit_c.rs:10528`) и
закрепляет TLS-обработчики по умолчанию (`nova_gc_pin`, `emit_c.rs:18732`).

## 2. Как Карина исполняется — это сужает поиск

* **Компилятор целиком работает в ДОЧЕРНЕМ ФАЙБЕРЕ:** `main.nv:326-328` —
  `supervised { spawn { exit_code.store(run(compiler_argv())) } }`. Значит, на
  воркере M:N, а не на главном потоке. Число воркеров по умолчанию —
  `uv_available_parallelism()` (`runtime.c:1827`), `NOVA_MAXPROCS` его задаёт.
  Поэтому «TLS главного потока» (№1420) для тела компилятора — НЕ главный
  подозреваемый.
* **Область `supervised` лежит на стеке главного потока:** в эмиссии
  `NovaFiberQueue _nova_scope_q_0 = {0};` — стек сканируется, её массивы
  (`nova_alloc`) достижимы.
* **Блок сопрограммы (контекст с сохранёнными регистрами и стек) — из арены**
  (`fibers.h:117`, `d.alloc_cb = nova_fiber_alloc`), а занятые слоты арены
  проталкиваются колбэком. Регистры приостановленного файбера лежат в
  сканируемой памяти.
* **Обработчики `with` в TLS-слотах** (`with Fs = real_fs(), Os = real_os()` в
  `run`) держатся ещё и стековой копией: в эмиссии
  `NovaVtable_X* _nv_tmp_N = …; /* GC root pin (TLS not scanned) */`.
* **Статики в C Карины** (аудит `main.c`, собранного оракулом с
  `--keep-artifacts`): файловых переменных с возможными указателями 174, корней
  14, закреплённых 4; 147 `nova_str` — ЛИТЕРАЛЫ (`{(const uint8_t*)"…", n}`,
  статическая память, безопасно). Незарегистрированного статика, указывающего
  в кучу GC, в эмиссии не найдено.

## 4. Различие Linux и Windows, которое замерено или прочитано

* Стенд №1461: на Windows за 30 минут не воспроизведён (обычный запуск
  20/20 одинаковы; самопроверка 4/4 — 542 диагностики; давление
  `GC_FREE_SPACE_DIVISOR` 30/100/1000 — красноты нет).
* Арена файберов: posix — `mmap`, Windows — `VirtualAlloc(MEM_RESERVE)` +
  `calloc` (`fiber_arena_win.c:505`); у обеих свой колбэк проталкивания.
* `GC_PRINT_STATS` на Windows пишет журнал в один файл `<exe>.gc.log` —
  параллельные процессы виснут; это №1485, НЕ корни GC (замерено).

## 5. Что предлагаю облаку (дешевле бисекции наугад)

1. **Сначала — уровень.** `GC_set_no_dls(0)` на стенде (Linux,
   `display_generic/pos_1`, `NOVA_MAXPROCS=1`): краснота ушла — корень в
   статике/данных; не ушла — в malloc/TLS/регистрах.
2. **Затем — главный поток против воркера:** `NOVA_MAXPROCS=1` против N (Linux
   уже дал разброс 236–349 против 208–2215 — воркеры значимы).
3. **Кандидаты 1–6 таблицы** проверяются точечно зондом через
   `NOVA_CG_INCLUDE` (`GC_add_roots` на диапазон или `nova_gc_pin` на
   объект), по одному: краснота ушла при одном — корень назван.
4. **Если ни один:** корень в C, который эмитит оракул (временные в регистрах
   при вызове рантайма, `GC_MALLOC_ATOMIC` с указателями внутри) — тогда
   `GC_DONT_GC=1` против точечного `GC_disable()` вокруг фаз конвейера Карины
   (лексер / разбор / проверка / эмиссия) локализует фазу.
