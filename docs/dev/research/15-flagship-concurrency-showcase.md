# Research 15 — Флагманское демо: живая визуализация конкурентных запросов

> **Статус:** research-артефакт (идеи + дизайн, НЕ план исполнения). Родитель
> плана [187-flagship-concurrency-demo](../../plans/187-flagship-concurrency-demo.md)
> (черновик заведён 2026-07-09). Реализация — после готовности
> 173-семьи (structured concurrency) и 178 (http/SSE-стриминг).
>
> Дата: 2026-07-09. Автор-решение: владелец выбрал вариант «(а) флагман
> максимальной выразительности» + визуально красивый динамичный фронт,
> показывающий ход конкурентных запросов на беке.

## 1. Цель и тезис

Первое флагманское приложение Nova. Задача — **сделать зримой** главную
уникальность языка: structured concurrency + алгебраические эффекты в
сигнатурах дают безопасность, которой нет у Go/Rust/JS.

Проблема любой демонстрации concurrency: она **невидима**. «50 запросов за
800мс» — цифра, не эмоция. Живая визуализация хода задач (fan-out, разнобой
латентностей, дедлайн, отмена, чистое закрытие без leak'ов) превращает
невидимое в **зрелище** и бьёт прямо в README-питч «LLM пишет — человек
ревьюит»: рядом с анимацией висит одна строка сигнатуры
`fn aggregate(...) Net Time Fail -> Report`, и подпись «всё, что делает бек — тут».

## 2. Отбор идеи (из 5 кандидатов)

Критерии: (1) бьёт в главный тезис; (2) на том, что уже работает; (3) не
игрушка; (4) «вау» читается за 5 секунд.

| # | Идея | Вердикт |
|---|---|---|
| 1 | HTTP API-сервис с эффект-слоями | 🥇 ядро (есть `effect_density/`) |
| 2 | Конкурентный агрегатор (structured concurrency) | 🥇 ядро (бьёт в 173, приоритет) |
| 3 | CLI-инструмент (data-pipeline/линтер) | практично, но эффекты невыпуклы |
| 4 | Порт реальной утилиты | вторичный материал |
| 5 | FFI-витрина (SQLite) | эффекты раскрывает слабо |

**Выбор: комбо #1+#2** — HTTP-сервис-агрегатор, который конкурентно ходит в
несколько источников. Одним приложением показывает три козыря сразу:
эффекты в сигнатурах, handler-подмену (тесты без моков), structured
concurrency с отменой/дедлайнами.

## 3. Транспорт живого хода бек→фронт

| Вариант | Плюс | Минус сейчас |
|---|---|---|
| **SSE** (рекомендую) | HTTP + `text/event-stream`, событийная модель 1:1 с «ход работы» | нужен http-стриминг (178) |
| WebSocket | двусторонний (кнопка «отмени» с фронта) | ws-хендшейк/фреймы поверх Net |
| Polling `/status` | на голом Net уже сейчас | дёрганно, не «динамично» |

**SSE** — событийная модель «задача стартовала / прогресс / завершилась /
отменена» ложится один-в-один. Это же выявляет стриминг-возможности 178.

### Вариант B — Граф-рой (максимум динамики, меньше ясности)

Центр `aggregate`, от него пульсирующие live-линии к воркерам; гаснут при
error/cancel. «Вау», но статуса/времени читается меньше.

### Вариант C — Waterfall (профессионально, «как DevTools»)

Фикс-ось времени, бары растут вправо; killer-строка внизу
«wall 1.42s vs sequential 4.1s → 2.9×» — рациональный аргумент выигрыша.

### Сравнение

| | A swimlanes | B граф | C waterfall |
|---|---|---|---|
| читается за 5с | ★★★ | ★★ | ★★★ |
| «вау»-динамика | ★★ | ★★★ | ★ |
| дедлайн/отмена | ★★★ | ★★ | ★★ |
| 0 leaks / clean close | ★★★ | ★★ | ★★ |
| ускорение vs sequential | ★ | ✗ | ★★★ |
| сложность фронта | низкая | высокая | средняя |

**Рекомендация: гибрид A+C** — основа swimlanes (ясность + дедлайн + «0 leaks»)
плюс нижняя строка-цифра из C («×N быстрее последовательного»). Эмоция отмены
и рациональный аргумент — одним экраном. B держать для видео-тизера.

## 5. Сценарий-демо (две легенды: погода + health-check, зафиксировано 2026-07-09)

> **Эволюция легенды:** пагинация (надуманно — rate-limit, «зачем?») → метапоиск
> цен (узнаваемо, но нет бесплатного API без ключа/денег) → **погода + health-check**
> (владелец 2026-07-09). Причина финального выбора: нужны **реальные, бесплатные,
> доступные сегодня** источники, иначе Live-режим — бутафория. Обе легенды дают
> настоящую сеть без ключей и денег и показывают конкурентность с двух сторон.

**Важная рамка (честно):** для демонстрации возможностей ЯЗЫКА реальный внешний
API не обязателен — цель демо — structured concurrency (fan-out/дедлайн/отмена/
0 leaks), а не «умеем ходить в сервис X». Реальные источники нужны лишь чтобы
Live-режим не был бутафорией. Демо-режим остаётся на `fake_net(seed)`
(воспроизводимость для записи/сцены), Live — на `real_net()`.

### 5a. Легенда «Погода» (полезный fan-out — сбор данных)

Источник: **open-meteo.com** (`api.open-meteo.com`) — публичный, **без ключа,
бесплатно, работает сегодня**. Фронт запрашивает сводку → бек fan-out по **N
городам** (Москва, СПб, Новосибирск, Токио, Лондон…); строка = город; под-fan-out
(§6.4a) = несколько параметров (температура/осадки/ветер) или соседних дней.
Результат — агрегированная сводка «где теплее». Паттерн — классический
бэкенд-агрегатор (BFF).

### 5b. Легенда «Health-check» (fan-out ради статуса)

Реальные HTTP-запросы к **N известным доменам** (github / wikipedia / cloudflare /
российские сайты…); строка = сервис; замер времени ответа + статус-код. Дедлайн =
**SLA-таймаут**; зависший/медленный сервис → отмена. Результат — «N/M сервисов
здоровы, худшая латентность X». Devops-паттерн, узнаваемый инженерами.

### 5b'. Легенда «LLM-роутер» (race / first-wins; добавлена owner 2026-07-09)

Fan-out промпта по **N локальным LLM** (через **Ollama**, `localhost:11434` —
plain-HTTP, **без TLS/ключей/денег**, критерий owner «скачал и запустил»):
первый пригодный ответ побеждает, **проигравшие отменяются** (это второй паттерн —
`race`, уже в std/concurrency/cancellation.nv; aggregate = первый). Демо детектит
модели через `/api/tags` (модель = строка); нет Ollama → кнопка disabled, мок-LLM
с нейтральными именами работает всегда. Бонусы: латентность инференса 1-10с =
лучшая визуализация из всех легенд; `/api/generate` стримит токены (NDJSON) →
**прогресс строки = реальные токены**; отмена освобождает реальный GPU — «0 leaks»
не абстракция. On-brand для «языка AI-эры». Опция №4 — поисковый race
(DDG/Wikipedia, бесключевые; HTTPS → за 116). Детали: план 187 §2.5/§7.8.

### 5c. Общее для обеих + честная оговорка про латентности

Обе — **тот же код** `aggregate`, разный `with Net = …` и разный список
источников (это и есть демонстрация тезиса Nova). Killer-логика одинакова:
«показать готовое за дедлайн (2с), опоздавших отменить каскадно, 0 leaks».

⚠️ **Открытые API/сайты часто отвечают быстро** (те самые доли секунды — исходное
наблюдение владельца). Компенсируем: (1) **под-fan-out** растягивает прогресс
строки; (2) **реальный разброс** между источниками (Токио дальше Москвы;
зарубежный сайт медленнее) даёт «гонку»; (3) для гарантии дедлайн-эффекта в демо —
**1–2 заведомо медленных источника** (дальний сервер / тяжёлый эндпоинт) — это
честная медленная цель, не искусственная задержка.

Демо-режим: данные засеяны (`fake_net(seed)`) под каждый сценарий — реальные
имена городов/доменов, часть намеренно медленные (упрутся в дедлайн), часть
падают (`Fail 503/timeout`). Live-режим (`real_net()`) — настоящие запросы.

# 6. Дизайн и архитектура бека

> Опора — на **реально работающие** примитивы (проверено по коду 2026-07-09):
> `examples/effects/spawn_demo.nv`, `examples/net/echo_server.nv`,
> `examples/effect_density/{service,http}.nv`.

## 6.1 Реальные примитивы Nova, на которых стоим

- **Эффект = контракт операций** без полей: `type X effect { op(...) -> T }`.
- **Предоставление/подмена хендлера как значения:** `with Net = real_net() { ... }`
  (echo_server). В тестах — `with Net = fake_net(seed) { ... }` → **тесты без моков**.
- **Structured concurrency:** `supervised { spawn {...}; spawn {...} }` — скоуп
  ждёт всех; `spawn` — fire-and-forget (D50), результат через mut-захват.
- **Гомогенный fan-out:** `parallel for i in items { ... }` внутри `supervised`.
- **Выведение эффектов** у приватных функций (D28): в теле пишешь без
  сигнатуры, компилятор проставляет; `nova check --show-effects`.
- **Сужение `Fail`** через handler-блок: `with Fail[E] = |e| interrupt to_http(e) { ... }`
  (http.nv) — ловит доменные ошибки в одной точке, отдаёт Response.

## 6.2 Известные gap'ы компилятора (архитектура их обходит честно)

- 🔴 **`ro results = parallel for … { expr }` даёт `()` в обычной `fn`**
  (Plan 91 Ф.6): массив результатов по D71 корректно типизируется пока только
  в `test {}`-блоках. **Следствие для дизайна:** результаты воркеров собираем
  **через mut-захват в supervised-scope** (как spawn_demo), НЕ через
  value-форму `parallel for`. Маркер отслеживания — при заведении плана.
- **Дедлайны/отмена** (`deadline:`/`timeout:`, чистая отмена) — в 173-семье, в
  активной работе. Архитектура закладывает их как **отдельную фазу за гейтом
  173**; для раннего прототипа возможен «мягкий дедлайн» (воркер сам проверяет
  бюджет времени через `Time`), с честной пометкой «не настоящая отмена».
- **HTTP-сервер и SSE-стриминг** — 178 (READY, не CLOSED). До него — прототип
  на голом `Net` (echo_server-стек) с ручным `text/event-stream`, либо polling.

## 6.4 Ключевая сигнатура (сердце демо)

```nova
// service.nv — весь бек в одной строке для панели-сигнатуры на фронте
export fn aggregate(sources []Url, budget Duration)
    Net Time Fail[AggError] -> Report
```

Fan-out (обход gap 6.2 — сбор через mut-захват в supervised):

```nova
fn aggregate(sources []Url, budget Duration) -> Report {
    ro started = Time.now()
    mut results []Result[SourceData, AggError] = vec_filled(sources.len(), pending())
    supervised {
        parallel for i in 0..sources.len() {
            // мягкий дедлайн до готовности 173: воркер уважает бюджет
            results[i] = run_with_budget(sources[i], started, budget)
        }
    }
    Report.from(results, Time.now() - started)
}
```

> После 173: `parallel for` заменяется на скоуп с настоящей отменой по
> `deadline: started + budget`; воркеры, не успевшие, **отменяются рантаймом**
> и закрываются чисто. Это и есть «→⟂ cancel / 0 leaks» на экране.

## 6.4a Визуальная модель: waterfall (полоса = время), 2026-07-09

**История решения (три итерации с владельцем):**
1. *Наблюдение:* строка = ОДИН url → запрос идёт доли секунды, бар «моргнёт»,
   прогресс не виден.
2. *Первая попытка:* разбить строку на под-fan-out (сегментированный бар из ячеек-
   под-запросов) — чтобы бар полз ступенями. **Отвергнуто:** ячеек разное число
   по строкам, глаз читает ленту как ложную «шкалу времени», сбивает.
3. *Принято:* **полоса = ВРЕМЯ (waterfall)**. Бар растёт слева направо к дедлайну;
   у всех строк **одна ось времени**. Вложенность из ВИЗУАЛА убрана; под-детали
   (сколько дней/проверок) — просто числом `5/7` + декоративные насечки на баре
   (не шкала). Это честно (как вкладка Network в браузере) и решает «моргает».

**Backend-модель (одноуровневый fan-out, обход gap 6.2 через mut-захват):**

```nova
fn aggregate(sources []Source, budget Duration) -> Report {
    ro started = Time.now()
    mut results []Result[Data, AggError] = vec_filled(sources.len(), pending())
    supervised {
        parallel for i in 0..sources.len() {
            // мягкий дедлайн до готовности 173: воркер уважает бюджет
            results[i] = fetch(sources[i], started, budget)
        }
    }
    Report.from(results, Time.now() - started)
}
```

**Что показывает на экране:**
- каждая строка = один источник; **бар растёт по времени** к дедлайн-линии;
- разброс латентностей источников → видна «гонка»;
- источник, упёршийся в дедлайн, → **отмена** (бар гаснет частицами, `⟂ cancel`),
  `0 leaks` — killer-инвариант Nova;
- **sequential-мир** (бледный пунктир) тянется заметно дольше → контраст «×N быстрее».

> После 173: `parallel for` заменяется скоупом с настоящей отменой по
> `deadline: started + budget` — воркеры отменяются рантаймом и закрываются чисто.

**Вложенность (scope ⊃ scope) — опция «позже», не в MVP-визуале.** Если под-fan-out
понадобится (реально много под-запросов на источник), вернуть его как
разворачивающуюся строку (клик → под-дорожки), НЕ как сегменты в баре. Пока
под-детали передаются числом.

## 6.5 Модель событий SSE (контракт фронт↔бек)

```
event: task            data: {"id":"weather-a","kind":"started","t":0}
event: task            data: {"id":"weather-a","kind":"progress","pct":40,"t":300}
event: task            data: {"id":"news-1","kind":"failed","err":"503","t":410}
event: task            data: {"id":"news-2","kind":"cancelled","reason":"deadline","t":2000}
event: summary         data: {"fanout":6,"done":2,"live":0,"failed":1,"cancelled":1,
                              "wall_ms":1420,"sequential_ms":4100,"speedup":2.9,"leaks":0}
```

`TaskEvent` — sum-тип в `domain.nv`, сериализуется в эти JSON'ы. Событие
эмитится из воркера в момент смены статуса (через доп. эффект `Emit` или
канал в оркестратор — решение фазы реализации).

## 6.6 Тесты без моков (демонстрация handler-подмены)

```nova
test "aggregate: 1 fail + 1 deadline, остальные ok, 0 leaks" {
    with Net  = fake_net(seed: 42) {      // засеянные латентности/ошибки
    with Time = fixed_clock(0) {          // детерминизм дедлайна
        ro r = aggregate(SOURCES, budget: 2.seconds())
        assert(r.done == 4)
        assert(r.failed == 1)
        assert(r.cancelled == 1)
        assert(r.leaks == 0)              // ключевой инвариант Nova
    }}
}
```

Тот же код бека, что в проде — меняется только хендлер. Это и есть
«эффект→handler→тесты без моков» из README, но на конкурентном коде.

## 6.7 Детерминизм демо

Латентности/ошибки источников **засеваются** (`fake_net(seed)`), НЕ реальные
внешние API — иначе демо флачит, а для записи/сцены нужна воспроизводимость.
Реальные источники — опциональный «boss-режим» вторым хендлером `real_net()`.

## 7. Зависимости и очередность (для будущего плана 187)

| Фаза | Зависит от | Что даёт |
|---|---|---|
| Прототип на голом Net + polling/ручной SSE | ничего (echo_server-стек) | ранняя картинка, мягкий дедлайн |
