# Ревью: комбинаторы Option/Result — какие добавить, какие нет

> **Статус: research/предложение** (2026-07-16, по запросу владельца при работе над
> флагманом 187 — цепочка `env→parse→cast` в `resolve_port` не пишется однострочно).
> Решение — за владельцем. Кандидат — Plan 200 Пункт 14. Родитель-контекст:
> [D86](../../../spec/decisions/04-effects.md#d86) (`??` coalesce), D85 (`!!`), D4/D67 (`?`).

## 1. Что уже есть

| | Методы | Операторы |
|---|---|---|
| **Option** | `is_some · is_none · map · ok_or · or` (+ debug/serialize/deserialize) | `??` `!!` `?` |
| **Result** | `is_ok · is_err · map · map_err · ok · err` (+ debug) | `??` `!!` `?` |

- `??` (D86) — coalesce: **разворачивает до `T`**, fallback обязан быть типа `T` (или
  `never`: throw/panic/return). Правая часть ленивая (сахар над `match`).
- `!!` (D85) — unwrap-или-throw. `?` (D4/D67) — try-пробрасывание.

## 2. Философия Nova (ключ к отбору)

Value-fallback у Nova **принципиально операторный**. D86-AMEND (владелец, 2026-07-07)
**ретрактировал** `@unwrap_or(v)`/`@unwrap_or_else(f)` — дублировали `x ?? v` (правая часть
ленивая, покрывает и `_or_else`); дрейф 29 вызовов оператора против 2 у методов; «когда
нужен доступ к ошибке — явный `match`». **Правило отбора:** добавляем ТОЛЬКО то, что
операторами (`??`/`!!`/`?`) и `.map`/`match` **невыразимо**.

## 3. Анализ каждого канонического комбинатора

| Комбинатор | Выразим существующим? | Вердикт |
|---|---|---|
| **`flat_map(fn→M)`** (bind) | НЕТ — `.map(f)` даёт вложенный `M[M[U]]`, снять нечем | **ДОБАВИТЬ** |
| **`filter(pred)`** (Option) | НЕТ — `??`/`map` не отбрасывают Some по предикату | **ДОБАВИТЬ** |
| `or_else(fn→M)` | В основном ДА: value-случай = `?? f()`; остаётся лишь «fallback сам Option, остаёмся в монаде» — редко, Nova-канон = `match`/вложенный `??`. Тот же класс, что ретрактированные близнецы | ❌ НЕ добавлять |
| `unwrap_or` / `unwrap_or_else` | ДА — `?? v` | ❌ ретракт D86 |
| `map_or(d,f)` / `map_or_else` | ДА — `.map(f) ?? d` | ❌ не нужно |
| `flatten()` | = `flat_map(\|x\| x)` | опц., низкий приоритет |
| `inspect` / `inspect_err` | side-effect peek; `?? {…}`/`match` закрывают | опц., низкий |
| `zip` · `is_some_and` · `ok_or_else` | ниша / выразимо | пропустить |

**Разбор `or_else` vs `??` (спрашивал владелец):** формально не идентичны — `??`
разворачивает до `T` (fallback типа `T`), `or_else` остаётся `Option[T]` (fallback типа
`Option[T]`, цепочка продолжается). Единственная дельта — «остаться в монаде при цепочке
опциональных fallback'ов»:
```nova
primary(k).or_else(|| cache(k)).or_else(|| disk(k))   // -> Option[V]
// через ?? — только вложенно и с финальным значением (выходя из Option):
primary(k) ?? (cache(k) ?? (disk(k) ?? default))       // -> V
```
```nova
primary(k) ?? cache(k) ?? disk(k) ?? default           // -> V
```
`??` **право-ассоциативен** (эмпирически проверено 2026-07-16: `a ?? b ?? c ?? d`
type-check'ается без скобок = `a ?? (b ?? (c ?? d))`), поэтому мульти-fallback пишется
плоской цепочкой БЕЗ вложенности — пока цепочка заканчивается конкретным значением (выход
из Option в `T`). `or_else` нужен ТОЛЬКО чтобы «остаться в `Option[T]`» (без финального
значения, продолжая `.map`/`.filter`) — редкий случай, Nova-канон адресует его `match`'ем
(как и при ретракте `unwrap_or_else`). → `or_else` в тот же класс «не добавлять».

## 4. Рекомендация — три метода

```nova
fn Option[T]   @flat_map[U](f fn(T) -> Option[U])   -> Option[U]
    => match @ { Some(v) => f(v), None => None }

fn Result[T,E] @flat_map[U](f fn(T) -> Result[U,E]) -> Result[U,E]
    => match @ { Ok(v) => f(v), Err(e) => Err(e) }

fn Option[T]   @filter(pred fn(T) -> bool) -> Option[T]
    => match @ { Some(v) => if pred(v) { Some(v) } else { None }, None => None }
```

- **`flat_map`** — единственное, что операторы не дают (bind/монадическая цепочка
  fallible-шагов без ручного снятия вложенности). Имя `flat_map` (не `and_then`/`then`):
  сиблинг к существующему `map`, без булевого багажа `and`/`or` и без коллизии с
  Promise-`then`/`bool::then` (обоснование — сессия 2026-07-16).
- **`filter`** — Some→None по предикату; `??`/`map` этого не делают.

Первый потребитель — `resolve_port` и подобные цепочки:
```nova
fn resolve_port() Os -> u16 =>
    env("AGGREGATOR_PORT").flat_map(|s| s.to_int().ok()).map(|n| n as u16) ?? DEFAULT_PORT
```

## 5. Объём

- std: 3 метода в `std/src/prelude/core.nv` (рядом с `map`/`ok`/`or`) — чистый .nv,
  тела тривиальны (match). Тесты рядом с модулем.
- Спека: не язык-меняющее (методы над существующими типами, не новый синтаксис/семантика) —
  D-амендмент НЕ нужен; отметить в p-реестре. Свериться с D86-философией (эти три —
  невыразимы операторами, в отличие от ретрактированных близнецов).
- Риск: минимальный (чистые комбинаторы, no-effect, no-alloc).
