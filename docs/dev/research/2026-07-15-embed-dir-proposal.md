# Предложение: `embed_dir(...)` — вшить целую папку в бинарь (расширение D412)

> **Статус: ПРИНЯТО — вариант A (владелец, 2026-07-15).** `embed_dir(...)` вводится,
> дизайн = §3 вариант A (`EmbeddedDir` + `get`/`paths`, нулевая копия). В очередь на
> реализацию; язык-меняющее → D412-амендмент (или новый D-блок) в том же слиянии.
> Маркер `[M-embed-dir]` (backlog) — из PROPOSED в APPROVED/queued. Родитель:
> [D412](../../../spec/decisions/03-syntax.md#d412) (`embed("file")` — single-file).

## 1. Что сейчас и чего не хватает

`embed("relative/path")` (D412) вшивает **ОДИН файл** как `[]u8` (аналог Rust
`include_bytes!` / Zig `@embedFile` / C23 `#embed`). Целую директорию одним вызовом
вставить нельзя.

Практический кейс (флагман 187): фронт целиком внутри бинаря = «скачал и запустил»,
ноль внешних файлов. Сейчас это решается тем, что `frontend/index.html`
**самодостаточен** (CSS+JS inline) → один `embed()`. Но как только фронт дробится
(`index.html` + `app.js` + `style.css` + шрифт + картинки), приходится писать
`embed()` **на каждый файл** и роутить вручную — многословно и легко забыть файл.

## 2. Как это делают другие языки (survey)

| Язык | Один файл | Целая папка |
|---|---|---|
| **Go** | — | **`//go:embed dir/*` → `embed.FS`** (эталон): компилятор обходит папку, все файлы в бинарь; читается как настоящая ФС (`fs.ReadFile`), отдаётся HTTP-серверу напрямую (`http.FileServer(http.FS(...))`) |
| **Rust** | `include_bytes!` (single) | НЕ встроено; крейты `rust-embed` (`#[derive(RustEmbed)] #[folder="…"]` → `.get(path)`), `include_dir!` |
| **Zig** | `@embedFile` (single) | НЕТ one-liner; build-скрипт / comptime-обход листинга |
| **C23** | `#embed` (single) | НЕТ; исторически `xxd -i` (C-массивы) / resource-компилятор |
| **C#/.NET** | — | «Embedded Resources»: файлы проекта по glob → в сборку, `GetManifestResourceStream(name)` |
| **Java** | — | ресурсы classpath (`getResourceAsStream`) внутри JAR (zip) |
| **Nova (D412)** | `embed("file")` | **пока НЕТ** (это предложение) |

**Вывод:** Go — самый чистый (директива + виртуальная ФС «путь→байты», раздаётся как
real FS). Остальные — single-file builtin + сторонний макрос/сборка, либо система
«ресурсов». Nova сегодня на уровне Rust/Zig/C23 (single-file).

## 3. Набросок дизайна (по Go-эталону, адаптировано под Nova)

**Форма:** `embed_dir("relative/dir")` — компайл-тайм интринсик (класс C, как `embed`),
аргумент только строковый литерал. Возвращает **иммутабельную карту `путь→[]u8`**
(ключ — путь относительно embed-корня, POSIX-слэши; значение — нулевокопийный
`[]u8`-вид на статический блоб, как single-`embed`).

```nova
// весь frontend/ в бинарь одним вызовом
ro assets = embed_dir("frontend")           // тип: EmbeddedDir (path -> []u8)
// раздача: mux отдаёт любой файл из папки
ro body = match assets.get("app.js") { Some(b) => b, None => not_found() }
```

**Ключевые решения (нужен owner sign-off):**
1. **Тип возврата.** Вариант A: `EmbeddedDir`-значение с `get(path)->Option[[]u8]` +
   `paths()->[]str` (Go-подобная FS-абстракция). Вариант B: сразу
   `HashMap[str, []u8]` (проще, но GC-копия против нулевой копии single-embed).
   Рекомендация: A (нулевая копия сохранена, blob'ы в .rodata, карта — статические
   пары путь→вид).
2. **Материализация.** Каждый файл → свой `static const uint8_t nova_blob_<n>[]`
   (как single-embed, D412 §«Материализация»); + статическая таблица
   `{путь, &blob, len}`. `get` — линейный/бинарный поиск по таблице (папки малы).
3. **Рекурсия и фильтр.** Обходить поддеревья? (Go `dir/*` — верхний уровень,
   `dir/**` эффективно рекурсивно через несколько паттернов). Предложение: `embed_dir`
   рекурсивен по умолчанию (весь поддеревья), опц. glob-фильтр позже.
4. **Fingerprint пересборки.** Как single-embed — все файлы папки суть build-зависимости
   (изменение/добавление/удаление → пересборка). Обход папки на компиляции +
   детерминированный порядок (сорт путей) для воспроизводимого вывода.
5. **Границы.** `..` выше корня проекта — ошибка (как D412); пустая папка → пустая
   карта; символ-линки — не следовать (безопасность), либо явное решение.
6. **Content-Type.** НЕ дело интринсика (он про байты). Хелпер в std/http (mime по
   расширению) — отдельно; `embed_dir` остаётся чистым «путь→байты».

## 4. Объём/риск

- Компилятор: обход директории на этапе резолва embed (`embed_resolve.rs`), эмиссия
  N блобов + таблицы (`emit_c.rs`, прецедент single-embed уже есть — переиспользовать).
- Спека: амендмент D412 (или новый D-блок) в том же слиянии — **язык-меняющее**.
- std: тип `EmbeddedDir` (nv-sourcing) + опц. mime-хелпер http.
- Риск низкий: механика single-embed уже есть; новое — обход папки + таблица-поиск.

## 5. Рекомендация

Ввести `embed_dir` по варианту A (EmbeddedDir + get/paths, нулевая копия) —
закрывает «фронт целиком в бинарь» одной строкой (флагман 187 — первый потребитель),
догоняет Go по эргономике, сохраняет D412-модель материализации. Приоритет — не
срочный (single-embed + самодостаточный html уже покрывают MVP флагмана); удобство,
не блокер. Кандидат-маркер `[M-embed-dir]` (proposed, owner-gated).
