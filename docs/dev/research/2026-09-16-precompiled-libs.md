# Прекомпилированные библиотеки: можно ли собрать `.nv` в lib и не перекомпилировать

**Статус:** исследование под вопрос владельца 2026-09-16: «насколько формат lib расширяем — можно
ли компилировать `.nv` в библиотеку, где функции без дженериков уже содержат код, а дженерики
инстанцируются в конечном приложении; какие варианты». Вердикт — модель «объекты по модулям +
интерфейс из MIR + инстанцирование по представлению с дедупликацией на линковке», это работа
Карины (novac), не оракула; здесь — варианты, цена, порядок.

## 1. Как собирается Nova сегодня (факты)

| факт | где |
|---|---|
| Сборка — **целой программой**: `resolve_imports_inline` сливает entry и все импортированные модули в один `Module` → один `.c` → clang. Раздельной компиляции модулей в архитектуре нет | `compiler-codegen/src/imports.rs:823`, шапка `nova-cli/src/build_cache.rs` |
| Кэш — content-addressed, гранулярность **вся сборка**: ключ = хэш всех исходников + отпечаток компилятора + `#cfg` + ОС + mono-depth; попадание = переиспользовать `.c`, clang запускается всегда | `build_cache.rs:1-40` |
| Дженерики — **мономорфизация** (stenciling): by-value для value-records (D277), туплов (D354), `char` ≠ `int` в mono (D128); `any` — единственный erased-путь (`void*` + `type_id`, D54) | `02-types.md` D277/D354/D128 |
| Карина: коллектор инстансов по образцу rustc (`Instance { def, args }`, worklist, дедуп до имени); **не берёт** CGU-партиционирование, `share-generics`, GC-shape и словари — «выключено, потому что D122 требует zero-cost» | `docs/dev/novac-architecture.md:1425-1450` |
| Карина прямо называет развилку: статический layout без индирекции ⇒ «не можешь отдать дженерик через бинарную границу без тела» (rustc, C++, Zig); словари ⇒ раздельная компиляция и стабильный ABI (Swift, C#), но не zero-cost. «У Nova нет ни стабильного ABI, ни cross-crate инстанцирования» | `novac-architecture.md:228-240` |
| Монотонность резолва (нет специализации, нет негативных фактов) — держится в т. ч. ради «кеша и раздельной компиляции» | `novac-architecture.md:1035-1040` |
| Пакеты потребляются **исходниками**: резолвер берёт новейший тег по `version`, сборка компилирует чужой `.nv` вместе со своим | AGENTS.md «Satellite package repositories» |
| Символы C уже манглятся детерминированно и глобально (`Nova_str_method_to_f64`, `Nova_P309Bag_method_put__nova_int`) — но без weak/COMDAT: в emit_c нет `__attribute__((weak))`/`selectany` | grep по `emit_c.rs`, реестр №309 |
| Часть «глобальных» решений сегодня по имени на весь CU: теги сумм (`sum_schema_registry`), резолв варианта по голому имени (№136/№962), `NOVA_TYPEINFO_<T>` per-type для `any` | `sum_schema_registry.rs`, реестр |

Следствие: сегодня «lib» = исходники + кэш `.c` целой программы. Ничего модульного переиспользовать нельзя, потому что единица кодогена — вся программа.

## 2. Что именно хочется

Пакет `P` собран один раз. Приложение `A` импортирует `P` и:
- **не перекомпилирует** конкретные функции `P` (без тип-параметров) — берёт готовый объектный код;
- **инстанцирует** дженерики `P` под свои типы у себя;
- если `P` сам где-то инстанцировал `Vec[int]`, а `A` тоже — код один, не два.

Это ровно модель C++ (`.a` + заголовки с шаблонами), Rust (`rlib` = объекты + MIR дженериков), OCaml (`.cmxa` + `.cmx`), Swift (`.swiftmodule` с `@inlinable`-телами), Haskell (`.a` + `.hi` с unfoldings).

## 3. Варианты

| № | модель | донор | что даёт | цена | вердикт |
|---|---|---|---|---|---|
| 0 | статус-кво: целая программа + кэш `.c` | сегодня | просто, детерминизм, мега-CU-гейт | любое изменение входа = полная пересборка; чужой пакет компилируется у каждого потребителя | остаётся оракулу |
| 1 | **объекты по модулям + интерфейс с телами дженериков + инстанцирование у потребителя + дедуп на линковке** | rustc `rlib`+MIR, C++ `.a`+templates, OCaml `.cmx` | конкретный код собирается один раз; дженерики zero-cost как сейчас; дубли инстансов схлопывает линковщик (weak/COMDAT) | нужны: (а) модульная единица кодогена вместо `resolve_imports_inline`; (б) формат интерфейса — сериализованный проверенный MIR дженериков + таблицы типов/протоколов/эффектов/контрактов; (в) weak-символы для инстансов; (г) все «глобальные по CU» таблицы (теги сумм, typeinfo, схемы) — детерминированы по DeclId, не по порядку CU | **целевая** |
| 2 | 1 + **инстанцирование по представлению** (все `T` одной формы делят тело) | Go GC-shape stenciling (без словарей), требование Карины из `2026-09-04-typed-index-vec.md` §206 | инстансов на порядок меньше ⇒ библиотека может **заранее** отдать инстансы для типовых представлений (`int`-shape, ptr-shape); потребитель редко инстанцирует сам | что считать «представлением» — нормативный вопрос (размер+выравнивание+GC-скан-карта+consume-статус); методы протоколов у разных `T` одной формы разные ⇒ либо словарь (запрещено D122), либо инстанс всё же по типу там, где вызываются bound-методы | **надстройка над 1**, только для дженериков без bound-вызовов |
| 3 | словари/witness-таблицы (полное стирание) | Swift, C#, Haskell dictionaries | библиотека полностью прекомпилирована, стабильный ABI | индирекция на каждом bound-вызове, невозможна by-value-специализация (D277), противоречит D122 | **нет**, спека запрещает |
| 4 | пред-инстанцирование по списку (`extern template`, Rust `share-generics`) | C++11, rustc debug | библиотека отдаёт инстансы, которые сама использует; потребитель переиспользует совпавшие | без weak-символов даёт дубли; Карина явно не берёт `share-generics` | частный случай 1(в), отдельно не нужен |

## 4. Что придётся решить для варианта 1 (по убыванию цены)

1. **Единица кодогена = модуль, не программа.** Сегодняшнее слияние в один `Module` даёт
   глобальную нумерацию всего (`@fresh_uniq`, теги, typeinfo). Каждое такое место — либо
   детерминированный ключ от `DeclId`/`TyId`, либо ленивая эмиссия в CU потребителя с weak-дедупом.
   Носители, где это уже болит: №136/№962 (варианты по голому имени на весь CU), №309
   (манглинг режима параметра). То есть требование «одно правило — одна дверь по DeclId» из
   Карины и есть предусловие раздельной компиляции.
2. **Интерфейс библиотеки.** Не исходник и не `.c`, а **проверенный MIR** (план 274.8) экспортных
   деклараций: сигнатуры с эффектами (вывод эффектов кросс-модульный — сигнатуры должны быть в
   интерфейсе явно, `novac-architecture.md:801`), контракты и результаты их доказательства
   (элизия bounds по контракту — Plan 140.2 — иначе потребитель не знает, что элидировать), тела
   дженериков и `#inline`-кандидатов, `#coerce`-пары (D429 R8: пара активна там, где видна),
   `#cfg`-раскладка. Формат версионируется отпечатком компилятора: несовпадение = пересборка из
   исходников, не ошибка.
3. **Дедуп инстансов на линковке.** `__attribute__((weak))` (clang/gcc) и `__declspec(selectany)`
   + `/FORCE:MULTIPLE`-free COMDAT для MSVC; имя инстанса = детерминированный манглинг от
   `Instance { def, args }` (уже есть у Карины). Без этого модель 1 не работает вовсе.
4. **Формат контейнера.** `.a`/`.lib` объектов + один файл интерфейса рядом; пакетный резолвер по
   тегу продолжает тянуть исходники (они нужны для пересборки при смене компилятора), lib — кэш
   рядом с ними, а не замена. Это снимает вопрос доверия к чужим бинарям.
5. **Инстанцирование по представлению (вариант 2)** — после 1: только для дженериков, не
   вызывающих bound-методы (контейнеры: `Vec[T]`, `IndexVec[I, T]`, `Option[T]`); правило
   «представление = (size, align, GC-карта, consume)» в спеку; bound-вызовы оставляют инстанс
   по типу.

## 5. Чего не делаем

- Словари/стирание (вариант 3) — против D122 и D277.
- Стабильный бинарный ABI между версиями компилятора — интерфейс привязан к отпечатку
  компилятора; пересборка из исходников — норма.
- Раздельная компиляция в оракуле — это архитектура Карины (план 274), у оракула остаётся
  кэш целой программы.

## 6. Рекомендация

Модель 1 как цель Карины, модель 2 как её продолжение для контейнеров. Записать в
`novac-architecture.md` как требование к драйверу и коллектору (сейчас там «cross-crate
инстанцирования нет» констатацией, не решением); открыть план после 274.8, потому что интерфейс
библиотеки — это сериализованный MIR, и без него формат lib определять нечем. До этого
дешёвое улучшение оракулу — не нужно: кэш `.c` целой программы уже покрывает «не перекомпилировать
при неизменных входах», а модульный кэш без раздельной компиляции невозможен (шапка
`build_cache.rs` это и говорит).
