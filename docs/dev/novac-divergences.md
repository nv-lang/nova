# Реестр расхождений novac ↔ оракул

Контракт (план [274](../plans/274-novac-self-hosted-compiler.md) §10.3а; машинная
половина — `novac/divergences.allow`, судья — `check-novac-differential.sh` и
корпусный раннер `scripts/tools/novac-diff-corpus.sh`): каждая строка allow
обязана иметь здесь историю — что расходится, почему наше поведение верно, и
D-блок, если расхождение видимо как поведение языка. Каждая запись и каждый
прогон несут ревизию оракула и режим сборки novac (§10.3: иначе классификация
невоспроизводима через неделю). Пустой allow — здоровое состояние.

## Сознательные расхождения (зеркало allow)

Пока НЕТ ни одного: `novac/divergences.allow` пуст, дифф-страж на фикстурах и
корпусный раннер зелёные без исключений.

## Выборка №221.1 — известные дефекты фронтенда против подмножества Э1

Требование приёмки Э1 (274 §9): «известные дефекты фронтенда из №221.1 выбраны
в список ожидаемых расхождений; открытые вопросы, задевающие подмножество,
закрыты или исключены поимённо».

Выборка сделана 2026-08-14 полным чтением реестра (~650–700 записей;
оракул cc7f3fab2, novac single-file). Задевают подмножество — четыре записи
плюс один пограничный; всё остальное — кодоген/рантайм/std/инструменты либо
конструкции вне подмножества.

| № | статус | что | как задевает дифф Э1 |
|---|---|---|---|
| №652 | открыт (К1, ждёт решения владельца) | чекер оракула МОЛЧА принимает типовую несоундность: `fn f() -> int { "str" }`, `if 5 { }` — обе формы из ядра Э1 | сегодня совпадение: novac в Э1 тоже без типового чекера, оба ложно принимают. КОГДА №652 закроют — оракул начнёт отвергать, а novac продолжит принимать → появится DANGER-класс; это ОЖИДАЕМО и лечится типовым чекером novac (Э2+), не обходом |
| №564 | открыт (К1) | `nova build` и `nova check` судят объявление `module` РАЗНЫМ кодом (разные требования к имени) | дифф-раннер и страж зовут оракул только через `check` — внутри прогона консистентно; но вердикт «оракул принял» НЕ переносится на `build` автоматически |
| №539 | видимо открыт (D452 принят, энфорс за планом 264) | парсер оракула принимает два оператора на строке без `;` | novac-парсер Э1 сознательно скопировал это поведение (разделители не проверяются) → сегодня совпадение; после ужесточения оракула дифф покажет расхождение — тогда novac ужесточается той же волной |
| №493 | ЗАКРЫТ 2026-08-13 | пропавший `-> T` молча давал `()`-возврат | закрыт ДО пина cc7f3fab2 — расхождения не даёт; упомянут, потому что бил ровно в `fn ... -> int` из Э1 |
| №495 (пограничный) | открыт | `_`-группировка в числовых литералах (D44) не валидируется лексером оракула | лексер novac `_` в числе не принимает (у него `1_000` — это `1` + идент `_000`); в приёмочной паре и мутациях basics таких литералов нет, эмиттер их не встречает; при расширении подмножества литералов — свериться с D44 заново |

Сегодняшний итог выборки: на пине cc7f3fab2 НИ ОДНА запись не требует строки в
`novac/divergences.allow` — известные дефекты дают либо совпадение (оба
принимают/отвергают одинаково), либо расхождение строго в будущем времени
(после фикса оракула). Открытые №652/№539 — именованные источники БУДУЩИХ
расхождений; при их закрытии в оракуле дифф-раннер покраснеет — это штатный
сигнал «двигай пин и чини/ужесточай novac той же волной», не сюрприз.

## Предсказания Э2-а — внесены ДО кода (274 §7; 2026-08-14, пин c5a0bc425)

Расширение подмножества на basics целиком (strings → records → demo →
match_demo). Что ожидаю от дифф-гейта ЗАРАНЕЕ:

1. **match_demo.nv объявляет сумму старой формой** (`type Shape` + leading-`|`,
   без enum-маркера D406) — оракул на пине её ПРИНИМАЕТ (проверено корпусным
   прогоном: файл в классе «отставание», не «оба отвергли»). Контракт novac =
   оракулу на пине: парсер Э2 принимает эту форму. Если оракул ужесточит D406,
   дифф покраснеет — штатный сигнал «пин двигается, novac ужесточается той же
   волной». Язык здесь не меняю (правка формы корпуса — земля интегратора).
2. **№652 на basics не проявится**: файлы типо-корректны; ложных принятий
   оракула на них нет — контракт-совпадение будет честным.
3. **f64 в records/demo/match_demo**: печать чисел с плавающей точкой должна
   выйти байт-в-байт (формат печати — из оракульской эмиссии фикс-пойнтом,
   не из моих представлений о printf).
4. **Поведенческое число растёт только через смоук**: каждый новый файл
   подмножества входит в behavior-match исключительно побайтовым диффом
   stdout+exit — «собрался» не считается.

## Дефекты оракула, задевающие СБОРКУ novac (не дифф)

Отдельный класс: не меняют исход дифф-гейта, но ломают компиляцию самого
novac оракулом. Носители — маркеры `[LEGACY-#NNN]` в исходниках novac
(страж `check-novac-legacy-workarounds.sh`).
