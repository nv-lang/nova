## 1. Слои

Референс — **Go** (`cmd/go` ↔ `cmd/compile`): один бинарник наружу, разделённые программы
внутри.

| слой | что делает | в месяц |
|---|---|---|
| **компилятор** (`novac/src/**`) | исходники + конфиг → диагностики + артефакты; не знает про пакеты, тулчейны, сеть | пишется |
| **драйвер** (Rust, как есть) | граф пакетов, зависимости, кэш, тулчейн, линковка, демон | не трогается |
| **CLI** | разбор аргументов, печать | тонкий `novac`-бинарь для дифф-гейта; остальное — Rust |

Инварианты слоя: (1) компилятор читает только переданное — ни обхода ФС, ни резолва
пакетов. Счётчик: **1**.

## 2. Карта модулей — до листьев

Референс размещения — Go (`cmd/compile/internal/*`: мелкие пакеты по фазам). Папка =
один модуль (конвенция проекта). Лимит — 1000 строк на файл, жёстко.
«Одна дверь»: у каждого класса задачи ровно один модуль-решатель.

| модуль | назначение (одна строка) | дверь какого класса задач | инв. |
|---|---|---|---|
| `source` | текст исходника: `FileId`, `Span`, строчный индекс | представление исходника | 1 |
| `diag` | `Diagnostic` по схеме §7; человеческий текст рендерится ИЗ структуры | форма диагностики | 2 |
| `lex` | текст → токены **с тривией** | токенизация | 1 |
| `tree` | зелёное дерево: неизменяемые узлы, тривия, узлы-ошибки; ширины, не позиции | синтаксис-как-данные | 2 |
| `syntax` | красный вид поверх `tree`: родители, позиции, типизированные аксессоры; **типизированная проекция КАНОНИЗИРУЕТ**: поверхностные формы живут только в зелёном дереве, `check` видит канонические узлы | навигация + канонизация | 2 |
| `parse` | токены → зелёное дерево; восстановление после ошибок | построение дерева | 1 |
| `types` | канон типа: конструкция и интернирование `ResolvedType` | **конструкция типа** | 2 |
| `names` | резолв имён и модулей: «имя → объявление»; **порядконезависим**: collect → resolve, два прохода (урок B10m: write-once pre-scan ломал forward-reference) | резолв имени | 2 |
| `check` | чекер; **единственный писатель** `sem` | типизация и правила | 1 |
| `sem` | семантическая модель: `resolved_types`, `resolved_callees`, `node_substs` — дом каналов 196 | правда о типах/вызовах | 1 |
| `lower` | понижение в бэкенд-агностик форму; **место будущего MIR** | понижение | 1 |
| `mono` | сбор инстанцирований | мономорфизация | 1 |
| `emit_c` | бэкенд A: C-текст | выпуск C | 1 |
| `pipeline` | **единственный владелец порядка проходов**; API `compile(files, cfg) → (диагностики, артефакты)` | оркестровка | 1 |
| `main` (бинарь) | тонкий CLI поверх `pipeline` | — | 0 |

Ключевые «одно окно», закреплённые картой (примеры владельца, 274.1 §2б):

- **тип строится только в `types`**: кортеж — обычный тип; «без дженериков» — частный
  случай «с дженериками» (пустой список), не вторая ветка;
- **позиция типа не выбирает конструктор** (пример владельца 2026-08-14: именованный
  кортеж инлайном `[](a: int, b: str)` сейчас НЕ работает — только через объявление
  `type`; значит у инлайн- и объявленной формы разные пути — вторая дверь). Формулировка владельца:
  «если позиция — тип, он должен РАСПАРСИВАТЬСЯ и РЕСОЛВИТЬСЯ одним и тем же окном,
  а не в зависимости от того, где тип в коде написан». То есть окно — вся цепочка:
  **один нетерминал грамматики** `Type` в `parse` (каждая позиция — параметр, возврат,
  аннотация let, generic-аргумент, объявление `type`, каст — ссылается на него; второй
  входной точки вида `parse_type_str` не существует) → **одно понижение**
  `TypeExpr → ResolvedType` в `check`/`types` → **один конструктор** в `types`
  (D315 доказал третье звено ретайром `type_ref_to_c` — четвёртого дубля таблицы;
  `novac` обязан держать все три). `type X = …` лишь ПРИВЯЗЫВАЕТ имя к типу,
  построенному тем же конструктором; каждая форма типа работает в каждой позиции типа
  по построению. Если спека запрещает
  форму в позиции — это одно правило-проверка в `check`, а не отсутствующая ветка
  конструктора. Расхождения с нынешним компилятором в таких местах — в реестр
  (`bug-legacy` либо `by-design` с D-блоком), молча не расширять;
- **метод = функция с receiver-параметром**: `names`/`check` не имеют «методного» пути
  рядом с «функциональным»;
- **порядок проходов существует только в `pipeline`** — урок LSP, звавшего десять
  проходов по именам.

Счётчик раздела: **19** (сумма колонки).

## 3. Рёбра — с колонкой «что течёт»

Вход стража `check-novac-deps.sh` (Э1). Ребро вне таблицы — красный. Ребро без «что течёт» —
красный. Референс дисциплины — модель `rustc_codegen_ssa`: бэкенд не видит ничего выше
понижения.

| из | в | что течёт |
|---|---|---|
| `lex` | `source` | читает `SourceText`; наружу отдаёт `Token[]` (тривия внутри токенов) |
| `parse` | `lex` | `Token[]` |
| `parse` | `tree` | строит `GreenNode` |
| `parse` | `diag` | выпускает синтаксические диагностики |
| `tree` | `lex` | листья зелёного дерева — `Token` ДАННЫМИ; tree не зовёт лексер, только несёт его тип |
| `syntax` | `tree`, `source` | проекция: позиции из ширин + текст для рендера |
| `names` | `syntax`, `diag` | читает объявления/области; выпускает диагностики резолва |
| `check` | `syntax`, `names`, `types`, `diag` | читает КАНОНИЧЕСКИЕ узлы проекции (поверхностных форм на этом ребре нет — контракт); строит типы ТОЛЬКО через `types`; пишет `sem` (единственный) |
| `check` | `tree`, `lex`, `source` | **Э1-временное** (до появления `syntax`): мини-чекер читает зелёное дерево, токены и позиции напрямую; снимается при Э2-red-слое — ревью среза обязано это ребро удалить |
| `mono` | `sem` | читает инстанцирования |
| `lower` | `syntax`, `sem`, `diag` | тела + типы → бэкенд-агностик форма; MIR-пассы владения (К5) выпускают СВОИ диагностики |
| `emit_c` | `lower`, `mono` | **только** пониженная форма (несёт ДАННЫМИ интернированный канон типов И `DeclId`-пути для мэнгла §4а п.5); рёбер-импортов к `syntax`/`tree`/`check`/`names`/`types` НЕТ |
| `pipeline` | `source`, `lex`, `parse`, `check`, `lower`, `mono`, `emit_c`, `diag` | оркеструет (ЕДИНСТВЕННЫЙ, кто зовёт фазы); наружу — `(Diagnostic[], Artifact[])` |
| `main` | `pipeline`, `diag` | зовёт compile; печатает из структуры |

Запреты, которые страж держит отдельно: `emit_c` (и будущий `backend_native`) не
импортируют ничего выше `lower`; никто, кроме `check`, не пишет `sem`; никто, кроме
`types`, не конструирует `ResolvedType`.

Инварианты: (1) рёбра только из таблицы, и каждое несёт контракт «что течёт»;
ацикличность отдельным инвариантом не считается — она следует из самой таблицы (вердикт
К4, §16). Счётчик: **1**.

## 4. Карта информации

Референс — каналы 196, доказанные живьём (mismatch=0 на флипнутых классах). Каждый
класс информации — одна дверь-производитель; потребители читают, не перевычисляют
(урок 196: `infer_call_ret_c` мимо чекера стоил месяцев).

| класс информации | дверь-производитель | потребители |
|---|---|---|
| токены | `lex` | `parse` |
| синтаксис | `parse` (строит) / `tree` (владеет) | `syntax` → все |
| позиции | `syntax` (вычисляет из ширин) | `diag`, LSP, все |
| «имя → объявление» | `names` | `check`, LSP |
| типы значений и вызовов | `check` → `sem` | `lower`, `mono`, `emit_c` (через `lower`), LSP |
| инстанцирования | `mono` | бэкенды |
| пониженная форма | `lower` | бэкенды |
| C-текст | `emit_c` | драйвер |
| диагностики | каждый производит СВОИ; форма — `diag` | `main`, LSP, агент |

Инварианты: (1) `sem` после `check` неизменяем; (2) ни один потребитель не перевычисляет
чужой класс. Счётчик: **2**.

## 4а. Идентичность — не имя

Требование владельца 2026-08-14: имена повторяются — между модулями, между вариантами
разных сумм, между методами разных типов — и в нынешнем компиляторе это источник
постоянных багов. Класс измерен многократно: №576/№613 — обход достижимости ходит по ИМЕНАМ (голый
конструктор варианта терял метод-сет типа; ранняя гипотеза «имя решает раньше
объявления» опровергнута окном плана 270 — правим по финальному вердикту реестра), B11q
(нить из одних имён — баунды потеряны), №534 (захват `spawn` берёт чужое имя), №617
(алиас утекает за пределы файла), [M-d289] (коллизия модульно-квалифицированных путей);
корневой класс окна C так и называется — «резолв по имени, а не по типу».

**Правило: имя — ключ ровно в одной двери (`names`), идентичность — везде дальше.**

1. Каждая декларация при резолве получает **`DeclId`** — уникальный, стабильный внутри
   компиляции (эталон — rustc `DefId`). После фазы `names` ни одна таблица не ключуется
   строкой: `sem`, `mono`, `lower`, `emit_c` знают только `DeclId`/`NodeId`.
2. **Вариант суммы = (DeclId суммы, индекс варианта)**, не имя. Имена вариантов свободно
   повторяются между суммами — коллизия невозможна по построению, а не по дисциплине.
3. **Метод**: пара «(DeclId типа-носителя, имя)» существует только ВНУТРИ резолва; наружу
   выходит `DeclId` метода. «Метод = функция с receiver» (§2) делает это бесплатным.
4. **Области видимости — пространствами**: варианты живут в пространстве своей суммы,
   методы — своего типа, top-level — своего модуля. Голого глобального пространства имён
   нет вовсе.
5. **Мэнглинг — функция от DeclId-пути** (модуль → тип → имя → substs), а не от имени:
   ровно то, что `ResolvedType::Named{module}` уже начал в текущем каноне.
6. **Страж** (входит в `check-novac-deps.sh`-семейство): `Map[str, …]` как таблица резолва вне
   модуля `names` — красный. Строка законна как ключ только там, где происходит
   сопоставление написанного текста с декларацией, — и это одно место.

Инварианты: (1) после `names` строковых ключей нет; (2) `DeclId` стабилен внутри
компиляции. Счётчик: **2**.

## 5. Дерево

Референс — **Roslyn** (красно-зелёные деревья). Решение 5 зонтика.

- **Зелёный слой** (`tree`): неизменяемые узлы; хранят **ширины**, не абсолютные позиции;
  тривия (пробелы, переводы строк, комментарии) прикреплена к токенам
  (leading/trailing); переиспользуются между правками.
- **Красный слой** (`syntax`): родители и абсолютные позиции, вычисляются лениво;
  типизированный AST — **проекция**, не вторая структура.
- **Узлы-ошибки — по построению**: нераспознанная конструкция остаётся поддеревом сырых
  токенов. Сломанный и недописанный ввод представим всегда; «продолжить после ошибки»
  есть куда записывать.

Инварианты: (1) **ре-сериализация зелёного дерева побайтово равна исходнику** — главный,
проверяется на каждом файле корпуса дифф-гейтом; (2) у каждого узла есть span (через
ширины); (3) зелёные узлы неизменяемы. Счётчик: **3**.

## 6. Пять требований к интерфейсу

Нормативно в [274 §4](../plans/274-novac-self-hosted-compiler.md); здесь — как карта их
несёт: нет `Result` (все фазы возвращают «результат + диагностики» — форма API
`pipeline`); сломанное представимо (§5, узлы-ошибки); отравление (§7); позиции везде
(§5, ширины + `syntax`); нет общего изменяемого состояния (фазы — функции; `sem`
неизменяем после производителя). Аудит нынешнего компилятора по этим пяти — §13.

Инварианты: раздел — указатель на норму 274 §4, своей конструкции не несёт; пять
требований посчитаны там, здесь ноль новых. Счётчик: **0**.

## 7. Диагностика

Референс — **rustc** (`--error-format=json`). Первый потребитель — агент (274 §6),
поэтому схема нормативна, а человеческий текст — рендер из неё, никогда наоборот.
Страж — `check-novac-diag-schema.sh` с Э1.

```json
{
  "id": "стабильный-в-выдаче идентификатор диагностика",
  "code": "E_...",
  "severity": "error | warning",
  "primary": { "file": "...", "start": 0, "end": 0 },
  "message": "...",
  "notes": [ { "span": {}, "text": "..." } ],
  "suggestion": { "span": {}, "replacement": "..." },
  "poisoned_by": "id первопричины | null"
}
```

**Отравление:** узел, построенный по сломанному вводу, помечен; фазы по нему молчат;
вторичный диагностик либо подавлен, либо несёт `poisoned_by`. **Явный сентинел
обязателен** — измеренная альтернатива хуже: нынешний чекер держит «нет каскадов» на
пермиссивном unknown («не вывелось — пропусти проверку»), и та же механика глотает
настоящие ошибки: `fn f() -> int { "str" }` и `if 5` проходят `nova check` зелёным
(№652, подтверждено пробой). Отравление отличается от пермиссивности одним: у него есть
правило «ошибка УЖЕ репортнута», у пермиссивности — нет. «Одна ошибка — одна
причина» держит `check-novac-no-cascade.sh` (фикстуры «одна посеянная опечатка → ровно один
диагностик»), потому что дифф-гейт каскады не ловит — оракул сам каскадит.

Инварианты: (1) каждый диагностик валиден против схемы; (2) у error всегда есть
`primary`-span. Счётчик: **2**.

## 8. Семантический слой

Референс — **свой канон, доказанный 196-м, + rustc** (интернирование). Дом урожая 196
(§14): каналы становятся полями `sem`, а не изобретаются заново.

- `types`: `ResolvedType` — единственная форма правды о типе (D315); интернирование —
  структурно равные типы суть один объект; **без арен** — у нас GC, протяжка времён
  жизни не нужна (аренная механика rustc — обход отсутствия GC, не переносится);
- **generic-параметр — полный объект с первого дня**: TypeVar несёт свои constraints
  (баунды, share-ness, thread-safety) от объявления до точки использования — эталон
  rustc `ParamTy`+predicates. Урок корня B11q (нить `gs` из одних ИМЁН через 31 сайт —
  тупик, на котором консолидация 196 упёрлась) и №150: это ОДНА абстракция под оба
  класса, проектируется один раз;
- `sem`: `resolved_types: NodeId → ResolvedType`, `resolved_callees`, `node_substs` —
  только данные, ноль логики;
- `check` — единственный писатель; после него `sem` заморожен.

## 12. MIR — эскизы (полная проработка на Э4)

Эскиз = референс + границы + «что берём/не берём», БЕЗ разрешения вопросов уровня Э4.

- **Скелет** (rustc MIR): базовые блоки, локалы с типами из `sem`, терминаторы.
  Берём форму; не берём четыре промежуточных уровня rustc (AST→HIR→THIR→MIR —
  наросшая история, нам хватит одного понижения).
- **Дропы и перемещения** (rustc drop elaboration / move-check): D432 auto-cleanup и
  линейность D131/D133 — явными инструкциями на CFG; `spawn consume` проверяется по
  графу — на дереве это либо отвергает корректное, либо пропускает гонку (№456 —
  измеренная цена).
- **Владение и протоколы** (Swift SIL): экзистенциалы и структурные протоколы —
  напряжение «обобщённый код против стёртого значения» (разбор Display/to_str).
- **Эффекты** (Koka, evidence passing): хендлер как значение-свидетельство; у rustc
  ответа нет. Стык с файберами — §15.
- **Safepoint'ы и GC-карты** (Go SSA): точки приостановки — явные в MIR, стек-карты
  для Boehm-замены в перспективе; в месяц не трогается.

## 12а. Развилка мономорфизации — варианты и цены (решение на Э4, не здесь)

Вход: №640 — цена полной mono измерена (семь строк → 444 тела, 285 КБ C; объём не
зависит от программы); `rt_slots` 8246+ хитов — цена mono БЕЗ канала подстановок.

| вариант | за | против |
|---|---|---|
| **A. Полная mono** (как сейчас) | предельная скорость кода; простой C-ABI | цена компиляции — №640; объём C; дубли тел |
| **B. GC-shape словари** (Go 1.18) | код на КЛАСС форм (все указательные — одна); резко меньше C; быстрая компиляция | непрямые вызовы; словари в ABI; стык со структурными протоколами и эффектами через словарь — не исследован |
| **C. Гибрид** (mono для примитивов/малых, shape для указательных) | баланс цены и скорости | опасность класса «второе вычисление» (К4, §16): две механики. Легален ТОЛЬКО если выбор стратегии — решение ВНУТРИ одной двери `mono` (per-instance политика), а не два пути кода по конвейеру |

**Критерий решения (Э4):** замер сборки корпуса + бенч паритета Go на M:N-нагрузке —
числами, не вкусом; и жёсткое условие конструкции: при любом варианте стратегия живёт в
`mono`, бэкенд получает уже развёрнутые инстансы и о вариантах не знает.

Решение здесь НЕ принимается (274 §9, Э4); эскиз существует, чтобы Э1–Э2 не заложили
ничего, что закрывает вариант B или C — а именно: подстановки только через `node_substs`
(§14.1), никакой mono-логики в `emit_c`.

## 15. Непокрытые места — поимённо

Ни один референс не покрывает; проектируем сами, каждое — с записанной причиной.

1. **Эффекты × M:N-файберы.** Koka компилирует эффекты без тредов; Go даёт M:N без
   эффектов. Комбинации целиком нет ни у кого. Открыто; черновик — на Э4 (MIR-эффекты).
2. **Эффекты через границу `spawn`.** Хендлер — значение; что происходит при переносе
   продолжения на другой воркер. Открыто; решается вместе с 1.
3. **Линейность при отмене `supervised`.** consume-обязательства на пути отмены/таймаута
   (D408/D449 × D131) — пути появляются не там, где написаны. Открыто; Э4, дропы на CFG.
4. **Рантайм-градусные контексты** (no-alloc/no-GC код планировщика и клея аллокатора) —
   нужны Э6 (Vela-на-Nova); Go решает `nosplit`-дисциплиной вне языка. Кандидат в
   языковое решение — D-блоком, не раньше Э4.
5. **Шов LSP** — каналом что: in-proc FFI или IPC-процесс. **Решить перед Э3** —
   дедлайн из 274.1; на месяц не влияет.

## 16. Классы проблем двух месяцев — и их конструктивное решение

Требование владельца 2026-08-14: классы, с которыми проект возится последние два месяца,

Структуру держит страж `check-novac-arch-class-proofs.sh` (самотест 5/5); содержательность

Источник: кластеризация реестра четырьмя чтецами (№390–652 + backlog), семь классов.
Статус: адверсарная проверка завершена — 7/7 вердиктов, ДВЕ волны (вторая — по
исправленному тексту). Все находки внесены; переатрибуции носителей отражены в блоках.
Выжившее ядро: К4 — верность и место устояли со второй волны; остальные пересобраны.

### К1. M:N-рантайм: множество несогласованных учётов вместо одного владельца

Носители после адверсарной чистки: ядро — №438, №427, №443, №498 и родня (гонки
учётов самой Vela). Переатрибуции: №456 — корнем в К5 (симптом рантаймный, корень
компиляторный — consume-identity, так пишет и реестр); №458 — протокольная
недоведённость parной операции (род К7), не учёт; №457 — не перевоспроизведён
(гипотеза реестра: носитель №456/№498); M-218 — гонка Rust-ДРАЙВЕРА, закрыта локально
2026-07-20, слой решением К1 не покрывается. Механизм:
каждая фича заводит свой учёт — ~28 атомиков состояния фибра, два счётчика владения
одним сокетом, свой путь доставки отмены у каждого примитива; комбинации не
спроектированы, дефекты видны только под нагрузкой (257 следов починки гонок).

**Решение:** одно слово состояния на сущность, переходы — CAS по явной таблице; один
владелец учёта на ресурс. Реализуется при переезде Vela на Nova (Э6), вход —
консолидация состояния [250](../plans/250-vela-state-consolidation.md).
**Верность:** референс продакшеном — ранний Go держал ОДНО слово `gstatus` с явными
переходами и жил без этого класса. Честно о ролях: оракул C-Vela держит только
СОХРАНЕНИЕ поведения (он сам несёт дефекты класса); класс убивают конструкция + машинный
инвентарь слов состояния ([250](../plans/250-vela-state-consolidation.md)) +
стресс-гейт [debugging-races.md](debugging-races.md) как приёмка.
**Место:** рантайм (Э6, 274 §1.3), НЕ карта компилятора; компилятора касается ДВУМЯ
рёбрами: «одна дверь атомиков» (§10) и consume-identity половин ресурса — это К5
(`check`/`lower`), где живёт корень №456.
**Минимальность:** инвариант «состояние сущности меняется одним CAS-переходом таблицы»
заменяет ~28 согласований пар атомиков; «один владелец учёта на ресурс» — его СЛЕДСТВИЕ
(второй счётчик того же ресурса = второе слово той же сущности, запрещён тем же
инвариантом), не отдельный. Отдельное плечо — доставка отмены: инвариант «отмена
приходит переходом слова состояния, не отдельным каналом»; цена его снятия — вечные
зависания под cancel (семья №457/№480). Итого два инварианта, и меньше нельзя: слово без
правила доставки отмены оставляет живым второй по цене под-механизм класса.

### К2. Резолв по голой строке имени через плоские last-wins таблицы

30 носителей (№536, №576, №617, №534, №623, M-d289 и родня; по вердикту К3 сюда же
переатрибутированы №613 — «обход достижимости ходит по именам», род №576 — и №627 —
выбор не того callee через границу алиаса, род №536/№617). Механизм: CU-широкие
таблицы ключуются именем без модуля/типа/области; последняя запись выигрывает, диспетч
молча берёт чужое объявление; исход зависит от состава CU.

**Решение:** §4а целиком — `DeclId` после единственной двери `names`; пространства имён
на сумму/тип/модуль; `names` порядконезависим (collect → resolve).
**Верность:** двухчастная (вердикт: одночастная держала только пол-класса). НИЖЕ
`names` коллизия невыразима — таблицы ключуются идентичностью, совпадение имён не
совпадение ключей (rustc `DefId`, продакшен). ВНУТРИ `names` — единственного места, где
строки легальны, — класс держит инвариант (а): резолв ключуется парой
(`NamespaceId`, имя), плоской CU-широкой таблицы кандидатов не существует; квалификатор
и тип приёмника ФИЛЬТРУЮТ пространство, а не гейтят пост-фактум (механизмы №536/№627 —
ровно пост-фактум-гейт над плоской таблицей). Оговорка носителей: №623 — заявленная
форма не воспроизведена пробой 2026-08-13, его механизм («единственный кандидат без
проверки годности») — правило годности в `check`, не ключевание.
**Место:** `names` (единственная строковая дверь; дом инварианта (а)) + `sem` (носит
DeclId); `parse` не резолвит; `emit` имён не РЕЗОЛВИТ — имя доезжает компонентом
`DeclId`-пути данными пониженной формы (§3, мэнглинг §4а п.5).
**Минимальность:** ДВА инварианта: (а) внутри `names` ключ несёт `NamespaceId` — снять
при зелёном (б): №536/№627/остаток №534 возвращаются, страж строковых ключей их не
видит; (б) после `names` строковых ключей нет (`check-novac-no-string-keys.sh`; для (а)
тот же страж получает второй чек: таблица в `names` без `NamespaceId`-компонента —
красная) — снять: №617-кодоген и №613-достижимость возвращаются. Каждый контрпример
бьёт по своему инварианту.

### К3. C-представление порождается посайтно из текста типа

26 носителей (№581, №483, M-valuerecord-семья и родня). Переатрибуции по вердикту:
№613 и №627 — в К2 (реестр сам вяжет их к №576 и №536/№617: там неверен РЕЗОЛВ, и
каноничное имя неверного метода остаётся неверным методом); №619 — вне семи классов
(комментарий-дрейф, род №484: текст, не поведение). Механизм: имя/форма C
форматируются локально на сайте из текстового представления типа — две схемы имени
одного типа, heap-допущения зашиты в бокс/mono/vtable-пути, value-записи и составные
payload-формы дают CC-FAIL на прошедшем check коде.

**Решение:** §9 — бэкенд читает ТОЛЬКО пониженную форму; C-имя — одна чистая функция от
канона `ResolvedType` + `DeclId`-путь (§4а п.5); формы значений (value/tuple/payload) —
явные в `lower`, а не допущение эмиттера.
**Верность:** источник один И дверь одна: всё вычисление C-имени и репрезентации — один
модуль ниже шва, держится стражем `check-novac-c-name-door.sh` (форматирование
имени/репрезентации вне двери — красное; вердикт показал, что без НАЗВАННОГО стража
«одна функция» — проза: две функции от одного канона легальны по всем рёбрам). То же
плечо убивает valuerecord-семью: две репрезентации одного канона — это два выхода одной
функции, невыразимо. Прецедент в малом — D315 (ретайр `type_ref_to_c`). Переатрибуция:
№483 — корень не имя, а фабрикация `nova_unit` для расходящегося хвоста (`Never`);
решается явным представлением расходимости в `lower`/MIR (§12, Э4); до Э4 держится
правилом `lower`: расходящееся выражение не материализует значения.
**Место:** `lower` + `emit_c` ниже шва; рёбра §3 запрещают бэкенду доступ к тексту
типов и к `syntax` — посайтному форматтеру негде взять вход. Уточнение контракта ребра
(внесено в §3): пониженная форма НЕСЁТ интернированный канон типов ДАННЫМИ — поэтому
«функция от `ResolvedType` в `emit_c`» не противоречит запрету ребра-ИМПОРТА к `types`.
**Минимальность:** пересчитана второй волной — несущий инвариант ОДИН, семантический —
«C-имя и репрезентация — функция от интернированного канона (`ResolvedType` +
`DeclId`-путь): один канон ⇒ ровно одно имя и одна репрезентация». Пункты (а) «ровно
одна функция» и (б) «вход — только канон» — его конструктивная РЕАЛИЗАЦИЯ, не отдельные
инварианты: (а) исключает два выхода (№581 — обе схемы выводились из типа двумя
функциями), (б) исключает вход, различающий написания (`[]T`=`Vec[T]`). Меньше нельзя,
потому что подмножества {а} и {б} падают каждое своим контрпримером — а семантический
инвариант целиком и есть их конъюнкция, выраженная одной фразой.

### К4. Второе вычисление уже решённого суждения

32 носителя (№480, №541, №634, P67-LEGACY-класс). Переатрибуция: №495 — в К6/К7 (его
тело — «нормы спеки без энфорса вовсе», ноль реализаций, не две; а внутренний дубль
D406/D310 — внутримодульный, графом рёбер не ловится — честная граница К4). Механизм:
суждение реализовано
дважды — эмиттер перевыводит типы мимо каналов, cmd_build/check/LSP несут свои копии
пайплайна, интерполяция — свой диспетч печати; вторая копия отстаёт молча.

**Решение:** §3/§4 — потребители читают `sem`, не перевычисляют; порядок проходов
существует только в `pipeline`; LSP и CLI зовут ту же библиотеку.
**Верность:** честной трёхчастной формулой (вердикт опроверг одночастную «это граф»):
(1) МЕЖмодульные копии внутри компилятора не собираются по графу рёбер §3 — №480 и
P67-LEGACY-класс умирают конструкцией; (2) копии из ЛЕГАЛЬНЫХ входов (`lower` видит
`syntax`+`sem`) держит §4-инв.2 «потребитель не перевычисляет чужой класс» + запреты §3
(конструирует только своя дверь); (3) потребители ВНЕ карты — LSP, линт, CLI (№541,
хвост №634) — это исполнение инварианта (б) на внешнем шве: LSP/CLI стоят в колонке
потребителей карты §4, и §4-инв.2 запрещает им второй парсер так же, как модулям; страж
паритета (`check-novac-lsp-parity.sh`, Э3, шов §15.5) — ПРИЁМКА (б) там, куда
`check-novac-deps.sh` не достаёт. Уточнение по №480 (вывод самого реестра → 172.12):
копия-стек поверх AST не собирается без ребра к `syntax`; против копии поверх пониженной
формы — §4а: локалы в `lower`/`emit` суть `DeclId`, не имена. Демонтаж 196 доказал
направление на живом (mismatch=0 на флипнутых классах).
**Место:** `pipeline` (единственный оркестратор) + таблица рёбер §3 с колонкой «что
течёт» (`check-novac-deps.sh`).
**Минимальность:** пересчитана второй волной ((в) не независим) — ДВА инварианта:
(а) рёбра только из таблицы §3, каждое несёт контракт «что течёт» (ацикличность отдельно
не требуется — следует из таблицы); (б) §4-инв.2 «потребитель не перевычисляет чужой
класс» — действует на ВСЕХ потребителей карты §4, включая LSP и CLI. «Зовут `pipeline`»
— не третий инвариант, а исполнение (б) на внешнем шве (дверь порядка уже посчитана в
§2); страж паритета — приёмка, не инвариант. Снятие (а) — №480/P67-LEGACY собираются
вновь; снятие (б) — легальный второй инференс в `lower` И №541 разом. Дом (б) — §4.

### К5. Владение объявлено прозой; энфорс знает только канонические пути

20 носителей (№467, корень №456, №410, №419, M-d180-семья, M-detach-consume-escape).
Механизм: `ro`/`consume`/unsafe-обязанности не выражены в представлении (пара булевых
вместо перечисления, обязанность в докстринге), проверка перечисляет «хоженые» пути —
match-payload, defer, detach-капчер молча гасят обязательство.

**Решение** (три звена; третье добавлено второй волной — unsafe-плечо механизма первые
два не закрывали): (1) режим владения — в представлении: перечисление Ro/Mut/Consume в
типе, не пара булевых; обязанность из докстринга нелегальна; (2) дропы и
consume-обязательства — явные MIR-инструкции, проверка — баланс по ВСЕМ путям CFG;
(3) **unsafe — часть сигнатуры** (`unsafe fn`): фабрикация значений мимо конструктора
легальна только через unsafe-дверь, вызов — только из unsafe-контекста (носители №419
`append_zero`, №422 `Vec.new(ptr,len,cap)` — у них баланс владения сходится тривиально,
их держит именно звено 3).
**Верность:** rustc drop elaboration / move-check — продакшен-прецедент звеньев 1–2;
№456 — точно по реестру: «авто-cleanup срабатывает безусловно — дизарм на пути явного
close не виден», цена дерева вместо графа: по CFG путь close — обычное ребро. Оговорка:
«включая отмену и таймаут» держится только после закрытия §15.3 (открытый вопрос);
пометка источника: M-d180-семья живёт в backlog, не в №221.1.
**Место:** режимы и правила — `check`; баланс — пасс над MIR ПОСЛЕ `lower` (на дереве
нельзя — §12); диагностики пасса — по ребру `lower`→`diag`, внесено в §3 (иначе страж
рёбер краснил бы легальную реализацию).
**Минимальность:** ДВА инварианта (вердикт: одного мало — unsafe-носители проходят
зелёный баланс): (а) каждое обязательство выражено в представлении (режим в типе,
unsafe в сигнатуре) — снять: балансировать нечего, №467/№419/№422 возвращаются при
зелёном (б); (б) баланс обязательств по всем путям CFG — снять: путь
(match-payload, defer, detach-капчер) гасит обязательство молча — №456, M-d180.

### К6. Энфорс посажен на перечисление синтаксических форм

Носители после чистки второй волны: №466 — корнем B (четыре ветки конструирования мимо
обёртки; его же корни «нет правила на присваивание полю» — в К5, release-стирание
`#debug` — в К7), «пять из шести форм параметра» и родня. Переатрибуция: «семья №649» —
вне семи классов (род стражей гейта №645/№647/№648/№649: механизм отвечает не на тот
вопрос — не формы AST). Механизм: проверка написана по списку конкретных форм AST;
незанесённая форма проходит молча; рефакторинг пользователя обходит энфорс.

**Решение** (дом канонизации исправлен второй волной — прежняя формула «parse→lower»
противоречила §5-инв.1 и позиции `lower` после `check`): канонизирует **типизированная
проекция `syntax`** (§2): поверхностные формы живут только в зелёном дереве (лосслесс
не страдает), `check` по контракту ребра §3 видит ТОЛЬКО канонические узлы; правило
пишется один раз против канона (примеры в карте: метод=функция, «без дженериков» =
пустой список, позиция типа не выбирает конструктор).
**Верность:** «незанесённая форма» не существует для правил по построению — контракт
ребра `check`→`syntax`; сама проекция тотальна: исчерпывающий match без wildcard (родня
инварианта К7-(а)), непокрытая поверхностная форма — ошибка компиляции компилятора;
хвост давит `check-novac-diff-fuzz.sh` (после Э2); прецедент — desugar rustc.
**Место:** канонизация — `syntax` (проекция); правила — только `check`; зелёное дерево
держит лосслесс (§5), `emit` форм не знает.
**Минимальность:** счётом «ноль НОВЫХ инвариантов» (вердикт предлагал пару — берём
вариант сильнее): (а) «правило только на каноне» — это КОНТРАКТ ребра `check`→`syntax`,
посчитан в §3, отдельного инварианта не заводит; (б) «нормализация тотальна» — это
исчерпывающий match проекции, тот же механизм, что К7-(а). Снятие контракта ребра —
правила снова видят поверхностные формы, комбинаторика (форма × правило) возвращается;
снятие тотальности — молчаливый пропуск формы, №466-корень B.

### К7. Полуготовый механизм: возможность без обязательств

17 носителей (семья №652, `-> consume T` как no-op, `#zero_on_move` с молчаливым
непринятием, №465 как измеренный прецедент слабой фикстуры). Переатрибуция: №469 — вне
К7 (работающий `__sret` без грамматической формы; семья «спека↔реализация разошлись»,
№487). Механизм: синтаксис принят, а семантика/диагностика/энфорс не доведены —
конструкция парсится и молча не работает; в представлении нет Poisoned,
«недоведённость» неотличима от «законно неизвестного».

**Решение** (пересобрано по вердикту — прежняя опора на `check-test-fixture-coverage.sh`
не держит: тот страж дифф-базный и слеп к слиянию БЕЗ нового кода диагностики, ровно где
класс и рождается): главный инвариант — ПО ПОСТРОЕНИЮ: **диспетч `check` по видам узлов —
исчерпывающий match БЕЗ wildcard-арма**; вид узла, не получивший правила, не проходит
молча — компилируется только с явным армом `E_NOT_IMPLEMENTED` + Poisoned (генерализация
решения владельца по №465). Приёмкой сверху — карта «форма грамматики × фикстуры», где
фикстура обязана НАБЛЮДАТЬ обязательство (positive — эффект виден, negative — отказ
виден; №465 — измеренный контрпример слабой формулировки: A8.25–A8.28 были зелёными при
невставленном вызове хелпера).
**Верность:** зазор «принято парсером — не доведено чекером» невыразим: новый вид узла
без арма — ошибка КОМПИЛЯЦИИ компилятора (exhaustive match), арм-заглушка честно
диагностирует и травит. Уточнение второй волны: семью №652 exhaustive-диспетч НЕ
закрывает — её механизм живёт ВНУТРИ написанных армов (skip-on-unknown); её держит
дисциплина §7 как третий элемент: в `check` нет пермиссивного unknown — тип либо
известен, либо Poisoned с уже репортнутой первопричиной. №465 умер ниже чекера (вызов
хелпера не вставлен в кодоген) — этот ярус наблюдает только фикстура (б).
**Место:** `check` (exhaustive-диспетч) + `diag` (Poisoned §7) + приёмка (карта
форм × фикстур, свой страж `check-novac-grammar-fixture-coverage.sh`, Э1 — дифф-базный
`check-test-fixture-coverage.sh` этому классу не судья).
**Минимальность:** пересчитана второй волной — несущих инварианта ДВА — (б) карта
форм × наблюдающих фикстур и (в) запрет пермиссивного unknown (§7: «ошибка уже
репортнута» — единственная законная форма незнания это Poisoned). (а) исчерпывающий
диспетч — конструктивная механика РАННОСТИ, не несущий инвариант: при живом (б)
пропущенный арм ловится гейтом, (а) ловит его раньше — на компиляции компилятора.
Снятие (в) — семья №652 возвращается при зелёных (а) и (б); снятие (б) — №465/№616
живут до первого пользователя; снятие (а) класс не возвращает, но переносит отказ с
компиляции на гейт.
