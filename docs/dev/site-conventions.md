# Конвенции сайта nv-lang.org

> Решения владельца по сайту (репа `www`). Дом решений — здесь (docs/dev, внутренняя
> зона), НЕ в spec/decisions (D-номера = спека языка) и НЕ в репе www (точка входа
> агентов — nova). Формат — датированные пункты с якорями; отдельной нумерации нет
> (conventions-governance: один источник правды). Приёмка любой сайтовой волны
> сверяется с этим файлом.

## release-neutrality {#release-neutrality}
(2026-08-02, стоячее до v0.1) На сайте нет утверждений о релизах: никаких
«released», ссылок на GitHub Releases/теги nova, обещаний бинарных артефактов.
Source-build — единственный путь установки, так и подавать. Ветка
`release-v0-1-page` не мержится и не публикуется до явной команды владельца.
Прецеденты правок: футеры «Релизы/Releases» → «Обсуждения/Discussions»
(2026-08-02, /install/ и общий Footer.astro).

## en-ru-sync {#en-ru-sync}
(2026-08-02, подтверждено многократно) Русские зеркала страниц (`ru/**`,
`ru-*`-партиалы) обновляются СИНХРОННО с en в той же волне. Правка только
одной стороны не сдаётся.

## docs-guide-only {#docs-guide-only}
(2026-08-02, docs-split) Doc-контент сайта тянется ТОЛЬКО из `docs/guide/`
репы nova (`sync-decisions.mjs`). `docs/dev/` не цитировать и не линковать;
проверка «синк не тянет dev/» — часть приёмки. Старые плоские пути
`docs/<имя>.md` мертвы — при встрече обновлять на `docs/guide/<имя>.md`.
Сгенерированный контент (`site/src/content/decisions|spec|docs`) руками не
править — правки уйдут при следующей сборке; чинить источник в nova.

## compilable-examples {#compilable-examples}
(2026-08-02) Каждый код-пример на рукописных страницах обязан компилироваться
реальным компилятором (`nova check`/`build`) перед сдачей. Синтаксис не
выдумывать — сверять со `spec/decisions/` + `examples/`. Прецеденты находок:
пример `/doc/` с удалённой блок-формой `realtime nogc { }` не компилировался;
формулировка о контрактах противоречила ретракту Plan 140. Страница не
обещает того, что не подтверждено фактом (прецедент: оговорка про Boehm GC
на /install/ до закрытия №268/№269).

## honest-dates {#honest-dates}
(2026-08-02, план 241) Даты «last updated» на страницах — только дата
последнего коммита ИСТОЧНИКА. Штамповать датой сборки запрещено (ложный
сигнал свежести); нет данных — блок даты не рендерить.

## edit-vs-source {#edit-vs-source}
(2026-08-02, план 241) «Edit this page» — только для guide-страниц (источник
`docs/guide/`, правки welcome). Страницы `/spec/` и `/decisions/` — «Source
on GitHub» без приглашения редактировать: спека нормативна, изменения идут
через D-блоки решением владельца. «Open an issue» — везде.

## community-channels {#community-channels}
(2026-08-02) До v0.1 канал сообщества — GitHub Discussions/Issues (в футере).
Discord не заводить (пустой сервер у pre-alpha хуже отсутствия).

## blog-is-history {#blog-is-history}
(2026-08-02, из задания site-agent) Опубликованные блог-посты — летопись: код
и формулировки в них не актуализируем. Новые посты пишутся в актуальных
идиомах.

## plans-home {#plans-home}
(2026-08-02, находка владельца) Планы по сайту живут в репе **www**:
`plans/NN-*.md` (01…06; префикс `www-` снят переименованием 2026-08-02,
слово владельца). Новые сайтовые планы записывать туда с нумерацией `NN`,
статус — строкой в самом файле (как в nova). Бывший nova-план 241 (подвал
контент-страниц) перенесён туда как `06-docs-footer.md`; исторические
упоминания «план 241» и «www-06» = этот файл.

## acceptance {#acceptance}
(стоячее) Приёмка любой сдачи: `npm run build` (включая check-links) +
`npm run check` + `npm run check:highlight` — все зелёные; en/ru синхронны;
[#release-neutrality](#release-neutrality); [#docs-guide-only](#docs-guide-only)
(«dev не утёк»); `dist/` не коммитится. Ветка исполнителя — только своя
(`p-<задача>`); мерж в main сайта и пуш зеркал — за интегратором или по его
явному слову.
