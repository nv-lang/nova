## 0. Одна фраза

Написать `scripts/tools/queue-snapshot.py` — скрипт, который ВЫВОДИТ очередь
работ командами и кладёт ответ в `target/queue.json`, чтобы Stop-хук из того же
плана мог машинно отличить «работа кончилась» от «окно замолчало».

## 1. Зачем это существует (без этого ты напишешь не то)

Владелец 2026-09-18: «работа по плану постоянно останавливается и в
интеграторе, и в Карине; `/flow` не помогает, `/push-controller` сам иногда
останавливается, `/goal` не помогает — как решить раз и навсегда». Замер по
одиннадцати стенограммам проекта: 1104 конца хода, из них с объявленным
следующим шагом 7, заблокировано прежним хуком 5. Один процент.

Корень не в командах, а в том, что **очередь выводится, а не ведётся** (решение
2026-08-10, и оно правильное: рукописная таблица расходилась молча и была вторым
домом правды). Но у выводимой очереди есть следствие, которого никто не сделал:
**в момент конца хода её не существует как факта**, поэтому ни одна машина не
может ответить «осталась ли работа», и любой страж остаётся судить текст.
`/flow`, `/goal`, `/push-controller` — всё это текст, который читает то самое
окно, чью остановку он должен предотвратить.

План 292 переворачивает умолчание: продолжение не требует ничего, **остановка
требует машинно проверяемой причины**. Твой скрипт — то, чем эта причина
проверяется. Он не заводит второй дом правды: он КЭШИРУЕТ ответ команд, которые
и так прописаны в записке интегратора.

Полный план: [`docs/plans/292-stop-requires-proof.md`](../../plans/292-stop-requires-proof.md)
— прочти Ш.2 целиком и раздел «Слово интегратора» (условия И.1–И.3). Они
нормативны, этот бриф их не заменяет.

## 5. Контракт файла `target/queue.json` — это ДОГОВОР с хуком, не пожелание

```json
{ "role": "integrator|carina|controller|none",
  "at": "2026-09-18T22:40:00+03:00",
  "produced_by": "python scripts/tools/queue-snapshot.py .",
  "ok": true,
  "failed_sources": [],
  "open": ["слить ветку research/regex-nlib-0917", "№1157 — образец со строчным именем"],
  "sources": {
    "mirrors_behind": { "value": 0,    "cmd": "git ls-remote --heads gitverse main" },
    "unmerged_branches": { "value": 2, "cmd": "git branch --no-merged main" },
    "blockers": { "value": 74,         "cmd": "python scripts/guards/registry-routes-scan.py ." } }
}
```

Что хук делает с этими полями (прочти `check_queue` в
`scripts/claude-hooks/guard-stop-v2.py` — он уже написан и это его реальное
поведение, а не намерение):

| поле | как читается хуком |
|---|---|
| файла нет / старше 30 мин | БЛОК с требованием обновить: окно чинит это само, одной командой |
| `ok: false` | ПРОПУСК + запись побега в `target/.stop-guard/escapes.log` с именами из `failed_sources` |
| `role: "none"` | код `очередь-пуста` считается законным без проверок |
| `open` непуст | БЛОК с перечислением до пяти пунктов |
| `open` пуст при `ok: true` | ПРОПУСК — остановка доказана |

**Три условия интегратора, каждое обязательно:**

* **И.1 — снимок цитируется источником, а не собой.** Он живёт вне git
  (`target/` уже под `.gitignore`), несёт `produced_by` и `at`, и у КАЖДОГО
  источника стоит `cmd` — **дословная команда**, которой получено значение.
  Смысл: читатель не верит автору, а повторяет команду и получает то же.
* **И.2 — на снимок не опирается ни одно решение.** Он открывает ворота
  Stop-хука и ничего больше: не закрывает строку реестра, не двигает базу, не
  выбирает следующий шаг.
* **И.3 — отказ снимка не имеет права выглядеть пустой очередью.** Недостижимое
  зеркало, не ответивший `git` — это `ok: false` плюс `failed_sources`, и
  НИКОГДА не пустой `open`. Пустой `open` при мёртвом источнике превращает хук в
  разрешение молчать, и это невидимо.

## 6. Источники: бери готовое, НЕ пиши свой счётчик

Команды — из записки интегратора, раздел «Очередь — СПРАШИВАЕТСЯ, а не ведётся»
(`docs/dev/prompts/integrator-handoff.md`). Прочти его целиком: там два урока,
купленных ошибками, и оба про этот скрипт.

1. **Три зеркала, а не одно.** `git ls-remote --heads <remote> main` для
   `origin`, `gitverse`, `sourcecraft`; зеркала сравниваются между собой.
   `git rev-list --count origin/main..main` когда-то ответил 0, тогда как два
   других зеркала отставали на 70 коммитов.
2. **Блокеры считает ТОЛЬКО `python scripts/guards/registry-routes-scan.py .`**
   — это ядро стража `check-registry-routes`, печатает `blockers=N` и список
   номеров. Самодельный счёт реестра уже дважды дал неверное число (греп — 75,
   самодельное правило — 47, верное — своё). **Третий счётчик даст третье
   число, и спор о готовности пойдёт про арифметику вместо кода.** Зови скрипт
   и разбирай его вывод.
3. **Несли́тые ветки:** `git branch --no-merged main`.
4. **Гейт в источники НЕ входит:** он идёт сорок минут, снимком не снимается, а
   записанный вчерашний вердикт — тот самый протухший кэш, ради борьбы с которым
   очередь и перестали вести руками.

**Замеры (2026-09-18, эта же машина), чтобы ты не изобретал бюджет:**
`registry-routes-scan.py .` — 0,48 с; `ls-remote` — gitverse 0,7 с, origin
1,4 с, **sourcecraft 9,8 с**. Последовательно ~12 с. Поэтому: **источники
опрашиваются ПАРАЛЛЕЛЬНО, таймаут на источник 15 с, общий бюджет ≤ 15 с.**

**Урок, купленный на тех же замерах, и он прямо про твой код:** первая попытка
измерить три зеркала показала отказ всех трёх — на деле в Git Bash нет
`/usr/bin/time -f`, и падала ИЗМЕРЯЛКА, а не зеркала. Твой скрипт обязан
различать «команда запустилась и вернула ошибку» (отказ источника → в
`failed_sources`) и «команду не удалось запустить вовсе» (дефект скрипта или
среды → тоже `ok: false`, но с ЯВНО другой формулировкой). Одинаковая запись
для двух разных бед делает лог бесполезным ровно тогда, когда он нужен.

## 7. Что такое `open` — правило вывода, а не твой вкус

`open` СОБИРАЕТСЯ из `sources`, руками не пишется:

* `mirrors_behind > 0` → пункт «запушить на зеркала: <имена>»;
* каждая несли́тая ветка → пункт «слить ветку <имя>»;
* ~~каждый номер из `blockers_list` → пункт «№<N> — <начало заголовка строки>»~~.

> **ОТМЕНЕНО 2026-09-18 вердиктом интегратора, сверено по плану 274 (окно `nova-90`).**
> `blockers` в `open` НЕ ИДЁТ. Поле `БЛОКИРУЕТ ТЕГ` осталось от мёртвого события — тега
> ОРАКУЛА, которого не будет (274, строки 46–50); замены источника не будет вовсе, смысл
> поля «перечитывается как „блокирует релиз Карины“ при работе со строкой, а не сплошной
> заменой» (274, ~4963). Как ХРАПОВИК счёт законен и остаётся в `sources` со своей
> командой; как ОЧЕРЕДЬ он лжив — «73 открытых пункта» прочтётся как работа, которой нет.
> Правило сборки теперь держится клеткой самотеста, а не только текстом.

Пустой `open` при непустых `sources` — **ошибка скрипта, а не пустая очередь**;
такой случай обязан давать `ok: false`.

**Очередь выводится только для роли `integrator`, и это признано в плане.** У
Карины и контролёра в их записках раздела про очередь НЕТ, вывести её не из
чего. Не выдумывай: для `carina` и `controller` пиши
`ok: false` и `failed_sources: ["очередь роли <X> не выводится: источник не
назван"]`. Хук такое окно пропустит и запишет побег — это честно, а побег
каждый день в логе есть то давление, которое заставит источник назвать. **В
отчёте спроси владельца/интегратора прямо:** чем является очередь Карины
машинно — открытые строки реестра с её меткой, шаги её плана, что-то третье.

Роль определяется так же, как её определяет хук (см. `detect_role`):
`NOVA_WINDOW_ROLE`, иначе ветка — `main` → integrator, `p274-novac` → carina,
ветка со словом `controller` → controller, иначе `none`.

2. Напиши `scripts/tools/queue-snapshot.py`. Вход: путь к дереву (по умолчанию
   `.`). Выход: `target/queue.json` по контракту §5 + строка в stdout с итогом
   (роль, `ok`, число пунктов, время работы).
3. Напиши самотест `scripts/tools/selftest/test-queue-snapshot.py` рядом с
   образцом `scripts/claude-hooks/selftest/test-guard-stop-v2.py` — он показывает
   форму: клетки парами, и в каждой паре одна ждёт отказа, другая — успеха.
   Обязательные клетки:
   - недостижимый источник (подставь несуществующий remote) → `ok: false`,
     имя источника в `failed_sources`, `open` НЕ пустой-и-ok;
   - незапускаемая команда (подставь несуществующий исполняемый файл) → тоже
     `ok: false`, но формулировка ЯВНО другая;
   - роль `carina` → `ok: false` с названной причиной, а не пустая очередь;
   - два прогона подряд дают одинаковое содержимое (кроме `at`);
   - пункты `open` собраны из всех трёх источников, а не из одного.
4. **Сшивка с хуком — обязательный шаг, без него работа не принята.** Сними
   настоящий снимок и прогони по нему хук: с непустым `open` конец хода с
   «СТОП: очередь-пуста» должен БЛОКИРОВАТЬСЯ, с пустым и `ok: true` —
   проходить, с `ok: false` — проходить и оставлять запись в
   `target/.stop-guard/escapes.log`.
5. Прогони самотест хука: `python scripts/claude-hooks/selftest/test-guard-stop-v2.py`
   — должно остаться **PASS 22 FAIL 0**.
6. Обнови в плане 292 Ш.2: отметь сделанное, впиши ИЗМЕРЕННОЕ время работы
   снимка, впиши расхождения из шага 1. Планы правятся вместе с кодом, не после.
7. Коммит по правилам §2, потом отчёт.
