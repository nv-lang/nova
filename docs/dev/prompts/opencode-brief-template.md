# Шаблон задания для opencode (механический исполнитель)

**Требование владельца 2026-08-08:** «используй opencode для задач агентам там, где
это возможно; для механического исполнителя нужны очень точные команды, точный путь
внутри проекта, явный список запретов и образец строки результата».

Этот файл — **шаблон, а не памятка**: копируй его целиком и заполняй, вместо того
чтобы каждый раз сочинять бриф заново. Два первых задания провалились именно
потому, что бриф сочинялся на ходу.

## Что opencode тянет, а что нет

**ТЯНЕТ:** перечисления, сверки, сборка таблицы фактов из кода, механические
замены по точному списку, отчёты «где что лежит». Проверено: читает файлы,
пишет файл, выходит с нулём.

**НЕ ТЯНЕТ (не давать):** классификацию с поиском эквивалента, суждение
«баг это или норма», проектирование, приёмку. Это к sonnet/opus.

## Ограничения среды — знать до написания брифа

1. **Запись ЗА пределы каталога проекта БЛОКИРУЕТСЯ** его системой разрешений
   (`permission requested: external_directory` → отказ). Путь результата ОБЯЗАН
   быть внутри репозитория. Первое задание провалилось ровно на этом: я дал путь
   в `%TEMP%`.
2. **Свои временные файлы он тоже пишет вовне** — если задача требует
   промежуточного файла, задание провалится. Формулируй так, чтобы промежуточных
   файлов не требовалось («держи в памяти», «пиши сразу в итоговый файл»).
3. **Сбрасывает рабочий каталог** в корень проекта (`Shell cwd was reset to …`).
4. Вызов: `opencode run "<текст>"`; есть `-m provider/model`, `--agent`,
   `-c/--continue`. Исполняемый файл — `opencode.exe` в npm-каталоге
   (обёртка в PATH ломалась о кириллицу в пути).

## Приёмка результата opencode

Как у любого окна: **интегратор проверяет сам**. Отчёт-перечисление — сырьё,
не вердикт. Классификацию по нему делает человек. Если в файле появились
выводы или рекомендации — это признак, что бриф был сформулирован нечётко.

## Готовый рабочий каталог — `scratch-opencode/`

Не выдумывай путь для логов и не проси `/tmp`: в корне проекта уже есть
`scratch-opencode/` (содержимое под `.gitignore`, сам каталог существует). Все
промежуточные файлы направляй туда:

```
cd d:/Sources/nv-lang/nova && <команда> > scratch-opencode/step1.log 2>&1
echo "RC=$?"
```

Это и есть ответ на `permission requested: external_directory` — не ослаблять
защиту opencode, а не давать бриф, которому внешний путь нужен.

### Два наблюдения о самом запуске (2026-08-09, проверено)

* **Прогон не завершается сам вовремя.** Проба записала файл за секунды, но
  процесс не вышел и за пять минут. Запускай opencode с таймаутом и проверяй
  результат **по артефактам в `scratch-opencode/`**, а не по коду возврата
  команды и не по ожиданию её выхода.
* **Однажды обёртка упала так:** путь до `opencode.exe` потерял кириллическое
  имя пользователя и превратился в `C:\Users\` + `/node_modules/...`. Гипотеза
  про `LC_ALL=C` **проверена и не подтвердилась** (`HOME` под ним разрешается
  верно), причина не установлена. Записано как наблюдение, не как диагноз: если
  повторится — смотреть на обёртку `npm`, а не на локаль.
