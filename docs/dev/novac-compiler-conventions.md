# Конвенция компилятора `novac`

**Нормативный документ.** Как ПИСАТЬ код `novac/**`. Имя и место выбраны владельцем
2026-08-14 (274 §10.5): предмет в имени; старая
[compiler-conventions.md](compiler-conventions.md) остаётся адресом своего предмета,
пока жив нынешний компилятор.

**Чем этот документ отличается от предшественника — способом, не содержанием.**
Содержание — оплаченные уроки старой конвенции и реестра; но здесь **правило без
стража в документ не попадает** (№636: правило прозой не действует). У каждого правила
строка «Страж:» — имя механизма и его статус. Статусы — как в сводном аудите
[274 §10.3а](../plans/274-novac-self-hosted-compiler.md): ✅ в гейте · 🕐 этап, ДО кода,
которому подсуден (Э1-каркас не принимается без своего набора) · ⚖ суждение приёмки,
честно.

Общие конвенции проекта (`nv-coding-style`, `naming-conventions`, `module-conventions`,
`test-conventions`) действуют как есть и здесь не дублируются.

## П1. Один источник истины; потребители читают, не перевычисляют

Тип, резолв, подстановка вычисляются ОДИН раз своей дверью (`check` → `sem`); всякий,
кому нужен факт, читает таблицу. Перевывод чужого факта — дефект, даже если даёт тот же
ответ сегодня (завтра разойдётся молча — весь план 196 был демонтажом этого).
**Страж:** `check-novac-deps.sh` — рёбра и «что течёт»; `sem` пишет только `check`. 🕐 Э1.

## П2. Идентичность — не имя

Имя — ключ ровно в одной двери (`names`); дальше только `DeclId`/`NodeId`
(архитектура §4а; носители класса — №576, B11q, №534, №617).
**Страж:** `check-novac-no-string-keys.sh`. 🕐 Э1.

## П3. Порядок проходов живёт в одном месте

Фазы зовёт только `pipeline`; факт не используется до готовности его производителя
(фаза-корректность старой конвенции, урок LSP с десятью проходами по именам).
**Страж:** `check-novac-deps.sh` — ни у кого, кроме `pipeline`, нет рёбер к фазам как
к исполняемым шагам. 🕐 Э1.

## П4. Отравление вместо пермиссивности; никаких молчаливых fallback-типов

Ошибка помечает узел; правило одно: «уже репортнуто — молчи». Пермиссивный
unknown, глотающий настоящие ошибки, запрещён — цена измерена (№652:
`fn f() -> int { "str" }` и `if 5` проходят нынешний check зелёным). Auto-выведенный
неверный тип «чтобы собралось» — дефект, не сервис.
**Страж:** `check-novac-no-cascade.sh` (опечатка → ровно один диагностик) +
`check-novac-diag-schema.sh` (`poisoned_by` обязателен у вторичных). 🕐 Э1.

## П5. Никакого хардкода имён Nova в компиляторе

Методы, типы, операции — из деклараций (`.nv` / декларированные интринсики);
захардкоженное имя `to_str`/`Vec`/`equal` в коде компилятора — дефект (уроки D109,
№576; легитимный остаток — только то, чего в декларациях нет, и он перечислен явно).
Интринсик обязан декларировать свою репрезентацию — тип и эмит не расходятся (урок D77).
**Страж:** `check-novac-no-name-hardcode.sh` — греп строковых литералов с именами
языка/std вне таблиц деклараций. 🕐 Э2 (в Э1-подмножестве builtin-список мал и
перечислен в одном файле). Добавлен в 274 §10.3.

## П6. Никаких тихих дыр

`_ => return`/пустая ветка без диагностики или маркера — дефект. Непокрытая форма
callee — ранняя диагностика, не поздний ICE (уроки B11al/B12q/r/s).
**Страж:** общий `check-marker-registry-sync.sh` (маркер без записи в реестре) ✅ +
`check-novac-no-panic.sh` (ICE ловится фаззингом). 🕐 Э1.

## П7. Расхождение с оракулом — только через реестр

Поведение видимо → любое отличие от нынешнего компилятора несёт запись в
`novac-divergences.md` (корзина + номер/D-блок). Молчаливое расширение или сужение
языка запрещено — включая «у нас случайно заработало» (bootstrap §6: реализация не
закрывает открытые вопросы).
**Страж:** `check-novac-differential.sh` — расхождение вне реестра красное. 🕐 Э1.

## П8. Снос легаси — только NO-HIT

Удалять ветку/функцию можно после трейс-доказательства недостижимости на корпусе
(методология D182; мета-урок Wave-1: демонтаж ветками без трейса дал 0 снесённых и
откаты по первому репро).
**Страж:** ⚖ — суждение приёмки с обязательным трейсом в тексте слияния; машинного
критерия «доказательство приложено» нет, и это сказано честно.

## П9. Файл ≤ 1000 строк; модуль = одна ответственность

Жёстко с первого коммита (274 §10.4: легаси нет — лимит стоит ноль).
**Страж:** `check-novac-file-size.sh`. 🕐 Э1.

## П10. Фикстура на каждый фикс; баг в реестр — минимизированным

Закрытый дефект оставляет красневшую фикстуру навсегда; запись в реестр несёт
минимальное репро (авто-редьюсером, когда он есть).
**Страж:** общий `check-test-fixture-coverage.sh` ✅ (после №639 понимает обе формы);
`check-novac-repro-min.sh` 🕐 Э2.

## П11. Инварианты считаются и минимизируются конструкцией

Каждый раздел карты несёт счётчик; новый инвариант в коде — через
`conventions-governance` («как можно меньше, и ни одного на честном слове»).
**Страж:** `check-novac-arch-invariants.sh` ✅ в гейте + общий
`check-invariant-discipline.sh` ✅.

## Что сознательно НЕ правило

Стиль, длина функций, форма комментариев сверх общих конвенций — не нормируется:
правило, которое нечем держать и незачем, разжижает документ. Список правил растёт
только вместе со стражами.

## П12. Внутренние инварианты: одна дверь `ice()`, паника — транспорт до супервизора

Выработано 2026-08-14 разбором эталонов по вопросам владельца (полный разбор —
ревью Э1; сюда перенесена вечная часть, wip-файл смертен).

**Как у эталонов.** rustc: голый `panic!` в исходнике запрещён внутренним
линтом; двери `bug!`/`span_bug!` дают ICE с привязкой к месту, а
`span_delayed_bug` откладывает ICE и гасит его, если компиляция уже выдала
настоящую ошибку — это убивает класс «ICE на сломанном вводе». Roslyn:
внутренняя ошибка наружу выходит ДИАГНОСТИКОЙ «internal compiler error»,
процесс цел. Go: `base.Fatalf` — всегда именованная дверь. LLVM/Clang —
антиобразец для цели «стабильность»: release без ассертов превращает
`llvm_unreachable` в UB (мискомпиляция вместо краха); у Clang берём другое —
crash-репродьюсер (родня методики автоминимизации, план 274 §12.3).

**Три факта Nova, на которых стоит правило** (поправки владельца 2026-08-14):
assert/контракты/границы работают И В РЕЛИЗЕ — «debug-яруса» не существует,
анти-LLVM позиция встроена в сам язык; `?? panic(...)` — по сути assert;
паника ЛОВИТСЯ на выходе из файбера в супервизоре — граница рендера, которую
rustc делает catch_unwind'ом драйвера, у нас есть в языке.

**Правило.**

1. Голый `panic(` в `novac/src` — под страж (`check-novac-no-naked-panic`,
   завести вместе с этим правилом): явный инвариант идёт через одну дверь
   `ice(...)`/`ice_at(span, ...)` в `diag` — с местом и по схеме §7
   (`E_NOVAC_ICE`, machine-first, «это баг компилятора, не вашего кода»),
   а не строкой свободной формы.
2. Рендер границы — двумя ступенями. Э1 (сейчас): дверь `ice()` печатает
   §7-JSON САМА и лишь затем умирает по правилу языка (panic = смерть
   файбера) — машинный читатель получает структурную строку даже на баге
   компилятора. Полный Roslyn-паттерн — рендер ДОЛЕТЕВШЕЙ паники (в т.ч.
   assert/контракта из глубины) на границе — включается, когда компиляция
   переезжает в дочерний файбер (шов драйвера, Э2+): механизм готов, это
   эффект `Supervisor` (D416, `std/concurrency/supervisor`), спека выправлена
   2026-08-14 («свой panic fiber не ловит; родитель его супервизирует»).
3. `delayed_ice` по образцу rustc — с Э2, когда чекер держит инварианты
   поверх Err-узлов: сломанный инвариант при уже выданной пользовательской
   ошибке гасится; при чистой компиляции — стреляет.
4. Языковая защита (assert/контракты/границы) не выключается никаким
   профилем сборки novac — и это не настройка, а определение цели
   «стабильность прежде скорости».
