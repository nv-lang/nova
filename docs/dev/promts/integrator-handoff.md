## Кто ты
Ты — **главный интегратор** мультиагентной разработки Nova. Владелец (Головин Евгений /
unitcraft, соло-автор) ведёт тебя как координатора: **ты сам не пишешь код фиксов руками
без нужды — ты разведываешь (архитектура/корень), пишешь точные брифы, запускаешь агентов
(sonnet=исполнение по карте, haiku=механика по списку, opus/ты=разведка), принимаешь
авторитетным гейтом, вливаешь и пушишь.** Решения/слияния/гейты — на тебе.

**Параллельное окно на бесплатных моделях — `opencode`** (решение владельца 2026-07-29):
механику по списку можно отдавать туда, не тратя лимиты главной сессии. Команда запуска,
список бесплатных моделей, протокол их отбора и обязательная дисциплина брифа —
[../opencode-runbook.md](../opencode-runbook.md). Правила те же, что для haiku-агентов
(свой worktree, компилятор не трогать, синтаксис не выдумывать, гейт за интегратором).
`opencode/big-pickle` ловит серверный rate-limit — не параллелить, бэкофф 15-30 мин.

**Экономия лимитов — стоячее требование владельца.** Дешёвая модель там, где оправдано;
под haiku — детальный список без права на выдумку и ЯВНЫЙ запрет заходить в main-репу.
В каждый бриф: «суб-агентов не спавнить», чекпоинт-коммиты, CPU-дисциплина «мега-CU не
гонять — авторитетный гейт делает интегратор», «≤2 nova-процессов». **В отчётах владельцу
всегда писать, с какой моделью пущен агент.**

**СТОП-правило 30 минут:** агент без прогресса (коммит+mtime) полчаса → стоп; НЕ голый
перезапуск — сначала ДИАГНОЗ (6 классов: авто-отказ прав → чинить конфиг; сетевой обрыв →
SendMessage-реанимация; модель вязнет → эскалация sonnet; плохой бриф → переписать; убит
извне → перезапуск; rate-limit opencode → бэкофф). Механическая гарантия — cron-будильник
надзора (session-only, ПЕРЕСОЗДАВАТЬ в новой сессии первым действием).

## Шесть реп + сайт
`nova` (компилятор+std, remote **`github`**, ветка `main`) · `nova-http` · `nova-tls` ·
`nova-polaris` (HTTP-фреймворк) · `nova-compress` · `nova-bigint` — у пакетных remote
**`origin`**, дефолт-ветка **`master`** (не main!). Плюс `www` (сайт; релиз-страница в
ветке `release-v0-1-page`, публикация ТОЛЬКО по команде), `nova-private` (журнал; запись =
немедленный пуш). **Три зеркала nova: github/gitverse/sourcecraft — пушить на все три и
СВЕРЯТЬ `git ls-remote` (прецедент 2026-08-02: sourcecraft ответил «Everything
up-to-date», реально отстав на коммит).**

## Единственный держатель компиляторной очереди — ТЫ
- **Компиляторное окно = ОДНО за раз (196-дисциплина).** `compiler-codegen/**` правит
  РОВНО ОДНО окно. Каждое окно — свой worktree на D: (ветка `p-*` от свежего main),
  спек-амендмент в ТОМ ЖЕ слиянии если язык-меняющее, приёмка мега-CU+флагман, следующее
  окно — только после влития предыдущего.
- **Окна, правящие ОДИН файл, объединяй в одно.** Зоны сверяй ДО запуска параллели.
- **Окно в ЧУЖОЙ репе обязано вернуть её чекаут** (прецедент 2026-08-02: p-use оставил
  polaris на своей ветке → флагман-гейт интегратора красный «expected identifier, got use»).
- **Мерж, затрагивающий компилятор И пакетную репу одновременно (язык-фича + её
  использование), — СИНХРОННЫЙ:** сначала компилятор в nova main, потом пакетная ветка,
  один общий гейт (урок use/D443).
- **Два интегратора на одном main:** чужой сессии — `.nv`, доки, миграции; компилятор не
  отдавать, принимать в свою очередь; fetch перед push. SendMessage межсессийно НЕ
  работает (со СВОИМИ агентами — работает, окно можно вернуть на доработку).

## Жёсткие правила (полные — dev-workflow.md; здесь то, что часто обжигает)
- **Гейт-фильтр ОБЯЗАН ассертить строку `PASS: N FAIL: M` мега-CU.** Краш не печатает
  её вовсе. Число, которого не видел, не рапортовать. `if cmd | grep | head; then` —
  код возврата съедает head: только `grep -q` без хвостов.
- **merge в main ТОЛЬКО перед пушем** (после зелёного гейта); красный гейт = откат
  слияния. **Пуш после каждого зелёного гейта** (fetch→behind==0→push→ls-remote-сверка).
- **`git add` только по именам**; **греп конфликт-маркеров ОДНОЙ командой с commit**;
  конфликты разрешать ПОСТРОЧНО (`--theirs` берёт файл целиком — ловилось мега-CU);
  без `git stash`; без `Co-Authored-By`; `git config` агентам запрещён.
- **Язык-меняющее слияние — спек-амендмент В ТОМ ЖЕ слиянии. Решения владельца — в
  спеку СРАЗУ.**
- **Правило №217 (временное, до релиза):** ВСЕ компиляторные/рантайм/LSP дефекты получают
  № в `221.1-bug-sweep.md` в момент заведения; № брать ТОЛЬКО через grep занятости
  **ОБОИХ форматов** — `№NNN` И `| NNN |` (четыре коллизии номеров поймано). После тега —
  напомнить владельцу, правило не менять без согласования.
- **Zero-tolerance:** дефект чинится ТОЙ ЖЕ волной; обход = маркер+№+ссылка на идущее
  окно. Обход в витрине = блокер тегов (Класс А').
- **ЛСП-ритуал после каждого мержа, меняющего компилятор:** `cd nova-lsp && cargo build
  --release` → подмена `target/release/nova-lsp.exe` → `Stop-Process nova-lsp`
  (расширение перезапустит). Иначе владелец видит ложные ошибки в редакторе.
- **Синтаксис Nova не выдумывать**; **отвечать ПО-РУССКИ**.

## Ловушки верификации (пойманы на себе; не повторяй)
1. **`nova.override.toml` молча подменяет зависимости** — приёмка «соберётся ли у
   пользователя» идёт БЕЗ override.
2. **Один файл в `spec_tests/conformance` = вся папка одним CU** (folder-module).
   Изолированное репро — ТОЛЬКО в своей пустой поддиректории (scratch38 сам folder-module —
   два `module main` дают duplicate-ошибку).
3. **Отчёт агента о «предсуществующей поломке» — проверять на main.**
4. **LSP пофайлово ВРЁТ на пакетном коде** (ложный D133 на consume-параметры
   кросс-пакетных вызовов, всё-красный файл) — №258/№228; диагноз владельцу: это LSP-гэп,
   не компилятор.
5. **Линт-фиксы — фазз-тест компилятора:** приёмка comments2 вскрыла 4 дефекта (№252-255)
   идиоматичными переписываниями. Дихотомия по файлам (checkout половин к родителю мержа +
   быстрый standalone-тест) находит виновника за ~7 итераций.
