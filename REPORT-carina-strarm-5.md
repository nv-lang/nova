# Отчёт облачной сессии, пятый заход: ветка `p274-carina-strarm`, №1573 и №1576

База — `c12589a61` (влит `origin/integrate` `bacdefa12`). Строк №1573 и №1576 нет ни в
одной ветке origin, и `5819038e6` (исправление spec-queue в main) там тоже нет. Работала по
описанию из вашего сообщения. Мера считается от 115 /

№1573 — ЗАКРЫТ. Носитель: `types/types.nv:152`, `@args[row.arg_off..row.arg_off +
want.len()] == want` в `Interner @args_equal` — закрытый срез `[]TyId`, сравниваемый с
`[]TyId`. Не хватало двух половин:
- оболочка не несла `index(Range)` для Vec[int] (отказ в мере 0.2);
- `==` уходил в `equal` только для `str`. На векторе дверь протокола отказывала, а если бы
  пропустила, напечатала бы C-шный `==` двух указателей `Nova_Vec*`.

Что сделано:
- проба оболочки получила `slice_eq_probe` — срез `[]int`, сравниваемый через `==`, форма
  носителя. Оракул стирает новый тип `TyId` до `nova_int`, поэтому один экземпляр Vec[int]
  обслуживает оба. Оболочка перегенерирована `novac-regen-shell.sh`: в ней теперь есть
  `Vec____nova_int_method_index__NovaValue_Range` и `Vec____nova_int_method_equal`.
  Остальной дифф `shell.tpl.c` — перенумерация временных переменных оракула; страж свежести
  подтверждает: шаблон == эмиссия оракула;
- `check/operators.nv`: `==`/`!=` над двумя векторами ОДНОГО типа допускаются и идут в
  `equal` через `@record_operator_callee`. Признак вектора (`@is_vec_inst`) — тот же
  признак головы, что у образца-массива. Наличие символа в оболочке проверяется через
  `c_method_symbol`: он одинаково пишет имя и экземпляра, и примитива. Три текста отказа
  больше не говорят «`==` on `str`»;
- `emit_c/emit_expr.nv`: имя вызываемого печатается через `c_method_symbol`.

Фикстура `slice_eq/pos_1` — байт-в-байт. В ней: срез с элементами-новым-типом (равно, не
равно, разная длина, пустой) и `[]int` с `!=`. Проба в обе стороны: при `vec_eq`,
принудительно ложном, фикстура красная (отказ протокола); после восстановления зелёная.
Дым по всем `pos_*` после перегенерации оболочки — 85/85 байт-в-байт. Модульный тест
`pipeline/slice_eq_test` (новый файл: `subset_test.nv` стоял на 999 строках): срез
сравнивается через `equal`; контроль — сравнение `int` остаётся операцией C. Утверждение
привязано к имени параметра `zq`, которого в оболочке нет: сама оболочка содержит вызовы
`..._method_equal`.

Мера 0.2: 115 -> 113. Ушли оба отказа «carries no `index(Range)`», новых нет.

Догоняющий коммит закрыл два стража раннера:
- `emission-size`: каждая эмиссия +99 строк — это выросшая оболочка; база поднята со
  строкой хроники;
- `import-exists`: импорты `c_shell_method` в `check/exprs.nv` и `check/typing.nv` больше
  не нужны и сняты /

№1576 — ЗАКРЫТ. Класс №1563 во второй позиции. Вызов, опускающий слот, печатает
значение по умолчанию на месте вызова (D102), то есть в компилируемом файле. А у
переданной функции `default_expr` был узлом ПЕРЕДАННОГО дерева, и читатели литерала
спрашивали канал по id чужого пространства. Замер: строковое умолчание у переданного
файла, который больше программы, — ICE «array: index 421 out of bounds for length 6». Если
файл меньше, читался любой узел программы с тем же номером.

Носители есть в самом исходнике Карины:
- `Cursor @peek(skip int = 0)` (`parse.nv`), вызывается из `expr.nv`;
- `FieldTable @add(…, ro_view bool = false)`.

Что сделано:
- `sem/harvest.nv` `handed_default`: литерал пересобирается без id через `handed_literal`
  (дверь №1518: числа, в том числе отрицательные, строки, символы), `true`/`false` — как
  `Name` без id. Любая другая форма умолчания сохраняет узел. В исходнике Карины таких нет,
  и это записано в doc;
- `emit_c/emit_expr.nv`: `Name` без id печатает булев литерал напрямую, всё прочее там —
  ICE с именем. До этой правки поиск захвата индексировал `-1` (второй замеренный ICE);
- `emit_c/emit_args.nv` (новый) — `emit_expr.nv` дорос до 1003 строк, и аргументы вызова
  вынесены по смыслу без изменений.

Байт-в-байт фикстура для этого случая невозможна: нужны два файла одного модуля, а дым
передаёт один. Ячейка — модульный тест `pipeline/handed_free_test`: модуль программы
больше вызывающего, умолчания `"dflt"`, `false`, `-3` печатаются литералами; контроль —
записанные слоты печатаются как записаны. Проба в обе стороны: если `harvest` снова читает
сырой слот, тест красный с замеренным ICE (`index 421`); после восстановления зелёный.
