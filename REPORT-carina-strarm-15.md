## 5a. Образцы

`_` НАД MUST-CONSUME. Норма нашлась — **D461 (Б)** («`_`-имя нельзя использовать; линейное значение нельзя
выбросить», 03-syntax.md:12911): «Линейное (`consume`) значение нельзя выбросить `_`-паттерном» — ошибка
компилятора. Своего кода спека правилу не даёт: `E_LINEAR_PAYLOAD_DISCARDED` — имя оракула. Строка реестра №674
закрыта под этим блоком. Попутно — таблица D133: `let _ = tx` → `D133-suppress-not-allowed`.

Карина: `E_NOVAC_LANG` со ссылкой «D461 (B)». Суд — в типизации, в ветке `Wild` (`match_arms.nv` →
`@judge_wildcard`). Корень плеча `match` выбросом не считается: он ловит то, что оставили плечи выше
(`Some(consume t) => …, _ => …` видит только `None`), — ровно как читает оракул (проба) /

ДЕСТРУКТУРИЗАЦИЯ: `consume (x, y) = e` — части must-consume, свои под словом `consume` привязки; `ro`/`mut` —
`E_CONSUME_KEYWORD_MISSING`. Запись, объявленная `consume`, разбирается своим `consume`-методом (D133:
`@into_parts`). Образец над ней остаётся отказом со сроком; оракул на этой форме сам даёт ложный
`D133-not-consumed` по `int`-части.

Попутно: значение из нескольких частей в переносимой позиции уносит свои must-consume части. Это строка таблицы
D133 «`(a, b)` в позиции возврата». Сделано без нового вида в коде: слово «кортеж» — согласование владельца /

ОБРАЗЕЦ ЦИКЛА:
- `for consume t in v` потребляет `v` и владеет элементом на каждый проход (D156, collection-aware);
- `while Some(consume t) = e` владеет значением прохода (D432 §2, форма 2);
- оба — тела: судятся в его конце и на `break`/`continue`;
- простой `for t in v` — вид элемента.

Попутно: вызов метода `-> @` (D409) отвечает своим приёмником — место, не свежее значение. `v.push(x)`
оператором ничего не бросает /

`..base`: формы нет ни у одного компилятора — `Box { n: 3, ..b }` не разбирает и оракул («expected identifier,
got `..`»). Отказа «ради правила» не заводил /

## 5b. `@cleanup` (D432)

Тип must-consume с эффект-чистым `fn T consume @cleanup(o ScopeOutcome) -> ()` в файле — АФФИННЫЙ.

Его значение, связанное `consume x = e` (D432 §2: ровно эта форма) или `consume`-параметром (rev-2), можно не
потреблять: компилятор ставит вызов `@cleanup(Success)` там, где область покидается с ещё принадлежащим
значением:
- конец блока;
- `return` (после значения);
- `break`/`continue` (§6);
- внутреннее значение — первым.

Явно потреблённое не чистится повторно (§4).

Как сделано:
- **проход** решает места и пишет их в канал (`CleanupRow`, `cleanups`/`cleanup_at`, §10.3б/§10.3в плана 274);
- **понижение** кладёт `Stmt.Cleanup` (новый `lower/ir_cleanup.nv`). Возвращаемое значение идёт через
  временный: присваивание месту возврата печатается как сам `return`, а очистка обязана выполниться между ними.
  Это нашёл дым на первой же пробе — очистка стояла после `return`;
- **печать** — `<@cleanup>(<значение>, nova_make_ScopeOutcome_Success())`;
- **mono**: вызываемые очистками — корни достижимости, как неявные вызовы `wanted`. Тоже нашёл линковщик на
  первой пробе /

Отказ по имени со сроком, а не неверная очистка:
- значение, принадлежащее на ЧАСТИ путей (рантайм drop-флаг, §5);
- `@cleanup` с эффектами (их пропагация, амендмент §1 2026-08-04);
- конец `=>`-тела;
- расходящийся вызов (исход Panic).

Привязки образцов и части деструктуризации остаются строго линейными (§2, амендменты №667/№672) /
