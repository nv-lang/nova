# Отчёт облачной сессии: ветка `p274-carina-k1` (№1520, №1521)

База `8405e5fcd` (`origin/p274-carina-cloud`). Окружение: Linux, clang, `libgc-dev`;
оракул и Карина собрались без обходов.

**№1520 КОРЕНЬ:** вопрос «должно ли тело закончиться значением» задавался в ДВУХ местах, и
они расходились. Ходьба типизации (`value_body_of`; её проходят и тела файла, и каждый
экземпляр переданного тела) знала `-> @` (D409). Отказ ходьбы подмножества
(`@report_if_tail_has_no_value`, только тела файла) не знал. Итог: своё
`fn Ctr mut @reset() -> @ { @n = 0 }` получало ложный отказ «body ends without a value», а
такое же тело из std типизировалось как оператор. Эмиссионная половина строки (переданное
тело без `return`, segfault) на этой базе уже была закрыта шагом Э.10 4c-2/4d
(`Emitter.ret_self`, `da27aecc4`, позже базы охотника `e448f0193`).
/ **ФИКС:** `novac/src/check/tail_rules.nv` — `promises_tail_value`, один ответ на «должно ли
тело значение»; его спрашивают и `value_body_of`, и `@report_if_tail_has_no_value`. Для `-> @`
ответ «нет», то есть хвост, голый `return` и хвостовой `if` без `else` дают `return @`.
/ **ПРОБЫ:** `fluent-clear-alias` -> совпадало / совпадает; `fluent-clear-chain-f64` ->
совпадало / совпадает; `fluent-module-mark` -> совпадало / совпадает (все три закрыты
базой, не этой веткой); `ctl-fluent-own-refused` -> ложный отказ / `0` `0`, как оракул;
новые `fluent-handed-bare-return` (std `Vec @dedup`: голый `return` и выход с конца) ->
совпадало / совпадает; `fluent-module-bare-return` (модуль программы `Vec[T] @mark_if`) ->
совпадало / совпадает.
/ **ПРИЁМКА ПО ОГОВОРКЕ:** да, кроме правила 3 D409. D409 реализован одной дверью для своего и
переданного тела: хвост, голый `return` и ветви `if` дают `return @` и в проверке, и в
эмиссии; три пробы К1 печатают как оракул; `ctl-fluent-own-refused` компилируется и
печатает `0`/`0`; проба на голый `return` в переданном теле есть (две). **Осталось:**
правило 3 D409 — явный `@` в хвосте, `return @` и `=> @` оракул отвергает как
`E_EXPLICIT_SELF_RETURN`, а Карина принимает все три (проба
`explicit-self-return-accepted`, ниже в «ОТКРЫТО»). В оговорку строки это не входило. /

**ОТКРЫТО:**
1. **Новый дефект, К7, D409 правило 3.** Явный `@` в хвосте, `return @` и `=> @` в теле
   `-> @`: оракул отвергает все три как `E_EXPLICIT_SELF_RETURN`, Карина принимает и
   печатает `1 2 2`. Проба `docs/dev/hunts/novac/probes/2026-10-01-carina-k1/explicit-self-return-accepted/`.
   Место: судья тела `-> @` в `check/` — он же новая дверь `promises_tail_value`
   (`tail_rules.nv`). Чинится там же. Заметка: `pipeline_test.nv:921` даёт переданное тело
   `@push(v T) -> @ => @`; станет отказом, если его когда-нибудь инстанцируют.
2. **Новый дефект, класс «один вердикт о файле».** Тело экземпляра только типизируется
   (`check_instance` -> `type_fn`), обход подмножества и формы его не проходит.
   `ro s str = @len()` в `Vec[T] @bad` модуля программы Карина принимает и печатает `0`;
   оракул даёт E7301 на `geo.nv:4`. Та же строка в своём файле Карины — отказ «a declared
   local type is not compiled yet». Проба
   `docs/dev/hunts/novac/probes/2026-10-01-carina-k1/instance-skips-subset-walk/`. В
   самосборке тело модуля проверит его собственная единица, но `novac check main.nv`
   отвечает «чисто». Родня находки 6 охотника (`coalesce-instance-check-blind`).
3. **Ложный отказ, К2, D181.** Беглая `mut`-цепочка на временном значении:
   `c.reset().set_pos(4)` отвергается «parameter `@` needs a mutable place … (P14)», оракул
   принимает. Найдено при сборке фикстуры, в фикстуру не вошло. Проба не сохранена:
   `type Ctr { n int }`, два `-> @`-метода `mut`, вызов цепочкой.
4. **№1521 целиком** — см. вопрос 1.
5. **Оракул, возможный дефект.** `println(@len())` в теле
   `export fn Vec[T] mut @mark() -> @` модуля `hp.geo` оракул отвергает:
   `undefined identifier println` (`geo.nv:4:5`). Но `println` — прелюдия
   (07-modules.md, «Prelude — without import»). Проба охотника `diag-wrong-file-module`.
6. **Причина не установлена.** Почему у строк std-методов (`Vec @first`, `@clear`)
   `handed_from` пуст, хотя у файлов std есть строка `module collections.vec`: C-имя
   экземпляра берёт модуль файла (`novac_fn_hp_first__…`, `novac_fn_clear__…`). Это часть
   №1521 (C-имя), не разбиралась. /

**ВОПРОСЫ ИНТЕГРАТОРУ:**

**1. №1521: какой путь.** Сработала развилка задания, перестройку не начинал.

**Путь А — «экземпляр несёт модуль и файл, двери спрашивают» в нынешнем `Ctx`.**
- **А1, функции.** `sem/harvest.nv` (`harvest_fn`): одноимённую свободную функцию ДРУГОГО
  модуля регистрировать, а тень D125 оставить только для копии своего модуля.
  `resolve/resolve.nv`: видимость (`@sees`) проверять ДО `fits` в `@lookup`, `@only_row_of`
  и `@has_name`, строки `""` считать модулем файла. `check/run.nv`: `check_instance`
  строит `FnIndex.build_for` с импортами дерева тела и его модулем. `pipeline/pipeline.nv`:
  передать дерево тела. `check/calls.nv`: вход через плоский `defs.def_of`.
  Что ломается: замер D125 (`is_high_surrogate` — ложная неоднозначность) и 237
  неоднозначностей копии себя в самосборке — держатся только тем, что видимость фильтрует
  раньше доминирования; риск для меры 0.2. Закрывает `hygiene-helper-fn` и
  `hygiene-helper-overload`.
- **А2, файл диагностики.** У `Diagnostic` появляется файл или индекс дерева — 5 литералов в
  4 файлах. Три печатающих двери `main.nv` называют файл тела. `pipeline.nv` перестаёт
  переписывать спан в 0..0. Закрывает `diag-wrong-file-*` и `diag-body-file-module`.
- **А3, C-имя.** `sem/mangle.nv:221-222` плюс причина пустого `handed_from` у std.
- **Чего А НЕ закрывает:** константы и типы модуля тела (`hygiene-const-oracle-fails`,
  приватный тип тела). Им нужен ключ «модуль + имя», а `DefTable` плоская. Значит, по
  оговорке («каждое суждение») класс остаётся открытым.
- **Цена:** 6–8 файлов, среднее.

**Путь Б — область имён на модуль.** `DefTable` ключуется парой (модуль, имя) или живёт по
таблице на модуль внутри `Ctx`. Harvest регистрирует ВСЕ функции, константы и типы
переданных модулей с их домом; приватное — признак, а не отсутствие строки. Каждый вопрос об
имени задаётся «из модуля M»: файл спрашивает со своим модулем, экземпляр — с модулем тела.
- **Места:** `def_of` — 24 вызова в 15 файлах; `ty_of_name` — 11; вызовы `FnIndex`
  (`lookup`/`only_row_of`/`has_name`/`first_row_of`) — 15. Плюс `sem/collect.nv`,
  `sem/harvest.nv`, `sem/mangle.nv` (C-имя константы с модулем — у оракула
  `Nova_const_hp_geo_SCALE`).
- **Что даёт:** закрывает класс целиком, включая D281 одной дверью — туда же уходит
  `priv-leak-moduleless`.
- **Цена:** это волна, а не правка: широко трогает меру 0.2 и самосборку.

**Рекомендация:** Б — отдельной волной Э.10. Только она закрывает класс по оговорке; путь А
оставляет константы и типы, то есть ту же К1 в соседней форме. А2 (файл диагностики) от
таблицы имён не зависит, её можно взять первой как самостоятельный шаг.
