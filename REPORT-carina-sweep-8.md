## №1643 — заглушки оболочки, класс целиком

Оракул выпускает стёртый обобщённый слой оболочки телами, которые выбрасывают параметры и
возвращают константу: `{ (void)nova_self; (void)other; return (nova_bool){0}; }`. Скан по форме
тела находит **101** такую функцию — `Nova_Vec_*` (52), `Nova_HashMap_*` (23), `Nova_Set_*` (14) и
12 итераторов (`Nova_MapIter_*`, `Nova_FilterIter_*`, `Nova_KeysIter_*`, …). `InteropTable @has` отвечал по ИМЕНИ, так что путь Карины к любой
из них собирался и отвечал константой.

- `emit_c/shell.nv` `stub_names`: один проход по шаблону рядом со сканом идентификаторов, имена
  возвращаются, помечает их `shell_surface` (таблица — её локал); заглушка —
  `static`-определение, тело которого — один или больше `(void)<параметр>;` и ОДИН `return` из
  `NULL`, `NOVA_UNIT` или `(T){0}`. Тело без `(void)` не берётся (константная функция без
  параметров может быть настоящей).
- `sem/interop.nv`: множество `stubs`, `@add_stub`; `@has` для заглушки отвечает «нет» — любой путь
  уходит к экземпляру из тела std или к отказу по имени.
- Сам `shell.tpl.c` не тронут — это эмиссия оракула, её держит страж свежести.
- **Проверено:** все 101 имя скана сверены с `@has` временным тестом; модульный тест
  `pipeline/shell_stub_test.nv` (заглушки трёх форм возврата против настоящих тел того же семейства).
- **Чего этот шаг НЕ доказывает:** живого пути Карины в заглушку я не нашёл — вектор с
  элементом-newtype стирается до носителя (`Vec____nova_int`), а не в `Nova_Vec`; мера и смоуки до
  и после совпадают. Правка закрывает класс заранее, а не чинит наблюдённый неверный вывод.

## D46 — `==`/`!=` на векторах (вариант а)

- Расширена существующая дверь `==` (`@record_operator_callee`, до сих пор только `str`), второй не
  заводил: два вектора одного типа → `@vec_op_carried` (дверь `xs[i]`) даёт строку `equal` —
  конкретный экземпляр оболочки, иначе экземпляр из тела std, иначе отказ по имени оболочки — и она
  записывается вызываемым; судья операторов пару пропускает.
- `is_vector_ty` (sem) — один ответ «это `[]T`?» для чекера и эмиттера; эмиттер печатает вызов
  через `vec_op_c`.
- Стёртая `Nova_Vec_method_equal` никогда не кандидат (№1643).
- `[]u8`, `[]str` — экземпляры есть в оболочке, работают байт-в-байт; `[]int`, `[]TyId` — экземпляра в
  оболочке нет, тело std на замыканиях `view_at(i, |a| ...)` → честный отказ в экземпляре `equal`.
