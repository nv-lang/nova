# REPORT-p761 — newtype в payload и порядок объявления

КОРЕНЬ: порядок объявления ломает сборку, только когда payload арма берётся СВЯЗКОЙ ОБРАЗЦА и оборачивается в `Some` (`Const(row) => Some(row)`). Сумма выше newtype опускала payload раньше, чем эмиттер узнавал представление newtype, и получала `Nova_Row*`; связка наследовала этот тип, а `Option[Row]` в сигнатуре был `NovaOpt_nova_int`. Четыре встречные пробы интегратора брали `Some(7 as Row)`, то есть значение, а не связку, и потому были зелёными. Число пиров, транзитивный импорт и поля записи роли не играют: красная форма собирается из одного файла. Тот же класс у `type X alias int`. /
ФИКС: `compiler-codegen/src/codegen/emit_c/type_repr_early.rs:54` — представление каждого не-generic newtype/alias регистрируется в `type_aliases` до эмиссии первого типа, цепочки разрешаются до неподвижной точки; вызов в `emit_c.rs:7793`. /

Пробы вне Карины (`docs/plans/repro/761-newtype-order/`): a (один файл, сумма выше, `Some(r)`) -> 1 ошибка / зелено; e (пиры, объявление в последнем файле) -> 1 ошибка / зелено; g (alias) -> 4 ошибки / зелено; b, c, d, f (контроль, `r as int` без Option, `Some` от свежего значения, обратный порядок пиров) -> зелено / зелено. /
