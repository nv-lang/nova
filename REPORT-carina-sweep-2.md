## №1560 — подробно

`arg_class` (check/type_of.nv) отвечал `ro` на любой `x.f` «консервативно, ведь `ro` принимает
любой режим» — это неверно: `mut`-параметр/приёмник `ro` отказывает (P14). `@f` вообще падал в
«owned temporary». Теперь `field_class`: класс поля — класс КОРНЯ цепочки (`.f`, `@f`, скобки);
`mut`/`consume`-корень даёт `mut` (не `consume`: вынос из поля — другой вопрос), `ro`-корень
или небиндинг (`f().x`) — `ro`. Индекс — по-прежнему временное (уже, без изменений).

Опора на спеку (spec-reader, сверено): 02-types.md:11978–11981 (поле `mut`-биндинга пишемо,
`ro` — нет), :13463–13478 (`walk_root`: mut-вызов через цепочку судится у корня; ro-корень —
`E_LOCAL_NOT_MUT`/`E_RECEIVER_BINDING_NOT_MUT`). Оракул на `ro`-корне отказывает тем же
E_LOCAL_NOT_MUT (neg_1).

Снято: P14 89 → 1, и следом «this type has no such method» 47 → 2 — за отказанным `@ir…` не
решался тип приёмника следующего вызова. Новых диагностик нет (сверка списков до/после).

Уже оракула, названо: `mk().c.bump()` (поле результата вызова) остаётся отказом, хотя :13480
разрешает мутацию hoisted-временного; поле `ro`-приёмника (`fn T @peek() => @c.bump()`)
отказывается — оракул ПРИНИМАЕТ, правило корня отказывает (возможный permissive оракула, ниже).

## №1565

Аргументы типизируются до выбора вызываемого, а ожидание у вызова снимается — голому `None`
негде взять инстанс. Теперь аргумент-«отсроченный вариант» (`None`, не затенённый биндингом)
пропускается обходом аргументов (слот ключа неизвестен — поиск сопоставляет по остальным) и
типизируется ПОСЛЕ FnFound с типом параметра как ожиданием; только если выбор вызываемого ничего
не отказал (одна причина — один раз). Обобщённый параметр инстанса не даёт — отказ по причине.

**Признание:** коммит `fec5251` я сделал, не прогнав модульные тесты; `option_test` закреплял
старое поведение (`take(None)` отказан) и покраснел. Починено отдельным коммитом `4fed860`:
то, ради чего был случай, сохранено — ожидание функции в аргумент не течёт (параметр
`Option[str]` под `-> Option[int]`, вызов чист); отказ для параметра другой суммы держит
фикстура none_arg/neg_1.

## №1564

`shell_method_symbol(ctx, row, t)` (sem/coerce.nv) — написание по СТРОКЕ: `consume`-приёмник
простого типа → `Nova_<T>_consume_<name>`, прочее — `c_method_symbol`. Им пользуются дверь
метода (check/methods.nv), эмиссия (emit_c/emit_expr.nv) и `coerce_shell_symbol`. В эмиссии
метод, который шелл держит под своим написанием, считается шелловым даже там, где
`Ctx @instantiates` говорит «тело наше»: **`instantiates` (sem/handed_bodies.nv) спрашивает то
же неверное `_method_`-написание** — это зона p274-carina-mono-k2, я его не трогал; там тот же
пробел, его стоит закрыть одной строкой через `shell_method_symbol`. База поверхности sem 325 →
326 со строкой хроники.

## №1563

После harvest каждого handed-файла `resolve_const_defaults` индексирует константы файла с
литеральным инициализатором (NameTable), `apply_const_defaults` (#realtime nogc) заменяет
дефолт-имя такой константы её литералом без идентичности (`handed_literal`, дверь №1518).
Попутно найдено: с выключенным проходом emit падает ICE «array: index 32 out of bounds» —
узел дефолта из чужого дерева читается в канале компилируемого файла. Для литеральных дефолтов
handed-функций (`cap int = 16`) этот же риск остаётся: их узел тоже из чужого дерева; сейчас
не проявился, но класс тот же (см. «Открыто»).

## ДЕФЕКТЫ (новые, номер — ваш)

1. **Оракул, possibly permissive:** мутирующий метод через поле `ro`-приёмника принимается:
   `type Ctr { n int }`, `fn Ctr mut @bump() -> int`, `type Outer { c Ctr }`,
   `fn Outer @peek() -> int => @c.bump()` — `nova check` чисто. По `walk_root` (02-types.md:13474–13477)
   корень `@` у не-`mut` метода — `ro`, ожидается E_RECEIVER_BINDING_NOT_MUT. Корень `@` в тексте
   правила отдельно не разобран (spec-reader) — спорно; Карина отказывает.
2. **Карина, handed_bodies.nv `instantiates`:** спрашивает `_method_`-написание и для
   `consume`-методов шелла отвечает «тело наше» — эмиссия звала бы несуществующий
   `novac_fn_<module>_<name>`. Обойдено в эмиттере, корень — в зоне k2.
3. **Карина, класс «узел чужого дерева в канале»:** литеральный дефолт handed-функции несёт id
   своего дерева; с константой-дефолтом это дало ICE «index out of bounds» (проба: фикстура
   handed_const_default при выключенном `resolve_const_defaults`). Литерал-дефолт стоит
   пересобирать через `handed_literal` тем же проходом.
4. **Стражи раннера в облаке:** часть стражей берёт `novac/target/novac.exe`, а не `NOVAC_BIN`;
   на Linux там лежала устаревшая копия, и `fixture-expect` в первом отчёте мог судить старый
   бинарь. Перед этим прогоном копия обновлена.
